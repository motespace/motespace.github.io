堆

一、是什么

Section titled “一、是什么”

堆(Heap)是计算机科学中一类特殊的数据结构的统称

堆通常是一个可以被看做一棵完全二叉树的数组对象，如下图：

总是满足下列性质：

  • 堆中某个结点的值总是不大于或不小于其父结点的值
  • 堆总是一棵完全二叉树

堆又可以分成最大堆和最小堆：

  • 最大堆：每个根结点，都有根结点的值大于两个孩子结点的值
  • 最小堆：每个根结点，都有根结点的值小于孩子结点的值

  • 一个节点的左节点等于其本身节点坐标 * 2 + 1

时间复杂度

Section titled “时间复杂度”

关于堆的插入和删除时间复杂度都是Olog(n)，原因在于包含n个节点的完全二叉树，树的高度不会超过log2n

堆化的过程是顺着节点所在路径比较交换的，所以堆化的时间复杂度跟树的高度成正比，也就是Olog(n)，插入数据和删除堆顶元素的主要逻辑就是堆化

三、总结

Section titled “三、总结”
  • 堆是一个完全二叉树
  • 堆中每一个节点的值都必须大于等于(或小于等于)其子树中每个节点的值
  • 对于每个节点的值都大于等于子树中每个节点值的堆，叫作“大顶堆”
  • 对于每个节点的值都小于等于子树中每个节点值的堆，叫作“小顶堆”
  • 根据堆的特性，我们可以使用堆来进行排序操作，也可以使用其来求第几大或者第几小的值

🎯 面试常考

Section titled “🎯 面试常考”

Q1：堆是什么?为什么优先队列用堆而不是有序数组?

Section titled “Q1：堆是什么?为什么优先队列用堆而不是有序数组?”

堆是完全二叉树 + 满足堆序性质(父节点总比子节点大/小)。 JavaScript 没有内置堆,通常用数组模拟:left = 2i+1, right = 2i+2, parent = (i-1)/2。

为什么优先队列用堆:

插入 取最值 空间
有序数组 O(n)(要移动) O(1) O(n)
堆 O(log n) O(log n) O(n)
平衡 BST O(log n) O(log n) O(n)

堆是数组 + 树结构,比 BST 实现简单得多,常数更小。

Q2：堆的调整( sift up / sift down)是怎么回事?

Section titled “Q2：堆的调整( sift up / sift down)是怎么回事?”

上浮(sift up):插入时把新元素放到数组末尾,然后和父节点比较,小的往上交换, 直到父节点不大于它或到根。

下沉(sift down):取堆顶时,把最后一个元素放到堆顶,再和两个孩子中较小的交换, 直到满足堆序。

复杂度:树高是 log n,每次调整最多走一条路径,所以是 O(log n)。

为什么取堆顶要用最后一个元素补位:这样才能保持「完全二叉树」的形状(不能挖空中间), 补完再下沉修正。

Q3：堆排序的原理?为什么不是 O(n log n) 稳定?

Section titled “Q3：堆排序的原理?为什么不是 O(n log n) 稳定?”

建堆:O(n)(不是 O(n log n),用自底向上逐个下沉,总和是 O(n)) 反复取堆顶放末尾:n 次 × 每次 O(log n) = O(n log n)

为什么不稳定:相等元素的交换会打乱相对顺序。

实际很少用:原地排序但不是 O(n) 空间(快排是 O(log n) 递归栈)。

Q4：Top K 用堆还是全排序?

Section titled “Q4：Top K 用堆还是全排序?”

用大小为 K 的堆,不要全排序:

  • 求最大的 K 个 → 小顶堆(堆顶是当前 K 个里最小的,来了更大的就替换)
  • 求最小的 K 个 → 大顶堆

复杂度 O(n log K),比全排序的 O(n log n) 好,尤其 K 远小于 n 时差距明显。

典型场景:1 万条数据找 Top 100、滑动窗口最大值(单调队列也是类似思路)。

📝 小结

Section titled “📝 小结”
  • 堆 = 完全二叉树 + 堆序,用数组模拟,left=2i+1 / right=2i+2 / parent=(i-1)/2。
  • 优先队列用堆:插入 O(log n)、取最值 O(log n),比有序数组的 O(n) 插入好得多。
  • 取堆顶用最后一个元素补位是为了保持完全二叉树形状,再 sift down 修正,整体 O(log n)。
  • Top K 用大小为 K 的堆,复杂度 O(n log K),求最大 K 用小顶堆。
