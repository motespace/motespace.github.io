快速排序

一、是什么

Section titled “一、是什么”

快速排序（Quick Sort）算法是在冒泡排序的基础上进行改进的一种算法，从名字上看就知道该排序算法的特点是快、效率高，是处理大数据最快的排序算法之一

实现的基本思想是：通过一次排序将整个无序表分成相互独立的两部分，其中一部分中的数据都比另一部分中包含的数据的值小

然后继续沿用此方法分别对两部分进行同样的操作，直到每一个小部分不可再分，所得到的整个序列就变成有序序列

例如，对无序表49，38，65，97，76，13，27，49进行快速排序，大致过程为：

  • 首先从表中选取一个记录的关键字作为分割点（称为“枢轴”或者支点，一般选择第一个关键字），例如选取 49

  • 将表格中大于 49 个放置于 49 的右侧，小于 49 的放置于 49 的左侧，假设完成后的无序表为：{27，38，13，49，65，97，76，49}

  • 以 49 为支点，将整个无序表分割成了两个部分，分别为{27，38，13}和{65，97，76，49}，继续采用此种方法分别对两个子表进行排序

  • 前部分子表以 27 为支点，排序后的子表为{13，27，38}，此部分已经有序；后部分子表以 65 为支点，排序后的子表为{49，65，97，76}

  • 此时前半部分子表中的数据已完成排序；后部分子表继续以 65 为支点，将其分割为{49}和{97，76}，前者不需排序，后者排序后的结果为{76， 97}

  • 通过以上几步的排序，最后由子表{13，27，38}、{49}、{49}、{65}、{76，97}构成有序表：{13，27，38，49，49，65，76，97}

三、应用场景

Section titled “三、应用场景”

快速排序时间复杂度为O(nlogn)，是目前基于比较的内部排序中被认为最好的方法，当数据过大且数据杂乱无章时，则适合采用快速排序

🎯 面试常考

Section titled “🎯 面试常考”

Q1：快排的原理?为什么平均 O(n log n) 最坏 O(n²)?

Section titled “Q1：快排的原理?为什么平均 O(n log n) 最坏 O(n²)?”

选一个基准(pivot),把数组分区成「比 pivot 小」和「比 pivot 大」, 再对两个分区递归。

最坏 O(n²) 的原因:每次分区都极度不均衡(比如已经有序的数组选第一个元素做 pivot), 递归退化成链式,总代价是 n + (n-1) + (n-2) + ... = O(n²)。

平均 O(n log n):随机选 pivot,期望每次分区均匀。

工程解法:

  • 随机选 pivot 或三数取中(取首、中、尾的中位数),能避免有序数组退化
  • 小数组切换到插入排序
  • 三路分区(小于/等于/大于):大量重复元素时,快排能接近 O(n)

Q2：快排和归并排序怎么选?

Section titled “Q2：快排和归并排序怎么选?”
快排 归并
平均时间 O(n log n) O(n log n)
最坏 O(n²) O(n log n)
空间 O(log n) 递归栈 O(n) 辅助数组
稳定性 不稳定 稳定
缓存友好 好(原地 partition) 差(要跳着访问)

选型:

  • 内存紧张 / 要求稳定 / 外部排序 → 归并
  • 内存里排序大数组 → 快排(常数小、缓存友好)

JS 内置 sort 用的是 TimSort(稳定、快速、对部分有序友好), 不是纯快排 —— 所以 Array.prototype.sort 在 V8 里是稳定的。

Q3：快排的 partition 怎么写?Hoare 划分和 Lomuto 划分有什么区别?

Section titled “Q3：快排的 partition 怎么写?Hoare 划分和 Lomuto 划分有什么区别?”

Lomuto(经典教材版):选末尾元素做 pivot,把小于 pivot 的都交换到左边。

每次划分要多次交换。

Hoare(更优):双指针从两端向中间夹,交换次数更少,常数更小。 快排的工业实现(如 V8 的 Array#sort 早期版本)用类似思路。

Hoare 的坑:返回的分割点不一定是 pivot 的最终位置, 所以 partition 返回后递归区间要用 lo..pivot 和 pivot+1..hi 还是 lo..pivot-1 / pivot+1..hi 要小心, 容易造成死循环。

📝 小结

Section titled “📝 小结”
  • 快排 = 分区 + 递归,平均 O(n log n),最坏 O(n²)(有序数组 + 固定 pivot)。
  • 防退化三招:随机/三数取中选 pivot、小数组切插入排序、三路分区处理大量重复元素。
  • 归并稳定但要 O(n) 空间;快排原地但不稳定 —— 依稳定性要求和内存选。
  • Lomuto 划分交换次数多,Hoare 双指针更快;Hoare 返回的分割点语义要记清,否则死循环。
