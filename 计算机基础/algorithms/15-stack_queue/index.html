栈、队列

一、栈

Section titled “一、栈”

栈（stack）又名堆栈，它是一种运算受限的线性表，限定仅在表尾进行插入和删除操作的线性表

表尾这一端被称为栈顶，相反地另一端被称为栈底，向栈顶插入元素被称为进栈、入栈、压栈，从栈顶删除元素又称作出栈

所以其按照先进后出的原则存储数据，先进入的数据被压入栈底，最后的数据在栈顶，需要读数据的时候从栈顶开始弹出数据，具有记忆作用

二、队列

Section titled “二、队列”

跟栈十分相似，队列是一种特殊的线性表，特殊之处在于它只允许在表的前端（front）进行删除操作，而在表的后端（rear）进行插入操作

进行插入操作的端称为队尾，进行删除操作的端称为队头，当队列中没有元素时，称为空队列

在队列中插入一个队列元素称为入队，从队列中删除一个队列元素称为出队。因为队列只允许在一端插入，在另一端删除，所以只有最早进入队列的元素才能最先从队列中删除，故队列又称为先进先出

三、应用场景

Section titled “三、应用场景”

栈

Section titled “栈”

借助栈的先进后出的特性，可以简单实现一个逆序数处的功能，首先把所有元素依次入栈，然后把所有元素出栈并输出

包括编译器的在对输入的语法进行分析的时候，例如"()"、"{}"、"[]"这些成对出现的符号，借助栈的特性，凡是遇到括号的前半部分，即把这个元素入栈，凡是遇到括号的后半部分就比对栈顶元素是否该元素相匹配，如果匹配，则前半部分出栈，否则就是匹配出错

包括函数调用和递归的时候，每调用一个函数，底层都会进行入栈操作，出栈则返回函数的返回值

生活中的例子，可以把乒乓球盒比喻成一个堆栈，球一个一个放进去（入栈），最先放进去的要等其后面的全部拿出来后才能出来（出栈），这种就是典型的先进后出模型

队列

Section titled “队列”

当我们需要按照一定的顺序来处理数据，而该数据的数据量在不断地变化的时候，则需要队列来帮助解题

队列的使用广泛应用在广度优先搜索种，例如层次遍历一个二叉树的节点值（后续将到）

生活中的例子，排队买票，排在队头的永远先处理，后面的必须等到前面的全部处理完毕再进行处理，这也是典型的先进先出模型

🎯 面试常考

Section titled “🎯 面试常考”

Q1：栈和队列的区别?JS 里怎么实现?

Section titled “Q1：栈和队列的区别?JS 里怎么实现?”

栈:后进先出(LIFO)。队列:先进先出(FIFO)。

JS 没有内置栈和队列,但有现成结构:

  • 栈:array.push() / array.pop()
  • 队列:array.push() / array.shift() —— 但 shift() 是 O(n)(要搬元素)!

前端高频场景:

  • 调用栈:函数调用、递归 —— 栈溢出就是它满了
  • 任务队列:微任务/宏任务(event loop)
  • 组件栈:React 的 Fiber 树本质也是栈式
  • 括号匹配、表达式求值、撤销/重做

Q2：浏览器的事件循环和栈队列什么关系?

Section titled “Q2：浏览器的事件循环和栈队列什么关系?”

事件循环是「任务队列 + 调用栈」的组合:

  1. 调用栈执行同步代码,栈空后才有机会取任务
  2. 宏任务队列(timer、I/O、UI 渲染)每轮取一个
  3. 微任务队列(Promise.then、MutationObserver、queueMicrotask)在当前宏任务执行完后全部清空

关键顺序:一个宏任务 → 清空所有微任务 → (可能)渲染 → 下一个宏任务。

面试高频:「输出顺序」类题目考的就是这个。 另外:微任务里再产生微任务,会在同一轮被清空,不会插队到宏任务之间。

Q3：什么时候会栈溢出?

Section titled “Q3：什么时候会栈溢出?”

调用栈有上限(浏览器大约 1 万层,Node 大约 1.1 万层),超过就 RangeError: Maximum call stack size exceeded。

典型触发:

  • 无终止条件的递归
  • 深递归的树遍历(比如深度 10 万的 DOM)
  • 链式调用过深(a.b.c.d...)

解决:

  1. 改写成循环 + 显式栈(DFS 用数组模拟栈)
  2. 尾递归优化 —— 但 JS 引擎大多没有实现尾调用优化,不能指望
  3. 分批处理:大数据用 requestIdleCallback / setTimeout 切片

📝 小结

Section titled “📝 小结”
  • 栈 LIFO、队列 FIFO;JS 没有内置,队列要用 head 指针避免 shift() 的 O(n)。
  • 事件循环 = 调用栈 + 宏任务队列 + 微任务队列,顺序是「一个宏任务 → 清空所有微任务 → 下一个宏任务」。
  • 调用栈上限约 1 万层,深递归要改写成循环 + 显式栈。
  • 前端高频场景:调用栈、任务队列、React Fiber 树、撤销重做。
