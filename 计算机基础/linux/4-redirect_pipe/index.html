七、重定向与管道的区别

Section titled “七、重定向与管道的区别”
管道 | 重定向 >/>>
本质 两个进程间传递数据 修改进程的文件描述符
作用域 连接两个命令 单个命令的输出到文件
处理对象 标准输出（STDOUT） STDOUT 或 STDERR
执行主体 两边同时执行 单个命令
数据形式 流（Stream） 文件

🎯 面试常考

Section titled “🎯 面试常考”

Q1：重定向和管道的区别?2>&1 是什么顺序?

Section titled “Q1：重定向和管道的区别?2>&1 是什么顺序?”

重定向改变文件描述符的指向:> 覆盖、>> 追加、< 输入。 管道把一个命令的 stdout 连到另一个命令的 stdin:cmd1 | cmd2。

2>&1 的顺序很关键:

  • > file 2>&1 = stdout 和 stderr 都进 file(2 先指向 stdout 的目标,再把 stdout 重定向)
  • 2>&1 > file = stderr 进 当前的 stdout(终端),stdout 进 file —— 两个分流

面试高频:2>&1 放前面还是后面,决定了是「合并」还是「分流」。

Q2：管道默认是字节流还是字符流?为什么 grep 有时读不到最后一个单词?

Section titled “Q2：管道默认是字节流还是字符流?为什么 grep 有时读不到最后一个单词?”

默认是字节流(byte stream),不是字符流。

后果:grep 从管道读时是按块读的,如果最后一个单词没有换行符结尾, grep 可能因为缓冲区没满而读不到它。

解法:

  • 源命令加换行(echo 自带,printf 要手动)
  • 用 grep --line-buffered 处理流式输出
  • 理解 stdbuf -o0 控制缓冲

另一个坑:管道会吞掉命令的退出码,最后一个命令的退出码才是整条管道的退出码。 false | true 的退出码是 0。要拿到真实退出码用 set -o pipefail。

📝 小结

Section titled “📝 小结”
  • 重定向改 fd 指向,管道把 stdout 连到 stdin。
  • 2>&1 的位置决定「合并」还是「分流」:> f 2>&1 合并,2>&1 > f 分流。
  • 管道是字节流,源没换行时 grep 可能读不到最后一段。
  • 管道会吞掉中间命令的退出码,要严格检查用 set -o pipefail。
