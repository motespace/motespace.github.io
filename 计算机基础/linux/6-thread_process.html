Linux 进程与线程 ​

进程是资源分配的基本单位，线程是 CPU 调度的基本单位。理解两者的区别和 Linux 中的实现，是排查性能问题的基础。

一、进程基础 ​

1.1 什么是进程 ​

进程（Process）是运行中的程序的实例。每个进程有独立的内存空间、文件描述符、寄存器状态。

程序（二进制文件） ──加载到内存──→ 进程（运行的实例）
                                              │
                         PID: 12345           │
                         内存空间（独立）      │
                         文件描述符（独立）    │
                         寄存器状态（独立）    │

1.2 进程的组成 ​

每个进程包含三部分：

部分说明
程序代码可执行指令
数据全局变量、堆、栈
PCB（进程控制块）内核数据结构，存储进程状态、PID、优先级等

PCB（Process Control Block）是进程存在的唯一标志，内核通过 PCB 管理所有进程。

1.3 进程状态 ​

         ┌─────────────────────────────┐
         │      创建（New）             │
         └──────────┬──────────────────┘
                    ↓
    ┌──────────────────────────────┐
───→│     就绪（Ready）            │←────────────────┐
    │  (等待 CPU 调度)             │                 │
    └──────────┬──────────────────┘                 │
               ↓                                    │
    ┌──────────────────────────────┐               │
───→│     运行（Running）           │               │
    │  (正在 CPU 上执行)            │               │
    └──────────┬──────────────────┬──┘               │
               ↓                 ↓                  │
    ┌────────────────┐  ┌────────────────┐        │
    │  阻塞（Blocked）│  │  终止（Exit）   │        │
    │  (等待 I/O)     │  └────────────────┘        │
    └────────┬────────┘                             │
             │                                      │
             └──────────────────────────────────────┘

二、线程基础 ​

2.1 什么是线程 ​

线程（Thread）是进程内的执行单元，同一个进程的所有线程共享进程的地址空间和资源。

进程 A
├── 线程 1（执行 main 函数）
├── 线程 2（处理 I/O）
└── 线程 3（处理网络）
     ↑共享堆、全局变量、打开的文件
     ↑独立栈、寄存器、PC

2.2 进程 vs 线程 ​

维度进程线程
资源分配独立地址空间共享进程地址空间
开销大（需复制完整环境）小（共享大部分资源）
通信IPC（管道、Socket）直接读写共享内存
隔离性进程间隔离，互不影响一个线程崩溃可能影响整个进程
并发多进程可利用多核多线程更能发挥多核优势

类比：

  • 进程 = 独立的工厂（互不干扰）
  • 线程 = 工厂内的工人（共享仓库）

2.3 Node.js 的线程模型 ​

Node.js 主进程是单线程（V8 主线程），但通过 libuv 线程池处理异步 I/O：

Node.js 主线程（单线程 JS 执行）
    │
    ├── 处理 JS 代码
    └── 调用 libuv
              │
              ├── 同步任务 → libuv 工作线程池（默认 4-128 线程）
              │                 处理：fs、crypto、dns.lookup
              │
              └── 异步任务 → 操作系统（epoll/kqueue/IOCP）
                              处理：网络 I/O、文件描述符事件

Web Worker（浏览器端）：

javascript
// 主线程
const worker = new Worker('compute.js')
worker.postMessage({ data: largeArray })
worker.onmessage = (e) => console.log('结果:', e.data)

// compute.js（独立线程）
self.onmessage = (e) => {
  const result = heavyComputation(e.data)
  self.postMessage(result)
}

三、Linux 进程管理命令 ​

3.1 ps — 查看进程 ​

bash
# 查看所有进程（详细）
ps aux

# 查看特定进程
ps aux | grep node

# 查看进程树
ps auxf

# 查看特定用户
ps -u ubuntu

# BSD 风格（显示进程树和状态）
ps axo pid,ppid,stat,%cpu,%mem,cmd

STAT 状态码：

状态含义
RRunning（运行或就绪）
SSleeping（可中断睡眠）
DDisk Sleep（不可中断 I/O）
ZZombie（僵死）
TStopped（暂停/跟踪）
IIdle（空闲内核线程）

3.2 top / htop — 实时监控 ​

bash
# 实时监控（按 CPU 排序）
top

# 按内存排序
top -o %MEM

# 指定刷新间隔
top -d 2

# htop（更直观，需安装）
htop

top 关键指标：

  • load average: 0.52, 0.48, 0.51 — 1/5/15 分钟系统负载
  • 负载 > CPU 核数 → 有进程在等待 CPU

3.3 pgrep / pkill — 快速进程操作 ​

bash
# 找进程 PID
pgrep -f "node server.js"

# 找进程并显示详细信息
pgrep -a -f "node"

# 温柔终止
pkill -15 -f "node"

# 强制杀死
pkill -9 -f "node"

3.4 /proc — 进程详细信息 ​

bash
# 进程的内存映射
cat /proc/<PID>/maps

# 进程状态
cat /proc/<PID>/status | grep -E "VmRSS|Name|Pid"

# 进程打开的文件
ls -la /proc/<PID>/fd

四、进程间通信（IPC） ​

4.1 常见方式 ​

方式适用场景
管道（Pipe）父子进程间单向数据流
Socket任意进程间（可跨机器）
共享内存高频数据交换（最快）
信号（Signal）简单事件通知
消息队列异步任务队列
文件持久化数据交换

4.2 信号（Signal） ​

bash
# 常用信号
kill -l
# 1) SIGHUP   挂起（进程重启）
# 9) SIGKILL  强制杀死（不可捕获）
# 15) SIGTERM 优雅终止（可捕获）
# 18) SIGCONT 继续运行
# 19) SIGSTOP 暂停（不可捕获）

# 发送信号
kill -15 <PID>     # 优雅终止
kill -9 <PID>      # 强制杀死
kill -HUP <PID>    # 重载配置（nginx、docker）

# 进程捕获信号
# Node.js: process.on('SIGTERM', () => { gracefulShutdown() })

五、守护进程（Daemon） ​

5.1 什么是守护进程 ​

守护进程是后台运行、独立于终端的系统服务，生命周期长，通常开机自启。

普通进程                 守护进程
─────────────────       ─────────────────
终端关闭 → 进程死        终端关闭 → 继续运行
无控制终端               无控制终端（setsid）

5.2 PM2 守护进程管理 ​

PM2 是 Node.js 专用的进程管理器：

bash
# 启动
pm2 start server.js --name api

# 守护运行（自动重启崩溃）
pm2 start server.js --name api --restart-delay 1000 --max-restarts 10

# 查看进程列表
pm2 list

# 查看日志
pm2 logs api
pm2 logs api --lines 100 --nostream

# 重启
pm2 restart api

# 优雅停止
pm2 stop api

# 保存进程列表（重启后自动恢复）
pm2 save

# 设置开机自启
pm2 startup        # 生成启动命令，运行提示的命令

5.3 systemd 守护进程 ​

Linux 标准服务管理（CentOS 7+、Ubuntu 16.04+）：

bash
# 查看服务状态
systemctl status nginx

# 启动 / 停止 / 重启
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx

# 开机自启
sudo systemctl enable nginx
sudo systemctl disable nginx

# 查看所有服务
systemctl list-units --type=service --state=running

六、实战：CPU / 内存问题排查 ​

6.1 排查 CPU 100% ​

bash
# 1. top 找到高 CPU 进程
top -o %CPU

# 2. 查看该进程的子进程
ps auxf | grep <PID>

# 3. Node.js V8 采样（生产环境可用）
kill -USR2 <PID>   # 触发 V8 采样
# 采样文件生成在 Node 进程 cwd 下：node_<pid>.log

# 4. 分析采样
node --prof-process isolate-*.log | head -30

6.2 排查内存持续增长 ​

bash
# 1. 每分钟记录 RSS（物理内存）
while sleep 60; do
  date >> /tmp/memory.log
  ps -o pid,rss,vsz -p <PID> >> /tmp/memory.log
done &

# 2. 分析内存趋势
cat /tmp/memory.log

# 3. Node 堆内存
node -e "console.log(process.memoryUsage())"
# { rss: 50MB, heapTotal: 18MB, heapUsed: 12MB, external: 3MB }
