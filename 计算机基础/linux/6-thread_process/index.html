Linux 进程与线程

进程是资源分配的基本单位，线程是 CPU 调度的基本单位。理解两者的区别和 Linux 中的实现，是排查性能问题的基础。

一、进程基础

Section titled “一、进程基础”

1.1 什么是进程

Section titled “1.1 什么是进程”

进程（Process）是运行中的程序的实例。每个进程有独立的内存空间、文件描述符、寄存器状态。

1.2 进程的组成

Section titled “1.2 进程的组成”

每个进程包含三部分：

部分 说明
程序代码 可执行指令
数据 全局变量、堆、栈
PCB（进程控制块） 内核数据结构，存储进程状态、PID、优先级等

PCB（Process Control Block）是进程存在的唯一标志，内核通过 PCB 管理所有进程。

二、线程基础

Section titled “二、线程基础”

2.1 什么是线程

Section titled “2.1 什么是线程”

线程（Thread）是进程内的执行单元，同一个进程的所有线程共享进程的地址空间和资源。

2.2 进程 vs 线程

Section titled “2.2 进程 vs 线程”
维度 进程 线程
资源分配 独立地址空间 共享进程地址空间
开销 大（需复制完整环境） 小（共享大部分资源）
通信 IPC（管道、Socket） 直接读写共享内存
隔离性 进程间隔离，互不影响 一个线程崩溃可能影响整个进程
并发 多进程可利用多核 多线程更能发挥多核优势

类比：

  • 进程 = 独立的工厂（互不干扰）
  • 线程 = 工厂内的工人（共享仓库）

🎯 面试常考

Section titled “🎯 面试常考”

Q1：进程和线程的区别?什么时候用多线程?

Section titled “Q1：进程和线程的区别?什么时候用多线程?”

进程:资源分配的最小单位,有自己的独立地址空间(互相隔离)、文件描述符表。 线程:CPU 调度的最小单位,共享进程的地址空间、堆、文件描述符。

进程 线程
地址空间 独立 共享
创建/切换开销 大 小
通信 需要 IPC(管道/socket) 直接读写共享内存
隔离性 强 弱(一个崩全崩)

用多线程的条件:任务计算密集(纯 CPU)且彼此独立。 如果是 I/O 密集(大量网络/磁盘等待),多进程或异步更合适 —— Node 的单线程 + 异步 I/O 就是这个思路。

Node 的取舍:JS 单线程跑业务代码,但把 I/O 交给 libuv 线程池, 把 CPU 密集交给 Worker Threads(独立 V8 isolate)。

Q2：多线程怎么保证数据安全?

Section titled “Q2：多线程怎么保证数据安全?”

共享内存必然有竞态。三种手段:

  1. 锁(mutex):最通用,但有死锁风险(多个锁获取顺序不一致就会死锁)
  2. 无锁数据结构:CAS、原子操作
  3. 消息传递:每个线程有独立队列,只通过队列通信 —— 最安全,也是 Go 的 CSP 思路

Node worker_threads 的注意点:

  • 传数据默认是结构化克隆(会复制),大数据用 SharedArrayBuffer 或 transferable
  • Atomics 提供原子操作
  • 但真正的性能瓶颈通常在 DOM 操作,worker 里没有 DOM,所以不适合把渲染逻辑放进去

📝 小结

Section titled “📝 小结”
  • 进程是资源分配单位(独立地址空间、隔离强),线程是调度单位(共享内存、切换快)。
  • 多线程适合计算密集且任务独立;I/O 密集更适合多进程/异步(Node 的单线程+libuv 线程池就是这个取舍)。
  • 共享内存的三个解法:锁、无锁数据结构、消息传递(最安全)。
  • worker_threads 传大数据用 SharedArrayBuffer,默认是结构化克隆会复制。
