Linux 用户与权限管理 ​

Linux 是多用户操作系统，通过用户和用户组管理文件访问权限。前端工程师在服务器上部署项目时，常需要管理文件所有者和权限。

一、用户与用户组基础 ​

1.1 三类访问者 ​

Linux 文件权限针对三类对象：

对象说明
所有者（Owner）文件创建者，拥有最高权限
用户组（Group）文件所属组的成员，可获批量的组级别权限
其他人（Other）既不是所有者，也不是同组成员的其他用户

1.2 权限字符 ​

rwx r-x r--
├──┘ ├──┘ ┊
│   │    └── 其他用户 (Other)
│   └───── 用户组 (Group)
└──────── 文件所有者 (Owner)
  • r（Read）= 读，权限值 4
  • w（Write）= 写，权限值 2
  • x（eXecute）= 执行，权限值 1

1.3 ls -l 详解 ​

bash
drwxr-xr-x  3 ubuntu www-data  4096  Oct 15 10:30  project
-rw-r--r--  1 ubuntu www-data  1024  Oct 15 09:00  .env
字段含义
d文件类型（d=目录，-=文件）
rwxr-xr-x所有者 rwx / 组 r-x / 其他 r-x
3硬链接数（目录内子目录数+2）
ubuntu文件所有者
www-data文件所属组
4096文件大小（字节）
Oct 15 10:30修改时间
project文件名

二、用户操作 ​

2.1 useradd — 创建用户 ​

bash
# 创建普通用户
sudo useradd -m -s /bin/bash deploy

# 参数说明
# -m：创建主目录（/home/deploy）
# -s：指定登录 shell

# 创建系统用户（无登录 shell）
sudo useradd -r -s /sbin/nologin appuser

# 创建用户并指定主目录
sudo useradd -d /var/www/deploy -m deploy

2.2 passwd — 设置密码 ​

bash
# 设置当前用户密码
passwd

# 设置指定用户密码（root 执行）
sudo passwd deploy

# 查看密码状态
passwd -S deploy
# deploy P 2024-10-15 0 99999 7 -1
# P = 有密码，LK = 锁定

# 锁定/解锁用户
sudo passwd -l deploy    # 锁定（禁止登录）
sudo passwd -u deploy    # 解锁

2.3 usermod — 修改用户 ​

bash
# 加入附加组
sudo usermod -aG www-data deploy

# 修改登录 shell
sudo usermod -s /bin/bash deploy

# 锁定账户（等价于 passwd -l）
sudo usermod -L deploy

# 解锁
sudo usermod -U deploy

2.4 userdel — 删除用户 ​

bash
# 删除用户（保留主目录）
sudo userdel deploy

# 删除用户及主目录
sudo userdel -r deploy

三、用户组操作 ​

3.1 groupadd — 创建组 ​

bash
sudo groupadd developers
sudo groupadd -r nginx       # 系统组（ID < 1000）

3.2 gpasswd — 管理组成员 ​

bash
# 添加用户到组
sudo gpasswd -a deploy developers

# 从组移除
sudo gpasswd -d deploy developers

# 设置组管理员（可由管理员添加成员，无需 root）
sudo gpasswd -A deploy developers

# 查看组成员
getent group developers

3.3 groups — 查看用户所属组 ​

bash
groups              # 当前用户
groups deploy      # 指定用户

四、权限管理 ​

4.1 chmod — 修改权限 ​

bash
# 数字方式（r=4, w=2, x=1）
chmod 755 script.sh          # rwxr-xr-x
chmod 644 config.json       # rw-r--r--
chmod 600 .env              # rw-------
chmod 700 /root              # rwx------

# 符号方式（更直观）
chmod u+x file               # 所有者加执行权限
chmod g-w file               # 组去掉写权限
chmod o=r file               # 其他人只读
chmod a+x file               # 所有人加执行
chmod u=rwx,g=rx,o=rx file  # 精确设置

# 递归
chmod -R 755 /var/www/html
chmod -R o-w /var/www/html  # 去掉其他用户的写权限（安全加固）

4.2 chown — 修改所有者 ​

bash
# 改所有者
sudo chown ubuntu file.txt

# 改所有者和组
sudo chown ubuntu:www-data file.txt

# 递归（服务器部署常用）
sudo chown -R ubuntu:www-data /var/www/html

Nginx + Node 典型权限问题：

bash
# Nginx 以 www-data 运行，读静态文件
# Node 以 ubuntu 运行，写日志

# 方案 1：统一用户组
sudo usermod -aG ubuntu www-data
sudo chown -R ubuntu:www-data /var/www/html

# 方案 2：让日志目录可写
sudo chown -R ubuntu:www-data /var/log/project
sudo chmod -R 775 /var/log/project

4.3 chgrp — 修改所属组 ​

bash
sudo chgrp www-data /var/www/html/shared

五、特殊权限 ​

5.1 SUID（4000） ​

文件执行时以文件所有者身份运行，而非调用者身份。

bash
# 典型例子：passwd 命令
# -rwsr-xr-x 1 root root  ... /usr/bin/passwd
# 普通用户执行 passwd，可修改自己的密码（需要 root 权限写 /etc/passwd）

5.2 SGID（2000） ​

目录内新建的文件继承目录的组，而非创建者的主组。

5.3 Sticky Bit（1000） ​

目录内文件只允许所有者删除（/tmp 目录典型用法）。

bash
# /tmp 的权限
drwxrwxrwt  12 root root  ...  /tmp
#               ↑
#            t = sticky bit（其他人只能删自己的文件）

六、sudo 权限管理 ​

6.1 su — 切换用户 ​

bash
# 切换到指定用户（需要目标用户密码）
su - ubuntu

# 切换到 root（需要 root 密码）
su -

# 以指定用户执行单条命令
su - ubuntu -c "pm2 list"

6.2 sudo — 提权执行 ​

bash
# 当前用户需要列入 /etc/sudoers 才可使用 sudo
sudo systemctl restart nginx

# 免密码（调试用，生产慎用）
sudo -n systemctl restart nginx

6.3 /etc/sudoers 配置 ​

bash
# 编辑 sudoers（语法错误会导致所有用户无法 sudo，务必用 visudo）
sudo visudo

# 允许 ubuntu 用户无密码 sudo
ubuntu  ALL=(ALL) NOPASSWD: ALL

# 允许 deploy 用户只能重启 nginx
deploy  ALL=(ALL) NOPASSWD: /bin/systemctl restart nginx

# 默认：root 有完整权限
root    ALL=(ALL) ALL

七、真实权限问题排查 ​

场景 1：Nginx 403 Forbidden ​

bash
# 1. 检查文件权限
ls -la /var/www/html/index.html
# 正常应该：-rw-r--r-- www-data www-data

# 2. 检查目录权限（目录需要 x 权限才能进入）
ls -la /var/www/html/
# 正常应该：drwxr-xr-x www-data www-data

# 3. 检查 Nginx 运行用户
grep "^user" /etc/nginx/nginx.conf
# user www-data;

# 4. 修复
sudo chown -R www-data:www-data /var/www/html
sudo chmod -R 644 /var/www/html
sudo find /var/www/html -type d -exec chmod 755 {} \;

场景 2：Node 无法写入日志 ​

bash
# 1. 确认 Node 运行用户
ps aux | grep node
# ubuntu  ... node server.js

# 2. 检查日志目录权限
ls -la /var/log/project/

# 3. 修复
sudo chown -R ubuntu:ubuntu /var/log/project
sudo chmod 755 /var/log/project
