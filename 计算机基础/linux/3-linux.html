Linux 前端工程师常用命令 ​

前端工程师在部署、调试、排查问题时，SSH 到服务器是常态。本文覆盖高频 Linux 命令，按场景分类，配真实输出。

一、进程管理 ​

1.1 ps — 查看进程 ​

bash
# 查看所有进程（含命令行）
ps aux

# 查看特定进程
ps aux | grep node

# 查看进程树
ps auxf

# 查看特定用户进程
ps -u ubuntu

关键字段：

  • PID：进程 ID
  • STAT：状态（R=运行，S=睡眠，Z=僵尸）
  • TIME：CPU 累计时间

真实输出示例：

USER   PID %CPU %MEM    VSZ   RSS TTY  STAT START   TIME COMMAND
root   123  0.1  0.2  123456  8900 ?    S    10:00   0:05 node /app/server.js

1.2 top / htop — 实时监控 ​

bash
# 实时监控（按 CPU 排序）
top

# 按内存排序
top -o %MEM

# htop（更直观，需安装）
htop

top 关键行：

%Cpu(s):  1.2 us,  0.8 sy,  0.0 ni, 97.5 id  ← CPU 使用率
MiB Mem :  16384 total,   2048 free              ← 内存
MiB Swap:   2048 total,   2048 available         ← 交换分区

实战场景：Node.js 内存泄漏排查

bash
# 发现内存占用高
top -o %MEM
# 找到 node 进程 PID
# 进一步查看
ps aux | grep node
# 看更细的内存分布
pm2 list

1.3 pgrep / pkill — 快速匹配进程 ​

bash
# 查找 node 进程 PID
pgrep -f "node /app"

# 杀死所有 node 进程
pkill -f "node /app"

# 温柔终止（收到 SIGTERM）
pkill -15 -f "node /app"

# 强制杀死（收到 SIGKILL）
pkill -9 -f "node /app"

1.4 systemctl — 服务管理（Systemd） ​

bash
# 查看服务状态
systemctl status nginx

# 启动 / 停止 / 重启
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx

# 开机自启
sudo systemctl enable nginx
sudo systemctl disable nginx

# 查看所有服务状态
systemctl list-units --type=service --state=running

PM2 进程管理（Node 专用）：

bash
pm2 list                    # 查看所有进程
pm2 start server.js --name api   # 命名启动
pm2 restart api             # 重启
pm2 logs api                # 查看日志
pm2 monit                   # 实时监控面板
pm2 save                    # 保存进程列表（重启后恢复）
pm2 startup                 # 设置开机自启
pm2 kill                    # 停止所有

二、内存与磁盘 ​

2.1 free — 内存使用 ​

bash
free -h          # 人类可读格式（GB/MB）
free -m          # 单位 MB
free -s 3        # 每 3 秒刷新

输出解读：

              total        used        free      shared  buff/cache   available
Mem:          7.7Gi       3.1Gi       1.2Gi       45Mi       3.4Gi       4.2Gi
Swap:         2.0Gi        0B         2.0Gi
  • buff/cache：内核缓冲区，不代表可用内存不足
  • 看 available 而非 free，才是真正可用

Node 内存排查：

bash
# 进程内存
ps -o pid,rss,vsz,comm -p <PID>

# /proc 读取更详细（单位 KB）
cat /proc/<PID>/status | grep -E "VmRSS|VmSize"

2.2 df / du — 磁盘 ​

bash
# 查看磁盘整体使用率
df -h

# 查看 inode（文件数限制）
df -i

# 查看当前目录大小（显示前 10）
du -sh *
du -sh * | sort -hr | head -10

# 看某个目录的大小
du -sh /var/log

# 找大文件（>100MB）
find / -size +100M -type f 2>/dev/null

实战场景：服务器磁盘满了

bash
df -h                         # 确认哪个分区满了
du -sh /* | sort -hr          # 逐层找出最大目录
du -sh /var/log/* | sort -hr  # 定位到具体日志文件
# 清理：日志截断
> /var/log/nginx/access.log   # 截断而非删除（进程仍持有 fd）

三、网络诊断 ​

3.1 netstat / ss — 端口与连接 ​

bash
# 查看监听端口
netstat -tlnp
ss -tlnp

# 查看所有连接
ss -tan

# 查看特定端口占用
ss -tlnp | grep :443

# 查看 TIME_WAIT 连接（HTTP/1.1 长连接问题）
ss -tan state time-wait | grep :80

netstat vs ss：ss 更快速（读取内核 netlink 而非 /proc），netstat 需要额外解析。

3.2 lsof — 文件描述符与进程 ​

bash
# 查看端口占用
lsof -i :3000

# 查看某个进程打开的文件
lsof -p <PID>

# 查看打开的文件描述符数量
lsof -p <PID> | wc -l

# 查看网络连接
lsof -i -N

Nginx "Too many open files" 排查：

bash
# 看当前 limit
lsof -p <nginx_pid> | wc -l
# 看系统级限制
cat /proc/sys/fs/file-nr

3.3 curl — HTTP 调试 ​

bash
# 基础请求
curl -v https://api.example.com/users

# 带 Header
curl -H "Authorization: Bearer xxx" https://api.example.com/profile

# POST JSON
curl -X POST -H "Content-Type: application/json" \
     -d '\''{"name": "tom"}'\'' https://api.example.com/users

# 下载并查看响应头
curl -I https://example.com

# 超时控制
curl --connect-timeout 5 --max-time 10 https://example.com

# 跳过证书验证（测试环境）
curl -k https://self-signed.example.com

# 查看完整 HTTP 过程
curl -v https://example.com 2>&1 | grep -E "< HTTP|Location:"

线上调试实战：

bash
# 1. 检查接口是否可达
curl -I https://api.example.com/health

# 2. 检查 DNS 解析
curl -v https://api.example.com 2>&1 | grep "Trying|Connected"

# 3. 检查证书
openssl s_client -connect api.example.com:443 -servername api.example.com

# 4. 检查响应时间
curl -w "time_namelookup: %{time_namelookup}s\ntime_connect: %{time_connect}s\ntime_total: %{time_total}s\n" \
     -o /dev/null -s https://api.example.com

3.4 ping / traceroute — 路由与延迟 ​

bash
# 检测连通性
ping -c 4 api.example.com

# 路由追踪
traceroute api.example.com   # Linux
tracert api.example.com      # Windows

# 查看 MTU
ping -M do -s 1400 api.example.com

四、日志分析 ​

4.1 tail — 实时日志 ​

bash
# 实时滚动
tail -f /var/log/nginx/access.log

# 实时 + 行数
tail -n 100 -f /var/log/nginx/access.log

# 过滤关键词
tail -f /var/log/app.log | grep ERROR

# 排除关键词
tail -f /var/log/app.log | grep -v HEALTH_CHECK

4.2 grep — 日志搜索 ​

bash
# 搜索关键词
grep "ERROR" /var/log/app.log

# 搜索并显示前后 3 行（上下文）
grep -C 3 "ERROR" /var/log/app.log

# 忽略大小写
grep -i "error" /var/log/app.log

# 正则匹配
grep "status:\s*[45][0-9]{2}" /var/log/app.log

# 搜索多个关键词
grep -E "ERROR|WARN" /var/log/app.log

# 统计匹配行数
grep -c "ERROR" /var/log/app.log

# 搜索 gzip 压缩日志
zgrep "ERROR" /var/log/app.log-20231010.gz

4.3 awk — 结构化日志分析 ​

Nginx 访问日志分析：

bash
# 统计 HTTP 状态码
awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -rn

# 统计 TOP 10 IP
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# 统计 QPS（每秒请求数）
awk '{print $4}' /var/log/nginx/access.log | cut -d: -f2 | sort | uniq -c | sort -rn | head -10

# 统计平均响应时间（需要带响应时间字段的日志格式）
awk -F'"' '{print $NF}' access.log | awk '{sum+=$1; count++} END {print sum/count "ms"}'

JSON 日志分析：

bash
# 提取 error 字段（如果日志是 JSON 格式）
grep "ERROR" app.log | jq '.error' | sort | uniq -c

# 统计各错误类型数量
grep "ERROR" app.log | jq -r '.type' | sort | uniq -c | sort -rn

4.4 find — 查找日志文件 ​

bash
# 找 7 天前的日志
find /var/log -name "*.log" -mtime +7

# 找大于 100MB 的日志
find /var/log -size +100M

# 查找并批量删除（删除前先确认）
find /var/log -name "*.log" -mtime +30 -ls

五、权限与用户 ​

5.1 chmod / chown ​

bash
# 数字权限 r=4 w=2 x=1
chmod 755 /path/to/script.sh   # rwxr-xr-x
chmod 644 /path/to/file.txt    # rw-r--r--
chmod +x /path/to/script.sh   # 添加执行权限

# 递归修改
chown -R ubuntu:ubuntu /var/www/html

# 只改文件所有者
chown ubuntu /path/to/file

常见权限问题排查：

bash
# nginx 无权限读静态文件
ls -la /var/www/html/
# → 检查是否有 www-data 用户可读

# Node 写文件权限
ls -la /var/log/app/
# → 确保 Node 进程用户有写权限

5.2 sudo / su ​

bash
# 以 root 执行
sudo systemctl restart nginx

# 切换用户
sudo su - ubuntu

# 以特定用户运行命令
sudo -u ubuntu pm2 list

六、性能辅助 ​

6.1 uptime — 负载 ​

bash
uptime
# 10:30:15 up 42 days,  3:22,  2 users,  load average: 0.52, 0.48, 0.51

解读：load average 是 1/5/15 分钟平均负载。超过 CPU 核数说明有积压。

6.2 iostat — I/O ​

bash
# 每 2 秒报告一次
iostat -x 2

# 看具体磁盘
iostat -x sda 2

关键字段：%util > 80% 说明 I/O 饱和。

6.3 strace — 追踪系统调用（高级） ​

bash
# 追踪进程系统调用
strace -p <PID>

# 追踪并输出到文件（生产慎用！）
strace -p <PID> -f -e trace=write -o /tmp/trace.log

七、实战场景 ​

场景 1：Node.js 服务 CPU 100% 排查 ​

bash
# 1. 确认哪个进程
top -o %CPU

# 2. 找到 PID，看子进程
ps auxf | grep <PID>

# 3. 看详细调用
strace -p <PID> -c   # 统计系统调用
strace -p <PID> -f   # 跟踪子进程

# 4. Node 专用：V8 采样
kill -USR2 <PID>   # 触发 V8 采样
# 然后从 Node 日志或 --prof 输出看热点

场景 2：内存持续增长（内存泄漏） ​

bash
# 1. 每分钟记录 RSS
while true; do
  date; ps -o pid,rss,vsz -p <PID>;
  sleep 60;
done >> /tmp/memory.log

# 2. 观察增长趋势

场景 3：服务器无法连接 ​

bash
# 1. 本地网络
ip addr
ip route

# 2. 端口是否监听
ss -tlnp | grep :80

# 3. 防火墙
sudo iptables -L -n
sudo iptables -L -n | grep DROP

# 4. 端口连通性
nc -zv api.example.com 443

# 5. DNS 解析
