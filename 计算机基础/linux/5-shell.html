Linux Shell 脚本基础 ​

Shell 是 Linux 内核与用户之间的命令行接口，既可以交互执行命令，也可以编写脚本批量执行。前端工程师掌握 Shell 脚本，能显著提升部署、自动化和排查效率。

一、常见 Shell 类型 ​

Linux 启动后显示的默认程序就是 Shell，常见类型：

Shell说明
sh（Bourne Shell）最古老，所有 Unix/Linux 都支持
bash（Bourne Again Shell）sh 的增强版，Linux 默认，功能最全
zshbash 的进阶版（主题、插件生态好，macOS 默认）
fish交互友好，自动补全强大，但脚本语法不兼容 bash
bash
# 查看当前 shell
echo $SHELL
# /bin/bash

# 查看所有可用 shell
cat /etc/shells

# 切换 shell
bash        # 进入 bash 子 shell
zsh         # 进入 zsh 子 shell
exit        # 退出当前 shell

二、Shell 变量 ​

2.1 变量基础 ​

bash
# 定义变量（等号两侧不能有空格）
NAME="微尘"
VERSION=1.0

# 使用变量
echo $NAME
echo "${NAME}_v${VERSION}"

# 只读变量
readonly CONST="固定值"
CONST="new"   # 报错：bad substitution

# 删除变量
unset NAME

2.2 环境变量 ​

bash
# 查看所有环境变量
env
printenv

# 查看特定变量
echo $PATH
echo $HOME
echo $USER

# 设置临时环境变量（当前 shell 有效）
export NODE_ENV=production

# 永久生效（写入配置文件）
echo '\''export NODE_ENV=production'\'' >> ~/.bashrc
source ~/.bashrc

2.3 特殊变量 ​

变量含义
$0脚本自身文件名
$1-$9第 1-9 个参数
$#参数个数
$@所有参数（每个独立）
$*所有参数（合并为一个字符串）
$$当前脚本 PID
$?上一条命令的退出码（0=成功，非0=失败）
bash
# 脚本中使用
# ./deploy.sh production 8080
echo "第1个参数: $1"      # production
echo "参数个数: $#"      # 2
echo "所有参数: $@"      # production 8080
echo "上一个命令退出码: $?" # 0

四、循环 ​

4.1 for 循环 ​

bash
# 遍历列表
for pkg in nginx node python; do
  echo "安装 $pkg..."
  which $pkg || echo "$pkg 未找到"
done

# 遍历文件
for file in *.log; do
  echo "处理: $file"
  gzip "$file"
done

# C 风格 for 循环
for ((i=1; i<=5; i++)); do
  echo "第 $i 次"
done

# 遍历命令输出
for line in $(cat names.txt); do
  echo "处理: $line"
done

# 遍历目录
for dir in /var/log/*/; do
  echo "日志目录: $dir"
done

4.2 while 循环 ​

bash
# 读取文件行
while IFS= read -r line; do
  echo "行: $line"
done < file.txt

# 条件循环
count=1
while [ $count -le 10 ]; do
  echo "计数: $count"
  count=$((count + 1))
done

# 无限循环（Ctrl+C 退出）
while true; do
  curl -s http://localhost:3000/health > /dev/null 2>&1
  if [ $? -ne 0 ]; then
    echo "$(date): 服务异常，重新启动..."
    pm2 restart api
  fi
  sleep 5
done

五、函数 ​

5.1 函数定义与调用 ​

bash
# 定义函数
greet() {
  echo "你好, $1"
}

# 调用
greet "张三"
# 输出：你好, 张三

# 返回值（只能是退出码 0-255）
check_service() {
  if systemctl is-active --quiet nginx; then
    return 0
  else
    return 1
  fi
}

if check_service; then
  echo "Nginx 运行正常"
else
  echo "Nginx 未运行"
fi

5.2 函数参数与局部变量 ​

bash
backup_file() {
  local src="$1"          # 局部变量
  local dest="$2"

  if [ -f "$src" ]; then
    cp "$src" "$dest"
    echo "备份成功: $src -> $dest"
  else
    echo "文件不存在: $src" >&2  # 错误输出
    return 1
  fi
}

backup_file "/etc/nginx/nginx.conf" "/backup/nginx.conf.bak"

六、实战脚本 ​

6.1 自动部署脚本 ​

bash
#!/bin/bash
# deploy.sh — 前端项目自动部署

set -euo pipefail   # 遇到错误、变量未定义、管道失败立即退出

APP_DIR="/var/www/html"
BACKUP_DIR="/backup"
RELEASE_DIR="/var/www/releases"
TIMESTAMP=$(date +%Y%m%d%H%M%S)

# 颜色输出
RED='\033[0;31m'
GREEN='\033[0;32m'
NC='\033[0m'

log() { echo -e "${GREEN}[$(date)]${NC} $1"; }
error() { echo -e "${RED}[$(date)] ERROR:${NC} $1" >&2; }

# 检查运行用户
if [ "$EUID" -ne 0 ]; then
  error "请用 sudo 运行此脚本"
  exit 1
fi

# 构建
log "开始构建..."
cd /home/ubuntu/project
npm run build

# 备份旧版本
if [ -d "$APP_DIR" ]; then
  log "备份旧版本到 $BACKUP_DIR/$TIMESTAMP..."
  mv "$APP_DIR" "$BACKUP_DIR/$TIMESTAMP"
fi

# 部署新版本
log "部署新版本..."
cp -r dist "$APP_DIR"
chown -R www-data:www-data "$APP_DIR"

# 重启服务
log "重启服务..."
pm2 restart api || pm2 start npm --name api -- start

log "部署完成！"

6.2 日志清理脚本 ​

bash
#!/bin/bash
# clean-logs.sh — 清理旧日志

LOG_DIR="/var/log/project"
DAYS=30

echo "查找 ${DAYS} 天前的日志文件..."
find "$LOG_DIR" -name "*.log" -mtime +$DAYS

read -p "确认删除以上文件？(y/n) " confirm
if [ "$confirm" = "y" ]; then
  find "$LOG_DIR" -name "*.log" -mtime +$DAYS -delete
  echo "已删除旧日志文件"
else
  echo "取消操作"
fi

七、脚本执行方式 ​

bash
# 方式 1：作为可执行文件（需加 shebang + 执行权限）
chmod +x deploy.sh
./deploy.sh

# 方式 2：用 bash 解释器执行
bash deploy.sh
sh deploy.sh   # 注意：sh 不支持 bash 特有语法

# 方式 3：source（当前 shell 执行，用于加载环境）
source ~/.bashrc
. ./env.sh       # 短格式 source

shebang 行（脚本第一行，指定解释器）：

bash
#!/bin/bash
#!/usr/bin/env bash   # 更可移植（自动找 bash 路径）
