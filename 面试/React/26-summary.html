React 常见问题与解法 ​

这一页是一份排查手册:「React 跑起来不对」时,先在这里按现象定位。 各个 API 的原理与源码在后面的专题页,这里不重复讲原理,只讲现象 → 原因 → 解法。

一、怎么用这一页 ​

遇到 React 的怪问题,按这个顺序查:

1. 先定位是哪一类    → 第二节的分类
2. 对照速查表        → 第三节:现象 / 原因 / 解法 / 专题页
3. 去专题页看原理    → 第四节索引,点对应链接

通用排查顺序:先看控制台警告 → 再看 React DevTools Profiler → 再看 DevTools 的 React Profiler 组件树 → 最后读代码。

二、五类高频问题 ​

2.1 渲染类 ​

现象根因解法
setState 后 console.log 还是旧值state 更新是异步批处理的,不是立刻生效用函数式更新 setX(prev => prev + 1);要读最新值用 useRef
组件不重渲染改的是对象/数组的引用,React 比较引用发现没变不可变更新:展开运算符、immer
无限渲染useEffect 里 setState,依赖数组每次都是新引用依赖数组写原始值;或把 setState 移到事件里
useEffect 跑两次React 18 StrictMode 故意双调用暴露副作用副作用必须幂等 + 有清理函数
父组件渲染,子组件也跟着渲染props 或 context 变了memo + 稳定的 props;或状态下沉

2.2 闭包类 ​

症状:定时器 / 事件回调里拿到的 state 永远是初始值。

根因:每次渲染都会生成一个新的函数,函数捕获了当次渲染的 state;定时器注册时捕获的那份会一直存在。

三种解法:

js
// ① 依赖数组带上它(最常用)
useEffect(() => {
  const id = setInterval(() => doSomething(count), 1000)
  return () => clearInterval(id)
}, [count])

// ② 用 ref 存最新值(回调不需要重建时)
const countRef = useRef(count)
countRef.current = count

// ③ 读最新值用函数式 setState
setCount(prev => prev + 1)

2.3 状态类 ​

问题判断标准
该用 useState 还是 useRef需要触发渲染 → state;只是保存、不需要渲染 → ref
对象要不要整体替换setObj({ ...obj, a: 1 }) 会触发渲染;直接 obj.a = 1 不会
状态放哪一层谁能修改就放谁那层;全局共享才提到 store
派生值要不要存 state不要,直接 useMemo 或直接算,存 state 会多一份同步负担

2.4 列表类 ​

症状:删除 / 排序列表后,输入框里的内容串到了别的行。

根因:key 用错了。用 index 时,React 按位置匹配节点,位置没变就复用旧组件,state 就串了。

解法:key 用稳定唯一的业务 id。如果列表是完全静态、永不重排的,index 也不会出问题。

2.5 性能类 ​

症状先查解法
memo 组件还是重渲染props 是不是每次都传了新对象/新函数稳定引用:useMemo / useCallback / 模块级常量
Context 一改全树重渲染value 是不是每次新建value 用 useMemo;或按更新频率拆多个 Provider
长列表卡顿DOM 节点数虚拟列表;content-visibility: auto
输入卡顿有没有同步重计算useMemo / useDeferredValue

2.6 清理类(内存泄漏) ​

js
useEffect(() => {
  const id = setInterval(tick, 1000)      // ← 定时器
  const ws = new WebSocket(url)           // ← 连接
  window.addEventListener('resize', onR)  // ← 监听
  return () => {
    clearInterval(id)
    ws.close()
    window.removeEventListener('resize', onR)
  }
}, [])

缺清理 = 泄漏:组件卸载后回调还在跑,轻则报「setState on unmounted」,重则内存持续上涨。

2.7 SSR 类 ​

症状:控制台报 Hydration failed。

根因:服务端渲染出的 HTML 与客户端首次渲染结果不一致。常见原因:随机值、时间戳、window 判断、locale/时区差异、浏览器插件注入。

解法:把不稳定的内容延迟到客户端(useEffect 里再渲染),或用 suppressHydrationWarning 局部豁免。

📝 小结 ​

  • 这一页是排查手册,不是 API 手册:按「现象 → 原因 → 解法」组织,每个问题都指向对应专题页。
  • React 的怪问题几乎都落在五类里:渲染(异步批处理与引用)、闭包(捕获旧 state)、列表(key 用错)、清理(副作用没取消)、SSR(两端不一致)。
  • 三个最值得记住的根因:setState 是异步的、对象/数组要换引用、定时器与事件回调会捕获旧 state。
  • 排查动线:控制台警告 → React DevTools → Profiler 录制 → 读代码。
  • 面试话术:每个问题按「现象 → 原因 → 解法」讲,并能延伸到底层机制(调度与闭包),这比罗列结论有说服力;准备 2~3 个自己真踩过的坑最可信。
