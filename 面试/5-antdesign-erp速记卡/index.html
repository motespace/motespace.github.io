📌 二、Ant Design 必背 15 问

Section titled “📌 二、Ant Design 必背 15 问”

详细版：Ant Design 实战

# 问题 一句话答案
1 Form 为什么要 useForm？ 拿到实例才能在组件外 getFieldValue/setFieldsValue/validateFields/resetFields；不传就是“非受控 Form”，外部只能靠 onFinish 拿值
2 Form 有哪几个关键 API？ getFieldValue/getFieldsValue/setFieldValue/setFieldsValue/resetFields/validateFields/getFieldError/isFieldsTouched
3 字段联动的标准写法？ Form.useWatch('a', form) 订阅 + useEffect 联动；或 Form.Item shouldUpdate 精确控制重渲染范围
4 联动的坑？ 隐藏字段的旧值会被一起提交 → 手动 setFieldValue(f, undefined) 或 preserve={false}；useWatch([]) 订阅整个表单会全量 re-render
5 动态增删字段？ Form.List（fields/add/remove/move），新增项必须给初值
6 Table 必写的属性？ rowKey（不写会选中错乱）、columns（用 useMemo 稳定引用）、scroll.x（否则固定列不生效）
7 Table 排序筛选怎么做？ onChange(pagination, filters, sorter, extra) 一次拿全，真实过滤排序交给后端；后端排序字段要白名单，防注入
8 1 万行表格怎么办？ ERP 首选后端分页（要跳页/导出/总数）；确需全量用 antd v5.9+ virtual + scroll={{x,y}}
9 列多/列少分别怎么处理？ 列多：scroll.x + 固定首尾列 + ellipsis；列少：用 span 合并栅格布局，别硬凑
10 主题定制怎么做？ Token 三层：全局 token / 组件 token / algorithm（darkAlgorithm）；ConfigProvider theme={{ token, components }}
11 多租户换肤？ 品牌色后端下发 → 运行时改 token + 注入 CSS 变量给非 antd 部分用
12 message 主题不生效？ 用了静态 message.info()，它脱离 ConfigProvider 上下文 → 根节点包 &lt;App&gt;，用 App.useApp()
13 antd Form vs RHF+Zod？ antd 受控(store 订阅)、开箱即用、布局强；RHF 非受控、性能好、schema 可前后端共享。ERP 统一 antd，超大单表单用 RHF
14 二次封装怎么做？ 只封装有业务语义的（StatusTag/PageTable/BizForm）；pages → business → ui → antd 依赖单向；透传 className/style/ref；自带 loading/empty/error 三件套
15 Element UI 也用过吗？ Vue 生态的对应物，思路一致（数据驱动 + 插槽扩展 + 主题变量覆盖）；React 岗主答 antd

三个一定要主动说的坑（面试官爱追问）：① 静态 message 丢主题；② 隐藏字段旧值被提交；③ Table 没写 rowKey / columns 没 memo。

📌 三、ERP / CRM 场景必背 12 问

Section titled “📌 三、ERP / CRM 场景必背 12 问”

详细版：ERP / CRM 业务场景题

# 场景 关键答案
1 列表组合筛选很慢 筛选全交后端 + 防抖 300ms + AbortController 取消竞态 + 条件写进 URL query + 后端分页
2 Excel 批量导入 5 万行 SheetJS 解析放 Web Worker → 表头映射 → 行级预校验 → 批量查重（不要一行一请求）→ 每批 500~1000 行提交 → 失败行导出成错误报告让用户改后重传 → batchId 幂等
3 导出 10 万行崩了 前端生成必崩。走服务端异步导出：传筛选条件拿 taskId → 轮询/推送 → OSS 签名下载地址 → 下载中心。前端兜底：超 1 万行直接转后台任务
4 CSV 中文乱码 文件头加 UTF-8 BOM \uFEFF；或干脆导 xlsx
5 三种客户字段不一样 Schema 驱动动态表单：字段元数据后端下发，visible + useWatch 做联动，custom 类型塞业务组件
6 审批流状态管理 前端用状态机（TRANSITIONS 映射表）而不是一堆 if；按钮按 can(action, status) 渲染；驳回必填意见；最终状态以后端返回为准；多人同时审批由后端校验状态机
7 两人同时改一条记录 乐观锁 version：提交带 version，后端 WHERE id=? AND version=?，影响 0 行 → 409 → 提示刷新或字段级合并
8 不同角色看到不同数据 行级权限必须后端做（前端过滤是假过滤，接口已泄露）；列级脱敏后端做；前端只管 scope 切换 + 按钮级权限 + 数据范围提示
9 列表和详情数据不一致 TanStack Query 双缓存天然不一致 → invalidate / setQueryData 精准更新 / WebSocket 推送；标签页切回前台时 invalidate
10 切换租户要清什么 queryClient.clear() + store + localStorage + 字典/菜单/权限 + WebSocket 重连 + AbortController 取消在途请求；更稳：直接整页跳转
11 动态表单（配置型） Schema 下发 + 字段级组件拆分（各自 useWatch）+ 校验规则用 Zod 动态编译；性能坑是订阅整个表单
12 多人协作/离线编辑 CRDT（Yjs）/ 操作日志重放；乐观锁只解决“最后写入者赢”

📌 四、监控与排障必背 6 问

Section titled “📌 四、监控与排障必背 6 问”

详细版：异常监控与错误上报 · 线上问题定位与降级

# 问题 关键答案
1 线上错误怎么发现？ window.onerror（同步 + 资源错误，捕获阶段）+ unhandledrejection（异步）+ React ErrorBoundary（渲染）→ 上报 Sentry/自建 → 按分级告警
2 上报要带什么字段？ message/stack/componentStack + URL/路由 + userId/租户 + release 版本 + 设备浏览器 + 最近操作路径 breadcrumb。没有上下文的上报等于没上报
3 生产为什么配 SourceMap？ 压缩后堆栈不可读。构建生成 .map 上传监控平台 → 线上错误能还原到源码行。上传完必须从静态服务器删掉，否则源码泄露
4 ErrorBoundary 能捕获哪些？ 只能捕获 React 渲染树内、渲染/生命周期阶段的错误；事件回调和异步回调不会冒泡，要自己 try/catch
5 用户说“页面打不开”怎么查？ ① 确认影响面 ② 看监控（错误率/接口成功率/资源 404/白屏率）③ 按 release 聚合 ④ 用操作轨迹复现 ⑤ 先止损（回滚/关开关/降级）再定位 ⑥ 复盘出带 owner 的改进项
6 前端怎么降级？ 功能开关（按租户/百分比灰度）+ 数据降级（缓存兜底、4xx 不重试）+ 渲染降级（ErrorBoundary 局部兜底不全页白屏）+ 极端情况按顺序关功能。前提：每条降级路径都有测试

📌 五、TypeScript 必背 6 问

Section titled “📌 五、TypeScript 必背 6 问”

详细版：进阶面试题 Q11-Q25

# 问题 关键答案
1 泛型组件怎么写？ function List&lt;T&gt;(props)；.tsx 里箭头函数要写 <T,> 否则被当 JSX
2 泛型 Hook 怎么写？ 泛型放调用点推导：queryFn: () => request&lt;User&gt;(url)，调用方不用再断言
3 satisfies vs as const？ satisfies 校验结构同时保留字面量类型；as const 保留字面量但不校验。做路由表/权限点常量用 satisfies
4 穷尽检查怎么做？ switch + default: assertNever(x)，x: never；新增状态时编译期报错
5 unknown vs any？ 外部数据一律 unknown 再收窄；any 会传染整个表达式
6 什么时候用类型断言？ 只在你比编译器更清楚类型时；更好的做法是类型守卫 x is T 或 Zod 校验

📝 小结

Section titled “📝 小结”
  • 这是一张针对中后台 + ERP/CRM 岗位的临阵卡:Ant Design 15 问、ERP/CRM 12 问、监控排障 6 问、TypeScript 6 问。

  • AI 差异化打法:讲「我用 AI 把某个流程压缩了多少」,而不是「我会用 Copilot」。
  • 反问环节挑 2~3 个技术/业务问题(团队规模、技术栈、当前最大挑战),不要问薪资。
  • 红线:不夸大、不贬低前公司、不说「我不擅长」这类致命表述。
  • 应急话术:遇到不会的问题,先说思路与推理方向,再诚实说明不确定。
