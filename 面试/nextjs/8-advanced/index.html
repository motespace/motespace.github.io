Q23: Next.js 如何处理错误？

Section titled “Q23: Next.js 如何处理错误？”

答案：

三层错误处理：

  1. error.tsx：捕获子路由错误
  2. global-error.tsx：根错误边界
  3. not-found.tsx：404 页面

Q25: Server Components 能使用 Context 吗？

Section titled “Q25: Server Components 能使用 Context 吗？”

答案：

不能直接在 Server Components 中使用 Context。

但有以下替代方案：

  1. Server Components 传递数据给 Client Components
  1. 使用 URL 参数
  1. 使用 Cookies

Next.js 怎么防止 CSRF 攻击?

Section titled “Next.js 怎么防止 CSRF 攻击?”

答案：三层防护。

关键:SameSite=Lax 是最省事的一层 —— 跨站的 POST 请求不会带 Cookie,天然免疫。

Next.js 里怎么做权限控制?

Section titled “Next.js 里怎么做权限控制?”

答案：三层配合,前端隐藏只是体验,服务端校验才是安全边界。

关键:不要只在客户端判断角色。接口必须独立校验,否则改个请求参数就能越权。

📝 小结

Section titled “📝 小结”
  • Q23 错误处理:error.tsx(客户端组件的错误边界)、not-found.tsx + notFound()、global-error.tsx、未捕获异常用 instrumentation.ts 上报。
  • Q24 国际化:[locale] 动态路由段 + middleware 检测语言并重定向;文案按语言分包;Intl 处理日期数字;SEO 用 alternates.languages。
  • Q25 Server Components 能用 Context 吗?只能用 Server Context(不触发客户端渲染),不能使用 React 客户端 Context;跨边界传值要用 props 或 children。
  • CSRF 防护:Server Actions 自带 Origin 校验与 SameSite Cookie;自定义 API Route 要自己做 Token + Origin 校验。
  • 权限控制:中间件做粗粒度拦截,Server Component / Route Handler 内做数据级鉴权,前端隐藏只是展示层。
  • 面试加分:能讲清「中间件与数据层鉴权为什么都要做」。
