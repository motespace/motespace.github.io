基础概念

Q1: Next.js 是什么？有什么特点？

Section titled “Q1: Next.js 是什么？有什么特点？”

答案：

Next.js 是一个基于 React 的全栈框架，主要特点：

  • 多种渲染模式：SSR、SSG、ISR、CSR
  • App Router：基于文件系统的路由系统，支持嵌套布局
  • Server Components：默认服务端渲染，减少客户端 JS
  • API Routes：快速创建 API 端点
  • 开箱即用：TypeScript 支持、CSS Modules、Tailwind、自动构建优化
  • 图像优化：next/image 自动优化图片
  • 字体优化：next/font 自动优化字体加载

Q2: App Router 和 Pages Router 的区别？

Section titled “Q2: App Router 和 Pages Router 的区别？”

答案：

特性 App Router Pages Router
发布时间 Next.js 13 Next.js 9
路由基础 app/ 目录 pages/ 目录
组件默认 Server Components Client Components
布局 layout.tsx 嵌套布局 _app.tsx 单层布局
数据获取 async/await getStaticProps 等
动态路由 generateStaticParams getStaticPaths
样式 支持更多方案 主要 CSS Modules
Server Components ✅ 支持 ❌ 不支持

Q3: 什么是 Server Components？有什么优势？

Section titled “Q3: 什么是 Server Components？有什么优势？”

答案：

Server Components 是在服务端渲染的 React 组件。

优势：

  1. 减少客户端 bundle：组件代码不会发送到客户端
  2. 直接访问服务端资源：数据库、文件系统
  3. 更好的 SEO：HTML 在服务端生成
  4. 减少网络往返：数据获取靠近数据源
  5. 自动代码分割：只需要加载当前页面需要的组件

Next.js 的核心概念有哪些?

Section titled “Next.js 的核心概念有哪些?”

答案：

概念 说明
App Router / Pages Router 两套路由体系,App Router 是 13+ 的默认
Server / Client Components 服务端组件不打包 JS 到客户端,客户端组件才带 'use client'
Server Actions 服务端函数,可直接作为表单 action 调用
Route Handlers app/api/*/route.ts 写的 REST 接口
Middleware Edge Runtime 运行的请求拦截器
Rendering 模式 SSG / SSR / ISR / CSR 可按路由选择

一句话:Next.js 就是「React + 一套约定好的渲染与数据获取范式」,约定带来了 SEO、路由、部署的默认解法。

为什么用 Next.js 而不是纯 React SPA?

Section titled “为什么用 Next.js 而不是纯 React SPA?”

答案：

维度 纯 React SPA Next.js
首屏 白屏等 JS 下载执行 SSR/SSG 直接出 HTML
SEO 需要额外 SSR,配置复杂 默认支持,metadata 直接配
路由 自己装 react-router 内置,支持嵌套路由、布局、加载态
数据获取 useEffect + SWR/Query 服务端直接取数,或 Server Actions 变更数据
部署 纯静态托管即可 需要 Node 环境(SSG 除外)
首包体积 全部逻辑进客户端 服务端逻辑不进包

什么时候还用 SPA? 完全后台系统(不需要 SEO)、或者需要复杂客户端状态(纯 CSR 交互密集)。这时用 Vite + React 也完全合理。

📝 小结

Section titled “📝 小结”
  • Q1 Next.js 是React 的全栈框架:内置路由、SSR/SSG/ISR、数据获取、API 路由、图片优化、构建与部署。
  • Q2 App Router vs Pages Router:App Router 基于 RSC + Server Actions,数据获取在服务端组件里 await;Pages Router 用 getServerSideProps/getStaticProps 取数。
  • Q3 Server Components:组件在服务端渲染且不打包进客户端,能直接访问数据库与内部服务,减少客户端 JS;限制是不能用 state/effect/浏览器 API。
  • 核心概念:路由约定(app/ 目录即路由)、RSC 与 Client Component 边界、缓存与再验证、Metadata API、Middleware。
  • 面试话术:一句话「Next.js 的价值在于把「数据获取 + 渲染」都放在服务端做,再把交互部分下发到客户端」。
