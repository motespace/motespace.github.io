Q7: Service Worker 缓存策略有哪些？

Section titled “Q7: Service Worker 缓存策略有哪些？”

答案：

策略 说明 适用场景
Cache First 先缓存，失败再网络 静态资源、SDK
Network First 先网络，失败再缓存 频繁更新的数据
Stale While Revalidate 返回缓存，后台更新 变化频率适中的资源
Network Only 只用网络 实时数据
Cache Only 只用缓存 完全离线

Q8: 前端性能优化 checklist？

Section titled “Q8: 前端性能优化 checklist？”

答案：

加载阶段：

  • 压缩 JS/CSS/图片
  • 启用 Tree Shaking
  • 代码分割、路由懒加载
  • 预加载关键资源
  • 使用 CDN
  • 强缓存 + 分版本文件名

渲染阶段：

  • Critical CSS 内联
  • 非关键 CSS 异步加载
  • 图片懒加载
  • 字体优化

运行时：

  • 事件防抖节流
  • 长列表虚拟滚动
  • 减少重排重绘
  • Web Worker 处理重任务

监控：

  • Core Web Vitals 埋点
  • 性能指标上报
  • 异常监控
  • 真实用户监控（RUM）

📝 小结

Section titled “📝 小结”
  • 七个场景覆盖性能优化的主战场:首屏、长列表、高频交互、骨架屏、WebSocket、高并发、Service Worker 缓存。
  • 首屏:资源瘦身与内联关键 CSS、预加载关键资源、路由懒加载、CDN、骨架屏;目标是提升 LCP。
  • 长列表:虚拟滚动 + 固定行高或高度缓存,配合 content-visibility 与分页加载。
  • 高频交互:节流防抖、requestAnimationFrame 批处理、避免同步布局读写、用 CSS transform 走合成层。
  • WebSocket:心跳保活、断线重连(指数退避)、消息合并与节流渲染、二进制协议、只渲染可视区数据。
  • 高并发:请求合并与去重、虚拟滚动、Worker 处理计算、避免全局状态过大。
  • Service Worker 策略:Cache First(静态)、Network First(接口)、Stale While Revalidate(折中)。
  • 面试加分:每个场景都带优化前后的数字。

🔗 同知识点:方法论与监控 — 体系讲解:性能优化方法论:Measure → Profile → Optimize → Verify · 性能监控体系:从 SDK 到看板
