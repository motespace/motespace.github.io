Webpack 的构建流程?

Section titled “Webpack 的构建流程?”

答案：三个阶段。

面试表达:「Webpack 本质上是从 entry 出发的递归依赖遍历,每个模块经过 Loader 转换变成 JS,依赖关系被记录成依赖图,最后在 Seal 阶段把依赖图划分成 chunk 并优化输出。」

对比 Vite:Vite dev 阶段不做这个过程,浏览器要哪个模块就转译哪个,启动快一个量级;生产阶段才用 Rollup 走类似流程。

Loader 和 Plugin 的区别?

Section titled “Loader 和 Plugin 的区别?”

答案：

Loader Plugin
作用对象 单个文件 整个构建过程
输入输出 source → source 挂钩 webpack 生命周期
典型用途 把非 JS 文件转成 JS 注入能力、修改产物

口诀:处理文件内容 → Loader;介入构建流程 → Plugin。

常见 Loader:css-loader(把 CSS 转成 JS 模块)、style-loader(把 CSS 注入 DOM)、babel-loader / swc-loader(转译 TS/JSX)、file-loader / asset modules(处理图片字体)。

常见 Plugin:HtmlWebpackPlugin(生成 index.html)、MiniCssExtractPlugin(抽离 CSS 成文件)、DefinePlugin(编译期常量替换)、CopyWebpackPlugin(拷贝静态文件)、TerserPlugin(压缩)。

📝 小结

Section titled “📝 小结”
  • Q23 构建提速:持久化缓存、并行(线程池/多进程)、缩小 loader 作用范围、babel-loader 换 swc/esbuild、跳过 node_modules、devtool 生产关掉、增量构建。
  • Q24 Tree Shaking 原理:基于 ESM 静态结构做可达性分析,标记未使用的导出并 DCE;依赖 sideEffects: false 才能删整个模块;CJS 无法摇树。
  • Q25 分包策略:按 splitChunks 的 chunks/cacheGroups(node_modules 单独抽 vendor)、按路由动态 import()、按业务域拆分;配合预加载与 CDN。
  • 构建流程:解析配置 → 建立依赖图 → loader 转换 → 模块 → chunk → 优化 → 输出。
  • Loader vs Plugin:loader 处理单个模块的内容转换,plugin 介入编译生命周期并能操作构建产物。
  • 面试加分:能用 webpack-analyzer 指出体积大头并给出替换方案。
