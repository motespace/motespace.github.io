React.memo 和 useMemo 有什么区别?

Section titled “React.memo 和 useMemo 有什么区别?”

答案：缓存的对象不同。

React.memo useMemo
缓存什么 组件的渲染结果 计算结果
粒度 组件 值
比较方式 浅比较 props 浅比较依赖数组
作用 跳过子组件重渲染 避免重复计算

常见误用:

每次父组件渲染都创建新的 item 对象 → 浅比较失败 → memo 白做。

结论:memo 用来跳过子组件渲染,useMemo 用来缓存昂贵计算。两者都不该无脑用,缓存本身也有成本。

React 18 的并发模式解决了什么问题?

Section titled “React 18 的并发模式解决了什么问题?”

答案：解决「渲染是不可中断的」这个根本限制。

可中断的含义:渲染到一半发现优先级更高的更新(比如用户又输入了一个字),可以丢弃当前工作重新开始,保证输入永远流畅。

API 用途
startTransition 标记为非紧急更新,可被中断
useTransition 拿到 isPending,显示加载态
useDeferredValue 延迟一个值,常用于搜索输入防抖
Suspense 配合并发,数据未就绪时展示 fallback

关键点:并发渲染 ≠ 多线程渲染。JS 仍然在主线程跑,只是「可暂停、可放弃、可恢复」。

📝 小结

Section titled “📝 小结”
  • Q13 避免不必要渲染:React.memo、useMemo/useCallback、状态下沉、Context 拆分与 value 稳定、避免内联对象/函数传给 memo 组件;用 Profiler 定位。
  • Q14 虚拟 DOM:内存中的轻量描述树,渲染 → diff → 提交;价值在于编程模型与批量更新,不是天然更快。
  • Q15 diff 原理:同层比较 + 双指针 + key 识别身份 + 类型不同则重建;React 的简化假设换来 O(n) 常见性能。
  • Q16 代码分割:React.lazy + Suspense、动态 import()、打包器 splitChunk;配合预加载关键 chunk 避免二次等待。
  • memo vs useMemo:memo 比较 props 决定是否重渲染组件,useMemo 缓存计算结果。
  • React 18 并发模式解决的:长任务阻塞主线程、渲染无法被打断、优先级无法区分;通过 Fiber + Lane + Scheduler 实现。
  • 面试加分:讲清「memo 失效的三个常见原因」。
