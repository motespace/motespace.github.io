十二、缓存策略场景题

摘自 场景面试题库

44. HTTP 缓存（强缓存 / 协商缓存）

Section titled “44. HTTP 缓存（强缓存 / 协商缓存）”

场景：项目上线后，用户浏览器一直显示旧版本（即使后端代码已更新），怎么排查和优化？

答案要点：

追问：

  • 怎么强制刷新？→ Ctrl+Shift+R（绕过缓存）/ 加版本号 ?v=2
  • ETag 怎么生成？→ 基于文件内容（大小、修改时间、hash）；分布式系统用唯一 ID
  • 强缓存和协商缓存怎么选？→ 不变资源（带 hash JS）强缓存；HTML / API 协商缓存
  • CDN 缓存了旧资源怎么清？→ CDN 提供刷新接口（阿里云 / CloudFlare / 七牛都支持）

45. Service Worker 离线缓存（PWA）

Section titled “45. Service Worker 离线缓存（PWA）”

场景：用户在地铁里打开 SaaS 后台，网络断了，页面空白。怎么做到离线可用？

答案要点：

追问：

  • Service Worker 怎么调试？→ Chrome DevTools → Application → Service Workers
  • 缓存怎么更新？→ 修改 CACHE_NAME 版本号 + activate 事件清理旧缓存
  • 缓存空间限制？→ Chrome ~6% 硬盘空间；超限会按 LRU 清理
  • 怎么强制刷新？→ self.skipWaiting() + clients.claim() 立即接管

46. IndexedDB / 内存缓存（大数据本地存储）

Section titled “46. IndexedDB / 内存缓存（大数据本地存储）”

场景：商户后台要本地存 100MB 的离线数据（产品列表、客户资料），localStorage 不够用怎么办？

答案要点：

追问：

  • IndexedDB 容量限制？→ 取决于浏览器和硬盘空间，一般 50MB - 几 GB
  • 怎么迁移 schema？→ onupgradeneeded 中处理版本升级
  • LRU 和 LFU 区别？→ LRU（最近最少用） / LFU（最不经常用）；LFU 更准但开销大
  • 缓存一致性问题？→ 加版本号 / 时间戳；接口返回 304 时校验

📝 小结

Section titled “📝 小结”
  • 缓存题要按层级答:内存(JS 变量/Map)→ 浏览器(HTTP 缓存、localStorage、IndexedDB)→ Service Worker(Cache API)→ CDN → 服务端缓存。
  • 策略选择:Cache First(静态资源)、Network First(实时数据)、Stale While Revalidate(折中)、Network Only。
  • 关键问题:缓存key 的设计(含用户与版本)、失效策略(TTL + 版本号 + 主动清除)、多标签页一致性(BroadcastChannel/storage 事件)、离线兜底。
  • 版本与发版:文件名带 content hash 或运行时版本号,发版即失效;sw.js 内容变化触发 update → activate 时清理旧 cache。
  • 敏感数据:用户相关缓存要按用户隔离并在登出时清除。
  • 面试加分:能说清「没有 PWA 时缓存有什么不同」——只剩 HTTP 缓存与浏览器存储,无法做离线与请求拦截。
