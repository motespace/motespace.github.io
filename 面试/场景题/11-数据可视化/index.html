十一、数据可视化进阶场景题

摘自 场景面试题库

40. ECharts 大数据渲染（5 万+ 点）

Section titled “40. ECharts 大数据渲染（5 万+ 点）”

场景：IoT 大屏展示 5 万个传感器历史数据点，ECharts 渲染卡顿、tooltip 响应慢。

答案要点：

追问：

  • ECharts 大数据模式下 tooltip 还能用吗？→ 能，但显示的是采样后的数据（不精确）
  • LTTB 算法能保留特征吗？→ 能（保留波峰波谷），但峰值具体数值不准，需要时查后端
  • 5 万点真实数据怎么查？→ 点击/hover 时调 API 查后端真实值（不存前端）

41. 实时数据帧率控制（30fps vs 60fps）

Section titled “41. 实时数据帧率控制（30fps vs 60fps）”

场景：IoT 大屏 100 个传感器每秒推送一次，setState / setOption 太频繁导致 FPS 掉到 20。

答案要点：

追问：

  • 30fps 和 60fps 怎么选？→ 大屏显示 30fps 就够流畅；交互密集选 60fps
  • 怎么测真实帧率？→ Chrome DevTools Performance → Frames 模式 / Stats.js / 自定义 monitor
  • 数据量太大 WebSocket 消息堆积？→ 客户端按设备聚合订阅 + 服务端只推变化（diff）

42. 大屏自适应（不同分辨率）

Section titled “42. 大屏自适应（不同分辨率）”

场景：IoT 大屏要部署到 1920×1080、2K、4K、超宽屏不同显示器，怎么做适配？

答案要点：

追问：

  • rem 和 vw 哪个好？→ rem 更适合文字（可访问性，可被浏览器放大）；vw 更适合布局
  • scale 方案的坑？→ 鼠标交互位置计算要乘 scale；transform 影响 fixed 定位
  • 怎么保证 4K 屏清晰？→ 用 SVG / 高分图（2x、3x）+ image-set() 自适应

43. WebGL / 3D 大屏（Three.js）

Section titled “43. WebGL / 3D 大屏（Three.js）”

场景：3D 数字孪生大屏（工厂/园区/城市），Three.js 渲染 10 万+ 三角形，怎么优化？

答案要点：

追问：

  • 3D 大屏怎么选型？→ Three.js（生态最丰富） / Babylon.js（微软，更高级） / PlayCanvas（带编辑器）
  • 10 万三角形卡顿怎么排查？→ Spector.js 录制 draw call + Chrome DevTools Performance
  • WebGL 和 Canvas 2D 怎么选？→ 3D 选 WebGL；2D 大量元素选 Canvas 2D（更轻量）
  • 模型加载慢？→ Draco 压缩（-90% 体积）+ LOD + 分片加载

📝 小结

Section titled “📝 小结”
  • 可视化场景题考:选型、复杂数据的表现、交互一致性、性能与可访问性。
  • 选型:ECharts(业务图表)、AntV G6(关系图)、D3(高度定制)、Three.js/WebGL(3D 与海量点)。
  • 真实场景问题:空数据与极值怎么展示、时间序列的聚合与降采样、大量 tooltip 的性能、多图表联动与下钻、图表的可访问性(颜色对比度 + 数据表格替代)。
  • 性能:关闭动画、节流 setOption、大数据采样与 progressive 渲染、Canvas 替代 SVG。
  • 面试加分:能讲「图表和表格的取舍」(需要精确读数用表格,需要趋势用图表),体现产品思维。
