摘自 场景面试题库

17. 如何做技术选型？

Section titled “17. 如何做技术选型？”

场景：领导让你选一个状态管理库（Pinia / Zustand / Redux / MobX），你怎么选？

答案要点：

追问：

  • Pinia 和 Vuex 区别？→ Pinia 去掉 mutations，去掉 modules 嵌套，TS 友好
  • Redux Toolkit 解决了 Redux 什么问题？→ 简化样板代码，内置 immer
  • 不用状态管理库可以吗？→ 小项目可以，跨组件共享状态多了就需要

18. SSR/CSR 怎么选？

Section titled “18. SSR/CSR 怎么选？”

场景：营销活动页（强 SEO）和后台系统（重交互）分别用什么方案？

答案要点：

场景 推荐 理由
营销页（SEO 重要） SSR (Next.js / Nuxt) 首屏直出 HTML，搜索引擎友好
后台系统（重交互） CSR (SPA) 不需要 SEO，首屏可慢，重交互性能好
内容站（博客） SSG (Next.js static / Hexo) 提前构建成静态文件，部署到 CDN
电商详情页 ISR (Next.js) 兼顾性能和实时性（后台更新商品定时重新生成）
App 内嵌 H5 CSR WebView 性能好 + 不需要 SEO

追问：

  • SSR 有什么坑？→ 服务端渲染开销、Node 进程内存、缓存策略复杂
  • Next.js 14 默认什么？→ App Router 默认 SSR，但可以选 SSG/CSR
  • 首屏白屏怎么解决？→ streaming + Suspense + skeleton

19. 性能优化怎么量化？

Section titled “19. 性能优化怎么量化？”

场景：PM 说“页面太慢了”，怎么定位和优化？

答案要点：

追问：

  • 性能优化 ROI 怎么算？→ 用户停留时长 + 转化率
  • 哪些优化是“过度优化”？→ 加载 1KB 图片压成 0.9KB（收益太小）
  • 怎么避免优化回退？→ Lighthouse CI + 性能监控

20. 老项目重构怎么推进？

Section titled “20. 老项目重构怎么推进？”

场景：接手一个 5 年的 React 老项目（200+ 组件，无 TS，无测试），怎么重构？

答案要点：

追问：

  • 怎么推动 TypeScript 迁移？→ 先 .d.ts 声明文件，再改 .ts
  • 重构期间线上故障怎么办？→ Feature Flag + 灰度发布
  • 团队抵触怎么办？→ 用业绩说话（重构后 bug 减少 X%）

📝 小结

Section titled “📝 小结”
  • 综合题考的是拆解能力:把一个模糊需求拆成「信息收集 → 方案对比 → 取舍 → 落地 → 度量」。
  • 典型题目:接手一个烂项目、需求频繁变更、技术选型争议、线上事故、跨团队协作、带新人。
  • 答题框架:先澄清约束(规模/工期/人力/预算)→ 列出方案与代价 → 给出决策与理由 → 说明如何降低风险 → 事后如何验证。
  • 关键是要有明确的结论,不要罗列一堆可能性。
  • 面试加分:能说出「当时我选了 A,后来发现 B 更合适,于是做了 X 的折中」,体现判断与迭代能力。
