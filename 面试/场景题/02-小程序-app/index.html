二、微信小程序 / App 场景题

摘自 场景面试题库

11. 登录流程完整设计

Section titled “11. 登录流程完整设计”

场景：小程序首次打开，怎么拿到用户唯一标识？

答案要点：

追问：

  • code 泄露会怎样？→ 5 分钟过期，只能换一次 openid
  • session_key 怎么用？→ 解密 encryptedData（用户敏感信息）
  • 怎么保持登录态？→ token 存 storage，每次请求带 Authorization header

12. setData 性能优化

Section titled “12. setData 性能优化”

场景：实时数据大屏，每秒更新 100 个数据点，setData 卡顿。

答案要点：

追问：

  • 100 个数据点用 webview 渲染会不会卡？→ 用 canvas 绘制，不用 view
  • 单次 setData 上限？→ 1MB 字符串 / 16MB 单次
  • 实时数据用什么传输？→ WebSocket 推送（不是轮询）

13. 小程序超过 2MB 限制

Section titled “13. 小程序超过 2MB 限制”

场景：小程序主包 2.5MB，超过微信限制怎么办？

答案要点：

追问：

  • 主包还是太大？→ 删掉大图、用 CDN、压缩代码
  • 独立分包 vs 普通分包？→ 独立分包不依赖主包，可以单独加载；普通分包依赖主包
  • 预加载怎么配？→ preloadRule 进入某页面时预加载指定分包

14. 跨端兼容（H5 / 小程序 / App）

Section titled “14. 跨端兼容（H5 / 小程序 / App）”

场景：同一份代码在 H5/小程序/App 上运行，出了问题怎么定位？

答案要点：

追问：

  • 跨端组件差异？→ 优先用 uni-app 提供的统一组件（<view>、<text>）
  • CSS 兼容？→ rpx 自动适配、避免用 viewport 单位
  • 真机调试怎么抓包？→ Charles / Fiddler / mitmproxy

15. IoT 大屏 1000 个传感器点位

Section titled “15. IoT 大屏 1000 个传感器点位”

场景：1000 个 IoT 设备实时上报数据，要在地图上显示状态（正常/异常/离线）。

答案要点：

追问：

  • WebSocket 断了怎么办？→ 心跳检测 + 指数退避重连
  • 数据延迟 5s 怎么办？→ 后端按设备聚合推送（不要每个设备单独推）
  • 地图底图选什么？→ 高德/百度/天地图（带 IoT 标注 API）

16. WebSocket 重连机制

Section titled “16. WebSocket 重连机制”

场景：App 在电梯里网络断了 30 秒，恢复后 WebSocket 自动重连。

答案要点：

追问：

  • 心跳包频率？→ 30 秒一次，3 次没响应认为断开
  • 断线期间的数据丢失？→ 客户端按 seq 记录，服务端补偿
  • 心跳包 vs keepalive？→ TCP keepalive 是协议层，心跳包是应用层（更可控）

📝 小结

Section titled “📝 小结”
  • 小程序 / App 的场景难点集中在:跨端差异、setData 性能、包体积与分包、审核与发布流程、登录与授权。
  • 高频场景:登录授权链路(wx.login → code → 后端换 openid)、支付、分享与拉起、消息推送、离线与弱网、审核拒绝与隐私协议、灰度发布。
  • 答题要点:讲清平台差异如何用条件编译收敛,以及性能问题定位手段(真机 performance、setData 频次监控)。
  • 通用工程答案:统一请求层(域名、拦截器、错误码)、统一登录态管理、埋点与错误上报、分包与预下载策略。
  • 面试加分:说出一条「因为审核/隐私合规我们改了某个设计」的经历,体现落地能力。
