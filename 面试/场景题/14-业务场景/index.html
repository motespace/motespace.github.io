十四、业务场景题（电商 / 订单 / 支付）

摘自 场景面试题库

49. 购物车一致性（多端同步）

Section titled “49. 购物车一致性（多端同步）”

场景：用户 PC 端加购物车，手机 H5 也加购物车，两个端数据不一致。怎么同步？

答案要点：

追问：

  • 怎么保证最终一致性？→ 版本号 + 时间戳 + 服务端是 SSOT
  • 离线操作怎么恢复？→ IndexedDB 队列 + 联网时按时间戳顺序同步
  • 冲突解决怎么选？→ LWW（简单场景）/ CRDT（协同场景）/ 手动（重要数据）
  • WebSocket 断了怎么办？→ 心跳 + 重连 + 重连后拉取服务端最新数据

50. 支付流程（防重 + 回调 + 幂等）

Section titled “50. 支付流程（防重 + 回调 + 幂等）”

场景：用户点“立即支付”，网络慢重复点了 3 次，怎么防重复支付？支付成功后跳转失败怎么补偿？

答案要点：

追问：

  • 为什么前端防重不够？→ 前端可绕过（DevTools 直接调 API），必须后端幂等
  • 幂等键怎么生成？→ UUID / 雪花算法 / 业务唯一标识（订单号）
  • 回调怎么保证可靠？→ 重试机制（指数退避）+ 死信队列 + 人工对账
  • 怎么处理支付中状态？→ 订单状态机明确 + 前端展示 pending 状态

51. 订单状态机（前端可表达的状态流转）

Section titled “51. 订单状态机（前端可表达的状态流转）”

场景：电商订单有 10+ 种状态（待付款/待发货/已发货/已完成/已取消/退款中…），状态流转复杂，前端怎么建模？

答案要点：

追问：

  • 为什么用状态机？→ 明确状态边界 + 防非法跳转 + 可视化
  • XState vs 自写状态机？→ XState 功能强（嵌套、历史状态、可视化）；简单场景自写
  • 前端状态和服务端状态不一致？→ 服务端是 SSOT，前端只是镜像
  • 复杂状态怎么拆？→ 子状态机 / 并行状态机（XState 支持）

📝 小结

Section titled “📝 小结”
  • 业务场景题(电商/订单/支付)考的是业务理解 + 状态机 + 一致性。
  • 核心概念:订单状态机(待付款/待发货/已完成/已取消/退款中)、幂等(支付回调、下单)、对账与补偿(定时任务 + 补偿机制)、库存扣减的并发控制(乐观锁/悲观锁/Redis 预扣)、超卖与秒杀。
  • 前端视角:支付轮询与结果同步、退款流程的状态反馈、优惠券与金额计算的精度问题(用整数分)、防重复提交。
  • 答题框架:画出状态流转 → 说明异常分支(超时、重复回调、并发)→ 给出兜底与对账方案。
  • 面试加分:能讲「支付回调重复到达我们怎么处理」这类真实设计。
