十八、测试策略场景题

摘自 场景面试题库

58. 单元测试策略（Vitest / Jest）

Section titled “58. 单元测试策略（Vitest / Jest）”

场景：项目 0 测试覆盖，怎么从 0 到 1 搭建单元测试体系？

答案要点：

追问：

  • 测试覆盖率多少合适？→ 工具函数 100%，业务组件 60-80%，整体 60%+
  • 怎么从 0 起步？→ 先测工具函数（容易、收益高）→ 再测关键业务组件 → 最后补页面
  • Vitest vs Jest？→ Vitest 更快（基于 esbuild）、Vite 集成好；Jest 生态更成熟
  • 测试运行慢？→ Mock 异步、并行运行、用 happy-dom 替代 jsdom

59. E2E 测试（Playwright / Cypress）

Section titled “59. E2E 测试（Playwright / Cypress）”

场景：核心业务（登录 → 下单 → 支付）怎么用 E2E 测试保证不挂？

答案要点：

追问：

  • E2E 测试成本高？→ 只测核心流程（10-20 个），其他靠单元测试
  • 测试不稳定（flaky）？→ 避免硬编码等待 + 用 auto-wait + 隔离测试数据
  • Playwright vs Cypress？→ Playwright 跨浏览器更好；Cypress 实时调试更好
  • 视觉回归测试怎么用？→ 关键页面 + 每次 PR 对比 + 阈值合理（不能太严）

📝 小结

Section titled “📝 小结”
  • 测试策略题考的是「怎么用有限的测试成本换取可接受的线上风险」。
  • 分层:单元(工具函数、状态机、计算逻辑)、集成(组件与交互)、E2E(关键路径与冒烟)、契约测试(接口层)。
  • 覆盖率策略:核心逻辑高覆盖、边缘展示组件不强求,CI 设红线卡住。
  • 稳定性:E2E 数据隔离与幂等清理、禁 sleep、网络 mock、并行与分片、失败留 trace。
  • 落地:PR 必跑单测 + 关键 E2E,主干跑全量;前端测试金字塔要用倒金字塔思路(集成测试承担更多)。
  • 面试加分:能给出「E2E 从 40 分钟压到 8 分钟」的优化过程,或「线上问题 70% 被 E2E 拦截」的数据。
