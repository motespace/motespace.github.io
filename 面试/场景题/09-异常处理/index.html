九、异常处理 / 降级场景题

摘自 场景面试题库

35. 全局异常处理（ErrorBoundary + 兜底）

Section titled “35. 全局异常处理（ErrorBoundary + 兜底）”

场景：组件渲染时报错导致整个页面崩溃白屏；用户操作触发未捕获的 Promise 错误，怎么办？

答案要点：

追问：

  • ErrorBoundary 捕获不到哪些错误？→ 异步代码、事件处理器错误、SSR 错误（要自己 try/catch）
  • 错误恢复策略？→ 降级 UI + 重试按钮 + 必要时整页 reload
  • 怎么防止错误上报风暴？→ 同类错误采样（同一 message 1 分钟只上报 1 次）+ 上报前过滤
  • 怎么定位到具体行？→ Source Map 上传（生产环境）

📝 小结

Section titled “📝 小结”
  • 异常处理场景题考:错误分类 → 分层兜底 → 用户可感知 → 定位与修复。
  • 错误分类:网络错误(可重试)、业务错误(需提示)、代码错误(需上报)、边界错误(需降级)。
  • 分层兜底:全局 error/unhandledrejection → 框架 ErrorBoundary → 局部 try/catch → 页面级错误页 → 局部降级(兜底数据、关闭功能)。
  • 用户体验:错误提示要可行动(说明原因与下一步),不能只弹「出错了」;静默失败要有降级路径。
  • 稳定性:重试与退避、熔断、幂等、监控上报与告警。
  • 面试加分:讲清「哪些错误该重试、哪些必须让用户重新操作」,体现对业务语义的理解。
