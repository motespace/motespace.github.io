十、表单专项场景题

摘自 场景面试题库

36. 复杂联动校验（异步校验、字段交叉校验）

Section titled “36. 复杂联动校验（异步校验、字段交叉校验）”

场景：商户注册表单，省市区三级联动；账号名要调后端查重；身份证号要校验合法性 + 调公安网比对。

答案要点：

追问：

  • 怎么避免每输入一个字符就发请求？→ debounce + token 机制过滤过期响应
  • 表单怎么做到性能和体验平衡？→ 失焦校验 + 提交时全量校验 + 异步校验 loading 提示
  • 多个字段联动校验失败怎么提示？→ 顶部汇总 + 字段红字 + 自动滚动到第一个错误字段

37. 表单回填 + 编辑场景（脏检查、初始值同步）

Section titled “37. 表单回填 + 编辑场景（脏检查、初始值同步）”

场景：用户打开编辑弹窗回显后端数据；改了字段没保存就关闭弹窗，怎么提示“有未保存的内容”？

答案要点：

追问：

  • setFieldsValue 会触发校验吗？→ 默认不会（需要 setFieldsValue(val, { validateOnly: false }) 才会）
  • 怎么只回填不触发 dirty？→ 回填后调用 form.resetFields() 重置 dirty 状态
  • 路由切换怎么拦截？→ 路由 beforeEach + 全局状态管理表单 dirty；或 React Router v6 的 useBlocker

38. 千级字段性能（动态表单、字段懒加载）

Section titled “38. 千级字段性能（动态表单、字段懒加载）”

场景：商户后台“商品发布”页 200+ 字段（基础信息/规格/物流/营销），首次加载卡顿、滚动掉帧。

答案要点：

追问：

  • Antd Form 200+ 字段卡顿？→ 用 Form.useWatch 精确订阅 + 拆分子组件（每个字段独立组件）
  • 动态表单怎么实现？→ 后端返回 JSON Schema + 前端 JSON Schema 渲染器（FormRender）
  • 字段联动性能问题？→ watch 字段要精确（useWatch(name)），不要全量订阅

39. 草稿自动保存（防丢、版本管理）

Section titled “39. 草稿自动保存（防丢、版本管理）”

场景：用户填了半小时的表单，浏览器崩溃/误关页面，所有内容丢失。SaaS 后台必备。

答案要点：

追问：

  • localStorage 容量限制？→ 5-10MB，整个表单够用；超过用 IndexedDB
  • 多端草稿同步？→ 服务端草稿 + 版本号；冲突时手动合并
  • 草稿是否上报埋点？→ 上报“草稿恢复率”，衡量用户对功能的需求强度

📝 小结

Section titled “📝 小结”
  • 表单是后台系统的高频痛点,场景点:联动校验、动态增删、异步校验与竞态、大字段性能、跨页/分段提交、草稿保存。
  • 技术选型:antd Form(中后台开箱即用)vs React Hook Form + Zod(性能与类型更好),Vue 侧用 el-form + async-validator。
  • 关键技巧:字段级订阅避免全表重渲染、dependencies 实现联动、Form.List 处理动态项、Schema 驱动(配置型 ERP/CRM 必用)。
  • 异步校验要处理竞态(旧请求后到不能覆盖新结果)、防抖与取消请求。
  • 提交链路:客户端校验 → 服务端二次校验 → 幂等键 → 分段提交与进度 → 失败可回滚。
  • 面试加分:讲「我们怎么把 20+ 字段的活动表单从 800ms 优化到 200ms」这类具体优化。
