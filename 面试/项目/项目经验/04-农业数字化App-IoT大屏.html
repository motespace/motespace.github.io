农业数字化项目：App + IoT 大屏 ​

项目概览 ​

时间：2019 年底 - 2020（项目搭建期；2020 年是业务持续交付期） 角色：早期项目，前端开发 技术栈：uni-app、Vue 2、Vuex、ECharts、websocket、海康威视 WebSDK 推荐程度：补充项目

这是一个早期农业数字化项目，包含消费者端、服务人员端 App 和农业物联网监控大屏。面试时建议作为补充项目，用于说明移动端、端能力接入、地图联动和数据可视化经验。

面试时可以这样概括：

这个项目不是单纯摆几个图表，它要把 IoT 实时数据、地图点位、趋势分析和视频监控放在同一个大屏里，让管理方能快速看到基地运行情况。

项目时代背景（面试补充） ​

如果面试官对"2019 年底用 Vue 2 + uni-app + ECharts 做 IoT 大屏"有疑问，可以这样解释：

  • Vue CLI 3 时代：2018 年 8 月 Vue CLI 3 正式发布，2019 年底已经是主流，大屏项目用的是 vue.config.js 配置（不是老的 webpack.config.js），符合当时的工程化标准。
  • uni-app 早期：2018 年 DCloud 推出 uni-app，2019 年底已经稳定但还在快速迭代，跨端编译到 H5 / 小程序 / App 的兼容性问题较多，需要写条件编译兜底。
  • ECharts 4.x：当时还没有 ECharts 5，地图组件用的是 4.x 的 effectScatter + 自定义 pin symbol 组合方案。
  • IoT 协议：传感器数据走 HTTP 轮询（不是 WebSocket），每 30 秒 - 15 分钟刷新一次；大屏天气数据走的是高德 / 心知天气类 API，行政区编码是 6 位数字（如信丰县 360722）。

面试表达要点：

这是 2019 年底启动的项目，技术栈符合当时的主流：Vue CLI 3 + Vue 2.6 + uni-app + ECharts 4.x。我在里面负责的是业务代码和图表联动，工具链和构建配置当时由团队 leader 主导。这段经历现在更多体现"跨端和 IoT 可视化能力"，不是技术深度。

业务全貌 ​

App 业务线 ​

这是"农业电商 + 果农服务 + 溯源互动"的移动端项目。

消费者版：

  1. 首页展示农场、商品、认养入口、活动。
  2. 用户可以购买农场直供商品。
  3. 用户可以认养果树，查看认养记录和果树信息。
  4. 支持竞拍、订单、支付、物流或状态跟踪。
  5. 扫码查看产地、批次、种植记录等溯源信息。
  6. 通过 IM、直播和果农产生互动。

果农版：

  1. 操作台查看待办和农事信息。
  2. 学习种植技术、查看施肥方案。
  3. 发布或参与橙友圈社区。
  4. 通过问答咨询处理问题。
  5. 与消费者或平台进行沟通。

面试表达：

这个项目是我早期移动端项目，价值是完整跑过交易、认养、溯源、消息、IM 和直播这些移动端业务闭环。现在我不会把它作为主项目，但它能证明我不只做后台，也做过跨端和端能力接入。

IoT 大屏业务线 ​

大屏围绕农业产业做 IoT 可视化，主要展示：

  1. 基地分布：不同果园或基地在地图上的位置。
  2. 环境监测：温度、湿度、光照、雨量、CO2、土壤墒情、PH 等。
  3. 价格指数：不同时间、区域或品类的价格走势。
  4. 产量走势：产量、采摘、销售等趋势。
  5. 结构分布：树龄、土壤、基地类型等占比。
  6. 视频监控：查看果园实时画面，多摄像头预览和云台控制。

面试表达：

这个项目不是单纯摆几个图表，它要把 IoT 实时数据、地图点位、趋势分析和视频监控放在同一个大屏里，让管理方能快速看到基地运行情况。

我负责的内容 ​

  1. 负责移动端首页、商品、认养、订单、支付、扫码溯源、农事服务和社区问答。
  2. 处理消息触达、即时通讯和直播入口。
  3. 对接传感器数据，展示温湿度、光照、雨量、二氧化碳、土壤墒情和酸碱度等指标。
  4. 实现地图点位、数据浮层、底部轮播和视频监控联动。
  5. 处理不同端的生命周期、权限、支付、扫码和页面返回差异。

一分钟介绍 ​

这是一个同时包含移动端和 IoT 大屏的农业数字化项目。App 侧重点是交易、认养、溯源和服务闭环；大屏侧重点是传感器数据、基地地图、趋势图和视频监控联动。我主要负责前端页面、接口协作、跨端适配和数据展示。

App 业务实现 ​

1. 认养业务 ​

可以按流程讲：

  1. 用户进入认养专区，查看可认养果树或果园。
  2. 选择认养对象，查看价格、周期、权益和说明。
  3. 提交认养订单并支付。
  4. 支付成功后生成认养记录。
  5. 用户后续可以查看果树状态、农事记录、图片或直播画面。
  6. 到期或收获阶段关联订单、配送或权益领取。

前端难点：

  1. 认养状态比普通商品多，比如可认养、已认养、待支付、认养中、已到期。
  2. 入口多，首页、详情、订单、个人中心都可能进入认养信息。
  3. 移动端支付结果需要处理返回、刷新和失败重试。

2. 认养圈 / 社区（真实代码片段） ​

认养圈是消费者和果农的社区，本质上是一个简化版的微博 + 评论列表。真实页面用 v-for 渲染帖子、点赞、评论：

vue
<!-- 真实代码片段：xinfeng-sell/pages/adoption/adoption.vue（节选） -->
<template>
  <view class="moments__post" v-for="(post, index) in posts" :key="index">
    <view class="post-left">
      <image class="post_header" :src="post.headImage || '../../static/index/xflogo/192.png'" />
    </view>
    <view class="post_right">
      <view class="post-name">{{post.name}}</view>
      <view class="post-time">{{post.create_time}}</view>

      <view class="thumbnails">
        <!-- 关键：图片懒加载 + 点击预览 -->
        <image lazy-load mode="aspectFill"
               :src="image+'?x-oss-process=image/resize,p_50'"
               :data-src="image"
               @tap="previewImage(post.images, index_images)" />
      </view>

      <view class="toolbar">
        <view class="like" @tap="like"
              :data-adoptionid="post.adoption_id"
              :data-adoptionindex="index">
          <image :src="post.islike==0
            ?'../../static/index/islike.png'
            :'../../static/index/like.png'" />
        </view>
      </view>
    </view>
  </view>

  <chat-input @send-message="send_comment"
              @blur="blur"
              :focus="focus"
              :placeholder="input_placeholder" />
</template>

设计要点：

  • 图片懒加载：lazy-load + OSS 缩放参数（?x-oss-process=image/resize,p_50）双管齐下，移动端列表里图片不能一次加载全。
  • mode="aspectFill"：uni-app 裁剪模式，等比缩放填满，避免图片拉伸变形。
  • 聊天输入组件封装：评论框做成可复用组件，外部通过 @send-message 拿到提交内容。

3. WebSocket 即时通讯（真实代码） ​

App 的 IM（认养圈、果农 - 消费者沟通）走 WebSocket。下面是 App 启动时连接 WebSocket 的真实代码：

js
// 真实代码片段：xinfeng-sell/App.vue
onShow: function() {
  uni.getStorage({
    key: 'onlyToken',
    success: e => { this.theToken = e.data }
  })

  // 通过 theToken 是否为空判断是否登录
  if (this.theToken == '' || this.theToken == null) {
    // 未登录：不连 WebSocket
  } else {
    uni.getStorage({
      key: 'memberId',
      success: e => {
        // 关键：登录后用 memberId 建立 WS 连接
        uni.connectSocket({
          url: that.$wsServerUrl + '/api/im/connect/memberId/' + e.data,
          success(data) {},
        })
        uni.onSocketOpen(function(res) {
          console.log('websocket连接成功')
        })
        uni.onSocketClose(function(res) {
          console.log('WebSocket 连接失败！')
        })
      }
    })

    // 关键：监听全局关闭事件 → 自动重连
    uni.onSocketClose(function(res) {
      console.log('WebSocket 已关闭！')
      uni.getStorage({
        key: 'memberId',
        success: e => {
          uni.connectSocket({
            url: that.$wsServerUrl + '/api/im/connect/memberId/' + e.data,
            success(data) {},
          })
          uni.onSocketOpen(function(res) {
            console.log('websocket重连成功')
          })
          uni.onSocketClose(function(res) {
            console.log('WebSocket 重连失败！')
          })
        }
      })
    })
  }
}

onHide: function() {
  // 关键：App 切后台时关闭 WS，省电省流量
  uni.closeSocket()
  uni.onSocketClose(function(res) {
    console.log('WebSocket 已关闭！')
  })
}

设计要点：

  • 登录后连接：通过 onlyToken 判断登录状态，未登录不连 WS。
  • onShow 连、onHide 断：App 切后台时关闭 WebSocket，回来重新连接——避免后台空连接浪费电量和流量。
  • 自动重连：监听 onSocketClose 后重新 connectSocket，WS 服务重启或网络抖动都能恢复。

这段代码的真实问题（迁移时可优化）：

  • 没有退避策略：重连立即触发，高频失败时打爆服务器。
  • 没有心跳：长时间无消息可能被中间设备断开。
  • 重连成功后才挂载 onSocketMessage：消息处理在哪个时机注册要看具体业务代码。

4. 竞拍 / 支付 / 订单 ​

竞拍：

  1. 展示竞拍商品、起拍价、当前价、倒计时。
  2. 用户出价后刷新当前状态。
  3. 竞拍结束后生成结果或订单。

支付：

  1. 订单确认页展示商品、金额、地址、支付方式。
  2. 接入微信 / 支付宝支付。
  3. 支付后处理成功、失败、取消、返回 App 的状态刷新。

订单：

  1. 待支付、待发货、待收货、已完成、已取消等状态。
  2. 订单详情展示商品、支付、配送、售后或溯源入口。
  3. 列表页要处理分页、状态筛选和下拉刷新。

面试表达：

这类移动端业务看起来普通，但状态处理很关键。尤其是支付后用户可能从外部支付页返回，前端不能只依赖本地状态，要重新查订单结果。

5. 扫码溯源 ​

流程：

  1. 用户扫描二维码。
  2. 前端解析二维码里的批次、商品或溯源码。
  3. 调接口查询产地、果园、批次、种植记录、采摘或检测信息。
  4. 页面按时间线或模块展示溯源内容。
  5. 异常码、过期码、无数据要有兜底提示。

价值表达：

扫码溯源本身不是技术难点，但它把"前端 + 后端 + IoT + 物流"串起来了，体验上很有冲击力。

6. App 端能力接入 ​

  • 讯飞语音：果农版农事记录语音输入。
  • 萤石云直播：认养果树实时画面。
  • WebSocket：认养圈、果农沟通、订单状态推送。
  • 高德地图：定位附近的农场。

面试表达：

App 项目里的端能力接入很常见，但要分清"前端做了什么"和"端 SDK 做了什么"。比如萤石云直播是 H5 嵌入 SDK 还是 App 原生拉流，前端责任不一样。

IoT 大屏实现 ​

1. 大屏数据接口格式（真实接口约定） ​

下面是从 信丰大屏数据接口数据格式.md 抽出的真实接口格式：

json
// 物联网数据模块
{
  "temperature": 37.5,
  "sunny":    { "value": 600, "unit": "H",  "max": 1000 },
  "rainy":    { "value": 800, "unit": "mm", "max": 1000 },
  "humidity": 48
}

// 首页地图点位（每个 value 第三项是 hover 要展示的数据）
[
  {
    "name": "创丰家庭农场",
    "value": [
      114.931329,                                    // 经度
      25.391958,                                     // 维度（原文如此，应为 latitude）
      [
        { "key": "土地温度", "value": "22.5℃" },
        { "key": "土地湿度", "value": "21.6%VOL" }
      ]
    ]
  }
]

// 交易平台数据
{ "adoptNum": 60, "tradePrice": 1250, "orderNum": 3600 }

设计要点：

  • value 数组的"超载"用法：经度、维度 + hover 数据都塞在一个数组里，是早期接口设计偷懒的做法（避免定义嵌套对象）。前端解析时要按位置取值，对新人不太友好。
  • 单位内置：湿度带 "%VOL"，温度带 "℃"，前端不要二次拼接，直接展示。

2. 地图点位 + IoT 数据浮层（真实核心代码） ​

大屏核心难点是地图点位 + hover/点击后展示 IoT 数据。下面是从 IotGeoMap.vue 抽出来的真实核心代码：

vue
<!-- 真实代码片段：xinfeng/src/components/charts/IotGeoMap.vue -->
<script>
export default {
  data() {
    return {
      myCharts: '',
      weather: '强沙尘暴',
      ico: '&#xe631;',
      temperature: 0,
      timeInterval: '',  // 关键：定时器 ID，用于销毁清理
    }
  },
  props: ['height', 'rows'],
  methods: {
    initMap() {
      this.$axios.get('/geo/xinfeng.json').then((res) => {
        let option = {
          geo: {
            map: 'xinfeng',  // 关键：注册自定义地图（信丰县边界）
            aspectScale: 0.9,
            zoom: 1.3,
            label: { show: true, color: '#fff', fontSize: 16 },
            itemStyle: { areaColor: '#213f9c', borderColor: '#4260c2', borderWidth: 2 },
          },
          series: [
            // 系列 1：圆点波纹（动效）
            {
              name: '圆点',
              type: 'effectScatter',
              coordinateSystem: 'geo',
              symbolSize: 16,
              data: this.rows,
              rippleEffect: { scale: 3, brushType: 'stroke' },
              silent: true,   // 关键：圆点不响应鼠标事件，只做动效
              tooltip: { show: false },
            },
            // 系列 2：标记（pin 图标，可点击）
            {
              name: '标记',
              type: 'scatter',
              coordinateSystem: 'geo',
              symbol: 'pin',
              symbolSize: 36,
              data: this.rows,
              tooltip: {
                formatter: (params, ticket, callback) => {
                  // 关键：tooltip 内容是异步加载的！
                  this.$axios.get('/api/iot/multipledataquery', {
                    params: {
                      baseCode: params.data.areaCode,
                      metric: 'KQWD,KQSD,TRWD,TRSD,PH,GZ,CO2',  // 关键：多指标一次查
                      start: new Date().getTime() - 1000 * 60 * 60,
                      downsample: 'HALFHOUR_AVG',
                      deep: 1,
                    }
                  }).then((res) => {
                    const data = res.data.datas
                    // 拼接 tooltip HTML：左侧天气图标 + 右侧指标表格
                    let left = "<div style='float: left;...'><span>" + this.ico + "</span><p>天气：" + this.weather + "</p><p>温度：" + this.temperature + "</p></div>"
                    let right = "<table>" + title
                    for (let i = 0; i < data.length; i++) {
                      right += i % 2 === 0
                        ? "<tr><td>" + data[i].metricName + "：" + data[i].value[0] + "</td>"
                        : "<td>" + data[i].metricName + "：" + data[i].value[0] + "</td></tr>"
                    }
                    callback(ticket, '<div style="min-width: 440px">' + left + right + '</div>')
                  }).catch((error) => { console.info(error) })

                  return "加载中...."   // 关键：先返回占位文案，拿到数据再 callback
                },
                extraCssText: 'box-shadow: rgb(59, 117, 213) 0px 0px 20px inset;background:rgba(33,33,99,0.68);border-radius: 0.5%',
              },
            },
          ],
        }

        this.$echarts.registerMap('xinfeng', res.data)  // 关键：注册地图数据
        this.myCharts = this.$echarts.init(document.getElementById(this.id))
        this.myCharts.setOption(option)
      })
    },

    // 关键：外部调用 → 高亮地图点位（底部轮播切换时调用）
    activeSeries(id) {
      let t = this.index
      for (let i = 0; i < this.rows.length; i++) {
        if (this.rows[i].farmId === id) {
          t = i
          break
        }
      }
      this.myCharts.dispatchAction({ type: 'downplay', seriesIndex: 1, dataIndex: this.index })
      this.myCharts.dispatchAction({ type: 'highlight', seriesIndex: 1, dataIndex: t })
      this.myCharts.dispatchAction({ type: 'showTip',  seriesIndex: 1, dataIndex: t })  // 关键：自动展开 tooltip
      this.index = t
    },

    initWeather() {
      this.$axios.get('/api/rep/weather/360722').then((res) => {  // 360722 是信丰县行政编码
        const data = res.data
        this.temperature = data.lives[0].temperature + '℃'
        this.weather = data.lives[0].weather
        this.ico = this.icon[data.lives[0].weather]
      })
    },

    refreshWeather() {
      this.timeInterval = setInterval(() => {
        this.initWeather()
      }, 900000)  // 关键：15 分钟刷新一次天气
    },

    refreshMap() {
      // 关键：rows 变化时彻底销毁重建图表（ECharts 不能 diff 大改动）
      this.myCharts.clear()
      this.myCharts.dispose()
      this.initMap()
    },
  },

  mounted() {
    this.initWeather()
    this.initMap()
    this.refreshWeather()
    window.onresize = () => { this.myCharts.resize() }  // 关键：窗口缩放重新计算尺寸
  },

  watch: {
    'rows': 'refreshMap'  // 关键：rows 变化重建图表
  },

  beforeDestroy() {
    clearInterval(this.timeInterval)  // 关键：销毁时清理定时器
  },
}
</script>

设计要点：

  • 两层 series（圆点 + pin）：圆点用 effectScatter 做波纹动效，silent: true 不响应鼠标；pin 图标用 scatter 接收鼠标事件。
  • tooltip 异步加载：formatter 先返回 加载中....，接口返回后再用 callback(ticket, html) 异步更新 tooltip。这是 ECharts 异步 tooltip 的标准模式。
  • 多指标一次查询：metric: 'KQWD,KQSD,TRWD,TRSD,PH,GZ,CO2' 用逗号分隔一次查 7 个指标，避免 7 个并行请求。
  • dispatchAction 实现联动：底部轮播切换时调用 activeSeries(id)，地图自动高亮对应点位并展开 tooltip。
  • 路由参数变化重建图表：watch.rows 触发 clear + dispose + initMap，避免 ECharts 旧配置和新数据不一致。
  • 销毁清理：beforeDestroy 里 clearInterval 清掉定时器，大屏长时间运行时至关重要。
  • 窗口 resize：大屏经常拉伸窗口，myCharts.resize() 重新计算尺寸。

设计要点：

  • ref 调用子组件方法：父组件通过 ref 拿到子组件实例，直接调用 activeSeries。这种"命令式"调用比 props/event 链更直接，适合地图/图表这类有状态的对象。
  • 数据一致性：轮播切换时同时刷新三个数据源（设备数、地图数据、地图高亮），避免 UI 显示旧基地的数据。
  • 核心不是散点效果：面试时要强调"地图、轮播和指标始终指向同一个当前基地"，这是大屏多模块联动的关键。

4. 图表组件封装 ​

大屏图表可以讲这几类：

  1. 趋势类：折线图展示温湿度、价格、产量变化。
  2. 对比类：柱状图展示基地、区域或品类之间的差异。
  3. 占比类：饼图展示树龄、土壤、品类结构。
  4. 综合类：雷达图展示多维环境状态。
  5. 状态类：水波图展示湿度、水位或容量类指标。
  6. 地图类：区域地图和基地点位联动。

封装重点：

  1. 图表组件不直接写死接口字段，而是接收业务数据后统一转换。
  2. option 基础样式统一，比如字体、颜色、tooltip、legend。
  3. 数据为空时显示空状态，避免图表报错。
  4. 大屏缩放时图表要 resize。

5. 0 与无数据的区分（关键细节） ​

ts
function formatSensor(value: number | null) {
  // 关键：不能直接用 value || '--'，否则有效的 0 会被误判为空
  if (value === null || value === undefined || Number.isNaN(value)) return '--'
  return String(value)
}

设计要点：

  • || 替换问题：传感器温度可能是 0（零下低温），用 || '--' 会显示 --，丢失有效数据。
  • null / undefined / NaN 三态：这三种都要视为"无数据"，但 0 必须保留。

7. 大屏适配 ​

常见方案：

  1. 以设计稿宽高为基准，比如 1920 x 1080。
  2. 根据当前屏幕宽高计算缩放比例。
  3. 外层容器做整体缩放，内部模块保持设计稿布局。
  4. 图表监听容器变化后执行 resize。
  5. 字体和图表间距不能只靠浏览器自适应，否则大屏会变形。

面试追问 ​

Q：这个项目最难的地方是什么？

A：移动端的状态闭环和大屏的多模块联动。移动端支付、订单和认养状态需要处理返回和刷新；大屏则要让地图、轮播、指标、图表和视频围绕同一个当前基地同步。

Q：地图点位和底部轮播怎么同步？

A：我会维护一个当前基地 id。轮播切换、地图点击、点位 hover 都更新这个 id，然后地图高亮、浮层内容和右侧指标都从这个状态派生，避免各模块各自维护状态导致不同步。

Q：实时大屏如何避免内存问题？

A：每个定时器都在组件销毁时清理，图表实例避免重复初始化，接口失败时做兜底，窗口变化统一触发 resize，长时间运行比首次显示更重要。

Q：传感器数据为空怎么办？

A：前端要区分 0 和无数据。0 是有效值，无数据要显示占位或暂无数据，不能直接用 value || '--' 这种写法，否则会把有效的 0 误判掉。

Q：支付完成后如何保证状态准确？

A：支付完成不能只依赖本地回调，因为用户可能中途离开或从外部页面返回。前端需要在返回 App / 页面重新可见时刷新订单状态。

Q：为什么这个项目在简历里合并成一个？

A：它们属于同一农业数字化业务背景，一个偏移动端业务闭环，一个偏 IoT 可视化。合并后简历更紧凑，但面试时可以根据岗位分别展开 App 或大屏部分。

Q：为什么不主动讲具体推送 SDK 或地图效果？

A：这些属于实现细节，不是项目核心价值。面试时先讲消息触达、页面回流、地图联动和数据刷新，面试官追问时再说明具体端能力或图表实现。

Q：图表长时间运行怎么避免问题？

A：定时器要在组件销毁时清理，请求要做失败兜底，图表实例避免重复初始化，窗口变化时统一 resize。大屏经常长时间开着，这些比普通页面更重要。

Q：ECharts 异步 tooltip 是怎么实现的？

A：在 tooltip.formatter 里先返回占位文案（比如"加载中...."），然后用 callback(ticket, html) 在异步接口返回后回填完整 HTML。ECharts 会自动用返回的 HTML 替换占位内容。

Q：App 的 WebSocket 连接和重连是怎么做的？

A：登录后用 uni.connectSocket 建立连接；onShow 连、onHide 断；监听 onSocketClose 后重新 connectSocket 实现自动重连。但项目里没有退避策略和心跳，这是后续可以优化的点。

Q：uni-app 项目最大的痛点是什么？

A：早期 uni-app 跨端兼容问题多，自定义组件在 H5 和小程序表现不一致，需要大量条件编译。还有就是原生能力（推送、扫码、支付）要分端写，调试比较麻烦。
