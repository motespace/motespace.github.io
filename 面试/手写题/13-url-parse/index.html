Q1: 手写 URL 解析要点？

Section titled “Q1: 手写 URL 解析要点？”

答：

  1. 用 regex / 字符串方法
  2. 处理 hash、pound、protocol、host、path 顺序
  3. decodeURIComponent 解码

Q2: URLSearchParams 和手写解析区别？

Section titled “Q2: URLSearchParams 和手写解析区别？”

答：

  • URLSearchParams：原生 API，性能好、覆盖全
  • 手写：灵活、能定制（处理数组 query）

Q3: encodeURIComponent 和 encodeURI 区别？

Section titled “Q3: encodeURIComponent 和 encodeURI 区别？”

答：

  • encodeURIComponent：编码所有特殊字符（包括 / ? &）
  • encodeURI：只编码空格等少数，不编码 URL 结构字符

Q4: 浏览器 URL 长度限制？

Section titled “Q4: 浏览器 URL 长度限制？”

答：

  • IE：2083 字符
  • Chrome：32k+
  • 服务器：8k（nginx 默认）

Q6: 怎么处理 URL 中的 hash 路由？

Section titled “Q6: 怎么处理 URL 中的 hash 路由？”

答：

📝 小结

Section titled “📝 小结”
  • URL 结构:protocol://host:port/pathname?search#hash,其中 host 含域名与端口,search 是 ? 后的查询串。
  • 生产首选 URL 与 URLSearchParams:new URL(location.href)、url.searchParams.get('id')、params.toString()。
  • 手写解析查询串:先 decodeURIComponent,再按 & 切分、按 = 取键值,注意没有 = 的参数与重复 key。
  • 易错点:decodeURIComponent 会在畸形 % 序列上抛错,生产要 try/catch;+ 在查询串里表示空格(用 URLSearchParams 会自动处理)。
  • 面试加分:讲清「为什么手写解析容易漏掉编码与空值」,并说明生产为何直接用标准 API。
