七、面试高频追问

Section titled “七、面试高频追问”

Q1: 为什么用 translate3d 而不是 top？

Section titled “Q1: 为什么用 translate3d 而不是 top？”

答：

  • transform: translate3d(0, y, 0) 只触发合成，不重排不重绘
  • top: y 触发重排 + 重绘 + 合成，性能差 10-100x
  • 顺便开启 GPU 合成层

Q2: 怎么支持下拉加载更多？

Section titled “Q2: 怎么支持下拉加载更多？”

答：监听 scroll 事件，当 scrollTop + clientHeight >= scrollHeight - threshold 时触发加载。

Q3: 怎么优化滚动性能？

Section titled “Q3: 怎么优化滚动性能？”

答：

  1. rAF 节流：scroll 事件用 requestAnimationFrame 节流
  2. CSS contain：每行 contain: content 隔离重绘
  3. content-visibility：未实测的容器跳过布局

Q5: 虚拟列表 SEO 怎么处理？

Section titled “Q5: 虚拟列表 SEO 怎么处理？”

答：服务器端渲染（SSR）一次性输出核心内容，客户端再叠加虚拟列表。或者用 noscript fallback。

Q6: 已知高度 vs 未知高度，怎么选？

Section titled “Q6: 已知高度 vs 未知高度，怎么选？”
  • 已知高度：固定行高版本（性能最佳）
  • 未知高度：动态行高版本（首次测量 + 估算 fallback）

📝 小结

Section titled “📝 小结”
  • 核心思想:只渲染可视区域内的元素,用两个占位元素撑起上下空白,总高度保持不变。
  • 关键计算:scrollTop / itemHeight 得出起始索引,viewportHeight / itemHeight 得出渲染数量,再多渲染几行做缓冲。
  • 动态行高:需要测量并缓存每项高度 + 维护偏移量前缀和(或估算 + 滚动后校正),否则滚动会跳动。
  • 二维虚拟列表(表格/大屏)要同时处理行列两个方向的可见范围。
  • 面试加分:能讲「为什么直接用 translateY 定位而不是 top」(避免重排)、以及与 content-visibility: auto 的取舍。
  • 真实项目:万行表格、IoT 大屏、设备列表都用得上。
