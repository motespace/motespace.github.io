call / apply / bind

7 年经验面试必问：“手写 call / apply / bind？”“bind 支持 new 吗？” 本文按“原理 → 实现 → 边界”组织。

一、call

Section titled “一、call”

fn.call(thisArg, arg1, arg2, ...)

原理：把函数作为 thisArg 的方法调用一次。

二、apply

Section titled “二、apply”

fn.apply(thisArg, [arg1, arg2, ...])

三、bind

Section titled “三、bind”

fn.bind(thisArg, arg1, arg2) 返回新函数

原因：箭头函数没有自己的 this，继承外层。

六、面试追问

Section titled “六、面试追问”

Q1: 手写 call 怎么防止属性冲突？

Section titled “Q1: 手写 call 怎么防止属性冲突？”

答：用 Symbol 作为属性名（防止和 thisArg 的属性冲突）。

Q2: bind 后能不能再 bind？

Section titled “Q2: bind 后能不能再 bind？”

答：不能。原生 bind 也是如此，第一次 bind 后 this 已写死。

Q3: bind 支持 new 吗？

Section titled “Q3: bind 支持 new 吗？”

答：原生 bind 支持。new 调用时 this 是新创建的实例（忽略 thisArg）。手写实现要判断 instanceof Bound。

Q4: 手写 apply 怎么处理类数组？

Section titled “Q4: 手写 apply 怎么处理类数组？”

答：args 参数可以传类数组（带 length），也可以 spread。生产用 Array.from(args) 转。

Q6: Reflect.construct 是什么？

Section titled “Q6: Reflect.construct 是什么？”

答：Reflect.construct(Target, args, newTarget) 类似 new + constructor。手写 bind 时配合使用能更精确模拟原生行为。

Q7: 箭头函数的 this 怎么改？

Section titled “Q7: 箭头函数的 this 怎么改？”

答：改不了。箭头函数没有自己的 this，bind / call / apply 都无效。如果要改 this，改用普通函数。

📝 小结

Section titled “📝 小结”
  • 三个方法都用来改变函数执行时的 this,并可传参:call(thisArg, ...args)、apply(thisArg, argsArray)、bind(thisArg, ...args) 返回新函数。
  • call/apply 立即执行,bind 返回绑定后的新函数(可重复调用)。
  • bind 的两个特性:永久绑定 this、绑定后的函数不能被 new 调用(new 会忽略 thisArg)。
  • 箭头函数没有自己的 this,bind 对箭头函数无效;bind 后的函数 length 会减去已绑定的参数个数。
  • 手写 bind 要用柯里化思路:先 fn.bind(thisArg) 返回一个保存 this 的中间函数,再逐步收集参数。
  • 面试话术:能讲「call 与 apply 只差参数形式,bind 的价值是永久绑定与柯里化」。
