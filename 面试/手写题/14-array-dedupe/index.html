三、性能对比

Section titled “三、性能对比”
方法 时间复杂度 空间复杂度
Set O(n) O(n)
indexOf O(n²) O(n)
sort + 去重 O(n log n) O(n)
Map / filter O(n) O(n)

结论：Set / Map 最优。

五、面试追问

Section titled “五、面试追问”

Q1: Set 去重为什么快？

Section titled “Q1: Set 去重为什么快？”

答：底层用哈希实现，O(1) 查找，整体 O(n)。

Q2: 怎么去重对象数组？

Section titled “Q2: 怎么去重对象数组？”

答：按某个 key（如 id）去重，构造 Set 记录已出现 key，filter 时跳过重复。

Q3: Set 能识别 1 vs ‘1’？

Section titled “Q3: Set 能识别 1 vs ‘1’？”

答：不能。Set 用 SameValueZero 比较，会把 1 和 ‘1’ 视为不同。 如果业务上需要兼容，加 key 转换：new Set(arr.map(String))。

Q4: 怎么处理 NaN 去重？

Section titled “Q4: 怎么处理 NaN 去重？”

答：Set 和 indexOf 都能去重 NaN（SameValueZero 算法把 NaN === NaN）。

Q6: 1 万 + 元素的去重性能？

Section titled “Q6: 1 万 + 元素的去重性能？”

答：Set 最优（O(n)）。indexOf（O(n²)）会卡。

📝 小结

Section titled “📝 小结”
  • 常用实现:Set(最简洁,O(n))、filter + indexOf(O(n²))、reduce + includes、对象映射(注意键会变字符串,数字与字符串会冲突)、排序法(会改变顺序)。
  • 特殊值:NaN 在 indexOf 中永远找不到(要用 Object.is 或 Number.isNaN);+0 与 -0 在 Set 中被视为相同。
  • 对象数组去重要按业务 key(如 id),需要自己写 Map。
  • 性能:数据量大用 Set;JSON.stringify 序列化去重会丢失 undefined 并受 key 顺序影响,不推荐。
  • 面试加分:讲「为什么 indexOf 找不到 NaN」和「对象去重该用什么维度」。
