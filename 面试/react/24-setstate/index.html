📝 小结

Section titled “📝 小结”
  • 经典结论:在 React 事件处理器与生命周期里 setState 是异步批处理的,在 setTimeout / 原生 DOM 事件等 React 之外的环境里是同步的(React 18 后基本全变成批处理)。
  • 「异步」指的是state 不会立刻更新:this.state 在调用后仍是旧值,要等渲染完成才更新;但队列是异步处理的,不是延后执行。
  • React 18 用 createRoot 后,所有更新都自动批处理(包括 Promise、定时器、原生事件),这消除了大量「为什么这里没批处理」的困惑。
  • 多次 setState 会被合并成一次渲染;若后一次依赖前一次的结果,必须用函数式更新 setState(prev => prev + 1)。
  • React 18 的 flushSync 可以强制同步刷新(用于测量 DOM 等场景),但会牺牲并发特性。
  • 面试加分:讲清「「异步」指的是 state 更新时机,不是执行时机」——这是这道题最常被答错的点。
