📌 二、Ant Design 必背 15 问 ​

详细版：Ant Design 实战

#问题一句话答案
1Form 为什么要 useForm？拿到实例才能在组件外 getFieldValue/setFieldsValue/validateFields/resetFields；不传就是"非受控 Form"，外部只能靠 onFinish 拿值
2Form 有哪几个关键 API？getFieldValue/getFieldsValue/setFieldValue/setFieldsValue/resetFields/validateFields/getFieldError/isFieldsTouched
3字段联动的标准写法？Form.useWatch('a', form) 订阅 + useEffect 联动；或 Form.Item shouldUpdate 精确控制重渲染范围
4联动的坑？隐藏字段的旧值会被一起提交 → 手动 setFieldValue(f, undefined) 或 preserve={false}；useWatch([]) 订阅整个表单会全量 re-render
5动态增删字段？Form.List（fields/add/remove/move），新增项必须给初值
6Table 必写的属性？rowKey（不写会选中错乱）、columns（用 useMemo 稳定引用）、scroll.x（否则固定列不生效）
7Table 排序筛选怎么做？onChange(pagination, filters, sorter, extra) 一次拿全，真实过滤排序交给后端；后端排序字段要白名单，防注入
81 万行表格怎么办？ERP 首选后端分页（要跳页/导出/总数）；确需全量用 antd v5.9+ virtual + scroll={{x,y}}
9列多/列少分别怎么处理？列多：scroll.x + 固定首尾列 + ellipsis；列少：用 span 合并栅格布局，别硬凑
10主题定制怎么做？Token 三层：全局 token / 组件 token / algorithm（darkAlgorithm）；ConfigProvider theme={{ token, components }}
11多租户换肤？品牌色后端下发 → 运行时改 token + 注入 CSS 变量给非 antd 部分用
12message 主题不生效？用了静态 message.info()，它脱离 ConfigProvider 上下文 → 根节点包 <App>，用 App.useApp()
13antd Form vs RHF+Zod？antd 受控(store 订阅)、开箱即用、布局强；RHF 非受控、性能好、schema 可前后端共享。ERP 统一 antd，超大单表单用 RHF
14二次封装怎么做？只封装有业务语义的（StatusTag/PageTable/BizForm）；pages → business → ui → antd 依赖单向；透传 className/style/ref；自带 loading/empty/error 三件套
15Element UI 也用过吗？Vue 生态的对应物，思路一致（数据驱动 + 插槽扩展 + 主题变量覆盖）；React 岗主答 antd

三个一定要主动说的坑（面试官爱追问）：① 静态 message 丢主题；② 隐藏字段旧值被提交；③ Table 没写 rowKey / columns 没 memo。

📌 三、ERP / CRM 场景必背 12 问 ​

详细版：ERP / CRM 业务场景题

#场景关键答案
1列表组合筛选很慢筛选全交后端 + 防抖 300ms + AbortController 取消竞态 + 条件写进 URL query + 后端分页
2Excel 批量导入 5 万行SheetJS 解析放 Web Worker → 表头映射 → 行级预校验 → 批量查重（不要一行一请求）→ 每批 500~1000 行提交 → 失败行导出成错误报告让用户改后重传 → batchId 幂等
3导出 10 万行崩了前端生成必崩。走服务端异步导出：传筛选条件拿 taskId → 轮询/推送 → OSS 签名下载地址 → 下载中心。前端兜底：超 1 万行直接转后台任务
4CSV 中文乱码文件头加 UTF-8 BOM \uFEFF；或干脆导 xlsx
5三种客户字段不一样Schema 驱动动态表单：字段元数据后端下发，visible + useWatch 做联动，custom 类型塞业务组件
6审批流状态管理前端用状态机（TRANSITIONS 映射表）而不是一堆 if；按钮按 can(action, status) 渲染；驳回必填意见；最终状态以后端返回为准；多人同时审批由后端校验状态机
7两人同时改一条记录乐观锁 version：提交带 version，后端 WHERE id=? AND version=?，影响 0 行 → 409 → 提示刷新或字段级合并
8不同角色看到不同数据行级权限必须后端做（前端过滤是假过滤，接口已泄露）；列级脱敏后端做；前端只管 scope 切换 + 按钮级权限 + 数据范围提示
9列表和详情数据不一致TanStack Query 双缓存天然不一致 → invalidate / setQueryData 精准更新 / WebSocket 推送；标签页切回前台时 invalidate
10切换租户要清什么queryClient.clear() + store + localStorage + 字典/菜单/权限 + WebSocket 重连 + AbortController 取消在途请求；更稳：直接整页跳转
11动态表单（配置型）Schema 下发 + 字段级组件拆分（各自 useWatch）+ 校验规则用 Zod 动态编译；性能坑是订阅整个表单
12多人协作/离线编辑CRDT（Yjs）/ 操作日志重放；乐观锁只解决"最后写入者赢"

📌 四、监控与排障必背 6 问 ​

详细版：异常监控与错误上报 · 线上问题定位与降级

#问题关键答案
1线上错误怎么发现？window.onerror（同步 + 资源错误，捕获阶段）+ unhandledrejection（异步）+ React ErrorBoundary（渲染）→ 上报 Sentry/自建 → 按分级告警
2上报要带什么字段？message/stack/componentStack + URL/路由 + userId/租户 + release 版本 + 设备浏览器 + 最近操作路径 breadcrumb。没有上下文的上报等于没上报
3生产为什么配 SourceMap？压缩后堆栈不可读。构建生成 .map 上传监控平台 → 线上错误能还原到源码行。上传完必须从静态服务器删掉，否则源码泄露
4ErrorBoundary 能捕获哪些？只能捕获 React 渲染树内、渲染/生命周期阶段的错误；事件回调和异步回调不会冒泡，要自己 try/catch
5用户说"页面打不开"怎么查？① 确认影响面 ② 看监控（错误率/接口成功率/资源 404/白屏率）③ 按 release 聚合 ④ 用操作轨迹复现 ⑤ 先止损（回滚/关开关/降级）再定位 ⑥ 复盘出带 owner 的改进项
6前端怎么降级？功能开关（按租户/百分比灰度）+ 数据降级（缓存兜底、4xx 不重试）+ 渲染降级（ErrorBoundary 局部兜底不全页白屏）+ 极端情况按顺序关功能。前提：每条降级路径都有测试

📌 五、TypeScript 必背 6 问 ​

详细版：进阶面试题 Q11-Q25

#问题关键答案
1泛型组件怎么写？function List<T>(props)；.tsx 里箭头函数要写 <T,> 否则被当 JSX
2泛型 Hook 怎么写？泛型放调用点推导：queryFn: () => request<User>(url)，调用方不用再断言
3satisfies vs as const？satisfies 校验结构同时保留字面量类型；as const 保留字面量但不校验。做路由表/权限点常量用 satisfies
4穷尽检查怎么做？switch + default: assertNever(x)，x: never；新增状态时编译期报错
5unknown vs any？外部数据一律 unknown 再收窄；any 会传染整个表达式
6什么时候用类型断言？只在你比编译器更清楚类型时；更好的做法是类型守卫 x is T 或 Zod 校验

📌 六、三个"我做过"的故事（STAR 压缩到 60 秒） ​

故事 1：后台列表页性能治理（对应"性能优化"条款） ​

S：商户管理 SaaS 的客户列表，1 万+ 数据，翻页卡顿，运营抱怨
T：把首屏从 3s 降到 1s 内
A：① 全量拉取改后端分页 + 组合筛选下推；② Table 加 rowKey + columns useMemo
   + 行内编辑抽成 memo 子组件；③ 大数据量视图用虚拟滚动
   ④ 接入 Web Vitals 上报 LCP/INP，按版本对比
R：首屏 3s → 0.9s，长任务从 6 个降到 1 个

可追加：虚拟滚动不适合需要跳页/导出的后台场景，所以最终选了分页 —— 讲取舍，比讲技术更加分。

故事 2：组件沉淀与复用（对应"组件化设计与实现"条款） ​

S：多个页面重复写弹窗 + 表单 + 状态标签，改一次要改 5 个文件
T：抽成可复用业务组件
A：① StatusTag 把"状态 → 颜色/文案"映射收口，用 as const + keyof 保证类型
   ② PageTable 统一 loading/分页/空态/错误态，暴露 toolbar 插槽
   ③ 目录分层 pages → business → ui → antd，依赖单向
   ④ 配套 Storybook 文档 + 单元测试
R：同类需求交付从 3 天降到 1 天，复用率从 0 到 60%+

故事 3：AI 能力落地（对应"AI 应用建设经验"加分项） ​

S：运营录入客户信息慢，字段多、格式乱
T：做个 AI 辅助录入提效
A：① 失焦触发，后端调 LLM + 工商信息 API 回填
   ② 所有 AI 结果标"AI 生成"标识，**必须人工确认才落库**（不直接写业务数据）
   ③ 流式输出用 SSE，主线程可中断
   ④ 脱敏：PII 不出网
R：录入耗时下降，人工采纳率 XX%

⚠️ 讲 AI 时一定要带上"人工确认 + 脱敏 + 兜底"，不然面试官会担心合规风险。

📌 七、AI 差异化打法（30 秒版） ​

JD 写"有 AI 应用建设经验的优先考虑",这是你相对 3 年经验候选人的最大差异点:

- 不说"我用过 Copilot",说"我做过 AI 应用的前端集成":
  流式输出(SSE/ReadableStream)、Function Calling、Prompt 模板管理、
  RAG 检索结果可视化、LLM 应用的权限与降级设计
- 强调你是"前端 + AI 应用"双栈,不是只会调 API
- 一句话收尾:"AI 在后台系统的价值不是炫技,是把重复录入和查询自动化,
  同时保留人工确认和审计,不然业务不敢用。"

📌 八、反问面试官（挑 2~3 个问，别问薪资） ​

   （显得你在认真理解业务，而不是只想写代码）

4. 团队现在的痛点更偏业务迭代速度，还是性能/稳定性？
5. 团队规模多大？前端几个人？代码评审和测试流程是怎样的？
6. JD 提到 AI 应用建设，目前是在规划阶段还是已有落地场景？

第 6 个一定要问 —— 顺势把 AI 话题拉回来深入聊。

📌 十、临场应急话术 ​

不会的问题：

"这个我没在实际项目里用过。不过按我的理解是……（说出你知道的相邻原理）。
如果让我做，我会先……再……"

—— 展示的是思考方式，比硬编安全得多。

被质疑深度：

"你说得对，我刚才那个说法不够准确。准确地说应该是……"

—— 承认 + 立刻修正，比坚持错答案加分。

问到你博客里的内容：

"这块我在自己的技术笔记里整理过，我的思路是……"

—— 展示你有沉淀习惯，这是加分项。
