Vue 2 生命周期 ​

简历里写了"主导风控平台 Vue 2 → Vue 3 迁移"。理解 Vue 2 生命周期是迁移的基础，也是面试必考题。本文按执行顺序组织，配真实项目代码。

1. 生命周期全景图 ​

┌────────────────────────────────────────────────────────────┐
│  beforeCreate → created → beforeMount → mounted            │
│                                                            │
│  beforeUpdate → updated                                    │
│                                                            │
│  activated → deactivated (keep-alive)                      │
│                                                            │
│  beforeDestroy → destroyed                                 │
└────────────────────────────────────────────────────────────┘

2. 8 个核心钩子（按执行顺序） ​

2.1 beforeCreate ​

js
// 组件实例刚创建，数据观测、事件配置前
// 此时：data、methods、computed、watch 都不可用
export default {
  beforeCreate() {
    console.log(this.$data)      // undefined
    console.log(this.someMethod) // undefined
  },
}

实际用途：几乎不用。可以在插件初始化时做一些全局动作。

2.2 created ​

js
// 数据观测、属性方法运算完毕，$el 还没生成
// 此时：data、methods、computed、watch 都可用，DOM 不存在
export default {
  data() { return { list: [] } },
  created() {
    // ✅ 常用：异步请求、初始化非 DOM 数据
    this.fetchList()

    // ❌ 不要在这里操作 DOM（this.$el 还不存在）
  },
  methods: {
    async fetchList() {
      const res = await api.getList()
      this.list = res.data
    },
  },
}

面试坑：created 和 mounted 的区别

createdmounted
DOM 是否就绪❌✅
$el 是否存在❌✅
异步请求✅✅
操作 DOM❌✅
子组件是否就绪❌✅

2.3 beforeMount ​

js
// 模板编译完成，但还没挂载到 DOM
// 几乎不用

2.4 mounted ​

js
// DOM 已挂载，this.$el 可用
// ✅ 常用：DOM 操作、第三方库初始化、订阅事件
export default {
  mounted() {
    // 1. 初始化图表
    this.chart = echarts.init(this.$refs.chart)

    // 2. 监听全局事件
    window.addEventListener('resize', this.handleResize)

    // 3. 初始化第三方库
    this.editor = new wangEditor(this.$refs.editor)

    // 4. 订阅 store
    this.unsubscribe = this.$store.subscribe(() => {})
  },

  beforeDestroy() {
    // ⚠️ 必须清理：防止内存泄漏
    window.removeEventListener('resize', this.handleResize)
    this.chart?.dispose()
    this.editor?.destroy()
    this.unsubscribe?.()
  },
}

真实项目教训：mount 里订阅的事件、计时器、第三方实例，必须在 beforeDestroy 里清理，否则路由切换会内存泄漏。

2.5 beforeUpdate ​

js
// 数据更新时调用，发生在虚拟 DOM 重新渲染前
// 可以访问现有 DOM，但更新后的数据还没渲染
// 极少使用

2.6 updated ​

js
// 数据更新导致的虚拟 DOM 重新渲染完成后
// ✅ 适用于：依赖 DOM 更新后的操作
export default {
  updated() {
    // 注意：updated 里改数据可能死循环（除非用条件判断）
    // 例如：第三方库的图表数据同步
    if (this.chart && this.chartData) {
      this.chart.setOption(this.chartData)
    }
  },
}

面试坑：updated 里改数据会死循环

js
// ❌ 无限循环：this.list 变了 → updated → this.list.push(...) → 再变 → 再触发
updated() {
  this.list.push(this.list.length)
}

// ✅ 用 nextTick 或者加判断
updated() {
  if (this.needSync) {
    this.$nextTick(() => {
      this.chart.setOption(this.list)
      this.needSync = false
    })
  }
}

2.7 beforeDestroy ​

js
// 实例销毁前
// ⚠️ 关键：清理所有副作用！
export default {
  beforeDestroy() {
    // 1. 计时器
    clearInterval(this.timer)

    // 2. 事件监听
    window.removeEventListener('resize', this.handleResize)
    document.removeEventListener('keydown', this.handleKeydown)

    // 3. 第三方实例
    this.chart?.dispose()
    this.editor?.destroy()

    // 4. 取消未完成的请求
    this.controller?.abort()

    // 5. 解绑 Vuex / EventBus
    this.$store.unregisterModule('dynamic')
    this.$bus.$off('event-name', this.handler)

    // 6. EventBus 解绑自定义事件
    bus.$off('addCondition', this.handleAddCondition)
  },
}

2.8 destroyed ​

js
// 实例销毁后，所有指令解绑、事件监听移除、子组件销毁
// 通常不用，业务清理都在 beforeDestroy

3. keep-alive 钩子 ​

keep-alive 包裹的组件被切换时不会销毁，而是缓存。多了两个钩子：

js
export default {
  // 被激活时（从隐藏到显示）
  activated() {
    // 恢复滚动位置、刷新数据
    window.scrollTo(0, this.scrollY)
    this.refreshList()
  },

  // 被停用时（从显示到隐藏）
  deactivated() {
    // 保存滚动位置、暂停动画
    this.scrollY = window.scrollY
    this.chart?.dispatchAction({ type: 'showTip', seriesIndex: 0 })  // 关闭 tooltip
  },
}

真实项目代码（风控平台）：

vue
<template>
  <!-- 多标签页切换，缓存已访问的页面 -->
  <keep-alive :include="cachedViews">
    <router-view />
  </keep-alive>
</template>
js
// 路由切换时
beforeRouteLeave(to, from, next) {
  if (from.meta.keepAlive) {
    // 保存页面状态
    const component = this.$vnode.componentInstance
    if (component) {
      component.scrollTop = window.scrollY
      component.searchParams = { ...this.searchParams }
    }
  }
  next()
}

4. 父子组件生命周期执行顺序 ​

重要：父子组件生命周期是嵌套的，不是父先全部跑完再跑子。

4.1 挂载阶段 ​

text
父 beforeCreate
父 created
父 beforeMount
  子 beforeCreate
  子 created
  子 beforeMount
  子 mounted
父 mounted  ← 父 mounted 在所有子 mounted 之后

为什么？ 因为父组件模板里有子组件标签，渲染父模板时遇到子组件就触发子组件的渲染流程。

4.2 更新阶段 ​

text
父 beforeUpdate
  子 beforeUpdate
  子 updated
父 updated

4.3 销毁阶段 ​

text
父 beforeDestroy
  子 beforeDestroy
  子 destroyed
父 destroyed

5. 真实项目案例 ​

5.1 风控平台的规则引擎组件 ​

vue
<!-- recursionModelCondition.vue（节选） -->
<script>
export default {
  name: 'recursionModelCondition',
  data() {
    return {
      conData: {
        class: 'PDCT',
        linking: 'All',
        conditions: [],
      },
    }
  },
  watch: {
    // props 变化时同步到内部数据
    treeData: {
      handler(newV) {
        this.conData = JSON.parse(JSON.stringify(newV))
      },
      deep: true,
      immediate: true,
    },
    // 内部数据变化时通知父组件
    conData: {
      handler() {
        this.$emit('change', this.conData)
      },
      deep: true,
    },
  },
  mounted() {
    this.fetchFieldOptions()
  },
  beforeDestroy() {
    // 清理 EventBus 监听
    if (this.busHandler) {
      this.$bus.$off('addCondition', this.busHandler)
    }
  },
}
</script>

设计要点：

  • 用 JSON.parse(JSON.stringify(...)) 做深拷贝，避免父子数据相互污染。
  • watch.treeData + immediate: true 在挂载时立即同步一次数据。
  • beforeDestroy 里清理 this.$bus 监听，这是 EventBus 最容易漏的点。

5.2 大屏 ECharts 组件 ​

vue
<script>
export default {
  data() {
    return {
      myCharts: null,
      timeInterval: null,
    }
  },
  props: ['height', 'rows'],
  mounted() {
    this.initMap()
    this.refreshWeather()
    window.addEventListener('resize', this.resize)

    // 关键：定时器保存到 this 上，destroy 时清理
    this.timeInterval = setInterval(() => {
      this.initWeather()
    }, 900000)
  },

  // ✅ 关键：路由切换前主动清理
  beforeRouteLeave(to, from, next) {
    if (this.myCharts) {
      this.myCharts.dispose()  // ECharts 实例必须 dispose，否则内存泄漏
    }
    if (this.timeInterval) {
      clearInterval(this.timeInterval)
    }
    next()
  },
}
</script>

6. 迁移到 Vue 3 的注意事项 ​

6.1 生命周期钩子重命名 ​

Vue 2Vue 3
beforeCreate❌ 不再需要（setup 本身就是）
created❌ 不再需要
beforeMountonBeforeMount
mountedonMounted
beforeUpdateonBeforeUpdate
updatedonUpdated
activatedonActivated
deactivatedonDeactivated
beforeDestroyonBeforeUnmount
destroyedonUnmounted
errorCapturedonErrorCaptured

6.2 写法变化 ​

js
// Vue 2：选项式
export default {
  mounted() { this.fetchData() },
  beforeDestroy() { this.cleanup() },
}

// Vue 3：组合式
import { onMounted, onBeforeUnmount } from 'vue'
export default {
  setup() {
    onMounted(() => { fetchData() })
    onBeforeUnmount(() => { cleanup() })
  },
}

6.3 父子组件同步方式变化 ​

js
// Vue 2：父 mounted 在所有子 mounted 之后
// Vue 3：setup 早于所有子组件的 onMounted

// ✅ Vue 3 想在挂载时访问子组件：用 ref + onMounted
import { ref, onMounted } from 'vue'
const childRef = ref()
onMounted(() => {
  // 此时 child.value 已经是子组件实例
  console.log(childRef.value.something)
})

7. 常见面试题 ​

题目答案要点
第一次页面加载会触发哪些钩子beforeCreate → created → beforeMount → mounted
DOM 渲染在哪个钩子完成mounted
父子组件生命周期执行顺序父开始 → 子开始 → 子完成 → 父完成（嵌套）
keep-alive 多出哪两个钩子activated、deactivated
destroyed 和 beforeDestroy 区别destroyed 时组件已经销毁，DOM 不存在；beforeDestroy 时还能访问 this
updated 里能改数据吗可以，但要避免死循环（用条件判断或 nextTick）
为什么 mounted 里能拿到 $refs因为挂载阶段已经完成，DOM 节点已经渲染

8. 项目踩过的坑 ​

  1. 路由切换内存泄漏：mounted 里 addEventListener 或 setInterval，忘了在 beforeDestroy 清理。
  2. ECharts 实例没 dispose：大屏类组件路由切走时没 chart.dispose()，切回来重复 init 导致内存翻倍。
  3. EventBus 解绑漏：父子组件用 $bus 通信，子组件 destroy 时没 $off，事件回调到不存在的组件上。
  4. created 里操作 DOM：this.$el 还不存在，报错 Cannot read property 'xxx' of null。
  5. watch 默认不深度监听：对象内部属性变化不触发回调，必须加 deep: true（或用计算属性）。

9. 真实项目迁移经验 ​

迁移风控平台时，按 7 层迁移顺序处理生命周期：

  1. 全局替换钩子名：beforeDestroy → onBeforeUnmount，destroyed → onUnmounted。
  2. 合并 created + beforeCreate 到 setup：直接搬到 setup() 函数里。
  3. 检查 this 引用：所有 this.xxx 改成显式导入的变量。
  4. 清理 this.$on / this.$off：Vue 3 推荐用 mitt / tiny-emitter 替代 EventBus。
  5. 验证 keep-alive 缓存：钩子名变了，activated/deactivated 也改成新名字。
