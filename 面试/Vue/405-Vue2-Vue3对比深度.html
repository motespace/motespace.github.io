2. 响应式原理对比（核心） ​

2.1 Vue 2：Object.defineProperty ​

js
// Vue 2 响应式实现（简化）
function defineReactive(obj, key, val) {
  const dep = new Dep()  // 依赖收集器

  Object.defineProperty(obj, key, {
    get() {
      dep.depend()       // 收集依赖（谁在用我）
      return val
    },
    set(newVal) {
      if (newVal === val) return
      val = newVal
      dep.notify()       // 通知依赖（用我的人更新了）
    },
  })
}

function observe(obj) {
  Object.keys(obj).forEach(key => defineReactive(obj, key, obj[key]))
}

// 使用
const state = { count: 0 }
observe(state)
state.count = 1  // 触发 set → dep.notify()

2.2 Vue 2 的局限性 ​

js
// ❌ 1. 无法检测对象属性的添加
const vm = new Vue({ data: { user: { name: 'tom' } } })
vm.user.age = 18  // 响应式系统不知道，视图不更新

// 解决方案：Vue.set(vm.user, 'age', 18)

// ❌ 2. 无法检测对象属性的删除
delete vm.user.name  // 不更新

// 解决方案：Vue.delete(vm.user, 'name')

// ❌ 3. 无法检测数组下标变化
vm.list[0] = 'new'  // 不更新
vm.list.length = 0  // 不更新

// Vue 2 重写了 7 个数组方法：push/pop/shift/unshift/splice/sort/reverse
// 这 7 个能触发更新，其他不行

2.3 Vue 3：Proxy ​

js
// Vue 3 响应式实现（简化）
function reactive(target) {
  return new Proxy(target, {
    get(target, key, receiver) {
      track(target, key)  // 收集依赖
      return Reflect.get(target, key, receiver)
    },
    set(target, key, value, receiver) {
      const oldValue = target[key]
      const result = Reflect.set(target, key, value, receiver)
      if (oldValue !== value) {
        trigger(target, key)  // 触发更新
      }
      return result
    },
    deleteProperty(target, key) {
      const result = Reflect.deleteProperty(target, key)
      trigger(target, key)  // 删除也能触发更新
      return result
    },
  })
}

2.4 Vue 3 的改进 ​

js
// ✅ 1. 能监听新增属性
const state = reactive({ user: { name: 'tom' } })
state.user.age = 18  // ✅ 自动响应

// ✅ 2. 能监听删除属性
delete state.user.name  // ✅ 自动响应

// ✅ 3. 能监听数组下标
state.list[0] = 'new'      // ✅
state.list.length = 0       // ✅

// ✅ 4. 能监听 Map / Set
const map = reactive(new Map())
map.set('key', 'value')     // ✅

// ✅ 5. 性能更好
// Proxy 拦截整个对象，不需要遍历所有属性
// Vue 2 初始化时要递归遍历所有 key 做 defineProperty

2.5 ref vs reactive ​

js
// Vue 3 推荐全部用 ref（社区主流方案）
import { ref, reactive } from 'vue'

const count = ref(0)
count.value++  // 访问 .value

// reactive 只在确定是对象时用
const user = reactive({ name: 'tom', age: 18 })
user.age++  // 直接访问属性

// 为什么推荐 ref？
// 1. 原始类型只能 ref（reactive 会报警告）
// 2. ref 可以整体替换，reactive 整体替换会丢响应性
// 3. 模板里 ref 自动解包，reactive 不会自动解包

// ❌ reactive 整体替换丢响应性
let state = reactive({ count: 0 })
state = reactive({ count: 1 })  // ❌ 丢响应性（局部变量重新赋值不影响原对象）

// ✅ ref 可以整体替换
const count = ref(0)
count.value = 1  // ✅

3. 虚拟 DOM 和 Diff 算法 ​

3.1 静态标记（PatchFlag） ​

Vue 3 在编译阶段给虚拟 DOM 打标记，只 diff 动态部分：

js
// Vue 2：编译后
function render() {
  return h('div', [
    h('h1', this.title),
    h('p', { class: 'content' }, this.content),
    h('span', { style: { color: 'red' } }, 'static'),
  ])
}
// diff 时要遍历所有节点对比

// Vue 3：编译后带 patch flag
function render() {
  return h('div', null, [
    h('h1', { key: 1 /* TEXT */ }, this.title),         // 标记 1：文本会变
    h('p', { key: 2 /* CLASS */ }, this.content),      // 标记 2：class 会变
    h('span', null, 'static'),                          // 标记 0：静态节点，直接跳过
  ])
}
// diff 时只对比有标记的节点

结果：跳过静态节点，diff 复杂度从 O(n) 降到接近 O(动态节点数)。

3.2 Block Tree ​

Vue 3 把模板编译成 Block 树，每个 Block 收集动态子节点：

html
<template>
  <div>
    <header>标题</header>      <!-- 静态，不进 Block -->
    <main>
      <p>{{ message }}</p>     <!-- 动态，进 Block -->
      <button @click="onClick">按钮</button>
    </main>
  </div>
</template>

编译后：

Block(root)
  ├── header (静态，跳过)
  └── main
      ├── p [TEXT]
      └── button (事件绑定)

优化：更新时只遍历 Block 内的节点，不递归整个树。

3.3 hoist 静态节点 ​

html
<template>
  <div>
    <span>static</span>      <!-- 被 hoist 到外层，只创建一次 -->
    <span>{{ dynamic }}</span> <!-- 每次重渲染 -->
  </div>
</template>
js
// 编译后
const hoisted = createVNode('span', null, 'static')  // 创建一次
function render() {
  return createVNode('div', null, [
    hoisted,  // 复用
    createVNode('span', null, ctx.dynamic, 1),  // 动态
  ])
}

4.2 写法对比 ​

js
// Vue 2：Options API
export default {
  data() { return { count: 0 } },
  mounted() { console.log('mounted', this.count) },
  beforeDestroy() { console.log('cleanup') },
}

// Vue 3：组合式
import { ref, onMounted, onBeforeUnmount } from 'vue'
export default {
  setup() {
    const count = ref(0)
    onMounted(() => console.log('mounted', count.value))
    onBeforeUnmount(() => console.log('cleanup'))
    return { count }
  },
}

// Vue 3：<script setup>（最简洁）
<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'
const count = ref(0)
onMounted(() => console.log('mounted', count.value))
onBeforeUnmount(() => console.log('cleanup'))
</script>

4.3 父子组件执行顺序变化 ​

text
Vue 2：
  父 beforeCreate → 父 created → 父 beforeMount
    子 beforeCreate → 子 created → 子 beforeMount → 子 mounted
  父 mounted

Vue 3（组合式）：
  父 setup（同步执行）
    子 setup（同步执行）
    子 onMounted
  父 onMounted

变化：setup 是同步的，onMounted 才是挂载后的钩子。

5. API 风格对比 ​

5.1 Options API vs Composition API ​

js
// Vue 2 Options API：相关代码分散到不同选项
export default {
  data() {
    return { count: 0, user: null }
  },
  computed: {
    doubleCount() { return this.count * 2 },
  },
  methods: {
    increment() { this.count++ },
    async fetchUser() { /* ... */ },
  },
  mounted() {
    this.fetchUser()
  },
}

// Vue 3 Composition API：相关代码集中
import { ref, computed, onMounted } from 'vue'

export default {
  setup() {
    const count = ref(0)
    const user = ref(null)

    const doubleCount = computed(() => count.value * 2)

    function increment() { count.value++ }

    async function fetchUser() { /* ... */ }

    onMounted(() => fetchUser())

    return { count, user, doubleCount, increment }
  },
}

5.2 组合式 API 的核心优势 ​

1. 逻辑复用（替代 mixins）

js
// ❌ Vue 2 mixins：命名冲突、隐式依赖
const myMixin = {
  data() { return { count: 0 } },
  methods: { increment() { this.count++ } },
}

// ✅ Vue 3 composable：显式、灵活
function useCounter(initial = 0) {
  const count = ref(initial)
  const increment = () => count.value++
  return { count, increment }
}

// 使用
const { count, increment } = useCounter(10)

2. TypeScript 支持更好

ts
import { ref, Ref } from 'vue'

function useCounter(initial: number = 0): {
  count: Ref<number>
  increment: () => void
} {
  const count = ref(initial)
  return { count, increment: () => count.value++ }
}

3. 代码组织更灵活

js
// 按"功能"组织，而不是按"选项"组织
function UserProfile() {
  // 用户相关
  const user = ref(null)
  async function fetchUser() { /* ... */ }

  // 权限相关
  const permissions = ref([])
  function checkPermission(code: string) { /* ... */ }

  // 表单相关
  const form = reactive({ name: '', email: '' })
  const errors = reactive({})

  return { user, permissions, form, errors }
}

5.3 Options API 不是被淘汰了 ​

js
// Vue 3 同时支持 Options API 和 Composition API
// 小项目 / 老项目维护用 Options API 完全 OK

// 推荐策略：
// - 新项目优先用 <script setup>
// - 老项目维护用 Options API（迁移成本最低）

6. TypeScript 支持对比 ​

6.1 Vue 2 的痛点 ​

ts
// Vue 2 的 data 类型推导非常弱
export default {
  data() {
    return { count: 0, name: 'tom' }  // 类型推导能拿到
  },
  methods: {
    increment() {
      this.count++  // this 的类型是 Vue 实例，没有 count
    },
  },
  // 需要 vue-class-component + vue-property-decorator 才能勉强写
}

6.2 Vue 3 的改进 ​

ts
// <script setup lang="ts"> 全自动推导
<script setup lang="ts">
import { ref, defineProps, defineEmits } from 'vue'

interface Props {
  msg: string
  count?: number
}
const props = defineProps<Props>()  // 类型安全

interface Emits {
  (e: 'change', value: string): void
}
const emit = defineEmits<Emits>()  // 类型安全

const count = ref(0)  // Ref<number>
count.value.toFixed(2)  // ✅ 类型安全
</script>

改进点：

  • defineProps / defineEmits 用泛型声明类型。
  • ref / reactive 自动推导。
  • this 不再需要（组合式 API）。
  • 模板里也能类型检查。

7.1 Fragment：多根节点组件 ​

vue
<!-- Vue 2：必须有单一根节点 -->
<template>
  <div>

<!-- Vue 3：可以有多个根节点 -->

9. 生态对比 ​

9.1 状态管理 ​

js
// Vuex 3/4（Vue 2 / Vue 3 早期）
import { createStore } from 'vuex'

const store = createStore({
  state: { count: 0 },
  mutations: {
    increment(state) { state.count++ },
  },
  actions: {
    incrementAsync({ commit }) {
      setTimeout(() => commit('increment'), 1000)
    },
  },
})

// Pinia（Vue 3 推荐）
import { defineStore } from 'pinia'

export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),
  actions: {
    increment() { this.count++ },
    async incrementAsync() {
      await delay(1000)
      this.count++
    },
  },
})

// 使用
const counter = useCounterStore()
counter.increment()  // 直接调
counter.count        // 直接访问

Pinia 优势：

  • 完整的 TypeScript 支持。
  • 没有 mutations（直接 actions 改 state）。
  • 支持 Composition API 风格（defineStore(id, () => {...})）。
  • 更轻量（~1KB）。

9.2 路由 ​

js
// Vue Router 3（Vue 2）
import VueRouter from 'vue-router'
const router = new VueRouter({
  mode: 'history',
  routes: [...],
})
new Vue({ router }).$mount('#app')

// Vue Router 4（Vue 3）
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(),
  routes: [...],
})
app.use(router)

主要差异：

  • 工厂函数替代 new（更好的 TS 推导）。
  • addRoutes 改成 addRoute（Vue 2 → 3 迁移踩坑点）。
  • 通配符语法变化：path: '*' → path: '/:pathMatch(.*)*'。

10.3 真实迁移经验（来自风控平台项目） ​

迁移前准备：

  1. 盘点 Vue 2 占比：登录页、权限、菜单、核心业务页面占比。
  2. 关键依赖兼容：vue-router、vuex、Element Plus / Element UI、第三方图表库。
  3. 建立灰度发布：双构建并行，老构建回滚快。
  4. 写 codemod 脚本：处理模板层的机械替换（slot / sync / v-deep）。

迁移执行：

js
// 步骤 1：升级依赖
{
  "vue": "^3.4.0",
  "vue-router": "^4.0.0",
  "vuex": "^4.0.0",  // 先升 vuex 4，下一步再迁 pinia
  "element-plus": "^2.0.0",
}

// 步骤 2：替换全局 this 引用
// codemod 处理大部分，剩余手工 review

// 步骤 3：拆分 Options API
// 老组件用 Options API 保留，新组件用 <script setup>
// 长期逐步替换老组件

踩坑清单（完整版见 面试/项目/项目经验/03-智能风控引擎平台.md）：

  1. Vue Router 4 addRoutes 不存在：必须 forEach + addRoute。
  2. v-hasPermi 自定义指令失效：Vue 3 指令 API 变了。
  3. Vue.prototype 改 app.config.globalProperties。
  4. Element Plus 的 el-submenu 重命名为 el-sub-menu。
  5. v-deep 改 :deep()。
  6. 静态资源路径要加 ~ 或 @。
  7. Mock 数据要在生产构建中剔除。

题目答案要点
