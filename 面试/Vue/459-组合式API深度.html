Vue 3 组合式 API ​

Vue 3 最重要的特性。组合式 API 不是新语法，而是"组织代码的方式"。本文按使用频率排序，配真实项目代码。

1. 为什么需要组合式 API ​

Vue 2 的 Options API 把代码按"选项"分块（data、methods、computed、watch），一个功能相关的代码被拆到不同选项里。复杂组件会出现"跳来跳去"的问题。

组合式 API 把同一功能的代码放在一起，更易维护和复用。

vue
<!-- Vue 2 Options API：data / methods / computed 分散 -->
<script>
export default {
  data() {
    return { count: 0, doubleCount: 0 }
  },
  computed: {
    // 和 data 隔了一段
  },
  methods: {
    increment() { /* 和 data 又隔了 */ },
  },
}
</script>

<!-- Vue 3 组合式 API：相关代码集中 -->
<script setup>
import { ref, computed } from 'vue'

const count = ref(0)
const doubleCount = computed(() => count.value * 2)

function increment() {
  count.value++
}
</script>

2. 核心 API ​

2.1 ref 和 reactive ​

ts
import { ref, reactive } from 'vue'

// ref：可以包装任何类型，包括原始类型。访问/修改要用 .value
const count = ref(0)
count.value++  // JS 中
count.value    // JS 中读取

// reactive：只能包装对象。直接访问属性，不需要 .value
const state = reactive({ name: 'tom', age: 18 })
state.age = 19

// 模板里 ref 自动解包，不需要 .value
// <div>{{ count }}</div>  ✅
// <div>{{ count.value }}</div>  ❌ 多余

什么时候用 ref，什么时候用 reactive？

  • 推荐全部用 ref：社区主流方案（Vue 团队官方也建议），因为 reactive 有一些坑（解构失去响应性、不能整体替换等）。
  • reactive 只在确定是对象且不需要整体替换时用。

2.2 computed：缓存的计算属性 ​

ts
import { ref, computed } from 'vue'

const list = ref([1, 2, 3, 4, 5])

// ✅ 计算属性：依赖不变就不重算
const evenList = computed(() => list.value.filter(n => n % 2 === 0))

// ❌ 普通函数：每次访问都重算
const getEvenList = () => list.value.filter(n => n % 2 === 0)

computed vs watch：

  • computed 用于"由其他值算出新值"，有缓存。
  • watch 用于"当某个值变化时执行副作用"，无缓存。

2.3 watch 和 watchEffect ​

ts
import { ref, watch, watchEffect } from 'vue'

const userId = ref(1)
const user = ref(null)

// watch：显式指定监听源 + 回调
watch(userId, async (newId, oldId) => {
  const res = await fetch(`/api/users/${newId}`)
  user.value = await res.json()
}, { immediate: true })  // immediate：立即执行一次

// watchEffect：自动收集依赖，组件挂载时立即执行
const count = ref(0)
watchEffect(() => {
  console.log(`count is ${count.value}`)
  // 自动监听 count
})

watch 三个常用选项：

  • immediate: true：立即执行一次回调（用于"页面加载就拉数据"）。
  • deep: true：深度监听（监听对象内部属性变化）。慎用，性能差。
  • flush: 'post'：回调在 DOM 更新后执行（用于"拿到更新后的 DOM"）。

2.4 生命周期 ​

ts
import { onMounted, onUpdated, onUnmounted } from 'vue'

onMounted(() => {
  console.log('组件挂载')
  // 推荐：异步请求、事件绑定、计时器
})

onUnmounted(() => {
  console.log('组件卸载')
  // 清理计时器、取消请求、解绑全局事件
})

Vue 2Vue 3
beforeCreate不再需要（setup 本身就是）
created不再需要
beforeMountonBeforeMount
mountedonMounted

2.5 组件通信 ​

vue
<!-- 父组件 -->
<script setup lang="ts">
import { ref } from 'vue'
import Child from './Child.vue'

const message = ref('hello')
function handleReply(data: string) {
  console.log('子组件回复:', data)
}
</script>

<template>
  <Child :msg="message" @reply="handleReply" />
</template>

<!-- 子组件 Child.vue -->
<script setup lang="ts">
const props = defineProps<{ msg: string }>()
const emit = defineEmits<{
  (e: 'reply', data: string): void
}>()

function send() {
  emit('reply', 'hi from child')
}
</script>

2.6 defineExpose：暴露给父组件 ​

vue
<!-- 子组件：默认 setup 语法糖下父组件拿不到内部状态 -->
<script setup>
import { ref } from 'vue'
const count = ref(0)
function reset() { count.value = 0 }

// 显式暴露
defineExpose({ count, reset })
</script>

<!-- 父组件：通过 ref 拿到 -->
<script setup>

import Child from './Child.vue'

  console.log(childRef.value.count)
  childRef.value.reset()

<template>
  <Child ref="childRef" />
</template>

3. 实战模式 ​

3.1 自定义 composable（hook） ​

把可复用逻辑抽成 composable，是 Vue 3 最重要的工程能力之一。

ts
// composables/useFetch.ts
import { ref, watchEffect, type Ref } from 'vue'

export function useFetch<T>(url: Ref<string> | string) {
  const data = ref<T | null>(null) as Ref<T | null>
  const error = ref<Error | null>(null)
  const loading = ref(false)

  watchEffect(async () => {
    loading.value = true
    error.value = null
    try {
      const finalUrl = typeof url === 'string' ? url : url.value
      const res = await fetch(finalUrl)
      data.value = await res.json()
    } catch (e) {
      error.value = e as Error
    } finally {
      loading.value = false
    }
  })

  return { data, error, loading }
}

// 使用
const userId = ref(1)
const { data: user, loading } = useFetch<User>(
  computed(() => `/api/users/${userId.value}`)
)

3.2 表单组件封装（真实项目代码） ​

vue
<!-- 表单组件：支持 v-model -->
<script setup lang="ts">
interface Props {
  modelValue: string
  placeholder?: string
  disabled?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  placeholder: '请输入',
  disabled: false,
})

const emit = defineEmits<{
  (e: 'update:modelValue', value: string): void
}>()

function onInput(e: Event) {
  emit('update:modelValue', (e.target as HTMLInputElement).value)
}
</script>

<template>
  <input
    :value="modelValue"
    :placeholder="placeholder"
    :disabled="disabled"
    @input="onInput"
  />
</template>

<!-- 使用：v-model 自动展开为 :modelValue + @update:modelValue -->
<MyInput v-model="username" />

3.4 递归组件 ​

vue
<!-- TreeNode.vue -->
<script setup lang="ts">
interface TreeNode {
  id: string
  label: string
  children?: TreeNode[]
}

defineProps<{
  node: TreeNode
}>()
</script>

<template>
  <div class="tree-node">
    <span>{{ node.label }}</span>
    <!-- 关键：用 v-for 渲染 children，组件名引用自己 -->
    <TreeNode
      v-for="child in node.children"
      :key="child.id"
      :node="child"
    />
  </div>
</template>

文件名必须和组件名一致（TreeNode.vue），且 <script setup> 自动以文件名作为组件名。

4. 常见坑 ​

4.1 解构丢失响应性 ​

ts
import { reactive } from 'vue'

const state = reactive({ count: 0 })

// ❌ 直接解构：count 变成普通 number，丢失响应性
const { count } = state
count++  // 视图不更新

// ✅ 用 toRefs 保留响应性
const { count } = toRefs(state)
count.value++  // ✅
// 或者直接用 state.count++

4.2 ref 的 .value 别在模板里写 ​

vue
<script setup>
import { ref } from 'vue'
const count = ref(0)
</script>

<template>
  <div>{{ count }}</div>      <!-- ✅ 自动解包 -->
  <div>{{ count.value }}</div>  <!-- ❌ 显示 [object Object] / 0 value -->
</template>

例外：作为 props 传递到子组件时，子组件接收到的还是 ref，在子组件里要用 .value。

4.3 shallowRef 和 triggerRef ​

默认 ref 是深响应（对象内部属性变化也会触发更新）。对于大对象 / 第三方实例，应该用 shallowRef 提升性能。

ts
import { shallowRef, triggerRef } from 'vue'

const heavyObj = shallowRef({ list: [...Array(10000)] })

// 修改内部属性不会触发更新
heavyObj.value.list.push(1)

// 必须 triggerRef 手动触发
heavyObj.value.list.push(1)
triggerRef(heavyObj)

4.4 不要在 watch 里修改监听源 ​

ts
// ❌ 死循环：count 变 → watch 触发 → count 又变
watch(count, (newVal) => {
  count.value = newVal + 1
})

// ✅ 用 nextTick 或 computed
watch(count, (newVal) => {
  // 只读
  console.log(newVal)
})

6. 真实项目经验 ​

6.1 风控平台迁移（airisk） ​

把 Vue 2 Options API 全部迁到 Vue 3 组合式 API 的工作量比想象大：

  • 每个 .vue 文件都要重写（Options API → <script setup>），不能 codemod。
  • mixins 替换为 composables：mixins 的命名冲突和隐式依赖很难调试。
  • this 替换为显式导入：this.$refs、this.$emit、this.$store 都要改。
  • type-only props/emits：用 <script setup lang="ts"> 后，类型推导能覆盖 90% 场景。

详见 面试/项目/项目经验/03-智能风控引擎平台.md 的"Vue 2 → Vue 3 迁移"小节。

6.2 组合式 API 的最大好处：跨组件复用 ​

ts
// composables/useTable.ts：抽列表页通用逻辑
export function useTable<T>(fetchApi: (params: any) => Promise<T[]>) {
  const list = ref<T[]>([])
  const loading = ref(false)
  const pagination = reactive({ page: 1, pageSize: 20, total: 0 })
  const searchParams = ref({})

  async function refresh() {
    loading.value = true
    try {
      const res = await fetchApi({ ...searchParams.value, ...pagination })
      list.value = res.list
      pagination.total = res.total
    } finally {
      loading.value = false
    }
  }

  watch([() => pagination.page, () => pagination.pageSize, searchParams], refresh, {
    immediate: true, deep: true,
  })

  return { list, loading, pagination, searchParams, refresh }
}

// 任何列表页都能直接用
const { list, loading, pagination, searchParams } = useTable(fetchUsers)

这是 Options API 时代 mixins 几乎做不到的：mixins 没法传参数，composable 可以。
