微信小程序是什么？和 H5 的区别是什么？

📚 深度专题推荐：本文是关于「小程序基础架构」的精炼回答。面试高频题，重点理解双线程模型。

一、微信小程序是什么？

Section titled “一、微信小程序是什么？”

一种运行在微信内部的应用形态：

  • 不需要下载安装（用户扫一扫 / 搜一搜直接打开）
  • 不是 H5，也不是原生 App，是介于两者之间的特殊形态
  • 使用 WXML + WXSS + JS（类 HTML + CSS + JS 的自定义方言）

二、双线程架构（核心）

Section titled “二、双线程架构（核心）”

两个线程的分工

Section titled “两个线程的分工”
线程 负责 不能做
视图线程（WebView） 渲染 WXML/WXSS、处理用户交互 不能直接调用 wx API
逻辑线程（JSCore） 执行 JS 业务逻辑、调用 wx API 不能直接操作 DOM
Native 层 提供 wx API、文件、网络、存储等系统能力 —

为什么是双线程？

Section titled “为什么是双线程？”
  1. 安全：JS 在沙箱里跑，不能直接操作 DOM（防 XSS / 跳转）
  2. 可控：渲染层由 WebView 管理，逻辑层由微信管控 → App 行为可控
  3. 流畅：逻辑层不阻塞渲染层（异步通信）

JSBridge 通信流程（重要）

Section titled “JSBridge 通信流程（重要）”

三、和 H5 的区别

Section titled “三、和 H5 的区别”
维度 H5 小程序
运行环境 浏览器 微信（WebView + JSCore 双线程）
渲染 HTML + CSS WXML + WXSS（类 HTML/CSS）
开发语言 JS JS（无 DOM/BOM API）
系统能力 受浏览器限制 wx.* API（扫码、定位、支付、获取微信用户信息等）
性能 一般 比 H5 快（双线程隔离 + 预加载）
体积限制 无 单包 2MB（主包），总计 16MB
上线审核 否 需要微信审核
入口 URL 扫码、搜一搜、分享卡

四、为什么小程序启动快？

Section titled “四、为什么小程序启动快？”
  1. 预加载 WebView：用户访问过的小程序，微信会缓存 WebView
  2. 资源预下载：分包加载，主包 + 分包
  3. 双线程隔离：逻辑层不阻塞渲染层

五、面试追问

Section titled “五、面试追问”

Q：双线程有什么缺点？

A：线程间通信有序列化开销，频繁 setData 会卡顿。所以 setData 要尽量：

  • 单次设置多个字段（合并）
  • 数据量不能太大（建议 < 256KB）
  • 不要在循环里调用

Q：小程序可以操作 DOM 吗？

A：不能。微信沙箱环境不暴露 DOM/BOM API。只能通过 this.setData() 更新数据 → 框架 diff → 视图更新。

Q：小程序的 WXML 和 HTML 的核心区别？

A：

  • WXML 用 &lt;view&gt; &lt;text&gt; 而不是 <div> <span>（性能优化）
  • 标签属性用 bindtap 而不是 onclick
  • 数据绑定用 {{}}，类似 Vue 的 Mustache
  • 支持 wx:if、wx:for 指令

📝 小结

Section titled “📝 小结”
  • 小程序的核心是双线程架构:逻辑层(JSCore/V8)与视图层(WebView)分离,通过 Native 层转发数据与事件。
  • 因此 setData 是跨线程通信:数据要序列化后传给视图层,再由视图层 diff 更新 DOM——这是小程序性能问题的根源。
  • 与 H5 的差异:无 DOM 操作、渲染层不能发请求(受合法域名限制)、有平台 API 差异、包体积与审核限制、启动更快(无需下载 HTML/CSS/JS)。
  • 面试加分:能说清「双线程带来的通信成本决定了小程序必须少 setData」,这条是原理层的关键。
