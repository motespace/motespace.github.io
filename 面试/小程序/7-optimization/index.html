八、面试追问

Section titled “八、面试追问”

Q：小程序怎么定位性能问题？

A：

  1. 微信开发者工具 → 性能 Trace 工具
  2. setData 数据监测（开发者工具控制台）
  3. vConsole（移动端调试）
  4. 埋点上报关键指标（首屏时间、setData 次数）

Q：分包加载的优缺点？

A：

  • ✅ 启动快（只下载主包）
  • ✅ 包体积灵活（总 16MB）
  • ❌ 首次进入分包页面有加载延迟（需要 preloadRule 预下载）
  • ❌ 跨分包通信麻烦（用 globalData 或 storage）

Q：独立分包 vs 普通分包？

A：

  • 普通分包：必须依赖主包，进入分包前会下载主包
  • 独立分包：不依赖主包，可以单独加载（适合营销活动页、临时入口）

Q：小程序能跑 WebAssembly 吗？

A：小程序基础库 2.13+ 支持 WASM，适合图像处理、加密算法等场景。

📝 小结

Section titled “📝 小结”
  • 官方指标:启动耗时(小程序启动性能评分)、页面渲染耗时、包体积(主包 ≤ 2MB,总包 ≤ 20MB)、setData 频率与数据量。
  • 启动优化:减少启动时同步任务与首屏请求、预请求、分包(subpackages)、预下载包、组件按需注入、独立分包。
  • 运行时优化:setData 最小化(路径写法、分页、合并)、列表用 recycle-view 或分页、避免 wx.createSelectorQuery 频繁调用。
  • 图片优化:用云开发/CDN、压缩与 WebP、按屏幕尺寸给 srcset、避免大 base64。
  • 网络优化:合并请求、缓存静态数据、弱网重试与超时、预请求。
  • 超限处理:主包瘦身(分包 + 组件按需 + 移除未用依赖 + 资源外置 CDN),并说明「分包首屏要预下载」。
  • 面试加分:给出「包体积从 2.4MB 降到 1.6MB 的具体手段」。
