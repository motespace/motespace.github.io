小程序 setData 原理是什么？有什么坑？

📚 深度专题推荐：本文是关于「小程序数据绑定 / setData」的精炼回答。高频中的高频，性能优化的核心。

一、setData 是什么？

Section titled “一、setData 是什么？”

this.setData(data, callback) 把数据从逻辑层发送到视图层，触发 WXML 重新渲染。

二、setData 原理

Section titled “二、setData 原理”

关键点

Section titled “关键点”
  1. 跨线程通信：逻辑层 → 视图层，有序列化 / 网络开销
  2. 不是实时的：setData 是异步的，视图更新在下一个渲染帧
  3. callback 在视图更新完成后执行

六、面试追问

Section titled “六、面试追问”

Q：setData 为什么是异步的？

A：因为跨线程通信有延迟。逻辑层发出 setData 后立刻返回，不等视图层真正更新。视图层在下一次渲染帧统一处理。这是为了避免阻塞逻辑层。

Q：怎么同步拿到 setData 后的值？

A：

  1. 用 callback（推荐）
  2. 直接用 this.data.xxx（注意：setData 之后的下一行，this.data 已经是新值）

Q：data 和 properties 的区别？

A：

  • data：组件内部数据，类似 Vue 的 data
  • properties：父组件传的 props，不能直接修改（单向数据流），要修改需要用 this.setData({ propertiesField: ... })

Q：列表渲染用什么？为什么不用 v-for？

A：用 wx:for，类似 Vue 的 v-for。建议始终指定 wx:key，相当于 React 的 key，提升 diff 性能。

📝 小结

Section titled “📝 小结”
  • setData 的原理:把数据从逻辑层序列化传到视图层,视图层做 diff 后更新节点——数据量大时序列化与 diff 都很贵。
  • 性能坑:一次 setData 传整个对象(应只传变化字段)、高频小步 setData(应合并)、在 setData 后立刻读 DOM(渲染未完成)、key 缺失导致全量 diff、大数组整体替换。
  • 路径写法:setData({ 'a.b[0].c': v }) 支持路径表达式,能减少传输量;this.setData 的第二个回调可在渲染完成后执行。
  • 数据量参考:单次 setData 建议 ≤ 64KB(社区经验值),列表页应分页而非一次 setData 全部。
  • 面试加分:讲清「渲染是异步的」——setData 后马上读 DOM 拿到的是旧值,要用回调。
