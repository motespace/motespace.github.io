Pinia 是什么？和 Vuex 比有什么区别？

📚 深度专题推荐：本文是关于「Pinia」的精炼回答。Vue 3 官方推荐的状态管理方案，逐步替代 Vuex。

一、Pinia 是什么？

Section titled “一、Pinia 是什么？”

Pinia 是 Vue 官方（Vue.js 团队成员 Eduardo San Martin Morote）开发的新一代状态管理库，Vue 3 官方推荐。

🎯 核心定位：Vuex 5 的精神继承者，但是重写过的，去掉了 Vuex 的 mutations、modules 嵌套等冗余设计。

二、和 Vuex 的核心区别

Section titled “二、和 Vuex 的核心区别”
维度 Vuex 4 Pinia
API 风格 Options（state/getters/mutations/actions） 组合式（类似 setup 函数）
mutations ✅ 必须（同步） ❌ 去掉，actions 可同步可异步
模块化 modules + namespaced 每个 store 天然独立
TypeScript 一般 ✅ 一等公民，类型推断完美
体积 ~10KB ~1KB
Composition API 一般 ✅ 原生适配
持久化 插件实现 插件实现（更简单）
devtools ✅ ✅
热更新 需配置 ✅ 默认支持

四、为什么去掉 mutations？

Section titled “四、为什么去掉 mutations？”

Vuex 4 设计：actions → commit → mutations → state Pinia 设计：actions → state（一步到位）

理由：

  • mutations 本质就是同步函数，强制分层意义不大
  • TypeScript 推断更友好
  • devtools 依然能追踪所有 state 变更（Pinia 通过 Proxy 拦截）

七、面试追问

Section titled “七、面试追问”

Q：为什么 Vue 3 推荐 Pinia 而不是 Vuex 5？

A：实际上 Pinia 原本就是 Vuex 5 的草稿，后来独立发布。官方认为 mutations 分层是历史包袱，Pinia 直接 actions 改 state 更简洁，TypeScript 推断更好。

Q：Pinia 怎么实现的响应式？

A：内部用 Vue 3 的 reactive() 把 state 包成 Proxy 代理，actions 通过 Object.assign 绑定 this，getters 用 computed。

Q：Pinia 在大型项目怎么组织？

A：按业务领域划分 stores（每个领域一个文件），通过 useXxxStore() 跨领域组合。例如：

  • stores/user.ts（用户）
  • stores/cart.ts（购物车）
  • stores/product.ts（商品）

Q：为什么用 storeToRefs 解构？

A：Pinia 的 store 是一个 reactive 对象，直接解构会丢失响应式（如 { name } = userStore）。storeToRefs 类似 toRefs，把每个属性变成 ref。

📝 小结

Section titled “📝 小结”
  • Pinia 是 Vue 3 的官方状态管理,也是 Vuex 的继任者;Vuex 在 Vue 3 里已停止新功能,官方推荐 Pinia。
  • 核心差异:去掉 mutations(直接改 state)、去掉 module 嵌套(改为多个扁平 store)、TypeScript 推导更好、支持 SSR、体积更小。
  • 结构:defineStore('id', { state, getters, actions }) 或 setup 写法;setup 写法能自由组合组合式 API,更适合复杂逻辑。
  • 状态修改:store.count++ 或 store.increment();跨 store 调用直接 useOtherStore()。
  • 持久化用插件订阅 store.$subscribe 写入 localStorage,或用 pinia-plugin-persistedstate。
  • 面试话术:从「Vuex 的痛点(mutations 冗余、嵌套 modules、TS 支持差)」讲到「Pinia 怎么解决」,比直接背 API 有说服力。
