Vue 3 组合式 API

Vue 3 最重要的特性。组合式 API 不是新语法，而是“组织代码的方式”。本文按使用频率排序，配真实项目代码。

1. 为什么需要组合式 API

Section titled “1. 为什么需要组合式 API”

Vue 2 的 Options API 把代码按“选项”分块（data、methods、computed、watch），一个功能相关的代码被拆到不同选项里。复杂组件会出现“跳来跳去”的问题。

组合式 API 把同一功能的代码放在一起，更易维护和复用。

2. 核心 API

Section titled “2. 核心 API”

2.1 ref 和 reactive

Section titled “2.1 ref 和 reactive”

什么时候用 ref，什么时候用 reactive？

  • 推荐全部用 ref：社区主流方案（Vue 团队官方也建议），因为 reactive 有一些坑（解构失去响应性、不能整体替换等）。
  • reactive 只在确定是对象且不需要整体替换时用。

2.2 computed：缓存的计算属性

Section titled “2.2 computed：缓存的计算属性”

computed vs watch：

  • computed 用于“由其他值算出新值”，有缓存。
  • watch 用于“当某个值变化时执行副作用”，无缓存。

2.3 watch 和 watchEffect

Section titled “2.3 watch 和 watchEffect”

watch 三个常用选项：

  • immediate: true：立即执行一次回调（用于“页面加载就拉数据”）。
  • deep: true：深度监听（监听对象内部属性变化）。慎用，性能差。
  • flush: 'post'：回调在 DOM 更新后执行（用于“拿到更新后的 DOM”）。

2.4 生命周期

Section titled “2.4 生命周期”

Vue 2 → Vue 3 生命周期重命名：

Vue 2 Vue 3
beforeCreate 不再需要（setup 本身就是）
created 不再需要
beforeMount onBeforeMount
mounted onMounted
beforeUpdate onBeforeUpdate
updated onUpdated
beforeDestroy onBeforeUnmount
destroyed onUnmounted

6. 真实项目经验

Section titled “6. 真实项目经验”

6.1 风控平台迁移（airisk）

Section titled “6.1 风控平台迁移（airisk）”

把 Vue 2 Options API 全部迁到 Vue 3 组合式 API 的工作量比想象大：

  • 每个 .vue 文件都要重写（Options API → &lt;script setup&gt;），不能 codemod。
  • mixins 替换为 composables：mixins 的命名冲突和隐式依赖很难调试。
  • this 替换为显式导入：this.$refs、this.$emit、this.$store 都要改。
  • type-only props/emits：用 &lt;script setup lang="ts"&gt; 后，类型推导能覆盖 90% 场景。

详见 面试/项目/项目经验/03-智能风控引擎平台.md 的“Vue 2 → Vue 3 迁移”小节。

6.2 组合式 API 的最大好处：跨组件复用

Section titled “6.2 组合式 API 的最大好处：跨组件复用”

这是 Options API 时代 mixins 几乎做不到的：mixins 没法传参数，composable 可以。

面试常考

Section titled “面试常考”
题目 答案要点
组合式 API vs Options API 逻辑组织 / 复用 / TS 支持
ref vs reactive 推荐全部 ref；reactive 解构丢响应性
computed vs watch computed 是算出值（缓存），watch 是副作用
watchEffect vs watch 自动收集依赖 vs 显式指定
解构丢响应性怎么解决 toRefs 或不解构
为什么 Vue 3 用 Proxy 替代 Object.defineProperty 能监听数组下标、新增/删除属性

📝 小结

Section titled “📝 小结”
  • 组合式 API 的价值是按逻辑组织代码而不是按选项类型:同一个业务关注点的响应式数据、计算属性、方法可以写在一起,还能抽成 composable 复用。
  • 核心 API:ref/reactive、computed、watch/watchEffect、provide/inject、defineProps/defineEmits、defineExpose、生命周期钩子。
  • 组合式函数(composable)约定:命名 useXxx、参数用 reactive 或普通对象、返回 readonly 状态与操作方法。
  • 常见坑:reactive 解构丢失响应式、watch 里改被监听数据、composable 里忘记 onUnmounted 清理定时器。
  • 性能优化:把不需要响应式的数据用 markRaw/shallowRef,避免大对象深度响应式。
  • 面试话术:能讲出「我封装了哪个 useXxx,在哪个项目解决了什么复用问题」,比背 API 强得多。
