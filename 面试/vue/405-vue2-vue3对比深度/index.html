Vue 2 vs Vue 3 对比

简历里写了“主导风控平台 Vue 2 → Vue 3 + Vite 迁移”，这是面试必问的对比题。本文按“原理 → API → 生态 → 性能 → 迁移”五个维度展开，配真实代码和迁移经验。

1. 核心差异总览

Section titled “1. 核心差异总览”
维度 Vue 2 Vue 3
响应式原理 Object.defineProperty Proxy
虚拟 DOM 完整 diff 优化（编译时标记提升）
API 风格 Options API Composition API + Options API
TypeScript 弱支持 一等公民
生命周期 8 个钩子 重命名 + 组合式 setup
状态管理 Vuex 3/4 Pinia（官方推荐）
路由 Vue Router 3 Vue Router 4
构建工具 Webpack Vite（官方推荐）
包体积 ~22KB ~10KB（gzip 后）
性能 一般 提升 1.3-2 倍
Fragment ❌ ✅
Teleport ❌ ✅
Suspense ❌ ✅
多 v-model ❌ ✅

10.3 真实迁移经验（来自风控平台项目）

Section titled “10.3 真实迁移经验（来自风控平台项目）”

迁移前准备：

  1. 盘点 Vue 2 占比：登录页、权限、菜单、核心业务页面占比。
  2. 关键依赖兼容：vue-router、vuex、Element Plus / Element UI、第三方图表库。
  3. 建立灰度发布：双构建并行，老构建回滚快。
  4. 写 codemod 脚本：处理模板层的机械替换（slot / sync / v-deep）。

迁移执行：

踩坑清单（完整版见 面试/项目/项目经验/03-智能风控引擎平台.md）：

  1. Vue Router 4 addRoutes 不存在：必须 forEach + addRoute。
  2. v-hasPermi 自定义指令失效：Vue 3 指令 API 变了。
  3. Vue.prototype 改 app.config.globalProperties。
  4. Element Plus 的 el-submenu 重命名为 el-sub-menu。
  5. v-deep 改 :deep()。
  6. 静态资源路径要加 ~ 或 @。
  7. Mock 数据要在生产构建中剔除。

12. 面试常考

Section titled “12. 面试常考”
题目 答案要点
Vue 3 响应式为什么用 Proxy 能监听新增/删除属性、数组下标、Map/Set
Proxy 有什么缺点 浏览器兼容性差（IE11 不支持）；Proxy 不能监听非对象
Vue 3 性能提升在哪 静态提升 + PatchFlag + Block Tree + tree-shaking
Composition API 优势 逻辑复用、TS 支持、代码组织
父子组件 setup 执行顺序 父 setup → 子 setup → 子 onMounted → 父 onMounted
Vuex vs Pinia Pinia 无 mutations / TS 友好 / 轻量
Vue 2 数组响应式问题 重写 7 个数组方法，其他方式（索引、length）不响应
为什么 Pinia 替代 Vuex TypeScript 支持更好 / 无 mutations / 组合式风格

📝 小结

Section titled “📝 小结”
  • 响应式原理是最大差异:Vue 2 用 Object.defineProperty(无法拦截新增属性与数组下标,需要 Vue.set/Vue.delete),Vue 3 用 Proxy(全量拦截,天然支持新增/删除/数组)。
  • 编译优化:Vue 3 模板编译会打上 PatchFlag 与静态提升,只 diff 动态绑定的部分;Vue 2 全量 diff。
  • 生命周期改名:beforeDestroy/destroyed → beforeUnmount/unmounted;created 里拿不到 DOM,mounted 才能。
  • API 风格:Vue 3 保留选项式同时引入 Composition API,<script setup> 是当前推荐。
  • 新特性:Fragment(多根节点)、Teleport(传送 DOM)、Suspense(异步组件)、ref 自动解包、Proxy 响应式。
  • 性能:Vue 3 更小更快(Proxy + 编译期优化 + Tree-shaking),但 Vue 2 的 Options API 在存量项目里依然稳定。
  • 面试话术:先讲响应式差异(能延伸到 Proxy 拦截与依赖收集),再讲编译优化,最后落到迁移成本与团队规范。
