Vuex 是什么？5 大核心模块是什么？

📚 深度专题推荐：本文是关于「Vuex」的精炼回答。如需了解 Vue 3 推荐的状态管理方案 Pinia，请阅读 Pinia 介绍（如有补充）。

一、Vuex 是什么？

Section titled “一、Vuex 是什么？”

Vuex 是 Vue 官方的集中式状态管理库，解决多组件共享状态的痛点。

适用场景：

  • 多个组件依赖同一个状态
  • 来自不同组件的行为要变更同一份状态

二、5 大核心模块

Section titled “二、5 大核心模块”
模块 作用 类比
state 存放共享状态 data
getters state 的派生值（可缓存） computed
mutations 同步修改 state 的唯一途径 methods（同步）
actions 提交 mutations，可异步 methods（异步）
modules 状态分模块管理 —

1. state

Section titled “1. state”

组件读取：this.$store.state.count 或 mapState(['count'])

2. getters

Section titled “2. getters”

3. mutations（唯一可同步改 state 的地方）

Section titled “3. mutations（唯一可同步改 state 的地方）”

触发：this.$store.commit('increment', { step: 1 })

⚠️ 为什么 mutations 必须同步？ 因为 devtools 依赖 mutation 的执行顺序记录状态快照，异步会导致追踪错乱。

4. actions（异步 + 业务逻辑）

Section titled “4. actions（异步 + 业务逻辑）”

触发：this.$store.dispatch('fetchUser', 123)

5. modules（分模块）

Section titled “5. modules（分模块）”

使用：this.$store.state.user.name / this.$store.commit('user/SET_NAME')

Section titled “三、数据流（严格单向）”

⚠️ 组件不能直接改 state，必须通过 commit 触发 mutation。

Section titled “四、辅助函数（少写模板代码）”

五、严格模式（开发环境建议开启）

Section titled “五、严格模式（开发环境建议开启）”

开启后：任何 mutation 之外的方式修改 state 都会报错（便于追踪所有 state 变更）。

六、面试追问

Section titled “六、面试追问”

Q：为什么 mutation 必须同步，action 可以异步？

A：Vuex 内部用 Vue 的响应式 + devtools 追踪。如果 mutation 异步，devtools 不知道何时算“结束”，状态快照会错乱。action 内部调 commit 触发 mutation，仍然保持 mutation 同步。

Q：组件可以直接修改 state 吗？为什么？

A：技术上可以（state 是响应式的），但不应该。原因：

  1. 严格模式下会报错
  2. 状态变更不可追踪，无法调试
  3. 破坏单向数据流的设计

Q：Vuex 和全局 eventBus 有什么区别？

A：

  • eventBus：事件驱动，松散，但大型项目容易乱
  • Vuex：集中式管理，所有状态变更都过 store，可预测、可调试

Q：Vuex 4 相比 Vue 3 有变化吗？

A：API 基本一致，主要变化：

  • 用 createStore 替代 new Vuex.Store
  • 全面支持 TypeScript 类型推断
  • 安装方式改为 app.use(store)
  • 与 Vue 3 响应式系统对齐

Q：为什么 Vue 3 官方推荐 Pinia 而不是 Vuex？

A：详见 Pinia 完整介绍。一句话：Pinia 更轻、组合式风格、TypeScript 友好、自动 tree-shaking。

📝 小结

Section titled “📝 小结”
  • Vuex 五大核心:state(状态)、getters(派生)、mutations(同步改状态)、actions(异步/副作用)、modules(模块化)。
  • 数据流严格单向:dispatch → action → commit → mutation → state 变化 → getter/render 更新;组件里只能 commit/dispatch,不能直接改 state。
  • mutations 必须是同步的,因为 devtools 依赖它做时间旅行调试;异步逻辑放 actions。
  • 辅助函数:mapState/mapGetters/mapMutations/mapActions,减少模板里的重复写法。
  • namespaced: true 让模块有独立命名空间,避免 action/mutation 名冲突;模块间通信用 rootState 或命名空间前缀。
  • 严格模式(strict: true)在开发环境检测是否在 mutation 外改了 state,是很好的实践。
  • 面试话术:讲清「为什么要有 mutations」(可追踪、可 devtools、可严格模式)比直接说「五大模块」有深度。
