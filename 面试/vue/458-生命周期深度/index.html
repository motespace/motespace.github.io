8. 项目踩过的坑

Section titled “8. 项目踩过的坑”
  1. 路由切换内存泄漏：mounted 里 addEventListener 或 setInterval，忘了在 beforeDestroy 清理。
  2. ECharts 实例没 dispose：大屏类组件路由切走时没 chart.dispose()，切回来重复 init 导致内存翻倍。
  3. EventBus 解绑漏：父子组件用 $bus 通信，子组件 destroy 时没 $off，事件回调到不存在的组件上。
  4. created 里操作 DOM：this.$el 还不存在，报错 Cannot read property 'xxx' of null。
  5. watch 默认不深度监听：对象内部属性变化不触发回调，必须加 deep: true（或用计算属性）。

9. 真实项目迁移经验

Section titled “9. 真实项目迁移经验”

迁移风控平台时，按 7 层迁移顺序处理生命周期：

  1. 全局替换钩子名：beforeDestroy → onBeforeUnmount，destroyed → onUnmounted。
  2. 合并 created + beforeCreate 到 setup：直接搬到 setup() 函数里。
  3. 检查 this 引用：所有 this.xxx 改成显式导入的变量。
  4. 清理 this.$on / this.$off：Vue 3 推荐用 mitt / tiny-emitter 替代 EventBus。
  5. 验证 keep-alive 缓存：钩子名变了，activated/deactivated 也改成新名字。

详见 面试/项目/项目经验/03-智能风控引擎平台.md 的“Vue 2 → Vue 3 迁移”小节。

📝 小结

Section titled “📝 小结”
  • 8 个核心钩子按序:beforeCreate → created → beforeMount → mounted → beforeUpdate → updated → beforeDestroy → destroyed,父子组件是「父 beforeCreate → 子 beforeCreate → 子 created → 子 beforeMount → 子 mounted → 父 mounted」。
  • keep-alive 包裹时,组件不会 unmount,改用 activated / deactivated。
  • updated 里改数据会触发再次更新甚至死循环,应改数据源或用 nextTick。
  • 迁移 Vue 3:beforeDestroy/destroyed → beforeUnmount/unmounted,并新增 beforeUnmount 用于清理定时器。
  • 项目实践:请求放 created,依赖 DOM 的初始化放 mounted,定时器与监听在 beforeUnmount 清理。
  • 面试话术:被问「父子组件生命周期顺序」时,能背出挂载是子先、销毁是父先(父 beforeDestroy → 子 beforeDestroy → 子 destroyed → 父 destroyed)。
