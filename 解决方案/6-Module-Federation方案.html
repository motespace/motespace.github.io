Module Federation 完整实战 ​

跨应用共享模块的现代方案：Webpack 5 / Vite 都能用。 本文按"原理 → 配置 → 实战"组织。

一、Module Federation 是什么 ​

1.1 解决的问题 ​

应用 A 有个 Button 组件
应用 B 也想要
传统方案：
  - 抽到 npm 包 + 升级 + 重新部署 A 和 B
  - 改业务代码同步

MF 方案：
  - 应用 A 暴露 Button
  - 应用 B 直接 import('@app-a/Button') 远程加载
  - 不用发布、不用重启

1.2 核心概念 ​

  • Host（容器）：消费远程模块的应用
  • Remote（远程）：暴露模块的应用
  • Shared：共享依赖（React、Vue、组件库等）

二、架构 ​

应用 A（Host）
  ↓ import('appB/Button')
应用 B（Remote）暴露 Button
  ↓ 运行时加载
应用 B 把 Button + 依赖打包成单独 chunk

三、Webpack 5 配置 ​

3.1 应用 B（Remote） ​

js
// webpack.config.js
const { ModuleFederationPlugin } = require('webpack').container

module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: 'appB',
      filename: 'remoteEntry.js',
      exposes: {
        './Button': './src/components/Button',
        './utils': './src/utils/index',
      },
      shared: {
        react: { singleton: true, requiredVersion: '^18.0.0' },
        'react-dom': { singleton: true, requiredVersion: '^18.0.0' },
      },
    }),
  ],
}

3.2 应用 A（Host） ​

js
// webpack.config.js
module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: 'appA',
      remotes: {
        appB: 'appB@http://localhost:8081/remoteEntry.js',
      },
      shared: {
        react: { singleton: true, requiredVersion: '^18.0.0' },
        'react-dom': { singleton: true, requiredVersion: '^18.0.0' },
      },
    }),
  ],
}

3.3 使用远程组件 ​

jsx
// appA/src/App.jsx
import React, { lazy, Suspense } from 'react'

// 异步加载远程 Button
const RemoteButton = lazy(() => import('appB/Button'))

function App() {
  return (
    <div>
      <h1>应用 A</h1>
      <Suspense fallback={<div>Loading...</div>}>
        <RemoteButton>Click me</RemoteButton>
      </Suspense>
    </div>
  )
}

四、Vite Federation（Vite 版） ​

Vite 通过 @originjs/vite-plugin-federation 插件支持 MF。

4.1 应用 B（Remote） ​

ts
// vite.config.ts
import { federation } from '@originjs/vite-plugin-federation'

export default defineConfig({
  plugins: [
    federation({
      name: 'appB',
      filename: 'remoteEntry.js',
      exposes: {
        './Button': './src/components/Button.vue',
      },
      shared: {
        vue: { singleton: true },
      },
    }),
  ],
  build: {
    target: 'esnext',
    cssCodeSplit: false,
  },
})

4.2 应用 A（Host） ​

ts
import { federation } from '@originjs/vite-plugin-federation'

export default defineConfig({
  plugins: [
    federation({
      name: 'appA',
      remotes: {
        appB: {
          type: 'module',
          entry: 'http://localhost:5174/assets/remoteEntry.js',
          format: 'esm',
        },
      },
      shared: {
        vue: { singleton: true },
      },
    }),
  ],
})

4.3 使用 ​

vue
<script setup>
import { defineAsyncComponent } from 'vue'

const RemoteButton = defineAsyncComponent(() => import('appB/Button'))
</script>

<template>
  <RemoteButton>点击</RemoteButton>
</template>

五、Shared 详解 ​

5.1 Singleton（单例） ​

js
shared: {
  react: {
    singleton: true,  // ⬅️ 强制单例（Host 用一个版本）
    requiredVersion: '^18.0.0',
  },
}

为什么需要：如果 A 用 React 18，B 用 React 19，Hook 会炸。

5.2 Eager（急切加载） ​

js
shared: {
  'react-dom': {
    singleton: true,
    eager: false,  // ⬅️ 异步加载（默认）
  },
}

eager: true：同步加载，启动时阻塞 eager: false（默认）：异步加载，按需加载

5.3 Version 协商 ​

js
shared: {
  react: {
    singleton: true,
    requiredVersion: '^18.0.0',  // Host 需要 18.x
  },
}
  • 如果 Remote 有 18.2.0，Host 有 18.3.0 → 用 18.3.0
  • 如果 Remote 有 17.0.0 → 报错（不兼容）

六、TypeScript 支持 ​

6.1 声明远程模块 ​

ts
// appA/src/remote-modules.d.ts
declare module 'appB/Button' {
  import { FC } from 'react'
  const Button: FC<{ children?: React.ReactNode }>
  export default Button
}

declare module 'appB/utils' {
  export function formatDate(d: Date): string
  export function formatMoney(n: number): string
}

6.2 自动生成类型 ​

bash
# 使用 Module Federation 工具生成类型
npx mf-typescript-generator --output ./src/remote-modules.d.ts

七、运行时流程 ​

应用 A 启动
  ↓
加载 remoteEntry.js（B 的入口清单）
  ↓
首次 import('appB/Button')
  ↓
webpack runtime 下载 Button chunk
  ↓
解析依赖（React、shared）
  ↓
校验版本（singleton）
  ↓
执行组件代码，挂载
  ↓
后续 import 直接复用

八、性能优化 ​

8.1 预加载 Remote ​

js
// 启动时预加载，但不在首屏用
import('appB/Button')

8.2 异步边界 + Suspense ​

jsx
<Suspense fallback={<Skeleton />}>
  <RemoteButton />
</Suspense>

8.3 CDN 部署 ​

appB 的 remoteEntry.js 上 CDN
所有应用通过 CDN 加载（不直连 B 的服务器）

8.4 缓存 ​

HTTP 强缓存 + Service Worker 缓存 remoteEntry.js

九、调试技巧 ​

9.1 跨应用 source map ​

js
// webpack.config.js
{
  devtool: 'source-map',
  optimization: {
    minimize: false,
  },
}

9.2 Chrome DevTools ​

  • Network：看 remoteEntry.js、Button.chunk.js 加载情况
  • Sources：Webpack 5 会把远程模块也展示在 Sources 里
  • Console：__webpack_require__.cache 可以看运行时缓存

9.3 错误处理 ​

jsx
const RemoteButton = lazy(() =>
  import('appB/Button').catch(() => ({
    default: () => <div>应用 B 加载失败，请刷新</div>,
  }))
)

十、实战案例 ​

10.1 设计系统跨应用共享 ​

设计系统（Remote）：暴露 Button / Form / Modal / Table
电商前台（Host）：消费设计系统
管理后台（Host）：消费设计系统
营销活动（Host）：消费设计系统

10.2 工具库共享 ​

utils 包（Remote）：暴露 lodash / dayjs / http
所有应用（Host）：消费 utils

10.3 微前端 + MF 共享 ​

主应用 → qiankun 注册子应用
子应用 1 → MF 暴露业务组件
子应用 2 → 通过 MF 消费子应用 1 的组件

十一、常见坑 ​

11.1 版本冲突 ​

Remote 用 React 18.2，Host 用 React 18.3
shared: { react: { singleton: true } }
→ 加载时用 Host 的 18.3，Remote 内部代码可能在某些 API 上行为不同

解决：把所有应用锁版本。

11.2 CSS 隔离 ​

MF 不会自动隔离 CSS，多个应用都用 Button 时样式冲突。

解决：CSS Modules + 命名空间（.appA-Button）。

11.3 全局状态冲突 ​

如果 Remote 用了 localStorage，多个应用覆盖。

解决：用 namespace（appA.userInfo）。

11.4 循环依赖 ​

A 远程加载 B，B 又远程加载 A。

解决：抽出共享层（MF 自身设计就要求 Shared 单例）。

十二、面试高频追问 ​

Q1: Module Federation 和 npm 共享组件区别？ ​

答：

  • npm：编译时依赖，发布一次需要所有应用升级
  • MF：运行时依赖，Remote 升级 Host 自动用新版本
  • 选型：稳定不变 → npm（如 lodash）/频繁迭代 → MF（如业务组件）

Q2: Module Federation 和 qiankun 区别？ ​

答：

  • MF：共享模块（组件、工具），子应用还是独立部署
  • qiankun：完整微前端（独立应用 + 沙箱 + 路由）
  • 可以组合用：qiankun 子应用之间用 MF 共享组件库

Q3: MF 性能怎么样？ ​

答：

  • 首次加载稍慢（要拉远程 chunk）
  • 二次访问极快（HTTP 缓存 + SW 缓存）
  • 适合大型项目，小型项目用 npm 就好

Q4: MF 怎么控制 Remote 版本？ ​

答：通过 shared 的 requiredVersion + CI 测试。Remote 发版时跑 Host 集成测试。

Q5: Vite 用 MF 有什么坑？ ​

答：

  • vite-plugin-federation 不支持动态 chunk 名（要先手动 split）
  • ESM/CJS 混用需要 target: 'esnext'
  • 调试比 Webpack 麻烦

面试追问(深化原 Q1-Q5) ​

  • Module Federation 原理? Webpack/Rollup 插件;运行时加载远程模块(类似 dynamic import)
  • 共享依赖机制? 配置 shared: { react: { singleton: true } };主应用 React 被子应用复用
  • MF vs npm 包发布? npm:编译时集成,版本锁死;MF:运行时集成,版本灵活
  • MF 落地坑? 共享依赖版本冲突、CSS 不隔离、调试复杂

📝 小结 ​

  • Module Federation 不是微前端框架,而是构建期的模块共享机制:把一个应用的模块暴露给另一个应用运行时加载。
  • 核心配置:name(容器标识)、filename、两个 exposes/shared;运行时靠 remoteEntry.js 建立容器协议。
  • shared 的关键参数:required(是否必须一致)、singleton(全局唯一)、eager(是否立即加载)、version(版本策略)。
  • 版本冲突的解法:用 singleton + version 强制共享同一份,或者用 required 报错快速暴露问题,而不是运行时诡异行为。
  • 性能坑:共享配置不当会重复加载依赖(React 加载两份 → hooks 报错);要用 eager 与预加载控制首屏。
  • 调试:开 devtools、看 window.__webpack_share_scopes__、用 publicPath 解决资源路径问题。
  • 与微前端的区别:联邦是「共享」,qiankun 是「隔离」;真实项目通常两者混用。
