前端可观测性 0-1 方案（监控/埋点/错误上报） ​

配套解决方案文档：从零搭建一个生产级前端可观测性 SDK，覆盖错误监控 + 性能监控 + 用户行为埋点三大支柱，同时给出 React 17+ 和 Vue 3 完整实现。

一、为什么需要前端可观测性 ​

现代前端应用已经不再是纯静态页面，而是承担了业务核心链路。当线上出问题时：

  • 不知道用户操作路径（复现不了）
  • 不知道真实性能（用户机器千差万别）
  • 不知道错误规模（多少用户受影响）

三大支柱：

  • 错误监控：JS 异常 / Promise 拒绝 / 资源加载失败 / SSR 异常
  • 性能监控：Web Vitals（FCP/LCP/INP/CLS）/ Long Task / 自定义时长
  • 用户行为埋点：PV/UV / 按钮点击 / 页面停留 / 转化漏斗

业界方案对比：

方案优势劣势
Sentry错误监控最强，DevTools 完善性能监控弱、埋点需自己写
阿里云 ARMS性能 + 错误一体贵、私有化难
字节 RUM字节内部验证，吞吐大主要服务字节系
自研 SDK灵活可控、贴合业务维护成本高

什么时候该自研：

  • 业务有独特埋点需求（细粒度控制）
  • 数据敏感不能上 SaaS
  • 想要统一数据仓库（不分散到多家）

二、整体架构 ​

4 层架构：

┌─────────────────────────────────────────────────────────┐
│  第 1 层：采集层（前端 SDK）                                │
│  ├─ 错误捕获（window.onerror / unhandledrejection）         │
│  ├─ 性能采集（PerformanceObserver）                         │
│  └─ 行为埋点（DOM 监听 / React Fiber / Vue Proxy）          │
└─────────────────────────────────────────────────────────┘
                          ↓ HTTP/JSON or Beacon
┌─────────────────────────────────────────────────────────┐
│  第 2 层：上报网关                                          │
│  ├─ 鉴权（项目 token）                                      │
│  ├─ 限流（防 SDK 异常导致雪崩）                              │
│  └─ 字段校验（防前端注入）                                   │
└─────────────────────────────────────────────────────────┘
                          ↓ Kafka
┌─────────────────────────────────────────────────────────┐
│  第 3 层：数据服务                                          │
│  ├─ 实时聚合（错误数 / 性能 P95 / 漏斗）                      │
│  ├─ 离线分析（Spark / ClickHouse）                          │
│  └─ 告警（阈值 / 同比）                                    │
└─────────────────────────────────────────────────────────┘
                          ↓ Query
┌─────────────────────────────────────────────────────────┐
│  第 4 层：可视化                                            │
│  ├─ 错误大盘（聚合 / 单条详情 / SourceMap）                  │
│  ├─ 性能趋势（Web Vitals / 长任务）                         │
│  └─ 行为分析（漏斗 / 路径 / 留存）                          │
└─────────────────────────────────────────────────────────┘

关键设计原则：

  • 采集不影响业务：埋点 SDK 必须容错，不能反过来报错
  • 数据最终一致：网络抖动可丢，不可阻塞主线程
  • 隐私合规：GDPR / 个保法，敏感字段脱敏
  • 可降级：SDK 加载失败不影响页面功能

3.1 通用事件模型 ​

typescript
// 任何事件都有这 7 个基础字段
interface BaseEvent {
  /** 事件唯一 ID（UUID） */
  eventId: string
  /** 事件类型：click / pageView / error / performance / ... */
  eventType: string
  /** 客户端时间戳（ms） */
  timestamp: number
  /** 项目 / 应用标识 */
  project: string
  /** 当前页面 URL */
  url: string
  /** 设备信息 */
  device: DeviceInfo
  /** 用户信息 */
  user: UserInfo
}

interface DeviceInfo {
  platform: 'PC' | 'H5' | 'Android' | 'iOS' | 'WebView' | 'PWA'
  osName: string
  osVersion: string
  deviceModel: string
  userAgent: string
  networkType: 'wifi' | '5g' | '4g' | '3g' | '2g' | 'unknown'
  screenSize: { width: number; height: number }
  timezone: string
}

interface UserInfo {
  /** 匿名 ID（未登录也能追踪） */
  anonymousId: string
  /** 登录账号（可选） */
  account?: string
  /** 自定义维度（VIP 等级、AB 组等） */
  dimensions?: Record<string, string | number>
}

// packages/sdk/src/throttle.ts
export class RateLimiter {
  private count = 0
  private resetTime = Date.now()
  constructor(private maxPerMinute: number) {}

  pass(): boolean {
    const now = Date.now()
    if (now - this.resetTime >= 60_000) {
      this.count = 0
      this.resetTime = now
    }
    if (this.count >= this.maxPerMinute) return false
    this.count++
    return true
  }
}

5.2 React Fiber 遍历 ​

typescript
// packages/sdk/src/auto-track/react.ts
/**
 * React 17+ 事件委托到 root 容器,DOM 上读不到 onClick
 * 必须从 DOM 找到 React Fiber,再沿 fiber.return 链往上找带 onClick 的组件
 */
export function setupReactAutoTrack(meta: () => Record<string, any>) {
  document.addEventListener('click', (e) => {
    let node = e.target as any
    while (node && node !== document.body) {
      // React 内部挂在 DOM 节点上的 Fiber 引用
      const fiberKey = Object.keys(node).find(
        k => k.startsWith('__reactFiber$') || k.startsWith('__reactInternalInstance$')
      )
      if (!fiberKey) {
        node = node.parentNode
        continue
      }

      const fiber = node[fiberKey]
      // 沿 fiber.return 链往上回溯
      let current = fiber
      while (current) {
        const onClick = current.memoizedProps?.onClick || current.pendingProps?.onClick
        if (onClick) {
          const componentName = current.type?.name || current.elementType?.name
          sdk.track({
            eventType: 'click',
            properties: {
              component: componentName,
              text: (e.target as HTMLElement).textContent?.slice(0, 100),
            },
            meta: meta(),
          })
          return
        }
        current = current.return
      }
      return
    }
  }, true)
}

// packages/sdk/src/error/index.ts
import { classifyError } from './utils/error'

export function setupErrorMonitor(config: SDKConfig, rateLimiter: RateLimiter) {
  if (typeof window === 'undefined') return

  // 监听 JS 错误(捕获阶段)
  window.addEventListener('error', (e) => {
    handleError(e, config, rateLimiter)
  }, true)

  // 监听 Promise 拒绝
  window.addEventListener('unhandledrejection', (e) => {
    const fakeEvent = {
      error: e.reason instanceof Error ? e.reason : new Error(String(e.reason)),
      message: e.reason?.message || String(e.reason),
      filename: '',
      lineno: 0,
      colno: 0,
    } as ErrorEvent
    handleError(fakeEvent, config, rateLimiter)
  })

  // 监听资源加载错误
  window.addEventListener(
    'error',
    (e) => {
      const target = e.target as HTMLElement
      if (target && target !== window && 'src' in target) {
        handleError(e, config, rateLimiter)
      }
    },
    true
  )
}

function handleError(e: Event, config: SDKConfig, rateLimiter: RateLimiter) {
  // 1. 采样
  if (Math.random() > config.errorSampleRate) return

  // 2. 分类
  const { errorType, data } = classifyError(e)

  // 3. 过滤
  if (config.ignoreErrors.some(p => p.test(data.message || ''))) return
  if (config.ignoreUrls.some(p => p.test(data.fileName || ''))) return

  // 4. 限流
  if (!rateLimiter.pass()) return

  // 5. 构造事件
  const event: ErrorEvent = {
    eventId: generateUUID(),
    eventType: 'error',
    errorType,
    timestamp: Date.now(),
    project: config.project,
    url: location.href,
    device: getDeviceInfo(),
    user: getUserInfo(),
    ...data,
  }

  // 6. 用户自定义 hook
  const processed = config.beforeSend?.(event)
  if (!processed) return

  // 7. 上报
  report(processed, config)
}

// packages/sdk/src/transport/index.ts
import { reportQueue } from './queue'

export function report(event: BaseEvent, config: SDKConfig) {
  if (!navigator.onLine) {
    reportQueue.push(event)
    return
  }

  switch (config.transport) {
    case 'beacon':
      reportByBeacon(event, config)
      break
    case 'xhr':
      reportByXHR(event, config)
      break
    case 'fetch':
    default:
      reportByFetch(event, config)
  }
}

function reportByBeacon(event: BaseEvent, config: SDKConfig) {
  // Beacon 优点:浏览器关闭页面也能发;缺点:payload 限制 64KB
  const blob = new Blob([JSON.stringify(event)], { type: 'application/json' })
  const success = navigator.sendBeacon(config.reportUrl, blob)
  if (!success) {
    reportByFetch(event, config)
  }
}

function reportByFetch(event: BaseEvent, config: SDKConfig) {
  // 用 fetch + keepalive 保证页面卸载时也能完成
  fetch(config.reportUrl, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(event),
    keepalive: true,  // 关键:允许 unload 后继续
  }).catch(() => {
    reportQueue.push(event)
  })
}

9.2 离线缓存与重试 ​

// packages/sdk/src/transport/queue.ts
const STORAGE_KEY = '__obs_queue__'
const MAX_QUEUE_SIZE = 100

export const reportQueue: BaseEvent[] = loadQueue()

function loadQueue(): BaseEvent[] {
  try {
    const data = localStorage.getItem(STORAGE_KEY)
    return data ? JSON.parse(data) : []
  } catch {
    return []
  }
}

function saveQueue() {
  try {
    if (reportQueue.length > MAX_QUEUE_SIZE) {
      reportQueue.splice(0, reportQueue.length - MAX_QUEUE_SIZE)
    }
    localStorage.setItem(STORAGE_KEY, JSON.stringify(reportQueue))
  } catch {
    // localStorage 满(quota exceeded)静默
  }
}

export function pushQueue(event: BaseEvent) {
  reportQueue.push(event)
  saveQueue()
}

export function drainQueue() {
  if (reportQueue.length === 0) return
  if (!navigator.onLine) return

  const batch = reportQueue.splice(0, reportQueue.length)
  fetch(getConfig().reportUrl, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ events: batch }),
  }).then(() => {
    saveQueue()
  }).catch(() => {
    reportQueue.unshift(...batch)
    saveQueue()
  })
}

if (typeof window !== 'undefined') {
  window.addEventListener('online', drainQueue)
  setTimeout(drainQueue, 5_000)
}

/**
 * 在路由切换时自动上报 pageView + pageLeave
 */
export function usePageView(pageName: string, properties?: object) {
  const router = useRouter()
  const startRef = useRef(Date.now())

  useEffect(() => {
    const handleStart = (url: string) => {
      sdk.track({
        eventType: 'pageLeave',
        properties: { page: pageName, stayDuration: Date.now() - startRef.current },
      })
    }

    const handleComplete = (url: string) => {
      setTimeout(() => {
        const loadTime = performance.now()
        sdk.track({
          eventType: 'pageView',
          properties: {
            page: pageName,
            url,
            loadTime,
            ...properties,
          },
        })
        startRef.current = Date.now()
      }, 50)
    }

    router.events.on('routeChangeStart', handleStart)
    router.events.on('routeChangeComplete', handleComplete)

    return () => {
      router.events.off('routeChangeStart', handleStart)
      router.events.off('routeChangeComplete', handleComplete)
    }
  }, [pageName, router])
}

/**
 * 真实生产级 Page Analytics Hook
 * 处理:路由切换 / 计时 / 防双发 / ref 持久化

export const usePageAnalytics = (platform: Platform) => {
  const router = useRouter()

  // 原因:每秒更新计时若用 setState,会触发整个组件 re-render
  const pageLoadStartRef = useRef<number>(Date.now())      // 页面进入时间
  const pageLoadTimeRef = useRef<number>(0)              // 本次加载耗时
  const stayDurationRef = useRef<number>(0)              // 停留时长
  const stayTimerRef = useRef<NodeJS.Timeout | null>(null) // 计时器
  const anonymousIdRef = useRef<string>('')              // 匿名 ID
  const accountRef = useRef<string | undefined>(undefined)

  // ===== 防双发:useRef 持久化(不会因 re-render 重置) =====
  const pageLoadSentRef = useRef<boolean>(false)
  const pageLeaveSentRef = useRef<boolean>(false)

  const fromRef = useRef<string | null>(null)
  const toRef = useRef<string>(router.asPath)

  /** 匿名 ID:第一次访问生成 UUID,持久化到 localStorage */
  const getOrCreateAnonymousId = useCallback((): string => {
    if (typeof window === 'undefined') return ''
    try {
      const STORAGE_KEY = 'anonymousId'
      let id = localStorage.getItem(STORAGE_KEY)
      if (!id) {
        id = `h5-${uuidv4()}`                              // ← 加 h5- 前缀便于排查
        localStorage.setItem(STORAGE_KEY, id)
      }
      return id
    } catch { return '' }
  }, [])

  /** 50ms 延迟:确保新页面 DOM 已渲染(关键性能细节) */
  const calculateLoadTime = useCallback(() => {
    const loadTime = performance.now() - pageLoadStartRef.current
    pageLoadTimeRef.current = loadTime
    pageLoadSentRef.current = false  // 重置,允许新页面发
  }, [])

  /** 离开旧页面前发 pageLeave */
  const handlePageLeave = useCallback((fromRoute: string) => {
    if (pageLeaveSentRef.current) return  // ← 防双发关键
    try {
      const finalStayDuration = Date.now() - pageLoadStartRef.current
      stayDurationRef.current = finalStayDuration
      sdk.track({
        eventType: 'pageLeave',
        properties: {
          page: fromRoute,
          stayDuration: finalStayDuration,  // 毫秒
          anonymousId: anonymousIdRef.current,
          account: accountRef.current,
        },
      })
      pageLeaveSentRef.current = true
    } catch (e) { /* 静默 */ }
  }, [])

  useEffect(() => {
    // 监听路由开始:离开旧页
    const handleRouteChangeStart = (url: string) => {
      handlePageLeave(router.asPath)
      pageLoadStartRef.current = Date.now()  // 重置起点
    }

    // 监听路由完成:50ms 后发 pageLoad(等 DOM)
    const handleRouteChangeComplete = () => {
      setTimeout(() => {
        if (document.readyState === 'complete') {
          sdk.track({
            eventType: 'pageView',
            properties: {
              page: toRef.current,
              pageLoadTime: pageLoadTimeRef.current,
              anonymousId: anonymousIdRef.current,
              account: accountRef.current,
              networkType: getNetworkType(),
              deviceModel: osName,
            },
          })
        }
      }, 50)  // ← 50ms 关键值
    }

    router.events.on('routeChangeStart', handleRouteChangeStart)
    router.events.on('routeChangeComplete', handleRouteChangeComplete)

    // 离开页面兜底
    window.addEventListener('beforeunload', () => {
      handlePageLeave(router.asPath)
    })

    return () => {
      router.events.off('routeChangeStart', handleRouteChangeStart)
      router.events.off('routeChangeComplete', handleRouteChangeComplete)
    }
  }, [router, handlePageLeave])
}

关键设计点：

  • 全部用 useRef 不触发 re-render（每秒更新计时）
  • pageLeaveSentRef 防止 routeChangeStart + beforeunload 双触发
  • 50ms 延迟确保新页面渲染完
  • anonymousId 用 h5-${uuid} 格式加前缀方便排查

10.7 React Fiber 自动遍历埋点(项目独有) ​

React 17+ 事件委托到 root 容器,DOM 上读不到 onClick。真实方案是从 DOM 反查 React Fiber,沿 fiber.return 链向上找带 onClick 的组件：

typescript
// packages/sdk-react/src/auto-track/react.ts
/**
 * 零业务侵入的自动埋点
 * 原理:DOM 节点上有 React 内部引用 `__reactFiber$xxx`,
 * 沿 Fiber.return 链向上回溯,找到最近的带 onClick 的组件
 */
export function setupReactAutoTrack(meta: () => Record<string, any>) {
  document.addEventListener('click', (e) => {
    let node = e.target as any
    while (node && node !== document.body) {
      // 1. 找 DOM 上的 React Fiber 引用
      const fiberKey = Object.keys(node).find(
        (k) => k.startsWith('__reactFiber$') || k.startsWith('__reactInternalInstance$')
      )
      if (!fiberKey) {
        node = node.parentNode
        continue
      }

      // 2. 沿 fiber.return 链往上找有 onClick 的组件
      const fiber = node[fiberKey]
      let currentFiber = fiber
      while (currentFiber) {
        const onClick = currentFiber.memoizedProps?.onClick || currentFiber.pendingProps?.onClick
        if (onClick) {
          // 3. 找到了!触发埋点(业务代码无需任何改动)
          const componentName = currentFiber.type?.name || currentFiber.elementType?.name
          sdk.track({
            eventType: 'click',
            properties: {
              component: componentName,           // 自动捕获"哪个组件"
              text: (e.target as HTMLElement).textContent?.slice(0, 100),
            },
            meta: meta(),
          })
          return  // 一次只算一次,防重复
        }
        currentFiber = currentFiber.return  // 父 Fiber
      }
      return
    }
  }, true)  // ← 第 3 参数 true:捕获阶段注册
}

10.8 高级节流(leading + trailing) ​

300ms 是埋点场景的黄金值:能合并"连点 5 下",但又不会丢"最后一下点击"：

typescript
// packages/sdk/src/throttle.ts
/**
 * Throttle(不是 debounce)
 * - leading: 头部立即触发(第 1 下立刻发)
 * - trailing: 尾部补一次(最后 1 下不丢)
 * - cancel: 支持取消(组件卸载清理)
 */
function throttle<F extends (...args: any[]) => any>(
  fn: F,
  delay: number,
): (...args: Parameters<F>) => ReturnType<F> | void {
  let lastCallTime = 0
  let timeoutId: ReturnType<typeof setTimeout> | null = null
  let pendingArgs: Parameters<F> | null = null
  let pendingThis: unknown

  const throttled = function (this: unknown, ...args: Parameters<F>): ReturnType<F> | void {
    const now = Date.now()
    const timeSinceLastCall = now - lastCallTime

    if (timeSinceLastCall < delay) {
      // 在节流窗口内:暂存最新参数,等末尾补发
      pendingArgs = args
      pendingThis = this
      if (!timeoutId) {
        // 尾部补一次 — 防止"最后一下点击"被丢掉
        timeoutId = setTimeout(() => {
          lastCallTime = Date.now()
          if (pendingArgs) fn.apply(pendingThis, pendingArgs)
          timeoutId = null
          pendingArgs = null
        }, delay - timeSinceLastCall)
      }
      return
    }

    // 头部立即触发
    lastCallTime = now
    return fn.apply(this, args)
  }

  // 支持 cancel(防止组件卸载后 timer 还在跑)
  throttled.cancel = () => {
    if (timeoutId) {
      clearTimeout(timeoutId)
      timeoutId = null
      pendingArgs = null
    }
  }
  return throttled
}

关键差异:

  • throttle:头部立即 + 尾部补 1 次(适合埋点)
  • debounce:只在停顿时触发 1 次(会丢"最后一下"点击)

实战:连点 5 下按钮,throttle 发 2 条(头部 1 + 尾部 1),debounce 只发 1 条(最后 1 下)。

interface TrackBinding {
  /** 事件名(必填) */
  name: string
  /** 额外属性(可选) */
  properties?: Record<string, any>

export const VTrack: Directive<HTMLElement, TrackBinding> = {

11.8 Vue Router 完整追踪(替代 React 的 routeChange) ​

Vue 3 + Vue Router 的页面追踪比 Next.js 更简单,一次注册就行:

typescript
// packages/sdk-vue/src/composables/usePageTracking.ts
import { onMounted, watch, ref } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import type { ObsVueInstance } from '../plugin'

/**
 * 一行 usePageTracking() 自动追踪:
 * - 进入页面(pageLoad)
 * - 离开页面(pageLeave)
 * - URL query 变化(也是 pageView)
 */
export function usePageTracking() {
  const obs = inject<ObsVueInstance>('obs')
  const route = useRoute()
  const router = useRouter()

  const enterTime = ref(Date.now())
  const pageLoadTime = ref(0)

  // 进入页面
  const trackEnter = () => {
    enterTime.value = Date.now()
    // 50ms 后算 pageLoadTime(等 DOM 渲染)
    setTimeout(() => {
      pageLoadTime.value = performance.now() - enterTime.value
      obs?.track('pageView', {
        path: route.path,
        query: route.query,
        pageLoadTime: pageLoadTime.value,
        // 自动捕获路由 meta(如果业务方在路由配了埋点标签)
        meta: route.meta,
      })
    }, 50)
  }

  // 离开页面
  const trackLeave = () => {
    const stayDuration = Date.now() - enterTime.value
    obs?.track('pageLeave', {
      path: route.path,
      stayDuration,
    })
  }

  // 首次加载
  onMounted(trackEnter)

  // 监听路由变化
  watch(
    () => route.path,
    (newPath, oldPath) => {
      if (oldPath) trackLeave()  // 离开旧页
      trackEnter()                  // 进入新页
    }
  )

  // 路由守卫拦截(可选,业务方可重写)
  router.beforeEach((to, from, next) => {
    if (from.path) trackLeave()  // 浏览器前进后退也触发
    next()
  })
}

  }, 5000)
})

onUnmounted(() => {
  // 离开页面:清理 timer + 上报最终停留时长
  clearInterval(timer)
  track('detail_leave', { totalStayTime: stayTime.value })
})

// 关键:Vue Router 切页时,组件会触发 onUnmounted
// 这就是天然的 pageLeave 时机,不用手动监听 route
</script>

优势:

  • 自动绑定到 Vue 组件生命周期
  • 无需手动监听 beforeRouteLeave 或 unmounted
  • timer / event listener 自动清理,无内存泄漏
  • 每个页面独立追踪,不污染全局

十五、面试高频问题 ​

Q1: 为什么不用 Sentry 而要自研？ ​

  1. 业务有独特埋点需求,Sentry 只能做错误
  2. 数据敏感不能上 SaaS
  3. 想统一数据仓库(不分散多家)
  4. 学习成本:自研过程中深入理解浏览器机制(Fiber 遍历、PerformanceObserver)

Q2: React 17+ 事件委托到 root 后怎么找到 onClick？ ​

  • DOM 上读不到 onClick
  • 用 __reactFiber$xxx 内部属性找到 React Fiber
  • 沿 fiber.return 链往上回溯到最近的带 onClick 的组件
  • 这是 React 内部约定,源码里有

Q3: 怎么防止告警风暴？ ​

  • 采样:按比例采样(性能 10%、错误 100%)
  • 限流:每分钟最多 N 条(我们用 30)
  • 去重:相同 stack 5 分钟内只报 1 次
  • 用户级:单用户单日最多 100 条

Q4: 上报失败怎么处理？ ​

  • 离线缓存:localStorage 排队,online 事件重发
  • 降级:连续失败 5 次后停止上报(防死循环)
  • 超时:单次上报 5s 超时(不影响页面)
  • Beacon:页面卸载时优先用 sendBeacon(保证发出)

Q5: SDK 怎么保证不影响主业务？ ​

  • try-catch 包所有回调:SDK 出错不能反过来影响业务
  • 静默日志:用 console.warn 而非 console.error(不触发监控)
  • 防重入:单例 + freeze 防止业务方修改
  • 独立队列:上报和业务用不同 fetch

Q6: 性能监控为什么不全采？ ​

  • 数据量大:1000 用户 * 60 指标 * 24h = 144 万条/天
  • 采样足够:P75 指标 10% 采样误差 < 5%
  • 关键指标全采:错误、LCP 差值变化
  • 降级方案:差网络环境(2g/3g)不上报

Q7: SSR 错误怎么监控？ ​

  • 服务端没有 window,监听不到 error
  • 在 getServerSideProps / loader 里手动 captureError
  • 用 fetch 上报(没有 sendBeacon)
  • dev 环境故意 throw,prod 静默上报

Q8: 你自研 SDK 踩过哪些坑？ ​

  • 类型坑:ErrorEvent 的 error 字段可能不存在
  • 跨域坑:Script error.(跨域 script)拿不到 stack
  • 循环引用坑:JSON.stringify 抛错(unhandledrejection 里的 reason)
  • 包大小坑:SDK 越大影响 LCP,要 tree-shake 友好
  • 版本坑:埋点 schema 演进用 beforeSend 兼容老版本
