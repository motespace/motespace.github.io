2.2 统一错误捕获 ​

ts
// src/core/error-reporter.ts
class ErrorReporter {
  init() {
    // 1. 全局 JS 错误
    window.addEventListener('error', (e) => {
      this.report({
        type: 'js_error',
        message: e.message,
        stack: e.error?.stack,
        lineno: e.lineno,
        colno: e.colno,
        filename: e.filename,
      })
    })

    // 2. Promise 异常
    window.addEventListener('unhandledrejection', (e) => {
      this.report({
        type: 'promise_error',
        message: e.reason?.message ?? String(e.reason),
        stack: e.reason?.stack,
      })
    })

    // 3. 资源加载错误（捕获阶段才能监听到）
    window.addEventListener(
      'error',
      (e) => {
        if (e.target !== window) {
          const target = e.target as HTMLElement
          this.report({
            type: 'resource_error',
            tagName: target.tagName,
            src: (target as any).src || (target as any).href,
          })
        }
      },
      true  // ⬅️ capture 阶段
    )
  }

  async report(error: ErrorPayload) {
    await fetch('/api/report/error', {
      method: 'POST',
      body: JSON.stringify({
        ...error,
        userId: getUserId(),
        url: location.href,
        userAgent: navigator.userAgent,
        timestamp: Date.now(),
        appVersion: APP_VERSION,
      }),
    })
  }
}

2.3 Vue / React 错误边界 ​

React 错误边界 ​

tsx
import { ErrorInfo } from 'react'

class ErrorBoundary extends React.Component {
  state = { hasError: false }

  static getDerivedStateFromError() {
    return { hasError: true }
  }

  componentDidCatch(error: Error, info: ErrorInfo) {
    reportError({
      type: 'react_error',
      error,
      componentStack: info.componentStack,
    })
  }

  render() {
    if (this.state.hasError) return <ErrorPage />
    return this.props.children
  }
}

3.4 自定义业务指标 ​

ts
// src/core/performance-marker.ts
export function markStart(name: string) {
  performance.mark(`${name}_start`)
}

export function markEnd(name: string) {
  performance.mark(`${name}_end`)
  performance.measure(name, `${name}_start`, `${name}_end`)

  const measure = performance.getEntriesByName(name)[0]
  report({
    type: 'custom_metric',
    name,
    duration: measure.duration,
  })
}

// 用法
markStart('data-fetch')
fetchUser().then(() => markEnd('data-fetch'))

六、报警策略 ​

6.1 错误报警 ​

阈值：
- JS 错误率 > 1%（次/分钟）
- Promise 异常 > 5 次/分钟
- 特定错误出现 1 次立即报警（critical error）

方式：
- 钉钉 / 飞书机器人
- 企业微信群
- 邮件 / 短信

6.2 性能报警 ​

- LCP > 4s 占比 > 5%
- 接口 P95 > 1s
- 首屏时间 > 3s 占比 > 10%

7.3 上报队列 ​

ts
class ReportQueue {
  private queue: ReportPayload[] = []
  private flushInterval = 5000

  constructor(private url: string) {
    setInterval(() => this.flush(), this.flushInterval)
  }

  push(payload: ReportPayload) {
    this.queue.push(payload)
    if (this.queue.length >= 20) this.flush()  // 满 20 立即上报
  }

  async flush() {
    if (this.queue.length === 0) return
    const batch = this.queue.splice(0, 50)  // 取最多 50 条
    try {
      await fetch(this.url, {
        method: 'POST',
        body: JSON.stringify(batch),
      })
    } catch {
      // 失败放回队列
      this.queue.unshift(...batch)
      // 备份到 localStorage
      this.backup(batch)
    }
  }
}

八、面试高频追问 ​

Q1: 前端怎么监控错误？ ​

答：3 类捕获：window.onerror（运行时）、unhandledrejection（Promise）、资源加载错误（capture 阶段）。上报到后端 + Sentry。

Q2: Web Vitals 怎么测？ ​

答：用 web-vitals 库，监听 LCP / INP / CLS / FCP / TTFB。

Q3: 线上错误怎么定位？ ​

答：

  • Sentry Source Map 还原堆栈
  • 用户上下文（userId、sessionId、URL、UA）
  • 复现路径（用户操作录屏 / 行为日志）

Q4: 报警阈值怎么定？ ​

答：

  • 错误率 > 1% 报警（基于历史均值 + 2σ）
  • LCP P95 > 4s 报警
  • 关键路径断流立即报警

Q5: 监控系统怎么保证稳定？ ​

答：

  • 上报失败放 localStorage，下次启动重发
  • 上报队列有上限，避免内存爆炸
  • 异步、不阻塞主流程
  • try/catch 包裹上报逻辑

面试追问(深化原 Q1-Q5) ​

  • 前端监控 3 类? 错误(JS/网络/资源)、性能(FP/FCP/LCP/INP)、行为(UV/PV/转化)
  • Web Vitals 核心 3 指标? LCP(最大内容绘制 < 2.5s)、INP(交互延迟 < 200ms)、CLS(视觉稳定 < 0.1)
  • 真实用户 vs 实验室数据? 真实 RUM 采样各端;实验室(Lighthouse)固定环境;互补使用
  • 错误去重? 同一错误只上报一次:基于错误信息 hash + 用户 ID;避免风暴

📝 小结 ​

  • 监控三大类:错误(崩溃与异常)、性能(加载与运行)、行为(PV/点击/转化),三者要能按 sessionId 关联。
  • 错误监控:全局 error + unhandledrejection + 框架 ErrorBoundary 三层兜底,采集堆栈与版本。
  • 性能监控:Web Vitals(LCP/INP/CLS)+ 资源加载 + 接口耗时 + 首屏时间。
  • 行为监控:用统一事件模型(event + params)而不是每个业务写一套上报。
  • 报警策略:阈值 + 同比环比 + 告警分级,配合 Sentry 的 Issue 聚合(相同堆栈自动合并)降低噪音。
  • SDK 要点:体积、异步上报、采样、去重、失败重试、navigator.sendBeacon 兜底。
  • 面试加分:讲「怎么把告警噪音降下来」——聚合、阈值动态化、按影响用户数分级。
