MCP 协议客户端集成 ​

MCP（Model Context Protocol）是 2025 年新兴的 LLM 工具标准化协议——让 LLM 调任何外部工具就像调 HTTP API。 本文按"MCP 是什么 → 前端集成 → 实战"组织。

一、MCP 是什么 ​

MCP（Model Context Protocol） 由 Anthropic 开源（2024-11），定位是 "LLM 应用的 USB-C 接口"——统一 LLM 与外部工具/数据源的协议。

1.1 为什么需要 MCP ​

传统 Function Calling：
  - 每个 LLM（GPT/Claude/Gemini）有自己的 tools 格式
  - 每个工具要写一遍
  - 工具不能跨 LLM 复用

MCP：
  - LLM 侧：MCP Client（Anthropic SDK / Vercel AI SDK）
  - 工具侧：MCP Server（暴露 tools / resources / prompts）
  - 工具**一次实现，多 LLM 复用**

1.2 架构 ​

┌─────────────┐         ┌──────────────┐         ┌─────────────┐
│  LLM Client │ ──MCP──│  MCP Server  │ ──API───│  外部工具    │
│  (Claude)   │         │ (你的工具集) │         │  (数据库等) │
└─────────────┘         └──────────────┘         └─────────────┘
  • MCP Server：暴露 tools（函数）、resources（数据）、prompts（模板）
  • MCP Client：连接 MCP Server，让 LLM 调用

二、MCP Server 实现 ​

2.1 安装 SDK ​

bash
npm install @modelcontextprotocol/sdk

2.2 最小 Server ​

ts
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js'
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js'
import { z } from 'zod'

const server = new McpServer({
  name: 'my-tools',
  version: '1.0.0',
})

// 注册工具
server.tool(
  'get_weather',
  '查询指定城市天气',
  {
    city: z.string().describe('城市名'),
  },
  async ({ city }) => {
    const res = await fetch(`/api/weather?city=${city}`)
    const data = await res.json()
    return {
      content: [
        {
          type: 'text',
          text: `${city} 当前温度 ${data.temp}°C，湿度 ${data.humidity}%`,
        },
      ],
    }
  }
)

// 启动
const transport = new StdioServerTransport()
await server.connect(transport)

2.3 暴露 Resources（数据源） ​

ts
server.resource(
  'user-profile',
  'user://me',
  async (uri) => {
    const user = await db.users.findOne({ id: 'me' })
    return {
      contents: [
        {
          uri: uri.href,
          text: JSON.stringify(user),
          mimeType: 'application/json',
        },
      ],
    }
  }
)

2.4 暴露 Prompts（模板） ​

ts
server.prompt(
  'summarize',
  '总结一段文本',
  {
    text: z.string(),
  },
  ({ text }) => ({
    messages: [
      {
        role: 'user',
        content: {
          type: 'text',
          text: `请用 3 句话总结：\n\n${text}`,
        },
      },
    ],
  })
)

三、前端集成 MCP Client ​

3.1 浏览器侧 MCP 客户端 ​

MCP 默认走 stdio（命令行），浏览器侧要走 HTTP / WebSocket。

bash
npm install @modelcontextprotocol/sdk

3.2 HTTP 传输 ​

ts
import { Client } from '@modelcontextprotocol/sdk/client/index.js'
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp.js'

const client = new Client({
  name: 'my-app',
  version: '1.0.0',
})

const transport = new StreamableHTTPClientTransport(
  new URL('https://my-mcp-server.com/mcp')
)

await client.connect(transport)

// 列出所有可用工具
const tools = await client.listTools()

// 调用工具
const result = await client.callTool({
  name: 'get_weather',
  arguments: { city: '北京' },
})

3.3 React Hook ​

ts
import { useEffect, useState, useCallback } from 'react'

export function useMcpClient(serverUrl: string) {
  const [client, setClient] = useState<Client | null>(null)
  const [tools, setTools] = useState<any[]>([])
  const [isReady, setIsReady] = useState(false)

  useEffect(() => {
    let cancelled = false

    async function connect() {
      const c = new Client({ name: 'my-app', version: '1.0.0' })
      const transport = new StreamableHTTPClientTransport(new URL(serverUrl))
      await c.connect(transport)

      if (cancelled) {
        await c.close()
        return
      }

      const toolsList = await c.listTools()
      setClient(c)
      setTools(toolsList.tools)
      setIsReady(true)
    }

    connect().catch(console.error)
    return () => {
      cancelled = true
      client?.close()
    }
  }, [serverUrl])

  const callTool = useCallback(
    async (name: string, args: any) => {
      if (!client) throw new Error('MCP not connected')
      return client.callTool({ name, arguments: args })
    },
    [client]
  )

  return { client, tools, isReady, callTool }
}

3.4 用法 ​

tsx
function McpToolsExplorer({ serverUrl }: { serverUrl: string }) {
  const { tools, isReady, callTool } = useMcpClient(serverUrl)

  if (!isReady) return <div>连接中...</div>

  return (
    <div>
      <h2>可用工具 ({tools.length})</h2>
      {tools.map(tool => (
        <ToolCard
          key={tool.name}
          tool={tool}
          onInvoke={args => callTool(tool.name, args)}
        />
      ))}
    </div>
  )
}

四、LLM + MCP 集成 ​

4.1 把 MCP 工具转为 OpenAI 工具格式 ​

ts
async function mcpToolsToOpenAI(client: Client) {
  const mcpTools = await client.listTools()

  return mcpTools.tools.map(tool => ({
    type: 'function',
    function: {
      name: tool.name,
      description: tool.description,
      parameters: tool.inputSchema,  // MCP 已经是 JSON Schema
    },
  }))
}

4.2 完整对话循环 ​

ts
async function chatWithMcp(userInput: string) {
  // 1. 准备工具
  const tools = await mcpToolsToOpenAI(mcpClient)

  // 2. 调 LLM
  const messages = [{ role: 'user' as const, content: userInput }]
  let response = await openai.chat.completions.create({
    model: 'gpt-4',
    messages,
    tools,
  })

  // 3. 处理 tool_calls
  while (response.choices[0].message.tool_calls) {
    messages.push(response.choices[0].message)

    for (const toolCall of response.choices[0].message.tool_calls) {
      const args = JSON.parse(toolCall.function.arguments)

      // ✅ 通过 MCP 执行工具（而不是直接调 API）
      const result = await mcpClient.callTool({
        name: toolCall.function.name,
        arguments: args,
      })

      messages.push({
        role: 'tool',
        tool_call_id: toolCall.id,
        content: JSON.stringify(result.content),
      })
    }

    response = await openai.chat.completions.create({
      model: 'gpt-4',
      messages,
      tools,
    })
  }

  return response.choices[0].message.content
}

五、UI 工具的特殊处理 ​

UI 操作工具（弹窗、跳转、表单）需要前端拦截。

ts
// 工具注册
mcpClient.registerUIHandler('show_modal', async (args) => {
  return new Promise(resolve => {
    modal.confirm({
      title: args.title,
      content: args.message,
      onOk: () => resolve({ confirmed: true }),
      onCancel: () => resolve({ confirmed: false }),
    })
  })
})

六、MCP vs Function Calling ​

维度Function CallingMCP
协议LLM 厂商私有开放标准
工具复用单一 LLM跨 LLM 复用
实现成本低（API 直接调）中（要写 Server）
传输HTTP / 内部stdio / HTTP / WebSocket
生态LLM 厂商主导社区推动
成熟度成熟（2023+）新兴（2024-11+）

八、面试高频追问 ​

Q1: 什么是 MCP？ ​

答：Model Context Protocol，Anthropic 开源的 LLM 工具调用标准协议。定位"LLM 应用的 USB-C 接口"，让工具一次实现跨 LLM 复用。

Q2: MCP 和 Function Calling 区别？ ​

答：

  • Function Calling 是 LLM 厂商私有（OpenAI/Anthropic 各不同）
  • MCP 是开放协议，跨厂商、跨平台
  • MCP 通过 Server/Client 模型解耦工具实现和 LLM

Q3: 浏览器侧怎么用 MCP？ ​

答：用 HTTP / WebSocket 传输（不能用 stdio）。SDK @modelcontextprotocol/sdk 提供 StreamableHTTPClientTransport。

Q4: MCP 适合前端做吗？ ​

答：

  • 前端能做的：MCP Client（连接 Server、调用工具、UI 拦截）
  • 后端做的：MCP Server（暴露内部 API）
  • 特别适合：企业内部工具集统一、IDE 插件

面试追问(深化原 Q1-Q4) ​

  • MCP 解决了什么问题? 统一 LLM 与外部工具的协议(类似 USB-C);一次开发多端复用
  • MCP 架构? Host(Claude/Cline) → Client → Server(暴露工具);JSON-RPC 通信
  • MCP vs Function Calling? MCP 是协议层,FC 是 LLM 能力;MCP 可让 LLM 动态发现工具
  • 自己写 MCP Server? 4 步:声明 tools/resources → 实现 handler → stdio 通信 → 注册到 client

📝 小结 ​

  • MCP(Model Context Protocol)是把工具暴露给模型的统一协议,解决了「每个模型厂商一套工具接口」的问题。
  • 三类角色:Host(编排)、Client(与 Server 建立连接的一侧)、Server(提供工具与资源)。
  • 传输方式:本地用 stdio,远程用 SSE / Streamable HTTP;前端只能连远程(Server 跑在服务端)。
  • 工具定义用 JSON Schema 描述入参,调用流程与 Function Calling 一致:发现工具 → 模型发起调用 → 客户端执行 → 结果回传。
  • 与 Function Calling 的区别:FC 是模型厂商的私有协议,MCP 是开放协议,一套工具可接多家模型。
  • UI 工具的特殊处理:涉及 DOM 操作的工具要跑在 Host 侧并做权限确认,不能暴露任意执行能力。
  • 面试加分:能说清「MCP 解决了什么工程问题」——工具复用与跨模型迁移成本。
