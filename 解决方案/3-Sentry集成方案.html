Sentry 集成实战 ​

工业级前端监控的标准答案：Sentry + 自定义 + Source Map。

一、Sentry 是什么 ​

  • 错误捕获 + 聚合：自动 dedupe + 频率统计
  • Source Map 还原：堆栈还原到源码
  • 上下文：user / tags / breadcrumbs
  • Performance：性能监控（LCP / FID 等）
  • Release 追踪：每个版本错误率

二、安装 ​

bash
pnpm add @sentry/react @sentry/vite-plugin

三、Vite 接入 ​

3.1 初始化 ​

ts
// src/main.tsx
import * as Sentry from '@sentry/react'

Sentry.init({
  dsn: 'https://examplePublicKey@o0.ingest.sentry.io/0',
  integrations: [
    Sentry.browserTracingIntegration(),
    Sentry.replayIntegration(),
  ],

  // 采样率
  tracesSampleRate: 1.0,  // 生产建议 0.1
  replaysSessionSampleRate: 0.1,
  replaysOnErrorSampleRate: 1.0,

  // 环境
  environment: import.meta.env.MODE,
  release: import.meta.env.VITE_APP_VERSION,

  // 过滤
  beforeSend(event) {
    // 过滤掉不需要的错误
    if (event.exception?.values?.[0]?.type === 'ChunkLoadError') {
      return null  // 路由切换的 chunk 错误
    }
    return event
  },
})

3.2 路由集成（React Router） ​

tsx
import { wrapCreateBrowserRouter } from '@sentry/react'

const sentryCreateBrowserRouter = wrapCreateBrowserRouter(createBrowserRouter)

const router = sentryCreateBrowserRouter([/* routes */])

3.3 Source Map 上传 ​

ts
// vite.config.ts
import { sentryVitePlugin } from '@sentry/vite-plugin'

export default defineConfig({
  build: {
    sourcemap: true,  // 必须开启
  },
  plugins: [
    sentryVitePlugin({
      org: 'your-org',
      project: 'your-project',
      authToken: process.env.SENTRY_AUTH_TOKEN,
      release: { name: process.env.VITE_APP_VERSION },
    }),
  ],
})

3.4 错误边界 ​

tsx
import * as Sentry from '@sentry/react'

function App() {
  return (
    <Sentry.ErrorBoundary fallback={<ErrorPage />}>
      <Routes />
    </Sentry.ErrorBoundary>
  )
}

五、自定义上下文 ​

5.1 用户信息 ​

ts
// 登录后
Sentry.setUser({
  id: '123',
  email: 'tom@example.com',
  role: 'admin',
})

// 登出
Sentry.setUser(null)

5.2 Tags / Contexts ​

ts
// Tag（用于搜索）
Sentry.setTag('page_locale', 'zh-CN')
Sentry.setTag('feature_flag', 'new_ui')

// Context（结构化数据）
Sentry.setContext('order', {
  id: 'ORDER_123',
  amount: 100,
})

// 全局 Breadcrumb（行为流）
Sentry.addBreadcrumb({
  category: 'navigation',
  message: 'From /home to /order',
  level: 'info',
})

5.3 自定义错误捕获 ​

ts
try {
  await fetchUser(id)
} catch (err) {
  Sentry.captureException(err, {
    tags: { feature: 'user-profile' },
    extra: { userId: id },
  })
  throw err
}

六、Source Map 完整流程 ​

6.1 Vite 配置 ​

ts
// vite.config.ts
import { sentryVitePlugin } from '@sentry/vite-plugin'

export default defineConfig({
  build: {
    sourcemap: true,
  },
  plugins: [
    sentryVitePlugin({
      org: 'your-org',
      project: 'your-project',
      authToken: process.env.SENTRY_AUTH_TOKEN,
      release: {
        name: process.env.VITE_APP_VERSION,
        create: true,
        finalize: true,  // 自动 finalize release
      },
      // 排除一些无关文件
      sourcemapsAssetsPath: 'dist',
    }),
  ],
})

6.2 CI 集成 ​

yaml
# .github/workflows/release.yml
- name: Build
  env:
    SENTRY_AUTH_TOKEN: ${{ secrets.SENTRY_AUTH_TOKEN }}
    VITE_APP_VERSION: ${{ github.ref_name }}
  run: pnpm build
  # sentryVitePlugin 会自动上传 source map

6.3 隐藏 Source Map ​

ts
// vite.config.ts
build: {
  sourcemap: 'hidden',  // 产物不含 .map，但 Sentry 能拿到
}

7.1 用户反馈组件 ​

function FeedbackButton() {

7.2 Session Replay (录屏) ​

ts
Sentry.init({
  replaysSessionSampleRate: 0.1,  // 10% 用户录屏
  replaysOnErrorSampleRate: 1.0,   // 出错必录

八、报警规则 ​

8.1 在 Sentry UI 配置 ​

  • Alert > Create Alert
  • 条件：error frequency、new issue、回归 issue
  • 通知：邮件、Slack、钉钉、PagerDuty

8.2 实战配置 ​

- 新 issue 立即报警
- 高频 issue（每分钟 > 100 次）报警
- Release 回归（错误率比上一个版本高 20%）报警

九、Release 健康度 ​

9.1 Crash-Free Sessions ​

99.5% 表示 0.5% 的会话发生崩溃
低于 95% 需要立即响应

9.2 Adopting ​

新版本上线 24 小时后，看 Crash-Free 是否达到历史均值。

十、面试高频追问 ​

Q1: Sentry 怎么接？ ​

答：安装 @sentry/react，在 main.tsx init。Vite 项目用 sentryVitePlugin 自动上传 Source Map。

Q2: Source Map 怎么上传？ ​

答：CI 构建产物时自动上传（sentryVitePlugin 配置 authToken）。前端产物的 .map 不放在线上，避免暴露源码。

Q3: 错误堆栈怎么还原？ ​

答：Sentry 服务端有 Source Map，错误堆栈自动还原到 TS 源码的行列号。

Q4: 怎么防止 Sentry 误报？ ​

答：用 beforeSend 过滤。常见过滤：ChunkLoadError、ResizeObserver loop、Network Error。

Q5: Session Replay 有什么坑？ ​

答：

  • 录屏会增加 Sentry 配额（按 replay 计费）
  • 敏感信息（密码）会被录到，需要 mask
  • 录屏影响性能（采样率别高于 10%）

面试追问(深化原 Q1-Q5) ​

  • Sentry 5 大特性? 错误聚合、Source Map 自动解析、Release 跟踪、Performance 监控、Issue 告警
  • sourcemap 上传注意? 仅上传到监控服务,不部署到生产;CI 阶段上传
  • 隐私合规? 过滤敏感字段(密码、token);欧盟用户需要 GDPR 合规
  • 自定义 context? Sentry.setUser({ id, email }) / setTag / setContext 辅助排查

📝 小结 ​

  • Sentry 的核心价值:自动聚合相同错误 + SourceMap 还原真实堆栈 + Release 追踪 + 用户行为轨迹(breadcrumb)。
  • 接入只需三步:装 SDK → 初始化并设置 dsn → 上传 SourceMap 并绑定 release。
  • Source Map 必须上传到 Sentry 而非留在本地,并在 CI 里与产物版本绑定,否则线上堆栈是压缩后的无用信息。
  • 自定义上下文:用户信息、租户、路由、接口参数(注意脱敏)、业务字段,这些是定位问题的关键。
  • Release 健康度能看到「这次发版引入了多少新错误」,是发布决策的重要依据。
  • 用户反馈(用户点"这条报错对我有影响")能把错误和业务影响关联起来。
  • 面试标准答法:讲清「为什么错误必须带版本号」——没有版本号就无法定位是哪个发布引入的。
