Python 虚拟环境与依赖管理 ​

让脚本能"换台电脑就跑"——这是从「写给自己看」到「交给别人跑」的关键一步。 本文以 venv + pip 为基础,顺带介绍 poetry / uv 这类更现代的方案。

🎯 学到这步能做什么 ​

  • 解释"虚拟环境"是什么、为什么必须有
  • 用 venv 隔离每个项目的依赖
  • 用 pip + requirements.txt 锁定依赖版本
  • 知道 poetry / uv / pipenv 各自适合什么场景
  • 不再因为「同事跑不起来我的脚本」而怀疑人生

❓ 为什么需要虚拟环境 ​

直接 pip install requests 会装到全局 Python,有两个问题:

  1. 版本冲突:项目 A 要 requests 2.x,项目 B 要 requests 1.x,全机器只能装一个
  2. 不可复现:换台电脑 / 部署到服务器,你不知道当时装的是哪一版

虚拟环境 = 给每个项目一个独立的 site-packages,互不影响。

bash
# 创建 + 激活(以 Windows PowerShell 为例)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate

激活后命令行前缀会出现 (.venv),所有 pip install 都装到这个独立目录。

🔧 venv:Python 自带 ​

venv 是 Python 3.3+ 自带的模块,不需要 pip install。

bash
# 1. 创建虚拟环境
python -m venv .venv          # .venv 是惯例文件夹名

# 2. 激活
# Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# Windows CMD:
.\.venv\Scripts\activate.bat
# Linux / macOS:
source .venv/bin/activate

# 3. 退出
deactivate

激活后 which python / where python 指向 .venv/Scripts/python.exe。

把虚拟环境加进 .gitignore ​

.venv/ 不该提交,仓库里只留依赖清单:

# .gitignore
.venv/
venv/
__pycache__/
*.pyc
*.egg-info/
dist/
build/

📥 pip 常用命令 ​

bash
pip install requests              # 装最新版
pip install requests==2.31.0      # 锁版本
pip install requests>=2.30        # 装 >=2.30 的最新版
pip install -r requirements.txt   # 按清单装
pip install "requests[security]"  # 装可选依赖(方括号里的 extras)

pip list                          # 看当前环境装了啥
pip list --format=columns          # 列更整齐
pip show requests                 # 看某库的详细信息(版本/路径/依赖)
pip show -f requests              # 包含安装的文件列表
pip freeze > requirements.txt     # 导出当前环境的所有依赖

pip uninstall requests            # 卸载
pip cache purge                   # 清下载缓存
pip config list                   # 看当前 pip 配置

pip freeze vs pip list 的区别 ​

命令输出格式用途
pip list表格,带 Latest 列给人看
pip freeze包==版本 严格格式给 pip install -r 用

生成 requirements.txt 永远用 pip freeze,别用 pip list > req.txt。

📄 requirements.txt 写法 ​

text
# 基础写法:严格锁版(生产推荐)
requests==2.31.0
flask>=2.3,<3.0

# extras:装可选依赖
uvicorn[standard]==0.30.0

# 从 git 仓库装(不推荐,但有时必要)
# git+https://github.com/user/repo.git@main

# 从本地装
# -e ./my_pkg

# 开发依赖(测试、lint)建议分开
# requirements-dev.txt
pytest==7.4.0
black==23.7.0

锁定依赖 vs 灵活依赖 ​

写法含义适用场景
requests==2.31.0严格锁版生产/部署,推荐
requests>=2.30至少 2.30库开发(给下游用)
requests最新版个人脚本玩玩

生产环境永远锁版,否则某次 pip install -r 装到新版本会突然炸。

用 pip-tools 自动生成 ​

bash
pip install pip-tools
# requirements.in 写宽松版本:
#   requests
#   flask>=2.0

pip-compile requirements.in      # 生成锁定的 requirements.txt
pip-sync requirements.txt        # 同步当前环境到 requirements.txt 完全一致

pip-compile 会解算依赖树,产出和 pip freeze 类似但更稳定。

🚀 换源:加速 pip 下载 ​

国内访问 PyPI 慢,常用镜像:

bash
# 临时换源
pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple

# 永久换源(写到配置)
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 配的地址:
#   Linux:   ~/.config/pip/pip.conf
#   macOS:   ~/Library/Application Support/pip/pip.conf
#   Windows: %APPDATA%\pip\pip.ini

🎵 poetry:更现代的方案 ​

poetry 把"依赖管理 + 虚拟环境 + 打包发布"做成一站式。

bash
# 安装(官方推荐 pipx 或 官方脚本)
pip install poetry

# 初始化(在已有项目里)
poetry init

# 加依赖(自动写进 pyproject.toml)
poetry add requests
poetry add pytest --group dev    # 加到 dev 依赖
poetry add fastapi --group web   # 自定义分组

# 装所有依赖(根据 pyproject.toml + poetry.lock)
poetry install

# 跑命令(在虚拟环境里)
poetry run python main.py
poetry run pytest
poetry shell                     # 进入虚拟环境 shell

pyproject.toml 长这样 ​

toml
[project]
name = "my-app"
version = "0.1.0"
description = ""
authors = ["Your Name <you@example.com>"]
requires-python = ">=3.10"
dependencies = [
    "requests==2.31.0",
    "flask>=2.3,<3.0",
]

[tool.poetry.group.dev.dependencies]
pytest = "^7.4"
black = "^23.7"

poetry.lock 必须提交 ​

poetry.lock 锁定了精确版本 + hash,换台电脑 poetry install 装出完全一样的环境。

# .gitignore
.venv/

# 但要提交:
# pyproject.toml
# poetry.lock

⚡ uv:速度新王 ​

uv 是 Astral 团队(Ruff 的作者)用 Rust 写的下一代 Python 工具,完全兼容 pip 接口,但快 10-100 倍。

bash
# 安装(Linux/macOS)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

# 创建虚拟环境(比 python -m venv 快 80 倍)
uv venv .venv

# 装依赖(比 pip 快 10-100 倍)
uv pip install requests

# 按 requirements 装
uv pip install -r requirements.txt

# 锁定依赖(类似 poetry.lock)
uv pip compile requirements.in -o requirements.txt

# 一体化:类似 poetry 但更快
uv init                          # 初始化项目
uv add requests                  # 加依赖
uv run python main.py            # 跑命令

特点:

  • 兼容 pip 生态(老的 requirements.txt 不用改)
  • 装包速度极快(pip install 在大项目可能要几分钟,uv 几秒)
  • 内置虚拟环境管理
  • 2024 年开始被大量项目采用,新项目优先推荐

🧭 工具选型对比 ​

工具优势劣势推荐度
venv + pip内置、零依赖、生态最广依赖扁平、不能多版本 Python⭐⭐⭐⭐⭐ 入门首选
uvpip 完全兼容,极快,新派新工具,生态在长⭐⭐⭐⭐⭐ 2024 首选
poetry依赖树清晰、锁文件、内置虚拟环境学习曲线、旧项目不通用⭐⭐⭐⭐ 中大型项目
pipenv类似 poetry,先出现维护慢、社区转 poetry⭐⭐
conda装 Python 解释器 + 非 Python 库重、慢、不在 PyPI 生态⭐⭐⭐ 数据科学专用
pdmPEP 582 标准学习成本⭐⭐⭐

选型建议 ​

  • 新项目:直接 uv init,最快最现代
  • 中大型 Python 项目:用 poetry,生态成熟
  • 老项目 / 简单脚本:venv + pip + requirements.txt,没人会说不对
  • 数据科学:conda 或 uv 都行,conda 解决非 Python 库(CUDA、MKL)更省心

⚠️ 容易踩的坑 ​

坑表现解决
PowerShell 激活 venv 报错「禁止运行脚本」默认禁止 Activate.ps1Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 后重试
pip install 装到了全局 Python没激活虚拟环境检查命令行前缀有没有 (.venv)
requirements.txt 里写 requests 不锁版部署时版本漂移,突然炸永远锁版 requests==2.31.0
pip freeze 把无关库也写进去装了一堆测试依赖用 poetry 分组,或 pip-compile
macOS 用系统 Python 建 venv系统 Python 不归你管,升级会炸装 pyenv 管理多版本,或显式用 python3 -m venv
pip install 提示 externally-managed-environment新版系统 Python(PEP 668)禁止全局装用 pip install --break-system-packages(不推荐) 或建 venv / 用 uv
多个项目混用同一个 venvA 项目升级库搞坏 B 项目一项目一 venv,不放全局
poetry.lock 没提交同事装的版本和你不一样必须提交 lock 文件
Windows 路径里有中文 / 空格venv 创建失败项目路径用纯英文无空格
