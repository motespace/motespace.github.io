Python 虚拟环境与依赖管理

让脚本能“换台电脑就跑”——这是从「写给自己看」到「交给别人跑」的关键一步。 本文以 venv + pip 为基础,顺带介绍 poetry / uv 这类更现代的方案。

❓ 为什么需要虚拟环境

Section titled “❓ 为什么需要虚拟环境”

直接 pip install requests 会装到全局 Python,有两个问题:

  1. 版本冲突:项目 A 要 requests 2.x,项目 B 要 requests 1.x,全机器只能装一个
  2. 不可复现:换台电脑 / 部署到服务器,你不知道当时装的是哪一版

虚拟环境 = 给每个项目一个独立的 site-packages,互不影响。

激活后命令行前缀会出现 (.venv),所有 pip install 都装到这个独立目录。

🔧 venv:Python 自带

Section titled “🔧 venv:Python 自带”

venv 是 Python 3.3+ 自带的模块,不需要 pip install。

激活后 which python / where python 指向 .venv/Scripts/python.exe。

pip freeze vs pip list 的区别

Section titled “pip freeze vs pip list 的区别”
命令 输出格式 用途

锁定依赖 vs 灵活依赖

Section titled “锁定依赖 vs 灵活依赖”
写法 含义 适用场景
requests==2.31.0 严格锁版 生产/部署,推荐
requests>=2.30 至少 2.30 库开发(给下游用)
requests 最新版 个人脚本玩玩

生产环境永远锁版,否则某次 pip install -r 装到新版本会突然炸。

⚡ uv:速度新王

Section titled “⚡ uv:速度新王”

uv 是 Astral 团队(Ruff 的作者)用 Rust 写的下一代 Python 工具,完全兼容 pip 接口,但快 10-100 倍。

特点:

  • 兼容 pip 生态(老的 requirements.txt 不用改)
  • 装包速度极快(pip install 在大项目可能要几分钟,uv 几秒)
  • 内置虚拟环境管理
  • 2024 年开始被大量项目采用,新项目优先推荐

🧭 工具选型对比

Section titled “🧭 工具选型对比”
工具 优势 劣势 推荐度
venv + pip 内置、零依赖、生态最广 依赖扁平、不能多版本 Python ⭐⭐⭐⭐⭐ 入门首选
uv pip 完全兼容,极快,新派 新工具,生态在长 ⭐⭐⭐⭐⭐ 2024 首选
poetry 依赖树清晰、锁文件、内置虚拟环境 学习曲线、旧项目不通用 ⭐⭐⭐⭐ 中大型项目
pipenv 类似 poetry,先出现 维护慢、社区转 poetry ⭐⭐
conda 装 Python 解释器 + 非 Python 库 重、慢、不在 PyPI 生态 ⭐⭐⭐ 数据科学专用
pdm PEP 582 标准 学习成本 ⭐⭐⭐

选型建议

Section titled “选型建议”
  • 新项目:直接 uv init,最快最现代
  • 中大型 Python 项目:用 poetry,生态成熟
  • 老项目 / 简单脚本:venv + pip + requirements.txt,没人会说不对
  • 数据科学:conda 或 uv 都行,conda 解决非 Python 库(CUDA、MKL)更省心

⚠️ 容易踩的坑

Section titled “⚠️ 容易踩的坑”
坑 表现 解决
PowerShell 激活 venv 报错「禁止运行脚本」 默认禁止 Activate.ps1 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 后重试
pip install 装到了全局 Python 没激活虚拟环境 检查命令行前缀有没有 (.venv)
requirements.txt 里写 requests 不锁版 部署时版本漂移,突然炸 永远锁版 requests==2.31.0
pip freeze 把无关库也写进去 装了一堆测试依赖 用 poetry 分组,或 pip-compile
macOS 用系统 Python 建 venv 系统 Python 不归你管,升级会炸 装 pyenv 管理多版本,或显式用 python3 -m venv
pip install 提示 externally-managed-environment 新版系统 Python(PEP 668)禁止全局装 用 pip install --break-system-packages(不推荐) 或建 venv / 用 uv
多个项目混用同一个 venv A 项目升级库搞坏 B 项目 一项目一 venv,不放全局
poetry.lock 没提交 同事装的版本和你不一样 必须提交 lock 文件
Windows 路径里有中文 / 空格 venv 创建失败 项目路径用纯英文无空格
