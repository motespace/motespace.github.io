Step 6:上线 checklist

Section titled “Step 6:上线 checklist”

上线前

Section titled “上线前”
  • 应用在测试环境完整跑过
  • NODE_ENV=production / 关 debug
  • .env 配好,所有 secret 用环境变量
  • 数据库连得通,migration 跑过
  • 备份最新
  • 监控配好(指标 + 告警)
  • HTTPS 证书 OK

上线中

Section titled “上线中”
  • nginx 配好,语法检查过
  • systemd 服务起来
  • 健康检查接口通(/health 返回 200)
  • curl 真实接口一次
  • 日志没异常

上线后

Section titled “上线后”
  • 监控 1 小时没告警
  • 业务关键流程跑一遍
  • 备份任务跑通(测试恢复)
  • 记下回滚方案(代码 git tag + DB 备份位置)

⚠️ 容易踩的坑

Section titled “⚠️ 容易踩的坑”
坑 表现 解决
上线后没监控 挂了没人知道 监控 + 告警必装
数据库没备份 数据丢恢复不了 定期 mysqldump + 异地
.env 提交到 git 密码泄露 .gitignore + 部署时手写
直接用 root 跑 安全风险 User=deploy
nginx 没配 gzip 流量浪费 gzip on
HTTPS 证书没自动续 过期访问报红 certbot timer 已配,验证
没设 LimitNOFILE 高并发 fd 耗尽 LimitNOFILE=65535
systemd 服务起不来 不知道原因 journalctl -u myapp -n 50
反向代理后 IP 错 应用拿到 nginx IP proxy_set_header X-Real-IP
数据库和应用一台机器 单点 后期分机器
