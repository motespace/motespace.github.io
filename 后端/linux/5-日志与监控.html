Linux 日志与监控 ​

没日志 = 抓瞎,出问题不知道发生了什么。 没监控 = 救火,出问题才知道。 本文覆盖日志收集 + 系统监控 + 告警方案。

📋 日志基础 ​

text
Linux 日志三股:
├─ systemd-journal: 二进制,集中(systemd 服务)
├─ /var/log/*.log:   文本,经典(rsyslog / 应用)
└─ 应用自己的日志文件: 写文件 / stdout

生产建议:
- 应用日志走 stdout(让 docker / systemd 接)
- 老的 syslog 留着兼容

📜 journalctl(systemd 日志) ​

详见 systemd 章节。这里补一些高级用法:

bash
# 按时间
journalctl --since "2024-01-15 10:00" --until "2024-01-15 12:00"
journalctl --since yesterday
journalctl --since "2 days ago"

# 按服务
journalctl -u nginx -u mysql

# 按优先级
journalctl -p err
journalctl -p warning

# 跟踪 + 过滤
journalctl -u myapp -f | grep ERROR

# 持久化(默认 /run/log,重启丢)
sudo mkdir -p /var/log/journal
sudo systemd-tmpfiles --create --prefix /var/log/journal
sudo systemctl restart systemd-journald

📁 /var/log 经典日志 ​

bash
ls -lh /var/log
# auth.log          SSH 登录
# syslog            系统日志
# kern.log          内核
# nginx/            nginx 日志
# mysql/            mysql 错误日志
# ufw.log           防火墙

实时跟踪 ​

bash
tail -f /var/log/nginx/access.log
tail -f /var/log/nginx/error.log

找关键信息 ​

bash
# 看 SSH 登录失败
grep "Failed password" /var/log/auth.log | tail -20

# 看 502 / 504
grep -E "502|504" /var/log/nginx/error.log | tail -20

# 按访问量排 IP(看是不是被打)
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head

🔄 logrotate 滚动 ​

应用一直写日志,几天就撑爆盘。用 logrotate 自动切割 + 压缩 + 删除旧的。

配置文件 ​

/etc/logrotate.d/myapp:

/var/log/myapp/*.log {
    daily                          # 每天切
    rotate 7                       # 保留 7 份
    compress                       # gzip 压缩
    delaycompress                  # 上一份不立即压
    missingok                      # 文件不存在不报错
    notifempty                     # 空文件不切
    create 0640 app app            # 切完新建空文件,权限
    sharedscripts
    postrotate                     # 切完执行的钩子
        systemctl reload myapp > /dev/null 2>/dev/null || true
    endscript
}
bash
# 手动触发(调试用)
sudo logrotate -d /etc/logrotate.conf    # dry run
sudo logrotate -f /etc/logrotate.conf    # 强制跑

🛠️ 应用日志最佳实践 ​

推荐:JSON 结构化日志 ​

python
# Python
import json, logging
logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s %(levelname)s %(message)s'
)

logger = logging.getLogger("myapp")
logger.info(json.dumps({
    "event": "user_login",
    "user_id": 123,
    "ip": "1.2.3.4",
}))
javascript
// Node.js
const winston = require('winston');
const logger = winston.createLogger({
  format: winston.format.json(),
  transports: [new winston.transports.Console()],
});
logger.info({ event: 'user_login', user_id: 123 });

输出到 stdout ​

推荐:应用把日志打到 stdout,让 docker / systemd 接。不要自己写文件。

python
print(json.dumps({...}), flush=True)
# 或 logging.StreamHandler(sys.stdout)

这样容器化、systemd 服务、k8s 都能直接收集。

📊 系统监控指标 ​

关键指标(CNCF / Prometheus 标准) ​

类别指标
CPU使用率、load、各核状态
内存已用 / 可用 / swap / cache
磁盘空间使用率、IOPS、await
网络入 / 出带宽、丢包率、错误包
应用QPS、延迟、错误率
业务注册数、订单数(自定义)

USE 原则(Brendan Gregg):

  • Utilization:使用率
  • Saturation:饱和度
  • Errors:错误数

📈 Prometheus + Grafana ​

开源监控的事实标准。

架构 ​

text
应用 / node_exporter / mysql_exporter
    ↓ 暴露 /metrics 端点
Prometheus(抓取存储)
    ↓
Grafana(可视化)
    ↓
Alertmanager(告警)

快速起 ​

docker-compose.yml:

yaml
services:
  prometheus:
    image: prom/prometheus
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
      - prom_data:/prometheus
    ports:
      - "9090:9090"

  grafana:
    image: grafana/grafana
    volumes:
      - grafana_data:/var/lib/grafana
    ports:
      - "3000:3000"
    depends_on:
      - prometheus

  node-exporter:
    image: prom/node-exporter
    ports:
      - "9100:9100"

volumes:
  prom_data:
  grafana_data:

prometheus.yml:

yaml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: node
    static_configs:
      - targets: ['node-exporter:9100']

Grafana 配数据源 http://prometheus:9090,导入社区 dashboard(Node Exporter Full:ID 1860)。

应用暴露指标 ​

python
# prometheus_client(Python)
from prometheus_client import Counter, Histogram, generate_latest

REQUESTS = Counter("http_requests_total", "Total", ["method", "path"])
LATENCY = Histogram("http_request_duration_seconds", "Duration", ["path"])

@app.middleware("http")
async def metrics_middleware(request, call_next):
    start = time.time()
    response = await call_next(request)
    REQUESTS.labels(method=request.method, path=request.url.path).inc()
    LATENCY.labels(path=request.url.path).observe(time.time() - start)
    return response

@app.get("/metrics")
def metrics():
    return Response(generate_latest(), media_type="text/plain")
javascript
// prom-client(Node)
const client = require('prom-client');
client.collectDefaultMetrics();

app.get('/metrics', async (req, res) => {
  res.set('Content-Type', client.register.contentType);
  res.end(await client.register.metrics());
});

🔔 告警 ​

方案 ​

工具特点
AlertmanagerPrometheus 配套,支持邮件 / Slack / 钉钉
Grafana AlertingGrafana 内置,可视化好
云监控告警阿里云 / 腾讯云,接电话 / 短信
Sentry / 飞书 / 钉钉机器人业务告警 + 异常捕获

Alertmanager 钉钉告警 ​

alertmanager.yml:

yaml
route:
  receiver: dingtalk

receivers:
  - name: dingtalk
    webhook_configs:
      - url: 'https://oapi.dingtalk.com/robot/send?access_token=YOUR_TOKEN'
        send_resolved: true

告警规则(prometheus):

yaml
groups:
  - name: node
    rules:
      - alert: HighCPU
        expr: 100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 5m
        annotations:
          summary: "CPU 高 {{ $value }}%"

      - alert: DiskFull
        expr: (node_filesystem_avail_bytes / node_filesystem_size_bytes) * 100 < 10
        for: 5m
        annotations:
          summary: "磁盘剩余 {{ $value }}%"

⚠️ 容易踩的坑 ​

坑表现解决
日志塞满磁盘DB / 应用挂了logrotate + 监控告警
日志没时间戳排错找不到时间应用打日志带 ISO 时间
多个服务时间不同步日志关联不上装 chrony / ntpd
单日志文件 GB 级grep / tail 慢logrotate 切小
监控指标太多Prometheus 撑爆控制 scrape interval / 标签基数
告警太频繁(告警风暴)没人看配 for: 5m / 静默规则
告警发邮件没人查告警等于没有接电话 / 短信 / 钉钉强提醒
Grafana dashboard 没人维护监控变成摆设选社区热门 ID,定期 review
docker / k8s 日志文件化容器删日志丢接 stdout 到 Loki / 云日志
