🔧 systemd 是什么

Section titled “🔧 systemd 是什么”

systemd 是现代 Linux 的服务管理器(init 系统),取代了老旧的 SysVinit。

一个“服务”(service)由 unit 文件描述,放在固定目录。

📁 unit 文件位置

Section titled “📁 unit 文件位置”
路径 谁放 优先级
/etc/systemd/system/*.service 系统管理员 最高(你部署应用放这)
/run/systemd/system/*.service 运行时 中
/usr/lib/systemd/system/*.service 系统包 低(包管理器用)

应用部署一律放 /etc/systemd/system/,不要碰 /usr/lib/。

字段速查

Section titled “字段速查”

[Unit] 段

Section titled “[Unit] 段”
字段 作用
Description 人类可读描述
After 在谁之后启动(仅顺序,不等就绪)
Requires 强依赖(失败连坐)
Wants 弱依赖(失败不管)

[Service] 段

Section titled “[Service] 段”
字段 常用值 作用
Type simple (默认) / forking / notify 启动类型
User / Group 用户名 用非 root 跑
WorkingDirectory 路径 工作目录
ExecStart 命令 必填
ExecReload 命令 重新加载配置
ExecStop 命令 停止
Restart no / always / on-failure / on-abnormal 何时重启
RestartSec 秒 重启前等多久
Environment KEY=val 环境变量
EnvironmentFile 文件路径 从文件读环境变量
StandardOutput / StandardError journal / 文件 日志输出

[Install] 段

Section titled “[Install] 段”
字段 作用
WantedBy=multi-user.target 多用户模式默认 target(开机自启)

⚠️ 容易踩的坑

Section titled “⚠️ 容易踩的坑”
坑 表现 解决
改了 unit 没生效 还是旧行为 systemctl daemon-reload
启动失败没日志 status 看不到原因 journalctl -u myapp -n 50 --no-pager
用 root 跑应用 容器逃逸 = 主机 root 加 User=app
WorkingDirectory 不对 找不到文件 设绝对路径
Type 选错 forking 服务报 Type=simple 错误 Node/Python 一般用 simple,Nginx 用 forking
Restart=always 配错 启动失败一直重启 用 on-failure,再加 StartLimitIntervalSec
环境变量不生效 应用读不到 用 EnvironmentFile 而不是 Environment(空格路径会出 bug)
改了 systemd 配置系统挂了 重启不了 配 rescue 模式 / 保留旧版本
服务启动慢导致超时 Job for xxx.service failed TimeoutStartSec=60 延长
