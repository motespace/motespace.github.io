Linux SSH 与远程操作 ​

部署到生产 / 调试线上 / 跨机器同步文件 —— 几乎全靠 SSH。 本文覆盖 SSH 客户端用法 + 文件传输 + 跳板 + 免密登录。

注:docs/计算机基础/linux/ 已覆盖文件操作、权限、Shell 等基础。 本章聚焦后端运维日常的远程操作,与基础篇互补不重复。

🎯 学到这步能做什么 ​

  • 用 ssh 客户端连远端,不用每次输密码
  • 用 scp / rsync 传文件
  • 配置跳板(堡垒机)连内网机器
  • 用 ssh config 管理多台机器

🔌 ssh 基础连接 ​

bash
ssh user@host                        # 默认 22 端口
ssh user@host -p 2222                # 指定端口
ssh root@192.168.1.100

第一次连接会问 fingerprint,输入 yes 存进 ~/.ssh/known_hosts。

退出 / 中断 ​

  • exit / Ctrl+D —— 退出 ssh
  • ~ + .(转义序列,新行后按)—— 断开连接
  • ~ + Ctrl+Z —— 后台挂起 ssh

🔑 免密登录 ​

每次输密码麻烦,用 SSH key 免密:

bash
# 1. 生成密钥对(默认 RSA 4096)
ssh-keygen -t ed25519 -C "your@email.com"
# 或用 RSA:ssh-keygen -t rsa -b 4096

# 2. 拷贝公钥到远端
ssh-copy-id user@host
# 老系统没有 ssh-copy-id,手动拷:
cat ~/.ssh/id_ed25519.pub | ssh user@host 'mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys'

# 3. 测试(应该不用输密码)
ssh user@host

密钥文件位置 ​

文件作用
~/.ssh/id_ed25519私钥(保密,不要传)
~/.ssh/id_ed25519.pub公钥(给远端)
~/.ssh/known_hosts已知主机 fingerprint
~/.ssh/authorized_keys远端,谁可以登我
~/.ssh/config客户端配置

私钥权限 ​

bash
chmod 600 ~/.ssh/id_ed25519
# 权限太大 ssh 拒绝用

⚙️ ssh config 多机器管理 ​

~/.ssh/config:

ini
Host prod-web
    HostName 1.2.3.4
    User deploy
    Port 22
    IdentityFile ~/.ssh/id_ed25519

Host prod-db
    HostName 10.0.1.5
    User mysql
    Port 2222

Host *.internal
    User dev
    ProxyJump bastion

Host bastion
    HostName bastion.example.com
    User dev

Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3

效果:

bash
ssh prod-web                        # 直接登
ssh prod-db                         # 直接登
ssh db.internal                     # 自动跳堡垒机
scp file.tar.gz prod-web:/tmp/      # 传文件直接用别名

📁 scp / rsync 文件传输 ​

scp(简单,基于 ssh) ​

bash
# 上传
scp local.txt user@host:/path/to/dest/
scp -r ./dist user@host:/var/www/    # 目录
scp -P 2222 file user@host:/tmp/    # 指定端口(大写 P)

# 下载
scp user@host:/remote/file.txt ./

# 跨主机传(经过本机)
scp user1@a:file user2@b:/

rsync(增量,推荐) ​

bash
# 同步本地 → 远端(只传变化的部分)
rsync -avz --progress ./dist/ user@host:/var/www/
# -a: 归档模式(权限、时间、递归)
# -v: 详细
# -z: 压缩
# --progress: 显示进度

# 排除
rsync -avz --exclude='node_modules' --exclude='.git' \
  ./project/ user@host:/opt/project/

# 远端 → 本地
rsync -avz user@host:/var/log/app/ ./logs/

# 模拟运行(看会传啥)
rsync -avzn ./dist/ user@host:/var/www/
# -n: dry run

scp vs rsync:

维度scprsync
协议sshssh
增量❌ 每次全传✅ 只传差异
断点续传❌✅ (--partial)
删除目标端多余文件❌✅ (--delete)
适合小文件 / 一次性大目录 / 定期同步

🚪 跳板 / 堡垒机 ​

生产环境常常不能直连内网服务器,要先连堡垒机再往里跳。

方式 1:ProxyJump(推荐,新版 ssh) ​

ini
Host internal-web
    HostName 10.0.1.10
    User deploy
    ProxyJump bastion

Host bastion
    HostName bastion.example.com
bash
ssh internal-web
# 自动先登堡垒机,再从堡垒机跳到 internal-web

多级跳:

ini
Host deep-server
    HostName 10.0.1.20
    ProxyJump bastion,internal-web

方式 2:ssh -L 端口转发(老方法) ​

bash
ssh -L 8080:internal-host:80 bastion
# 访问 localhost:8080 = 访问 internal-host:80
# 适合临时调试

方式 3:ssh -D SOCKS 代理 ​

bash
ssh -D 1080 bastion
# 把 ssh 当 SOCKS5 代理
# 浏览器配 SOCKS5 = 127.0.0.1:1080,流量走堡垒机

💡 常用技巧 ​

远程跑命令,不登进去 ​

bash
ssh user@host 'df -h'
ssh user@host 'systemctl restart nginx'
ssh user@host 'cd /opt/app && git pull && pm2 restart all'

保持长连接不断 ​

服务端(/etc/ssh/sshd_config):

ini
ClientAliveInterval 60
ClientAliveCountMax 3
# 客户端空闲 60s 发心跳,3 次无响应断开

客户端(~/.ssh/config):

ini
Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3

tmux / screen 防掉线 ​

bash
ssh user@host
tmux                            # 进 tmux
# 在 tmux 里跑长任务
# 网络断了重连,tmux attach 还在
tmux attach                     # 重新接入

⚠️ 容易踩的坑 ​

坑表现解决
私钥权限太大Permissions 0644 too openchmod 600 ~/.ssh/id_*
改了 authorized_keys 不生效权限问题chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
ssh-copy-id 不存在macOS 老版本手动 cat ~/.ssh/id_*.pub | ssh ...
跳板机转发卡顿GFW / 网络问题加 -o "ProxyCommand=nc ..." 或换工具
主机 key 变了报警告REMOTE HOST IDENTIFICATION HAS CHANGEDssh-keygen -R host 清掉旧 key
rsync 路径结尾斜杠行为不一样源 /path/ 拷内容,/path 拷整个目录
服务器改 SSH 端口忘了连不上加 -p 2222 或写 config
长时间无操作断开tmux / screen配 ServerAliveInterval
