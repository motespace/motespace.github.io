Linux 网络诊断 ​

应用连不上 DB、调不通接口、怀疑丢包、被攻击? 本文给一套网络排查工具组合拳。

🎯 学到这步能做什么 ​

  • 看本机网络状态 / 端口 / 连接
  • 测网络通不通 / 端口开没开
  • 抓网络包分析
  • 排查 DNS 解析问题

🖥️ 本机网络信息 ​

bash
# IP / 网卡
ip a                              # 现代命令
ip addr show
ifconfig                          # 老命令(部分发行版没了)

# 路由
ip route
route -n                          # 老

# DNS 配置
cat /etc/resolv.conf
systemd-resolve --status          # systemd 系统

# 看公网 IP
curl ifconfig.me
curl ip.sb

📡 测连通性 ​

bash
# ping(测基础连通,ICMP)
ping -c 4 example.com

# 看路由路径
traceroute example.com            # 经典工具
tracepath example.com             # 不需要 root

# TCP 端口通不通(ping 不行时用这个)
nc -zv example.com 80             # netcat
nc -zv 10.0.1.5 3306              # 测内网 DB 端口

# 或者用 curl 简单测
curl -v telnet://example.com:23

🔌 看连接 / 端口 ​

ss(现代,推荐) ​

bash
# 看所有连接
ss -tunap
# -t TCP, -u UDP, -n 不解析, -a 全部, -p 显示进程

# 只看 LISTEN(本机开了哪些端口)
ss -tulnp

# 看某端口
ss -tulnp | grep :80

# 按状态统计
ss -tan | awk '{print $1}' | sort | uniq -c

# TIME_WAIT 太多(常见性能问题)
ss -tan state time-wait | wc -l

netstat(老) ​

bash
netstat -tulnp                     # 等价 ss -tulnp
netstat -an | grep ESTAB           # 看已建立的连接

端口被谁占 ​

bash
sudo lsof -i :8080
sudo ss -tulnp | grep :8080

🌐 DNS 排查 ​

bash
# 看 DNS 解析
dig example.com
dig +short example.com             # 只看结果
dig example.com @8.8.8.8           # 指定 DNS 服务器

# 反查
dig -x 8.8.8.8

# 批量解析
host example.com
nslookup example.com

# 系统 DNS 配置
cat /etc/resolv.conf
cat /etc/nsswitch.conf | grep hosts

常见 DNS 问题 ​

bash
# 1. 解析慢 / 失败
#    看 /etc/resolv.conf 第一行是不是好的 DNS
#    换成 8.8.8.8 / 1.1.1.1 / 114.114.114.114

# 2. /etc/hosts 优先级高于 DNS
cat /etc/hosts                     # 手动解析

# 3. 缓存
sudo systemd-resolve --flush-caches
# 或
sudo /etc/init.d/nscd restart

🌍 HTTP 调试 ​

bash
# 看响应头 / 状态码
curl -I https://example.com
curl -v https://example.com

# 模拟各种请求
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name":"张三"}' \
  -H "Authorization: Bearer xxx"

# 看完整往返时间
curl -w "@-" -o /dev/null -s https://example.com <<'EOF'
    time_namelookup:  %{time_namelookup}s\n
       time_connect:  %{time_connect}s\n
    time_appconnect:  %{time_appconnect}s\n
       time_redirect:  %{time_redirect}s\n
  time_starttransfer:  %{time_starttransfer}s\n
                     ----------\n
          time_total:  %{time_total}s\n
EOF

🎣 抓包分析 ​

tcpdump ​

bash
# 基本抓包
sudo tcpdump -i eth0 port 80
# -i:网卡
# port: 过滤端口

# 写到文件
sudo tcpdump -i eth0 -w /tmp/cap.pcap port 80

# 看 HTTPS 不解(中间人),但能看连接 / SNI
sudo tcpdump -i eth0 -nn -s 0 port 443

# 过滤某个主机
sudo tcpdump -i eth0 host 10.0.1.5

# 组合
sudo tcpdump -i eth0 'port 80 and host 10.0.1.5'

把 /tmp/cap.pcap 拷到本地,Wireshark 打开看 GUI。

常用过滤 ​

bash
# TCP 三次握手
sudo tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0'

# 看 DNS
sudo tcpdump -i eth0 port 53

# 看 HTTP 请求
sudo tcpdump -i eth0 -A port 80
# -A: ASCII 输出

✅ 常见网络问题排查清单 ​

text
应用连不上 DB?
├─ 1. 网络通不通
│    nc -zv db-host 3306
├─ 2. DB 服务起来了?
│    ss -tulnp | grep 3306   (在 DB 机器上)
├─ 3. 防火墙
│    sudo iptables -L -n | grep 3306
│    云服务商安全组?
├─ 4. 应用配置
│    DB_HOST / DB_PORT 对不对
└─ 5. 用户权限
     GRANT ... TO user@'%'

调用外部 API 超时?
├─ 1. DNS 解析
│    dig api.example.com
├─ 2. 网络通
│    nc -zv api.example.com 443
├─ 3. 路由
│    traceroute api.example.com
├─ 4. 防火墙 / 代理
│    env | grep -i proxy
└─ 5. 应用超时设短了?
     timeout = 30s 可能不够

防火墙速查 ​

bash
# iptables(老)
sudo iptables -L -n
sudo iptables -L -n -t nat

# ufw(Ubuntu)
sudo ufw status
sudo ufw allow 80/tcp

# firewalld(CentOS / RHEL)
sudo firewall-cmd --list-all
sudo firewall-cmd --add-port=80/tcp --permanent

# 云服务商:ECS / CVM 安全组在控制台,不在主机内

⚠️ 容易踩的坑 ​

坑表现解决
ping 不通但服务能用ICMP 被防火墙挡改用 nc 测端口
curl https:// 超时443 出不去检查防火墙 / 代理 / 云安全组
curl 能通,浏览器不行浏览器代理 / DNS / 缓存排查浏览器设置
容器里 ping 不通容器默认无 pingapt install iputils-ping 或用 nc
ss 看不到连接在另一个 net namespacensenter -t PID -n ss -tunap
端口被监听但外网访问不到防火墙 / 安全组 / 监听 127.0.0.1ss -tulnp 看监听地址
0.0.0.0 vs 127.0.0.10.0.0.0 接所有,127.0.0.1 只接本地服务监听 0.0.0.0 才能外网访问
DNS 缓存导致改 hosts 不生效dig 还是老 IPsystemd-resolve --flush-caches
TCP TIME_WAIT 巨多高并发短连接后ss -tan state time-wait | wc -l,调 net.ipv4.tcp_tw_reuse=1
