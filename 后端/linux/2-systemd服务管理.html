🔧 systemd 是什么 ​

systemd 是现代 Linux 的服务管理器(init 系统),取代了老旧的 SysVinit。

text
内核启动
  ↓
systemd(PID 1)
  ↓ 拉起各种 service
  ├─ nginx.service
  ├─ mysql.service
  ├─ myapp.service   ← 你写的
  └─ ...

一个"服务"(service)由 unit 文件描述,放在固定目录。

📁 unit 文件位置 ​

路径谁放优先级
/etc/systemd/system/*.service系统管理员最高(你部署应用放这)
/run/systemd/system/*.service运行时中
/usr/lib/systemd/system/*.service系统包低(包管理器用)

应用部署一律放 /etc/systemd/system/,不要碰 /usr/lib/。

📝 Service unit 实战 ​

最小可运行模板 ​

/etc/systemd/system/myapp.service:

ini
[Unit]
Description=My Application
After=network.target              # 在网络起来之后启动

[Service]
Type=simple
User=app
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/node /opt/myapp/server.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

字段速查 ​

[Unit] 段 ​

字段作用
Description人类可读描述
After在谁之后启动(仅顺序,不等就绪)
Requires强依赖(失败连坐)
Wants弱依赖(失败不管)

[Service] 段 ​

字段常用值作用
Typesimple (默认) / forking / notify启动类型
User / Group用户名用非 root 跑
WorkingDirectory路径工作目录
ExecStart命令必填
ExecReload命令重新加载配置
ExecStop命令停止
Restartno / always / on-failure / on-abnormal何时重启
RestartSec秒重启前等多久
EnvironmentKEY=val环境变量
EnvironmentFile文件路径从文件读环境变量
StandardOutput / StandardErrorjournal / 文件日志输出

[Install] 段 ​

字段作用
WantedBy=multi-user.target多用户模式默认 target(开机自启)

🛠️ 常用 systemctl 命令 ​

bash
# 启停
sudo systemctl start myapp
sudo systemctl stop myapp
sudo systemctl restart myapp
sudo systemctl reload myapp          # 重新加载配置(不重启进程)

# 状态
sudo systemctl status myapp
sudo systemctl is-active myapp
sudo systemctl is-enabled myapp      # 是否开机自启

# 开机自启
sudo systemctl enable myapp
sudo systemctl disable myapp

# 重载 systemd(改了 unit 文件后)
sudo systemctl daemon-reload

# 看所有服务
systemctl list-units --type=service
systemctl list-unit-files --type=service

📜 journalctl 看日志 ​

systemd 把所有服务日志集中到 journal:

bash
# 看指定服务的日志
journalctl -u myapp
journalctl -u myapp -f               # 跟踪(f = follow)
journalctl -u myapp --since "1 hour ago"
journalctl -u myapp --since today
journalctl -u myapp -n 100           # 最近 100 行

# 看启动相关
journalctl -b                        # 本次启动
journalctl -b -1                     # 上次启动

# 按优先级
journalctl -p err                    # 错误及以上
journalctl -p warning

# 看全部
journalctl -f

日志大小限制 ​

/etc/systemd/journald.conf:

ini
[Journal]
SystemMaxUse=500M
SystemKeepFree=1G
MaxRetentionSec=30day
bash
sudo systemctl restart systemd-journald

# 手动清理
journalctl --vacuum-time=7d
journalctl --vacuum-size=500M

🟢 实战:Node 服务 ​

bash
# 1. 创建应用用户
sudo useradd -r -s /bin/false app
sudo mkdir -p /opt/myapp
sudo chown -R app:app /opt/myapp

/etc/systemd/system/myapp.service:

ini
[Unit]
Description=My Node App
After=network.target

[Service]
Type=simple
User=app
Group=app
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/node /opt/myapp/dist/server.js
Restart=on-failure
RestartSec=5
Environment=NODE_ENV=production
EnvironmentFile=/opt/myapp/.env

# 安全选项(生产推荐)
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/myapp

[Install]
WantedBy=multi-user.target
bash
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
sudo systemctl status myapp

🐍 实战:Python 服务(FastAPI) ​

bash
sudo useradd -r -s /bin/false appuser
sudo mkdir -p /opt/myapi
sudo chown -R appuser:appuser /opt/myapi

/etc/systemd/system/myapi.service:

ini
[Unit]
Description=My Python API
After=network.target

[Service]
Type=simple
User=appuser
WorkingDirectory=/opt/myapi
ExecStart=/opt/myapi/.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000 --workers 4
Restart=on-failure
RestartSec=5
EnvironmentFile=/opt/myapi/.env

[Install]
WantedBy=multi-user.target

⚠️ 容易踩的坑 ​

坑表现解决
改了 unit 没生效还是旧行为systemctl daemon-reload
启动失败没日志status 看不到原因journalctl -u myapp -n 50 --no-pager
用 root 跑应用容器逃逸 = 主机 root加 User=app
WorkingDirectory 不对找不到文件设绝对路径
Type 选错forking 服务报 Type=simple 错误Node/Python 一般用 simple,Nginx 用 forking
Restart=always 配错启动失败一直重启用 on-failure,再加 StartLimitIntervalSec
环境变量不生效应用读不到用 EnvironmentFile 而不是 Environment(空格路径会出 bug)
改了 systemd 配置系统挂了重启不了配 rescue 模式 / 保留旧版本
服务启动慢导致超时Job for xxx.service failedTimeoutStartSec=60 延长
