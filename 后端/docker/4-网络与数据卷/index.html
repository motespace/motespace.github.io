Docker 网络与数据卷

容器默认是“孤岛”。要让它和其他容器、和主机、和外网通,得懂网络。 数据要持久化,得懂 volume。这章讲清这两个底层。

🎯 学到这步能做什么

Section titled “🎯 学到这步能做什么”
  • 用 docker network 让容器互联
  • 把容器内端口暴露给外部
  • 用 volume 持久化数据
  • 区分 bind mount 和 named volume

🌐 网络模式

Section titled “🌐 网络模式”

模式 何时用
bridge(默认) 单机,容器互联
host 容器直接用主机网络(无隔离)
none 完全无网络
overlay 跨主机(Swarm / Kubernetes)
macvlan 容器有独立 MAC / IP(像真机)

bridge 详解

Section titled “bridge 详解”

为什么自定义网络比默认 bridge 好:

  • 默认 bridge 下,容器只能用 IP 互访(还要 --link,已过时)
  • 自定义网络下,自动 DNS 解析(用容器名)

💾 数据卷:volume vs bind mount

Section titled “💾 数据卷:volume vs bind mount”
维度 Volume(命名卷) Bind Mount(主机路径)
管理方 Docker 管理 用户管理
路径 /var/lib/docker/volumes/... 主机任意路径
备份 容易(docker volume) 看主机路径
跨平台 一致 Windows / Mac 性能差
适合 数据库数据 / 应用配置 开发时代码热更新

⚠️ 容易踩的坑

Section titled “⚠️ 容易踩的坑”
坑 表现 解决
容器间连不上 “no route to host” / DNS 失败 同一 network + 用服务名
bind mount 后容器内文件被覆盖 容器内有数据,主机没有 主机目录为空会“覆盖”容器内
改代码不生效 bind mount 路径错 检查 pwd 和容器路径
数据卷删了 数据库数据全没 docker volume rm 前确认
MySQL 容器重启后密码变了 改了 MYSQL_ROOT_PASSWORD 初始化后密码不能改,要么重建卷
macOS / Windows bind mount 慢 大文件 IO 慢 改用 named volume,或 --cached / --delegated
容器内时间不对 比主机晚 8 小时 -e TZ=Asia/Shanghai 或挂 /etc/localtime:/etc/localtime:ro
--link 已过时 用 --link 还在用 改自定义 network
端口冲突 bind: address already in use lsof -i :PORT / 换端口
