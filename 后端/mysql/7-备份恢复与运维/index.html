⚖️ 备份方式对比

Section titled “⚖️ 备份方式对比”
方式 工具 特点 适用
逻辑备份 mysqldump 导出 SQL,慢 小库 / 迁移
物理备份 xtrabackup / mysqlbackup 拷数据文件,快 大库 / 热备
增量备份 binlog 只记变更,极快 PIT(Point-In-Time)恢复

原则:

  • 至少每周全量 + 每天 binlog
  • 定期演练恢复(数据备份了但恢复不出来,等于没有)
  • 备份存异地(不同机房、不同云)

⚠️ 容易踩的坑

Section titled “⚠️ 容易踩的坑”
坑 表现 解决
--master-data=1 但又 STOP SLAVE 主从挂掉 主库用 =2(注释掉),从库手动写
没做恢复演练 真出事恢复不出来 每季度演练一次
备份在同机房 机房炸了备份也没了 异地备份(OSS / S3 / 异地机房)
binlog 没开 没 PIT 恢复能力 log_bin = ON + ROW 模式
从库 read_only 没开 应用误写从库,主从不一致 read_only = ON(super 权限也能绕,生产用 super_read_only)
主从延迟大 从库读到旧数据 接受(用缓存补偿) 或 强制读主
CHANGE MASTER TO 后没 START SLAVE 复制没启动 完整两步:CHANGE ... + START SLAVE
xtrabackup 恢复后启动不了 权限错 / InnoDB log 文件残留 chown -R mysql:mysql /var/lib/mysql
