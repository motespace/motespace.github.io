🔢 数值类型

Section titled “🔢 数值类型”
类型 字节 范围 用途
TINYINT 1 -128 ~ 127 / 0~255 UNSIGNED 年龄、状态码
SMALLINT 2 ±3.2 万 枚举数量
INT 4 ±21 亿 主键、计数
BIGINT 8 ±9.2 × 10¹⁸ 订单号、雪花 ID
FLOAT 4 7 位精度 不用
DOUBLE 8 15 位精度 科学计算
DECIMAL(M,D) 变长 精确小数 钱

要点:

  • 钱永远用 DECIMAL(10, 2),不要用 FLOAT / DOUBLE(浮点误差)
  • 主键自增用 INT UNSIGNED AUTO_INCREMENT,够 21 亿单表
  • 超大表 / 分布式用 BIGINT,可放雪花 ID(19 位)
  • 状态码 / 枚举用 TINYINT,省 3 字节比 INT

📝 字符串类型

Section titled “📝 字符串类型”
类型 长度上限 用途
CHAR(N) 255 固定长度(国家代码、MD5、UUID)
VARCHAR(N) 65535 / 实际 65533 可变长度(姓名、邮箱)
TEXT 65535 长文本(评论)
MEDIUMTEXT 16 MB 文章正文
LONGTEXT 4 GB 不推荐,文件存磁盘
ENUM 65535 个 固定选项
JSON 1 GB JSON 数据(MySQL 5.7+)

要点:

  • VARCHAR(N) 的 N 是字符数不是字节数
  • CHAR(32) 存 MD5、UUID(去掉 -)刚好,长度固定用 CHAR 比 VARCHAR 快
  • TEXT 字段不参与内存临时表,大字段考虑单独存表
  • JSON 类型(MySQL 5.7+)可以查询内部字段,比 TEXT + JSON.parse 好

⏱️ 时间类型

Section titled “⏱️ 时间类型”
类型 格式 占用 范围 用途
DATE YYYY-MM-DD 3 1000-01-01 ~ 9999-12-31 生日
TIME HH:MM:SS 3 ±838 小时 时长
DATETIME YYYY-MM-DD HH:MM:SS 8 1000-01-01 ~ 9999-12-31 创建时间(业务时间)
TIMESTAMP 同上 4 1970 ~ 2038 更新时间(UTC 自动转换)
YEAR YYYY 1 1901 ~ 2155 年份

要点:

  • 业务时间用 DATETIME(不受时区影响,不踩 2038 问题)
  • TIMESTAMP 有 2038 年问题,数据量大时慎用
  • 不用 VARCHAR 存时间,排序 / 比较 / 函数全失效
  • 时区:DB 服务器时区 + 应用服务器时区 + 用户时区,统一存 UTC 展示时转

🔑 主键设计

Section titled “🔑 主键设计”

自然主键 vs 代理主键

Section titled “自然主键 vs 代理主键”
类型 含义 例子
自然主键 业务字段本身唯一 身份证号、订单号
代理主键 与业务无关,只为唯一 自增 ID、UUID

经验:默认用代理主键(BIGINT AUTO_INCREMENT),除非业务字段真的稳定唯一。

UUID / 雪花 ID

Section titled “UUID / 雪花 ID”

分布式系统需要全局唯一 ID:

方案 长度 特点
自增 ID 8 字节 单库最快,不能分布式
UUIDv4 36 / 32 无序,索引性能差
UUIDv7(新) 36 / 16 字节 时间有序,推荐
雪花 ID 8 字节 long 分布式有序,Twitter / 美团用
雪花字符串 18 字符 业务可见,但要存 VARCHAR

🔗 外键与关联

Section titled “🔗 外键与关联”

实际项目里很多团队不用外键约束,理由:

  1. 性能开销(每次 INSERT/UPDATE 都要检查)
  2. 分布式 / 分库分表后外键失效
  3. ORM 自己维护关联关系

推荐做法:业务逻辑保证完整性,数据库只建索引不建外键约束(代码层用 SQLAlchemy / Prisma 关联)。

🔄 反范式:为了性能而冗余

Section titled “🔄 反范式:为了性能而冗余”

范式越严,JOIN 越多。高并发 / 高 QPS 读场景,适度反范式:

反范式原则:

  • 读多写少 → 反范式划算
  • 数据要严格一致(钱、库存) → 不反范式,事务保证
  • 冗余字段更新成本要可控(异步、消息队列)

⚠️ 容易踩的坑

Section titled “⚠️ 容易踩的坑”
坑 表现 解决
用 VARCHAR(255) 存一切 浪费空间、查询慢 按实际长度选
钱用 FLOAT / DOUBLE 计算误差(0.1 + 0.2 ≠ 0.3) 永远用 DECIMAL
时间存 VARCHAR 排序 / 比较失效,索引无用 DATETIME / TIMESTAMP
状态用中文 VARCHAR 存 '已付款' 占空间 用 TINYINT + 注释
TEXT 当主键 / 索引 不支持 用前缀索引:INDEX (content(50))
自增 ID 归零 / 溢出 21 亿后 BIGINT 续命 评估数据量,大表用 BIGINT
主键 UUID 用 VARCHAR(36) 索引性能差,占空间 用 BINARY(16) 或 UUIDv7
字段都 NOT NULL 不设默认值 业务代码到处 if is None 关键字段必设默认值
