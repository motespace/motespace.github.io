MySQL CRUD 与查询 ​

CRUD 是基本功,但 JOIN / 子查询 / 聚合才是真实面试 / 业务高频考点。 本文给完整的查询"兵器谱",从单表到多表。

🎯 学到这步能做什么 ​

  • 写完整 CRUD(增删改查)
  • 用 WHERE / ORDER / LIMIT / GROUP 组合查询
  • 写 INNER / LEFT / RIGHT JOIN
  • 用子查询、聚合函数、HAVING

➕ INSERT 进阶 ​

sql
-- 1. 单条插入
INSERT INTO users (name, email, age) VALUES ('张三', 'z@a.com', 25);

-- 2. 批量插入(快得多)
INSERT INTO users (name, email, age) VALUES
  ('李四', 'l@a.com', 30),
  ('王五', 'w@a.com', 28),
  ('赵六', 'z@a.com', 35);

-- 3. 插入或更新(ON DUPLICATE KEY)
INSERT INTO users (name, email, age) VALUES ('张三', 'z@a.com', 26)
ON DUPLICATE KEY UPDATE age = VALUES(age);
-- 适合"先查再改"的场景,原子操作

-- 4. INSERT IGNORE:遇到唯一键冲突就跳过
INSERT IGNORE INTO users (name, email) VALUES ('张三', 'z@a.com');
-- 不报错,但也不知道有没有真插进去,慎用

-- 5. 从 SELECT 结果插入
INSERT INTO user_archive (id, name, email)
SELECT id, name, email FROM users WHERE created_at < '2024-01-01';

批量插入大小 ​

sql
-- 推荐每批 1000-5000 行,过大事务回滚慢
INSERT INTO logs (...) VALUES (...), (...), ...;

⚠️ UPDATE / DELETE 安全写法 ​

永远先 SELECT 看要改哪些:

sql
-- 1. 先 SELECT 看一眼
SELECT * FROM users WHERE name = '张三';

-- 2. UPDATE(带 WHERE,不带全表更新!)
UPDATE users SET age = 26 WHERE name = '张三';

-- 3. 加 LIMIT 防御
UPDATE users SET age = 26 WHERE name = '张三' LIMIT 1;

-- 4. 事务包裹(可以回滚)
START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
-- 确认没问题再 COMMIT
COMMIT;
-- 或 ROLLBACK;

DELETE 三态 ​

sql
-- 1. DELETE FROM:真删(慢,会写 binlog)
DELETE FROM logs WHERE created_at < '2023-01-01';

-- 2. TRUNCATE:清空全表,重置自增(DDL)
TRUNCATE TABLE logs;

-- 3. 软删除:加 deleted_at 字段
UPDATE users SET deleted_at = NOW() WHERE id = 123;
-- 查询时 WHERE deleted_at IS NULL

生产环境几乎都用软删除,保留数据 + 可恢复。

🔍 SELECT 完整语法 ​

sql
SELECT [DISTINCT] columns
FROM table
[JOIN other_table ON conditions]
[WHERE conditions]
[GROUP BY columns]
[HAVING conditions]              -- 对聚合后的结果筛选
[ORDER BY columns [ASC|DESC]]
[LIMIT N [OFFSET M]];

执行顺序:FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

(这是写 SQL 时心里要默念的"流水线")

🎯 WHERE 条件 ​

sql
-- 比较
WHERE age >= 18
WHERE status = 1

-- 范围
WHERE age BETWEEN 18 AND 30
WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31'

-- 集合
WHERE city IN ('北京', '上海', '杭州')
WHERE id NOT IN (1, 2, 3)

-- 模糊匹配
WHERE name LIKE '张%'              -- 张开头
WHERE name LIKE '%三'              -- 三结尾
WHERE name LIKE '%中%'             -- 含中
-- 注意:LIKE 'xxx%' 能用索引,LIKE '%xxx' 用不了

-- NULL
WHERE deleted_at IS NULL           -- 不能用 = NULL
WHERE deleted_at IS NOT NULL

-- 多条件
WHERE age >= 18 AND city = '北京'
WHERE status = 1 OR status = 2

📊 ORDER BY / LIMIT ​

sql
-- 排序
SELECT * FROM users ORDER BY created_at DESC;             -- 最新优先
SELECT * FROM users ORDER BY age DESC, id ASC;            -- 先年龄后 ID

-- 分页(慢!)
SELECT * FROM users ORDER BY id LIMIT 20 OFFSET 0;        -- 第 1 页
SELECT * FROM users ORDER BY id LIMIT 20 OFFSET 20;       -- 第 2 页
SELECT * FROM users ORDER BY id LIMIT 20 OFFSET 1000000;  -- 第 50001 页,巨慢!

分页优化:深翻页 ​

sql
-- ❌ OFFSET 越大越慢(MySQL 要扫 OFFSET + LIMIT 行再扔掉)
SELECT * FROM users ORDER BY id LIMIT 20 OFFSET 1000000;

-- ✅ 游标分页(seek pagination)
SELECT * FROM users WHERE id > 1000000 ORDER BY id LIMIT 20;
-- 上一页最后一条的 id 传过来,WHERE id > last_id

📈 聚合与 GROUP BY ​

sql
-- 聚合函数
SELECT COUNT(*) FROM users;
SELECT AVG(age) FROM users;
SELECT MAX(age), MIN(age) FROM users;
SELECT SUM(amount) FROM orders;

-- 分组
SELECT city, COUNT(*) AS cnt, AVG(age) AS avg_age
FROM users
GROUP BY city
HAVING cnt > 10                      -- 筛掉小城市
ORDER BY cnt DESC;

要点:

  • SELECT 里的非聚合列必须出现在 GROUP BY 里(MySQL 严格模式)
  • WHERE 筛行,HAVING 筛组
  • 聚合函数会扫表,大表上慎用

🔗 JOIN 联表查询 ​

sql
-- 数据准备
users:   id, name
orders:  id, user_id, amount

INNER JOIN:只返回两表都匹配的 ​

sql
SELECT u.name, COUNT(o.id) AS order_count, SUM(o.amount) AS total
FROM users u
INNER JOIN orders o ON u.id = o.user_id
WHERE u.city = '北京'
GROUP BY u.id, u.name
HAVING order_count > 0
ORDER BY total DESC;

LEFT JOIN:左表全保留,右表没匹配的填 NULL ​

sql
-- 找出所有用户(包括没下过单的)
SELECT u.name, COUNT(o.id) AS order_count
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
GROUP BY u.id, u.name;

三种 JOIN 图解 ​

多表 JOIN ​

sql
SELECT
    o.id AS order_id,
    u.name AS user_name,
    p.name AS product_name,
    oi.quantity,
    oi.price
FROM orders o
JOIN users u        ON o.user_id  = u.id
JOIN order_items oi ON o.id       = oi.order_id
JOIN products p     ON oi.product_id = p.id
WHERE o.created_at > '2024-01-01'
LIMIT 100;

🪆 子查询 ​

sql
-- WHERE 子查询:找出下过单的用户
SELECT * FROM users WHERE id IN (SELECT DISTINCT user_id FROM orders);

-- FROM 子查询:把子查询当临时表
SELECT t.city, AVG(t.amount) FROM
  (SELECT u.city, o.amount FROM users u JOIN orders o ON u.id = o.user_id) t
GROUP BY t.city;

-- 标量子查询(返回单个值)
SELECT name, (SELECT COUNT(*) FROM orders WHERE user_id = users.id) AS cnt
FROM users;

关联子查询(慢,慎用):

sql
-- ❌ 每行都跑一次子查询
SELECT * FROM users u
WHERE EXISTS (SELECT 1 FROM orders WHERE user_id = u.id);

-- ✅ 通常用 JOIN 替代
SELECT DISTINCT u.* FROM users u
JOIN orders o ON u.id = o.user_id;

⚠️ 容易踩的坑 ​

坑表现解决
SELECT *浪费 IO,字段变更炸代码明确列名:SELECT id, name
WHERE 没用索引字段全表扫描走 索引章节
LIMIT N, M 深分页巨慢改游标分页 / WHERE id > last_id
WHERE age+1 = 20索引失效改 WHERE age = 19
LIKE '%xxx%'索引失效全文索引 / ES
IN (SELECT ...) 返回大结果集慢改 JOIN
没 LIMIT 的 UPDATE / DELETE全表更新 / 删库永远加 WHERE 和 LIMIT
GROUP BY 字段忘了聚合严格模式报错非聚合列全加 GROUP BY
COUNT(*) 慢全表扫副表存计数 / 用近似值
