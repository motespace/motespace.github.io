⚖️ ACID 四大特性

Section titled “⚖️ ACID 四大特性”
特性 含义 实现机制
Atomic 原子性 全成或全败 undo log
Consistent 一致性 数据从不合法状态过渡到合法 应用 + DB 约束
Isolation 隔离性 并发事务互不干扰 锁 + MVCC
Durable 持久性 提交后不丢 redo log

🔬 四种隔离级别

Section titled “🔬 四种隔离级别”

并发问题有 3 类:脏读 / 不可重复读 / 幻读。

隔离级别 脏读 不可重复读 幻读 性能
READ UNCOMMITTED ✅ ✅ ✅ 最高
READ COMMITTED ❌ ✅ ✅ 高
REPEATABLE READ(MySQL 默认) ❌ ❌ ✅(InnoDB 大部分场景无) 中
SERIALIZABLE ❌ ❌ ❌ 最低

概念解释

Section titled “概念解释”
  • 脏读:读到别人未提交的数据(别人回滚你就用了错的数据)
  • 不可重复读:同一事务内,两次读同一行,数据不一样(被别的事务改了)
  • 幻读:同一事务内,两次查同一范围,行数不一样(被别的事务插入/删除了)

MySQL InnoDB 在 REPEATABLE READ 下通过 MVCC + 临键锁基本避免了幻读。

🔐 锁的类型

Section titled “🔐 锁的类型”

按粒度:

锁类型 范围 开销 并发度
全局锁 整个 DB 极大 极低
表级锁 整张表 大 低(MyISAM 用)
行级锁 单行 / 范围 小 高(InnoDB 默认)

按模式:

锁 描述 兼容
共享锁(S) 读锁,可多人共持 S 与 S 兼容
排他锁(X) 写锁,独占 X 与谁都不兼容

🔒 行锁 / 间隙锁 / 临键锁

Section titled “🔒 行锁 / 间隙锁 / 临键锁”

InnoDB 的行锁是索引上的锁,不是“行记录”上的锁。

锁 范围 何时用
Record Lock 索引上的具体一条记录 等值查询命中
Gap Lock 索引记录之间的“间隙” 防止插入新行(防幻读)
Next-Key Lock Record + Gap,左开右闭 默认,REPEATABLE READ 用

间隙锁例子

Section titled “间隙锁例子”

实战:

  • 查询走索引 → 行锁 / 间隙锁(细)
  • 查询没走索引 → 表锁(粗)
  • REPEATABLE READ + 索引查询是最常用的高并发方案

避免死锁

Section titled “避免死锁”
  • 加锁顺序一致:多表操作约定统一的加锁顺序
  • 尽量用主键或唯一索引查(锁范围小)
  • 大事务拆小事务(长时间持锁是死锁温床)
  • 设置锁等待超时:SET innodb_lock_wait_timeout = 5(秒)
  • 用 SELECT ... FOR UPDATE NOWAIT / SKIP LOCKED(MySQL 8+)不阻塞

⚠️ 容易踩的坑

Section titled “⚠️ 容易踩的坑”
坑 表现 解决
事务里做 HTTP 调用 长时间持锁,阻塞别人 事务内只做 DB 操作,HTTP 放外面
事务里 SELECT sleep(10) 等同持锁 10 秒 不要在事务里 sleep
大事务(改 100 万行) undo log 暴涨,锁竞争 拆小批量
用 SERIALIZABLE 解决并发 性能暴跌 大部分场景 REPEATABLE READ 足够
FOR UPDATE 没走索引 表锁,锁全表 必须走索引
RC 隔离级别下没加 FOR UPDATE 不可重复读 业务允许就用 RC,不能就用 RR + 锁
死锁就重试同一个事务 死循环 加最大重试次数 + 退避
innodb_lock_wait_timeout 默认 50 秒 用户等不及 改 5-10 秒,失败快速返回
