网络安全清单

上线前 / 周常运维必查项。复制到 PR 模板或运维 Runbook。

一、HTTPS 配置

Section titled “一、HTTPS 配置”

1.1 必做

Section titled “1.1 必做”
  • 全站强制 HTTPS(301 重定向 HTTP → HTTPS)
  • HSTS 头(1 年 + includeSubDomains + preload)
  • TLS 1.2+(禁用 SSLv3 / TLS 1.0 / 1.1)
  • 强加密套件(ECDHE 优先)
  • OCSP Stapling
  • Certificate Transparency(自动)

1.2 检查命令

Section titled “1.2 检查命令”

1.3 证书管理

Section titled “1.3 证书管理”
  • 自动续期(Let’s Encrypt 90 天)
  • 过期前 30 天告警
  • 私钥不进 git / 日志
  • 定期轮换(1~2 年)

二、Cookie 安全

Section titled “二、Cookie 安全”

2.1 必做

Section titled “2.1 必做”
  • 鉴权 Cookie 用 HttpOnly
  • 强制 HTTPS 的 Cookie 用 Secure
  • 跨域 Cookie 用 SameSite=Lax 或 Strict
  • 重要 Cookie 加 __Host- 前缀
  • Cookie 不要存敏感信息(token 用短期,refresh 用长期)

2.2 检查

Section titled “2.2 检查”

三、CORS 配置

Section titled “三、CORS 配置”

3.1 必做

Section titled “3.1 必做”
  • 白名单(不用 *)
  • Allow-Credentials: true 时,Allow-Origin 不能是 *
  • 加 Vary: Origin 头
  • 预检缓存 Access-Control-Max-Age: 86400
  • OPTIONS 预检返回 204

3.2 检查

Section titled “3.2 检查”

四、CSP(内容安全策略)

Section titled “四、CSP(内容安全策略)”

4.1 必做

Section titled “4.1 必做”
  • 至少 Content-Security-Policy-Report-Only
  • default-src 'self' 起步
  • frame-ancestors 'none' 防点击劫持
  • base-uri 'self' 防劫持
  • 收集违规报告

🎯 面试常考

Section titled “🎯 面试常考”

Q1：前端能做什么,不能做什么?

Section titled “Q1：前端能做什么,不能做什么?”

能做的:

  • 避免 XSS(不 innerHTML 拼字符串、用框架转义、富文本过 DOMPurify)
  • 防 CSRF(SameSite + Token + Origin/Referer 校验)
  • 防点击劫持(X-Frame-Options / CSP frame-ancestors)
  • 不把密钥写进代码、不把敏感数据存 localStorage
  • 给第三方脚本加 SRI、用 CSP 限制脚本来源

不能做的(必须服务端做):

  • 真正的鉴权与授权(前端隐藏按钮等于没隐藏)
  • 参数校验(前端校验只是体验)
  • 限流、防重放、审计

Q2：CSP 怎么配才既安全又不出问题?

Section titled “Q2：CSP 怎么配才既安全又不出问题?”

渐进落地,别一上来就 default-src 'none':

  1. 先用 Report-Only 上线,收集违规报告
  2. 按报告逐条收紧
  3. 内联脚本用 nonce(每次响应生成随机值)或 hash,不要用 unsafe-inline
  4. script-src 不加 unsafe-eval(除非用了运行时编译)
  5. object-src 'none'、base-uri 'self'、frame-ancestors 'none' 这几条几乎无副作用,可以直接开

Q3：密钥应该怎么管理?

Section titled “Q3：密钥应该怎么管理?”

三条铁律:

  1. 不进前端 bundle —— import.meta.env.VITE_xxx 会被打进产物,任何人都能看 (这是最常见的泄露方式)
  2. 不提交仓库 —— 用环境变量 / 配置中心 / CI Secret,.env 加进 .gitignore
  3. 定期轮换 —— 泄漏后要能快速作废

检测:CI 里跑 gitleaks / trufflehog 扫提交历史, 前端产物里搜 sk-、AKIA 等密钥特征串。

📝 小结

Section titled “📝 小结”
  • 这份清单是发版前的闸门:传输层、认证、授权、输入、依赖、密钥、监控七个维度。
  • 前端不是安全边界 —— 前端隐藏的按钮等于没有,权限必须服务端校验。
  • 最容易被忽略的三条:密钥进了前端 bundle、依赖有已知漏洞没扫、只在前端做了权限判断。
  • 清单要能落到具体配置(响应头、环境变量、扫描命令),否则没法执行。
