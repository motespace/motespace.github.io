HTTP 状态码详解

一、为什么要关心状态码

Section titled “一、为什么要关心状态码”

HTTP 状态码是服务器对请求结果的标准化表达。前端需要根据状态码决定下一步操作:

  • 401:跳转登录
  • 403:无权限,提示
  • 404:找不到
  • 5xx:重试或提示
  • 304:协商缓存命中

常见错误:所有非 2xx 都按“系统错误”处理,导致用户看到“系统繁忙”提示,实际是登录失效。

1xx(信息性)— 几乎不用

Section titled “1xx(信息性)— 几乎不用”
状态码 含义
100 Continue 客户端发大 body 前先询问服务端是否接受
101 Switching Protocols WebSocket 升级响应

2xx(成功)

Section titled “2xx(成功)”
状态码 含义 前端处理
200 OK 请求成功 正常使用
201 Created 资源创建成功 POST 后返回新资源
202 Accepted 请求已接受但未完成 异步任务
204 No Content 成功但无响应体 DELETE 成功后
206 Partial Content 范围请求成功 视频分段下载

3xx(重定向)

Section titled “3xx(重定向)”
状态码 含义 前端处理
301 Moved Permanently 永久重定向 浏览器缓存,后续请求直接走新地址
302 Found 临时重定向 每次都重新请求
303 See Other 用 GET 重定向 POST 后跳 GET
304 Not Modified 协商缓存命中 用本地缓存
307 Temporary Redirect 临时重定向(保持方法) POST 重定向到 POST
308 Permanent Redirect 永久重定向(保持方法) 同 301 但保留方法

301 vs 302 区别:

  • 301:浏览器永久缓存,后续请求直接走新地址(SEO 友好)
  • 302:每次都重新请求(不缓存)

实战经验:URL 变更后用 301;临时跳转用 302 或 307。

Section titled “4xx(客户端错误)”
状态码 含义 前端处理
400 Bad Request 请求格式错误 检查请求参数
401 Unauthorized 未登录 / token 失效 跳转登录
403 Forbidden 登录了但没权限 提示“无权限访问”
404 Not Found 资源不存在 404 页面
405 Method Not Allowed 请求方法不允许 检查 API 文档
408 Request Timeout 请求超时 重试
409 Conflict 资源冲突 提示用户
410 Gone 资源永久删除 不可恢复
413 Payload Too Large 请求体过大 检查上传文件
414 URI Too Long URL 太长 检查参数
415 Unsupported Media Type Content-Type 不支持 检查请求头
422 Unprocessable Entity 校验失败 显示具体错误
429 Too Many Requests 请求过多 限速、重试

🎯 面试常考

Section titled “🎯 面试常考”

Q1：HTTP 状态码怎么分类?301 和 302 的区别是什么?

Section titled “Q1：HTTP 状态码怎么分类?301 和 302 的区别是什么?”

按语义分五类:

  • 1xx 信息(100 Continue、101 Switching Protocols)
  • 2xx 成功(200 OK、201 Created、204 No Content、206 Partial Content)
  • 3xx 重定向(301 永久、302 临时、304 Not Modified、307/308 保持方法重定向)
  • 4xx 客户端错误(400、401 未认证、403 已认证但无权限、404、409 冲突、429 限流)
  • 5xx 服务端错误(500、502 Bad Gateway、503 服务不可用、504 网关超时)

301 vs 302:

  • 301 = 永久重定向,浏览器会缓存这个映射,以后直接用新地址
  • 302 = 临时重定向,不缓存

实务坑:改域名用 301(搜索引擎转移权重),但登录后的跳转不能用 301—— 浏览器缓存了 301 之后,下次登录会直接跳到旧地址,用户永远回不来。登录跳转要用 302。

307/308 保持原请求方法(POST 仍是 POST),比 302 更严格。

Q2：401 和 403 的区别?什么时候用 401?

Section titled “Q2：401 和 403 的区别?什么时候用 401?”
  • 401 Unauthorized(名字有误导,实际是 Unauthenticated):没认证。响应应带 WWW-Authenticate 头,告诉客户端怎么认证
  • 403 Forbidden:认证了但没权限

前端处理:

  • 401 → 触发登录/刷新 Token 流程
  • 403 → 提示无权限,不要跳登录(用户已登录,跳过去会让他以为掉线了)

一个坑:401 也会被浏览器拦截,导致前端拿不到响应体里的业务错误码。 所以很多项目会用业务码(响应体里放 code: "TOKEN_INVALID")而不是 HTTP 401, 让前端能正常读到错误信息 —— 这也是 商户管理 SaaS 平台 里 INVALIDATION 业务码的由来。

Q3：429 和 503 的区别?限流应该返回哪个?

Section titled “Q3：429 和 503 的区别?限流应该返回哪个?”
  • 429 Too Many Requests:客户端请求太频繁。应该带 Retry-After 头告诉客户端多久后再试
  • 503 Service Unavailable:服务暂时不可用(过载、维护中)。可以带 Retry-After

限流返回 429,并配合响应头:

前端要做的:不要无脑重试。指数退避 + 抖动(jitter), 否则限流下所有客户端同时重试,把服务再打垮一次。

📝 小结

Section titled “📝 小结”
  • 五类状态码的语义边界要清楚,尤其 4xx(客户端错)vs 5xx(服务端错),排查线上问题时靠这个分流。
  • 301 是永久且浏览器会缓存,302 是临时;登录后跳转绝不能用 301,否则浏览器缓存后永远跳不回来。
  • 401 是没认证(要带 WWW-Authenticate),403 是认证了没权限;前端对 401 要跳登录,对 403 不要跳。
  • 429 用于限流(带 Retry-After),503 用于服务不可用;前端重试必须指数退避 + 抖动。
