Section titled “一、HTTP 基础”

Q1:HTTP 和 HTTPS 的区别?

Section titled “Q1:HTTP 和 HTTPS 的区别?”

答:

HTTPS 在 HTTP 基础上加:

  • TLS 握手(身份认证 + 密钥交换)
  • 数据加密(防窃听)
  • 数据完整性校验(防篡改)
  • 数字证书(防中间人)

Q3:HTTP/1.1 的队头阻塞?

Section titled “Q3:HTTP/1.1 的队头阻塞?”

答: HTTP/1.1 一个 TCP 连接上一个请求-响应完成后才能发下一个。即使浏览器开 6 个连接,也只是缓解。

HTTP/2 多路复用:一个 TCP 连接上多流,流内仍可能有队头阻塞(TCP 层丢包)。 HTTP/3 / QUIC:独立的流,一个流丢包不影响其他流。

详见 HTTP/1.1 队头阻塞与绕行手段

Q4:HTTP/2 vs HTTP/1.1 改进?

Section titled “Q4:HTTP/2 vs HTTP/1.1 改进?”

答:

  1. 二进制分帧:代替文本协议
  2. 多路复用:单连接并行多请求
  3. 头部压缩:HPACK 算法
  4. 服务器推送:已弃用(实际很少用)
  5. 流量优先级:高优先级帧先发

详见 HTTP/2 机制:分帧、多路复用与 HPACK

Q5:HTTP/3 基于什么?为什么?

Section titled “Q5:HTTP/3 基于什么?为什么?”

答:QUIC(基于 UDP)。

  • 解决 TCP 队头阻塞
  • 0-RTT 握手(更快)
  • 内置 TLS 1.3
  • 连接迁移(WiFi 切 4G 不重连)

详见 HTTP/3 与 QUIC 深度

Q18:DoH / DoT 是什么?

Section titled “Q18:DoH / DoT 是什么?”

答:

  • DoH(DNS over HTTPS):DNS 查询用 HTTPS 加密(端口 443)
  • DoT(DNS over TLS):DNS 查询用 TLS 加密(端口 853)
  • 防止运营商/防火墙劫持、监听 DNS 查询

Q20:WebSocket 心跳?

Section titled “Q20:WebSocket 心跳?”

答:

  • 客户端定期发 Ping(或者业务消息)

Q22:为什么 HTTP/2 后不需要雪碧图?

Section titled “Q22:为什么 HTTP/2 后不需要雪碧图?”

答: HTTP/2 多路复用,一个连接能并行下载多个小文件。雪碧图反而:

  • 增加 HTTP 缓存复杂度
  • 不能单独失效(改一个像素整个 sprite 失效)
  • 维护成本高

HTTP/2 时代:细颗粒度资源更优。

Q23:HTTPS 比 HTTP 慢多少?

Section titled “Q23:HTTPS 比 HTTP 慢多少?”

答:

  • 现代 CPU 有 AES-NI 指令集,加密开销 < 1%
  • TLS 1.3 1-RTT 握手(相比 TLS 1.2 2-RTT)
  • HTTP/2 强制 HTTPS,反而比 HTTP/1.1 快(多路复用)
  • 实际:几乎无性能差距

Q25:从 network 优化角度如何优化?

Section titled “Q25:从 network 优化角度如何优化?”

答:

  1. 减少请求数:合并、雪碧图、删除冗余
  2. 减小请求体积:压缩(gzip/Brotli)、图片优化、tree-shaking
  3. 缓存:强缓存、协商缓存、Service Worker
  4. 协议优化:HTTP/2、HTTP/3、TLS 1.3
  5. 就近访问:CDN、Anycast
  6. 预测加载:prefetch、preload

Q26:跨域方案对比?

Section titled “Q26:跨域方案对比?”

答:

方案 适用 限制
CORS 现代 API 跨域 复杂请求需预检
JSONP 老 API(GET) 仅 GET,难维护
postMessage iframe 跨域 需校验 origin
Nginx 反代 老项目快速解决 单点
CORS Anywhere 开发临时用 生产不安全

Q27:TCP 三次握手中可以携带数据吗?

Section titled “Q27:TCP 三次握手中可以携带数据吗?”

答:

  • 第三次 ACK 可以携带数据(此时客户端已确认能收到)
  • 前两次不能(防止攻击)

Q28:HTTPS 一定安全吗?

Section titled “Q28:HTTPS 一定安全吗?”

答:不一定。

  • HTTPS 只防传输层窃听/篡改
  • 应用层漏洞(XSS、CSRF、SQL 注入)HTTPS 防不了
  • 用户主动忽略证书警告
  • 自签名证书滥用

安全是纵深防御:HTTPS + CSP + 输入验证 + 鉴权。

📝 小结

Section titled “📝 小结”
  • 这一页是网络题的总索引,按 HTTP 基础 / 缓存 / 跨域与安全 / TCP / DNS / WebSocket / 性能分组。
  • 答这类题的统一结构:结论 → 原理 → 对比 → 场景,不要只背结论。
  • HTTP/2 解决 HTTP 层队头阻塞,HTTP/3 解决 TCP 层队头阻塞 —— 这句是高频送分点。
  • CORS 防「偷数据」,CSRF 防「发副作用」,SameSite 和 Token 是防 CSRF 的主力。
