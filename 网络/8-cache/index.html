8.2 强缓存（Cache-Control / Expires）

Section titled “8.2 强缓存（Cache-Control / Expires）”

Cache-Control 指令：

指令 含义
max-age=N 缓存 N 秒
no-cache 不直接用缓存，每次问服务器
no-store 完全不缓存
private 只允许浏览器缓存，CDN 不能
public 所有代理都能缓存
s-maxage=N CDN 缓存 N 秒
immutable 永不过期（带 hash 的文件名用）
must-revalidate 过期后必须重新验证
stale-while-revalidate=N 过期后 N 秒内用旧值

8.3 协商缓存（Last-Modified / ETag）

Section titled “8.3 协商缓存（Last-Modified / ETag）”

ETag vs Last-Modified：

ETag Last-Modified
精度 哈希指纹，精确到内容 秒级，文件内容变了但 mtime 没变会漏
性能 计算哈希略慢 直接读文件时间，快
适用 文件经常改动 文件改动频率低

🎯 面试常考

Section titled “🎯 面试常考”

Q1：强缓存和协商缓存的区别?什么时候会走协商缓存?

Section titled “Q1：强缓存和协商缓存的区别?什么时候会走协商缓存?”

强缓存:浏览器直接用本地副本,根本不发请求。由 Cache-Control / Expires 控制。

协商缓存:浏览器发请求,但带上 If-None-Match(ETag)或 If-Modified-Since(Last-Modified)。 服务端比对后:变了返回 200 + 新内容,没变返回 304(不带 body)。

什么时候走协商缓存:强缓存已过期,但资源还在有效期内(ETag 匹配则 304)。

优先级:先看强缓存 → 命中就用;没命中 → 发请求带条件头 → 304 或 200。

Q2：no-cache 和 no-store 有什么区别?

Section titled “Q2：no-cache 和 no-store 有什么区别?”

名字很像,含义完全不同:

  • no-cache:可以缓存,但每次使用前必须向服务端验证。不是「不缓存」
  • no-store:完全不缓存,任何时候都不存

常见误解:以为 no-cache = 不缓存,结果把带 hash 的静态资源设成 no-cache, 导致每个资源都发 304 请求,白白浪费。

正确用法:HTML 入口用 no-cache(要能拿到新版本),带 hash 的静态资源用 max-age=31536000, immutable。

Q3：ETag 是什么?为什么有了它还需要 Last-Modified?

Section titled “Q3：ETag 是什么?为什么有了它还需要 Last-Modified?”

ETag 是资源的内容指纹(如 "a1b2c3-17482943"),语义是「这个版本的标识」。

Last-Modified 是最后修改时间,只能精确到秒。

为什么两个都要:

  • ETag 更精确(内容变了但时间没变也能识别),但需要服务端计算指纹
  • Last-Modified 便宜,但同一秒内多次修改会漏判

强 ETag("xxx"):内容变了就变;弱 ETag(W/"xxx"):语义等价但字节不同的资源也返回同样的值, 适合动态生成的内容(如 gzip 前后内容不同)。

注意:CDN 场景下 ETag 必须包含压缩算法维度,否则会把 br 版发给不支持的客户端。

Q4：用户改了内容,但浏览器还是旧的,怎么排查?

Section titled “Q4：用户改了内容,但浏览器还是旧的,怎么排查?”

按这个顺序查:

  1. 响应头有没有 Cache-Control —— 没有就是走启发式缓存,浏览器自己猜过期时间
  2. 是不是配了 no-cache 但 CDN 忽略了它 —— CDN 的缓存规则优先级常常盖过源站
  3. 文件名有没有 hash —— app.js 改内容后 URL 不变,浏览器拿不到新版本;必须 app.[contenthash].js
  4. Service Worker 缓存没更新 —— SW 缓存和 HTTP 缓存是两套,SW 没换代就一直给旧的
  5. Vary 头 —— 缺 Vary: Accept-Encoding 会让 CDN 把 gzip 版发给 br 客户端

根治方案:文件名带 contenthash + 静态资源 immutable 长缓存 + HTML 入口 no-cache。

📝 小结

Section titled “📝 小结”
  • 两级缓存:强缓存不发请求,协商缓存发请求但可能返回 304;顺序是强缓存优先。
  • no-cache 是「缓存但每次要验证」,no-store 才是「不缓存」——这两个名字最容易搞混。
  • 带 hash 的静态资源用 max-age=31536000, immutable,HTML 入口用 no-cache,这是标准搭配。
  • 「改了不生效」最常见的原因是文件名没 hash + Service Worker 缓存没换代,排查要同时看 HTTP 缓存和 SW 缓存。
