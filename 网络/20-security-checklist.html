网络安全清单 ​

上线前 / 周常运维必查项。复制到 PR 模板或运维 Runbook。

一、HTTPS 配置 ​

1.1 必做 ​

  • [ ] 全站强制 HTTPS(301 重定向 HTTP → HTTPS)
  • [ ] HSTS 头(1 年 + includeSubDomains + preload)
  • [ ] TLS 1.2+(禁用 SSLv3 / TLS 1.0 / 1.1)
  • [ ] 强加密套件(ECDHE 优先)
  • [ ] OCSP Stapling
  • [ ] Certificate Transparency(自动)

1.2 检查命令 ​

bash
# 检查 TLS 配置
nmap --script ssl-enum-ciphers -p 443 example.com

# 检查 HSTS
curl -I https://example.com | grep -i strict-transport

# 检查 HTTP → HTTPS 重定向
curl -I http://example.com

# 检查证书过期
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null | openssl x509 -noout -dates

1.3 证书管理 ​

  • [ ] 自动续期(Let's Encrypt 90 天)
  • [ ] 过期前 30 天告警
  • [ ] 私钥不进 git / 日志
  • [ ] 定期轮换(1~2 年)

二、Cookie 安全 ​

2.1 必做 ​

  • [ ] 鉴权 Cookie 用 HttpOnly
  • [ ] 强制 HTTPS 的 Cookie 用 Secure
  • [ ] 跨域 Cookie 用 SameSite=Lax 或 Strict
  • [ ] 重要 Cookie 加 __Host- 前缀
  • [ ] Cookie 不要存敏感信息(token 用短期,refresh 用长期)

2.2 检查 ​

bash
# 检查 Set-Cookie 头
curl -I https://example.com/login

# 应该看到:
# Set-Cookie: token=xxx; HttpOnly; Secure; SameSite=Lax; Path=/

三、CORS 配置 ​

3.1 必做 ​

  • [ ] 白名单(不用 *)
  • [ ] Allow-Credentials: true 时,Allow-Origin 不能是 *
  • [ ] 加 Vary: Origin 头
  • [ ] 预检缓存 Access-Control-Max-Age: 86400
  • [ ] OPTIONS 预检返回 204

3.2 检查 ​

bash
curl -I -H "Origin: https://app.example.com" https://api.example.com/users
# 应该看到:
# Access-Control-Allow-Origin: https://app.example.com
# Vary: Origin

四、CSP(内容安全策略) ​

4.1 必做 ​

  • [ ] 至少 Content-Security-Policy-Report-Only
  • [ ] default-src 'self' 起步
  • [ ] frame-ancestors 'none' 防点击劫持
  • [ ] base-uri 'self' 防劫持
  • [ ] 收集违规报告

4.2 检查 ​

bash
curl -I https://example.com | grep -i content-security-policy

五、CSRF 防御 ​

5.1 必做 ​

  • [ ] SameSite Cookie(Lax/Strict)
  • [ ] 关键接口 CSRF Token
  • [ ] Referer / Origin 验证
  • [ ] 关键操作二次验证

5.2 检查 ​

js
// 模拟跨域表单提交
fetch('https://bank.com/transfer', {
  method: 'POST',
  credentials: 'include',
  body: JSON.stringify({ to: 'attacker', amount: 10000 }),
  headers: { 'Content-Type': 'application/json' },
})
// 应该被 SameSite=Lax 拒绝(POST 跨站不带 cookie)

六、限速 ​

6.1 必做 ​

  • [ ] 登录 / 注册 / 找回密码接口限速
  • [ ] 验证码防爆破
  • [ ] API 通用限速(每 IP / 每用户)
  • [ ] 上传接口限速

6.2 Nginx 限速 ​

nginx
# 每 IP 每秒 10 个请求
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

location /api {
  limit_req zone=api burst=20 nodelay;
}

七、Headers 安全 ​

7.1 必加 Headers ​

nginx
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
add_header Content-Security-Policy "default-src 'self'" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;

7.2 检查 ​

bash
# 用 securityheaders.com 在线检查
# 或
curl -I https://example.com | grep -iE "x-content|x-frame|strict-transport|content-security"

八、认证与授权 ​

8.1 必做 ​

  • [ ] 密码哈希用 bcrypt / argon2
  • [ ] 密码 12 位以上
  • [ ] 检查弱密码黑名单
  • [ ] 检查泄露密码(HIBP API)
  • [ ] 多因素认证(管理员强制)
  • [ ] 失败登录限速 + 锁定
  • [ ] Token 短期 + 过期时间
  • [ ] Refresh token 轮换

8.2 检查 ​

js
// 验证 JWT 是否带过期
const token = jwt.verify(tokenString, SECRET)
console.log(token.exp - Date.now() / 1000, '秒后过期')

九、上传下载 ​

9.1 必做 ​

  • [ ] 文件类型白名单(扩展名 + MIME + 实际内容)
  • [ ] 文件大小限制
  • [ ] 上传后重命名(随机)
  • [ ] 存储目录独立(防脚本执行)
  • [ ] 静态文件不与代码同源

十、DNS 安全 ​

10.1 必做 ​

  • [ ] DNSSEC 启用
  • [ ] DoH/DoT(防止劫持)
  • [ ] 注册商锁(防域名转移)
  • [ ] 多 DNS 备份

十一、监控与告警 ​

11.1 必做 ​

  • [ ] 异常登录检测(异地、频繁失败)
  • [ ] 异常操作告警(支付、大额、删除)
  • [ ] 异常流量检测(DDoS)
  • [ ] CSP 违规报告
  • [ ] 关键事件日志(留 6 个月+)

11.2 检查命令 ​

bash
# 看最近的登录失败
grep "login_failed" /var/log/app/audit.log | tail -100

# 看异常流量
awk '$9 >= 500 {print}' /var/log/nginx/access.log | tail -50

十二、API 设计 ​

12.1 必做 ​

  • [ ] 鉴权(每个接口)
  • [ ] 限速
  • [ ] 输入校验
  • [ ] 错误信息不暴露堆栈
  • [ ] 幂等性(支付等关键操作)
  • [ ] 限流 + 重试策略

十三、依赖安全 ​

13.1 必做 ​

  • [ ] npm audit 无高危
  • [ ] CI 集成 Snyk / Dependabot
  • [ ] 关键依赖固定版本
  • [ ] package-lock.json 在 git
  • [ ] CI 用 npm ci(不用 npm install)

14.1 网络层 ​

  • [ ] HTTPS 配置验证(ssllabs.com)
  • [ ] HSTS preload 提交

  • [ ] 安全 Headers 完整

14.2 应用层 ​

  • [ ] Cookie 配置正确
  • [ ] 鉴权 / Token 配置正确
  • [ ] 输入校验
  • [ ] 错误处理

14.3 运维层 ​

  • [ ] 证书自动续期

十五、应急响应 ​

15.1 安全事件分级 ​

P0:
  - 大规模数据泄露
  - 主站被挂马
  - 立即响应

P1:
  - 个别用户账号被盗
  - 单次 XSS / CSRF 攻击成功
  - 4 小时内响应

P2:
  - 可疑活动
  - 漏洞报告
  - 1 个工作日内响应

15.2 响应流程 ​

1. 确认事件
2. 评估影响范围
3. 隔离(暂停服务 / 撤销 token)
4. 修复(打补丁 / 关漏洞)
5. 复盘(写报告 / 改进流程)
