一、HTTPS 混合内容

Section titled “一、HTTPS 混合内容”

问题:页面是 HTTPS,但引用了 HTTP 资源(图片、JS、CSS),浏览器会拦截。

踩坑: 会员端 H5 上线 HTTPS 后,某些老图片仍是 HTTP 链接,被浏览器 block,显示“裂图”。

修复:

  1. 检查所有资源 URL,统一 https

三、Cookie 没设 HttpOnly

Section titled “三、Cookie 没设 HttpOnly”

问题:JS 能读 Cookie,XSS 直接偷走 token。

踩坑: 商户后台接入第三方统计 SDK,该 SDK 有 XSS 漏洞,偷走所有用户 token。

修复:

  • 鉴权用 Cookie 设 HttpOnly(JS 读不到)
  • 前端需要 token 时,从服务端 API 获取(不用 Cookie 里的)
  • 或用 __Host- 前缀防注入

🎯 面试常考

Section titled “🎯 面试常考”

Q1：线上问题怎么定位?按什么顺序查?

Section titled “Q1：线上问题怎么定位?按什么顺序查?”

先分类,再逐层下钻:

  1. 是不是普遍问题:看监控的受影响用户比例和错误率曲线
  2. 网络层:DevTools Network 面板看是否有请求失败/超时;curl -v 看服务端响应
  3. 服务端:看后端日志和链路追踪(trace id 贯穿前后端)
  4. 前端:Console 有没有报错、SourceMap 还原到具体代码行
  5. 环境差异:复现路径是不是只在某个浏览器/某个机型/某个网络下出现

关键工具:Service Worker 是最容易「本地正常线上出错」的隐藏变量, 排查时先在 DevTools → Application → Service Workers 里 unregister 掉再试。

Q2：混合内容(mixed content)怎么发现和修?

Section titled “Q2：混合内容(mixed content)怎么发现和修?”

发现:DevTools Console 会报 Mixed Content 警告,Security 面板也会列出; 线上可以通过 CSP 的 upgrade-insecure-requests 或 Content-Security-Policy-Report-Only 收集。

修:

  1. 全站 HTTPS 化,把资源 URL 改成协议相对(//cdn.x.com/a.js)或绝对 HTTPS
  2. 服务端加 301 跳转,把 HTTP 请求升级
  3. 第三方资源用 https 版本,或自己代理到 CDN

注意:upgrade-insecure-requests 是 CSP 指令,需要服务端加头, 能一次性把页面里的 HTTP 资源升级成 HTTPS。

Q3：Nginx 反代要传哪些头?漏了会怎样?

Section titled “Q3：Nginx 反代要传哪些头?漏了会怎样?”

必须显式传:

漏 Host:后端按 Host 做多域名路由或生成绝对 URL 时会错 漏 X-Forwarded-For / X-Real-IP:后端拿到的全是代理 IP, 限流按 IP 做就全算在代理头上(等于没限流),日志里也看不到真实客户端 IP, 风控和审计直接失效 漏 X-Forwarded-Proto:后端判断不了原始协议,生成 http:// 的重定向或 Cookie 没带 Secure

📝 小结

Section titled “📝 小结”
  • 这页的坑按「现象 → 根因 → 修法」组织,面试时直接讲坑比讲理论更有说服力。
  • 最高频的三个坑:混合内容、SameSite 没设导致跨站丢 Cookie、静态资源缓存策略配错。
  • 带 hash 的 JS 设 no-cache 是最反直觉的坑 —— hash 文件本来就可以永久缓存。
  • Nginx 反代要显式传 Host / X-Real-IP / X-Forwarded-For,否则后端拿到的全是代理 IP。
