网络相关项目踩过的坑 ​

来自简历项目"01 商户管理 SaaS"、"02 会员 Web/H5"、"03 智能风控引擎平台"的网络层踩坑经验。

一、HTTPS 混合内容 ​

问题:页面是 HTTPS,但引用了 HTTP 资源(图片、JS、CSS),浏览器会拦截。

踩坑: 会员端 H5 上线 HTTPS 后,某些老图片仍是 HTTP 链接,被浏览器 block,显示"裂图"。

修复:

  1. 检查所有资源 URL,统一 https
  2. Nginx 配置自动升级 HTTP → HTTPS:
    nginx
    add_header Content-Security-Policy "upgrade-insecure-requests" always;
  3. 或者全站搜索 http:// 替换成 https://

二、Cookie 没设 SameSite=Lax ​

问题:现代浏览器默认 SameSite=Lax,没显式设置会导致跨域 POST 不带 Cookie,接口 401。

修复:

ts
res.cookie('Authorization', token, {
  httpOnly: false,
  secure: true,
  sameSite: 'lax',  // 显式声明
  maxAge: 15 * 60 * 1000,
})

三、Cookie 没设 HttpOnly ​

问题:JS 能读 Cookie,XSS 直接偷走 token。

踩坑: 商户后台接入第三方统计 SDK,该 SDK 有 XSS 漏洞,偷走所有用户 token。

修复:

  • 鉴权用 Cookie 设 HttpOnly(JS 读不到)
  • 前端需要 token 时,从服务端 API 获取(不用 Cookie 里的)
  • 或用 __Host- 前缀防注入

四、静态资源没设缓存 ​

问题:每次都重新下载,浪费带宽,首屏慢。

修复:

nginx
# HTML:不缓存
location ~* \.html$ {
  add_header Cache-Control "no-cache, must-revalidate";
}

# 带 hash 的静态资源:长期缓存
location ~* \..+\.(js|css|png|jpg|svg|woff2)$ {
  add_header Cache-Control "public, max-age=31536000, immutable";
}

# API:不缓存
location /api {
  add_header Cache-Control "no-store";
}

注意:HTML 必须 no-cache(否则新版上线用户拿不到)。

五、带 hash 的 JS 设了 no-cache ​

问题:Webpack/Vite 输出的 app.abc123.js,设 no-cache 反而每次都发请求,慢。

修复:带 hash 的资源应该强缓存 1 年(max-age=31536000, immutable),文件名变了自然失效。

六、Nginx 没开 HTTP/2 ​

问题:HTTPS 已经上了,但 HTTP/2 没开,多路复用收益没拿到。

修复:

nginx
server {
  listen 443 ssl;
  http2 on;  # 一行开启 HTTP/2
  # ... SSL 配置
}

七、跨域 CORS 漏配预检 ​

问题:非简单请求(POST + JSON),没配 OPTIONS 处理,Nginx 返回 405。

修复:

nginx
location /api {
  # 预检请求直接 204
  if ($request_method = 'OPTIONS') {
    add_header Access-Control-Allow-Origin $http_origin always;
    add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS" always;
    add_header Access-Control-Allow-Headers "Content-Type, Authorization, X-Token" always;
    add_header Access-Control-Max-Age 86400;
    add_header Access-Control-Allow-Credentials true always;
    return 204;
  }

  # 实际请求
  add_header Access-Control-Allow-Origin $http_origin always;
  # ...
  proxy_pass http://backend;
}

八、Token 没设过期时间 ​

问题:签发 JWT 没加 expiresIn,token 永久有效,泄露后无法失效。

修复:

ts
const token = jwt.sign(payload, SECRET, {
  expiresIn: '15m',  // 短期
})

const refreshToken = jwt.sign(payload, REFRESH_SECRET, {
  expiresIn: '7d',  // 长期但可撤销
})

九、Nginx 反代丢失请求头 ​

问题:前端发请求带 X-Request-Id(链路追踪),Nginx 反代后丢失。

修复:

nginx
location /api {
  proxy_pass http://backend;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Request-Id $http_x_request_id;  # 转发自定义头
}

十、上传文件超过 nginx 默认限制 ​

问题:默认 client_max_body_size 1M,上传大文件 413。

修复:

nginx
http {
  client_max_body_size 100M;  # 全局
  # 或者按路由
  location /api/upload {
    client_max_body_size 500M;
  }
}

十一、WebSocket 反代配置错 ​

问题:WebSocket 连接被代理断开。

修复:

nginx
location /ws {
  proxy_pass http://backend;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_read_timeout 86400s;  # 防止超时断开
  proxy_send_timeout 86400s;
}

十二、CORS 配 * + credentials ​

问题:Access-Control-Allow-Origin: * 配 Allow-Credentials: true,浏览器拒绝。

修复:

nginx
# 错误
add_header Access-Control-Allow-Origin "*" always;
add_header Access-Control-Allow-Credentials true always;

# 正确
set $cors_origin $http_origin;
if ($cors_origin = "") { set $cors_origin "https://default.com"; }
add_header Access-Control-Allow-Origin $cors_origin always;
add_header Access-Control-Allow-Credentials true always;
add_header Vary "Origin" always;

十三、HTTP/3 启用后某些代理挂掉 ​

问题:HTTP/3 用 UDP,部分防火墙拦 UDP 443,fallback 没配好导致全挂。

修复:

nginx
server {
  listen 443 ssl;
  http2 on;
  http3 on;

  # HTTP/3 失败时浏览器自动 fallback 到 HTTP/2
  # 但要确保 HTTP/2 正常工作

  # 同时配置好 Alt-Svc(浏览器才知道 HTTP/3 可用)
  add_header Alt-Svc 'h3=":443"; ma=86400' always;
}

十四、API 响应没设 Content-Type ​

问题:后端返回 JSON 但没设 Content-Type: application/json,前端 response.json() 报错。

修复:

ts
// Express
res.setHeader('Content-Type', 'application/json; charset=utf-8')
res.send(JSON.stringify(data))

// Nest.js
@Header('Content-Type', 'application/json')

十五、Cookie Domain 配错 ​

问题:Cookie 设 Domain=api.example.com,但前端在 app.example.com,Cookie 不发送。

修复:

ts
// 错误
res.cookie('token', value, { domain: 'api.example.com' })

// 正确(共享给所有子域)
res.cookie('token', value, { domain: '.example.com' })  // 注意前面的点

十六、长连接超时 ​

问题:长轮询 / SSE 连接 60 秒被 Nginx 断开(默认 proxy_read_timeout 60s)。

修复:

nginx
location /api/long-poll {
  proxy_pass http://backend;
  proxy_read_timeout 600s;  # 10 分钟
  proxy_send_timeout 600s;
}

十七、预检请求缓存时间不够 ​

问题:每次跨域请求都发 OPTIONS,慢。

修复:

nginx
add_header Access-Control-Max-Age 86400;  # 缓存 24 小时

十八、Token 在 URL 中泄露 ​

问题:OAuth 回调 ?token=xxx,token 进浏览器历史记录、服务端日志。

修复:

ts
// ❌ 不要
res.redirect(`/callback?token=${token}`)

// ✅ 用 code 换 token
res.redirect(`/callback?code=${authCode}`)

十九、gzip 压缩错 ​

问题:gzip 压缩 JSON 后,前端 response.json() 报错(浏览器自动解压,但配置不对会失败)。

修复:

nginx
# 启用 gzip + Vary: Accept-Encoding
gzip on;
gzip_types application/json text/css application/javascript;
gzip_vary on;  # 重要!否则缓存错乱

二十、HTTPS 证书过期 ​

问题:Let's Encrypt 证书 90 天过期,没自动续期导致全站挂掉。

修复:

bash
# 自动续期(crontab)
0 3 * * * certbot renew --quiet

监控:证书过期前 30 天发告警(运维)。

二十一、CDN 回源配置 ​

问题:CDN 没配回源 Host,导致源站返回 404。

修复:CDN 配置里设回源域名 = 源站域名。

二十二、Content-Security-Policy 过严 ​

问题:CSP 配置错误导致 JS 全部 block。

修复:

  1. 先开 Content-Security-Policy-Report-Only,看违规
  2. 逐步收紧到强制
  3. 关键指令:script-src 'self',第三方加白

二十三、Cookie path 配错 ​

问题:Cookie 设 Path=/api,前端在 / 路径访问不到。

修复:

ts
// 大多数情况用 Path=/
res.cookie('token', value, { path: '/' })
