七、内存泄漏与性能

Section titled “七、内存泄漏与性能”
操作 注意事项
createObjectURL 必须配对 revokeObjectURL
FileReader 大文件读取会占主线程内存，及时 abort()
toBlob 编码过程异步但仍占内存
读取 100MB 文件 用 slice() + stream() 分块，别整读
Excel 解析 5 万行 xlsx 内存峰值 500MB+，放 Web Worker

八、面试高频问答

Section titled “八、面试高频问答”

Q1：File 和 Blob 有什么区别？

Section titled “Q1：File 和 Blob 有什么区别？”

答：File 继承自 Blob，多了 name、lastModified、type 三个属性，代表“用户磁盘上的一个文件”。Blob 是不可变的二进制块，可以装任意内容，用 FileReader/Blob.text() 读，用 createObjectURL 暴露成 URL。

Q2：怎么实现前端文件上传？

Section titled “Q2：怎么实现前端文件上传？”

答：基础版 FormData + fetch。进阶版：OSS 直传（后端给签名，前端直传 OSS，不占业务服务器带宽）、分片上传（大文件 + 断点续传 + 秒传 hash）、Web Worker 算 hash 不卡主线程。

Q3：怎么实现 Excel 导入？

Section titled “Q3：怎么实现 Excel 导入？”

答：SheetJS 解析 → 表头映射 → 行级校验 → 查重（批量接口）→ 分批提交（500~1000 行/批）→ 展示进度 → 失败行导出成错误报告让用户改后重传。大文件解析必须放 Web Worker，否则页面假死。

Q4：导出 CSV 中文乱码怎么解决？

Section titled “Q4：导出 CSV 中文乱码怎么解决？”

答：文件开头加 UTF-8 BOM（\uFEFF）。Excel 靠 BOM 判断编码，没有 BOM 就按本地 ANSI 解码导致乱码。new Blob(['\uFEFF' + csv], { type: 'text/csv;charset=utf-8' })。

Q5：前端生成 10 万行 Excel 会不会崩？

Section titled “Q5：前端生成 10 万行 Excel 会不会崩？”

答：会。SheetJS 生成 10 万行通常要 5~10 秒并占用大量内存，页面会卡死甚至崩溃。正确做法是走服务端异步导出：前端传筛选条件拿 taskId → 轮询/WebSocket 通知 → 给 OSS 签名下载地址。前端只做“创建任务 + 下载中心”。

Q6：怎么保证拖拽上传在移动端也能用？

Section titled “Q6：怎么保证拖拽上传在移动端也能用？”

答：拖拽在移动端基本不可用。必须同时提供 <input type="file"> 的点击选择入口，并把拖拽作为增强。另外要支持 capture 属性（移动端直接调相机）、多选、以及上传进度与取消。

📝 小结

Section titled “📝 小结”
  • 浏览器文件 API 的能力边界:File/Blob/FileReader/URL.createObjectURL。
  • createObjectURL 必须配对 revokeObjectURL,否则内存泄漏 —— 这是最常见的坑。
  • 大文件处理用 Blob.slice() 分片,不要 arrayBuffer() 一次性读进内存。
  • 拖拽上传靠 DataTransfer,配合 dragover 必须 preventDefault() 否则不触发 drop。
