Canvas 与图形

大屏、图表、图片处理、签名板都靠它。面试问“Canvas 和 SVG 有什么区别”，是图形岗和前端岗的高频题。

一、Canvas vs SVG vs WebGL

Section titled “一、Canvas vs SVG vs WebGL”
维度 Canvas SVG WebGL
渲染方式 像素绘制(立即模式) DOM 节点(保留模式) GPU 着色器
元素数量 不受限(就一个 canvas) 每个图形一个 DOM 不受限
事件处理 需自己算命中检测 直接绑定 DOM 事件 需自己算
缩放 位图,放大模糊 矢量,无限缩放清晰 位图/GPU
文字 需要换行、测量的复杂处理 原生支持 几乎不支持
可访问性 差(读屏读不到) 好(是 DOM) 差
性能(大量元素) 好 差(几千个节点就卡) 极好
适用 图表、大屏、游戏、图像处理 图标、示意图、少量图形 3D、地图、大数据可视化

七、面试高频问答

Section titled “七、面试高频问答”

Q1：Canvas 和 SVG 有什么区别？什么时候用哪个？

Section titled “Q1：Canvas 和 SVG 有什么区别？什么时候用哪个？”

答：

  • Canvas 是立即模式位图，元素多时性能好，但事件要自己做命中检测，可访问性差
  • SVG 是 DOM 节点，事件/CSS 免费，矢量缩放清晰，文字排版方便，但节点多会卡
  • 选型：图标/少量交互图形/需要无障碍 → SVG；图表/大屏/大量数据点 → Canvas；3D/海量 → WebGL

Q2：Canvas 画出来是模糊的？

Section titled “Q2：Canvas 画出来是模糊的？”

答：没做 devicePixelRatio 适配。canvas 的 width/height 是位图分辨率，style.width/height 是显示尺寸。解决：canvas.width = cssWidth * dpr，同时 ctx.scale(dpr, dpr)，之后用 CSS 像素坐标绘制。

Q3：为什么动画用 requestAnimationFrame 而不是 setInterval？

Section titled “Q3：为什么动画用 requestAnimationFrame 而不是 setInterval？”

答：rAF 与显示器刷新率同步、后台标签页自动暂停、传入高精度时间戳。setInterval 固定频率，在 120Hz 屏上会掉帧，在后台白耗 CPU，且用 elapsed 计算动画位置更准。

Q4：怎么优化 Canvas 大量元素的绘制？

Section titled “Q4：怎么优化 Canvas 大量元素的绘制？”

答：批量路径（同色图形一次 fill）、缓存静态层到离屏 canvas、减少 fillStyle/font 切换、用 OffscreenCanvas 放到 Worker 里渲染、数据没变不重绘。

Q5：Canvas 怎么做点击交互？

Section titled “Q5：Canvas 怎么做点击交互？”

答：没有 DOM 事件，要自己做命中检测——监听 click/mousemove，把鼠标坐标换算成 canvas 内部坐标（减去 getBoundingClientRect() 的偏移），再按几何形状判断命中（圆形用距离平方，矩形用范围）。复杂场景建议改用 SVG 或做分层 canvas（交互层用 SVG 覆盖）。

📝 小结

Section titled “📝 小结”
  • Canvas 是立即模式的像素绘制,SVG 是保留模式的矢量描述,选型看场景。
  • Canvas 适合大量图元(粒子、图表数据点)、需要逐像素滤镜;SVG 适合少量矢量图标、需要 DOM 交互和 CSS 动画。
  • Canvas 的痛点是没有场景图:自己管状态、手写命中检测、自己处理 DPR 缩放。
  • devicePixelRatio 要手动乘,否则高清屏上模糊。
