语义化与文档结构

语义化不是“把 div 换成 header”，而是让结构、样式、行为三者分离，并且让机器（搜索引擎、读屏软件）能理解页面。

2.2 文本内容标签

Section titled “2.2 文本内容标签”
标签 用途 关键点
<section> 通用主题分组 应该配标题(h1-h6),标题会进文档大纲
<article> 可独立分发的内容 博客文章、新闻、商品卡片
<aside> 侧边内容 侧栏、注脚、弹窗
<nav> 导航链接 不一定在 <header> 里,页内目录也可以
<header> 头部 可以出现多次(文章头部也可)
<footer> 尾部 同上
<figure> + <figcaption> 独立内容 + 说明文字 图片/图表的语义包裹
<mark> 标记突出内容 搜索结果高亮
<time datetime="2026-01-01"> 时间 机器可读格式
<data value="123"> 机器可读的值 与可见文本不同时用
<details> + <summary> 可折叠 纯 HTML 实现的展开收起
<dialog> 模态/非模态对话框 原生焦点管理、showModal()

2.3 交互标签

Section titled “2.3 交互标签”

🔑 <dialog> 的 showModal() 自带焦点陷阱和 inert 背景，比自己用 div 模拟弹窗好得多。但 antd/Element 的 Modal 之所以不用它，是为了跨浏览器一致性和动画控制（<dialog> 的动画需要 @starting-style 支持）。

三、语义化在 React / Vue 里的注意点

Section titled “三、语义化在 React / Vue 里的注意点”

必须用 div 的情况：

场景 原因
<header> 里再嵌 <header> 语义不冲突,但组件库内部 header 组件叫 Header 容易混淆
表格布局 <table> 有自己的语义(数据表),布局别用
表单标签 <label> 不能包含多个可交互元素
<a> 包 <button> 嵌套交互元素无效,应该用 role 或换标签

ARIA 的原则：能用原生标签就别用 ARIA。

ARIA 规则第一条：“No ARIA is better than bad ARIA”——错误的 ARIA 比没有 ARIA 更糟，因为它会让读屏软件播报错误信息。

四、表单增强（HTML5 的实际价值）

Section titled “四、表单增强（HTML5 的实际价值）”

4.1 新的 input type

Section titled “4.1 新的 input type”

实际收益：移动端会弹出对应的原生键盘（type="number" 弹数字键盘、type="datetime-local" 弹日期选择器），这是体验成本最低的优化。

4.2 原生校验（不写 JS 也能校验）

Section titled “4.2 原生校验（不写 JS 也能校验）”

⚠️ 原生校验的样式不可控，提示文案和浏览器绑定，国际化也麻烦。真实项目里通常还是自己写校验（antd Form / Zod），但 type 属性的移动端键盘优化值得用。

4.3 datalist：轻量下拉建议

Section titled “4.3 datalist：轻量下拉建议”

浏览器自带过滤，但样式不可控、移动端支持差。ERP 里更适合用 antd 的 AutoComplete / Select（支持远程搜索）。

5.2 defer vs async vs module

Section titled “5.2 defer vs async vs module”
属性 下载 执行时机 执行顺序 适用
无 阻塞解析 立即 文档顺序 极少数内联关键脚本
async 并行 到达即执行 不确定 独立脚本(埋点/广告)
defer 并行 DOMContentLoaded 前 文档顺序 常规第三方库
type="module" 并行 defer 语义 文档顺序 天然 defer + 严格模式 + 作用域隔离

面试高频：async 和 defer 的区别 → 下载都并行，async 先到先执行且不保证顺序，defer 保证顺序。

七、面试高频问答

Section titled “七、面试高频问答”

Q1：HTML5 新特性有哪些？

Section titled “Q1：HTML5 新特性有哪些？”

答：分三层讲——① 语义与可访问性（语义标签、<dialog>、<details>、表单增强）；② 能力开放（Canvas/WebGL、File API、Geolocation、Notification、MediaRecorder、IndexedDB）；③ 工程影响（Service Worker 改缓存模型、Web Worker 改线程模型、fetch/CORS 改请求模型）。

Q2：语义化标签真的会影响 SEO 吗？

Section titled “Q2：语义化标签真的会影响 SEO 吗？”

答：会，但权重不如内容和外链。真正的影响是信息架构清晰度——搜索引擎能正确识别主内容、导航、侧栏，避免把侧栏当成正文。更多实际收益在无障碍上：读屏软件的地标导航对盲用户是刚需。

Q3：为什么现在还需要语义化标签，很多项目全用 div？

Section titled “Q3：为什么现在还需要语义化标签，很多项目全用 div？”

答：常见原因是团队规范没跟上，或者组件库自己包了一层 div。可访问性是硬需求（部分海外市场有法律要求，如欧盟 EN 301 549、美国 ADA、我国《信息无障碍 通用设计规范》）。最低成本的做法：在 ESLint 里开 jsx-a11y 规则，CI 卡住。

Q4：defer 和 async 有什么区别？

Section titled “Q4：defer 和 async 有什么区别？”

答：下载都并行。defer 保证按文档顺序执行、在 DOMContentLoaded 前完成；async 到达就执行、执行顺序不确定。第三方统计脚本用 async，业务依赖库用 defer。

Q5：React 里用 <div onClick> 代替 <button> 有什么问题？

Section titled “Q5：React 里用 <div onClick> 代替 <button> 有什么问题？”

答：① 键盘不可达，Tab 键跳不过去；② 没有 role，读屏不播报为按钮；③ 没有原生 disabled 语义；④ 没有 Enter/Space 触发。正确做法是直接用 <button type="button">，需要样式的用 CSS 覆盖。

📝 小结

Section titled “📝 小结”
  • 语义化的价值在无障碍和 SEO:屏幕阅读器依赖标签语义判断控件类型。
  • <header>/<nav>/<main>/<aside>/<footer> 是页面骨架,别全用 div。
  • 表单增强才是 HTML5 真正改变开发方式的地方:type、required、pattern、<datalist>。
  • 语义化在 React/Vue 里要注意:自定义组件要透传 ref 和语义属性,否则丢掉了可访问性。
