⚡️内容大纲

文件与二进制 ​

ERP/CRM 最高频的实战场景：Excel 导入导出、附件上传、图片裁剪压缩、文件预览、离线草稿。这篇把 File / Blob / FileReader / 拖拽 / 下载一次讲透。

一、核心概念 ​

File      —— 用户选择的文件,继承自 Blob,额外有 name / lastModified / type
Blob      —— 二进制大对象,不可变;可以装文本也可以装二进制
FileReader—— 异步读取 Blob 内容(readAsText / readAsArrayBuffer / readAsDataURL)
URL.createObjectURL —— 为 Blob 生成临时 URL,给 <a download> 或 <img> 用
ArrayBuffer / TypedArray —— 真正的二进制视图,处理图片/加密/协议解析用

关系：

Blob
 ├─ File        (name, lastModified, type)
 ├─ FileReader  → 读成 string / ArrayBuffer / DataURL
 └─ createObjectURL → blob:xxx 临时地址(revoke 释放)

二、读取文件 ​

2.1 FileReader ​

ts
// 读成文本
function readText(file: File): Promise<string> {
  return new Promise((resolve, reject) => {
    const reader = new FileReader()
    reader.onload = () => resolve(reader.result as string)
    reader.onerror = () => reject(reader.error)
    reader.readAsText(file, 'UTF-8')
  })
}

// 读成 ArrayBuffer(处理二进制)
function readBuffer(file: File): Promise<ArrayBuffer> {
  return new Promise((resolve, reject) => {
    const reader = new FileReader()
    reader.onload = () => resolve(reader.result as ArrayBuffer)
    reader.onerror = () => reject(reader.error)
    reader.readAsArrayBuffer(file)
  })
}

// 读成 DataURL(直接塞进 <img src>),但体积膨胀 33%
reader.readAsDataURL(file)

⚠️ DataURL 会把体积放大约 1/3（Base64 编码），大文件不要用。正确做法是 URL.createObjectURL(file)，它是零拷贝的引用。

2.2 新式写法：Blob 方法（不用 FileReader） ​

ts
const text = await file.text()
const buffer = await file.arrayBuffer()
const stream = file.stream()      // ReadableStream,可 pipe

浏览器支持度：Blob.text() / Blob.arrayBuffer() 现代浏览器已全支持。

2.3 大文件流式处理 ​

ts
// 10GB 文件不能一次性读进内存 → 用 stream 分块处理
const reader = file.stream().getReader()
let total = 0

while (true) {
  const { done, value } = await reader.read()
  if (done) break
  total += value.byteLength
  // 处理这一块,或者送去 hash / 上传
}

三、拖拽上传 ​

3.1 放置目标 ​

tsx
const [over, setOver] = useState(false)

<div
  onDragOver={(e) => { e.preventDefault(); setOver(true) }}
  onDragLeave={() => setOver(false)}
  onDrop={(e) => {
    e.preventDefault()
    setOver(false)
    const files = Array.from(e.dataTransfer.files)
    handleFiles(files)
  }}
  style={{ border: over ? '2px dashed #1677ff' : '2px dashed #ccc' }}
/>

三个必写的细节：

  1. onDragOver 必须 e.preventDefault()，否则 drop 不触发
  2. onDrop 也要 e.preventDefault()，防止浏览器直接打开文件
  3. onDragLeave 在子元素间移动时也会触发 → 用计数器或 e.currentTarget.contains(e.relatedTarget) 判断

3.2 读取拖拽内容 ​

ts
const dt = e.dataTransfer

// 1. 文件
dt.files            // FileList
// 2. 拖进来的 URL(拖链接)
dt.getData('text/uri-list')
dt.getData('text/html')
// 3. 纯文本
dt.getData('text/plain')

// 区分"拖文件"和"拖文本"——只接受文件时要检查
if (dt.items.length > 0 && dt.items[0].kind === 'file') {
  const file = dt.items[0].getAsFile()
}

3.3 拖拽排序(表格行) ​

ts
// 用 draggable + dataTransfer 传递索引
function onDragStart(e: React.DragEvent, index: number) {
  e.dataTransfer.setData('text/plain', String(index))
  e.dataTransfer.effectAllowed = 'move'
}

function onDrop(e: React.DragEvent, targetIndex: number) {
  e.preventDefault()
  const from = Number(e.dataTransfer.getData('text/plain'))
  if (from === targetIndex) return
  reorder(from, targetIndex)
}

拖拽是移动端无法使用的交互。ERP 表格排序必须同时提供"上移/下移"按钮或编辑对话框，不能只有拖拽。

四、客户端下载 ​

4.1 Blob 下载 ​

ts
function downloadBlob(blob: Blob, filename: string) {
  const url = URL.createObjectURL(blob)
  const a = document.createElement('a')
  a.href = url
  a.download = filename
  document.body.appendChild(a)
  a.click()
  a.remove()
  URL.revokeObjectURL(url)     // 必须释放,否则内存泄漏
}

4.2 从接口返回的文件流下载 ​

ts
// 关键:响应类型是 blob,不是 json
const res = await fetch('/api/export', { method: 'POST', body: JSON.stringify(filters) })
if (!res.ok) throw new Error('导出失败')

const blob = await res.blob()

// 从 Content-Disposition 解析文件名
const disposition = res.headers.get('Content-Disposition') || ''
const match = /filename\*=UTF-8''([^;]+)/.exec(disposition)
const filename = match ? decodeURIComponent(match[1]) : '导出.xlsx'

downloadBlob(blob, filename)

坑：当接口返回的是 JSON 错误体但 Content-Type 写错时，前端会下载出一个"错误.json"。防御：

ts
const type = res.headers.get('Content-Type') || ''
if (type.includes('application/json')) {
  const err = await res.json()
  throw new Error(err.message || '导出失败')
}

4.3 大数据量导出：别在前端拼 ​

100 行以内   → 前端生成 xlsx,可接受
1 万行       → 前端生成会卡 3~5 秒,体验勉强
10 万行以上  → 必须后端异步导出 + 下载中心

客户端拼 CSV（流式，不占内存）：

ts
async function exportCsv(rows: any[], filename: string) {
  const encoder = new TextEncoder()
  const chunks: BlobPart[] = []
  const BOM = '\uFEFF'   // BOM:让 Excel 正确识别 UTF-8 中文

  chunks.push(BOM + '﻿' === BOM ? BOM : BOM)   // BOM
  chunks.push('姓名,手机号,等级\n')

  for (const row of rows) {
    chunks.push(`${row.name},${row.phone},${row.level}\n`)
  }

  downloadBlob(new Blob(chunks, { type: 'text/csv;charset=utf-8' }), filename)
}

🔑 CSV 中文乱码是必踩坑：Excel 打开 UTF-8 CSV 会乱码，必须在文件头加 BOM(\uFEFF)。或者干脆导出 .xlsx。

五、图片处理 ​

5.1 压缩 ​

ts
async function compressImage(file: File, maxSize = 1920, quality = 0.8): Promise<Blob> {
  const bitmap = await createImageBitmap(file)

  const scale = Math.min(1, maxSize / Math.max(bitmap.width, bitmap.height))
  const canvas = document.createElement('canvas')
  canvas.width = Math.round(bitmap.width * scale)
  canvas.height = Math.round(bitmap.height * scale)

  const ctx = canvas.getContext('2d')!
  ctx.drawImage(bitmap, 0, 0, canvas.width, canvas.height)
  bitmap.close()

  return new Promise((resolve) => canvas.toBlob((b) => resolve(b!), 'image/jpeg', quality))
}

八、面试高频问答 ​

Q1：File 和 Blob 有什么区别？ ​

答：File 继承自 Blob，多了 name、lastModified、type 三个属性，代表"用户磁盘上的一个文件"。Blob 是不可变的二进制块，可以装任意内容，用 FileReader/Blob.text() 读，用 createObjectURL 暴露成 URL。

Q2：怎么实现前端文件上传？ ​

答：基础版 FormData + fetch。进阶版：OSS 直传（后端给签名，前端直传 OSS，不占业务服务器带宽）、分片上传（大文件 + 断点续传 + 秒传 hash）、Web Worker 算 hash 不卡主线程。

Q3：怎么实现 Excel 导入？ ​

答：SheetJS 解析 → 表头映射 → 行级校验 → 查重（批量接口）→ 分批提交（500~1000 行/批）→ 展示进度 → 失败行导出成错误报告让用户改后重传。大文件解析必须放 Web Worker，否则页面假死。

Q4：导出 CSV 中文乱码怎么解决？ ​

答：文件开头加 UTF-8 BOM（\uFEFF）。Excel 靠 BOM 判断编码，没有 BOM 就按本地 ANSI 解码导致乱码。new Blob(['\uFEFF' + csv], { type: 'text/csv;charset=utf-8' })。

Q5：前端生成 10 万行 Excel 会不会崩？ ​

答：会。SheetJS 生成 10 万行通常要 5~10 秒并占用大量内存，页面会卡死甚至崩溃。正确做法是走服务端异步导出：前端传筛选条件拿 taskId → 轮询/WebSocket 通知 → 给 OSS 签名下载地址。前端只做"创建任务 + 下载中心"。

Q6：怎么保证拖拽上传在移动端也能用？ ​

答：拖拽在移动端基本不可用。必须同时提供 <input type="file"> 的点击选择入口，并把拖拽作为增强。另外要支持 capture 属性（移动端直接调相机）、多选、以及上传进度与取消。
