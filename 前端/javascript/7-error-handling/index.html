十、面试常考

Section titled “十、面试常考”

Q1:try-catch 有什么缺点?

Section titled “Q1:try-catch 有什么缺点?”

答:

  • V8 不能优化(性能略差)
  • 不能捕获异步错误(setTimeout、Promise)
  • 滥用导致代码难读
  • 解决:范围小 / 用 async/await / Promise 链

Q2:Promise.all vs allSettled?

Section titled “Q2:Promise.all vs allSettled?”

答:

  • Promise.all:任一失败就 reject,常用于“全部都要成功”
  • Promise.allSettled:全部都返回结果,常用于“独立任务批处理”

Q3:错误边界是?

Section titled “Q3:错误边界是?”

答:

  • React 类组件,捕获子组件错误
  • Vue 3 用 onErrorCaptured 钩子
  • 显示 fallback UI,不崩溃整个应用
  • 上报到监控平台(Sentry)

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • window.onerror vs addEventListener('error')? onerror 同步、不能阻止默认;addEventListener 标准、可多次监听
  • Promise 错误静默怎么查? window.addEventListener('unhandledrejection', e => report(e.reason))
  • try-catch 性能影响? V8 优化较差(TryOnException);但 try 块内代码仍优化;只 catch 路径不优化
  • 全局错误上报方案? error 事件 + unhandledrejection 事件 + Vue/React errorCaptured/Boundary + Sentry

📝 小结

Section titled “📝 小结”
  • 错误分三类:同步可捕获异常、Promise rejection、异步回调抛错(捕获不到)。
  • 全局兜底:window.onerror / unhandledrejection / error 事件(捕获资源加载失败)。
  • Promise 的错误要用 .catch 或 try/catch + await,.catch 不会兜住 setTimeout 里的抛错。
  • 生产环境要上报而不是只 log:带 userId、版本、路由、堆栈,否则定位不了。
