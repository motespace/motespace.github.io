异步与 Promise

异步是 JS 的核心机制，也是面试必考题。本文从“为什么需要异步”讲起，覆盖 Promise、async/await、事件循环和微任务队列。

1. 为什么 JS 是单线程

Section titled “1. 为什么 JS 是单线程”

JS 最初是浏览器脚本语言，主要任务是响应用户操作（点击、输入）。如果多线程同时操作同一个 DOM，会产生竞态条件。

单线程的解决方案：异步 + 事件循环。遇到 IO、定时器、网络请求这些“慢操作”时，主线程不等待，而是注册回调函数；操作完成后由事件循环把回调放回主线程执行。

7. 事件循环（Event Loop）

Section titled “7. 事件循环（Event Loop）”

JS 的执行顺序由调用栈 + 任务队列 + 微任务队列决定。

任务分类：

  • 宏任务（Macrotask）：setTimeout、setInterval、I/O、UI 渲染、requestAnimationFrame（部分浏览器归为宏任务）。
  • 微任务（Microtask）：Promise.then/catch/finally、queueMicrotask、MutationObserver、process.nextTick（Node）。

执行顺序：

  1. 执行当前宏任务（同步代码）。
  2. 执行所有微任务（清空微任务队列）。
  3. 必要时渲染 UI。
  4. 取下一个宏任务，循环。

面试追问

Section titled “面试追问”
  • async 函数返回值? 永远返回 Promise;非 Promise 值自动包装
  • await 后面接非 Promise? 直接 resolve,等价同步
  • 事件循环优先级? 同步 > 微任务 > 渲染(60Hz) > 宏任务
  • Node.js 事件循环 6 阶段? timers → pending callbacks → idle → poll → check → close;比浏览器复杂

项目里踩过的坑

Section titled “项目里踩过的坑”
  1. forEach + await 误用：导致批量操作变成并发，顺序和重试都不可控。
  2. 没有 try/catch：失败直接进入 unhandledRejection，控制台报错但 UI 没反馈。
  3. Promise 链里忘了 return：then 回调没 return 值，下一个 then 拿到 undefined。
  4. 重复点击导致并发请求：用 AbortController 取消上一次请求（搜索框输入即搜索场景）。

📝 小结

Section titled “📝 小结”
  • JS 单线程 + 事件循环:宏任务(timer/I/O/UI)与微任务(Promise)的执行顺序是「宏任务 → 清空所有微任务 → 下一个宏任务」。
  • await 之后的代码进入微任务队列,setTimeout 是宏任务 —— 这是「输出顺序」类题目的全部考点。
  • Promise 链的错误处理:.catch 只捕获上一个链的错误,try/catch 只能捕获 await 的。
  • 并发控制:Promise.all 并发但一个失败全挂;allSettled 拿全部结果;race 取最快。
