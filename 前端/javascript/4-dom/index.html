七、面试常考

Section titled “七、面试常考”

Q1:DOM 操作为什么慢?

Section titled “Q1:DOM 操作为什么慢?”

答:

  • DOM 操作触发 layout / paint / composite
  • 跨进程通信(JS 引擎 ↔ 渲染引擎)
  • 频繁操作累积耗时长
  • 解决:批处理、DocumentFragment、虚拟列表

Q2:textContent vs innerText vs innerHTML?

Section titled “Q2:textContent vs innerText vs innerHTML?”

答:

  • textContent:纯文本,快,安全(防 XSS)
  • innerText:可见文本,触发 reflow
  • innerHTML:HTML 字符串,慢,有 XSS 风险

Q3:NodeList vs HTMLCollection?

Section titled “Q3:NodeList vs HTMLCollection?”

答:

  • NodeList(querySelectorAll):静态快照
  • HTMLCollection(getElementsBy*):动态实时
  • 实战优先用 NodeList(行为可预期)

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • DOM 操作批处理? DocumentFragment 临时容器;requestAnimationFrame 一帧合并
  • innerText 兼容性? 旧 IE 私有属性,标准后行为不同;现代项目用 textContent
  • getComputedStyle 触发 reflow? 读取 style 必触发;避免在循环里读
  • 虚拟 DOM 解决了 DOM 慢的什么? 减少直接 DOM 操作(批处理);但本身有 diff 开销

📝 小结

Section titled “📝 小结”
  • DOM 查询:能用 querySelector 就别用 getElementById(前者要解析 CSS 选择器)。
  • 修改 DOM 会触发同步布局(reflow),读写交替会反复重排 —— 批量操作或用 requestAnimationFrame 断开。
  • 创建大量节点要用 DocumentFragment 或 cloneNode(true),逐个 appendChild 会多次触发重排。
  • innerHTML 有 XSS 风险,不可信内容要用 textContent 或 DOMPurify。
