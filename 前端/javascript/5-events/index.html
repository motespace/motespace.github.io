Q1:事件冒泡和捕获?

Section titled “Q1:事件冒泡和捕获?”

答:

  • 捕获:从外到内(window → target)
  • 目标:target
  • 冒泡:从内到外(target → window)
  • addEventListener 默认监听冒泡,{capture: true} 监听捕获

Q2:事件委托的好处?

Section titled “Q2:事件委托的好处?”

答:

  • 性能:少开监听器
  • 动态元素:新加的元素自动有监听
  • 内存占用少

Q3:stopPropagation vs preventDefault?

Section titled “Q3:stopPropagation vs preventDefault?”

答:

  • stopPropagation:阻止事件继续传播(冒泡/捕获)
  • preventDefault:阻止元素默认行为(如链接跳转、表单提交)
  • 两者独立,可同时用

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • 事件委托边界? 不适合 focus / blur(不冒泡);用 focusin / focusout 替代
  • passive 事件监听? addEventListener('touchstart', fn, { passive: true }) 告诉浏览器不调 preventDefault,提升滚动性能
  • React 17 事件挂 root 的影响? e.target / e.currentTarget 行为不变;stopPropagation 仍按 React 树
  • mouseenter vs mouseover? enter/leave 不冒泡;over/out 冒泡;避免子元素误触

📝 小结

Section titled “📝 小结”
  • 事件流三个阶段:捕获 → 目标 → 冒泡,addEventListener 的第三个参数决定监听哪个阶段。
  • 事件委托:把监听器挂在父容器上,靠 event.target 判断 —— 动态元素也能响应,且只用一个监听器。
  • stopPropagation 阻止传播,preventDefault 阻止默认行为(如表单提交),两者是不同的事。
  • React/Vue 的「合成事件」是自行实现的冒泡模拟,e.target 会被修正为真正触发的元素。
