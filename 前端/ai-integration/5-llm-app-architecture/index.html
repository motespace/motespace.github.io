Q1: 直接调 LLM API vs BFF 中转？

Section titled “Q1: 直接调 LLM API vs BFF 中转？”

答：生产用 BFF。原因：

  • API Key 安全（不暴露前端）
  • 限流（防止滥用）
  • 日志 / 监控（统一）
  • 鉴权（用户权限）
  • 缓存（降本）

Q2: 上下文太长怎么处理？

Section titled “Q2: 上下文太长怎么处理？”

答：

  • 滑动窗口（只保留最近 K 轮）
  • 摘要压缩（长对话自动摘要）
  • 关键消息保留（LLM 提取要点）
  • Token 计数 + 截断

Q3: 怎么评估 LLM 应用质量？

Section titled “Q3: 怎么评估 LLM 应用质量？”

答：

  • 自动化指标：BLEU/ROUGE、胜率
  • 用户反馈：点赞率
  • 业务指标：转化率、留存
  • Golden Set：人工标注的标准答案集

Q4: 流式 + Function Calling 怎么处理？

Section titled “Q4: 流式 + Function Calling 怎么处理？”

答：

  • 先流式输出普通内容
  • 遇到 tool_call 停止流式，执行工具
  • 工具结果 → 继续流式输出后续内容

Q5: 前端 + AI 工程师应该学什么？

Section titled “Q5: 前端 + AI 工程师应该学什么？”

答：

  • TypeScript（基础）
  • React / Vue（基础）
  • Streaming / SSE（必学）
  • Prompt Engineering（必学）
  • RAG 原理（加分）
  • Function Calling（加分）

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • LLM 应用 4 层架构? UI / API Gateway / LLM Orchestrator(Agent 框架) / LLM Provider
  • 如何选 LLM? 简单任务:小模型(成本低);复杂推理:大模型(GPT-4 / Claude);中文:bce-ernie / qwen
  • Token 成本控制? 压缩上下文、缓存(Semantic Cache)、小模型分流
  • 怎么评测 LLM 应用? Golden Set(标注答案)+ 自动化指标 + 人工抽检
  • Agent vs Chain? Chain 固定流程;Agent 动态决策(LLM 决定下一步)

📝 小结

Section titled “📝 小结”
  • 典型架构:前端(对话 UI + 流式渲染)→ BFF(会话管理、Prompt 拼装、模型代理、计费)→ 模型服务,关键是把密钥和 Prompt 留在服务端。
  • 前端职责:会话状态、消息渲染、流式、断线重连、引用展示、文件上传预览;不该出现 API Key。
  • BFF 职责:统一模型接入(多供应商适配)、Prompt 模板与版本、限流与配额、成本统计、内容安全。
  • 错误处理要区分:网络错误(重试)、限流(退避 + 提示)、内容安全拦截(明确告知)、上下文超长(自动摘要或裁剪)。
  • 成本控制:上下文裁剪、缓存前缀(Prompt caching)、小模型兜底、限制最大输出 token、埋点统计每次会话成本。
  • 可观测性:记录每轮耗时、token 用量、模型、错误类型,才能定位「慢」和「贵」。
  • 面试加分:能画一张完整架构图,并说清前端与 BFF 的边界为什么这么切。
