方案优点缺点
直接调用简单、延迟低API Key 暴露、无法限流、无法鉴权
BFF 中转安全、可控、灵活增加延迟、复杂度

3.3 上下文管理 ​

ts
class ContextManager {
  private maxTokens = 8000  // GPT-4 16k context 的安全上限
  private messages: ChatMessage[] = []

  add(message: ChatMessage) {
    this.messages.push(message)
    this.trim()
  }

  private trim() {
    const totalTokens = this.countTokens(this.messages)

    if (totalTokens > this.maxTokens) {
      // 策略 1：保留 system + 最近 N 轮
      const system = this.messages.filter(m => m.role === 'system')
      const recent = this.messages.slice(-10)
      this.messages = [...system, ...recent]
    }
  }

  private countTokens(messages: ChatMessage[]): number {
    // 用 gpt-tokenizer 或 tiktoken 估算
    return messages.reduce((sum, m) => sum + this.estimate(m.content), 0)
  }

  private estimate(text: string): number {
    // 粗略估算：英文 1 词 ≈ 1.3 token，中文 1 字 ≈ 1.5 token
    return Math.ceil(text.length / 2)
  }
}

async function cachedChat(userId: string, message: string) {
  const key = `chat:${userId}:${hash(message)}`
  const cached = await redis.get(key)
  if (cached) return JSON.parse(cached)

  const result = await openai.chat.completions.create({ /* ... */ })
  await redis.setex(key, 3600, JSON.stringify(result))
  return result
}

// 3. Embedding 缓存
async function getEmbedding(text: string) {
  const key = `embed:${hash(text)}`
  const cached = await redis.get(key)
  if (cached) return JSON.parse(cached)

  const result = await openai.embeddings.create({ model: 'text-embedding-3-small', input: text })
  await redis.setex(key, 86400, JSON.stringify(result.data[0].embedding))
  return result.data[0].embedding
}

四、错误处理 ​

4.1 重试 + 退避 ​

ts
async function withRetry<T>(
  fn: () => Promise<T>,
  options: { maxRetries?: number; baseDelay?: number } = {}
): Promise<T> {
  const { maxRetries = 3, baseDelay = 1000 } = options

  for (let i = 0; i <= maxRetries; i++) {
    try {
      return await fn()
    } catch (err: any) {
      if (i === maxRetries) throw err

      // 限流：429 → 指数退避
      if (err.status === 429) {
        await sleep(baseDelay * Math.pow(2, i) + Math.random() * 1000)
        continue
      }

      // 5xx → 重试
      if (err.status >= 500) {
        await sleep(baseDelay * Math.pow(2, i))
        continue
      }

      // 4xx → 不重试
      throw err
    }
  }
  throw new Error('Unreachable')
}

7.2 Prompt Injection 防护 ​

ts
function sanitizeUserInput(input: string): string {
  // 1. 剥离指令注入尝试
  const dangerous = [
    /ignore\s+(previous|all|above)\s+(instructions?|prompts?)/gi,
    /system\s*:/gi,
    /assistant\s*:/gi,
    /<\|.*?\|>/g,  // 特殊 token
  ]
  let cleaned = input
  for (const pattern of dangerous) {
    cleaned = cleaned.replace(pattern, '[FILTERED]')
  }

  // 2. 长度限制
  cleaned = cleaned.slice(0, 4000)

  return cleaned
}

八、面试高频追问 ​

Q1: 直接调 LLM API vs BFF 中转？ ​

答：生产用 BFF。原因：

  • API Key 安全（不暴露前端）
  • 限流（防止滥用）
  • 日志 / 监控（统一）
  • 鉴权（用户权限）
  • 缓存（降本）

Q2: 上下文太长怎么处理？ ​

答：

  • 滑动窗口（只保留最近 K 轮）
  • 摘要压缩（长对话自动摘要）
  • 关键消息保留（LLM 提取要点）
  • Token 计数 + 截断

Q3: 怎么评估 LLM 应用质量？ ​

答：

  • 自动化指标：BLEU/ROUGE、胜率
  • 用户反馈：点赞率
  • 业务指标：转化率、留存
  • Golden Set：人工标注的标准答案集

Q4: 流式 + Function Calling 怎么处理？ ​

答：

  • 先流式输出普通内容
  • 遇到 tool_call 停止流式，执行工具
  • 工具结果 → 继续流式输出后续内容

Q5: 前端 + AI 工程师应该学什么？ ​

答：

  • TypeScript（基础）
  • React / Vue（基础）
  • Streaming / SSE（必学）
  • Prompt Engineering（必学）
  • RAG 原理（加分）
  • Function Calling（加分）
  • LangChain / Vercel AI SDK（加分）
  • 向量数据库（加分）

面试追问(深化原 Q1-Q5) ​

  • LLM 应用 4 层架构? UI / API Gateway / LLM Orchestrator(Agent 框架) / LLM Provider
