Q1: Function Calling 和 RAG 怎么选？

Section titled “Q1: Function Calling 和 RAG 怎么选？”

答：

  • RAG：知识问答（“公司年假几天”）→ 检索 + 答
  • Function Calling：需要执行动作（“订机票”）→ 调用工具
  • 常组合用：先 RAG 检索知识，再 Function Calling 调工具

Q2: 前端怎么处理 Function Calling 的 UI 操作？

Section titled “Q2: 前端怎么处理 Function Calling 的 UI 操作？”

答：用状态机管理。LLM 调用 UI 工具时切换到 awaiting_tool 状态，UI 异步等待用户输入，结果回传 LLM。

Q3: Function Calling 的安全边界怎么划？

Section titled “Q3: Function Calling 的安全边界怎么划？”

答：

  • 关键操作（删、改、转账）：必须 UI 二次确认 + 服务端权限校验
  • 查询类操作：服务端权限校验即可
  • 前端能做：UI 弹窗、状态切换、输入校验
  • 后端必须做：权限、风控、敏感操作最终校验

Q4: LLM 输出格式错了怎么办？

Section titled “Q4: LLM 输出格式错了怎么办？”

答：

  • 解析失败 → 用 retry 让 LLM 重新生成
  • 多次失败 → fallback 给出错误提示

面试追问(深化原 Q1-Q4)

Section titled “面试追问(深化原 Q1-Q4)”
  • tool 描述怎么写好? 清晰说明何时用、参数格式、返回值;越具体 LLM 越准
  • 多次 tool 调用怎么办? 循环:LLM 决策 → 调 tool → 结果回传 → LLM 再决策(ReAct)
  • JSON Schema 校验? LLM 输出可能不符 schema;用 zod 校验 + 错误回传 LLM 修正
  • OpenAI vs Anthropic tool calling 区别? 协议类似,字段命名略不同;OpenAI 用 tools,Anthropic 用 tools(但消息结构不同)

📝 小结

Section titled “📝 小结”
  • Function Calling 是「模型输出结构化调用意图」:模型不直接执行,只返回 tool_calls,由你的代码真正执行,再把结果回传让模型继续。
  • 协议形态:注册 tools(name/description/parameters JSON Schema)→ 模型返回调用请求 → 你执行后回 role: 'tool' 消息 → 模型基于结果继续回答。
  • 前端要做的是工具注册器:把可执行函数映射成 schema,再把 schema 映射回执行器,加白名单校验。
  • UI 状态机是核心工程点:普通对话只有 idle → streaming → done,带工具后会有 tool-calling → tool-result → streaming,用户要能看到「正在调用某某工具」。
  • UI 工具(如切换标签页、填表单)与 API 工具(查数据库)要区分:前者前端执行并可回滚,后者走后端服务。
  • 安全边界:工具参数必须服务端二次校验(schema 校验 + 权限检查),模型给的参数永远当作不可信输入。
  • 面试加分:能画出一张「用户提问 → 模型决策 → 工具执行 → 结果回填 → 最终答案」的时序图。
