二、协议选择：SSE vs WebSocket vs Fetch Stream

Section titled “二、协议选择：SSE vs WebSocket vs Fetch Stream”

2.1 SSE（Server-Sent Events）

Section titled “2.1 SSE（Server-Sent Events）”

特点：

  • 单向（服务端 → 客户端）
  • 基于 HTTP/HTTPS，无需额外协议
  • 浏览器原生 EventSource API
  • 自动重连

2.2 Fetch + ReadableStream

Section titled “2.2 Fetch + ReadableStream”

特点：

  • 更灵活（可 POST、可自定义请求头）
  • 适合 LLM API（OpenAI/Anthropic 都用这个）
  • SSE 框架：客户端 EventSource，服务端 send events

2.3 WebSocket

Section titled “2.3 WebSocket”

特点：

  • 双向通信
  • LLM 应用很少用（除非需要双向交互）
  • 适合聊天历史同步、协作编辑

选择

Section titled “选择”
场景 推荐
单次 LLM 调用 Fetch + ReadableStream
实时日志 / 通知 SSE
双向交互 WebSocket

七、面试高频追问

Section titled “七、面试高频追问”

Q1: SSE 和 WebSocket 怎么选？

Section titled “Q1: SSE 和 WebSocket 怎么选？”

答：

  • SSE：单向、服务端 → 客户端、HTTP 协议、自动重连、ChatGPT 场景
  • WebSocket：双向、需要双向交互（实时协作、IM）

Q2: 流式输出的核心难点？

Section titled “Q2: 流式输出的核心难点？”

答：

  1. 分块解析：SSE 协议不保证按 chunk 边界切分，要 buffer 处理
  2. 错误恢复：网络中断 → 重连 + 重试 + 历史消息
  3. 渲染性能：高频更新（每秒 50+ 次） → rAF 防抖
  4. 取消机制：用户点停 → AbortController + 中断循环

Q3: Fetch vs EventSource 怎么选？

Section titled “Q3: Fetch vs EventSource 怎么选？”

答：

  • EventSource：只支持 GET、不支持自定义头、简单场景
  • Fetch + ReadableStream：支持 POST、自定义头、可设置超时/取消（推荐）

Q5: 流式输出怎么渲染 Markdown / 代码块？

Section titled “Q5: 流式输出怎么渲染 Markdown / 代码块？”

答：

  • 用 react-markdown / marked 实时渲染
  • 但不完整 token 可能破坏 Markdown 结构 → 流式渲染时关闭语法补全
  • 完成后重新解析完整 Markdown确保正确

面试追问(深化原 Q1-Q4)

Section titled “面试追问(深化原 Q1-Q4)”
  • SSE vs WebSocket 选哪个? SSE 单向、HTTP 友好、自动重连;WS 双向、低延迟
  • 流式响应取消? AbortController + signal;客户端断开 → 服务端感知
  • token 限流? 按用户 IP / 设备 ID 限频;防爬虫 + 控成本
  • chunked transfer 编码? HTTP/1.1 Transfer-Encoding: chunked;不需 Content-Length

📝 小结

Section titled “📝 小结”
  • 流式的本质是分块传输:服务端持续推送 token,前端增量渲染,而不是等完整响应一次性返回。
  • 协议选择:SSE(单向、走 HTTP/2、自带重连,最贴合 LLM 场景)、WebSocket(双向,适合语音/协同)、Fetch Stream(现代浏览器原生流式读取,前端首选)。
  • 前端用 fetch + response.body.getReader() 逐块解码,注意要处理分块边界把一个字符切开的问题(用 TextDecoder({stream:true}))。
  • React 里要用 useState 增量拼接或 useSyncExternalStore,并把渲染节流(rAF / 16ms),否则高频 setState 会卡。
  • 性能要点:Markdown 增量渲染用 react-markdown 会很慢,实践是分段解析 + memo;长回答要做虚拟滚动。
  • 中断与重试:用 AbortController 取消请求,断线后按 lastEventId 续接(SSE 自带 Last-Event-ID)。
  • 面试加分:讲清「流式对 TTFB 和首字延迟的影响」,以及为什么它能显著改善主观体验。
