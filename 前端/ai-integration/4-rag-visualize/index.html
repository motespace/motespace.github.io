RAG 检索结果可视化

RAG（检索增强生成）= 知识库 + LLM。前端负责把检索结果可视化，让用户信任答案。 本文按“RAG 流程 → 检索 UI → 流式答案 + Source 引用”组织。

一、RAG 是什么

Section titled “一、RAG 是什么”

前端能做什么：

  • 渲染检索片段（高亮关键词、滚动定位）
  • 可点击的 source 引用（跳转到原文）
  • 流式答案 + 检索结果同步展示
  • 用户反馈（“这条引用有用吗”）

Q1: 怎么评估 RAG 检索质量？

Section titled “Q1: 怎么评估 RAG 检索质量？”

答：

  • 召回率（Recall）：相关片段是否被找到
  • 准确率（Precision）：返回的片段是否真的相关
  • 答案准确率：用户反馈（点赞率）
  • 关键指标：Top-5 命中率、引用相关性分数

Q2: 检索结果太多 / 太少怎么办？

Section titled “Q2: 检索结果太多 / 太少怎么办？”

答：

  • 太多：用 MMR（最大边际相关性）去重 + 多样性
  • 太少：扩大检索范围 / 改写问题 / 增加文档
  • 不相关：换 embedding 模型 / 加 metadata 过滤

Q3: RAG 和 Long Context 怎么选？

Section titled “Q3: RAG 和 Long Context 怎么选？”

答：

  • RAG：成本低、速度快、可溯源、文档量大时优选
  • Long Context：答案质量高、上下文完整、但贵 + 慢
  • 折中：先用 RAG 选 Top 3，再用 Long Context 精读

Q4: 前端怎么提升 RAG 体验？

Section titled “Q4: 前端怎么提升 RAG 体验？”

答：

  • 流式 + 来源同步：检索结果先到，答案流式补
  • 可点击引用：用户可以验证答案
  • 侧边对照阅读
  • 用户反馈循环：点踩 → 改进检索
  • 多模态：图片/表格也作为检索结果

面试追问(深化原 Q1-Q4)

Section titled “面试追问(深化原 Q1-Q4)”
  • Embedding 模型选型? 英文 text-embedding-3-small;中文 bge-large / m3e;多语言 bge-m3
  • Chunk 大小怎么定? 200-500 tokens;太小召回差,太大噪音多;按文档结构切(标题/段落)
  • 向量检索 vs 关键词? 语义召回用向量;专有名词用 BM25;混合召回最佳
  • RAG 评估指标? 召回率 / 准确率 / 答案相关性 / 幻觉率;用 RAGAS / LangSmith 评估

📝 小结

Section titled “📝 小结”
  • RAG 前端的核心体验是可解释:用户能看到答案来自哪些片段、原文是什么、相似度多少。
  • 典型 UI:左侧检索结果列表(标题+摘要+来源),右侧流式答案,答案内联引用角标,点击引用跳转并高亮原文。
  • 高亮定位要靠「片段 id + 字符偏移」而不是纯文本匹配,否则重复内容会跳错位置。
  • 检索结果要做排序与折叠:默认展示 Top3,其余折叠;并显示「未找到相关内容」的空状态,别让用户以为模型在瞎编。
  • 用户反馈(有用/无用)用于做检索质量评估,和引用点击率一起看。
  • 侧边栏对照模式适合「文档问答」场景:左边原文右边答案,方便核对。
  • 面试加分:讲「怎么做引用可追溯」——检索时保留 chunk id + metadata,回传时一起返回给前端做锚点。
