Q1: Prompt 太长怎么办？

Section titled “Q1: Prompt 太长怎么办？”

答：

  • 用 System Prompt + User Prompt 分层
  • 用 Few-shot 代替冗长指令
  • 用 Prompt Compression（如 LLMLingua）压缩
  • 必要时拆成多个 LLM 调用

Q2: 怎么防止 Prompt Injection？

Section titled “Q2: 怎么防止 Prompt Injection？”

答：

  • 用户输入和 System Prompt 严格隔离
  • 用户输入做 转义 + 过滤
  • 工具参数 结构化校验（zod schema）
  • 关键操作 UI 二次确认

Q3: Prompt 怎么评估好坏？

Section titled “Q3: Prompt 怎么评估好坏？”

答：

  • 量化指标：成功率、长度、延迟、成本
  • A/B 测试：对比不同版本
  • 人工评估：让业务方抽样打分
  • 自动化测试：用 Golden Set（标准答案集）

Q4: 多轮对话怎么处理 Prompt 增长？

Section titled “Q4: 多轮对话怎么处理 Prompt 增长？”

答：

  • 滑动窗口：只保留最近 K 轮
  • 摘要压缩：长对话自动摘要
  • 关键消息保留：用 LLM 提取每轮要点
  • Token 计数 + 截断：超过模型 context window 就截断

面试追问(深化原 Q1-Q4)

Section titled “面试追问(深化原 Q1-Q4)”
  • Few-shot 几个例子最好? 3-5 个;太多 token 浪费,太少 LLM 学不到模式
  • 系统提示词 vs 用户提示词? 系统 = 角色 + 约束 + 工具描述;用户 = 实际任务;两者分离便于模板化
  • Chain-of-Thought (CoT) 怎么用? 提示词加 “Let’s think step by step” 让 LLM 输出推理过程
  • Prompt 注入防护? 严格区分系统/用户消息;用户输入转义;敏感操作二次确认

📝 小结

Section titled “📝 小结”
  • Prompt 模板化的价值:可复用、可版本化、可 A/B、可按业务动态拼装,把提示词从代码里抽出来集中管理。
  • 模板引擎对比:{{var}} 简单自研、${} JS 模板字符串、Handlebars/Mustache 支持条件与循环、Promptfoo/LangChain 面向评测。
  • 模板分层:系统提示(角色与硬约束)+ 任务模板(具体任务)+ 上下文注入(用户输入、检索片段、历史对话)。
  • 变量必须做转义与白名单,防止用户输入里的指令覆盖系统提示(prompt injection)。
  • 管理上要有:模板版本号、变更记录、回归测试集(固定输入 → 期望输出/评分)。
  • 面试加分:讲「我们把提示词抽到配置中心,改文案不发版」这类工程收益,以及用评测集防止改提示词改坏效果。
