一、浏览器渲染类 ​

Q1: 什么是 CRP？如何优化关键渲染路径？ ​

答案：

关键渲染路径（Critical Rendering Path）是浏览器将 HTML、CSS、JavaScript 转化为屏幕像素的过程。

流程：

HTML → DOM → CSSOM → Render Tree → Layout → Paint → Composite

优化方法：

优化手段实现方式
减少关键资源删除不必要的资源、延迟加载
压缩资源Minify、CSS/JS 压缩
优化 CSSCritical CSS 内联、非关键异步
优化 JSdefer/async、代码分割
预加载preload/prefetch
html
<!-- 关键 CSS 内联 -->
<style>body { margin: 0 }</style>

<!-- 预加载关键资源 -->
<link rel="preload" href="main.js" as="script">

<!-- 非关键 JS 延迟 -->
<script defer src="analytics.js"></script>

Q2: 重排和重绘的区别？如何避免？ ​

答案：

操作说明触发阶段
重排（Reflow）元素位置、尺寸变化Layout 阶段
重绘（Repaint）外观变化不影响布局Paint 阶段

触发重排的操作：

  • 增删 DOM 节点
  • 改变元素尺寸（width、height、margin、padding）
  • 内容变化（textContent）
  • 获取布局信息（offsetWidth、getComputedStyle）

优化方法：

javascript
// ❌ 错误：读写交替触发多次 Layout
element.style.width = element.offsetWidth + 'px'
element.style.height = element.offsetHeight + 'px'

// ✅ 正确：先读后写，批量操作
const width = element.offsetWidth
const height = element.offsetHeight
element.style.width = width + 'px'
element.style.height = height + 'px'
css
/* 使用 transform/opacity（只触发 Composite）*/
transform: translateX(100px);  /* 性能好 */
opacity: 0.5;                   /* 性能好 */

/* 避免使用（触发 Layout）*/
position: absolute;  /* 慎用 */
width: 100%;          /* 慎用频繁变化 */

Q3: 什么是防抖和节流？区别是什么？ ​

答案：

防抖（Debounce）：事件触发 n 秒后执行，n 秒内再次触发则重置定时器。

javascript
function debounce(fn, delay) {
  let timer = null
  return function(...args) {
    clearTimeout(timer)
    timer = setTimeout(() => {
      fn.apply(this, args)
    }, delay)
  }
}

// 使用场景：搜索框输入（输入完成后才搜索）
input.addEventListener('input', debounce(handleSearch, 300))

节流（Throttle）：n 秒内只执行一次。

javascript
function throttle(fn, delay) {
  let last = 0
  return function(...args) {
    const now = Date.now()
    if (now - last >= delay) {
      last = now
      fn.apply(this, args)
    }
  }
}

// 使用场景：滚动事件（固定频率执行）
window.addEventListener('scroll', throttle(handleScroll, 100))
区别防抖节流
触发时机停止触发后 n 秒执行n 秒内最多执行一次
适用场景表单验证、搜索滚动、resize

二、React 性能优化类 ​

Q4: React 如何避免不必要的渲染？ ​

答案：

方法适用组件原理
shouldComponentUpdate类组件手动控制
PureComponent类组件浅比较 props/state
React.memo函数组件浅比较 props
useMemo值缓存计算结果
useCallback函数缓存函数引用
tsx
// 类组件
class Counter extends React.PureComponent {
  render() {
    return <div>{this.props.count}</div>
  }
}

// 函数组件
const Counter = React.memo(({ count }) => {
  return <div>{count}</div>
})

// 或自定义比较函数
const Counter = React.memo(
  ({ count }) => <div>{count}</div>,
  (prev, next) => prev.count === next.count
)

// 配合 useCallback
const handleClick = useCallback(() => {
  doSomething(id)
}, [id])

Q5: React 中的虚拟 DOM 是什么？工作原理？ ​

答案：

虚拟 DOM：用 JavaScript 对象描述真实 DOM 结构。

工作原理：

State 变化 → Re-render 生成新 VDOM → Diff 对比 → Patch 更新真实 DOM

优势：

  1. 减少直接 DOM 操作
  2. 批量更新减少重排重绘
  3. 跨平台能力（SSR、Native）

Diff 算法：

  • 同层对比
  • key 标记节点身份
  • 类型不同直接替换

Q6: React 的 diff 算法是怎么工作的？ ​

答案：

React 使用三种策略优化 diff：

1. 类型对比

jsx
// 如果节点类型改变，整个子树替换
<div> → <span> // 直接销毁重建

2. key 对比

jsx
// 使用 key 标记节点身份
{items.map(item => <li key={item.id}>{item.name}</li>)}
// 有 key：移动/更新/删除精准匹配
// 无 key：可能错误复用节点

3. 同层对比

jsx
// 只比较同层节点，不跨层比较
<div>
  <p>1</p>  ← 只和同层比较
</div>
<div>
  <p>2</p>
</div>

Q8: Vue3 比 Vue2 性能好在哪里？ ​

答案：

方面Vue2Vue3
响应式defineProperty（需深度遍历）Proxy（懒代理整个对象）
虚拟 DOM普通 diffBlock Tree + PatchFlag

Vue3 具体优化：

html
<!-- 1. 静态提升：不参与更新的元素只创建一次 -->
<span>静态内容</span>  <!-- 被提升到 render 函数外 -->

<!-- 2. PatchFlag：只标记动态部分 -->
<span>{{ msg }}</span>  <!-- 只比较 text -->

<!-- 3. 事件缓存：缓存事件处理函数 -->
<button @click="handleClick">  <!-- 不重复创建函数 -->

Q9: Vue 中的响应式原理是什么？ ​

答案：

Vue2：

javascript
// defineProperty 只能代理已有属性
Object.defineProperty(obj, 'prop', {
  get() { track() },      // 收集依赖
  set(newVal) { trigger() } // 通知更新
})

// 问题：新增属性需要 $set，数组索引需要 $set

Vue3：

javascript
// Proxy 代理整个对象
const proxy = new Proxy(obj, {
  get(target, key) {
    track(target, key)
    return Reflect.get(target, key)
  },
  set(target, key, newVal) {
    trigger(target, key)
    return Reflect.set(target, key, newVal)
  },
  deleteProperty(target, key) {
    trigger(target, key)
    return Reflect.deleteProperty(target, key)
  }
})

优势：

  • 可以监听新增属性
  • 可以监听数组索引和 length
  • 可以监听删除属性
  • 无需深度遍历

Q10: Vue 中 keep-alive 的作用？ ​

答案：

缓存组件实例，避免重复创建销毁。

vue
<template>
  <keep-alive :include="['Home', 'About']" :exclude="['Login']" :max="10">
    <router-view />
  </keep-alive>
</template>

属性：

  • include：缓存的组件名（逗号分隔、正则、数组）
  • exclude：不缓存的组件名
  • max：最大缓存数量

生命周期：

  • activated：激活时调用
  • deactivated：缓存时调用
vue
<script>
export default {
  activated() {
    console.log('组件激活')
  },
  deactivated() {
    console.log('组件缓存')
  }
}
</script>

Q12: Tree Shaking 的原理是什么？ ​

答案：

Tree Shaking 依赖 ES Module 的静态特性，移除未使用的代码。

条件：

  1. 使用 ES Module（import/export）
  2. package.json 设置 sideEffects
  3. 生产模式（mode: production）
json
{
  "sideEffects": ["*.css", "*.scss"]
}

原理：

1. 标记（usedExports）：标记所有导出引用的导出
2. 压缩（minimize）：移除未标记的导出
javascript
// math.js
export const add = (a, b) => a + b
export const multiply = (a, b) => a * b

// index.js
import { add } from './math'
add(1, 2)  // multiply 被标记为未使用

Q13: 分包的策略有哪些？ ​

答案：

splitChunks 配置：

javascript
{
  optimization: {
    splitChunks: {
      chunks: 'all', // all | async | initial
      minSize: 20000,
      cacheGroups: {
        // 第三方库
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          priority: -10
        },
        // 公共模块
        common: {
          name: 'common',
          minChunks: 2,
          priority: -20,

    }
  }
}

分包策略：

  • 业务代码和第三方库分离
  • 路由懒加载单独分包
  • 公共组件单独分包
  • 频繁更新的单独分包

五、网络与缓存类 ​

Q14: 说说强缓存和协商缓存？ ​

答案：

类型缓存位置命中条件常用头
强缓存客户端不过期就用Cache-Control、Expires
协商缓存服务器服务端确认可用Last-Modified、ETag

强缓存：

http
# Cache-Control
Cache-Control: max-age=31536000  # 1年
Cache-Control: no-cache         # 不缓存
Cache-Control: no-store         # 不缓存（包含敏感信息）

# Expires（已不推荐）
Expires: Wed, 21 Oct 2026 07:28:00 GMT

协商缓存：

http
# Last-Modified / If-Modified-Since
Last-Modified: Wed, 21 Oct 2025 07:28:00 GMT
If-Modified-Since: Wed, 21 Oct 2025 07:28:00 GMT

# ETag / If-None-Match（优先级更高）
ETag: "33a64df551425fcc55e4d42a148795d9f25f89d4"
If-None-Match: "33a64df551425fcc55e4d42a148795d9f25f89d4"

命中协商缓存：返回 304 Not Modified

Q15: 前端资源缓存的最佳实践？ ​

答案：

javascript
// HTML：不缓存或短期缓存
app.get('/views/*', (req, res) => {
  res.setHeader('Cache-Control', 'no-cache')
})

// 静态资源（JS/CSS）：长期缓存 + 分版本
app.use('/static', express.static('public', {
  maxAge: '1y',  // 1年
  etag: true
}))

// CDN 配置
Cache-Control: public, max-age=31536000, immutable

文件名加 hash：

javascript
// webpack 配置
{
  output: {
    filename: '[name].[contenthash:8].js'
  }
}
// 改变时 hash 变化，旧缓存自动失效

六、性能指标类 ​

Q16: Core Web Vitals 有哪些指标？ ​

答案：

指标全称目标测量
LCPLargest Contentful Paint≤ 2.5s加载
INPInteraction to Next Paint≤ 200ms交互
CLSCumulative Layout Shift≤ 0.1稳定

LCP 优化：

  • 预加载关键资源
  • 使用现代图片格式（WebP/AVIF）
  • 关键 CSS 内联
  • CDN 加速

INP 优化：

  • 减少主线程任务
  • 分解长任务（requestIdleCallback）
  • 避免布局抖动

CLS 优化：

  • 为图片/视频预留尺寸
  • 避免动态内容插入
  • 使用 font-display: swap

Q23: 如何优化高并发下的性能？ ​

答案：

// Bundle 合并
{
  splitChunks: { chunks: 'all' }
}

// 资源内联

2. 并发控制

javascript
// 限制并发请求数
async function fetchWithLimit(urls, limit = 6) {
  const results = []
  const executing = []

  for (const url of urls) {
    const promise = fetch(url).then(result => {
      results.push(result)
      executing.splice(executing.indexOf(promise), 1)
    })

    results.push(promise)

    if (executing.length >= limit) {
      await Promise.race(executing)
    }
  }

  return Promise.all(results)
}

3. 任务分解

javascript
// Web Worker 处理计算密集任务
const worker = new Worker('compute.js')
worker.postMessage({ data: largeArray })
worker.onmessage = ({ data }) => updateUI(data)

Q24: Service Worker 缓存策略有哪些？ ​

答案：

策略说明适用场景
Cache First先缓存，失败再网络静态资源、SDK
Network First先网络，失败再缓存频繁更新的数据
Stale While Revalidate返回缓存，后台更新变化频率适中的资源
Network Only只用网络实时数据
Cache Only只用缓存完全离线
javascript
// Stale While Revalidate
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.open(CACHE_NAME).then(cache =>
      cache.match(event.request).then(response => {
        const fetchPromise = fetch(event.request).then(networkResponse => {
          cache.put(event.request, networkResponse.clone())
          return networkResponse
        })
        return response || fetchPromise
      })
    )
  )
})
