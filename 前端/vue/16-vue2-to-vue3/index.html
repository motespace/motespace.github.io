📝 小结

Section titled “📝 小结”
  • 迁移的第一步是把选项式 API 转成 script setup,这一步收益最大也最机械。
  • filters 已被移除,用方法或计算属性替代;$children 移除;v-model 改用 modelValue;事件总线改用 mitt。
  • beforeDestroy/destroyed → beforeUnmount/unmounted;data 里的函数也要改成箭头函数(否则 this 指向不对)。
  • 用 @vue/compat 可以让大部分代码不用改,先跑通再逐步清理。

面试常考

Section titled “面试常考”

Q1:Vue 2 → Vue 3 最大的破坏性变化?

Section titled “Q1:Vue 2 → Vue 3 最大的破坏性变化?”

答:

  • 移除 filter:用 computed 替代
  • 移除 $children、$listeners:用 provide/inject / attrs
  • 移除 slot="xxx" attribute:统一用 &lt;template #xxx&gt;
  • 移除 keyCode 修饰符:用 key.name(@keyup.delete)
  • v-if 优先级:Vue 2 v-for > v-if;Vue 3 v-if > v-for
  • $on/$off/$once:移除(全局事件总线用 mitt / pinia)

Q2:迁移策略怎么选?

Section titled “Q2:迁移策略怎么选?”

答:

  1. 渐进迁移(推荐):用 @vue/compat 构建版本,新旧 API 兼容,逐步替换
  2. 重写:小项目 / 项目稳定可重写,Vue 3 + TS + Composition API
  3. 共存:大项目分模块,新模块用 Vue 3,旧模块维持 Vue 2(不推荐,复杂度高)

Q3:Vue 2 项目要立刻升级吗?

Section titled “Q3:Vue 2 项目要立刻升级吗?”

答:

  • 官方 EOL 2023-12-31:Vue 2 已停止维护,新项目必须 Vue 3
  • 企业老项目:评估 ROI;无新需求可维持,有新功能 / 安全要求则升级
  • 过渡方案:@vue/compat 兼容包 + 逐步替换
  • 库兼容:Element UI 升级到 Element Plus;Vuex 4 → Pinia

Q4:迁移常见坑点?

Section titled “Q4:迁移常见坑点?”

答:

  • v-model 语法变化:Vue 2 v-model="var" 等价 v-bind:value + @input;Vue 3 拆 modelModifiers
  • TypeScript 支持:Vue 3 原生支持;Vue 2 需要 vue-class-component / vue-property-decorator
  • 事件总线:Vue 2 new Vue() 替代;Vue 3 用 mitt / tiny-emitter
  • 过滤器:全部改成 computed 或方法
