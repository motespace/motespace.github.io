Vue3.0 所采用的 Composition Api 与 Vue2.x 使用的 Options Api 有什么不同？

开始之前

Section titled “开始之前”

Composition API 可以说是Vue3的最大特点，那么为什么要推出Composition Api，解决了什么问题？

通常使用Vue2开发的项目，普遍会存在以下问题：

  • 代码的可读性随着组件变大而变差
  • 每一种代码复用的方式，都存在缺点
  • TypeScript支持有限

以上通过使用Composition Api都能迎刃而解

正文

Section titled “正文”

一、Options Api

Section titled “一、Options Api”

Options API，即大家常说的选项API，即以vue为后缀的文件，通过定义methods，computed，watch，data等属性与方法，共同处理页面逻辑

如下图：

可以看到Options代码编写方式，如果是组件状态，则写在data属性上，如果是方法，则写在methods属性上…

用组件的选项 (data、computed、methods、watch) 组织逻辑在大多数情况下都有效

然而，当组件变得复杂，导致对应属性的列表也会增长，这可能会导致组件难以阅读和理解

二、Composition Api

Section titled “二、Composition Api”

在 Vue3 Composition API 中，组件根据逻辑功能来组织的，一个功能所定义的所有 API 会放在一起（更加的高内聚，低耦合）

即使项目很大，功能很多，我们都能快速的定位到这个功能所用到的所有 API

面试常考

Section titled “面试常考”

Q1:Composition API 解决了什么?

Section titled “Q1:Composition API 解决了什么?”

答:

  • Options API 逻辑分散(data/methods/computed 各处);Composition API 按“逻辑关注点”组织(数据+方法+生命周期放一起)
  • TS 友好(无需 this 类型推断)
  • 更好的 tree-shaking(按需 import)
  • 更好的逻辑复用(composable 替代 mixin)

Q2:setup() 里为什么不能用 this?

Section titled “Q2:setup() 里为什么不能用 this?”

答:

  • setup 在 beforeCreate 之前执行,组件实例还没创建
  • 所有 props/context 通过参数传入:setup(props, { emit, slots, attrs, expose })
  • Composition API 全程不依赖 this,更函数式

Q3:ref 和 reactive 怎么选?

Section titled “Q3:ref 和 reactive 怎么选?”

答:

  • ref:基本类型 + 对象皆可;.value 访问
  • reactive:只接受对象;直接访问(无 .value)
  • 模板里 ref 自动解包;script 里需 .value
  • 推荐:绝大多数场景用 ref(行为一致、好推断)

Q4:watch 和 watchEffect 区别?

Section titled “Q4:watch 和 watchEffect 区别?”

答:

  • watch:显式指定依赖(watch(source, cb));惰性(默认不立即执行)
  • watchEffect:自动收集依赖;立即执行一次
  • 老 watch 写法 watch: {} Options API 仍可用,但 setup 里推荐 watch / watchEffect

Q5:provide/inject 怎么保持响应性?

Section titled “Q5:provide/inject 怎么保持响应性?”

答:

  • 传 ref/reactive 进去(不是普通值)
  • inject 拿到的 ref 直接用,模板自动解包
  • 修改用 .value,跨层级响应正常
  • 现代项目优先用 Pinia 替代跨层级传值

📝 小结

Section titled “📝 小结”
  • Composition API 的价值是按逻辑关注点组织代码,而不是按选项类型。
  • 每个组合式函数是一个独立的作用域,内部的状态和生命周期互不干扰,天然可复用。
  • ref 管基本类型和整体替换的对象,reactive 管复杂对象的字段级修改;解构 reactive 会丢失响应式。
  • 组合式函数命名以 use 开头,让 Vue 能识别并做 lint 校验。
