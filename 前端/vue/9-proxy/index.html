一、Object.defineProperty

Section titled “一、Object.defineProperty”

定义：Object.defineProperty() 方法会直接在一个对象上定义一个新属性，或者修改一个对象的现有属性，并返回此对象

为什么能实现响应式
Section titled “为什么能实现响应式”

通过defineProperty 两个属性，get及set

  • get

属性的 getter 函数，当访问该属性时，会调用此函数。执行时不传入任何参数，但是会传入 this 对象（由于继承关系，这里的this并不一定是定义该属性的对象）。该函数的返回值会被用作属性的值

  • set

属性的 setter 函数，当属性值被修改时，会调用此函数。该方法接受一个参数（也就是被赋予的新值），会传入赋值时的 this 对象。默认为 undefined

三、Vue 2 vs Vue 3 响应式原理对比

Section titled “三、Vue 2 vs Vue 3 响应式原理对比”

这一节是面试高频题。Vue 2 的响应式和 Vue 3 的响应式核心机制完全不同, Vue 3 用 Proxy 重写不是简单的“升级”,而是根本性的架构改进。

3.1 核心差异对比表

Section titled “3.1 核心差异对比表”
维度 Vue 2(Object.defineProperty) Vue 3(Proxy)
实现方式 遍历对象属性,逐个 defineProperty 代理整个对象,get/set/deleteProperty 拦截
监听范围 仅对象属性 整个对象 + 数组 + Map/Set
新增属性 ⚠️ 监听不到(需 Vue.set 补救) ✅ 自动响应
删除属性 ⚠️ 监听不到(需 Vue.delete 补救) ✅ 自动响应
数组下标赋值 ⚠️ 监听不到(arr[0] = ...) ✅ 自动响应
数组 length 修改 ⚠️ 改 length 无效 ✅ 自动响应
初始化性能 全量递归遍历所有属性 访问时再递归(惰性代理)
嵌套对象 初始化时一次性递归到底 访问到才递归(按需)
IE 兼容 ✅ 支持 IE9+ ⚠️ 不支持 IE(Proxy ES6)
API 简洁度 需要 Vue.set / Vue.delete 一个 Proxy 全搞定

Q:Vue 3 为什么要用 Proxy 替代 defineProperty?

  1. 能监听新增/删除属性 —— Proxy 拦截 set / deleteProperty
  2. 能监听数组下标变化 —— 数组也是对象,Proxy 全拦截
  3. 性能更好 —— 惰性代理,访问到才递归,不用一次性遍历
  4. API 更简洁 —— 一个 Proxy 搞定,不用 Vue.set / Vue.delete
  5. 支持 Map/Set —— Vue 2 完全无法监听
  6. 唯一缺点:Proxy 不兼容 IE(IE 已退役,可忽略)

四、总结

Section titled “四、总结”

Object.defineProperty只能遍历对象属性进行劫持

Proxy直接可以劫持整个对象，并返回一个新对象，我们可以只操作新的对象达到响应式目的

Proxy可以直接监听数组的变化（push、shift、splice）

Proxy有多达13种拦截方法,不限于apply、ownKeys、deleteProperty、has等等，这是Object.defineProperty不具备的

正因为defineProperty自身的缺陷，导致Vue2在实现响应式过程需要实现其他的方法辅助（如重写数组方法、增加额外set、delete方法）

Proxy 不兼容IE，也没有 polyfill, defineProperty 能支持到IE9

📝 小结

Section titled “📝 小结”
  • Vue 3 用 Proxy 替代 defineProperty,解决了 defineProperty 的三个硬伤:新增/删除属性检测不到、数组索引与 API 调用监听不到、必须逐属性遍历 + 深层监听导致性能问题。
  • 响应式分三层:reactive(深层代理)、ref(通过 getter/setter 转换)、shallowRef/shallowReactive(只代理一层,用于大数据)。
  • 依赖收集靠 targetMap(WeakMap → Map)按 key 精确记录,改哪个 key 只通知谁。
  • toRaw 可以拿到原始对象(跳过代理),markRaw 标记为「不要转响应式」。

答:

Section titled “Q3:Proxy 有什么限制?”
