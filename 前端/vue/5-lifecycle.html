Vue 生命周期详解 ​

一、为什么需要了解生命周期 ​

Vue 组件从创建到销毁经历多个阶段,每个阶段触发不同的"钩子"——在这些钩子里可以:

  • created:初始化数据、发请求
  • mounted:操作 DOM、初始化第三方库
  • beforeUnmount:清理定时器、解绑事件

Vue 3 组合式 API(推荐):

ts
import { onMounted, onBeforeUnmount } from 'vue'

onMounted(() => {
  // 组件挂载后
})

onBeforeUnmount(() => {
  // 组件销毁前,清理资源
})

Vue 3 选项式 API(老项目):

ts
export default {
  mounted() { ... },
  beforeUnmount() { ... },
}

二、生命周期全流程 ​

┌─────────────────────────────────────────┐
│ 1. 创建阶段                              │
│   - beforeCreate                         │
│   - created(响应式数据、methods 已创建)  │
├─────────────────────────────────────────┤
│ 2. 挂载阶段                              │
│   - beforeMount                          │
│   - mounted(DOM 已挂载)                  │
├─────────────────────────────────────────┤
│ 3. 更新阶段(响应式数据变化时)             │
│   - beforeUpdate                         │
│   - updated                              │
├─────────────────────────────────────────┤
│ 4. 卸载阶段(组件销毁时)                  │
│   - beforeUnmount                        │
│   - unmounted                            │
└─────────────────────────────────────────┘

辅助钩子:
- errorCaptured:子组件抛错时
- renderTracked:渲染追踪(调试)
- renderTriggered:触发原因
- activated / deactivated:<keep-alive>

三、组合式 API 生命周期 ​

3.1 onMounted ​

ts
import { onMounted, ref } from 'vue'

const chartRef = ref<HTMLElement>()

onMounted(() => {
  // DOM 已挂载,可以访问 ref
  console.log('DOM:', chartRef.value)
  
  // 初始化第三方库(ECharts、地图)
  const chart = echarts.init(chartRef.value)
  chart.setOption({ /* ... */ })
})

SSR 注意点:onMounted 只在客户端执行,服务端渲染时不会调用。

3.2 onBeforeUnmount ​

ts
import { onBeforeUnmount } from 'vue'

let timer: number | null = null
let eventSource: EventSource | null = null

onMounted(() => {
  timer = window.setInterval(() => {
    console.log('tick')
  }, 1000)
  
  eventSource = new EventSource('/api/events')
  eventSource.onmessage = (e) => { /* ... */ }
})

onBeforeUnmount(() => {
  // 必须清理!
  if (timer) clearInterval(timer)
  eventSource?.close()
})

实战经验:每个 onMounted 都要配 onBeforeUnmount 清理——否则会内存泄漏。

3.3 onUpdated ​

ts
import { onUpdated, ref } from 'vue'

const contentRef = ref<HTMLElement>()

onUpdated(() => {
  // DOM 更新后,可以读最新 DOM
  console.log('高度:', contentRef.value?.scrollHeight)
})

实战:常用于"DOM 变化后调整布局"。

3.4 完整生命周期钩子 ​

ts
import {
  onBeforeMount,
  onMounted,
  onBeforeUpdate,
  onUpdated,
  onBeforeUnmount,
  onUnmounted,
  onActivated,
  onDeactivated,
  onErrorCaptured,
} from 'vue'

四、选项式 API 生命周期 ​

4.1 老项目风格 ​

ts
export default {
  data() {
    return { count: 0 }
  },
  
  beforeCreate() {
    // 组件实例刚创建,data/methods 还没初始化
    console.log('beforeCreate')
  },
  
  created() {
    // data/methods 已初始化,可访问 this
    console.log('created:', this.count)
    // 通常在这里发请求
    this.fetchData()
  },
  
  beforeMount() {
    // 模板编译完成,DOM 还没挂载
  },
  
  mounted() {
    // DOM 已挂载,可操作 DOM
    console.log('mounted:', this.$refs.chart)
  },
  
  beforeUpdate() {
    // 数据变化,DOM 还没更新
  },
  
  updated() {
    // DOM 已更新
  },
  
  beforeUnmount() {  // Vue 2 是 beforeDestroy
    // 清理工作
  },
  
  unmounted() {  // Vue 2 是 destroyed
  },
}

4.2 Options vs Composition API 对比 ​

OptionsComposition
钩子写法组件配置项显式 import 调用
this需要不需要
TS 支持一般优秀
复用mixin(不优雅)composable
代码组织按选项分块按逻辑分块

五、特殊场景 ​

5.1 keep-alive 缓存组件 ​

vue
<template>
  <keep-alive>
    <component :is="currentTab" />
  </keep-alive>
</template>

额外钩子:

  • onActivated:组件被激活(进入 keep-alive)
  • onDeactivated:组件被停用(离开 keep-alive)
ts
onActivated(() => {
  // 每次进入都触发
  refreshData()
})

onDeactivated(() => {
  // 每次离开都触发
  stopPolling()
})

5.2 错误处理 ​

ts
import { onErrorCaptured } from 'vue'

onErrorCaptured((err, instance, info) => {
  console.error('子组件错误:', err)
  console.log('组件:', instance)
  console.log('错误类型:', info)  // 'render' | 'event' | 'lifecycle'
  
  // 上报到 Sentry
  Sentry.captureException(err)
  
  // 返回 false 阻止继续传播
  return false
})

5.3 异步组件 ​

ts
import { defineAsyncComponent } from 'vue'

const AsyncModal = defineAsyncComponent(() => import('./Modal.vue'))

// 用法
<AsyncModal v-if="show" />

生命周期差异:

  • 异步组件加载完成才触发 created/mounted
  • 可以显示 loading 占位

5.4 Suspense ​

vue
<template>
  <Suspense>
    <template #default>
      <AsyncComponent />
    </template>
    <template #fallback>
      <Loading />
    </template>
  </Suspense>
</template>

配合异步组件:

ts
// AsyncComponent.vue
<script setup>
const data = await fetch('/api/data')  // 顶层 await
</script>

Suspense 等异步组件完成才显示。

六、父子组件生命周期顺序 ​

6.1 挂载 ​

父 beforeCreate
父 created
父 beforeMount
  ├ 子 beforeCreate
  ├ 子 created
  ├ 子 beforeMount
  ├ 子 mounted      ← 子先挂载
父 mounted

6.2 更新 ​

父 beforeUpdate
  ├ 子 beforeUpdate
  ├ 子 updated      ← 子先更新
父 updated

6.3 卸载 ​

父 beforeUnmount
  ├ 子 beforeUnmount
  ├ 子 unmounted    ← 子先卸载
父 unmounted

记忆:创建从外到内,渲染从内到外。

七、实战经验 ​

7.1 数据请求放哪里? ​

推荐放 onMounted(组合式) / mounted(选项式):
  - 浏览器环境(window 存在)
  - DOM 可访问
  - 不阻塞 SSR

如果用 SSR,要避免 mounted 里的副作用
ts
onMounted(async () => {
  const res = await fetch('/api/users')
  users.value = await res.json()
})

7.2 第三方库初始化 ​

ts
import * as echarts from 'echarts'
import { onMounted, onBeforeUnmount, ref } from 'vue'

const chartRef = ref<HTMLElement>()
let chart: echarts.ECharts | null = null

onMounted(() => {
  if (!chartRef.value) return
  chart = echarts.init(chartRef.value)
  chart.setOption({ /* ... */ })
})

onBeforeUnmount(() => {
  chart?.dispose()  // 必须清理!
  chart = null
})

7.3 事件监听 ​

ts
import { onMounted, onBeforeUnmount } from 'vue'

function handleResize() {
  console.log('窗口变了')
}

onMounted(() => {
  window.addEventListener('resize', handleResize)
})

onBeforeUnmount(() => {
  window.removeEventListener('resize', handleResize)
})

不要在 mounted 里 addEventListener 然后忘了 removeEventListener。

7.4 定时器 ​

ts
import { ref, onMounted, onBeforeUnmount } from 'vue'

const seconds = ref(0)
let timer: ReturnType<typeof setInterval> | null = null

onMounted(() => {
  timer = setInterval(() => {
    seconds.value++
  }, 1000)
})

onBeforeUnmount(() => {
  if (timer) clearInterval(timer)
})

7.5 WebSocket ​

ts
import { onMounted, onBeforeUnmount, ref } from 'vue'

const messages = ref<Message[]>([])
let ws: WebSocket | null = null

onMounted(() => {
  ws = new WebSocket('wss://api.example.com/ws')
  ws.onmessage = (e) => {
    messages.value.push(JSON.parse(e.data))
  }
})

onBeforeUnmount(() => {
  ws?.close()
})

九、SSR 注意点 ​

ts
// onMounted 只在客户端执行
onMounted(() => {
  console.log('window:', window.innerWidth)  // ❌ SSR 报错
})

// 用 onServerPrefetch 或放在 setup 里(同步部分)
const data = await fetch('/api/data')  // ✅ SSR 也能跑

SSR 生命周期:

服务端:setup() → onServerPrefetch()
客户端:setup() → onBeforeMount() → onMounted()

十、Vue 2 ↔ Vue 3 生命周期钩子对照表 ​

Vue 3 对钩子做了大幅调整:

  • ❌ 删除:beforeCreate / created —— 因为 setup() 已经覆盖了它们的功能
  • 🔄 重命名:beforeDestroy / destroyed → beforeUnmount / unmounted(语义更准确)
  • 🆕 新增:onRenderTracked / onRenderTriggered —— 调试响应式依赖用

9.2 为什么重命名 destroyed → unmounted? ​

Vue 3 把 beforeDestroy / destroyed 改为 beforeUnmount / unmounted,语义更准确:

术语含义
destroy听起来像"销毁实例对象",但实际上实例对象还在
unmount ✅准确表达"从 DOM 树卸载",this 仍然可用,只是 $el 没了
js
// Vue 2 (废弃)
export default {
  beforeDestroy() {
    clearInterval(this.timer)  // 实例还在,只是准备卸载
  }
}

// Vue 3
export default {
  beforeUnmount() {  // 语义清晰
    clearInterval(this.timer)
  }
}

9.3 Vue 2 vs Vue 3 代码对比 ​

数据请求(放哪里?) ​

js
// Vue 2 —— created
export default {
  data() {
    return { users: [] }
  },
  async created() {  // ✅ created 中发请求
    const res = await api.getUsers()
    this.users = res.data
  }
}
vue
<!-- Vue 3 —— onMounted 或 setup 顶层 -->
<script setup>
import { ref, onMounted } from 'vue'
const users = ref([])

onMounted(async () => {  // ✅ onMounted 中发请求
  const res = await api.getUsers()
  users.value = res.data
})
</script>

💡 created vs onMounted:两者都能发请求。created 触发更早(无 DOM),mounted 有 DOM。如果依赖 DOM(echarts 初始化),用 onMounted。

清理定时器/事件 ​

js
// Vue 2
export default {
  mounted() {
    this.timer = setInterval(() => {
      console.log('tick')
    }, 1000)
  },
  beforeDestroy() {  // 🔄 Vue 3 中重命名
    clearInterval(this.timer)
  }
}
vue
<!-- Vue 3 -->
<script setup>
import { onMounted, onBeforeUnmount } from 'vue'

let timer
onMounted(() => {
  timer = setInterval(() => console.log('tick'), 1000)
})
onBeforeUnmount(() => {
  clearInterval(timer)  // ✅ 必须配对,否则内存泄漏
})
</script>

9.4 父子组件生命周期顺序(Vue 2 / Vue 3 一致) ​

父子生命周期顺序规则不受版本影响:

挂载阶段(从外到内 → 从内到外):
父 beforeCreate → 父 created → 父 beforeMount
  → 子 beforeCreate → 子 created → 子 beforeMount → 子 mounted
  → 父 mounted

更新阶段:
父 beforeUpdate
  → 子 beforeUpdate → 子 updated
  → 父 updated

卸载阶段(从外到内 → 从内到外):
父 beforeDestroy/beforeUnmount
  → 子 beforeDestroy/beforeUnmount → 子 destroyed/unmounted
  → 父 destroyed/unmounted

十一、面试常考 ​

Q1:父子组件生命周期顺序? ​

答:

  • 创建/挂载:父先,但子先完成(created → mounted)
  • 更新:父先,但子先完成(beforeUpdate → updated)
  • 卸载:父先,但子先完成(beforeUnmount → unmounted)

Q2:created 和 mounted 区别? ​

答:

  • created:data/methods/computed 已初始化,但 DOM 还没生成,不能访问 $refs
  • mounted:DOM 已挂载,可以操作 DOM,常用于第三方库初始化
  • 服务端渲染:mounted 不执行

Q3:setup 和 created 哪个先? ​

答:

  • setup() 在 created 之前执行(实际等价)
  • 组合式 API 的 setup 替代了 created/beforeCreate
  • 组合式 API 里不用 beforeCreate/created,改用 setup 本身

面试追问(深化原 Q1-Q3) ​

  • onMounted 在 SSR 中执行吗? 不执行;SSR 阶段只有 setup / onServerPrefetch
  • 父子组件 mounted 顺序为什么反? Vue 先挂载父 → 父 mounted hook → 再递归挂载子;子全部完成才回到父 mounted
  • onUpdated 慎用? 容易死循环(改数据 → 触发 update);需要条件判断或 watch
  • keep-alive 多了哪两个生命周期? onActivated(激活)、onDeactivated(失活)
