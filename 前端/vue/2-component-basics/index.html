Q1:组件全局注册和局部注册怎么选?

Section titled “Q1:组件全局注册和局部注册怎么选?”

答:

  • 全局注册(app.component):任何组件都能用,但 tree-shaking 失效,包体积增大
  • 局部注册(components: { Button }):只在该组件可用,推荐
  • 建议:大多数场景用局部注册,只有真正全局的组件(如 &lt;Icon&gt;)才用全局

Q2:组件设计为什么要遵循单一职责?

Section titled “Q2:组件设计为什么要遵循单一职责?”

答:

  • 一个组件只做一件事 → 复用性高、易测试、易维护
  • 反例:一个 &lt;UserPage&gt; 组件里包含列表 + 详情 + 表单 + 弹窗 → 2000 行无法维护
  • 正例:拆成 &lt;UserList&gt; + &lt;UserDetail&gt; + &lt;UserForm&gt; + &lt;UserModal&gt;

Q3:组件 props 命名要注意什么?

Section titled “Q3:组件 props 命名要注意什么?”

答:

  • 遵循 camelCase(JS) → kebab-case(模板)的 Vue 惯例
  • 布尔类型 props 用 is/has/can 前缀(如 isVisible、hasIcon)
  • 必填项明确,可选给默认值
  • 避免直接改 props(单向数据流)

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • 全局注册还能用吗? 库作者或插件场景可以用(自动注入);业务项目不推荐
  • 单一职责拆分边界? 300 行 / 模板 100 行 / props 5 个以上是常见拆分阈值
  • 改 props 报警告怎么绕过? 用 computed 中转;或 $emit 通知父组件改
  • 组件命名 PascalCase vs 短横线? 模板用短横线(&lt;my-comp&gt;),JS 注册用 PascalCase(MyComp)

📝 小结

Section titled “📝 小结”
  • 组件 = 模板 + 逻辑 + 样式三部分,Vue 的 SFC 把它们放在一个 .vue 文件里。
  • 注册方式:局部注册(推荐,依赖显式)和全局注册(app.component),全局注册适合 UI 库,业务组件应局部注册避免污染。
  • name 选项是递归组件自引用和 &lt;KeepAlive include&gt; 的匹配依据,组件没有 name 会导致缓存失效。
  • 设计原则:容器只负责数据,组件只负责展示,业务组件尽量不直接发请求。
