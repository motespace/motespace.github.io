Q1:SSR vs CSR?

Section titled “Q1:SSR vs CSR?”

答:

  • SSR:首屏快、SEO 好、服务器压力大
  • CSR:交互流畅、服务器简单、首屏慢
  • SSG:静态预渲染,适合博客/文档
  • 现代推荐:SSR + 局部 hydration(Next.js、Nuxt 3)

Q2:为什么 Vue 3 适合 SSR?

Section titled “Q2:为什么 Vue 3 适合 SSR?”

答:

  • renderToString API 标准化
  • 响应式 Proxy 不影响 SSR(只追踪依赖)
  • Suspense 支持异步 SSR
  • tree-shaking 友好,SSR 包体积小

Q3:Nuxt 3 自动导入原理?

Section titled “Q3:Nuxt 3 自动导入原理?”

答:

  • unimport 插件扫描代码,识别变量
  • 自动注入 import 语句
  • 支持组件、composables、utils

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • Nuxt 3 的 nitro 是什么? 跨平台 server(支持 Node/Deno/Workers/Vercel/Cloudflare);Vue 3 官方 SSR 框架
  • SSR 水合不匹配怎么排查? 浏览器 DOM 和 client render 结果不一致;常见于 Date.now() / Math.random() / 浏览器 API
  • useFetch vs useAsyncData? useFetch 是 useAsyncData + $fetch 的封装;前者专用于 HTTP,后者更通用
  • Hydration 优化策略? lazy hydration(&lt;LazyComponent&gt;)、可见性触发(&lt;LazyVisible&gt;)、partial hydration(岛屿架构)
  • 什么时候不用 SSR? 强交互(toB 工具);SEO 不重要的后台;开发资源有限

📝 小结

Section titled “📝 小结”
  • SSR 的收益是首屏快 + SEO 好,代价是服务端渲染开销和 hydration 不一致风险。
  • hydration 不一致的常见原因:渲染期用了随机数、Date.now()、window、localStorage —— 这些要放到 onMounted 或用 useState 延迟。
  • Nuxt 3 提供 useAsyncData/useFetch 做数据预取,definePageMeta 做路由级配置。
  • SSG(静态生成)是 SSG/ISR/SSR 里的最优解(能静态就别服务端渲染)。
