Composable = 用 Composition API 封装的、可复用的、有状态/响应式的逻辑。

3.1 Vue 2 mixin(不优雅)

Section titled “3.1 Vue 2 mixin(不优雅)”

mixin 的问题:

  • 来源不清晰(不知道哪个 mixin 提供了什么)
  • 命名冲突(多个 mixin 同名属性)
  • 隐式依赖(this.xxx 来自哪个 mixin?)

3.2 Vue 3 composable(推荐)

Section titled “3.2 Vue 3 composable(推荐)”

优势:

  • ✅ 显式导入,来源清楚
  • ✅ 无命名冲突
  • ✅ TypeScript 友好
  • ✅ tree-shaking 友好
  • ✅ 容易测试

七、composable vs Pinia

Section titled “七、composable vs Pinia”

何时用哪个:

  • 仅一个组件用 → 普通 ref
  • 多个组件用,共享状态 → Pinia
  • 多个组件用,封装逻辑 → composable

Q1:Composable 和 mixin 区别?

Section titled “Q1:Composable 和 mixin 区别?”

答:

  • mixin (Vue 2):隐式、命名冲突、来源不清
  • composable (Vue 3):显式、TS 友好、tree-shaking
  • composable 是 mixin 的现代化替代

Q2:何时用 composable?

Section titled “Q2:何时用 composable?”

答:

  • 多个组件需要复用同一段逻辑(数据请求、状态、事件监听)
  • 替代 Vue 2 的 mixin
  • 与第三方库(VueUse)集成

Q3:composable 与 Pinia 区别?

Section titled “Q3:composable 与 Pinia 区别?”

答:

  • composable:封装逻辑,可有状态(组件级)
  • Pinia:管理状态(全局级)
  • composable 适合“行为”,Pinia 适合“数据”

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • composable 命名规范? use 前缀;返回响应式数据 + 操作方法的组合
  • composable 能返回 JSX 吗? 可以(返回 render 函数),但不如组件清晰
  • composable 内部能用生命周期吗? 能(onMounted、watch 等),但生命周期注册必须在 setup 同步阶段
  • VueUse 是什么? 常用 composable 集合(useStorage、useMouse、useEventListener),加速开发
  • composable 复用 vs HOC? HOC 是 Vue 2 模式;composable 是 Vue 3 原生方案,无嵌套地狱

📝 小结

Section titled “📝 小结”
  • 组合式函数 = 有状态的函数,内部可以用 ref/computed/watch/onMounted,对外 return 状态和方法。
  • 设计原则:输入明确(参数)、输出明确(返回对象)、副作用要能被调用方控制。
  • useXxx 命名,便于自动导入(unplugin-auto-import)和 lint 识别。
  • 跨组件共享状态不要靠 composable 的模块级变量(会变成隐式单例),应该用 provide/inject 或 Pinia。
