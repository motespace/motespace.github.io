Vue 组件通信(传值) ​

Vue 组件之间的所有通信方式。

  • 父子/祖孙传值(Props/Emit/Slot/Provide)
  • 兄弟/任意层级事件(EventBus / mitt / VueUse)
  • 全局状态管理(Pinia / Vuex)

组件注册方式和设计原则 → 2-component-basics

一、Props(父传子) ​

1.1 基本用法 ​

vue
<!-- 父组件 -->
<script setup>
import Child from './Child.vue'

const user = { name: 'tom', age: 20 }
</script>

<template>
  <Child :user="user" title="用户信息" :count="3" />
</template>

<!-- Child.vue -->
<script setup>
const props = defineProps({
  user: {
    type: Object,
    required: true,
  },
  title: String,
  count: {
    type: Number,
    default: 0,
  },
})
</script>

<template>
  <div>{{ title }}: {{ user.name }}</div>
</template>

1.2 TypeScript 类型 ​

vue
<script setup lang="ts">
interface User {
  id: number
  name: string
}

const props = defineProps<{
  user: User
  title?: string
  count?: number
}>()
</script>

运行时 + 类型(混合):

ts
const props = withDefaults(defineProps<{
  user: User
  title?: string
  count?: number
}>(), {
  title: '默认',
  count: 0,
})

1.3 Props 校验 ​

ts
defineProps({
  // 类型
  status: String,

  // 多个类型
  id: [String, Number],

  // 必填
  email: { type: String, required: true },

  // 默认值(对象/数组必须用工厂函数)
  items: { type: Array, default: () => [] },
  config: { type: Object, default: () => ({}) },

  // 自定义校验
  age: {
    type: Number,
    validator: (value) => value >= 0 && value <= 150,
  },
})

1.4 Props 注意事项 ​

vue
<script setup>
// ❌ 直接修改 props(Vue 会警告)
props.count++

// ✅ 要么 emit 事件让父组件改,要么用 computed
const doubled = computed(() => props.count * 2)
</script>

单向数据流:props 是只读的,父 → 子。

二、Emit(子传父) ​

2.1 基本用法 ​

vue
<!-- Child.vue -->
<script setup>
const emit = defineEmits(['update', 'delete', 'submit'])

// 触发事件
function handleUpdate(value) {
  emit('update', value)
}

function handleDelete() {
  emit('delete', { id: 1 })
}
</script>

<template>
  <button @click="handleUpdate(item)">更新</button>
  <button @click="handleDelete">删除</button>
</template>

<!-- 父组件 -->
<Child @update="onUpdate" @delete="onDelete" @submit="onSubmit" />

2.2 带参数的事件 ​

ts
// 单参数
emit('submit', formData)

// 多个参数
emit('position-change', x, y, z)

// 对象形式
emit('change', { id: 1, value: 'new' })

2.3 TypeScript 类型 ​

ts
// 带类型的 emit
const emit = defineEmits<{
  (e: 'update', value: string): void
  (e: 'delete', payload: { id: number }): void
  (e: 'submit', form: FormData): void
}>()

2.4 验证 emit ​

ts
const emit = defineEmits({
  submit: (form: FormData) => {
    if (!form.email) {
      console.warn('email 必填!')
      return false  // 阻止 emit
    }
    return true
  },
})

2.5 v-model 双向绑定 ​

vue
<!-- CustomInput.vue -->
<script setup>
const props = defineProps(['modelValue'])
const emit = defineEmits(['update:modelValue'])

function onInput(e: Event) {
  emit('update:modelValue', (e.target as HTMLInputElement).value)
}
</script>

<template>
  <input :value="modelValue" @input="onInput" />
</template>

<!-- 父 -->
<CustomInput v-model="searchText" />
<!-- 等价于 -->
<CustomInput :modelValue="searchText" @update:modelValue="searchText = $event" />

多个 v-model(Vue 3+):

vue
<CustomInput v-model:text="name" v-model:age="age" />
vue
<!-- CustomInput.vue -->
<script setup>
defineProps(['text', 'age'])
const emit = defineEmits(['update:text', 'update:age'])
</script>

三、Slot(插槽) ​

3.1 基本用法 ​

vue
<!-- Card.vue -->
<template>
  <div class="card">
    <header v-if="$slots.header">
      <slot name="header" />
    </header>

    <main>
      <slot />  <!-- 默认插槽 -->
    </main>

    <footer v-if="$slots.footer">
      <slot name="footer" />
    </footer>
  </div>
</template>

<!-- 父组件 -->
<Card>
  <template #header>
    <h2>卡片标题</h2>
  </template>

  <p>主要内容</p>

  <template #footer>
    <button>确认</button>
  </template>
</Card>

3.2 作用域插槽 ​

vue
<!-- List.vue -->
<script setup>
defineProps<{ items: Item[] }>()
</script>

<template>
  <ul>
    <li v-for="item in items" :key="item.id">
      <slot :item="item" :index="item.idx" />
    </li>
  </ul>
</template>

<!-- 父组件 -->
<List :items="list">
  <template #default="{ item, index }">
    <div class="custom-row">
      {{ index }}: {{ item.name }}
    </div>
  </template>
</List>

3.3 默认内容 ​

vue
<!-- Button.vue -->
<template>
  <button class="btn">
    <slot>
      默认文字  <!-- 没有传入时显示 -->
    </slot>
  </button>
</template>

3.4 动态插槽(Vue 3+) ​

vue
<template>
  <Card>
    <template v-for="(_, slot) in $slots" #[slot]="props">
      <component :is="slotComponents[slot]" v-bind="props" />
    </template>
  </Card>
</template>

四、Provide / Inject(跨层级传值) ​

4.1 基本用法 ​

vue
<!-- 祖先组件 -->
<script setup>
import { provide, ref } from 'vue'

const theme = ref('dark')
provide('theme', theme)
provide('updateTheme', (newTheme) => {
  theme.value = newTheme
})
</script>

<!-- 任意子组件(无论多深) -->
<script setup>
import { inject } from 'vue'

const theme = inject('theme', 'light')  // 默认 'light'
const updateTheme = inject('updateTheme')
</script>

<template>
  <div :class="theme">...</div>
</template>

4.2 类型化(TS) ​

ts

export interface User {

  name: string

4.3 适用场景 ​

✅ 适合:

  • 主题(深色/浅色)
  • 用户信息(全局)
  • i18n 语言包
  • 复杂表单的状态

❌ 不适合:

  • 普通父子组件传值 → 用 props/emit
  • 全局状态管理 → 用 Pinia

五、跨组件状态共享(兄弟 / 任意层级) ​

Props / Emit / Provide-Inject 处理了 父子 / 跨层级 的传值, 但还有一类场景 —— 任意组件之间(兄弟、跨多层级、跟父子无关的全局)—— 需要单独的处理方式。

5.1 现有方案的局限 ​

方案局限
Props单向,只能父子传
Emit子传父,只能父子
Slot内容分发,不是数据共享
Provide / Inject跨层级,但同一 source 只能注入一份

5.2 真实场景 ​

        App
       /   \
     A       B    ← 兄弟组件互传(A 改 → B 跟着变)
    / \     / \
   C   D   E   F  ← 任意层级之间共享(用户信息、主题、购物车)

典型需求:

  • 兄弟组件互传:列表选中 → 详情更新
  • 全局状态:登录用户、主题色、语言、购物车数量
  • 跨任意层级的事件总线:通知 toast 弹出、跨页面刷新

六、EventBus(事件总线) ​

EventBus = 一个全局的事件中心,任何组件可以 发事件 或 订阅事件, 适合"通知类"场景(不关心谁响应)。

6.1 Vue 2 经典实现 —— new Vue() ​

Vue 2 直接利用 Vue 实例作为事件总线,零依赖。

js
// event-bus.js
import Vue from 'vue'
export const EventBus = new Vue()
vue
<!-- 发送方:ComponentA.vue -->
<script>
import { EventBus } from '@/utils/event-bus'

export default {
  methods: {
    handleClick() {
      EventBus.$emit('user-login', { name: '张三' })
    }
  }
}
</script>
vue
<!-- 接收方:ComponentB.vue(任意位置) -->
<script>
import { EventBus } from '@/utils/event-bus'

export default {
  mounted() {
    EventBus.$on('user-login', (user) => {
      console.log('收到登录:', user)
    })
  },
  beforeDestroy() {
    // ⚠️ 必须手动解绑,否则内存泄漏
    EventBus.$off('user-login')
  }
}
</script>

优缺点:

✅ 优点❌ 缺点
零依赖,接入快全局单例,事件流难追踪
简单直观必须手动 $off,否则内存泄漏
适合一次性通知字符串事件名,TypeScript 无法校验
$on/$off 散落在各组件,代码组织散乱

6.2 Vue 3 为什么移除 $on / $off? ​

Vue 3 彻底移除了实例的 $on / $off / $once,官方在 Vue 3 RFC 中给出的原因:

  1. 代码组织变差 —— 事件订阅逻辑散落在各组件的 mounted,缺少集中管理
  2. 类型支持弱 —— 字符串事件名,TypeScript 完全无法校验
  3. 与新方案重叠 —— Provide/Inject + 响应式数据已经能覆盖大部分场景
  4. SSR 不友好 —— $on 注册的事件在 SSR 期间会丢失,水合后需要重新订阅

6.3 Vue 3 替代方案 ​

方案一:mitt(最轻量,~200 bytes) ​

bash
npm install mitt
ts
// utils/event-bus.ts
import mitt, { Emitter } from 'mitt'

// ✅ 类型化事件清单
type Events = {
  'user-login': { name: string }
  'logout': void
  'theme-change': 'light' | 'dark'
}

export const emitter: Emitter<Events> = mitt()
vue
<!-- 发送方 -->
<script setup lang="ts">
import { emitter } from '@/utils/event-bus'
emitter.emit('user-login', { name: '张三' })
</script>
vue
<!-- 接收方 -->
<script setup lang="ts">
import { onMounted, onBeforeUnmount } from 'vue'
import { emitter } from '@/utils/event-bus'

function onLogin(user: { name: string }) {
  console.log(user)
}

onMounted(() => emitter.on('user-login', onLogin))
onBeforeUnmount(() => emitter.off('user-login', onLogin))  // ⚠️ 别忘解绑
</script>

方案二:VueUse useEventBus(自动清理 ⭐ 推荐) ​

bash
npm install @vueuse/core
ts
// 任意组件中
import { useEventBus } from '@vueuse/core'

const bus = useEventBus<string>('user-login')

// 发送
bus.emit('张三')

// 订阅 —— onUnmounted 自动调用返回值清理 ✅
const stop = bus.on((val) => {
  console.log(val)
})

// 手动停止
stop()

SSR✅✅

6.4 该不该用 EventBus? ​

⚠️ 2024+ 的官方建议:能用 Pinia / Provide+reactive 解决的,不要用 EventBus。

场景推荐方案
全局状态(用户/主题/购物车)Pinia
中小型全局状态Provide + reactive
一次性的"通知"事件(toast 弹出)mitt / VueUse
父子组件通信Props + Emit(永远第一选择)

七、状态传值(全局状态管理) ​

当多个组件需要共享同一份数据且需要响应式更新,就该用状态管理库。

7.1 方案一:Provide + reactive(轻量,无需第三方) ​

适合中小型项目 / 主题切换 / 简单全局数据。

vue
<!-- App.vue -->
<script setup lang="ts">
import { provide, reactive } from 'vue'

const state = reactive({
  user: { name: '游客', role: 'guest' },
  theme: 'light',
  locale: 'zh-CN'
})

</script>

// stores/user.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useUserStore = defineStore('user', () => {
  // state
  const name = ref('游客')
  const role = ref<'guest' | 'admin'>('guest')

  // getters
  const isAdmin = computed(() => role.value === 'admin')

    role.value = newRole

    role.value = 'guest'

  return { name, role, isAdmin, login, logout }
})

八、Vue 2 vs Vue 3 对比 ​

8.1 Props 定义 ​

js
// Vue 2
export default {
  props: {
    title: { type: String, required: true },
    count: { type: Number, default: 0 },
  },
}

  title: { type: String, required: true },

  title: string
  count?: number

Vue 3 优势:

  • 无需 this

8.2 Emit 定义 ​

js
// Vue 2
export default {
  emits: ['update', 'delete'],
  methods: {
    handleUpdate() {
      this.$emit('update', value)  // this 访问
    },
  },
}

// Vue 3 - 组合式
<script setup>
const emit = defineEmits(['update', 'delete'])
function handleUpdate(value) {
  emit('update', value)  // 直接调用
}

// TS 类型化
const emit = defineEmits<{
  (e: 'update', value: string): void
  (e: 'delete', id: number): void
}>()
</script>

Q1:为什么 Vue 3 移除 $on / $off? ​

常见追问 ​

Q: Pinia 为什么去掉 mutation?

mutation 最初是为了支持 DevTools 时间旅行（同步记录 state 变更）。 Pinia 通过 Proxy 拦截所有 state 修改，能记录更细粒度的变化，无需显式 mutation。 代码更简洁：store.count++ 直接修改即可，DevTools 仍能追踪。

Q: 怎么从 Vuex 迁移到 Pinia?

  1. 每个 Vuex module → 一个独立 Pinia store
  2. mutations 内容合并到 actions（或者直接删除）
  3. getters 直接保留（Pinia getter 写法一样）
  4. state.x.y → useStore().y（自动扁平化，少一层）
ts
// Vuex: store.state.user.name
// Pinia: useUserStore().name   <- 扁平化

Q: Pinia 怎么用 SSR（Nuxt / Next 集成）?

ts
// nuxt 3 自动集成：@pinia/nuxt 模块
export default defineNuxtConfig({ modules: ['@pinia/nuxt'] })

// 自动在每个请求创建独立 store 实例（避免状态污染）
// 自动从 window.__PINIA__ 水合到客户端

→ Vue 3 新项目默认 Pinia；Vue 2 老项目继续用 Vuex 3。

Q3:Provide + reactive 和 Pinia 的区别? ​

维度Provide + reactivePinia
适用规模中小型全局态大型 / 多人协作
DevTools❌✅ 时间旅行
SSR需手动处理✅ 自动序列化
持久化插件需手写✅ pinia-plugin-persistedstate
学习成本低中

→ 简单主题切换 / 用户信息用 Provide;复杂业务用 Pinia。
