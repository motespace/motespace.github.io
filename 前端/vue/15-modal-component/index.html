用Vue3.0 写过组件吗？如果想实现一个 Modal你会怎么设计？

一、组件设计

Section titled “一、组件设计”

组件就是把图形、非图形的各种逻辑均抽象为一个统一的概念（组件）来实现开发的模式

现在有一个场景，点击新增与编辑都弹框出来进行填写，功能上大同小异，可能只是标题内容或者是显示的主体内容稍微不同

这时候就没必要写两个组件，只需要根据传入的参数不同，组件显示不同内容即可

这样，下次开发相同界面程序时就可以写更少的代码，意义着更高的开发效率，更少的 Bug 和更少的程序体积

Section titled “二、需求分析”

实现一个Modal组件，首先确定需要完成的内容：

  • 遮罩层

  • 标题内容

主体内容需要灵活，所以可以是字符串，也可以是一段 html 代码

特点是它们在当前vue实例之外独立存在，通常挂载于body之上

除了通过引入import的形式，我们还可通过API的形式进行组件的调用

还可以包括配置全局样式、国际化、与typeScript结合

面试常考

Section titled “面试常考”

Q1:Modal 组件设计要考虑哪些点?

Section titled “Q1:Modal 组件设计要考虑哪些点?”

答:

  1. 可访问性:焦点陷阱、ESC 关闭、aria-modal、role=“dialog”
  2. 遮罩:点击遮罩是否关闭(可配置)
  3. 滚动锁:打开时锁 body 滚动(避免背景滚动)
  4. Portal 渲染:<Teleport to="body"> 避免父组件 overflow: hidden 影响
  5. 动画:进入/离开过渡(<Transition>)
  6. 嵌套管理:多层 Modal 的 z-index 递增

Q2:Teleport 为什么必要?

Section titled “Q2:Teleport 为什么必要?”

答:

  • Modal 视觉上在最顶层(不被父组件 z-index/overflow 影响)
  • 但逻辑上仍属父组件树(emit、provide、slots 正常通信)
  • <Teleport to="body" :disabled="!usePortal"> 可关闭传送
  • React 等价物:createPortal

Q3:焦点陷阱怎么实现?

Section titled “Q3:焦点陷阱怎么实现?”

答:

  • 打开时记录 document.activeElement,关闭时恢复
  • 监听 keydown(Tab/Shift+Tab),在首个/末个可聚焦元素间循环
  • 库推荐:focus-trap / focus-trap-react;或自己写 useFocusTrap
  • 注意:动态内容更新时重新计算可聚焦元素

Q4:Modal 状态放父组件还是组件内?

Section titled “Q4:Modal 状态放父组件还是组件内?”

答:

  • 组件内:UI 状态(loading、disabled),不外露
  • 父组件:业务状态(表单数据、回调结果)
  • 用 defineExpose 暴露 imperative 方法(.open()、.close())
  • 用 v-model:visible 双向绑定显隐

📝 小结

Section titled “📝 小结”
  • Modal 设计的核心是状态提升和事件约定:visible 用 v-model 双向绑定,提交/取消用事件回传。
  • 锁定滚动用 overflow: hidden 配合滚动条补偿(padding-right),否则会出现内容跳动。
  • Esc 关闭和点击遮罩关闭要可配置 —— 强制用户确认的场景不能点遮罩关。
  • 焦点管理是关键:打开时聚焦第一个可交互元素,关闭时焦点归还给触发按钮(无障碍要求)。
