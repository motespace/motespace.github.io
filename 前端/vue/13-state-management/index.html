Vue 状态管理:Pinia / Vuex

一、为什么需要状态管理

Section titled “一、为什么需要状态管理”

Vue 组件间共享数据,常见需求:

  • 用户登录信息(全局)
  • 购物车(跨页面)
  • 主题(全局)
  • WebSocket 连接状态

不用状态管理的问题:

  • 页面间传值麻烦
  • 数据不同步
  • 难以追踪变化

Section titled “二、Pinia(推荐)”

Q1:Pinia 和 Vuex 区别?

Section titled “Q1:Pinia 和 Vuex 区别?”

答:

  • Pinia:Vue 3 推荐,API 简洁,无 mutations,完整 TS 支持
  • Vuex:老项目维护,模块化手动
  • 新项目用 Pinia,Vuex 维护模式

Q2:状态管理什么时候用?

Section titled “Q2:状态管理什么时候用?”

答:

  • 跨组件/跨页面共享数据 → Pinia
  • 简单跨层级传值 → provide/inject
  • 组件内复用逻辑 → composable
  • URL 状态(搜索、分页) → useUrlState

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • Pinia 为什么无 mutations? Composition API 时代 mutations 冗余;action 直接改 state,更简洁
  • store 怎么拆? 按业务域(useUserStore、useCartStore),避免单一大 store
  • storeToRefs 有什么用? 解构 store 时保持响应性;const { name } = storeToRefs(userStore)
  • getter 缓存? computed 自动缓存,依赖不变不重算;等价于 Vuex getters
  • Pinia 持久化原理? pinia-plugin-persistedstate 通过订阅 store,在变更时同步到 localStorage

九、Vue 2 vs Vue 3 状态管理对比

Section titled “九、Vue 2 vs Vue 3 状态管理对比”

9.1 Vuex 3(Vue 2 时代) vs Vuex 4(Vue 3 时代)

Section titled “9.1 Vuex 3(Vue 2 时代) vs Vuex 4(Vue 3 时代)”

变化:

  • 不再 Vue.use(Vuex),改 app.use(store)
  • state 改为函数返回(避免共享)
  • mutations / actions API 一致

9.2 Vuex 4 vs Pinia(关键决策点)

Section titled “9.2 Vuex 4 vs Pinia(关键决策点)”

Pinia 优势:

  • 无 mutations(简化流程)
  • 完整 TS 支持
  • 模块化自动(每个 store 一个文件)
  • Composition 风格(类 setup)

📝 小结

Section titled “📝 小结”
  • Pinia 是 Vue 3 官方推荐,相比 Vuex:去掉了 mutations、TS 友好、体积小、支持多个 store 互用。
  • 状态分类决定工具:组件内部用 ref/reactive,跨组件用 provide/inject,跨页面用 Pinia,服务端数据用 TanStack Query/SWR。
  • 不要把服务端数据塞进 Pinia —— 会有一致性问题(缓存、过期、重新验证),那是 Query 类库的职责。
  • Pinia 的 store 要按业务域拆,不要做成一个全局大 store。
