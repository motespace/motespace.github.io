React Scheduler 调度详解

一、为什么需要 Scheduler

Section titled “一、为什么需要 Scheduler”

React 18+ 的 Concurrent Mode(并发模式)让 React 能主动中断渲染,优先处理更紧急的任务(如用户输入)。

Scheduler 就是实现这个调度能力的核心模块——独立的库,后来被 React 团队剥离出来开源。

二、调度模型

Section titled “二、调度模型”

2.1 五档优先级

Section titled “2.1 五档优先级”

调度原则:

  • 高优先级任务插队打断低优先级
  • 同优先级任务先进先出
  • 低优先级可以被饿死(避免无限等待)

2.2 时间切片(Time Slicing)

Section titled “2.2 时间切片(Time Slicing)”

5ms 时间片的来源:研究显示,100ms 内响应用户感知“流畅”,所以每片 5ms × 多个片 ≈ 50ms 内能响应。

八、面试常考

Section titled “八、面试常考”

Q1:React 18 Concurrent Mode 是什么?

Section titled “Q1:React 18 Concurrent Mode 是什么?”

答:React 能主动中断渲染的机制。

  • 通过 Scheduler 调度任务
  • 高优先级任务插队(用户输入、点击)
  • 低优先级任务可中断(数据加载、列表渲染)
  • 不影响用户体验(用户感觉不到中断)

Q2:useTransition 和 setTimeout(fn, 0) 区别?

Section titled “Q2:useTransition 和 setTimeout(fn, 0) 区别?”

答:

  • setTimeout(fn, 0):至少延迟 4ms,无法中断
  • useTransition:调度系统内,可以被高优先级打断
  • useTransition 更可控,适合 UI 优化

Q3:React 怎么知道有用户输入?

Section titled “Q3:React 怎么知道有用户输入?”

答:

  • 浏览器原生 isInputPending() API(Chrome 87+)
  • 事件分发时识别事件类型(连续 vs 离散)
  • 渲染时检查 shouldYield,让出主线程

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • Concurrent Mode 和 Concurrent Rendering 区别? 前者是能力(可中断调度),后者是开启后的具体渲染模式
  • useTransition 内部机制? 把 setState 包到 startTransition,标记为非紧急;调度器降权 + 不阻塞输入
  • isInputPending 浏览器支持? Chrome 87+ 原生支持;其他浏览器降级到事件类型判断
  • MessageChannel 为什么不用 setTimeout? setTimeout 嵌套 4ms 节流;MessageChannel 是宏任务,无节流

Q4: 调度优先级怎么定?

Section titled “Q4: 调度优先级怎么定?”

答:

  • 5 个固定 lane(用户输入 > 动画 > 默认 > transition > 后台)
  • 事件分发时分配初始 lane;transition 内 setState 走低 lane
  • Lane 用二进制位,可“共存”多个(如 transition + input 同时有效)

Q5: Scheduler 是怎么抢断的?

Section titled “Q5: Scheduler 是怎么抢断的?”

答:

  • 每帧执行 workLoop,处理前调 shouldYield() 检查剩余时间(< 5ms)
  • 是就保存当前 workInProgress,return null 让出主线程
  • 浏览器执行 paint/事件后,下次宏任务续跑,从头开始(用 alternate 找上次的 workInProgress)

📝 小结

Section titled “📝 小结”
  • Scheduler 负责决定何时执行哪个任务,React 负责「要做什么」,两者分离。
  • 它用 MessageChannel 模拟 setTimeout 但能拿到更高优先级,并且有 isInputPending 主动检查用户输入。
  • 并发特性的本质是「把工作切成可中断的片段,按优先级调度」。
  • 和 requestIdleCallback 的区别:Scheduler 不依赖浏览器支持,在 React 内核里自己实现。
