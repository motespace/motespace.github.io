Q1: 你 React 项目遇到过什么性能问题？怎么定位？

  • 解决：React.memo + useCallback + useMemo

Q2: 你怎么用 React 18 的并发特性？

Section titled “Q2: 你怎么用 React 18 的并发特性？”

答：

  • 自动批处理（React 18 默认）
  • useTransition（搜索框 / 路由切换）
  • Suspense（流式 SSR）

Q3: React Server Components 了解吗？

Section titled “Q3: React Server Components 了解吗？”

答：服务端渲染组件，零 JS 到浏览器。Next.js 13+ 的 App Router 默认用 RSC。

Q4: 你们状态管理用什么？Redux 还是 Zustand？

Section titled “Q4: 你们状态管理用什么？Redux 还是 Zustand？”

答：Zustand（轻量 + 性能 + 不需要 boilerplate）。Redux 在大型项目用 RTK Query 处理服务端状态。

Q5: React 19 你们用了吗？

Section titled “Q5: React 19 你们用了吗？”

答：新项目在尝试，老项目暂不动 React。use hook 是杀手锏，简化异步组件写法。

📝 小结

Section titled “📝 小结”
  • 真实项目里 React 的难点不在 API,而在状态边界和渲染成本。
  • 状态按「谁能修改」划分:组件内部 state → 跨组件 props → 跨页面 store → 服务端数据(交给 Query 类库)。
  • 性能三板斧:减少 state 层级、状态下沉、列表虚拟化。
  • 自定义 Hook 封装业务逻辑时,要把依赖和清理做对,否则会出现数据竞争和内存泄漏。
