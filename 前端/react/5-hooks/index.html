1.1 为什么需要链表

Section titled “1.1 为什么需要链表”

React 用链表记录每个组件的 hooks，调用顺序必须稳定。

每次渲染：

  1. 重新执行函数组件
  2. 按调用顺序遍历 hooks 链表
  3. 匹配本次 hook 调用和上次的状态

Q1: 为什么 Hooks 不能写在 if 里？

Section titled “Q1: 为什么 Hooks 不能写在 if 里？”

答：React 用链表记录 hooks，调用顺序必须稳定。条件调用导致链表对不上，state 错乱。

Q2: useEffect 和 useLayoutEffect 区别？

Section titled “Q2: useEffect 和 useLayoutEffect 区别？”

答：

  • useEffect：浏览器绘制后执行（异步）
  • useLayoutEffect：DOM 更新后、绘制前执行（同步）

Q4: React.memo + useCallback 是不是必须的？

Section titled “Q4: React.memo + useCallback 是不是必须的？”

答：不是。如果子组件不昂贵，过度 memo 反而更慢（比对 + hooks 自身开销）。

Q5: useMemo 和 useCallback 怎么选？

Section titled “Q5: useMemo 和 useCallback 怎么选？”

答：

  • useMemo：缓存计算结果
  • useCallback：缓存函数引用（等价于 useMemo(fn, deps)）

Q6: React 19 的 use hook 解决了什么？

Section titled “Q6: React 19 的 use hook 解决了什么？”

答：

  • 可以在条件里调用（不像 useContext）
  • 支持 Promise（替代 useEffect + setState 写异步组件）

面试追问(深化原 Q1-Q6)

Section titled “面试追问(深化原 Q1-Q6)”
  • 闭包陷阱根源? 函数组件每次 render 创建新闭包;setState 引用的是本次 render 的 state;setState(prev => ...) 或 useRef 解决
  • useLayoutEffect 必用场景? DOM 测量(避免抖动)、防闪烁(同步执行在 paint 前)
  • useEffect 依赖能省? 用到 setState dispatch / ref 引用稳定可不写;但 ESLint 警告需手动禁用
  • useMemo 滥用危害? 本身有“存上次结果”的开销(数组对比 + 缓存内存);只在大计算或 memo 组件 prop 时用
  • hooks 为什么不能在条件里调? hooks 链表按调用顺序索引;条件调用破坏顺序 → state 对错位
  • use hook 优势? 条件调用(突破 hooks 规则);读 Promise(替代 useEffect + setState 异步组件)

Q7: useRef 拿 DOM 的原理?

Section titled “Q7: useRef 拿 DOM 的原理?”

答:

  • 每次 render 同一个 ref 对象 ({ current: ... })
  • commit 阶段 React 把 DOM 节点赋值给 ref.current
  • 函数组件需要 forwardRef 透传 ref

Q8: useImperativeHandle 何时用?

Section titled “Q8: useImperativeHandle 何时用?”

答:

  • 父组件需要调用子组件的“非 props 方法”(聚焦、滚动、播放)
  • 必须配合 forwardRef
  • 大多数场景 props 回调(onReady)更声明式

📝 小结

Section titled “📝 小结”
  • Hooks 用链表存储,每个组件实例一条,render 时按顺序遍历匹配。
  • 所以 Hooks 不能写在条件里 —— 调用顺序变了就匹配错,状态会串位。
  • useEffect 是副作用(订阅、定时器、请求),不是「生命周期」;它会等 DOM 提交后异步执行,清理函数在下一次 effect 前调用。
  • useLayoutEffect 同步执行,在 DOM 更新前跑,用于测量布局,默认用 useEffect 避免阻塞。
