六、面试常考

Q1:ErrorBoundary 为什么必须是 class 组件?

Section titled “Q1:ErrorBoundary 为什么必须是 class 组件?”

答:

  • React 17 没提供 hook 版 API
  • class 组件的 componentDidCatch + getDerivedStateFromError 是唯一方式
  • React 19 实验性提供 useErrorBoundary hook

Q2:ErrorBoundary 捕获不到哪些错误?

Section titled “Q2:ErrorBoundary 捕获不到哪些错误?”

答:

  • ❌ 事件处理器中的错误(try-catch)
  • ❌ 异步代码(setTimeout、Promise)
  • ❌ 服务端渲染(SSR)
  • ❌ 自身组件的错误
  • ❌ Suspense 异步组件的加载错误(需用其他方式)

Q3:Suspense 工作原理?

Section titled “Q3:Suspense 工作原理?”

答:

  • 组件抛出 Promise(异步)
  • Suspense 捕获这个 Promise
  • 显示 fallback(loading)
  • Promise resolve 后,显示真实组件

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • React 19 useErrorBoundary hook? 函数组件也能写 ErrorBoundary;但仍推荐 class(更稳、生态成熟)
  • 自定义 fallback 注意事项? 必须能独立渲染;不能依赖外部 state(可能崩)
  • Suspense 流式 SSR 原理? 嵌套 Suspense → 分块流式返回 HTML;用户先看到 shell,再 hydrate 子树
  • 错误边界能捕获 Promise reject 吗? 不能;Promise 内部用 try-catch 或 .catch()
  • ErrorBoundary 必须放在哪一层? 在“安全边界”外层(避免错误冒泡到整页崩溃)

Q4: 怎么测试 ErrorBoundary?

Section titled “Q4: 怎么测试 ErrorBoundary?”

答:

  • 用 react-testing-library 抛错组件 + render
  • 断言 fallback UI 出现
  • 用 console.error mock 避免污染测试输出
  • 测三种情况:正常渲染、错误时 fallback、错误恢复

📝 小结

Section titled “📝 小结”
  • Error Boundary 只能捕获子树渲染期的错误,捕获不到:事件回调、异步/Promise、SSR、服务端渲染、自身渲染错误——这些需要 try/catch 或 Error Boundary 无法覆盖的方案。
  • React 18 前 Error Boundary 必须是 class 组件(因为没有 hook 版的 componentDidCatch),React 19 起有实验性 hook 方案。
  • Suspense 的本质是挂起而不是 loading 布尔值:组件 throw 一个 promise,React 渲染最近边界的 fallback,promise resolve 后自动重渲染。
  • 边界要小:边界越大,挂起时白屏范围越大;边界太小则 fallback 闪烁。路由级是常用折中。
  • 错误边界 + Suspense 要配对使用:错误交给 ErrorBoundary,加载态交给 Suspense,两者职责不要混。
  • 面试追问「怎么测试 Error Boundary」:渲染一个会抛错的子组件,断言 fallback 出现且没有把整个应用打挂。
