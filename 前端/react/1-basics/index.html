Section titled “1. JSX 语法”

JSX 的本质：是 React.createElement 的语法糖。返回的是“虚拟 DOM 元素”（一个普通 JS 对象），不是真正的 DOM。

3.3 useRef

Section titled “3.3 useRef”

useRef vs useState：

  • useState：值变化触发重渲染。
  • useRef：值变化不触发重渲染，用于存储“不影响 UI 的值”。

3.4 useMemo / useCallback

Section titled “3.4 useMemo / useCallback”

什么时候用 useMemo / useCallback？

  • 计算昂贵（如大列表过滤、复杂对象构造）。
  • 作为 prop 传给被 React.memo 包裹的子组件。
  • 作为其他 Hook 的依赖。

不要过度优化：简单计算直接写，每次 useState 拿到的对象已经是新引用，再 useMemo 反而浪费。

5.2 key 的作用

Section titled “5.2 key 的作用”

为什么 key 重要：React 用 key 识别哪些元素“同一个”。删除/插入时：

  • 没有 key：React diff 算法按顺序对比，可能错误地复用旧组件实例。
  • 有稳定 key：React 能精确识别每个元素的位置。

Section titled “6. 错误边界（Error Boundary）”

React 组件抛错会导致整个应用崩溃。错误边界能捕获子树的错误。

9. 常见面试题

Section titled “9. 常见面试题”
题目 答案要点
受控组件 vs 非受控组件 受控：value + onChange；非受控：ref
useEffect 依赖数组规则 用了什么变量就写什么；否则用 ESLint 插件提示
useEffect 和 useLayoutEffect 区别 useEffect 异步（不阻塞渲染）；useLayoutEffect 同步（阻塞，DOM 更新后立即执行）
key 的作用 帮助 React 识别元素，列表渲染必须稳定
受控组件的 input 如何不报警告 value 配合 onChange，或者用 defaultValue（非受控）
React 事件机制 合成事件，委托到 root，onClick 等 camelCase
React 18 新特性 concurrent mode / automatic batching / Suspense / useId / useTransition

面试追问

Section titled “面试追问”
  • 受控 vs 非受控项目选哪个? 默认受控(状态可见、便于验证);非受控用于性能敏感 + 简单一次性输入
  • useEffect 依赖能省略吗? setState dispatch / ref 引用稳定可不写;但 ESLint 警告需手动禁用或拆 useRef
  • useLayoutEffect 必用场景? DOM 测量(避免抖动)、防闪烁(同步执行在 paint 前)
  • 合成事件为什么挂 root? 旧版挂 document 导致多 React 根互相影响;改 root 后可多根共存 + 嵌套安全
  • key 稳定性的判断? 数据库 id;index 在重排/过滤时错位 → 组件 state 残留
  • React 18 升级最大坑? Strict Mode 下 effect 双调用,会暴露非幂等副作用;Suspense fallback 时机微调

10. 真实项目踩过的坑

Section titled “10. 真实项目踩过的坑”
  1. useState 拿到旧值：连续多次 setState 用函数式更新。
  2. useEffect 死循环：依赖没写全 / 改 state 没判断。
  3. 组件无限渲染：函数组件里直接调用 setState。
  4. stale closure：useEffect 里拿到旧 state，加到依赖数组里。
  5. key 用 index：列表顺序变化时状态错乱。
  6. React.memo 不生效：传的函数引用每次都新创建，必须配合 useCallback。
  7. 大表单卡顿：用 react-hook-form 替代受控组件。

📝 小结

Section titled “📝 小结”
  • React 的核心心智模型是UI = f(state),单向数据流让渲染可预测。
  • 组件 = 函数,Props 是参数,State 是 Hook 里的数据;渲染是批量 + 异步的(React 18 自动批处理)。
  • Hooks 解决的是「逻辑复用」和「按关注点组织」,不是「类组件的替代品」。
  • 性能优化的核心是减少不必要的重渲染,而不是微优化。
