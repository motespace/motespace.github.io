React 状态管理 ​

状态管理是 React 应用的核心问题。本文从最简单的 useState 讲起，覆盖 Context、Redux、Zustand、MobX，按"够用就好"的顺序排列。

1. 状态分类（先想清楚再选工具） ​

在选状态管理工具之前，先把状态分清楚：

类别例子推荐方案
局部状态表单输入、弹窗显隐useState / useReducer
跨组件状态主题、当前用户、购物车Context / Zustand
服务端状态列表数据、详情数据React Query / SWR
全局复杂状态多模块协同、撤销重做Redux Toolkit / MobX

常见误区：把所有状态都扔进 Redux / Zustand，结果一个表单 onChange 也触发整个 store 更新。

2. useState：基础款 ​

tsx
import { useState } from 'react'

function Counter() {
  const [count, setCount] = useState(0)

  // ❌ 直接基于当前值更新，可能丢更新（异步场景）
  const handleClick = () => {
    setCount(count + 1)
    setCount(count + 1)  // 两次都基于旧值，最终只 +1
  }

  // ✅ 函数式更新：基于最新 state
  const handleClickSafe = () => {
    setCount(c => c + 1)
    setCount(c => c + 1)  // 最终 +2
  }
}

setState 的关键点：

  • 不会立即更新（批处理）。
  • 对象 / 数组必须返回新引用（不可变更新）。
  • 函数式更新获取最新值。

3. useReducer：复杂状态用 reducer 管 ​

当状态有多个子值、依赖前一个状态、或者更新逻辑复杂时，用 useReducer 替代多个 useState。

tsx
import { useReducer } from 'react'

type State = {
  count: number
  step: number
}

type Action =
  | { type: 'increment' }
  | { type: 'decrement' }
  | { type: 'setStep'; step: number }
  | { type: 'reset' }

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'increment': return { ...state, count: state.count + state.step }
    case 'decrement': return { ...state, count: state.count - state.step }
    case 'setStep':   return { ...state, step: action.step }
    case 'reset':     return { count: 0, step: 1 }
    default: return state
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0, step: 1 })

  return (
    <>
      <span>{state.count}</span>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'decrement' })}>-</button>
      <input
        type="number"
        value={state.step}
        onChange={(e) => dispatch({ type: 'setStep', step: Number(e.target.value) })}
      />
      <button onClick={() => dispatch({ type: 'reset' })}>重置</button>
    </>
  )
}

useReducer 适用场景：

  • 多个状态互相依赖。
  • 状态更新有多种类型（增删改查）。
  • 想把所有更新逻辑集中到 reducer 里测。

4. Context：跨组件传值 ​

Context 解决"props drilling"（父 → 子 → 孙 → 曾孙一层层传）问题。

tsx
import { createContext, useContext, useState, ReactNode } from 'react'

// 1. 创建 Context
const ThemeContext = createContext<{
  theme: 'light' | 'dark'
  toggle: () => void
}>({ theme: 'light', toggle: () => {} })

// 2. Provider 组件
function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<'light' | 'dark'>('light')
  const toggle = () => setTheme(t => (t === 'light' ? 'dark' : 'light'))

  return (
    <ThemeContext.Provider value={{ theme, toggle }}>
      {children}
    </ThemeContext.Provider>
  )
}

// 3. 自定义 hook 简化使用
const useTheme = () => useContext(ThemeContext)

// 4. 在任意子组件使用
function ThemedButton() {
  const { theme, toggle } = useTheme()
  return <button onClick={toggle}>当前主题：{theme}</button>
}

Context 性能陷阱：

tsx
// ❌ Provider value 用对象字面量：每次渲染都创建新引用，所有消费者都重渲染
<ThemeContext.Provider value={{ theme, toggle }}>
  {children}
</ThemeContext.Provider>

// ✅ 用 useMemo 锁住引用
const value = useMemo(() => ({ theme, toggle }), [theme])
<ThemeContext.Provider value={value}>
  {children}
</ThemeContext.Provider>

Context 不适合频繁更新的状态：比如输入框 onChange 触发更新 → 所有消费者组件都重渲染。这种情况要用状态管理库（Zustand / Redux）。

5. Zustand：轻量级状态管理（推荐） ​

Zustand 是我实际项目用得最多的状态库。优点：

  • API 极简（5 分钟上手）。
  • 不需要 Provider，直接 create。
  • 性能好，组件只订阅自己用到的 slice。
  • TypeScript 友好。
tsx
import { create } from 'zustand'
import { devtools, persist } from 'zustand/middleware'

interface UserState {
  user: User | null
  token: string | null
  setUser: (user: User | null) => void
  setToken: (token: string | null) => void
  logout: () => void
}

const useUserStore = create<UserState>()(
  devtools(
    persist(
      (set) => ({
        user: null,
        token: null,
        setUser: (user) => set({ user }),
        setToken: (token) => set({ token }),
        logout: () => set({ user: null, token: null }),
      }),
      { name: 'user-storage' },  // localStorage 持久化
    ),
  ),
)

// 使用：只订阅需要的字段，组件不会因为其他字段变化而重渲染
function Header() {
  const user = useUserStore((s) => s.user)         // 只订阅 user
  const logout = useUserStore((s) => s.logout)     // 方法不会变
  return <div onClick={logout}>{user?.name}</div>
}

// 组件外使用（不需要 hook 上下文）
function ApiClient() {
  const token = useUserStore.getState().token      // 同步读取
  return fetchWithToken(token)
}

Zustand 关键模式：

tsx
// 1. selector 函数：避免无关字段变化触发重渲染
const count = useStore((s) => s.items.length)

// 2. shallow 比较：选择多个字段时
import { shallow } from 'zustand/shallow'
const { name, age } = useStore((s) => ({ name: s.name, age: s.age }), shallow)

// 3. 异步 action
const useStore = create((set) => ({
  user: null,
  fetchUser: async (id: string) => {
    const res = await api.getUser(id)
    set({ user: res.data })
  },
}))

6. Redux Toolkit（RTK）：复杂项目的标准方案 ​

适合大型项目（多个团队协作、状态变更需要追溯、撤销/重做）。createSlice 把 action 和 reducer 写在一起，比传统 Redux 简洁很多。

tsx
// store/counterSlice.ts
import { createSlice, PayloadAction } from '@reduxjs/toolkit'

interface CounterState {
  value: number
}

const initialState: CounterState = { value: 0 }

const counterSlice = createSlice({
  name: 'counter',
  initialState,
  reducers: {
    increment: (state) => {
      state.value += 1   // RTK 用 Immer，可以"直接修改"state
    },
    incrementBy: (state, action: PayloadAction<number>) => {
      state.value += action.payload
    },
  },
})

export const { increment, incrementBy } = counterSlice.actions
export default counterSlice.reducer

// store/index.ts
import { configureStore } from '@reduxjs/toolkit'
import counterReducer from './counterSlice'

export const store = configureStore({
  reducer: { counter: counterReducer },
})

// 组件中使用
import { useSelector, useDispatch } from 'react-redux'

function Counter() {
  const value = useSelector((s: RootState) => s.counter.value)
  const dispatch = useDispatch()

  return (
    <button onClick={() => dispatch(increment())}>
      count: {value}
    </button>
  )
}

RTK Query：内置的数据请求方案

tsx
// store/api.ts
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react'

export const api = createApi({
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  endpoints: (builder) => ({
    getUser: builder.query<User, string>({
      query: (id) => `users/${id}`,
    }),
    getUsers: builder.query<User[], void>({
      query: () => 'users',
    }),
  }),
})

export const { useGetUserQuery, useGetUsersQuery } = api

// 组件中
function UserProfile({ id }: { id: string }) {
  const { data, error, isLoading } = useGetUserQuery(id)

  if (isLoading) return <Spinner />
  if (error) return <Error />
  return <div>{data?.name}</div>
}

7. MobX：响应式风格 ​

MobX 用 observable 把状态变成可观察的，组件用 observer 包裹自动响应。适合"类 OOP 思维"的项目。

tsx
import { makeAutoObservable, autorun } from 'mobx'
import { observer } from 'mobx-react-lite'

class CounterStore {
  count = 0
  step = 1

  constructor() {
    makeAutoObservable(this)  // 自动把属性和方法变成 observable/action
  }

  increment() { this.count += this.step }
  setStep(n: number) { this.step = n }
}

const store = new CounterStore()

const Counter = observer(() => (
  <div>
    <span>{store.count}</span>
    <button onClick={() => store.increment()}>+</button>
  </div>
))

MobX 特点：

  • 写法接近原生 JS，不用记 reducer/action 概念。
  • 细粒度响应（只更新真正用到状态的组件）。
  • 缺点：心智模型不一样，团队需要学习成本。

8. 服务端状态：React Query / SWR ​

前端状态 ≠ 服务端状态。列表、详情这些"来自后端的数据"不应该用 Redux/Zustand 管，应该用专门的服务端状态库。

tsx
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query'

// 1. 查询
function UserList() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['users'],
    queryFn: () => fetch('/api/users').then(r => r.json()),
    staleTime: 5 * 60 * 1000,  // 5 分钟内不重新请求
  })

  if (isLoading) return <Spinner />
  if (error) return <Error />
  return <List items={data} />
}

// 2. 变更 + 自动失效缓存
function CreateUser() {
  const queryClient = useQueryClient()
  const mutation = useMutation({
    mutationFn: (newUser: User) =>
      fetch('/api/users', { method: 'POST', body: JSON.stringify(newUser) }),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['users'] })  // 自动刷新列表
    },
  })
  return <button onClick={() => mutation.mutate({ name: 'tom' })}>新增</button>
}

// 3. 依赖查询
function UserPosts({ userId }: { userId: string }) {
  const { data: user } = useQuery({
    queryKey: ['user', userId],
    queryFn: () => fetch(`/api/users/${userId}`).then(r => r.json()),
  })
  const { data: posts } = useQuery({
    queryKey: ['posts', userId],
    queryFn: () => fetch(`/api/users/${userId}/posts`).then(r => r.json()),
    enabled: !!user,  // user 加载完才请求
  })
  return <div>{posts?.length} 篇文章</div>
}

React Query 自动处理的事：

  • 缓存（同样的 queryKey 不重复请求）。
  • 失效和重取（mutation 后自动 refetch）。
  • 加载 / 错误状态。
  • 乐观更新（先改 UI，再请求）。
  • 轮询、分页、无限滚动。

9. 选型建议 ​

项目规模推荐方案
1-3 页面useState + useReducer
中小项目（10+ 组件）Context + Zustand
中大型项目（多模块协作）Redux Toolkit + RTK Query
大量服务端状态React Query / SWR（不管用啥状态库都要叠这个）
已有 OOP / 响应式思维MobX

真实项目经验：

  • 商户管理 SaaS / 会员服务平台用的是 Zustand + React Query，轻量足够。
  • 复杂规则配置类应用（如风控平台）适合 Redux + Redux Toolkit，时间旅行调试很爽。
  • 不要把列表数据放 Redux/Zustand：会重复缓存，刷新逻辑写起来很痛苦。直接用 React Query。

10. 常见坑 ​

10.1 状态提升过度 ​

tsx
// ❌ 表格内部选中状态提升到全局
// 表格切换页码 → 整个 store 更新 → 无关组件重渲染
const [selectedRows, setSelectedRows] = useState([])

// ✅ 表格内部状态放组件内
function Table() {
  const [selectedRows, setSelectedRows] = useState([])
  // ...
}

10.2 状态过于分散 ​

tsx
// ❌ 5 个 useState 描述一个表单
const [name, setName] = useState('')
const [age, setAge] = useState(0)
const [email, setEmail] = useState('')
const [agree, setAgree] = useState(false)
const [errors, setErrors] = useState({})

// ✅ 用 useReducer 或 react-hook-form
const [form, dispatch] = useReducer(formReducer, initialState)

10.3 直接修改 state ​

tsx
// ❌ 对象/数组必须返回新引用
state.user.name = 'tom'
setState(state)

// ✅ 不可变更新
setState({ ...state, user: { ...state.user, name: 'tom' } })
// 或者用 immer
import { produce } from 'immer'
setState(produce(state, draft => {
  draft.user.name = 'tom'
}))

10.4 Zustand 不写 selector ​

tsx
// ❌ 返回整个 store：任何字段变化都重渲染
const store = useUserStore()

// ✅ 只选需要的字段
const user = useUserStore((s) => s.user)

11. 面试常考 ​

题目答案要点
Context 性能问题value 引用变化触发所有消费者重渲染；用 useMemo 或状态库
Redux vs ZustandRedux 标准化（团队/调试/撤销）；Zustand 轻量（中小项目）
为什么需要 React Query服务端状态有缓存/失效/重试/分页等复杂需求，不是简单 useState 能搞定
MobX vs Redux 思维差异MobX 面向对象 + 响应式；Redux 函数式 + 单向数据流
状态提升 vs Context vs 全局库简单：状态提升；中等：Context；复杂：状态库

12. 真实项目经验 ​

12.1 商户管理 SaaS（Next.js） ​

  • 全局状态：用 Zustand 管当前用户、权限码、I18n、主题。
  • 服务端状态：用 React Query 管列表、详情、分页、搜索。
  • 表单状态：用 react-hook-form + zod（schema 校验）。
tsx
// 真实目录结构
src/
  store/
    userStore.ts        // Zustand
    permissionStore.ts  // Zustand
  hooks/
    queries/
      useUsers.ts       // React Query
      useOrders.ts
  components/
    form/

  • Pinia（Vue 3 的状态库，类 Zustand）+ Vue Query。
  • 不用 Vuex 4：Pinia 的 TypeScript 支持和 Composition API 集成更好。

选型原则：够用就好。不要为了用 Redux 而用 Redux，中小项目 Zustand/Pinia 完全够用。
