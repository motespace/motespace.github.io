十、面试高频追问

Section titled “十、面试高频追问”

Q1: React 18 自动批处理怎么实现的？

Section titled “Q1: React 18 自动批处理怎么实现的？”

答：React 18 把批处理时机统一从“React 事件”扩展到“所有微任务 + setTimeout + Promise 等”。任何 setState 都会被 Schedule 进 PendingQueue，等所有 callback 跑完才 flush。

Q2: useTransition 和 useDeferredValue 区别？

Section titled “Q2: useTransition 和 useDeferredValue 区别？”

答：

  • useTransition：包裹 setState 调用，标记为低优先级
  • useDeferredValue：包裹值，让 value 走低优先级渲染
  • 选型：能拿到 setState 用前者；只能拿到 value 用后者

Q3: Suspense 解决了什么？

Section titled “Q3: Suspense 解决了什么？”

答：

  • 数据加载：组件抛 Promise，Suspense 展示 fallback
  • 流式 SSR：嵌套 Suspense 分块返回 HTML
  • 代码分包：lazy() 异步加载组件

Q5: 自动批处理有什么坑？

Section titled “Q5: 自动批处理有什么坑？”

答：

  • 副作用依赖 DOM 更新时序的场景（如 ref 测量），要小心
  • setTimeout 中 flushSync 才能强制同步

Q6: React 19 还有什么新特性？

Section titled “Q6: React 19 还有什么新特性？”

答：

  • use hook：条件调用、支持 Promise
  • Actions：自动处理 pending / error / optimistic update
  • Server Components：服务端组件，零 JS 体积
  • useFormStatus / useFormState：表单状态

Q7: 并发模式怎么开启？

Section titled “Q7: 并发模式怎么开启？”

答：React 18 默认开启所有并发特性（不需要 unstable_concurrentMode）。Next.js / Vite + React 18+ 自动支持。

面试追问(深化原 Q1-Q7)

Section titled “面试追问(深化原 Q1-Q7)”
  • 自动批处理边界? 全部微任务/setTimeout/Promise/原生事件;flushSync 强制同步
  • useTransition vs useDeferredValue 选哪个? 能拿到 setState 用前者;只能拿到 value 用后者
  • Suspense 三种用法? 数据加载(throw Promise)、流式 SSR(分块返回 HTML)、代码分包(lazy)
  • 自动批处理坑点? 副作用依赖 DOM 时序(如 ref 测量)需谨慎;setTimeout 中想同步用 flushSync
  • React 19 use hook 条件? 必须包在 Suspense 内,否则 throw error
  • 并发模式如何开启? React 18 默认开启;不需要 unstable_concurrentMode 前缀

Q8: 并发模式最大的用户感知?

Section titled “Q8: 并发模式最大的用户感知?”

答:

  • 输入响应快(高优先级插入)
  • 大列表渲染不卡(分片 + 跳过)
  • 切换 tab 切回时未完成工作可继续

Q9: 时间切片粒度怎么定?

Section titled “Q9: 时间切片粒度怎么定?”

答:

  • 默认 5ms(60fps 反推:1 帧 16.67ms,留 11ms 给浏览器)
  • shouldYield() 检查剩余时间
  • 紧急任务可整段跑完不让出(如用户输入触发的 update)

📝 小结

Section titled “📝 小结”
  • 并发模式让 React 能主动让出主线程给用户交互,而不是等一个大任务跑完。
  • useTransition 把非紧急更新标记为可中断,useDeferredValue 延迟一个值的渲染时机。
  • 并发 ≠ 多线程 —— JS 仍在主线程,只是「可暂停、可放弃、可恢复」。
  • 适合的场景:大列表筛选、路由切换、Tab 切换时的过渡。
