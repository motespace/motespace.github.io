Q1:useEffect 请求有什么问题?

Section titled “Q1:useEffect 请求有什么问题?”

答:

  • 无缓存
  • 无重试
  • 无去重
  • 无错误边界
  • 无自动聚焦刷新
  • 用 TanStack Query / SWR 解决

Q2:乐观更新怎么做?

Section titled “Q2:乐观更新怎么做?”

答:

  • onMutate:立即更新 UI
  • onError:失败回滚
  • onSettled:重新拉服务端数据

Q3:staleTime 和 cacheTime 区别?

Section titled “Q3:staleTime 和 cacheTime 区别?”

答:

  • staleTime:数据被视为新鲜的时间(默认 0,立即过期)
  • gcTime(旧 cacheTime):无订阅后多久清理(默认 5 分钟)
  • 实战:staleTime 设大(如 5 分钟)减少请求

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • useEffect 请求的隐藏问题? 内存泄漏(组件卸载后 setState)、竞态条件、loading 状态分散
  • 乐观更新注意事项? onMutate 必须返回 context 给 onError 回滚;onSettled 必须重新 fetch 兜底
  • staleTime 设多大? 用户感知新鲜的数据 → 设大(5-30 分钟);实时性要求高 → 设小(0-1 分钟)
  • gcTime 是什么? 旧名 cacheTime;无订阅后多久清理(默认 5 分钟)
  • 请求去重机制? TanStack Query 用 queryKey 哈希;同 key 并发请求只发一次,其他等待

Q4: SWR vs TanStack Query?

Section titled “Q4: SWR vs TanStack Query?”

答:

  • TanStack Query:功能更全(乐观更新、无限查询、SSR 集成、devtools)
  • SWR:API 更简洁,体积更小(~4KB);内置 stale-while-revalidate
  • 现代项目推荐 TanStack Query(团队/复杂业务);SWR 适合小项目/hackathon

📝 小结

Section titled “📝 小结”
  • useEffect + fetch 手写的核心问题:竞态、重复请求、依赖地狱、卸载后 setState、缓存缺失。
  • queryKey 是缓存的唯一标识,设计成数组(['merchant', id, filters]),层级要和后端资源对应,才能精准失效。
  • staleTime=数据多久算「旧」(决定是否后台重新拉取),gcTime=缓存保留多久(决定内存占用),两者别混。
  • 变更用 useMutation + onMutate 做乐观更新:onMutate 立即改缓存 → onError 回滚 → onSettled 失效重取。
  • 面试高分点:讲清楚缓存生命周期(stale → refetch → 失效 → gc)和请求去重(dedupeInterval、同 key 并发只发一次)。
