Q1:React 18 最大的变化?

Section titled “Q1:React 18 最大的变化?”

答:

  • 并发模式(可中断渲染)
  • 自动批处理(所有 setState 合并)
  • createRoot API
  • Suspense for data fetching

Q2:useTransition 用法?

Section titled “Q2:useTransition 用法?”

答:

适用:大列表过滤、搜索、Tab 切换。

Q3:Server Components 优势?

Section titled “Q3:Server Components 优势?”

答:

  • bundle 体积小(不发 JS 到客户端)
  • 服务端直接查数据库
  • 首屏快、SEO 好

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • Concurrent Mode 必须显式开? React 18 默认开;不需要 unstable_concurrentMode 前缀
  • useTransition 适用场景? 搜索框输入、过滤、排序、Tab 切换等“非紧急”更新
  • RSC 最大优势? 零客户端 JS;直接访问数据库;组件跨服务器边界复用
  • RSC 限制? 不能用 useState / useEffect;不能交互;需要 'use client' 指令开启 client component
  • Actions 解决了什么? 自动管理 pending / error / 乐观更新,免去手写 useState

Q4: useActionState 用法?

Section titled “Q4: useActionState 用法?”

答:

  • 替代 useState 手动管理 pending/error
  • 第一个参数:初始 state;第二个:reducer;第三个:form action
  • 返回 [state, formAction, isPending]
  • React 19 标配,form action 写法原生支持

Q5: useOptimistic 用法?

Section titled “Q5: useOptimistic 用法?”

答:

  • 异步 action 完成前先显示预期结果
  • 失败时自动 revert
  • 适合点赞、收藏、评论等“乐观”操作
  • 配合 useActionState 一起用,UI 立即响应

📝 小结

Section titled “📝 小结”
  • React 18 核心是并发渲染:渲染可被打断、拆分、恢复,配合 Scheduler 优先级把紧急更新(输入)先做完。
  • createRoot 才开启并发特性与自动批处理;ReactDOM.render(legacy)不批处理 React 18 之外更新。
  • useTransition = 标记非紧急更新,useDeferredValue = 把某个值延迟;前者管「这次更新可以等」,后者管「这个值可以晚点给」。
  • useSyncExternalStore 是订阅外部数据源的并发安全版 useState + useEffect,避免 tearing(撕裂)。
  • RSC 的本质是在服务端渲染且不打包进客户端 bundle,所以不能有 state/effect/浏览器 API,只能在 Server Component 顶层 await。
  • React 19:Actions(useActionState)、useOptimistic 乐观更新、use 读 Promise、ref 作为 prop 传给函数组件。
