面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • RHF 比 Formik 快在哪? 非受控输入(defaultValues)→ 不订阅每个 input 状态 → 减少 re-render
  • Zod 优势? TS 类型推导;静态检查;运行时验证;前后端共享 schema
  • 字段联动复杂度? 简单:watch + setValue;复杂:useWatch(避免整个表单 re-render)+ 动态 schema
  • handleSubmit 的错误处理? onInvalid(验证失败)和 onValid(提交)两个 callback
  • 表单性能优化? 非受控 + mode: 'onBlur' 减少校验次数;大表单字段懒加载 schema

Q4: 表单性能优化的 3 个关键?

Section titled “Q4: 表单性能优化的 3 个关键?”

答:

  1. 非受控输入:register 而非 Controller(后者走 React state)
  2. 字段级订阅:useWatch('fieldA') 只订阅一个字段,避免整个表单 re-render
  3. 懒加载 schema:大表单用动态 import 拆分校验规则

📝 小结

Section titled “📝 小结”
  • React 表单的核心矛盾:受控组件每次输入都触发整表单重渲染,非受控则要自己做脏检查。
  • React Hook Form 的解法是订阅式:只订阅你 watch 的字段,未订阅字段输入不触发渲染,这是性能关键。
  • FormProvider + useFormContext 把 useForm() 上下文化,深层字段不用层层传 form 实例。
  • 校验分两层:Schema 层(Zod,类型与规则同源)+ 交互层(提交时/失焦时触发),避免每敲一个字就报红。
  • 动态表单用 useFieldArray 做增删,用 watch(name) 做联动;面试常追问「怎么实现字段间联动」,答案就是 watch + setValue。
  • 项目经验可讲:一个「活动新增」表单用 Schema 驱动 + 字段级订阅,把 20+ 字段的提交从 800ms 降到 200ms。
