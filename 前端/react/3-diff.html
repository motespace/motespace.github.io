React Diff 算法（Reconciliation） ​

React 18+ 面试必问："Diff 为什么 O(n)？为什么需要 key？双端怎么对比？" 本文按"原理 → 源码级别实现 → 实战"三层组织。

一、为什么需要 Diff ​

1.1 朴素算法问题 ​

两棵树对比找最小更新 = O(n³)
10000 节点 = 10¹²次对比 = 不可能实时

1.2 React 启发式假设 ​

React 把 O(n³) 降到 O(n)，靠的是三条假设：

  1. 不同类型的元素产生不同的树：div → p，整个子树重建
  2. 通过 key 标识稳定子元素：列表用 key 标识身份
  3. 同级比较：不跨层级比较 DOM

代价：不是"最小更新"，但够快 + 够用。

二、Diff 三步流程 ​

1. 元素类型不同？→ 删旧建新（不用深入对比）
2. 元素类型相同？→ 更新属性（diff props）
3. 递归子节点 → 列表对比（同层比较）

2.1 元素类型不同 ​

jsx
// ❌ 旧：<div>...</div>
// ✅ 新：<p>...</p>
// React 行为：直接卸载 div，销毁所有子节点，重新挂载 p

为什么这么做：跨类型对比意义不大，成本高收益低。

2.2 元素类型相同 ​

jsx
<div className="old" title="hi" />
<div className="new" title="hi" />

// React 行为：保留 DOM 节点，只更新 className

2.3 递归子节点（列表对比） ​

jsx
// 老
<ul>
  <li key="a">A</li>
  <li key="b">B</li>
  <li key="c">C</li>
</ul>

// 新
<ul>
  <li key="b">B</li>
  <li key="c">C</li>
  <li key="d">D</li>
</ul>

带 key 的对比：O(1) 查找 vs O(n) 顺序对比

四、列表 Diff 源码级别 ​

4.1 单端指针（老版本 React） ​

老: [A, B, C]
新: [D, A, B]
key: [a, b, c]
    [d, a, b]

过程：
1. 拿新[0]=D，找老里 key=d → 没有
2. 拿新[1]=A，找老里 key=a → 老[0]=A，标记 pos1=diff
3. 拿新[2]=B，找老里 key=b → 老[1]=B，标记 pos2=diff
4. 结果：新建 D，移动 A、B，原位置保留 C

4.2 双端指针（新版本，React 16+） ​

老: [A, B, C, D]
新: [A, B, C, D, E]

双端指针：oldStartIdx=0, oldEndIdx=3, newStartIdx=0, newEndIdx=4

过程：
1. oldStart=A == newStart=A → 复用，oldStart=1, newStart=1
2. oldStart=B == newStart=B → 复用，oldStart=2, newStart=2
3. oldStart=C == newStart=C → 复用，oldStart=3, newStart=3
4. oldStart=D == newStart=D → 复用，oldStart=4, newStart=4
5. oldStart > oldEnd（oldStart=4 > oldEnd=3）→ 结束
6. newStart 还剩 E → 创建 E 插入
老: [A, B, C, D]
新: [A, B, D, C]

过程：
1. A == A → 复用
2. B == B → 复用
3. oldStart=C, newStart=D → 不匹配
4. 比较 oldEnd=D == newStart=D → 匹配，移动 D 到 oldStart 位置
   → 老变 [B, D, C]
5. oldStart=2(C), newStart=3(C) → 匹配，复用
6. 结束

4.3 为什么 key 不能用 index ​

jsx
// ❌ 用 index 当 key
{list.map((item, index) => <Item key={index} {...item} />)}

// 老：[A(index=0), B(index=1), C(index=2)]
// 新：[B(index=0), C(index=1), D(index=2)]

// React 视角：key 相同 → 复用
// 实际上：A 删除，B/C 状态可能错乱（input 的 value 保留的是 A 的）

真实项目坑：删除中间项时，后续项的组件 state 不重置。

jsx
// 真实场景：表格删除中间行
function Table({ rows }) {
  return rows.map((row, i) => (
    <Row key={i} row={row} />  // ❌
  ))
}

// 删除 row[1] 后，rows[2] 用了 row[1] 的 key
// Row 组件内部 state（编辑状态）保留 row[1] 的状态
// 用户看到 row[2] 显示的是 row[1] 的旧数据

五、Diff 的 Props 实现 ​

js
// 简化版 diffProps
function diffProps(oldProps, newProps) {
  const patches = []

  // 1. 更新变化的 props
  for (const key in newProps) {
    if (oldProps[key] !== newProps[key]) {
      patches.push({ type: 'SET_PROP', key, value: newProps[key] })
    }
  }

  // 2. 删除老的独有 props
  for (const key in oldProps) {
    if (!(key in newProps)) {
      patches.push({ type: 'REMOVE_PROP', key })
    }
  }

  return patches
}

六、单元素 Diff 完整流程 ​

js
// 简化版单元素 diff
function diff(oldVNode, newVNode) {
  // 1. 类型不同：替换
  if (oldVNode.type !== newVNode.type) {
    return { type: 'REPLACE', node: newVNode }
  }

  // 2. 类型相同：更新 props
  const propPatches = diffProps(oldVNode.props, newVNode.props)

  // 3. 递归子节点
  const childPatches = diffChildren(
    oldVNode.props.children,
    newVNode.props.children
  )

  return { type: 'UPDATE', propPatches, childPatches }
}

八、面试高频追问 ​

Q1: React Diff 为什么是 O(n) 而不是 O(n³)？ ​

答：靠三条假设：

  1. 类型不同 → 整树重建
  2. key 标识身份
  3. 同级比较 代价：不是最小更新，但 99% 场景够用。

Q2: 列表为什么需要 key？不带 key 会怎样？ ​

答：key 是 React 识别"同一元素"的依据。

  • 不带 key：React 按顺序对比，删除中间项时后续项错位
  • 带 key：React 按身份对比，能复用 + 移动

Q3: 为什么 index 不能当 key？ ​

答：删除中间项 / 排序后，index 和 item 不再对应。React 错以为是同一个组件，组件 state 不重置，导致数据错乱。

Q4: 为什么 React 不做"完美最小更新"？ ​

答：

  • O(n³) 太慢（10¹² 次对比）
  • 实测 O(n) 启发式效果足够好（99% 场景命中）
  • 不追求完美，追求工程效率

Q5: Diff 在 React 18 有什么变化？ ​

答：

  • React 18 引入 Concurrent Mode：Diff 可中断
  • 旧架构 Diff 必须一次跑完，新架构可以分片执行
  • 用户体验差异：不再卡顿

Q6: 移动端怎么做 Diff？ ​

答：React Native 也用同一套 Diff 算法，但 DOM 操作变成 Native Bridge 调用。

面试追问(深化原 Q1-Q6) ​

  • O(n) 最坏会退化吗? 列表全同 key + 全部重排 → O(n²);但 95% 场景启发式命中
  • 类型不同重建一定更优? 是。跨类型 DOM 属性差异大(div vs span、属性映射),复用成本 > 重建成本
  • React Native 用同一套 diff? 是。算法不变,只把 commit 阶段 DOM 操作换成 native bridge 调用
  • 完美最小更新为何没人做? O(n³) 维护成本高;启发式命中率高,工程性价比差
  • React 18 真"可中断 diff"? Render 阶段 diff 在 workInProgress 上跑,可中断;Commit 阶段不可
  • 双端指针 vs 单端? React 16+ 列表用头头/尾尾/keyMap,移动数比单端少 30%

Q7: 双端指针 diff 怎么工作? ​

答:

  • 两对指针:oldStart/oldEnd vs newStart/newEnd
  • 头头、尾尾比对;失败用 keyMap 找中间项;命中后移动到头部
  • 最坏 O(n),平均移动比单端少 30%

Q8: key 匹配失败时怎么办? ​

答:

  • 优先用开发者提供的 key
  • 没 key fallback 到 index(顺序匹配)
  • key 复用 = 复用 fiber + 复用 DOM + 保留 state
