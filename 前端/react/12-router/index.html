Q1:BrowserRouter vs HashRouter?

Section titled “Q1:BrowserRouter vs HashRouter?”

答:

  • BrowserRouter:/about,URL 干净,需服务端 fallback
  • HashRouter:/#/about,无需配置,SEO 略差
  • 新项目用 BrowserRouter

Section titled “Q1:如何做路由鉴权?”

答:

  • 包裹 ProtectedRoute 组件
  • 未登录 → Navigate to /login
  • 把原路径放在 state,登录后跳回

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • BrowserRouter 服务端 fallback 怎么配? Nginx 配 try_files $uri /index.html;或用 Vercel/Netlify 默认支持
  • HashRouter 优点? 不需要服务端配置;旧项目无服务端权限时可用
  • ProtectedRoute 怎么拿原路径? &lt;Navigate to="/login" state="{​{ from: location }​}" /&gt;;登录后从 location.state.from 跳回
  • lazy + Suspense 怎么配合 SSR? 需要 loadable 或框架级方案(Next.js dynamic import),避免服务端拿不到 chunk
  • 路由懒加载的边界? 路由级 chunk 粒度适合;过细(如每个组件)反而增加请求数

Q4: 路由懒加载 vs 组件懒加载?

Section titled “Q4: 路由懒加载 vs 组件懒加载?”

答:

  • 路由级:React.lazy(() => import('./page')) + Suspense;按页面分包,首屏快
  • 组件级:React.lazy 包裹大组件(如富文本、图表);用时才加载
  • 不要无限拆:每个 chunk < 50KB 才划算(网络往返成本)

📝 小结

Section titled “📝 小结”
  • React Router 有三种:BrowserRouter(history,需服务端 fallback)、HashRouter(hash,静态托管友好)、MemoryRouter(内存,测试/SSR 用)。
  • 三层取路由信息:useLocation(路径+search)、useParams(动态段)、useMatch(自定义匹配)。
  • 路由守卫本质是渲染前的一次权限判断,常见做法是封装 &lt;ProtectedRoute&gt; 组件统一处理,而不是在每个页面写 if。
  • 权限判断要区分前端可见性与后端鉴权:前端隐藏菜单只是体验,真正的权限必须在服务端再校验一次。
  • 懒加载用 React.lazy + Suspense,并把 Suspense 边界放在路由级别,不要包整个 App。
