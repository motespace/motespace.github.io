Fiber 架构（React 16+） ​

7 年经验面试必问："为什么需要 Fiber？""Fiber 是怎么实现可中断的？" 本文按"原理 → 双阶段 → 源码"组织。

一、React 15 Stack Reconciler 的问题 ​

1.1 同步递归 ​

js
// React 15 渲染过程
function render(element, container) {
  // 同步递归遍历所有节点
  // 一旦开始，无法中断
  // 主线程被占用几十到几百毫秒
}

1.2 问题 ​

  • ❌ 主线程被占用：JS 执行 + 布局 + 绘制全部阻塞
  • ❌ 无法中断：大列表渲染会卡顿
  • ❌ 无法优先级：用户输入和后端计算结果无法区分

二、Fiber 核心目标 ​

把渲染工作拆成小块，可以暂停、恢复、优先级调度。

用户输入（紧急）   ──┐
                  ├──> Scheduler 调度 ──> Fiber 工作单元
后端数据返回（低）  ──┘

三、Fiber 节点结构 ​

js
// 每个 React 元素对应一个 Fiber 节点
const fiber = {
  // 元素信息
  type: 'div',                  // 元素类型（'div' / 'div' / function Component）
  key: null,                     // 同 key
  elementType: 'div',            // 原始元素类型

  // 关联
  stateNode: domElement,         // 对应的真实 DOM
  return: parentFiber,           // 父 Fiber
  child: childFiber,             // 第一个子 Fiber
  sibling: siblingFiber,         // 下一个兄弟 Fiber

  // 链表结构（替代递归调用栈）
  alternate: workInProgressFiber,  // 双缓存（指向 workInProgress 树）

  // 状态
  pendingProps: { ... },         // 新的 props
  memoizedProps: { ... },        // 上次渲染的 props
  memoizedState: null,           // 上次渲染的 state（hooks 链表头）
  updateQueue: null,             // useState/useReducer 的更新队列

  // 副作用
  flags: 0,                      // 副作用标记（Update / Placement / Deletion）
  subtreeFlags: 0,               // 子树副作用
  lanes: 0,                      // 优先级（React 18+）

  // hooks
  dependencies: null,            // useEffect / useMemo 依赖
}

链表 vs 树：

树（递归调用栈）：              链表：
                                
A                              A ──child──> B ──child──> D
├─ B                            A ──sibling──> C
│  └─ D                        B ──sibling──> C
└─ C                          D 无 child

无法中断                       可中断（在任意节点停下）

四、双缓存机制（Double Buffering） ​

currentTree         workInProgressTree
   │                       │
   │                       │ （在内存中修改）
   │                       ↓
   └──── 渲染完成 ────> swap（原子切换）

好处：

  • 用户看到的永远是 currentTree（不会渲染一半）
  • workInProgress 修改完一次性切换
js
// 简化版双缓存
const root = {
  current: currentFiber,           // 用户当前看到的
  workInProgress: null,             // 正在工作的）
}

function render(element) {
  // 1. 复制 current 到 workInProgress
  root.workInProgress = {
    ...root.current,
    alternate: root.current,
  }

  // 2. 在 workInProgress 上工作
  workLoop()

  // 3. 完成后切换
  root.current = root.workInProgress
}

五、双阶段：Render + Commit ​

5.1 Render 阶段（可中断） ​

workLoop(deadline) {
  while (nextUnitOfWork && !shouldYield(deadline)) {
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork)
  }
}

可中断：每次执行完一个工作单元，检查 shouldYield(deadline)：

  • 剩余时间 < 1ms → 让出主线程
  • 浏览器处理用户输入
  • 下一帧继续

5.2 Commit 阶段（不可中断） ​

js
function commitRoot(root) {
  // 同步执行所有副作用
  // 1. 调用 componentDidMount / useEffect layout effect
  // 2. 更新真实 DOM
  // 3. 调用 useEffect
}

为什么不可中断：UI 一致性。如果分批 commit，用户会看到一半新 UI + 一半旧 UI（闪烁）。

5.3 时间切片 ​

一帧（16ms）：
├── 浏览器输入处理（紧急）
├── requestAnimationFrame 回调
├── 空闲时间
│   └── Fiber 工作单元（每帧可执行 5-10ms）
└── requestIdleCallback（如果还有时间）

六、begin work（单元节点处理） ​

js
function performUnitOfWork(fiber) {
  // 1. 处理当前 Fiber（执行函数组件 / 转换 class 组件）
  const nextChildren = beginWork(fiber, fiber.pendingProps)

  // 2. 处理 props / 子节点
  reconcileChildren(fiber, nextChildren)

  // 3. 返回下一个 Unit
  if (fiber.child) return fiber.child

  // 没有 child，找 sibling
  let nextFiber = fiber
  while (nextFiber) {
    // 4. completeWork（创建 DOM）
    completeWork(nextFiber)

    if (nextFiber.sibling) return nextFiber.sibling
    nextFiber = nextFiber.return
  }
}

七、Scheduler 调度器 ​

7.1 时间切片实现 ​

js
// 简化版 Scheduler
function shouldYield(deadline) {
  // deadline = 当前帧剩余时间
  return performance.now() >= deadline
}

function workLoop(deadline) {
  while (nextUnitOfWork && !shouldYield(deadline)) {
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork)
  }

  if (!nextUnitOfWork && root.current !== root.workInProgress) {
    commitRoot()  // 全部完成后提交
  }

  if (nextUnitOfWork) {
    // 还有工作 → 让出，等下一帧
    requestIdleCallback(workLoop)
  }
}

requestIdleCallback(workLoop, { timeout: 5000 })

十一、面试高频追问 ​

Q1: 为什么要 Fiber？Stack Reconciler 哪里不行？ ​

答：Stack 同步递归，无法中断，主线程被长时间占用，导致卡顿。Fiber 把工作拆成单元，时间分片 + 优先级调度。

Q2: Fiber 是怎么实现可中断的？ ​

答：

  1. 链表结构（替代递归调用栈）
  2. 工作单元（每处理完一个 Fiber 检查 deadline）
  3. 双缓存（workInProgress 在内存中修改）
  4. Render / Commit 双阶段（Render 可中断，Commit 不可）

Q3: Fiber 节点是链表还是树？ ​

答：逻辑上是树（child / sibling / return 关系），但存储是链表（便于遍历中断）。

Q4: Render 阶段和 Commit 阶段区别？ ​

答：

  • Render：可中断，diff + 调和（不算 UI 渲染）
  • Commit：不可中断，DOM 更新 + 副作用调用（用户立刻看到）

Q5: Fiber 树和优先级怎么配合？ ​

答：每个 Fiber 有 lanes 字段，标识优先级。Scheduler 按优先级选 workInProgress，高优先级插队。

Q6: React 18 的并发模式比 Fiber 多了啥？ ​

答：

  • Lane 模型：二进制位表示优先级
  • 自动批处理：所有 setState 都合并
  • Transition API：useTransition / useDeferredValue
  • Suspense 改进：流式 SSR

Q7: Fiber 和 Reconciler 是什么关系？ ​

答：Fiber 是数据结构（链表节点），Reconciler 是算法（在 Fiber 上执行 diff / 调和）。Fiber 是机制，Reconciliation 是流程。

面试追问(深化原 Q1-Q7) ​

  • Fiber 链表遍历顺序? 深度优先:子 → 兄弟 → return;beginWork 处理子,completeWork 处理完
  • 双缓存切换时机? Commit 阶段 rootFiber.current 切到 workInProgress;renderWithHooks 入口判断 alternate
  • Render 可中断、Commit 不可? Render 改的是内存 workInProgress,扔掉不污染;Commit 已动 DOM,中断致 UI 不一致
  • Lane 模型比旧 expirationTimes 好在哪? 二进制位可表达"多优先级共存"(transition setState + input 同帧)
  • 优先级饥饿怎么处理? Scheduler 检测低优先级连续 5 帧未执行 → 强制提升一级
  • workLoop 怎么让出主线程? 每个 fiber 处理前调 shouldYield(),剩余时间 < 5ms 就 return null

Q8: Fiber 节点 7 大类核心字段? ​

答:

  1. VDOM 信息:type / key / elementType
  2. 状态:pendingProps / memoizedProps / memoizedState
  3. 链表:return / child / sibling
  4. 副作用:flags / subtreeFlags / lanes
  5. 缓存:alternate(双树切换)
  6. 宿主:stateNode(DOM 节点 / 实例)
  7. 更新:updateQueue(useState/useReducer 队列)

Q9: beginWork 和 completeWork 区别? ​

答:

  • beginWork:处理子 fiber(diff、调和),返回下一个 workInProgress
  • completeWork:子 fiber 全部完成后处理自身(创建 DOM、收集 effect)
  • 整棵树遍历完才走 commitWork,一次性原子落地
