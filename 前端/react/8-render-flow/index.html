React 用双缓冲避免渲染中看到不完整状态:

七、优先级与 Lane 模型

Section titled “七、优先级与 Lane 模型”

React 18 用 Lane 模型 表达优先级:32 位整数,每一位代表一种优先级,更新时用位运算合并。

对渲染流程的影响:

  • 高优先级更新可以中断低优先级的渲染
  • 同 Lane 的更新会合并成一次 re-render
  • useTransition 产生的更新走 transition lane,不会阻塞输入响应

Lane 模型的完整设计(为什么用二进制位、各 Lane 的语义、调度器如何取最高优先级)→ Fiber 架构 第八章

Q2:Render 阶段为什么可中断?

Section titled “Q2:Render 阶段为什么可中断?”

答:

  • 浏览器主线程是共享资源
  • React 用时间切片(5ms),让出主线程
  • 让浏览器处理用户输入、动画等高优先级任务
  • 中断不丢工作(下次接着做)

Q3:Commit 阶段为什么不能中断?

Section titled “Q3:Commit 阶段为什么不能中断?”

答:

  • Commit 已经操作 DOM
  • 中断会导致 UI 处于不一致状态
  • 必须完整执行
  • useEffect 异步触发,不阻塞

Q4:fiber 是什么?

Section titled “Q4:fiber 是什么?”

答:

  • React 16+ 的协调单元
  • 每个 React 元素对应一个 fiber
  • 包含元素信息、关联其他 fiber、副作用
  • 组成 fiber 树,Render 阶段构建

面试追问(深化原 Q1-Q4)

Section titled “面试追问(深化原 Q1-Q4)”
  • 流程中哪步最贵? Commit 阶段 DOM 操作,触发 reflow/repaint
  • Render 中断会丢工作? 不会。workInProgress 暂存;下次从中断点续跑
  • 双树切换时机? Commit 阶段 rootFiber.current 切到 workInProgress
  • useEffect 在哪步? Commit 之后异步(不阻塞 paint);useLayoutEffect 在 Commit 同步段

Q5: useEffect vs useLayoutEffect 时机对比?

Section titled “Q5: useEffect vs useLayoutEffect 时机对比?”

答:

  • useEffect:paint 后异步执行
  • useLayoutEffect:DOM 更新后、paint 前同步执行
  • 测量 DOM / 防止闪烁 → useLayoutEffect;数据上报 / 订阅 → useEffect

Q6: 为什么 React 强调“Commit 必须原子”?

Section titled “Q6: 为什么 React 强调“Commit 必须原子”?”

答:

  • 一次 commit 包含所有变更原子落地
  • 分步 commit 会让用户看到中间状态(如表格 +1 行突然只显示 1 秒)
  • 副作用(useEffect)推迟到 paint 后,不让 commit 阻塞渲染

📝 小结

Section titled “📝 小结”
  • 完整链路:触发 setState → 调度(Scheduler 排优先级)→ 渲染(Fiber 递归,产出 effect 列表)→ 提交(同步改 DOM)→ 后续 passive effect。
  • render 阶段可能被多次执行且必须是纯函数,副作用只能放 effect 里。
  • commit 阶段是同步的、不可中断的,所以 DOM 变更不会出现中间态。
  • 排查性能先看 Profiler 的 commit 时间和 render 次数,不要凭感觉。
