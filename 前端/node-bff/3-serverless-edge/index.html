九、面试高频追问

Section titled “九、面试高频追问”

Q1: Serverless 和传统部署区别？

Section titled “Q1: Serverless 和传统部署区别？”

答：

  • 传统：固定机器、按时间计费、运维复杂
  • Serverless：按调用计费、自动扩缩容、零运维

Q2: Edge Functions 优势？

Section titled “Q2: Edge Functions 优势？”

答：地理就近、5ms 冷启动、低延迟。适合鉴权、A/B Test、AI 推理代理。

Q3: Vercel Edge Functions vs Cloudflare Workers？

Section titled “Q3: Vercel Edge Functions vs Cloudflare Workers？”

答：

  • Vercel：Next.js 原生、TypeScript
  • Cloudflare：300+ 节点、KV/D1/R2 生态
  • 选型：Next.js 项目用 Vercel；需要全球分布用 CF

Q4: Lambda 冷启动怎么优化？

Section titled “Q4: Lambda 冷启动怎么优化？”

答：

  • 减小 bundle（tree-shake、按需引入）
  • Provisioned Concurrency（预热）
  • 移到 Edge（Vercel / Cloudflare）

Q5: Serverless 上能用 WebSocket 吗？

Section titled “Q5: Serverless 上能用 WebSocket 吗？”

答：

  • Lambda：不支持长连接（15min 超时）
  • Cloudflare Durable Objects：支持
  • 实战：用 SSE / Webhook 而不是 WebSocket

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • Edge Computing 优势? 就近响应(全球 < 50ms);Cloudflare Workers / Vercel Edge / Deno Deploy
  • Edge 限制? 不能用 Node API;冷启动时间敏感;不适合大文件
  • Serverless 适用场景? 流量波动大(API)、CRON 任务、事件驱动(图片处理)
  • 冷启动优化? 减小 bundle、预热、预留并发;Cloudflare Workers < 5ms
  • 传统服务 vs Serverless 成本? 低频用 Serverless 便宜;高流量用传统 VPS / 容器

📝 小结

Section titled “📝 小结”
  • Serverless 的三个特征:按量计费、自动伸缩、免运维;代价是冷启动、运行时限制(超时/内存/文件系统只读)。
  • 平台对比:Vercel(Next.js 一体)、Cloudflare Workers(全球边缘 + KV/Durable Objects)、AWS Lambda(生态全、搭配 API Gateway/S3)。
  • Edge Runtime 的限制:不能用 Node API,只有 Web API;冷启动更低但不能用大依赖,适合轻逻辑(鉴权、A/B、改写、Geo 路由)。
  • Next.js 的 Middleware 就跑在 Edge,可以做「不合法请求在边缘就挡掉」。
  • 实战:在 Edge 做 AI 网关(鉴权、限流、Prompt 拼装、缓存),再转发到模型服务,能显著降低主干压力。
  • 局限要讲:长任务不友好、需要一致性强的事务不适合、调试链路长、厂商锁定。
  • 面试加分:能说清「哪些逻辑该放 Edge(轻、离用户近)」「哪些必须放服务端(重、需要访问内网数据库)」。
