Q1: 做过 Node.js 全栈吗？

Section titled “Q1: 做过 Node.js 全栈吗？”

答：Next.js App Router + Prisma + PostgreSQL / Server Actions 写 CRUD。TypeScript 端到端类型安全。

Q2: Server Component vs Client Component 区别？

Section titled “Q2: Server Component vs Client Component 区别？”

答：

  • Server Component：默认，渲染在服务端，零 JS 体积，能访问 DB
  • Client Component：‘use client’，渲染在浏览器，能交互
  • 优先 Server Component，需要交互用 Client Component

Q3: Server Action 是什么？

Section titled “Q3: Server Action 是什么？”

答：服务端函数，直接在表单 action / onClick 调用，免去写 API Route。

Q4: Next.js 怎么优化性能？

Section titled “Q4: Next.js 怎么优化性能？”

答：

  • Server Components 减少 JS 体积
  • Streaming（Suspense）不阻塞
  • ISR / Cache 减少数据请求
  • PPR（实验）混合渲染

Q5: Prisma vs raw SQL？

Section titled “Q5: Prisma vs raw SQL？”

答：

  • Prisma：类型安全、Migration、查询简洁
  • Raw SQL：性能极致、复杂查询
  • 实战：80% 用 Prisma，复杂报表用 raw SQL

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • Node 全栈框架选型? Express(经典)、Koa(中间件)、Fastify(快 2x)、NestJS(类 Spring)
  • Node 优势场景? I/O 密集(API、SSR、爬虫、BFF);不适合 CPU 密集(用 worker_threads)
  • Next.js 全栈能力? API Routes / Server Actions / Middleware;一套搞定前后端
  • Node 部署? PM2 / Docker / standalone;日志 + 监控必备

📝 小结

Section titled “📝 小结”
  • 全栈框架对比:Next.js(App Router,全栈 + SSR)、NestJS(后端为主)、Express/Koa(纯后端)、Nuxt(Vue 系)、Remix/React Router v7(路由即数据)。
  • Next.js 15 App Router 实战:Server Component 取数、Server Action 写数据、Route Handler 对外 API,前端不用再单独起后端服务。
  • 数据层推荐 Prisma:类型安全的查询客户端 + migration 管理 + Studio 可视化,适合快速迭代。
  • 认证用 NextAuth/Auth.js:统一 OAuth/凭证登录,自动处理 session,但授权规则仍要自己在数据层做。
  • 性能优化:并行取数、revalidate 控制缓存、Server Component 减少客户端 JS、图片走 next/image。
  • 实战 CRUD 的关键:表单校验与服务端二次校验、乐观更新、错误边界与 toast、列表分页与搜索。
  • 面试加分:讲「BFF 聚合多个后端服务、前端只调一个域」的收益:减少请求数、收敛鉴权与埋点。
