移动端适配:rem / vw 方案原理与坑

面试高频题。这篇回答「为什么 px 转 rem 能适配」以及「实际会踩哪些坑」, 光说「用了 postcss 插件把 px 转成 rem」是不够的。

一、为什么需要适配

Section titled “一、为什么需要适配”

移动端屏幕宽度差异巨大(320px 的小屏机 → 430px 的 Pro Max), 如果用固定 px 布局,在窄屏上会挤成一团,在宽屏上又留大片空白。

适配的本质:让页面的尺寸跟着屏幕宽度等比缩放, 也就是把「绝对像素」换算成「相对视口宽度的比例」。

🎯 面试常考

Section titled “🎯 面试常考”

Q1:移动端适配方案有哪些?各自原理? rem(JS 改根字号,1rem = 视口宽/10,需 postcss-pxtorem 转换)、vw(纯 CSS,100vw = 视口宽)、vw+rem 混合、 现在的 clamp() 流体排版。核心区别是 rem 需要 JS(有首屏闪烁),vw 不需要但 PC 端要限制。

Q2:postcss-px-to-viewport 的转换原理? 把 px 除以 viewportWidth / 100,换成 vw。32px 在 375 设计稿下 = 32 / 3.75 = 8.5333vw。 配置里 viewportWidth 要和设计稿宽度一致(375 或 750),否则比例全错。

Q3:用 rem 有什么坑? ① 需要 JS 改根字号,首屏有闪烁;② 用户改系统字号不跟随(无障碍);③ 第三方库 px 与 rem 混排要 exclude; ④ 1px 边框被放大;⑤ PC 大屏要 clamp 限上限。

Q4:iOS 键盘弹出页面被顶起怎么办? 100vh 是最大视口高度,键盘弹出时不变,内容被遮挡。用 100dvh(动态视口高度)或 visualViewport 监听 resize 把高度写进 CSS 变量。

Q5:怎么保证 1px 边框在高清屏上还是 1 物理像素? 两种:① postcss 里设 minPixelValue: 2,让 1px 不参与转换;② 用 transform: scaleY(0.5) 的伪元素画线。

📝 小结

Section titled “📝 小结”
  • rem 方案的原理只有一句:1rem = 视口宽/10,设计稿 px 除以 75 得 rem。
  • 它的代价是要 JS 改根字号(首屏闪)、不跟随用户字号(无障碍)、第三方库要 exclude。
  • vw 方案纯 CSS 无闪烁,但 PC 端必须 clamp 限上限。
  • 真正难的是那些细节:iOS 键盘的 dvh、安全区 env(safe-area-inset-*)、1px 边框、用户字号。
  • 现代做法是 clamp() 流体排版 + 容器查询,rem/vw 只在存量项目里维护。
