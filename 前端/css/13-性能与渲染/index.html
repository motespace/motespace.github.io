CSS 性能与渲染

7 年经验面试必问：为什么 transform 比 left/top 快？浏览器怎么把 CSS 变成像素？ 本专题按“原理 → 属性 → 实战”三层组织。

一、浏览器渲染流水线

1.1 关键渲染路径（CRP）

Section titled “1.1 关键渲染路径（CRP）”

1.2 各阶段耗时对比

Section titled “1.2 各阶段耗时对比”
阶段 触发条件 性能
Layout（重排） 几何变化（width/height/top/margin/padding） 最贵
Paint（重绘） 视觉变化（color/background/box-shadow）但不改变几何 中等
Composite（合成） transform / opacity / will-change 最便宜

💡 核心原则：能用 transform / opacity 解决，就别动 left / top / width。

二、重排 vs 重绘 vs 合成

Section titled “二、重排 vs 重绘 vs 合成”

2.1 重排（Reflow）

Section titled “2.1 重排（Reflow）”

触发：元素几何属性变化、DOM 结构变化、窗口 resize、字体加载。

影响范围：重排会递归触发祖先节点重排，最坏情况整个文档流重排（cost 最高）。

2.2 重绘（Repaint）

Section titled “2.2 重绘（Repaint）”

触发：视觉属性变化（color、box-shadow、background、border-color、visibility）。

影响范围：重绘一定伴随 layout 检查，但不重排。

2.3 合成（Composite）

Section titled “2.3 合成（Composite）”

触发：transform、filter（部分）、opacity、will-change 提示的图层。

原理：浏览器把元素提升到独立图层（Layer），图层的合成由 GPU 完成，不占用主线程。

性能对比实测

Section titled “性能对比实测”
操作 触发 耗时参考
top: 100px 重排 + 重绘 + 合成 5-15ms
transform: translateX(100px) 仅合成 0.1-1ms

100 倍性能差距，这就是 transform 是动画首选的原因。

Section titled “九、面试高频追问”

Q：transform 比 left/top 快？为什么？

Section titled “Q：transform 比 left/top 快？为什么？”

答：left/top 触发重排（reflow）+ 重绘 + 合成；transform 只触发合成（composite）。合成由 GPU 完成，不占主线程，且不触发整棵树重新计算。

Q：所有元素都加 will-change 行不行？

Section titled “Q：所有元素都加 will-change 行不行？”

答：不行。每个合成层都消耗 GPU 内存，层太多反而更慢。只在动画前动态添加，结束移除。

Q：怎么减少重排？

Section titled “Q：怎么减少重排？”

答：

  1. 批量修改 DOM（DocumentFragment）
  2. 离线修改（display:none 后修改，再显示）
  3. 动画用 transform / opacity
  4. 用 contain 隔离
  5. 用 content-visibility 跳过不可见元素

Q：contain 和 content-visibility 有什么区别？

Section titled “Q：contain 和 content-visibility 有什么区别？”

答：

  • contain：告诉浏览器“这个容器内部独立”，但仍然会渲染
  • content-visibility: auto：浏览器跳过不可见元素的渲染，性能更强

Q：长列表用 virtual scroll 还是 content-visibility？

Section titled “Q：长列表用 virtual scroll 还是 content-visibility？”

答：

  • virtual scroll：手动控制渲染数量（适合 10000+ 行）
  • content-visibility：自动跳过（适合任意数量，但首次加载有微小开销）
  • 最佳实践：virtual scroll + content-visibility 双管齐下

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • 重排重绘的代价? 重排必触发重绘;重绘不一定重排。避免在 for 循环里读 layout 属性
  • content-visibility: auto 实战? 列表/文章用 content-visibility: auto; contain-intrinsic-size: 0 500px; 跳过屏外
  • contain: layout/style/paint/size 含义? 告诉浏览器“内部独立”,只重算声明的维度
  • 浏览器渲染流水线? JS → Style → Layout → Paint → Composite(每步都可优化)
  • GPU 加速的限制? transform / opacity / filter / will-change 触发;颜色/边框变化仍走 CPU

📝 小结

Section titled “📝 小结”
  • 渲染流水线里,Layout 最贵、Paint 次之、Composite 最便宜 —— 优化的核心是避开 Layout。
  • 强制同步布局(read 之后立刻 write)是最常见的性能坑,批量读写或缓存到变量可解决。
  • contain: paint/layout 能把元素的布局和绘制限制在内部,减少影响范围。
  • content-visibility: auto 让屏外内容跳过渲染,长列表页面收益明显。
