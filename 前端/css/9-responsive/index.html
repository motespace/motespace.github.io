Q1:移动端适配方案有哪些?

Section titled “Q1:移动端适配方案有哪些?”

答（vw 方案）:

  • 用 postcss-px-to-viewport 插件，CSS 写 px，构建时自动转 vw
  • 设计稿 375px（iPhone 标准），写 padding: 16px → 转成 4.267vw
  • 字体也转 vw（fontViewportUnit: 'vw'），不用 rem
  • 需要固定值的元素用 .ignore- 前缀开头，插件不转换

答（rem 方案）:

  • JS 动态设置 document.documentElement.style.fontSize = clientWidth / 10 + 'px'
  • 所有 rem 元素跟着缩放
  • 设计稿 750px 时，1rem = 75px

Q2:响应式布局怎么做?

Section titled “Q2:响应式布局怎么做?”

答:

  • viewport meta（必须）
  • postcss-px-to-viewport（推荐）或 rem 方案：CSS 写 px，构建/运行时自动转换
  • 媒体查询：@media 适配不同屏幕
  • 弹性布局：Flex、Grid
  • 图片响应：srcset、picture

Q3:移动端 1px 边框问题?

Section titled “Q3:移动端 1px 边框问题?”

答:

  • 移动端 dpr >= 2，1 CSS 像素 = 2 物理像素
  • 1px 边框看起来太粗
  • 解决：transform: scaleY(0.5) + border: none

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • postcss-px-to-viewport 为什么 mediaQuery: false？ → 媒体查询断点如果也被转成 vw，比如 @media (min-width: 768px) 转成 min-width: 204.8vw，断点就彻底错乱了
  • @media (hover: hover) 用在哪？ → 区分触屏/桌面：触屏无 hover，避免 hover 样式在移动端误触发
  • container queries 解决了什么？ → 媒体查询看视口；容器查询看父容器宽度；真正组件级响应式
  • 移动端 1px 问题完整方案？ → transform scale 0.5 + 伪元素 / border-image / viewport 单位 + meta initial-scale=0.5
  • 设计稿 375px vs 750px 区别？ → 375px 是 iPhone 标准设计稿，1px = 1px 直接量；750px 通常是双倍图设计稿，1px 要除 2；两种都可以，375 更直观，750 方便切图
  • 哪些 px 不能转 vw？ → 极端小值（<1px，如 0.5px 描边）、固定宽高容器（如 44px 按钮）、媒体查询断点；解决方案是加 .ignore- 前缀或单独写死值

📝 小结

Section titled “📝 小结”
  • 响应式的三层:媒体查询(视口)、容器查询(容器)、流式尺寸(clamp/vw)。
  • 移动端必配 &lt;meta viewport content="width=device-width, initial-scale=1, viewport-fit=cover"&gt;。
  • iOS 键盘弹出会让 100vh 失真,用 100dvh;刘海和小黑条用 env(safe-area-inset-*)。
  • 1px 边框在高清屏上会变粗,用 minPixelValue 或 transform: scaleY(0.5) 处理。
