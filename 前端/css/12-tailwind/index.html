Q1:Tailwind 和传统 CSS 区别?

Section titled “Q1:Tailwind 和传统 CSS 区别?”

答:

  • 传统 CSS:写样式文件,命名易冲突
  • Tailwind:类即样式,HTML 看起来长但无命名烦恼
  • 设计系统内置,样式一致
  • 适合组件开发

Q2:Tailwind 的优点?

Section titled “Q2:Tailwind 的优点?”

答:

  • 不用想命名
  • 设计一致
  • 自动 tree-shaking
  • 学习成本低(看类名就懂)
  • 适合组件化开发

Q3:Tailwind 的缺点?

Section titled “Q3:Tailwind 的缺点?”

答:

  • HTML 类名长
  • 学习曲线(背类名)
  • 高度定制需写 @apply
  • 不适合复杂动画(用 CSS Modules 更好)
  • SEO 角度 HTML 看起来像 div 工厂

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • Tailwind JIT 模式优势? 按需生成,体积比 v3 PurgeCSS 小 10x;支持任意值(w-[137px])
  • 如何组织 Tailwind 主题? tailwind.config.js 扩展 theme.colors / spacing;设计 token 一处定义
  • @apply 用法? 在 CSS 中复用工具类:.btn { @apply px-4 py-2 bg-blue-500 };慎用,会失去 tree-shaking
  • Tailwind vs UnoCSS? UnoCSS 更快、按需更快、API 更现代(原子化 + 工具类 + 预设);新项目可考虑
  • 设计系统集成? Tailwind + shadcn/ui(headless 组件) + cva(变体管理) 当前主流

📝 小结

Section titled “📝 小结”
  • Tailwind 的核心是约束取值而非「写起来快」—— 间距、字号、颜色收敛到有限集合,视觉自然统一。
  • @apply 适合在需要写传统 class 的场景复用,但不要滥用(会失去 Tailwind 的意义)。
  • 暗色模式靠 dark: 前缀,配合 class 策略在 HTML 上切换 dark class 即可。
  • 和组件库集成要处理样式优先级:用 @layer 声明顺序,或提高选择器权重。
