七、面试常考

Q1:transition 和 animation 区别?

Section titled “Q1:transition 和 animation 区别?”

答:

  • transition:两状态间过渡(必须有触发),1 次
  • animation:多状态连续动画(@keyframes),可循环

Q2:如何优化动画性能?

Section titled “Q2:如何优化动画性能?”

答:

  • 用 transform / opacity(GPU 加速)
  • 避免 width / height / margin(重排重绘)
  • 用 will-change 提示
  • 用 Chrome DevTools Performance 看 Paint / Composite

Q3:transform 性能为什么好?

Section titled “Q3:transform 性能为什么好?”

答:

  • transform 在 GPU 上执行(合成线程)
  • 不触发 layout / paint
  • 只在最后合成,效率高

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • transition vs animation 选哪个? transition:状态变化;A/B 关键帧(复杂动画、多步)
  • will-change 误用? 长期挂着不释放 GPU 内存;只在动画前加,结束移除
  • prefers-reduced-motion 怎么尊重? 媒体查询检测用户系统设置 → 禁用或简化动画
  • JS 动画 vs CSS 动画? 简单状态用 CSS(性能好);复杂时间线用 JS(Web Animations API / GSAP)

📝 小结

Section titled “📝 小结”
  • transition 适合状态切换(hover/显隐),animation 适合有节奏的过程(加载、入场)。
  • 性能上只动 transform 和 opacity 的动画才能跑在合成器上,动 width/top 会触发重排导致掉帧。
  • will-change 不要常驻,只在动画即将开始时加、结束后移除,否则白占 GPU 显存。
  • 必须尊重 prefers-reduced-motion,对晕动症用户关闭动画。
