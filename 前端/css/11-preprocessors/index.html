一、为什么需要预处理器

Section titled “一、为什么需要预处理器”

原生 CSS 缺少:

  • ❌ 变量(虽然 CSS 变量现在有,但有限)
  • ❌ 嵌套
  • ❌ Mixin(代码片段复用)
  • ❌ 函数计算
  • ❌ 模块化(@import 是串行)

预处理器解决这些问题,最后编译成标准 CSS。

七、面试常考

Section titled “七、面试常考”

Q1:Sass 和 Less 区别?

Section titled “Q1:Sass 和 Less 区别?”

答:

  • Sass 用 @use @forward,Less 用 @import
  • Sass 函数更丰富(@function)
  • Less 内置 JS 函数
  • 生态 Sass 更大(Vue、Bootstrap 等用 Sass)
  • 性能 Sass 更快(新版 dart-sass)

Q2:PostCSS 解决什么问题?

Section titled “Q2:PostCSS 解决什么问题?”

答:

  • 自动加浏览器前缀
  • 用最新 CSS 语法,自动降级
  • 压缩、合并
  • 整体是 CSS 的“编译工具”

Q3:为什么需要预处理器?

Section titled “Q3:为什么需要预处理器?”

答:

  • 变量、嵌套、Mixin(原生 CSS 缺)
  • 模块化(@use)
  • 函数计算
  • 大型项目可维护性

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • @import vs @use? @import 重复编译,慢;@use 一次编译,推荐
  • Sass !default 用法? 变量只在未定义时赋值;用于库开发,允许用户覆盖
  • PostCSS 插件链顺序? postcss-import → tailwindcss → autoprefixer → cssnano
  • dart-sass vs node-sass? dart-sass 官方实现,快;node-sass 已废弃(deps 难装)

📝 小结

Section titled “📝 小结”
  • Sass/Less 提供变量、嵌套、mixin、函数,解决原生 CSS 的复用问题。
  • PostCSS 不是预处理器而是转换管线,postcss-preset-env 能用未来的 CSS 特性写现在的代码。
  • 现代项目里 Vite 已内置 PostCSS 和 Sass 支持,零配置。
  • 注意:嵌套写多了会让选择器层级变深、编译产物变大,建议嵌套不超过两层。
