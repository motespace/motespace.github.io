浏览器原理 ​

7 年前端面试必问。简历里写"性能优化"、"PWA"、"首屏优化"都需要浏览器原理支撑。本文按"输入 URL 到页面渲染"主线展开，配真实代码和项目经验。

1. 浏览器架构 ​

1.1 现代浏览器是多进程的 ​

浏览器主进程 (Browser Process)
├── 用户界面（地址栏、菜单、书签）
├── 网络进程管理
└── 渲染进程管理

渲染进程 (Renderer Process) — 每个 Tab 一个
├── GUI 渲染线程（负责页面渲染）
├── JS 引擎线程（执行 JS）
├── 事件触发线程（事件循环）
├── 定时器线程（setTimeout / setInterval）
├── 异步 HTTP 请求线程
└── 合成线程（CSS 动画 / 滚动）

GPU 进程（3D 绘制）
插件进程（PDF、Flash）

为什么是多进程？

  • 稳定性：一个页面崩溃不影响其他页面
  • 安全性：进程隔离，恶意页面无法访问其他进程
  • 性能：不同进程可以并行执行

SafariWebKitJavaScriptCore
FirefoxGeckoSpiderMonkey
Edge (新)BlinkV8

2. 输入 URL 到页面渲染全过程 ​

这是面试最常问的题之一，分 8 个阶段：

1. URL 解析
   ↓
2. DNS 查询（域名 → IP）
   ↓
3. TCP 连接（三次握手）
   ↓
4. 发送 HTTP 请求
   ↓
5. 服务器响应（返回 HTML / CSS / JS / 图片）
   ↓
6. 浏览器解析（HTML → DOM / CSS → CSSOM）
   ↓
7. 渲染（构建渲染树 → 布局 → 绘制）
   ↓
8. 加载完成（合成图层、显示）

2.1 浏览器解析流程 ​

html
<!DOCTYPE html>
<html>
  <head>
    <link rel="stylesheet" href="style.css">
  </head>
  <body>
    <div>Hello</div>
    <script src="app.js"></script>
  </body>
</html>

解析顺序（关键）：

1. HTML 解析 → DOM Tree
   ↓
2. 遇到 <link rel="stylesheet"> → 异步加载 CSS（不阻塞 DOM 解析）
   ↓
3. 遇到 <script>（无 async/defer）→ 阻塞 DOM 解析，执行 JS
   ↓
4. 遇到 <script async> → 异步加载，加载完立即执行（可能阻塞 DOM）
   ↓
5. 遇到 <script defer> → 异步加载，等 DOM 解析完才执行
   ↓
6. DOM + CSSOM 准备好 → 构建渲染树（Render Tree）
   ↓
7. 布局（Layout / Reflow）→ 计算每个节点位置和大小
   ↓
8. 绘制（Paint）→ 像素化
   ↓
9. 合成（Composite）→ 分层显示

2.2 script 标签的 async vs defer ​

html
<!-- 普通 script：阻塞 HTML 解析，下载完立即执行 -->
<script src="a.js"></script>

<!-- async：异步下载，下载完立即执行（不保证顺序） -->
<script async src="b.js"></script>

<!-- defer：异步下载，等 HTML 解析完按顺序执行 -->
<script defer src="c.js"></script>
<script defer src="d.js"></script>

真实项目（会员端 H5）：

html
<!-- 把不重要的脚本放在底部 + defer，提升首屏 -->
<head>
  <link rel="stylesheet" href="critical.css">  <!-- 关键 CSS 内联 -->
  <link rel="stylesheet" href="main.css" media="print" onload="this.media='all'">
  <!-- async 加载非关键 CSS，不阻塞渲染 -->
</head>
<body>
  <!-- 关键内容 -->
  <script defer src="analytics.js"></script>
  <script defer src="monitoring.js"></script>
</body>

3. 浏览器事件循环（与 JS 的区别） ​

3.1 浏览器事件循环 vs JS 事件循环 ​

JS 事件循环（ECMAScript 标准）：

  • 微任务：Promise.then、queueMicrotask
  • 宏任务：setTimeout、setInterval、I/O

浏览器事件循环（HTML 标准，更完整）：

执行栈（同步代码）
    ↓
微任务队列（清空）
    ↓
判断是否需要渲染
    ↓
渲染阶段（如果需要）
    ↓
requestAnimationFrame 回调
    ↓
宏任务队列（取一个）
    ↓
回到执行栈

核心差异：浏览器事件循环在"微任务 → 宏任务"中间多了渲染阶段，给浏览器机会更新 UI。

3.2 requestAnimationFrame ​

js
// 在浏览器下次重绘前调用，60fps 下约 16.67ms 一次
function animate() {
  element.style.transform = `translateX(${pos++}px)`
  requestAnimationFrame(animate)
}
requestAnimationFrame(animate)

与 setTimeout 对比：

特性setTimeoutrequestAnimationFrame
时机至少 N ms 后浏览器下次重绘前
帧率同步❌ 不一定✅ 自动同步
后台标签页仍然执行自动暂停
性能可能掉帧流畅

真实项目（数据大屏）：

js
// 大屏动画必须用 rAF，不用 setTimeout
function startRotation() {
  function tick() {
    angle += 0.5
    radarChart.setOption({ series: [{ data: getNewPoints(angle) }] })
    requestAnimationFrame(tick)
  }
  requestAnimationFrame(tick)
}

4. 强缓存 vs 协商缓存 ​

4.1 浏览器缓存机制 ​

首次请求：服务器返回资源 + 缓存标识
    ↓
二次请求：先看浏览器缓存
    ├── 强缓存命中 → 直接用本地，不发请求
    └── 强缓存未命中 → 发请求，看协商缓存
        ├── 协商缓存命中（资源未变）→ 304，浏览器用本地
        └── 协商缓存未命中（资源变了）→ 200，返回新资源

4.2 强缓存（Cache-Control / Expires） ​

http
# HTTP/1.1（推荐）
Cache-Control: max-age=31536000, immutable

# HTTP/1.0（兼容）
Expires: Wed, 21 Oct 2026 07:28:00 GMT

Cache-Control 指令：

http
Cache-Control: max-age=3600         # 缓存 1 小时
Cache-Control: no-cache             # 不直接用缓存，每次问服务器
Cache-Control: no-store             # 完全不缓存
Cache-Control: private              # 只允许浏览器缓存，CDN 不能
Cache-Control: public               # 所有代理都能缓存
Cache-Control: s-maxage=3600        # CDN 缓存 1 小时
Cache-Control: immutable            # 资源永不过期（带 hash 的文件名用）
Cache-Control: must-revalidate     # 必须重新验证
Cache-Control: stale-while-revalidate=60  # 过期后 60s 内用旧值

4.3 协商缓存（Last-Modified / ETag） ​

http
# 首次请求，服务器返回资源 + 标识
Last-Modified: Wed, 21 Oct 2026 07:28:00 GMT
ETag: "abc123"

# 二次请求，浏览器带上
If-Modified-Since: Wed, 21 Oct 2026 07:28:00 GMT
If-None-Match: "abc123"

# 服务器判断
资源未变 → 304 Not Modified（不带 body）
资源变了 → 200 OK（带新资源）

ETag vs Last-Modified：

ETagLast-Modified
精度哈希指纹，精确到内容秒级，文件内容变了但 mtime 没变会漏
性能计算哈希略慢直接读文件时间，快
适用文件经常改动文件改动频率低

真实项目（商户管理 SaaS）：

js
// Next.js 静态资源自动加 hash
import Image from 'next/image'

// webpack/Vite 自动生成：/static/chunks/main.abcd1234.js
// 配合 Cache-Control: max-age=31536000, immutable
// 永不过期，因为 hash 变了文件名就变了

5. 浏览器存储 ​

5.1 五种存储方式对比 ​

存储方式大小生命周期是否随 HTTP 请求发送适用场景
Cookie4KB可设置过期时间✅ 是（自动带）登录态、CSRF Token
LocalStorage5-10MB永久（除非手动清除）❌用户偏好、本地缓存
SessionStorage5-10MB关闭标签页就清除❌表单临时数据、跨页面状态
IndexedDB几百 MB永久❌大数据离线缓存
Cache API看配额手动管理❌Service Worker 缓存、PWA

5.2 真实项目使用（来自 merchant 项目） ​

js
// 1. 登录态用 HttpOnly Cookie（防 XSS 偷 token）
// 服务器设置：Set-Cookie: token=xxx; HttpOnly; Secure; SameSite=Lax

// 2. 用户偏好用 LocalStorage
localStorage.setItem('theme', 'dark')
localStorage.setItem('language', 'zh-CN')

// 3. 临时数据用 SessionStorage
sessionStorage.setItem('formDraft', JSON.stringify(formData))

// 4. IndexedDB 缓存大量数据（消息列表、离线数据）
const db = await openDB('app-db', 1, {
  upgrade(db) {
    db.createObjectStore('messages', { keyPath: 'id' })
  },
})
await db.put('messages', message)

// 5. Cache API（Service Worker）缓存静态资源
const cache = await caches.open('v1')
await cache.addAll(['/static/main.js', '/static/main.css'])

5.3 存储方案选择决策 ​

登录态 → Cookie（HttpOnly）
用户偏好 → LocalStorage
表单草稿 → SessionStorage
大量数据 → IndexedDB
PWA 资源 → Cache API

6. 同源策略与跨域 ​

6.1 同源策略 ​

同源：协议、域名、端口三者完全相同。

https://example.com:443/page1
                    ↓
跨域：https://api.example.com:443/data    ← 子域名不同
跨域：http://example.com:443/page         ← 协议不同
跨域：https://example.com:8080/api        ← 端口不同
跨域：https://other.com/api                ← 域名不同

同源策略限制：Cookie、LocalStorage、IndexedDB、DOM 访问、AJAX。

6.2 跨域解决方案 ​

CORS（最常用） ​

js
// 服务端（Node.js）
app.use((req, res, next) => {
  res.header('Access-Control-Allow-Origin', 'https://app.com')
  res.header('Access-Control-Allow-Methods', 'GET,POST,PUT,DELETE')
  res.header('Access-Control-Allow-Headers', 'Content-Type,Authorization')
  res.header('Access-Control-Allow-Credentials', 'true')  // 允许带 Cookie
  res.header('Access-Control-Max-Age', '86400')  // 预检请求缓存
  next()
})
js
// 客户端：fetch 跨域请求
fetch('https://api.example.com/data', {
  credentials: 'include',  // 带上 Cookie
  headers: {
    'Content-Type': 'application/json',
  },
})

预检请求（Preflight） ​

http
# 浏览器自动发起 OPTIONS 请求
OPTIONS /api/data HTTP/1.1
Origin: https://app.com
Access-Control-Request-Method: POST
Access-Control-Request-Headers: Content-Type

# 服务器响应
HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://app.com
Access-Control-Allow-Methods: POST

什么时候触发预检：

  • 非简单方法（PUT、DELETE）
  • 非简单请求头（Content-Type: application/json）
  • 带自定义头

JSONP（过时但要知道） ​

js
// 服务端
app.get('/api/data', (req, res) => {
  const callback = req.query.callback
  res.send(`${callback}(${JSON.stringify(data)})`)
})

// 客户端
function jsonp(url, callbackName) {
  const script = document.createElement('script')
  script.src = `${url}?callback=${callbackName}`
  window[callbackName] = (data) => {
    // 处理数据
    document.body.removeChild(script)
  }
  document.body.appendChild(script)
}

缺点：只能 GET、有 XSS 风险。生产别用。

js

nginx

7. 浏览器渲染流程（重要！） ​

7.1 关键路径 ​

DOM + CSSOM
    ↓
Render Tree（只包含可见节点，display:none 不进）
    ↓
Layout / Reflow（计算几何信息）
    ↓
Paint（绘制像素）
    ↓
Composite（合成图层）

7.2 Layout（回流 / 重排） ​

触发条件：

  • 添加 / 删除 DOM
  • 元素尺寸 / 位置改变
  • 内容变化（文字、图片）
  • 浏览器窗口 resize
  • 获取布局信息（offsetWidth、getComputedStyle 等）
js
// ❌ 多次触发布局（强制同步 layout）
const width1 = div.offsetWidth  // 触发 layout
div.style.width = '100px'       // 触发 layout
const width2 = div.offsetWidth  // 又触发 layout

// ✅ 批处理：读写分离
div.style.width = '100px'       // 先写
div.style.height = '200px'      // 先写
const width = div.offsetWidth   // 一次读取

7.3 Paint（重绘） ​

触发条件：

  • 颜色、背景、阴影改变
  • visibility 改变

Layout 一定触发 Paint，但 Paint 不一定触发 Layout。

7.4 Composite（合成） ​

只触发合成，不触发 layout 和 paint 的属性（性能最好）：

  • transform
  • opacity
  • will-change
css
.box {
  /* ✅ 只触发合成，性能好 */
  transform: translateX(100px);
  opacity: 0.5;
  will-change: transform;
}

.box {
  /* ❌ 触发布局和重绘，性能差 */
  left: 100px;
  top: 100px;
  width: 200px;
}

7.5 真实项目（数据大屏） ​

js
// ❌ 用 left/top 做定位动画，每帧都触发 layout
function animate(dom, x) {
  dom.style.left = x + 'px'
  if (x < 100) requestAnimationFrame(() => animate(dom, x + 1))
}

// ✅ 用 transform，只触发合成
function animateFast(dom, x) {
  dom.style.transform = `translateX(${x}px)`
  if (x < 100) requestAnimationFrame(() => animateFast(dom, x + 1))
}

8. Web Vitals（性能核心指标） ​

8.1 三大指标 ​

指标含义目标
LCP (Largest Contentful Paint)最大内容渲染时间< 2.5s
FID / INP首次输入延迟 / 交互到下一帧< 100ms / < 200ms
CLS (Cumulative Layout Shift)累积布局偏移< 0.1

8.3 优化 LCP ​

html
<!-- 1. 关键 CSS 内联 -->
<style>
  .hero { ... }
</style>

<!-- 2. 关键图片 preload -->
<link rel="preload" as="image" href="hero.jpg">

<!-- 3. 字体 preload + font-display -->
<link rel="preload" as="font" href="font.woff2" crossorigin>
<style>
  @font-face {
    font-family: 'Custom';

<!-- 4. 图片懒加载（非首屏） -->

8.4 优化 CLS ​

css
/* ❌ 没指定宽高，图片加载完会撑高 */
<img src="banner.jpg">

/* ✅ 显式指定宽高，浏览器预留空间 */
<img src="banner.jpg" width="800" height="400">

/* ✅ 或者用 aspect-ratio */
<img src="banner.jpg" style="aspect-ratio: 2 / 1">

8.5 优化 INP ​

ts
// 长任务拆分
function longTask() {
  // ❌ 同步执行，阻塞主线程 200ms+
  heavyCalculation()
}

// ✅ 用 scheduler.yield() 让出主线程
async function longTask() {
  for (let i = 0; i < 1000; i++) {
    processItem(i)
    if (i % 100 === 0) {
      await scheduler.yield()  // 让浏览器处理输入
    }
  }
}

9. 浏览器线程与异步 ​

9.1 一个经典问题：setTimeout 真的是 N ms 后执行吗？ ​

js
console.log('1')
setTimeout(() => console.log('2'), 0)
console.log('3')

// 输出：1, 3, 2
// 不是"立即执行"，而是"尽快执行"

原因：

  • setTimeout 把回调放入宏任务队列
  • 当前同步任务执行完 + 微任务清空 + 渲染后才执行

9.2 Promise 和 setTimeout 的执行顺序 ​

js
console.log('start')

setTimeout(() => console.log('setTimeout'), 0)
Promise.resolve().then(() => console.log('promise'))

console.log('end')

// 输出：start, end, promise, setTimeout
// promise.then 是微任务，setTimeout 是宏任务
// 微任务优先于宏任务

9.3 真实项目：避免阻塞主线程 ​

js
// ❌ 同步处理大量数据，主线程阻塞 500ms
function processAllData(items) {
  items.forEach(item => heavyProcess(item))
}

// ✅ 用 setTimeout / requestIdleCallback 拆分
function processInChunks(items, chunkSize = 50) {
  let index = 0
  function processChunk() {
    const chunk = items.slice(index, index + chunkSize)
    chunk.forEach(item => heavyProcess(item))
    index += chunkSize
    if (index < items.length) {
      requestIdleCallback(processChunk)
    }
  }
  processChunk()
}

10. Service Worker 与 PWA ​

10.1 Service Worker 生命周期 ​

注册 → 安装（install）→ 激活（activate）→ 控制页面
                                            ↓
                                       拦截 fetch

10.2 真实代码（来自 member-h5 PWA） ​

js
// 注册
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js')
    .then(reg => console.log('SW registered:', reg))
    .catch(err => console.error('SW failed:', err))
}

// sw.js（Service Worker 文件）
const CACHE_NAME = 'app-v1'
const urlsToCache = ['/', '/styles.css', '/main.js']

// 安装：预缓存关键资源
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then(cache => cache.addAll(urlsToCache))
  )
})

// 拦截请求：缓存优先
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then(response => {
      // 缓存命中直接返回
      if (response) return response

      // 否则请求网络
      return fetch(event.request).then(networkResponse => {
        // 动态缓存
        if (networkResponse.ok) {
          const clone = networkResponse.clone()
          caches.open(CACHE_NAME).then(cache => cache.put(event.request, clone))
        }
        return networkResponse
      })
    })
  )
})

10.3 PWA 离线场景 ​

js
// 会员端 H5 的弱网优化
// 1. 静态资源 cache-first
// 2. API 数据 network-first，失败用 stale-while-revalidate
self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url)

  if (url.pathname.startsWith('/api/')) {
    // API：网络优先，失败用缓存
    event.respondWith(
      fetch(event.request)
        .catch(() => caches.match(event.request))
    )
  } else {
    // 静态资源：缓存优先
    event.respondWith(
      caches.match(event.request).then(r => r || fetch(event.request))
    )
  }
})

const connections = []
self.addEventListener('connect', (event) => {
  const port = event.ports[0]

14. 项目踩过的坑 ​

  1. Cookie 跨域丢失：服务端没设 SameSite=None; Secure，HTTPS 站点下 Cookie 默认不发。
  2. 强缓存导致代码更新失效：不带 hash 的 JS 文件用 Cache-Control: max-age=3600，更新后用户拿不到新版本。
  3. Layout thrashing：循环里读写 offsetWidth 触发反复回流，掉帧严重。
  4. 图片没指定宽高导致 CLS：用户看到的文字突然跳动，体验差。
  5. PWA Service Worker 缓存没失效策略：缓存用了旧版本资源，新版本发布后用户拿不到。
