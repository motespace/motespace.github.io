Q1: React.FC 还推荐用吗？

Section titled “Q1: React.FC 还推荐用吗？”

答：React 18+ 不推荐。原因：

  1. 隐式包含 children（不灵活）
  2. 不支持泛型
  3. 官方在 FAQ 明确不推荐

替代：普通函数 + 显式接口

Q2: 泛型组件怎么写？

Section titled “Q2: 泛型组件怎么写？”

答：&lt;T&gt; 在函数签名，Props 引用 T。TS 自动推导调用时的 T。

Q4: React 19 的 use Hook 解决了什么？

Section titled “Q4: React 19 的 use Hook 解决了什么？”

答：

  • 可以条件调用（不像 useContext）
  • 支持 Promise（替代 useEffect + setState）
  • 支持 Context / AsyncIterable

Q5: Server Component 怎么写 TS？

Section titled “Q5: Server Component 怎么写 TS？”

答：直接用普通 TS 接口，但 Server Component 不能用 hook（‘use client’ 才能用）。

Q6: React Hook Form 性能优势？

Section titled “Q6: React Hook Form 性能优势？”

答：不通过 React state 维护表单（不触发 re-render），ref 直接读取。大型表单性能远超 Formik / Antd Form。

Q7: 状态管理选型？

Section titled “Q7: 状态管理选型？”

答：

  • 小型：useState + Context
  • 中型：Zustand / Jotai
  • 大型：Redux Toolkit + RTK Query
  • 服务端状态：React Query / SWR

面试追问(深化原 Q1-Q7)

Section titled “面试追问(深化原 Q1-Q7)”
  • React.FC 替代写法? function Comp({ name }: { name: string });无需 React.FC 包裹
  • 泛型组件 ref 类型? useRef&lt;HTMLDivElement&gt;(null);非原生 ref 用 ComponentRef&lt;typeof Comp&gt;
  • use Hook + Promise 类型? const data = use(promise) 推导为 Promise resolve 的值
  • Server Component 类型差异? 接收 props 是普通对象(非 Promise);async 组件可 await Promise<T>
  • RHF 的 useForm 类型? useForm&lt;FormValues&gt;() 自动推导 watch / handleSubmit / register

📝 小结

Section titled “📝 小结”
  • React + TS 的关键是** Props 契约**:用 interface 描述,React.FC 现在已不推荐(隐式 children 问题)。
  • 事件处理要单独标类型:React.ChangeEvent&lt;HTMLInputElement&gt;,不要用 any。
  • 泛型组件用 forwardRef + useImperativeHandle(React 19 起 ref 可直接作为 prop,不再需要 forwardRef)。
  • Zustand + TS 推荐 create&lt;T&gt;()() 显式标注状态类型,避免初始值为 {} 时类型被推成空对象。
