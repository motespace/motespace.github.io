const 泛型参数

TS 5.0 引入:让泛型参数默认按 const 推断,字面量类型不再被拓宽。

一、问题:字面量被拓宽

Section titled “一、问题:字面量被拓宽”

普通泛型参数会把字面量类型拓宽成基础类型。这是 TS 的默认行为,因为泛型参数的类型参数位置是「只读」的,推断时会做拓宽。

二、const 泛型参数

Section titled “二、const 泛型参数”

行为等价于给参数加上 as const,但不需要逐个写。

三、真正有用的场景

Section titled “三、真正有用的场景”

1. 保留数组字面量的元素类型

Section titled “1. 保留数组字面量的元素类型”

这个差别在表单校验、路由配置、DSL 场景里非常关键。

2. 保留嵌套对象的字面量类型

Section titled “2. 保留嵌套对象的字面量类型”

不用 const 泛型时,retries 会是 number,fallback.code 会是 number。

3. 从配置推导字面量联合类型

Section titled “3. 从配置推导字面量联合类型”

这是最实用的用法:从一份配置自动推导出字面量联合类型,不用手写。

4. 配合 satisfies 做校验

Section titled “4. 配合 satisfies 做校验”

四、const 泛型 vs as const vs satisfies

Section titled “四、const 泛型 vs as const vs satisfies”
写法 作用位置 效果
as const 表达式 把整个表达式变成 readonly 的字面量类型
const T 泛型参数 让这个泛型参数按 const 方式推断
satisfies T 表达式 用 T 校验表达式,但保留表达式原本推断出的窄类型

最佳组合:用 satisfies 做校验 + as const 或 const 泛型 保窄。

这样既校验了结构,又保留了字面量类型。

五、注意事项

Section titled “五、注意事项”

1. const 泛型不能和 extends 约束冲突

Section titled “1. const 泛型不能和 extends 约束冲突”

约束会限制推断结果,但字面量仍然保留。

2. 推断结果可能过窄

Section titled “2. 推断结果可能过窄”

这正是 const 的目的,但要清楚:返回的对象是 readonly 的。

六、适用版本

Section titled “六、适用版本”
  • TypeScript 5.0+ 才支持 const 泛型参数
  • 搭配 satisfies(也是 5.0 引入)效果最好
  • VitePress 1.6.4 自带的 TypeScript 版本足够新;如果项目 tsconfig 里锁了 <5.0 的 typescript 版本,需要升级

🎯 面试常考

Section titled “🎯 面试常考”

Q1: 为什么泛型参数里的字面量会被拓宽? 类型参数位置被视为「不可变」,TS 在推断时会做拓宽,把 'hello' 拓宽成 string、123 拓宽成 number,以保证泛型函数内部可以安全地接收该类型的其他值。

Q2: const 泛型参数解决什么问题? 让泛型参数按 as const 的方式推断,保留字面量类型和 readonly 属性。典型用途是从配置数组自动推导出字面量联合类型,以及保留数组元素的精确类型。

Q3: as const、const 泛型、satisfies 三者区别? as const 是表达式级的,把整个表达式变成 readonly 字面量;const T 是泛型参数级的,让该参数按 const 推断;satisfies 只做类型校验而不改变推断出的类型。satisfies 保留窄类型,as const 主动收窄。

Q4: 怎么从路由配置推导出路径联合类型?

Q5: const 泛型参数有什么副作用? 推断结果会带 readonly,对象不能改属性、数组不能 push。如果需要可变,用可变类型重新映射(如 [...T])。

📝 小结

Section titled “📝 小结”
  • const 泛型参数让泛型按 as const 推断,保留字面量类型和 readonly。
  • 最实用的场景是从配置数组自动推导出字面量联合类型。
  • satisfies 做校验、as const / const 泛型保窄,三者常配合使用。
  • 副作用是结果变 readonly,需要可变就重新映射类型。
