tsconfig.json 核心配置

一、是什么

Section titled “一、是什么”

tsconfig.json 是 TypeScript 项目的配置文件,告诉编译器:

  • 哪些文件要编译
  • 编译成什么目标(ES5/ES2020 等)
  • 类型检查严格到什么程度
  • 模块解析方式
  • 路径别名
  • 等等

最常用的命令是 tsc --init 生成默认配置,然后按项目需求调整。

三、常用配置详解

3.1 target — 编译目标 JS 版本

Section titled “3.1 target — 编译目标 JS 版本”
  • 老浏览器兼容:ES5(IE 都要死了,除非维护老项目)
  • 现代浏览器 + Node.js:ES2020
  • 最新特性:ES2022(class fields、at() 等)

Vue/React/Vite 项目一般 ES2020 起步。浏览器已经支持 ES2020,Vite 还会再降级。

3.2 module — 模块系统

Section titled “3.2 module — 模块系统”
值 含义 适用
ESNext 原生 ESM Vite/Next.js/Webpack 5
CommonJS Node.js 写 Node 工具包
UMD 通用模块 老库

Vite/Webpack 项目用 ESNext,Node CLI 工具用 CommonJS。

3.3 moduleResolution — 模块解析策略

Section titled “3.3 moduleResolution — 模块解析策略”
值 含义
bundler 假定有打包器(Vite/webpack),允许 import 写扩展名
node16 / nodenext 严格 Node.js 解析
classic 老策略,几乎不用了

Vue/React 项目:用 bundler(配合 module: ESNext)。

3.4 lib — 可用的内置 API 集合

Section titled “3.4 lib — 可用的内置 API 集合”
  • 不写 DOM:浏览器 API(window/document)不可用
  • 不写 ES2020:Promise.allSettled 等新 API 不可用

默认 target 是 ES5 时,lib 不会自动加 ES2020——必须显式写。

3.5 jsx — JSX 编译方式

Section titled “3.5 jsx — JSX 编译方式”
值 含义
react-jsx React 17+ 新 JSX 转换(推荐)
react-jsxdev 开发模式带更多调试信息
react 老 JSX 转换,要 import React from 'react'

四、严格模式(strict)

Section titled “四、严格模式(strict)”

strict: true 等于一次性开启下面 7 个:

选项 作用
noImplicitAny 禁止隐式 any(参数没标注类型时)
strictNullChecks null/undefined 不能随便赋值给其他类型
strictFunctionTypes 函数参数类型严格匹配(逆变)
strictBindCallApply bind/call/apply 的参数必须匹配
strictPropertyInitialization class 属性必须初始化
noImplicitThis this 隐式为 any 时报错
alwaysStrict 自动加 "use strict"

强烈建议新项目全部开启。老项目可以分阶段开启。

六、include / exclude / files

Section titled “六、include / exclude / files”
  • include:要编译的文件(支持 glob)
  • exclude:排除的(默认已排除 node_modules、bower_components、jspm_packages)
  • files:显式列出文件(很少用)

注意:vite/next/react-native 项目里,TS 通常不直接参与构建(Vite 用 esbuild),tsc 只做类型检查。所以 include 决定了哪些文件会被类型检查。

📝 小结

Section titled “📝 小结”
  • strict: true 是起点,一次性打开会暴露大量隐式 any,建议分模块渐进开启。
  • 关键项:target(决定编译到哪)、module/moduleResolution、jsx、paths、include。
  • noUncheckedIndexedAccess 能防住「数组取值永远是 T 而不是 T | undefined」这个高频坑。
  • paths 只影响类型检查,运行时要用 Vite 的 resolve.alias 同步配置。

面试常考

Section titled “面试常考”

Q1:strict 模式包含哪些?

Section titled “Q1:strict 模式包含哪些?”

答:

  • strictNullChecks:null/undefined 区分;不严格时 string | undefined 不能调 string 方法
  • noImplicitAny:禁止隐式 any
  • strictFunctionTypes:函数参数严格
  • strictBindCallApply:bind/call/apply 类型严格
  • strictPropertyInitialization:class 属性必须初始化
  • alwaysStrict:输出 strict 模式 JS
  • useUnknownInCatchVariables:catch 变量是 unknown

Q2:target 怎么选?

Section titled “Q2:target 怎么选?”

答:

  • 现代项目:ES2022 或 ESNext(Vite + esbuild 链)
  • 兼容老浏览器:ES2015(for...of、箭头函数、Promise)
  • 避免 ES5(语法过度降级,代码难读)
  • lib 配合 target:不写 lib 推断默认,需要新 API 显式加

Q3:常见必开选项?

Section titled “Q3:常见必开选项?”

答:

  • strict: true(包含上述 7 项)
  • noUnusedLocals / noUnusedParameters 提示未用变量
  • noFallthroughCasesInSwitch switch 必 break
  • noImplicitReturns 函数必须 return
  • noUncheckedIndexedAccess arr[i] 类型为 T | undefined
  • esModuleInterop 允许 import React from 'react'
