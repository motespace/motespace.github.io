映射类型是「用一套模板批量生成类型」的语法,条件类型是「按条件在类型层面做分支」的语法。

坑 1: 条件类型不分发

Section titled “坑 1: 条件类型不分发”

原因:T 被 string | number 整体代入,不满足「裸类型参数」的分布式条件。解决:包一层 T extends any ? ... : never,或者用 [T] extends [string] 阻止分发。

坑 2: infer 的位置

Section titled “坑 2: infer 的位置”

infer 只能出现在条件类型的 extends 子句里。

坑 3: 递归类型爆栈

Section titled “坑 3: 递归类型爆栈”

循环引用时 TS 会报「类型实例化过深」。解决:加终止条件,或者用接口代替递归别名。

🎯 面试常考

Section titled “🎯 面试常考”

Q1: 映射类型的语法? { [K in keyof T]: ... },K 遍历 T 的所有键。可以加 ? 变可选、加 readonly 变只读、用 - 前缀去掉修饰符、用 as 子句重映射或过滤键。

Q2: infer 是做什么的? 在条件类型中从被检查的类型里提取子类型。比如 T extends (...args: infer P) => any 提取函数参数类型,T extends Promise&lt;infer U&gt; 提取 Promise 的解包类型。

Q3: 什么是分布式条件类型? 当被检查类型是裸泛型参数时,条件类型会分发给联合类型的每个成员。ToArray<string|number> 得到 string[] | number[]。要阻止分发,把类型包成元组 [T] extends [string]。

Q4: 怎么让事件系统的类型安全? 用映射类型定义事件名到事件类型的对应关系,再用 infer 或索引访问让处理器的参数类型随事件名自动推导,传错事件名或用错事件对象都会报错。

Q5: Record<K, V> 和 { [P in K]: V } 有什么区别? Record 只是后者的语法糖,但 K 被约束为 keyof any(即 string | number | symbol),而手写的话 K 不受约束,还能用在更复杂的场景。

📝 小结

Section titled “📝 小结”
  • 映射类型是批量生成类型的语法,as 子句让它能重命名和过滤键。
  • 条件类型是类型层面的三元表达式,裸泛型参数会触发分布式。
  • infer 用于从复杂类型里提取子类型,是很多高级工具类型的核心。
  • 三个经典坑:非分布式、infer 位置限制、递归类型爆栈。
