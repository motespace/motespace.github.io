Q1: Vitest 和 Jest 区别？

Section titled “Q1: Vitest 和 Jest 区别？”

答：

  • Vitest：基于 Vite + esbuild，速度快、Vite 项目零配置
  • Jest：老牌稳定，生态成熟，但配置稍复杂
  • 选型：新项目 / Vite -> Vitest；老项目 / Webpack -> Jest

Q2: 怎么测试自定义 Hook？

Section titled “Q2: 怎么测试自定义 Hook？”

答：用 @testing-library/react 的 renderHook，可以触发 Hook 的副作用。

Q3: 怎么测试带 fetch 的组件？

Section titled “Q3: 怎么测试带 fetch 的组件？”

答：用 MSW 拦截 HTTP，组件代码不变，只改 mocks。

Q4: 测试覆盖率多少合适？

Section titled “Q4: 测试覆盖率多少合适？”

答：业务代码 60-70%，工具库 85%+。追求 100% 会过度测试。

Q5: userEvent 和 fireEvent 区别？

Section titled “Q5: userEvent 和 fireEvent 区别？”

答：

  • fireEvent：触发底层事件（click、change）
  • userEvent：模拟真实用户行为（type 会触发 keydown/input/change）
  • 优先 userEvent，更接近真实。

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • Vitest vs Jest? Vitest:Vite 原生、快、原生 ESM/TS;Jest:成熟、配置复杂、慢
  • vitest 优势? 配置 0(沿用 vite.config);HMR 风格 watch;与 vite 插件同生态
  • 组件测试库选型? React:@testing-library/react;Vue:@vue/test-utils
  • Stub vs Mock vs Spy? Stub:替换实现;Mock:验证行为(被调用几次);Spy:观察既有方法

📝 小结

Section titled “📝 小结”
  • Vitest 快的根因:复用 Vite 的模块转换与依赖图,测试之间共享 transform 结果,不用重复打包。
  • 配置要点:environment: 'jsdom'、globals: true、setupFiles 引入 @testing-library/jest-dom 与清理函数。
  • 组件测试用 Testing Library:断言用户可见行为(getByRole/text),而不是内部 state 与 class。
  • 异步用 waitFor / findBy,不要用固定 setTimeout 等待,否则测试会随机失败。
  • vi.mock 做模块 mock,vi.useFakeTimers() 测定时器,vi.spyOn 测已有模块的调用。
  • 常见坑:测试之间共享状态导致串号 → 每个测试前 reset;mocks 未复位 → vi.restoreAllMocks()。
  • 面试常问「Jest 和 Vitest 区别」:Vitest 更贴合 Vite/ESM、启动快、原生 ESM;Jest 生态成熟、兼容老项目。
