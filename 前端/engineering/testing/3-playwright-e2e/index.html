Q1: Playwright 和 Cypress 区别？

Section titled “Q1: Playwright 和 Cypress 区别？”

答：

  • Playwright：支持 Chromium / Firefox / WebKit，跨浏览器
  • Cypress：支持 Chromium / Firefox / Edge，不支持 Safari
  • 选型：需要 Safari 测试 -> Playwright；只要 Chromium -> Cypress 也行

Q2: 怎么减少 E2E 不稳定性？

Section titled “Q2: 怎么减少 E2E 不稳定性？”

答：

  1. 用 expect 自动等待，不要 waitForTimeout
  2. 用 data-testid 而不是 CSS
  3. 重试机制
  4. 避免依赖时间（用 fixed date mock）

Q3: E2E 测试覆盖多少？

Section titled “Q3: E2E 测试覆盖多少？”

答：只测关键路径（登录、注册、支付、核心流程）。10-20 个测试覆盖 80% 信心。

Q4: 怎么和单元测试配合？

Section titled “Q4: 怎么和单元测试配合？”

答：

  • 单元测试：测函数、Hook、组件逻辑（70%）
  • E2E：测用户视角的关键路径（10%）
  • 两者互补，不重叠

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • Playwright 优势? 跨浏览器(Chromium/Firefox/WebKit)、并行快、自动等待
  • Playwright vs Cypress? Playwright 多浏览器;Cypress 调试体验好但只 Chromium 系
  • E2E 慢怎么办? 并行(workers)、按需跑(受影响路径)、mock 外部依赖
  • 视觉回归? Playwright toHaveScreenshot() 自动比对;小项目实用
  • E2E 调试? --debug 模式;trace viewer;CI 视频录制

📝 小结

Section titled “📝 小结”
  • Playwright 的自动等待是最大优势:断言前自动等元素可操作,不需要手写 waitForTimeout。
  • 三大特性:跨浏览器(Chromium/Firefox/WebKit)、并行执行(多 worker 分片)、内置 trace viewer 可回放每一步。
  • 用 Page Object 封装页面操作、fixtures 做依赖注入(登录态、测试数据),测试用例只写业务步骤。
  • 网络拦截用 page.route() mock 接口,能构造超时、500、脏数据等异常场景。
  • 认证复用:storageState 存下登录后的 cookie,后续测试直接复用,避免每次登录。
  • CI 要做的事:安装浏览器依赖、--shard 分片并行、失败时上传 trace 与截图、禁止重试掩盖不稳定用例。
  • 面试加分:能讲「怎么让 E2E 稳定」——数据隔离(unique 数据 + 幂等清理)、禁止依赖执行顺序、禁 sleep。
