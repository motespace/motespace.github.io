02 AI 编程工具链

了解主流 AI 编程工具，明确每种工具的适用场景，避免用错工具。

[[toc]]

2.1 工具全景图

Section titled “2.1 工具全景图”

  • 代码补全类（IDE 内嵌）

    • GitHub Copilot — 适合：日常代码补全、简单函数生成
    • Cursor (Tab) — 适合：快速代码补全，基于当前文件上下文

  • 对话式编程类（IDE 侧边栏）

    • GitHub Copilot Chat — 适合：代码解释、单文件重构
    • Cursor Chat — 适合：项目级问答、跨文件修改
    • JetBrains AI Assistant — 适合：Java/Kotlin 项目

  • Agent 任务执行类（自主执行）

    • Codex (codex.ai) — 适合：端到端任务、PR 流程、多文件修改
    • Copilot Workspace — 适合：Spec to代码的端到端开发
    • Cursor Agent — 适合：复杂任务、可以自主操作文件

  • 自动化任务类

    • Codex Automate — 适合：定时任务、CI 监控、发布检查
    • GitHub Actions + AI — 适合：PR 自动审查、定时检查
    • CI Pipeline + LLM — 适合：构建失败自动分析

2.2 各工具详细对比

Section titled “2.2 各工具详细对比”

代码补全：Copilot vs Cursor Tab

Section titled “代码补全：Copilot vs Cursor Tab”
维度 GitHub Copilot Cursor Tab
补全速度 快 极快
上下文感知 好 更好（基于项目）
长代码生成 一般 强
价格 10美元/月 20美元/月（含 Pro 功能）
适合场景 日常补全 需要强上下文的长代码

对话式：Copilot Chat vs Cursor Chat

Section titled “对话式：Copilot Chat vs Cursor Chat”
维度 Copilot Chat Cursor Chat
可用范围 VS Code 内 全项目
文件修改 直接改文件 直接改文件
知识库 无 可上传文档
价格 10美元/月 20美元/月

Agent 类：Codex vs Cursor Agent

Section titled “Agent 类：Codex vs Cursor Agent”
维度 Codex Cursor Agent
执行模式 对话 + 任务 自主文件操作
多文件修改 强 强
Skill 系统 有（/automate, /autopilot） 无
多 Agent 协作 支持 不支持
价格 20美元/月 20美元/月
适合任务 端到端任务流（PR 流程、自动化） 单次复杂修改（重构、多文件改动）

2.3 工具选择决策树

Section titled “2.3 工具选择决策树”
  • 任务类型是什么？
    • 单文件/单函数修改：Copilot Chat 或 Cursor Chat 即可
    • 端到端任务（多文件 + 测试 + 验证）：Codex（开 Thread，让 AI 自主执行）
    • PR 自动审查 / 定时检查：Codex Automate 或 /autopilot
    • 日常代码补全：Copilot 或 Cursor Tab
    • 需要参考项目文档/知识库：Cursor Chat（可上传知识库）

2.4 本项目的工具栈

Section titled “2.4 本项目的工具栈”
工具 用途 场景
Codex 主要 AI 协作工具 代码生成、PR 流程、自动化
Copilot IDE 内补全 日常代码片段补全
Codex /autopilot PR 自动审查 保持 PR 可合并状态
Codex /automate 定时任务 CI 监控、依赖检查
Codex Canvas 可视化分析 数据图表、性能分析报告

2.5 工具链协同示例

Section titled “2.5 工具链协同示例”
  • 日常开发（Copilot）：IDE 内实时补全
  • 单文件修改（Copilot Chat）：解释、重构单文件
  • 端到端任务（Codex）：新功能开发，AI 生成 to跑测试 to报告
  • PR 流程（Codex /autopilot）：自动审查 + 解决冲突
  • 定时任务（Codex /automate）：自动化 CI 监控

2.6 常见误区

Section titled “2.6 常见误区”
误区 正确做法
所有任务都用 Copilot Chat Copilot Chat 适合单文件，复杂任务用 Codex
Codex 和 Copilot 功能重复 两者互补：Copilot 做补全，Codex 做任务
AI 生成的代码不用测 AI 幻觉率存在，所有 AI 生成代码必须跑测试验证
直接让 AI 写整个功能 先拆解任务，AI 每次只做一个闭环子任务

面试常考

Section titled “面试常考”

Q1:AI 编程工具 3 大类?

Section titled “Q1:AI 编程工具 3 大类?”

答:

  • 补全型:Copilot、Codeium(IDE 插件,行内补全)
  • 任务型:Codex、Cursor Composer(端到端任务)
  • 专项型:v0(UI 生成)、Bolt(全栈 demo)
  • 选:日常编码补全型;复杂任务用任务型

Q2:Codex 工具栈包含什么?

Section titled “Q2:Codex 工具栈包含什么?”

答:

  • MCP:Model Context Protocol(连接外部工具)
  • Skill:可复用的工作流定义
  • AGENTS.md:项目级规则文件
  • Automate:定时任务(heartbeat / cron)
  • Sub-agent:多 agent 协作

Q3:工具选型决策树?

Section titled “Q3:工具选型决策树?”

答:

  • 改 1-2 个文件:用补全型
  • 跨多文件改动:用 Agent(Codex)
  • 探索新想法/UI:用 v0 / Bolt
  • 团队协作:用 Codex + AGENTS.md 统一规范

📝 小结

Section titled “📝 小结”
  • 工具全景:IDE 内补全(Copilot/通义灵码)、CLI 代理(Codex CLI/Claude Code)、IDE 内的 Agent 面板(Cursor/Cline)、CI 里的自动化(自动 review、自动修 bug)。
  • 选择标准:上下文能力(能否读全仓库)、工具能力(能否跑命令、跑测试)、可控性(能否限制改动范围)、合规(代码是否出网)。
  • 最佳实践是「分层用」:补全写样板、代理做重构与批量修改、CI 做 review 与回归。
  • 常见误区:把 Agent 当搜索引擎问概念(不如直接查文档)、不给验收标准让它猜、一次给太大任务导致返工。
  • 面试可讲一个真实闭环:需求 → 让 Agent 先读代码给方案 → 人工确认 → 实现 → 自动跑测试 → review 修正 → 沉淀规则。
