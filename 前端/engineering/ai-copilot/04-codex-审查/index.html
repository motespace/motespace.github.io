04 Codex Code Review

用 Codex 代替人工做 PR 的初筛审查，节省 60% 的 Review 时间。

[[toc]]

4.1 传统 Review vs AI Review

Section titled “4.1 传统 Review vs AI Review”
维度 传统人工 Review AI Review
耗时 30 分钟 / PR 2 分钟 / PR
覆盖范围 只看关键路径 全量扫描
侧重点 业务逻辑正确性 语法/风格/明显 bug
发现深度 依赖经验，容易漏 能发现人容易忽略的模式问题

AI Review 的定位：做 80% 的初筛，人工只看 AI 标出的问题。

传统流程： PR 创建 → 人工 Review（30min）→ 反馈 → 修复 → 再 Review → …

AI Review 流程： PR 创建 → AI Review（2min）→ 反馈 → 人工 Review（只看 AI 标出的问题，10min）→ 修复 → AI Review → …

Section titled “4.3 Review 结果解读”

Section titled “通过（无需修改）”
  • TypeScript 类型定义完整
  • 组件命名符合规范
  • CSS 样式无泄漏

建议修改

Section titled “建议修改”

[medium] 第 45 行：重复的网络请求 getUserInfo() 在 useEffect 和 handleTabChange 里都调用了 建议：提取到自定义 hook 中统一管理

[high] 第 78 行：XSS 风险 userInfo.nickname 直接插入 innerHTML 建议：用 textContent 或 react dangerouslySetInnerHTML 配合 sanitize

必须修复

Section titled “必须修复”

[critical] API 错误未处理 const res = await getVipData() 没有 catch 建议：添加 try-catch 和 error 状态处理

4.4 Review 的边界

Section titled “4.4 Review 的边界”

AI Review 不是万能的，这些事 AI 做不了：

AI 能发现 AI 发现不了
语法错误、类型不完整 业务逻辑是否正确
明显的空指针 这个功能是否符合产品需求
代码风格不一致 这个改动是否影响其他模块
重复的网络请求 数据竞态条件
简单的 XSS 风险 架构设计是否合理
测试覆盖是否充分 是否符合公司编码规范（需要上下文）

4.6 建立 Review 习惯

Section titled “4.6 建立 Review 习惯”

PR 作者（你）：

  • PR 创建前自己先用 /review 自审一遍

面试常考

Section titled “面试常考”

Q1:AI Review vs 人工 Review?

Section titled “Q1:AI Review vs 人工 Review?”

答:

  • AI:24h 可用、一致性高、覆盖广;但缺业务理解
  • 人工:业务理解、安全敏感、架构决策;但主观、慢
  • 实战:AI 兜底 + 人工重点 review

Q2:/review 关注什么?

Section titled “Q2:/review 关注什么?”

答:

  • 正确性:逻辑、边界、错误处理
  • 性能:不必要计算、N+1、循环陷阱
  • 风格:命名、可读性、复杂度
  • 安全:输入校验、敏感信息泄露

Q3:Review 输出规范?

Section titled “Q3:Review 输出规范?”

答:

  • 严重等级:P0(必修)/ P1(应修)/ P2(可选)
  • 原因:为什么是问题
  • 建议:怎么改
  • 不接受反驳时:直接 “LGTM”

📝 小结

Section titled “📝 小结”
  • AI Review 的价值在于覆盖面广 + 不知疲倦,传统人工 review 受时间和熟悉度限制。
  • 重点让 AI 看:边界条件、空指针、错误处理、并发/竞态、命名一致性、是否有安全隐患、测试是否覆盖关键路径。
  • 输出要分级:必须改(P0/P1)/建议改(P2)/可选(P3),否则一堆 nit 会淹没真问题。
  • AI Review 的边界:它看不出「业务语义对不对」「这次改动该不该做」,也容易误报风格问题;必须有人类复核。
  • 建立习惯:每个 PR 必过 AI review → 人工筛选 → 用 /review 的问题清单走一遍自己的代码。
  • 面试可讲:把 AI review 接进 CI,要求「P0/P1 未解决不允许合并」,缺陷率变化是多少。
