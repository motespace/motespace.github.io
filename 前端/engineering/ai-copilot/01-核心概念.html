1.1 两种 AI 使用模式 ​

模式描述举例覆盖率
AI as Consultant（顾问）AI 给建议，人来执行问这段代码有什么问题~30%
AI as Agent（代理）AI 独立完成，人做决策把函数重构并补全测试~80%

大多数人的问题：一直在用"顾问模式"，没有切换到"代理模式"。

顾问模式（你做 AI 也在做）： 你：帮我写一个防抖函数 → AI：好的，这是代码 → 你：copy → 用

代理模式（你做决策 AI 执行）： 你：把这个模块的重构任务交给 AI，AI 生成 → 跑测试 → 报告结果

1.2 AI 的能力边界 ​

AI 擅长的事 ​

  • 重复性代码生成：CRUD、格式化、类型定义
  • 代码解释和文档：给函数写注释、生成 README
  • 单函数重构：提取变量、改命名、简化逻辑
  • 测试生成：给定函数签名生成边界用例
  • 技术调研：解释概念、对比方案、找参考链接
  • 文案生成：PR 描述、CHANGELOG、提交信息

AI 不擅长的事 ​

  • 业务逻辑理解：不知道你项目的领域知识
  • 多文件关联修改：改了一个文件，需要改其他 N 个相关文件
  • 真实运行时行为：无法感知网络/数据库/第三方服务
  • 安全/并发/迁移：这些需要人来判断和兜底
  • 模糊需求：需求不清晰时 AI 会瞎猜

1.3 有效协作的核心原则 ​

原则 1：给 AI 足够上下文 ​

差的 prompt（AI 瞎猜）： 写一个登录函数

好的 prompt（AI 知道要做什么）： 我用 Next.js + JWT + Cookie，实现会员登录：

  • POST /api/login 接收
  • 成功后 set-Cookie，key 是 Authorization
  • 密码用 bcrypt.compare 比对
  • 已经有 UserService.getByAccount 方法 请写这个 API 路由，用 TypeScript，参考项目现有风格

原则 2：让 AI 做闭环，不要只做一步 ​

差的协作（AI 只做一步）： 你：写一个排序算法 → AI 写完 → 你 copy → 结束

好的协作（AI 做闭环）： 你：实现这个排序函数，要求： 1. 写函数 + 单元测试（覆盖边界：空数组、单元素、已排序、逆序） 2. 跑测试 3. 如果测试失败，修复后重新跑 4. 最后把结果报告给我

原则 3：AI 的输出需要验证 ​

AI 会产生"幻觉"（hallucination），包括：

  • 虚假 API：声称某个库有这个函数，实际不存在
  • 错误类型：TypeScript 类型报错了，AI 说加 any 就行
  • 过期文档：引用了已废弃的 API 版本

验证方法：

  • 跑测试 / 类型检查
  • 查官方文档确认
  • 问 AI：这个 API 在哪个版本引入的？

原则 4：拆解任务是 AI 能做的前提 ​

AI 搞不定的模糊任务： 你：把这个页面做国际化

AI 能搞定的拆解任务： 你：这个页面需要国际化： 1. 所有中文硬编码文本找出来（我给你文件路径） 2. 生成 i18n key 列表 3. 替换到代码中 4. 补充 zh/en 两个语言文件 5. 跑 lint 验证无遗漏

1.4 Codex 专属概念 ​

Thread（线程） ​

Codex 中每个 Chat 就是一个 Thread，每个 Thread 有独立上下文：

  • Thread 内 AI 能记住完整的对话历史
  • 不同 Thread 之间的上下文不共享
  • 所以：每个任务开一个 Thread，避免上下文污染

Skill（技能） ​

预置的 AI 行为规范：

  • /automate — 创建自动化任务
  • /autopilot — 保持 PR 处于可合并状态
  • /review — AI Code Review
  • /canvas — 生成可视化图表

Agent（子代理） ​

Codex 可以 Spawn 子 Agent 独立执行任务：

  • 主 Agent 做规划和协调
  • 子 Agent 并行执行独立子任务
  • 适用于：多个文件同时修改、并行调研

Worktree（工作树） ​

独立的 Git 分支 checkout，互不干扰：

  • 适合：实验性重构、不确定是否要合并的工作
  • 每个 Worktree 有独立文件系统
  • 主线程和 Worktree 之间可以切换

1.5 本章小结 ​

AI 协作的核心在于：把 AI 当作一个初级工程师而不是搜索引擎。

  • 给足够的上下文（项目信息 + 需求描述 + 约束条件）
  • 拆解任务，让 AI 做闭环
  • AI 输出必须验证（跑测试 / 类型检查）
  • 用 Codex 的 Thread / Skill / Agent 提升协作效率

面试常考 ​

Q1:AI 编程的两种使用模式? ​

答:

  • Copilot 模式:实时补全、写单段代码;IDE 内
  • Agent 模式:接受任务、端到端改动;CLI / IDE 插件
  • 选:小改用 Copilot;大任务用 Agent
  • 未来:Agent 模式占比越来越大

Q2:AI 编程的 3 大局限? ​

答:

  1. 幻觉:编造不存在的 API;必须查文档/源码
  2. 上下文限制:大项目容易"看不全";需要精确范围
  3. 执行盲点:不理解业务规则、团队约定;需明确约束

Q3:有效协作 3 原则? ​

答:

  • 明确任务:目标 + 上下文 + 约束 + 验收标准
  • 小步迭代:复杂任务分步;每步确认
  • 验证输出:必读 diff;跑测试;看效果
