Monorepo 工程实践 ​

Monorepo 不只是工具，还要解决版本策略、CI/CD、协作流程。

一、版本策略 ​

1.1 固定版本（Fixed） ​

所有包同版本，统一发版：

@my/ui: 1.0.0
@my/utils: 1.0.0
@my/web: 1.0.0

下一个版本：全部升 2.0.0

适用：包之间强耦合、用户感知一个版本号（如 Material-UI）

1.2 独立版本（Independent） ​

每个包独立版本：

@my/ui: 1.2.3
@my/utils: 2.0.1
@my/web: 3.1.0

适用：包之间松耦合、业务代码各自迭代

1.3 混合模式 ​

@my/ui: 固定版本（设计系统）
@my/utils: 独立版本（业务工具）
@my/web: 独立版本（应用）

二、Changesets（推荐工具） ​

2.1 是什么 ​

@changesets/cli 管理版本变更、生成 changelog、自动开 PR。

2.2 安装 ​

bash
pnpm add -D -w @changesets/cli
pnpm changeset init

2.3 添加 changeset ​

bash
# 给改动加 changeset
pnpm changeset

# 交互式选择：
# ? Which packages would you like to include?
#   - @my/ui
# ? What kind of change is this?
#   - major / minor / patch
# ? Write a summary
#   "feat: add DatePicker component"

会生成 .changeset/random-name.md：

md
---
'@my/ui': minor
---

feat: add DatePicker component

2.4 版本 + changelog ​

bash
# 自动 bump 版本 + 生成 CHANGELOG.md
pnpm changeset version

# 提交变更
git add .
git commit -m "chore: version packages"

2.5 发布 ​

bash
# 自动发布到 npm
pnpm changeset publish

# CI 自动触发
# .github/workflows/release.yml

2.6 完整 release.yml ​

yaml
name: Release
on:
  push:
    branches: [main]

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0
      - uses: pnpm/action-setup@v2
      - run: pnpm install
      - run: pnpm changeset version
      - run: pnpm changeset publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
      - uses: pnpm/action-setup@v2
      - run: git commit -am "chore: release"
      - run: git push

三、CI/CD ​

3.1 增量构建 + 远程缓存 ​

yaml
# .github/workflows/ci.yml
name: CI
on: [pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: pnpm/action-setup@v2
      - run: pnpm install
      - run: turbo run build test lint --filter=[origin/main]...
        env:
          TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
          TURBO_TEAM: ${{ vars.TURBO_TEAM }}

3.2 单独构建某个包 ​

yaml
# 触发：标签推送
on:
  push:
    tags: ['v*']

jobs:
  publish-ui:
    - run: turbo run build --filter=@my/ui
    - run: pnpm changeset publish

3.3 危险操作 PR 检查 ​

yaml
# 检测依赖循环、版本冲突
- run: pnpm dlx syncpack list-mismatches
- run: pnpm dlx depcheck

四、依赖管理 ​

4.1 共享依赖 vs 子包依赖 ​

❌ 每个子包各自装 react（重复安装）
ui: react ^18.2.0
utils: react ^18.2.0
web: react ^18.2.0

✅ 通过 workspace 共享
ui 不装 react（web 装）
但 ui 不能独立运行（需要 web 提供）

最佳实践：

  • 核心框架（React、Vue）：装到每个包，让每个包可独立 build
  • 工具库（lodash、dayjs）：装到每个包
  • 构建工具（typescript、vite）：装到根 -w

4.2 版本统一（pnpm.overrides） ​

json
{
  "pnpm": {
    "overrides": {
      "react": "^18.2.0",
      "typescript": "^5.3.0"
    }
  }
}

强制所有包用指定版本。

4.3 安全审计 ​

bash
# 检查所有包的安全漏洞
pnpm audit

# 自动修复
pnpm audit --fix

7.2 目录结构 ​

my-monorepo/
  - apps/         # 应用（可独立部署）
  - packages/     # 包（可发布到 npm）
  - tools/        # 内部工具脚本
  - docs/         # 文档
  - scripts/      # 仓库级脚本

7.3 分支策略 ​

main 分支：所有包 latest
feat/ui-new-component：只在 ui 包变更
release/v2.0.0：发版分支

7.4 Commit 规范 ​

feat(ui): add DatePicker
fix(utils): formatDate timezone bug
docs(readme): update installation
chore(deps): upgrade react 18.3.0

八、迁移到 Monorepo ​

8.1 何时迁移 ​

- 多个项目有大量重复代码
- 需要共享组件库、TypeScript 类型、ESLint 配置
- 跨项目重构越来越多

8.2 迁移步骤 ​

bash
# 1. 初始化 Monorepo
mkdir my-monorepo && cd my-monorepo
pnpm init
cat > pnpm-workspace.yaml << 'EOF'
packages:
  - 'packages/*'
  - 'apps/*'
EOF

# 2. 把现有项目迁移
git mv ../old-project packages/ui
# 改 package.json: name 改为 @my/ui

# 3. 安装
pnpm install

# 4. 验证
pnpm -r run build
pnpm -r run test

8.3 渐进式迁移 ​

阶段 1：单仓库 + pnpm workspace（先合并配置）
阶段 2：拆分共享代码到 packages/ui
阶段 3：接入 Turborepo
阶段 4：接入 Changesets
阶段 5：CI/CD + 远程缓存

九、面试高频追问 ​

Q1: Monorepo 缺点是什么？ ​

答：

  • 构建慢（即使有缓存）
  • 权限控制难（所有人看所有代码）
  • 依赖冲突（版本兼容）
  • 学习成本（新人要理解整个仓库结构）

Q2: 怎么选版本策略？ ​

答：

  • 设计系统/工具库 -> 固定版本
  • 业务代码 -> 独立版本
  • 看用户期待：用户期望看到一个统一版本号还是多个子版本？

Q3: Changesets 好处？ ​

答：

  • 强制开发者写 changelog
  • 自动 bump 版本
  • 自动生成 release PR
  • 历史变更可追溯

Q4: 大型 Monorepo 怎么避免代码混乱？ ​

答：

  • 严格的 package 边界（每个包有 owner）
  • CODEOWNERS 文件
  • 跨包 import 受限（ESLint rules）
  • CI 检查循环依赖

Q5: 单仓 50+ 包，CI 怎么不慢？ ​

答：

  • Turborepo 增量构建 + 远程缓存
  • 按需触发（只跑变更包）
  • 拆 CI（按包分类并行）
  • 用 Nx 的 affected 命令

面试追问(深化原 Q1-Q5) ​

  • 代码共享 3 种? 源码引用(workspace:*)、构建产物(lib + 版本号)、运行时加载(MF)
  • 包发布最佳实践? Changesets 管理版本;语义化版本;主版本升级前发 deprecation 警告
  • TypeScript Project References? 子包独立 tsc 编译;references 配置;tsc -b 增量编译
  • ESLint 跨包配置? 根 eslint-config 包;子包 extends;Flat Config(ESLint 9+)更简洁
