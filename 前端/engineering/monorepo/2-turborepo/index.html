Monorepo 的“任务编排层”：增量构建 + 本地/远程缓存。 本文按“原理 → 配置 → 实战”组织。

1.2 Turborepo 解决

Section titled “1.2 Turborepo 解决”
  • 增量构建：只构建受影响的包（Git diff 判定）
  • 任务编排：按依赖顺序自动 topological 排序
  • 本地缓存：.turbo 目录缓存构建产物，未变化包秒过
  • 远程缓存：Vercel / 自部署 S3 / SSH，团队共享

Section titled “3.3 关键字段”
字段 含义

十一、面试高频追问

Section titled “十一、面试高频追问”

Q1: Turborepo 和 Nx 区别？

Section titled “Q1: Turborepo 和 Nx 区别？”

答：

  • Turborepo：轻量、专注任务编排 + 缓存、Vercel 生态
  • Nx：完整生态（代码生成器、依赖图、插件市场）、学习曲线高
  • 选型：中小项目 Turborepo，大型企业级 Nx

Q2: Turborepo 怎么知道哪些包变了？

Section titled “Q2: Turborepo 怎么知道哪些包变了？”

答案：两种方式：

  1. 本地缓存通过 inputs hash 判定
  2. Git diff 通过 –filter=[origin/main] 判定

Q3: 远程缓存安全吗？

Section titled “Q3: 远程缓存安全吗？”

答：默认上传产物 hash，不上传源码。但产物里可能包含 .env 编译结果，要排除。

Q4: Turborepo 能处理 Vue/React 混合吗？

Section titled “Q4: Turborepo 能处理 Vue/React 混合吗？”

答：可以。每个包的 build script 是独立的，可以 vue-cli + next.js + vite 混用。

面试追问(深化原 Q1-Q4)

Section titled “面试追问(深化原 Q1-Q4)”
  • Turborepo 核心能力? 任务编排 + 远程缓存 + 增量构建;比 nx 轻量
  • 远程缓存原理? 把任务输出 hash 化,缓存到云;同输入命中缓存直接返回
  • Turborepo vs Nx? Turbo:轻、只做缓存/编排;Nx:重,全功能(图分析、代码生成)
  • Pipeline 配置? turbo.json 配 pipeline.build.dependsOn: ['^build'] 拓扑排序

📝 小结

Section titled “📝 小结”
  • Turborepo 的价值是任务图 + 远程缓存:按依赖关系编排任务,命中缓存就直接复用产物,CI 时间能降一半以上。
  • turbo.json 三件套:pipeline(旧版)/tasks(新版)定义任务与依赖、outputs 声明产物目录(缓存 key 的基础)、globalDependencies 声明影响所有任务的输入。
  • dependsOn: ["^build"] 表示先构建依赖包,dependsOn: ["build"] 表示先构建自己。
  • 缓存 key = 任务 + 依赖图 + 输入文件 hash,所以产物必须声明到 outputs,否则会缓存到空。
  • 常用命令:turbo run build、turbo run build --filter=@app/web、--force 跳过缓存。
  • 面试加分:讲清「缓存命中率为 0 的原因通常是 outputs 没配或 globalDependencies 太大」。
