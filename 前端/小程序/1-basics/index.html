微信小程序基础与运行机制

小程序和 H5 的根本区别不在 API,而在运行模型: H5 是一个 WebView 跑网页,小程序是双线程各管一段。

1. 和 H5 的本质区别

Section titled “1. 和 H5 的本质区别”
H5 小程序
渲染环境 浏览器 DOM 逻辑层 JSCore + 视图层 WebView,双线程
逻辑与视图 同一线程 两个线程,靠 Native 层通信
DOM 操作 直接操作 不能直接操作,只能 setData
线程 单线程(事件循环) 逻辑层单线程 + 渲染层异步

1.1 双线程模型

Section titled “1.1 双线程模型”

为什么这么设计:逻辑层不阻塞视图层的渲染,保证「界面不卡」; 代价是通信有成本(setData 要跨线程传数据)和不能直接操作 DOM。

1.2 setData 是同步的「假象」

Section titled “1.2 setData 是同步的「假象」”

但视图层是异步拿到的。连续多次 setData 会被合并成一次通信(见 setData 原理)。

2. 目录结构与代码组织

Section titled “2. 目录结构与代码组织”

app.json 的 pages 字段是入口表:第一个是首页。页面路径不带扩展名。

注意 permission 与 requiredPrivateInfos: 调隐私接口(如 getLocation、chooseAddress)必须在 app.json 里声明用途, 否则审核会被拒,或者调用直接失败。

3. WXML:数据绑定与渲染

Section titled “3. WXML:数据绑定与渲染”

wx:key 极其重要:不写的话列表增删会复用错位(和 React 的 key 一个道理), 选 wx:key="id"(数据里的 id 字段)或 wx:key="*this"(元素本身)。

事件:

bind: 语法可以指定冒泡阶段(bind:tap 是冒泡阶段,bind:tap.capture 是捕获阶段)。

4. WXSS 与样式作用域

Section titled “4. WXSS 与样式作用域”
  • WXSS 是 CSS 的子集,不支持通配选择器 *(小程序会报错)
  • 组件样式默认隔离(类似 Vue 的 scoped),外部样式不影响组件内部
  • 全局样式写在 app.wxss,能作用于所有页面;要影响具体组件可以用 styleIsolation: 'apply-shared'

rpx 单位:750rpx = 屏幕宽度,自动适配不同机型。

5. 小程序与 Web 的能力边界

Section titled “5. 小程序与 Web 的能力边界”
能力 小程序 说明
DOM 操作 ❌ 只能 setData
localStorage ✅ wx.setStorageSync,单 key 1MB,总 10MB
Cookie ⚠️ 不是浏览器 cookie,只能用 wx.setStorage 或自建
页面跳转 ⚠️ wx.navigateTo,不能改地址栏
新窗口 ❌ 小程序没有多标签页概念
分享 ✅ onShareAppMessage
支付 ✅ 需要商户号 + 资质

6. 面试常考

Section titled “6. 面试常考”

Q1:小程序和 H5 有什么区别?

Section titled “Q1:小程序和 H5 有什么区别?”

答:核心是运行模型。小程序是双线程:逻辑层跑 JS、视图层负责渲染, 两者通过 Native 层通信,所以逻辑层不能直接操作 DOM,只能用 setData; H5 是单线程 + 直接 DOM 操作。另外小程序有平台能力(支付/分享/扫码)、 有审核和包体积限制、启动时先下载代码包再渲染。

Q2:为什么小程序不能直接操作 DOM?

Section titled “Q2:为什么小程序不能直接操作 DOM?”

答:因为视图层和逻辑层是两个线程。直接操作 DOM 会绕过框架的虚拟树, 导致状态和视图不一致(数据变了但视图没变,或者反过来)。 setData 的过程是:框架在逻辑层生成新的虚拟树 → 序列化差异 → 跨线程发给视图层 → 视图层做最小 DOM 操作。

Q3:app.json 有哪些关键配置?

Section titled “Q3:app.json 有哪些关键配置?”

答:pages(页面路径表,第一个是首页)、window(导航栏、背景色、下拉刷新)、 tabBar、permission(隐私接口用途声明,不给会被拒审)、requiredPrivateInfos、 subPackages(分包)、preloadRule(预下载规则)。
