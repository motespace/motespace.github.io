小程序登录流程与鉴权

小程序没有 cookie 也没有 session,登录是用 code 换 token的两段式流程。 面试里最常追问的是「code 是什么」「token 存哪」「过期怎么办」。

1. 完整流程

Section titled “1. 完整流程”

核心交换:前端永远拿不到 session_key,也永远拿不到 secret。

2. 关键接口

Section titled “2. 关键接口”

2.1 wx.login

Section titled “2.1 wx.login”

坑:

  • code 只能用一次,重复用会失败
  • 有效期 5 分钟,过期要重新 wx.login
  • 必须用户主动触发(不能自动调用),部分场景还会弹授权框

2.2 code2session(后端调)

Section titled “2.2 code2session(后端调)”

返回:

字段 含义
openid 用户在当前小程序下的唯一标识
unionid 用户在同一开放平台账号下多个应用间的统一标识(需要绑开放平台)
session_key 会话密钥,用户加密数据要用它解密,不能给前端

3. openid / unionid / session_key

Section titled “3. openid / unionid / session_key”
  • openid:应用内唯一。要跨应用识别同一用户,必须用 unionid。
  • unionid:需要把小程序绑定到微信开放平台账号,才有。
  • session_key:仅在用户授权后用于解密用户数据(手机号、encryptedData)。

session_key 的正确用法:后端存起来,用户授权拿到 encryptedData 后, 后端用 session_key 解密。任何时候都不能把 session_key 传到前端。

5. token 过期与续期

Section titled “5. token 过期与续期”

注意并发:多个请求同时 401 时只发一次刷新请求(上面用 refreshing 做了单飞), 否则会并发刷新导致 token 互相覆盖。

6. 静默登录:不打扰用户

Section titled “6. 静默登录:不打扰用户”

不是所有场景都需要用户点按钮。可以用 wx.getUserProfile 的替代方案:

区别:

  • wx.login:静默,不需要用户点击,拿 code 无需授权,但拿不到用户信息
  • wx.getUserProfile:需要用户点击,拿到头像昵称
  • wx.getPhoneNumber:需要用户点击 + 按钮 open-type,拿手机号

合规红线:不能静默收集用户信息,getUserProfile 必须是用户点击触发。

7. 面试常考

Section titled “7. 面试常考”

Q1:小程序登录的完整流程是什么?

Section titled “Q1:小程序登录的完整流程是什么?”

答:前端调 wx.login 拿一次性 code(5 分钟有效)→ 发给后端 → 后端带 appid/secret 调微信 code2session 换 openid/session_key → 后端查用户并签发自己的 token → 返回给前端 → 前端存起来,后续请求带 Authorization 头。 前端永远拿不到 secret 和 session_key。

Q2:code 是什么?有什么特点?

Section titled “Q2:code 是什么?有什么特点?”

答:code 是微信下发给小程序的临时登录凭证,用来换取 openid 和 session_key。 特点:一次性(用完即失效)、5 分钟过期、必须由 wx.login 主动触发获取。

Q3:openid、unionid、session_key 有什么区别?

Section titled “Q3:openid、unionid、session_key 有什么区别?”

答:openid 是用户在当前应用下的唯一标识;unionid 是同一开放平台账号下 跨应用的统一标识(小程序要绑开放平台才有);session_key 是会话密钥, 用于解密用户授权数据,只能存服务端,绝不能下发前端。

Q4:token 过期了怎么处理?

Section titled “Q4:token 过期了怎么处理?”

答:用短期 access token + 长期 refresh token。access token 过期请求返回 401, 客户端用 refresh_token 换新的并重放原请求。注意并发场景要加「单飞」控制, 避免多个 401 同时刷新互相覆盖 token。
