2.2 unhandledrejection

Section titled “2.2 unhandledrejection”

⚠️ unhandledrejection 只能兜底漏掉的 rejection。所有请求都应该显式 catch —— 否则接口失败在监控里表现为一堆 Promise 错误，噪音掩盖真问题。

2.3 React 错误边界

Section titled “2.3 React 错误边界”

错误边界的三个限制（高频追问）：

限制 原因 应对
只能捕获子树错误 React 树之外（事件处理器、异步）不会冒泡 事件处理器手动 try/catch
只能捕获渲染/生命周期错误 事件回调里的 setState 报错不会被捕获 自己 try/catch + 上报
没有兜底 UI 就白屏 默认会卸载整棵树 必须提供 fallback

推荐的分层策略：

ERP 后台尤其重要：一个表格接口挂了，不应该整页白屏 —— 应该表格区域显示“加载失败，点击重试”，其他区域照常用。

告警规则（Prometheus 风格）：

分母很重要：错误率而不是错误数。1000 个用户下 10 个错误是 1%，100 个用户下 10 个错误是 10%。只看绝对数会在流量高峰时误报，在低峰时漏报。

六、监控自身的坑

Section titled “六、监控自身的坑”
坑 症状 解决
上报接口被业务阻塞 报错时页面更卡 sendBeacon / 独立域名 / 失败丢弃不重试
错误风暴打爆后端 一次白屏产生上千条上报 采样 + 限流 + 只上报首次
SourceMap 泄露源码 拿到线上源码 构建产物不部署 .map
用户隐私泄露 上报里带身份证 beforeSend 统一脱敏

第三方脚本错误 无法复现 归类到 third-party tag,单独告警

七、面试高频问答

Section titled “七、面试高频问答”

Q1：线上错误怎么发现？

Section titled “Q1：线上错误怎么发现？”

答：靠全局捕获 + 监控平台告警。三层：window.onerror（同步错误 + 资源错误）、unhandledrejection（异步）、React ErrorBoundary（渲染错误）。错误上报到 Sentry/自建，按分级配告警阈值。

Q2：错误上报要带哪些字段？

Section titled “Q2：错误上报要带哪些字段？”

答：错误类型、message、stack、componentStack、页面 URL、路由、用户 ID、租户、版本号（release）、设备与浏览器、最近操作路径 breadcrumb、接口耗时。没有上下文的上报等于没上报。

Q3：为什么生产环境要配 SourceMap？

Section titled “Q3：为什么生产环境要配 SourceMap？”

答：压缩后堆栈不可读。构建时生成 .map 上传到 Sentry，让线上错误能还原到源码行列。上传完要把 .map 从静态服务器删掉，避免源码泄露。

Q4：ErrorBoundary 能捕获哪些错误？

Section titled “Q4：ErrorBoundary 能捕获哪些错误？”

答：只能捕获 React 渲染树内、渲染和生命周期阶段的错误。事件处理器里的报错、异步回调里的报错不会冒泡到 ErrorBoundary，需要自己 try/catch 上报。另外 ErrorBoundary 本身必须用 class 组件（没有 hook 版本的等价物）。

Q5：怎么防止错误上报接口把业务带崩？

Section titled “Q5：怎么防止错误上报接口把业务带崩？”

答：navigator.sendBeacon（浏览器保证发出去不阻塞页面卸载）、攒批上报、上报失败直接丢弃不重试、上报接口独立域名、同一错误采样限流。

📝 小结

Section titled “📝 小结”
  • 前端异常分三类:同步错误(渲染、事件回调,靠 window.onerror + error 捕获)、资源错误(脚本/图片加载,靠 ErrorEvent 的 capture 阶段)、异步错误(Promise、async/await,必须 unhandledrejection 捕获)。
  • 框架层错误用 window.addEventListener('error', handler, true) 捕获,React 侧再补 ErrorBoundary 兜住渲染期错误。
  • 企业主流方案是 Sentry:自动采集 stack、breadcrumb、用户操作轨迹、release 与 sourcemap 还原。
  • 自建上报要带上:错误信息、堆栈、页面路由、用户/租户标识、UA、网络状态、版本号——没有版本号就没法定位是哪个发布引入的。
  • 错误分级:P0(白屏/核心流程不可用)→ 立即告警;P1(功能异常)→ 聚合告警;P2(控制台警告)→ 只记录。
  • 监控自身的坑:上报接口失败要静默兜底(不能递归报错)、采样避免拖垮页面、sourcemap 必须上传且不公开。
  • 面试高频:「线上出错了你怎么查」——答上报链路 → 错误聚合 → 版本对比 → sourcemap 定位 → 复盘防复发。
