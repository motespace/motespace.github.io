Next.js Middleware 中间件

一、什么是 Middleware

Section titled “一、什么是 Middleware”

Middleware = 在请求到达页面 / API 之前执行的函数,可以修改请求、重定向、修改响应头等。

典型场景:

  • 鉴权(未登录跳登录页)
  • A/B 测试
  • 多语言切换
  • Bot 检测
  • 请求日志
  • 修改响应头(安全、缓存)

五、Middleware 与 Server Component 区别

Section titled “五、Middleware 与 Server Component 区别”
Middleware Server Component
运行时机 请求前 渲染时
可以改请求 ✅ ❌
可以改响应头 ✅ ✅
可以调用数据库 ❌(Edge Runtime) ✅
可以用 React ❌ ✅
适用场景 鉴权、A/B、重定向 数据获取、布局

六、Edge Runtime 限制

Section titled “六、Edge Runtime 限制”

Middleware 默认运行在 Edge Runtime(Vercel Edge / Cloudflare Workers):

限制:

  • 不能用 fs、path、process
  • 不能 require Node 模块
  • 仅 Web 标准 + 部分 npm 包

七、面试常考

Section titled “七、面试常考”

Q1:Middleware 用途?

Section titled “Q1:Middleware 用途?”

答:

  • 鉴权(未登录跳登录)
  • A/B 测试
  • 多语言
  • 安全头
  • 日志

Q2:Middleware 和 Server Component 区别?

Section titled “Q2:Middleware 和 Server Component 区别?”

答:

  • Middleware 在请求前运行,改请求/响应头
  • Server Component 在渲染时运行,负责数据获取和 UI
  • Middleware 不能用 React,Server Component 可以

Q3:Middleware 性能注意?

Section titled “Q3:Middleware 性能注意?”

答:

  • 默认 Edge Runtime,启动快
  • 但每次请求都执行,逻辑要快
  • 复杂操作(如查 DB)放到 Server Component

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • Middleware 在哪一层? Edge Runtime(CDN 节点);不能用 Node API(fs、net)
  • 匹配规则语法? matcher: ['/dashboard/:path*', '/api/:path*'];或 config.matcher
  • 重定向怎么写? NextResponse.redirect(new URL('/login', request.url))
  • header 修改? NextResponse.next({ request: { headers: requestHeaders } })
  • Middleware 限制? 不能用 process.cwd() 等 Node API;bundle 体积 < 1MB 限制

📝 小结

Section titled “📝 小结”
  • Middleware 跑在请求到达路由之前,用于重定向、鉴权、A/B、埋点、地理路由;它不是 API Handler,不能拿业务数据。
  • Middleware 默认跑在 Edge Runtime,不能用 Node API(文件系统、完整 crypto 等),但可用 fetch、URL、Headers。
  • matcher 决定拦截范围,可用正则排除静态资源与 API;写太宽会拖慢所有请求。
  • Middleware 可以读写 Cookie 与请求头,并可 NextResponse.redirect / rewrite;rewrite 是「换资源不换 URL」。
  • 与 Server Component 的区别:中间件先于渲染、做通用拦截;Server Component 在渲染期取数据,拿得到数据库与内部服务。
  • 面试常问「鉴权放哪」:中间件做粗粒度(有无 token、是否登录),真正的权限校验必须在服务端数据层再做一次,别只信前端。
