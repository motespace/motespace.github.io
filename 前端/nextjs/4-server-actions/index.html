Next.js Server Actions 详解

一、Server Actions 简介

Section titled “一、Server Actions 简介”

Server Actions 是 Next.js 14 稳定的功能，允许在服务端定义的异步函数直接从客户端调用。

核心特点

Section titled “核心特点”
  • 在 Server Component 中定义的异步函数
  • 客户端可直接调用，无需创建 API Route
  • 自动处理表单提交
  • 类型安全，支持 TypeScript
  • 内置乐观更新和重验证机制

十、最佳实践

Section titled “十、最佳实践”
  1. 分离关注点：Server Actions 只处理数据操作，组件负责 UI
  2. 始终验证输入：使用 Zod 等库进行类型安全的验证
  3. 提供用户反馈：使用 useActionState 显示 loading 和错误状态
  4. 重新验证相关缓存：数据修改后调用 revalidatePath 或 revalidateTag
  5. 处理并发：考虑使用 optimistic updates 提升 UX
  6. 错误边界：使用 error.tsx 捕获未处理的错误

面试常考

Section titled “面试常考”

Q1:Server Actions 是什么?

Section titled “Q1:Server Actions 是什么?”

答:

  • 'use server' 指令的异步函数,在服务端执行
  • 客户端直接调用,像 API 但无需手写
  • 用于:表单提交、数据变更、乐观更新
  • 优势:零 API 路由代码、类型安全、CSRF 保护内置

Q2:Server Actions vs API Routes?

Section titled “Q2:Server Actions vs API Routes?”

答:

  • Actions:'use server' 函数,适合“用户触发的写操作”
  • API Routes:app/api/.../route.ts;适合“外部消费 / Webhook / RESTful”
  • 选:业务内部用 Actions;对外 API 用 Routes

Q3:useFormStatus 和 useActionState 区别?

Section titled “Q3:useFormStatus 和 useActionState 区别?”

答:

  • useFormStatus:{ pending, data, method } 读父表单状态
  • useActionState(React 19):[state, formAction, isPending] 包装 reducer
  • 实战:useActionState 处理业务;useFormStatus 写按钮 loading

Q4:Server Actions 安全考虑?

Section titled “Q4:Server Actions 安全考虑?”

答:

  • 自动 CSRF 保护(POST + Origin header 检查)
  • 但仍要权限校验(谁在调用)
  • 敏感操作加二次确认(密码 / 短信)
  • 用 revalidatePath 失效缓存防脏读

📝 小结

Section titled “📝 小结”
  • Server Actions 是服务端函数,可以直接在客户端组件里 await 调用,框架自动发 POST 请求并带 CSRF 防护。
  • 本质上还是 HTTP:用 <form action={serverAction}> 提交是渐进增强的做法,不用 JS 也能用。
  • 状态用 useActionState(React 19)/ useFormState 管理:pending 表示进行中,state 带回返回的错误信息。
  • 变更后用 revalidatePath / revalidateTag 做按需失效,再 redirect() 跳转,这是标准的 mutation 流程。
  • 安全性:Server Action 是公开端点,必须自己鉴权、校验入参(别信任表单传来的 id),不能因为「在服务端」就放松。
  • 对比:Server Actions 适合「写」,Route Handlers 适合「需要自定义响应/被第三方调用/流式」,RSC 适合「读」。
