Next.js Middleware 中间件 ​

一、什么是 Middleware ​

Middleware = 在请求到达页面 / API 之前执行的函数,可以修改请求、重定向、修改响应头等。

请求 → middleware → 匹配路由 → 渲染页面
                ↓
            修改请求/响应
            重定向到登录
            设置 Cookie

典型场景:

  • 鉴权(未登录跳登录页)
  • A/B 测试
  • 多语言切换
  • Bot 检测
  • 请求日志
  • 修改响应头(安全、缓存)

二、基础用法 ​

2.1 文件位置 ​

Next.js 13+(App Router):

my-app/
├── app/
│   ├── page.tsx
│   └── ...
└── middleware.ts   ← 必须在根目录(或 src/)

2.2 基础 middleware ​

ts
// middleware.ts
import { NextRequest, NextResponse } from 'next/server'

export function middleware(request: NextRequest) {
  // 1. 修改请求头
  const requestHeaders = new Headers(request.headers)
  requestHeaders.set('x-custom-header', 'hello')
  
  // 2. 修改响应头
  const response = NextResponse.next({
    request: { headers: requestHeaders },
  })
  response.headers.set('x-response-time', Date.now().toString())
  
  return response
}

// 配置匹配路径
export const config = {
  matcher: [
    '/((?!api|_next/static|_next/image|favicon.ico).*)',
  ],
}

三、实战案例 ​

3.1 鉴权中间件 ​

ts
// middleware.ts
import { NextRequest, NextResponse } from 'next/server'

const PROTECTED_PATHS = ['/dashboard', '/admin', '/profile']
const PUBLIC_PATHS = ['/login', '/register', '/']

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl
  const token = request.cookies.get('session')

  // 需要鉴权的路径
  if (PROTECTED_PATHS.some(p => pathname.startsWith(p))) {
    if (!token) {
      const loginUrl = new URL('/login', request.url)
      loginUrl.searchParams.set('redirect', pathname)
      return NextResponse.redirect(loginUrl)
    }
  }

  // 已登录访问登录页 → 跳 dashboard
  if (token && PUBLIC_PATHS.includes(pathname)) {
    return NextResponse.redirect(new URL('/dashboard', request.url))
  }

  return NextResponse.next()
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
}

3.2 多语言路由 ​

ts
// middleware.ts
import { NextRequest, NextResponse } from 'next/server'

const LOCALES = ['en', 'zh', 'ja']
const DEFAULT_LOCALE = 'en'

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl

  // 跳过已有 locale 的路径
  const pathnameHasLocale = LOCALES.some(
    locale => pathname.startsWith(`/${locale}/`) || pathname === `/${locale}`
  )

  if (pathnameHasLocale) return NextResponse.next()

  // 从 Accept-Language 头检测
  const acceptLanguage = request.headers.get('accept-language') || ''
  const detectedLocale = acceptLanguage
    .split(',')[0]
    ?.split('-')[0]
  
  const locale = LOCALES.includes(detectedLocale) ? detectedLocale : DEFAULT_LOCALE

  // 重定向到 /zh/xxx
  const newUrl = new URL(`/${locale}${pathname}`, request.url)
  return NextResponse.redirect(newUrl)
}

export const config = {
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico).*)'],
}

3.3 A/B 测试 ​

ts
import { NextRequest, NextResponse } from 'next/server'

export function middleware(request: NextRequest) {
  // 根据 userId 哈希决定变体
  const bucket = hashUserId(request.cookies.get('userId') ?? 'anon') % 100
  
  const response = NextResponse.next()
  
  if (bucket < 50) {
    response.cookies.set('ab-variant', 'A')
  } else {
    response.cookies.set('ab-variant', 'B')
  }
  
  return response
}

export const config = {
  matcher: ['/'],
}

3.4 安全响应头 ​

ts
import { NextRequest, NextResponse } from 'next/server'

export function middleware(request: NextRequest) {
  const response = NextResponse.next()
  
  // 防止 XSS
  response.headers.set('X-Content-Type-Options', 'nosniff')
  response.headers.set('X-Frame-Options', 'DENY')
  
  // CSP
  response.headers.set('Content-Security-Policy', "default-src 'self'")
  
  // HSTS
  response.headers.set('Strict-Transport-Security', 'max-age=31536000; includeSubDomains')
  
  // Referrer
  response.headers.set('Referrer-Policy', 'strict-origin-when-cross-origin')
  
  return response
}

export const config = {
  matcher: ['/((?!api|_next/static).*)'],
}

四、Matcher 配置 ​

4.1 基本语法 ​

ts
export const config = {
  matcher: [
    // 匹配所有路径
    '/',

    // 匹配 /about/*
    '/about/:path*',

    // 多个路径
    ['/dashboard/:path*', '/admin/:path*'],

    // 排除
    '/((?!api|_next/static|favicon.ico).*)',
    /* 匹配除 api、_next/static、favicon.ico 之外的所有 */
  ],
}

4.2 常用排除 ​

ts
export const config = {
  matcher: [
    // 排除 Next.js 内部路径
    '/((?!_next/static|_next/image|favicon.ico).*)',

    // 排除 API
    '/((?!api/|_next/).*)',

    // 排除静态资源
    '/((?!.*\\.).*)',  // 不要带点的(非文件)
  ],
}

五、Middleware 与 Server Component 区别 ​

MiddlewareServer Component
运行时机请求前渲染时
可以改请求✅❌
可以改响应头✅✅
可以调用数据库❌(Edge Runtime)✅
可以用 React❌✅
适用场景鉴权、A/B、重定向数据获取、布局

六、Edge Runtime 限制 ​

Middleware 默认运行在 Edge Runtime(Vercel Edge / Cloudflare Workers):

ts
// ❌ Node.js API 不可用
const fs = require('fs')
const path = require('path')

// ✅ 可用 Web 标准 API
const url = new URL(request.url)
const cookies = request.cookies

限制:

  • 不能用 fs、path、process
  • 不能 require Node 模块
  • 仅 Web 标准 + 部分 npm 包

七、面试常考 ​

Q1:Middleware 用途? ​

答:

  • 鉴权(未登录跳登录)
  • A/B 测试
  • 多语言
  • 安全头
  • 日志

Q2:Middleware 和 Server Component 区别? ​

答:

  • Middleware 在请求前运行,改请求/响应头
  • Server Component 在渲染时运行,负责数据获取和 UI
  • Middleware 不能用 React,Server Component 可以

Q3:Middleware 性能注意? ​

答:

  • 默认 Edge Runtime,启动快
  • 但每次请求都执行,逻辑要快
  • 复杂操作(如查 DB)放到 Server Component
