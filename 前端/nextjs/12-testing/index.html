Q1:Next.js 测试用什么工具?

Section titled “Q1:Next.js 测试用什么工具?”

答:

  • 单元/集成:Vitest + @testing-library/react
  • E2E:Playwright(首选)或 Cypress
  • Server Component:用 @next/test-utils(实验性)

Q2:Server Component 怎么测试?

Section titled “Q2:Server Component 怎么测试?”

答:

  • 用 renderServerComponent 渲染
  • Mock 数据获取
  • 验证 HTML 输出
  • 不需要 DOM

Q3:Playwright vs Cypress?

Section titled “Q3:Playwright vs Cypress?”

答:

  • Playwright:跨浏览器(Chromium、Firefox、WebKit)、快、支持移动端
  • Cypress:DX 好、调试方便、但只支持 Chromium 系
  • 新项目推荐 Playwright

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • App Router 测试变化? Server Component 默认服务端;Client Component 才走 RTL
  • MSW 怎么配? Service Worker 拦截 fetch;setupServer 跑 Node 环境
  • Server Component 测什么? 业务逻辑 + 数据获取 + 渲染输出;不测 DOM
  • Playwright 配置 Next.js? webServer: { command: 'npm run dev', port: 3000 }
  • 快照测试注意? 避免大面积快照;只断言关键结构

📝 小结

Section titled “📝 小结”
  • 测试分层:纯函数/工具 → Vitest 单元测试;Server Component 的输出 → 用 Testing Library 或直接渲染断言;用户路径 → Playwright E2E。
  • Server Component 不能直接用 @testing-library/react 测(它是 async 组件),要么在测试里 await 组件后断言输出文本,要么用 E2E 覆盖。
  • Route Handler / Middleware 可直接调用导出的函数并构造 Request 对象断言响应。
  • Playwright 的价值在真实浏览器 + 网络拦截(page.route mock 接口),能稳定复现流式渲染与乐观更新。
  • CI 里要先起服务再跑 E2E,常见组合:vitest --run → playwright test,配合 trace 留存失败现场。
  • 面试加分:能说清「为什么组件测试经常不如 E2E 有价值」——mock 太多就测了个寂寞,只测纯逻辑 + 关键路径 E2E。
