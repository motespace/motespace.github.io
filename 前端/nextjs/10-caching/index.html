Q1:Next.js 有哪些缓存?

Section titled “Q1:Next.js 有哪些缓存?”

答:

  • Data Cache(fetch 缓存)
  • Full Route Cache(整页静态)
  • Router Cache(客户端导航缓存)
  • CDN Cache(部署边缘)

Q2:revalidate vs no-store?

Section titled “Q2:revalidate vs no-store?”

答:

  • revalidate: N:ISR,缓存 N 秒后重新拉
  • no-store:不缓存,每次请求都拉

Q3:revalidatePath vs revalidateTag?

Section titled “Q3:revalidatePath vs revalidateTag?”

答:

  • revalidatePath('/posts'):失效具体路径
  • revalidateTag('posts'):失效所有打这个 tag 的缓存
  • Tag 更精确,推荐

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • Data Cache 怎么触发? fetch(url, { next: { revalidate: 60, tags: ['posts'] } });默认强制缓存
  • Router Cache 怎么禁用? router.refresh() 或设置 dynamic = 'force-dynamic'
  • unstable_cache vs fetch cache? unstable_cache 用于非 fetch 数据(如数据库查询)
  • 缓存 4 层关系? CDN > Full Route > Data > Router;越往下越细粒度
  • 缓存预热? revalidateTag 配合 webhooks 主动失效;构建时 generateStaticParams

📝 小结

Section titled “📝 小结”
  • Next 的缓存分四层:浏览器缓存 → CDN → Full Route Cache(整页)→ Data Cache(fetch/RSC 数据),排查缓存问题要从上往下看。
  • Next 15 起 fetch 默认不缓存,要显式 next: { revalidate: n } 或 cache: 'force-cache',这是很多「数据不更新」问题的根因。
  • revalidate 既有路径级也有标签级(revalidateTag / revalidatePath),标签更适合「一批页面共享同一份数据」的场景。
  • unstable_cache 用于缓存非 fetch 的数据源(数据库查询),Next 15+ 可用 "use cache" 指令。
  • cookies() / headers() / searchParams 是动态 API,一旦使用整条路由会退化为动态渲染,别在根 layout 用。
  • 面试加分:讲清「静态优先,需要动态才降级」的判定顺序,以及 CDN 缓存要设置 s-maxage/stale-while-revalidate。
