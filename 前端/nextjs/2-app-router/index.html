面试常考

Section titled “面试常考”

Q1:App Router 核心概念?

Section titled “Q1:App Router 核心概念?”

答:

  • 文件系统路由:app/ 目录 = URL 段
  • 布局嵌套:layout.tsx 自动包裹子路由
  • Server Components:默认服务端,无 state/effect
  • 'use client' 指令:开启 Client Component
  • 特殊文件:page.tsx / layout.tsx / loading.tsx / error.tsx / not-found.tsx
  • 路由组:(group) 不影响 URL,仅组织代码

Q2:Server Component vs Client Component 边界?

Section titled “Q2:Server Component vs Client Component 边界?”

答:

  • Server:默认;不能 hooks、事件、浏览器 API;可 await Promise
  • Client:'use client' 开头;可交互;能 import server 不能 import 的东西
  • 原则:顶层 Server,叶子 Client(只把交互部分标 client)
  • 通信:Server 传 props 给 Client(必须可序列化)

Q3:Layout vs Template 区别?

Section titled “Q3:Layout vs Template 区别?”

答:

  • layout:跨路由持久(切换页面不重新挂载);保留 state
  • template:每次进入路由重新挂载;state 重置
  • 选:大多数用 layout(性能好);需要动画/重置时用 template

Q4:loading.tsx 怎么工作?

Section titled “Q4:loading.tsx 怎么工作?”

答:

  • 自动包 Suspense 边界
  • 数据未就绪时显示
  • 配合 Server Component 的 await 生效
  • 类似 useEffect + loading state,但无需手写

📝 小结

Section titled “📝 小结”
  • App Router 的心智模型:RSC(默认在服务端渲染)+ 客户端组件按需下发;'use client' 是边界声明,不是「这个文件在浏览器跑」。
  • 目录即路由:app/ 下文件夹 = 路径段,page.tsx = 页面,layout.tsx = 布局,loading/error/not-found/template 是约定文件名。
  • layout.tsx 在导航时不会重新渲染(状态保留),template.tsx 会;这是两者唯一但很关键的差别。
  • 布局嵌套 = 逐层组合,所以根 layout 放 <html>/<body>、子 layout 放业务壳层。
  • 客户端组件可以接收服务端组件传来的 children(作为 props),这是「服务端包壳 + 客户端交互」的组合方式。
  • 面试常问「为什么 App Router 首屏快」:因为 HTML 由服务端出,JS 少,且数据在服务端就取好了。
