一、四种渲染模式概览

Section titled “一、四种渲染模式概览”
模式 全称 渲染时机 HTML 内容 适用场景
SSR Server-Side Rendering 每次请求时 动态生成 需实时数据的页面
SSG Static Site Generation 构建时 预生成静态 静态内容、文档
ISR Incremental Static Regeneration 构建时 + 按需 静态 + 增量更新 更新不频繁的动态内容
CSR Client-Side Rendering 浏览器端 空壳 + JS 需登录的个性化页面

面试常考

Section titled “面试常考”

Q1:4 种渲染模式怎么选?

Section titled “Q1:4 种渲染模式怎么选?”

答:

  • SSG (Static):内容不变(博客/文档) → 最佳性能
  • ISR (Incremental):内容偶变、量大(电商商品) → SSG + 定时刷新
  • SSR (Dynamic):内容实时(用户仪表盘) → 每次请求
  • CSR (Client):SPA / 后台 / 登录后内容 → 客户端拉
  • 决策树:SEO + 实时性 + 数据量 → 选模式

Q2:App Router 默认是什么模式?

Section titled “Q2:App Router 默认是什么模式?”

答:

  • 静态(static)默认(可缓存)
  • 用了 cookies() / headers() / searchParams → 动态
  • fetch 默认 cache:'force-cache'(可改 'no-store')
  • 强制:export const dynamic = 'force-dynamic'

Q3:动态渲染怎么强制开启?

Section titled “Q3:动态渲染怎么强制开启?”

答:

  • export const dynamic = 'force-dynamic'
  • export const revalidate = 0
  • fetch(..., { cache: 'no-store' })
  • 用 cookies() / headers() 自动 dynamic

Q4:Edge Runtime 限制?

Section titled “Q4:Edge Runtime 限制?”

答:

  • 跑在 CDN 边缘节点
  • 不能用 Node API(fs、net、child_process)
  • 不能用 npm 包依赖 Node API
  • 优势:低延迟(就近响应);适合 Middleware / 简单 SSR

📝 小结

Section titled “📝 小结”
  • 四种模式:SSG(构建期生成,最静态)、ISR(构建期生成 + 定时/按需过期)、SSR(每次请求生成)、CSR(浏览器运行时生成)。
  • 选择标准:内容有多变 + 是否需要 SEO/首屏 → 决定 SSG/ISR/SSR;纯后台交互页 → CSR。
  • SSG 的代价是重新构建要等全部页面生成完,页面多时要用 generateStaticParams 提前指定路径,或改 ISR。
  • ISR 的关键参数是 revalidate(秒),本质是「stale-while-revalidate」:先返回旧内容,后台异步重建。
  • SSR 的瓶颈在服务端数据聚合,要并行请求 + 流式渲染(loading.tsx + Suspense)避免瀑布。
  • 面试追问「App Router 默认是什么渲染」:默认是静态预渲染,只有用了动态 API(cookies/headers/searchParams)才降级为动态渲染。
