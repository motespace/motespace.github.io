十一、面试常考

Section titled “十一、面试常考”

Q1:Next.js 怎么部署?

Section titled “Q1:Next.js 怎么部署?”

答:

  • 简单:Vercel(零配置)
  • 自定义:Docker + Node.js + Nginx
  • 静态:导出 HTML 到任何托管

Q2:Vercel vs 自建?

Section titled “Q2:Vercel vs 自建?”

答:

  • Vercel:零配置、CDN、自动 HTTPS,适合快速上线
  • 自建:可控、定制、隐私、节省成本(规模化后)
  • 中型项目:Vercel 起家,规模化后考虑迁移

Q3:standalone 模式的好处?

Section titled “Q3:standalone 模式的好处?”

答:

  • 只打包必要 node_modules
  • 镜像小(100MB)
  • 启动快
  • 适合 Docker

面试追问(深化原 Q1-Q3)

Section titled “面试追问(深化原 Q1-Q3)”
  • Vercel 优势? 零配置、Edge Network、自动 HTTPS、Preview Deployments
  • Vercel 成本? Hobby 免费;Pro $20/月;按 function 调用 + edge 流量计费
  • standalone 构建配置? output: 'standalone';Docker 镜像仅 ~150MB
  • 自建部署栈? Docker + Next.js standalone + Nginx + PM2;或 Cloudflare Pages / Netlify
  • 多区域部署? Vercel 默认全球;自建需 Cloudflare / Fastly / Akamai

📝 小结

Section titled “📝 小结”
  • 三种部署:Vercel(零配置、Serverless)、Docker(可控、可上自有 K8s)、output: 'standalone' 自建 Node(镜像最小、启动快)。
  • standalone 输出只含运行所需文件,部署时要把 .next/static 与 public 单独拷进去,否则静态资源 404。
  • 环境变量在构建期注入(会被写进产物),运行时改动必须走平台的环境配置或配置中心。
  • Node 版本必须与构建一致,否则出现 ABI/ESM 差异;用 .nvmrc + engines 锁住。
  • 多实例部署时,Session/文件上传等有状态逻辑必须外置到 Redis / 对象存储,否则实例间不一致。
  • 面试追问「怎么滚动发布不中断」:先起新实例健康检查通过 → 切流量 → 旧实例排空(注意长连接与 SSE 的优雅退出)。
