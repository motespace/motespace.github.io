Pages Router(Next.js 12 及之前) ​

一、Pages Router vs App Router ​

Next.js 有两套路由系统:

Pages RouterApp Router
版本Next.js 12 及之前Next.js 13+(稳定)
目录pages/app/
API类组件风格(getServerSideProps)函数组件 + async
数据获取顶层函数组件内 async/await
Layouts手动嵌套原生嵌套 layout
Streaming❌✅ Suspense + loading.tsx
Server Components❌✅

新项目推荐 App Router,老项目维护用 Pages Router。

二、文件路由约定 ​

pages/
├── index.tsx          # /
├── about.tsx           # /about
├── blog/
│   ├── index.tsx       # /blog
│   └── [slug].tsx      # /blog/:slug
├── [...all].tsx        # 404(通配)
└── _app.tsx            # 全局 App 组件

2.1 动态路由 ​

tsx
// pages/post/[id].tsx
import { useRouter } from 'next/router'

export default function Post() {
  const router = useRouter()
  const { id } = router.query  // 从 URL 拿 id
  return <div>Post {id}</div>
}

2.2 嵌套路由 ​

Pages Router 不支持嵌套 layouts(App Router 支持)。

tsx
// 嵌套要手动包
// pages/dashboard.tsx
import DashboardLayout from '@/components/DashboardLayout'

export default function Dashboard() {
  return (
    <DashboardLayout>
      <h1>Dashboard</h1>
    </DashboardLayout>
  )
}

2.3 路由组(Group) ​

Pages Router 不支持 App Router 的 (group) 语法。

三、数据获取 ​

3.1 getStaticProps(SSG) ​

tsx
// pages/blog/index.tsx
export async function getStaticProps() {
  const res = await fetch('https://api.example.com/posts')
  const posts = await res.json()
  return {
    props: { posts },
    revalidate: 60,  // ISR:60 秒重新生成
  }
}

export default function Blog({ posts }) {
  return <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>
}

执行时机:构建时(SSG)或 ISR revalidate 时。

3.2 getStaticPaths(动态路由 SSG) ​

tsx
// pages/post/[id].tsx
export async function getStaticPaths() {
  const res = await fetch('https://api.example.com/posts')
  const posts = await res.json()
  return {
    paths: posts.map((post) => ({
      params: { id: post.id },
    })),
    fallback: 'blocking',  // 关键:运行时也能生成
  }
}

export async function getStaticProps({ params }) {
  const res = await fetch(`https://api.example.com/posts/${params.id}`)
  const post = await res.json()
  return { props: { post } }
}

fallback 选项:

  • false:不在 paths 里的 404
  • true:运行时生成(返回 loading 状态)
  • 'blocking':运行时生成(SSR 等到完成)

3.3 getServerSideProps(SSR) ​

tsx
// pages/dashboard.tsx
export async function getServerSideProps(context) {
  // 每个请求都执行
  const { req, res, query, params } = context
  const cookie = req.headers.cookie
  
  const data = await fetch('https://api.example.com/data', {
    headers: { cookie },
  }).then(r => r.json())
  
  return {
    props: { data },
  }
}

export default function Dashboard({ data }) {
  return <div>{data.name}</div>
}

特点:

  • 每个请求都跑一次(慢!)
  • 能访问 cookie、headers
  • 不能用 revalidate

3.4 getInitialProps(传统) ​

tsx
// pages/_app.tsx 或 page.tsx
Page.getInitialProps = async (ctx) => {
  // 通用入口,但效率低
  return { data }
}

不推荐,只在老项目见到。

四、API Routes ​

Pages Router 支持 pages/api/:

ts
// pages/api/users.ts
import type { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  if (req.method === 'GET') {
    const users = await db.users.findMany()
    res.json(users)
  } else if (req.method === 'POST') {
    const user = await db.users.create({ data: req.body })
    res.status(201).json(user)
  }
}

使用:

ts
const res = await fetch('/api/users')
const users = await res.json()

tsx

import { Html, Head, Main, NextScript } from 'next/document'

6.2 useRouter ​

tsx
import { useRouter } from 'next/router'

function Component() {
  const router = useRouter()

  function handleClick() {
    router.push('/about')
    router.push({ pathname: '/post', query: { id: 1 } })

  }

八、Pages Router vs App Router 迁移 ​

8.1 共同 API ​

tsx
// 都能用
next/image, next/font, next/link, next/router
next/head, next/script, next/dynamic

8.2 主要差异 ​

ts
// Pages Router:数据获取在顶层
export async function getServerSideProps() {}

// App Router:数据获取在组件内
async function Page() {
  const data = await fetch(...)
}

8.3 渐进式迁移 ​

可以 Pages + App 共存(Next.js 13+):

  • 老页面留在 pages/
  • 新页面在 app/
  • 跨目录跳转兼容

九、SSR vs SSG vs ISR 选型 ​

getStaticProps (SSG):       构建时执行
getStaticProps + revalidate: ISR(增量静态)
getServerSideProps (SSR):   每个请求
1. 内容不常变(博客、文档)        → SSG
2. 内容更新不频繁,容忍延迟         → ISR(性能 + 实时性兼顾)
3. 每个用户不同(个人中心、订单)    → SSR
4. 完全个性化(用户登录后看到自己)  → CSR(用 SWR/React Query)

面试常考 ​

Q1:Pages Router 还会用吗? ​

答:

  • Next.js 13+ 默认 App Router
  • Pages Router 仍支持(未弃用)
  • 老项目维护用 Pages;新项目用 App
  • 13+ 推荐:新页面用 App,旧页面逐步迁移

Q2:Pages Router 数据获取方式? ​

答:

  • getStaticProps (SSG):构建时拉
  • getStaticPaths + getStaticProps (动态路由 SSG)
  • getServerSideProps (SSR):每次请求拉
  • 客户端:useEffect / SWR / React Query

Q3:Pages vs App Router 性能差异? ​

答:

  • App Router 支持 RSC、流式、Suspense 边界
  • Pages Router 整页渲染(无流式)
  • 大型应用 App Router 性能更优(更少 JS 下发)
  • 小型项目差异不大

Q4:从 Pages 迁移到 App 怎么搞? ​

答:

  • 渐进式:pages/ 和 app/ 共存
  • 把 pages/foo.tsx 移到 app/foo/page.tsx
  • getServerSideProps → 直接 await fetch in page component
  • getStaticProps → 用 fetch + cache 配置
  • 路由行为差异:_app.tsx → app/layout.tsx
