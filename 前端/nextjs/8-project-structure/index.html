📝 小结

Section titled “📝 小结”
  • 目录约定按职责分层:app/(路由与页面)、components/(展示组件)、features/(业务域)、lib/(无副作用的工具与请求封装)、types/、config/。
  • 约定优于配置:app/ 里的文件名与位置就是路由语义,不要在 app 目录里堆业务代码。
  • 环境变量:NEXT_PUBLIC_ 前缀的会被打进客户端 bundle,只能放公开配置;服务端密钥绝不能加这个前缀。
  • tsconfig.json 的 paths 别名把 @/ 指向 src/,跨包引用用 baseUrl + paths 或 pnpm workspace 包名。
  • 组件库与业务组件分层:设计系统组件(无业务)→ 业务组件(带领域模型)→ 页面(编排),这样换 UI 框架时改动收敛在第一层。
  • 避坑清单重点:不要在 app/ 里写 use client 的比例过高(会退化成 CSR)、不要在 Server Component 里用 window。

面试常考

Section titled “面试常考”

Q1:Next.js 项目结构怎么组织?

Section titled “Q1:Next.js 项目结构怎么组织?”

答:

  • App Router:app/(路由) + components/(组件) + lib/(工具) + types/(类型)
  • 路由组 (group) 分业务线:(marketing)/ / (dashboard)/ 不影响 URL
  • 私有文件夹 _folder 防止 Next.js 当路由:_components/
  • 共享布局:根 app/layout.tsx + 子 app/(group)/layout.tsx

Q2:lib/ vs utils/ 区别?

Section titled “Q2:lib/ vs utils/ 区别?”

答:

  • 两者都可,团队约定
  • 建议:lib/ 业务逻辑(API client、auth);utils/ 纯函数(formatDate、cn)
  • 避免:超大 utils/index.ts(全塞一起)

Q3:多语言 / 主题怎么组织?

Section titled “Q3:多语言 / 主题怎么组织?”

答:

  • 多语言:app/[lang]/... 动态段 + 中间件检测 lang
  • 主题:app/contexts/ThemeContext + CSS 变量
  • 实战:用 next-intl 库管 i18n;next-themes 管暗色模式

Q4:monorepo 中 Next.js 放哪?

Section titled “Q4:monorepo 中 Next.js 放哪?”

答:

  • 主流:apps/web(Next.js 应用) + packages/ui(共享组件) + packages/config(共享配置)
  • 工具:pnpm workspace + Turborepo
  • 共享组件库:packages/ui 用 tsup 打包,Next.js 直接 import
