Pages Router(Next.js 12 及之前)

一、Pages Router vs App Router

Section titled “一、Pages Router vs App Router”

Next.js 有两套路由系统:

Pages Router App Router
版本 Next.js 12 及之前 Next.js 13+(稳定)
目录 pages/ app/
API 类组件风格(getServerSideProps) 函数组件 + async
数据获取 顶层函数 组件内 async/await
Layouts 手动嵌套 原生嵌套 layout
Streaming ❌ ✅ Suspense + loading.tsx
Server Components ❌ ✅

新项目推荐 App Router,老项目维护用 Pages Router。

📝 小结

Section titled “📝 小结”
  • Pages Router 是 Next 12 及之前的老架构:pages/ 目录即路由,数据获取用 getServerSideProps / getStaticProps。
  • getServerSideProps 每次请求都跑(SSR),getStaticProps 构建期跑(SSG),getStaticPaths 配合 fallback 支持动态路由的按需生成。
  • _app.tsx 管全局布局与 Provider,_document.tsx 管 HTML 骨架(<Html>/<Head>/<body>),两者都不能在服务端组件语境下混用 App Router。
  • App Router 的本质变化:数据获取从「页面级 props」变成服务端组件里直接 await;缓存从 revalidate 秒数变成 tag/path + 显式 revalidate。
  • 迁移要点:getServerSideProps → RSC 直接 fetch;getStaticProps → 默认静态 + revalidate;useRouter → next/navigation。
  • 面试常问「为什么新项目用 App Router」:服务端组件减小客户端 bundle、原生流式与并行渲染、嵌套路由与布局更自然。

面试常考

Section titled “面试常考”

Q1:Pages Router 还会用吗?

Section titled “Q1:Pages Router 还会用吗?”

答:

  • Next.js 13+ 默认 App Router
  • Pages Router 仍支持(未弃用)
  • 老项目维护用 Pages;新项目用 App
  • 13+ 推荐:新页面用 App,旧页面逐步迁移

Q2:Pages Router 数据获取方式?

Section titled “Q2:Pages Router 数据获取方式?”

答:

  • getStaticProps (SSG):构建时拉
  • getStaticPaths + getStaticProps (动态路由 SSG)
  • getServerSideProps (SSR):每次请求拉
  • 客户端:useEffect / SWR / React Query

Q3:Pages vs App Router 性能差异?

Section titled “Q3:Pages vs App Router 性能差异?”

答:

  • App Router 支持 RSC、流式、Suspense 边界
  • Pages Router 整页渲染(无流式)
  • 大型应用 App Router 性能更优(更少 JS 下发)
  • 小型项目差异不大

Q4:从 Pages 迁移到 App 怎么搞?

Section titled “Q4:从 Pages 迁移到 App 怎么搞?”

答:

  • 渐进式:pages/ 和 app/ 共存
  • 把 pages/foo.tsx 移到 app/foo/page.tsx
  • getServerSideProps → 直接 await fetch in page component
  • getStaticProps → 用 fetch + cache 配置
  • 路由行为差异:_app.tsx → app/layout.tsx
