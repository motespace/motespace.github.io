跨端进阶对比

你简历有 uni-app 经验，再补充主流跨端方案的认知，面试时技术广度更全。

一、跨端方案全景

Section titled “一、跨端方案全景”
方案 渲染 DSL 性能 生态 适用
uni-app WebView + Native Vue 中 大 跨多端 + 小程序
Taro 4 WebView + RN React 中 中 多端统一
React Native Native React 高 大 纯 App
Flutter 自绘 Skia Dart 极高 大 高性能 App
Weex Native + V8 Vue 中 小 阿里系
Lynx Native + 自研 React 中 中 字节系

二、uni-app（你已熟悉）

Section titled “二、uni-app（你已熟悉）”

2.1 优势

Section titled “2.1 优势”
  • ✅ Vue 语法（学习成本低）
  • ✅ 多端编译（小程序 / H5 / App）
  • ✅ 条件编译（#ifdef MP-WEIXIN）
  • ✅ 生态丰富（uni-ui）

2.2 缺点

Section titled “2.2 缺点”
  • ❌ 性能比原生差（WebView 限制）
  • ❌ 大型 App 不擅长
  • ❌ 复杂动效性能差

2.3 适用

Section titled “2.3 适用”

小程序 + App + H5 一套代码

四、React Native

Section titled “四、React Native”

4.1 原理

Section titled “4.1 原理”

JS 引擎通过 Bridge 调用 Native 组件。渲染是 Native，逻辑是 JS。

4.2 优势

Section titled “4.2 优势”
  • ✅ 真正的 Native 渲染（性能接近原生）
  • ✅ React 生态
  • ✅ Hermes 引擎（启动快）
  • ✅ New Architecture（Fabric + TurboModules，去掉 Bridge）

4.3 缺点

Section titled “4.3 缺点”
  • ❌ 桥接延迟（旧架构 16ms）
  • ❌ 平台差异（iOS / Android 各有 API）
  • ❌ 包体积大

4.4 实战

Section titled “4.4 实战”

4.5 生态

Section titled “4.5 生态”
  • 导航：React Navigation
  • 状态管理：Zustand / Redux
  • 网络：Fetch / Axios
  • UI 库：NativeBase / Tamagui

五、Flutter

Section titled “五、Flutter”

5.1 原理

Section titled “5.1 原理”

自绘引擎（Skia），不依赖平台组件。

5.2 优势

Section titled “5.2 优势”
  • ✅ 极高性能（60fps 动效）
  • ✅ 跨端一致（iOS / Android UI 100% 一致）
  • ✅ Dart 性能强（AOT 编译）
  • ✅ Material / Cupertino 双主题

5.3 缺点

Section titled “5.3 缺点”
  • ❌ Dart 语言学习成本
  • ❌ 包体积大（最小 ~5MB）
  • ❌ Web / 桌面 支持较弱（虽然支持）

5.4 实战

Section titled “5.4 实战”

5.5 生态

Section titled “5.5 生态”
  • 状态管理：Provider / Riverpod / Bloc
  • 导航：go_router
  • 网络：dio
  • UI 库：Material / Cupertino

六、Taro 4（多端统一）

Section titled “六、Taro 4（多端统一）”

6.1 优势

Section titled “6.1 优势”
  • ✅ React 多端编译（H5 / 小程序 / RN）
  • ✅ 多端差异抹平
  • ✅ 京东系生态

6.2 实战

Section titled “6.2 实战”

6.3 适用

Section titled “6.3 适用”

React 团队 + 跨小程序 + App + H5

七、跨端方案选型

Section titled “七、跨端方案选型”
需求 推荐
小程序 + H5 + App 跨多端 uni-app / Taro
高性能 App（动效、复杂 UI） Flutter / RN
大型 App + 原生模块多 React Native
仅 iOS / Android 一套 Flutter
已有 Vue 项目 uni-app
已有 React 项目 Taro / RN

九、面试高频追问

Section titled “九、面试高频追问”

Q1: 跨端方案怎么选？

Section titled “Q1: 跨端方案怎么选？”

答：

  • 小程序 + H5：uni-app / Taro
  • 高性能 App：Flutter
  • 大型 App + RN 生态：React Native

Q2: uni-app 性能问题怎么解决？

Section titled “Q2: uni-app 性能问题怎么解决？”

答：

  • 减少 setData 调用
  • 长列表用 recycle-view
  • 复杂页面用 render 性能问题
  • 关键路径用 nvue（Native 渲染）

Q3: React Native 桥接延迟怎么解决？

Section titled “Q3: React Native 桥接延迟怎么解决？”

答：

  • New Architecture（Fabric + TurboModules）
  • 用 C++ 写 JSI
  • 减少跨 Bridge 调用

Q4: Flutter 怎么接入 LLM？

Section titled “Q4: Flutter 怎么接入 LLM？”

答：

  • HTTP 请求：dio 包
  • 流式：Stream API
  • 复杂场景：用 gRPC + Streaming

Q5: 跨端包体积大怎么办？

Section titled “Q5: 跨端包体积大怎么办？”

答：

  • 动态下发（拆包 + 按需加载）
  • 资源压缩（图片 webp / 字体 subset）
  • 第三方 SDK 按需引入

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • React Native vs Flutter 选哪个? 团队 React 背景选 RN(上手快);性能 / 复杂动画选 Flutter
  • Taro / uni-app 优势? 一码多端(微信/支付宝/抖音/H5);牺牲部分原生能力
  • 跨端的本质权衡? 一致性 ↔ 原生体验;性能 ↔ 开发效率
  • 未来趋势? RSC 跨端(React Server Components);Tauri 桌面;Flutter Web

📝 小结

Section titled “📝 小结”
  • 跨端方案按「产物形态」分:转译型(uni-app/Taro,产物是各平台原生代码)和渲染型(React Native/Flutter,自绘引擎)。
  • 转译型上手快、跨平台一致性更好,但受限于目标平台的渲染能力;渲染型性能上限高,但要处理原生差异。
  • 选型的第一考量是团队技术栈:Vue 团队选 uni-app,React 团队选 Taro/RN。
  • 不要只看「一次编写多端运行」,还要算上调试成本和平台特性缺失时的兜底方案。
