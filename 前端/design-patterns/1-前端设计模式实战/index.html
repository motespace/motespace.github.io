Q1: 用过什么设计模式？

Section titled “Q1: 用过什么设计模式？”

答：

  • 观察者/发布订阅：Vue 响应式、EventBus
  • 单例：Toast、Modal 全局管理器
  • 策略：表单校验、规则引擎
  • 装饰器：日志、缓存、TS 装饰器
  • 组合：菜单树、表单 List
  • 状态机：订单、加载状态

Q2: Vue 响应式用了什么模式？

Section titled “Q2: Vue 响应式用了什么模式？”

答：观察者模式 + Proxy 代理。Dep 是被观察者，Watcher 是观察者，Proxy 拦截 get/set。

Q3: 表单校验用什么模式？

Section titled “Q3: 表单校验用什么模式？”

答：策略模式。每种校验规则是一个策略（RequiredStrategy / EmailStrategy / MinLengthStrategy），可替换可扩展。

Q4: 单例模式有什么坑？

Section titled “Q4: 单例模式有什么坑？”

答：

  • 多 Tab 共享：每个 Tab 独立 VM 时不是单例了
  • 测试：单例难 mock
  • 解决：用依赖注入替代（React Context / Vue Provide）

Q5: 状态机和 Redux 区别？

Section titled “Q5: 状态机和 Redux 区别？”

答：

  • 状态机：定义状态 + 合法转换（如 XState）
  • Redux：reducer 函数管理状态，没有强约束转换
  • 实战：复杂业务（订单 / 工作流）用 XState

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • MVVM 在 React 中怎么实现? View = 组件;ViewModel = hooks / store;Model = 数据层
  • 观察者模式 vs 发布订阅? 观察者:Subject 直接通知 Observer;发布订阅:中间 EventBus
  • 策略模式在前端应用? 表单校验(不同规则);支付方式(不同渠道);权限策略
  • 单例模式注意? ES Module 本身就是单例;前端主要用 Module Pattern
  • 装饰器模式 React 应用? HOC 模式;但 React 官方已不推荐(嵌套地狱)

📝 小结

Section titled “📝 小结”
  • 前端模式的落点是「解决具体的前端问题」,不是照搬 GoF。
  • 最常用三个:单例(API client)、策略(可配置的行为)、观察者(跨组件通信)。
  • 组件里的「配置驱动」本质是策略模式 —— 把变化点做成配置。
  • 判断该不该用模式:先写 if-else,分支超过 3 个且会增长再抽。
