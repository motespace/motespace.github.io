十、面试高频追问

Section titled “十、面试高频追问”

Q1: 你们的 UI 风格怎么统一？

Section titled “Q1: 你们的 UI 风格怎么统一？”

答：通过设计系统——Design Token（CSS 变量 / JS 变量）+ 组件库 + Storybook + 设计原则文档。一处改全局生效。

Q2: 怎么和设计师协作？

Section titled “Q2: 怎么和设计师协作？”

答：设计师用 Figma Variables 维护 Token，前端用 Style Dictionary 自动转 CSS / JS。组件库用 Storybook 文档化。

Q3: 多主题怎么实现？

Section titled “Q3: 多主题怎么实现？”

答：CSS 变量 + data-theme 切换。或 Emotion / styled-components ThemeProvider。

Q4: 设计系统怎么落地？

Section titled “Q4: 设计系统怎么落地？”

答：

  1. 抽离现有组件到 packages/ui
  2. 用 Storybook 写文档
  3. 用 Design Token 统一变量
  4. 推动新项目使用，渐进式迁移旧项目

Q5: 怎么控制组件库体积？

Section titled “Q5: 怎么控制组件库体积？”

答：ES Modules + Tree Shaking + 按需引入 + 拆包。

面试追问(深化原 Q1-Q5)

Section titled “面试追问(深化原 Q1-Q5)”
  • 设计 Token 4 层? Global(品牌色) → Alias(语义色 primary) → Component(组件用) → Instance(具体值)
  • Ant Design / Material UI vs 自研? 中小项目:用现成的(快);大厂:自研(可控 + 品牌差异化)
  • shadcn/ui 优势? 复制源码到项目,完全可控;Tailwind + Radix 组合
  • 设计系统怎么和业务解耦? 业务组件只依赖 Token;主题切换通过 CSS 变量

📝 小结

Section titled “📝 小结”
  • 设计系统的价值是决策复用:颜色、间距、字号的取值收敛到有限集合。
  • Token 分三层:原始值 → 语义 token → 组件 token,换主题只改语义层。
  • 组件库要区分「业务无关的基座」和「带业务语义的封装」,后者放在业务仓库。
  • 落地难点不是写组件,是推动别人用 —— 需要 lint 规则和 code review 卡。
