UniApp 状态管理:Pinia / Vuex / 全局方案

一、为什么需要状态管理

Section titled “一、为什么需要状态管理”

UniApp 多个页面共享数据,常见需求:

  • 用户登录信息(全局)
  • 购物车(跨页面)
  • 主题/语言设置(全局)
  • WebSocket 连接状态(全局)

不用状态管理的问题:

  • 页面间传值麻烦(URL query、globalData、Storage)
  • 数据不同步(多个页面各自维护)
  • 难以追踪状态变化

📝 小结

Section titled “📝 小结”
  • 状态分三类:全局共享(Pinia/Vuex)、页面级(页面 data)、组件级(props/local)。
  • 小程序端推荐 Pinia:更轻、TS 友好、SSR 场景需手动持久化;Vuex 只在老项目维护。
  • globalData 只适合放「几乎不变的全局常量」(token、用户信息),不能放高频变化的数据,因为它不是响应式的。
  • 跨页面通信:URL 参数(少量)、Pinia(结构化)、uni.setStorageSync(持久化)。
  • 持久化方案:Pinia plugin 监听 store.$subscribe 写入 storage,启动时 hydrate;注意 storage 同步 API 在低端机有性能问题,大数据用异步 API。
  • SSR/H5 注意:服务端没有 window,状态初始化不能依赖浏览器 API。
  • 面试加分:说清「为什么状态管理不是越多越好」——能用局部状态解决就不要上全局,全局状态会让组件难以复用。

面试常考

Section titled “面试常考”

Q1:UniApp 状态管理 3 种?

Section titled “Q1:UniApp 状态管理 3 种?”

答:

  • Pinia (Vue 3 推荐):组合式 API,完整 TS 支持
  • Vuex (老项目):Vue 2 时代标配
  • globalData:App 级全局变量(简易)
  • 选:新项目 Pinia;老项目 Vuex;轻量 globalData

Q2:跨页面通信 4 种?

Section titled “Q2:跨页面通信 4 种?”

答:

  • URL 参数(简单);globalData(全局);uni.$emit/$on(事件);Pinia store(推荐)
  • 实战:页面间传参用 URL;跨页面共享状态用 Pinia
