UniApp 条件编译:一套代码多端发布

一、为什么需要条件编译

Section titled “一、为什么需要条件编译”

UniApp 一套代码要编译到多个端(微信小程序、App、H5、抖音小程序……),但不同端的能力不一样:

  • App 端有 native-plugin(原生插件)
  • 小程序没有 DOM,只有组件树
  • H5 支持完整 Web API
  • 抖音小程序不支持某些微信 API

如果不用条件编译:

  • 写一份代码,某些端运行时报错
  • 写多份代码,维护噩梦

条件编译就是:让一份代码在编译期变成多份,每份针对目标端优化。

📝 小结

Section titled “📝 小结”
  • 条件编译是编译期裁剪,不是运行时 if:写法 // #ifdef MP-WEIXIN ... // #endif,写在注释里,编译器按平台裁剪。
  • 平台标识:APP-PLUS、APP-NVUE、H5、MP-WEIXIN、MP-ALIPAY、MP-BAIDU、MP-ALL、quickapp-webview。
  • 典型用法:支付 API(微信支付 vs 支付宝)、分享、登录授权、导航栏样式、原生插件调用。
  • 条件编译 vs 运行时判断:能用条件编译就别用运行时 if——运行时判断仍会把另一端代码打进包体,增加体积。
  • 条件组件/文件:整目录或文件用 ifdef 命名约定(mp-weixin/),构建时只保留目标端目录。
  • 陷阱:条件编译块里不能定义跨块共用变量;#ifndef 是「除了该平台都生效」,常用于写平台独有实现。

Q1:条件编译怎么用?

Section titled “Q1:条件编译怎么用?”

答:

  • JS:// #ifdef H5 / // #endif(只在 H5 编译)
  • CSS:/* #ifdef MP-WEIXIN */ / /* #endif */
  • 模板:&lt;view v-if="..." /&gt; + 平台标识
  • 文件级:platforms.mp-weixin/index.vue 只在小程序编译
  • 平台标识:H5 / MP-WEIXIN / MP-ALIPAY / APP-PLUS / APP-ANDROID / APP-IOS

Q2:条件编译 vs 运行时判断?

Section titled “Q2:条件编译 vs 运行时判断?”

答:

  • 条件编译:编译期剔除;产物体积小、性能好;推荐
  • 运行时判断:if (uni.getSystemInfoSync().platform === 'ios') {} 运行时分支;兼容所有平台
  • 实战:能用条件编译就用;跨平台统一逻辑用运行时
