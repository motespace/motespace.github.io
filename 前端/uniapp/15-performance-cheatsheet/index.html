UniApp 性能优化速查

详细文档：UniApp 性能优化详解

一、视图层优化

Section titled “一、视图层优化”
优化点 方法
避免频繁 setData 合并数据更新,减少通信
频繁切换显示 用 v-show(切 display)
偶尔切换 用 v-if(销毁/创建)
长列表渲染 虚拟滚动 / 无限滚动
图片懒加载 loading-img 占位 + 滚动加载
复杂动画 走原生(nvue)
弹窗用组件 不用 v-if 嵌套

二、逻辑层优化

Section titled “二、逻辑层优化”
优化点 方法
减少同步 API 用异步替代(uni.request)
数据缓存 setStorage 缓存常用数据
避免重复请求 onShow 内做请求去重
计算量大 用 Web Worker(部分端)
长任务 拆分,setTimeout 让出主线程
图片处理 客户端压缩,服务端转码

三、包体积优化

Section titled “三、包体积优化”

3.1 分包加载

Section titled “3.1 分包加载”

实战经验:

  • 主包只放首屏必需的页面(< 2MB)
  • 其他页面放分包,按需加载
  • 分包之间能共享资源

3.2 静态资源优化

Section titled “3.2 静态资源优化”
类型 优化
图片 WebP / AVIF, < 100KB
图标 SVG sprite / iconfont
视频 不用本地,走 CDN 流媒体
音频 压缩,流式加载

3.3 tree-shaking

Section titled “3.3 tree-shaking”

HBuilderX / Vite 默认开启 tree-shaking,只打包用到的代码。

九、关键指标

Section titled “九、关键指标”

📝 小结

Section titled “📝 小结”
  • 记住四类指标就够:包体积、首屏时间、setData 频次、长列表帧率。
  • 优化手段按收益排序:分包 > 图片压缩 > 减少 setData > 虚拟列表 > 缓存/预请求。
  • 关键指标:小程序启动耗时看「小程序启动性能评分」,页面渲染看 Performance 面板与真机 performance 面板。
  • 跨端差异性能:H5 端受浏览器与网络影响大;App 端要关注原生插件与 WebView 版本。
  • 面试可用的数字:「首屏从 2.5s 降到 1.2s」这类有量化的优化结果,比罗列手段更有说服力。

Section titled “面试常考”

Q1:首屏加载优化 5 个关键?

Section titled “Q1:首屏加载优化 5 个关键?”

答:

  • 分包加载:subPackages 拆分主包 + 子包;首包 < 2MB
  • 按需引入:组件库用 easycom 自动,避免全量
  • 图片优化:CDN + WebP + 懒加载 + 合理尺寸
  • 骨架屏:减少白屏感知
  • 预加载:preloadRule 预下载子包

Q2:大列表卡顿怎么优化?

Section titled “Q2:大列表卡顿怎么优化?”

答:

  • 虚拟列表:&lt;recycle-scroller&gt; (uni-ui) / 自己实现(只渲染可视区)
  • 分页加载:onReachBottom 加载下一页
  • 图片懒加载:lazy-load 属性
  • 避免复杂计算:computed 缓存 / 异步处理
