Q1: 如何优化长列表性能？

Section titled “Q1: 如何优化长列表性能？”
  1. 使用 scroll-view 替代页面滚动
  2. 设置固定高度
  3. 使用唯一 key
  4. 超过 1000 项考虑虚拟列表
  5. 分页加载而非一次性加载

Q2: 为什么 setData 频繁导致卡顿？

Section titled “Q2: 为什么 setData 频繁导致卡顿？”

每次 setData 都会触发逻辑层和渲染层的通信，过度频繁会导致通信阻塞。优化方法：

  • 减少 setData 频率
  • 减少单次数据量
  • 使用局部更新而非全量更新

Section titled “Q4: 小程序包体积超限怎么办？”

🎯 面试常考

Section titled “🎯 面试常考”

Q1:UniApp 性能优化 3 层?

Section titled “Q1:UniApp 性能优化 3 层?”

答:

  • 启动:分包加载、预加载、按需引入
  • 运行:避免大列表渲染、虚拟列表、图片懒加载
  • 包体积:tree-shaking、压缩、避免引入完整库
  • 工具:微信开发者工具 → 代码质量评分

Q2:v-if vs v-show 在 UniApp?

Section titled “Q2:v-if vs v-show 在 UniApp?”

答:

  • 同 Vue:v-if 真销毁/创建;v-show 切 display
  • 跨端差异:H5/小程序都支持;v-if 切换开销大(不常用)
  • 频繁切换(如 Tab)用 v-show

📝 小结

Section titled “📝 小结”
  • 小程序性能核心是减少 setData:一次更新只传必要字段,避免整对象 setData,大数据分页。
  • 长列表用虚拟滚动组件,首屏用骨架屏 + 分包加载。
  • 包体积:主包控制在 2MB 以内,图片用 static + 压缩,大依赖(图表、富文本)分包或按需引入。
  • 首屏:把非必要请求延后(渲染后触发)、合并接口、缓存首屏数据。
  • 逻辑层:减少 setInterval、节流防抖、避免同步重计算、耗时操作分片。
  • 面试加分:能说出「setData 的通信成本 = 数据序列化 + 视图层 diff」,这是小程序端和 Web 端性能模型的本质差别。
