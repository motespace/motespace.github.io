Multi-Agent 多智能体系统

Multi-Agent = 多个 Agent 分工协作,完成复杂任务。 单个 Agent 解决不了的复杂任务(研究 + 写作 + 审阅),用 Multi-Agent 拆分。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：为什么需要 Multi-Agent?

工具和上下文会互相干扰:工具一多 schema 全进上下文,token 爆炸且 prompt 互相污染。拆成子 Agent 后,每个只带自己那套工具和上下文,主 Agent 只做路由。

Q2：怎么拆 Agent?

按「能力域」拆而不是按「流程步骤」拆:研究 Agent、写作 Agent、审核 Agent。共享状态通过消息传递,不要共享可变对象。

Q3：多 Agent 的代价?

Token 消耗成倍增加(每个子 Agent 都要重复读上下文)、延迟叠加、错误排查链路变长。所以要先确认单 Agent + 好工具真的做不了。

📝 小结

Section titled “📝 小结”
  • 多 Agent 的动机:职责分解(不同子任务需要不同工具与 Prompt)、上下文隔离(各自看不同的信息,避免互相污染)、并行提速。
  • 三大模式:Supervisor(一个中心 Agent 路由到专家 Agent,最常用最稳)、Swarm/交接(Agent 之间直接转交,handoff)、Debate/并行(多 Agent 独立作答再聚合,适合有唯一正确答案的任务)。
  • Supervisor 实现:共享 State + 多个专家节点 + 一个路由节点决定下一个专家 + 条件边分发。
  • 风险:路由错误(选错专家)、上下文丢失(子 Agent 看不到别的 Agent 的发现)、协调开销、成本翻倍。
  • 最佳实践:先试单 Agent + 多工具,不够再拆;拆分时给每个 Agent 明确的输入输出契约;共享信息走 State 而不是自由对话。
  • 面试加分:能讲「Supervisor 模式下 State 是唯一的真相来源」,避免子 Agent 之间传话丢失信息。
