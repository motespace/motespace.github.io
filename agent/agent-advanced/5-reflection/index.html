🎯 面试常考

Section titled “🎯 面试常考”

Q1：Reflection 是什么?

让 Agent 自检:生成 → 批评 → 修正,循环到通过或达到最大轮数。可以针对整体输出,也可以针对单个维度(事实性、完整性、语气)。

Q2：Reflection 的风险?

① 可能把对的改错;② 可能陷入死循环;③ 反思本身要调模型,成本翻倍。必须配最大轮数、超时和「不再修改就交付」的兜底。

Q3：什么时候值得开 Reflection?

错误代价高且能自动检测(代码、SQL、计算结果);开放式写作的反思收益低、风险高,更适合人工审阅。

📝 小结

Section titled “📝 小结”
  • 反思解决的是输出质量不稳:生成 → 评价 → 按评价重生成,是一个带评价节点的循环。
  • Reflexion(论文级):把失败原因写进「反思记忆」,下次同类问题避免重犯。
  • Self-RAG:检索与生成都自评,决定「要不要检索」「检索结果够不够好」。
  • CRAG:检索质量差时走纠正路径(重新检索或用更宽松的生成策略),而不是硬答。
  • HITL:在关键节点用 interrupt 暂停,等人工确认后 Command(resume=...) 继续;适合高风险操作(付款、发布、删除)。
  • 反思的代价是额外 token 与延迟,所以要有触发条件(只在低置信度或校验失败时反思),不能无脑反思。
  • 面试加分:讲清「反思是带条件触发的重试,不是无条件多跑一遍」,这体现成本意识。
