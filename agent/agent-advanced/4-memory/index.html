Memory 机制

Memory = Agent 的“长期记忆”。让 Agent 跨对话 / 跨任务记住用户偏好、历史、上下文。 没有 Memory 的 Agent = 失忆症患者。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：Agent 的记忆分几层?

短期(会话内:滑动窗口 / 摘要压缩)、长期(跨会话:向量库存用户偏好和事实,按需检索)、工作记忆(当前任务的中间产物,常放 State)。

Q2：上下文满了怎么办?

三种策略:滑动窗口(丢最老的)、摘要压缩(把历史压成摘要)、外部化(把细节写进存储,只留指针)。多数场景「摘要 + 外部检索」组合最实用。

Q3：长期记忆怎么存?

向量库存语义检索,配合元数据过滤(按 user_id / 时间 / 类型)。要处理记忆污染:写入前判断是不是无意义内容,检索时给相似度设阈值。

📝 小结

Section titled “📝 小结”
  • 记忆三层:短期(当前会话上下文)、长期(跨会话的用户偏好/事实,存外部 DB)、语义(可检索的知识,与 RAG 重叠)。
  • LangGraph 的短期记忆靠 checkpoint + thread_id:同一 thread 的状态自动累积,跨会话恢复靠换 thread_id。
  • 长期记忆的实现范式:从对话中抽取事实 → 存向量库/关系库 → 下次按相关性检索注入上下文;不是把全部历史塞进去。
  • 关键取舍:记忆要能过期与被纠正(用户说「我搬家了」要能更新旧事实),否则模型会被过期记忆污染。
  • 记忆注入会占 token,要做相关性筛选(只注入 top-k 相关记忆),并统计记忆带来的成本与收益。
  • 面试加分:能讲清「记忆 = 检索 + 写入策略 + 过期治理」,而不是「把历史都存起来」。
