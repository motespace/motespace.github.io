从 Demo 到生产:Agent 还差什么?

“能跑的 Demo” 和 “能上生产的 Agent” 之间,隔着五个缺口。

一、Demo 和生产的差距

Section titled “一、Demo 和生产的差距”

一个教程里的 Agent 通常长这样:

能上生产的版本至少要处理:

  • 工具接进来要标准化(不能每个工具一套调用格式)
  • 多个 Agent 要协作(不是一个 Agent 什么都干)
  • 对话要记得住(跨会话)
  • 答错了要能自我修正
  • 危险操作要人能拦住

下面五节,正好对应这五个缺口。

二、五个缺口

Section titled “二、五个缺口”

缺口 1:工具接入不标准化 → MCP

Section titled “缺口 1:工具接入不标准化 → MCP”

每个工具自己定义 schema、自己解析参数、自己处理鉴权,工具一多就没法维护。

MCP(Model Context Protocol) 把“工具/资源/提示词”的接入方式统一成一个协议:客户端(你的 Agent)连接 MCP Server,Server 暴露工具列表,调用方式完全一致。加一个新工具 = 起一个 MCP Server,不用改 Agent 代码。

缺口 2:一个 Agent 干不了所有事 → Multi-Agent

Section titled “缺口 2:一个 Agent 干不了所有事 → Multi-Agent”

把“查数据库”、“写文案”、“做审核”塞进一个 Agent,上下文会被撑爆,而且每一步的 prompt 都在互相干扰。

Multi-Agent 的思路是拆:一个主 Agent 负责路由,几个子 Agent 各自专精(每个有独立的上下文和工具集),主 Agent 决定交给谁。

缺口 3:对话记不住 → Memory

Section titled “缺口 3:对话记不住 → Memory”

无状态意味着每轮对话都要把全部历史重新传一遍,token 成本线性增长,长对话还会超出窗口。

Memory 分两层:短期(会话内滑动窗口 / 摘要压缩)+ 长期(向量库存用户偏好、事实,按需检索)。

缺口 4:答错了没人纠正 → Reflection

Section titled “缺口 4:答错了没人纠正 → Reflection”

Agent 一次输出就交付,错了也是错的。

Reflection 模式让 Agent 自检:生成 → 批评 → 修正,循环直到通过。配合 LangGraph 就是天然的环。

缺口 5:危险操作拦不住 → Human-in-the-Loop

Section titled “缺口 5:危险操作拦不住 → Human-in-the-Loop”

付款、删除数据、对外发邮件 —— 这些必须有人点头。靠 Prompt 里写“请谨慎”是没用的,必须在执行层拦截。

三、五个缺口的关系

Section titled “三、五个缺口的关系”

它们不是并列的五个技巧,而是从“能跑”到“敢上线”的五个必要条件。少一个,Agent 就会以某种方式在生产环境出事:

缺了 后果
工具标准化 工具越多越难维护,加一个改一片
Multi-Agent 上下文爆炸、成本失控
Memory token 成本线性增长,长对话失效
Reflection 错误直接交付给用户
Human-in-the-Loop 误操作不可逆

Section titled “四、这一节的读法”

后续章节是按这个顺序展开的:

🎯 面试常考

Section titled “🎯 面试常考”

Q1:一个 Agent 要上生产,需要补齐哪些能力? 五个方面:工具接入标准化(MCP)、多 Agent 分工、记忆(短期窗口 + 长期检索)、反思自纠、人工审批介入。这五项分别对应“可维护、可扩展、可负担、可靠、可控”。

Q2:为什么需要 Multi-Agent,一个 Agent 加更多工具不行吗? 工具一多,每个工具的 schema 都进上下文,既费 token 又互相干扰;而且不同任务需要的上下文完全不同。拆成子 Agent 后,每个子 Agent 只带自己那套工具和上下文,主 Agent 只做路由。

Q3:Reflection 有什么风险? 反思循环可能陷入死循环,也可能把正确答案“反思”成错误答案。所以要给最大轮数、超时和“不再修改就交付”的兜底策略。

Q4:Human-in-the-Loop 一定要放在执行层吗? 是。写在 Prompt 里(“执行前请先确认”)只是建议,模型可能不遵守;放在执行层(工具调用前挂起,等人放行)才是真正的拦截。LangGraph 的 interrupt_before 就是干这个的。

📝 小结

Section titled “📝 小结”
  • Demo 与生产的差距不在模型,在工程:工具标准化、多 Agent、记忆、反思、人工介入这五项。
  • 五项缺失分别对应五种生产事故,可维护性、可扩展性、成本、可靠性、可控性。
  • Reflection 必须配最大轮数与兜底,否则会自我否定或死循环。
  • Human-in-the-Loop 必须在执行层拦截,Prompt 层面的“请谨慎”没有强制力。
