MCP = 让 LLM 标准化接入外部工具 / 数据源的协议。 Anthropic 2024 年发布,Claude / Cursor 等都已支持,业界趋势。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：MCP 是什么?

Model Context Protocol,Anthropic 提出的开放协议,用来标准化「模型/Agent 怎么接工具和数据源」。客户端连 MCP Server,Server 暴露 tools / resources / prompts。

Q2：用 MCP 的好处?

工具接入标准化:加新工具只需起一个 Server,不用改 Agent 代码;还能让 Claude Desktop、Cherry Studio 等客户端直接复用同一套工具。

Q3：MCP 和普通 Function Calling 区别?

Function Calling 是模型能力(模型输出调用意图),MCP 是接入协议(工具怎么被描述和调用)。两者互补:MCP 定义工具,Function Calling 让模型去调。

📝 小结

Section titled “📝 小结”
  • MCP 是把工具与资源暴露给模型的开放协议,解决了「每家模型一套工具接口」与「工具无法跨应用复用」两个问题。
  • 三个角色:Host(编排方,持有 LLM 与用户交互)、Client(Host 内与 Server 通信的一侧)、Server(提供工具/资源/提示词)。
  • 三类资源:Tools(模型可调用)、Resources(可读数据,类似文件)、Prompts(可复用模板)。
  • 传输:stdio(本地子进程,如 Claude Desktop)与 SSE / Streamable HTTP(远程服务)。
  • 实现路径:Python(mcp SDK,FastMCP 装饰器最省事)、Node(@modelcontextprotocol/sdk)、TypeScript 版;调试用 mcp dev。
  • 与 Function Calling 的关系:FC 是模型厂商的私有协议,MCP 是开放标准;一套 MCP Server 可接多家模型与客户端。
  • 面试加分:讲清「MCP 的价值是工具复用与模型可迁移」,并说清 Host/Client/Server 的职责边界。
