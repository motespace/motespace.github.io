Python 异步编程(asyncio / await)

AI Agent 高并发场景必备。并发调用多个 LLM API / 异步 I/O 操作, 不用异步就只能串行,慢 10 倍不止。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：async/await 解决什么问题?

在 I/O 等待期间让出控制权,单线程就能并发处理大量 I/O。调 LLM API 全是网络 I/O,是 async 的典型场景。

Q2：什么时候不该用 async?

CPU 密集任务(async 不会让 CPU 并行,反而增加开销);或者代码只有一两个串行调用,直接用同步更清晰。

Q3：并发调用多个 LLM 怎么写?

asyncio.gather(*[client.ainvoke(p) for p in prompts]) 或 asyncio.as_completed(...);配合 httpx.AsyncClient 连接复用。

📝 小结

Section titled “📝 小结”
  • asyncio 解决 IO 密集并发(等待网络、DB、文件),不是 CPU 密集;CPU 密集要 ProcessPoolExecutor 或 C 扩展。
  • 语法:async def 定义协程、await 等待;调用协程函数不会自动执行,必须 await 或 asyncio.run()。
  • 核心组件:Task(并发任务单元)、gather(并发执行并取全部结果)、wait_for(超时)、Semaphore(并发上限)、TaskGroup(结构化并发)。
  • asyncio.sleep 是让出控制权;在协程里做 CPU 密集计算会阻塞整个事件循环——这是最常见的坑。
  • 与 JS 对比:JS 的 Promise 是自动调度的微任务,Python 必须显式创建 Task 才会并发;await 更像串行等待。
  • 面试加分:能讲清「asyncio 与 Node 事件循环的差异」——Python 需要显式调度,JS 是自动的。
