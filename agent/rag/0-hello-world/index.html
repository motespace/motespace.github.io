七、Hello RAG 总结

Section titled “七、Hello RAG 总结”
概念 一句话
Embedding 把文本变成向量(让计算机能“比较”)
向量库 存向量 + 高效检索(FAISS / pgvector)
检索 找最相关的几段
Prompt 把“参考资料 + 问题”塞给 LLM
生成 LLM 基于参考资料回答

核心:RAG = 检索 + 生成,让 LLM 用你的数据回答。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：RAG 的最小实现是什么?

把文档切片 → 算 Embedding 存进向量库 → 用户提问时用同样模型算 query 向量 → 检索 top-k 片段 → 拼进 Prompt 让模型基于片段回答。

Q2：为什么不直接把文档全塞进 Prompt?

上下文窗口有限、成本随文档量线性上升、模型容易「大海捞针」漏掉中间信息。检索能只给最相关的片段。

📝 小结

Section titled “📝 小结”
  • RAG = 先检索资料、再把资料塞进 Prompt 让模型基于资料回答,用外部知识补上模型的短板。
  • 20 行就能跑通:准备文档 → Embedding → 存向量库 → 检索 → 拼 Prompt → 调 LLM → 输出。
  • 最小代码用 FAISS(内存向量库,开发够用)或 Chroma 持久化。
  • 效果验证:问一个文档里明确有答案的问题,确认答案来自资料而不是模型记忆。
  • 这个 Hello World 的价值是打通全链路,后面每一步的复杂度都是在这条链上叠加的。
  • 面试加分:能说出「RAG 的本质是把「检索」插在模型回答之前,让模型的输出有据可依」。
