Embedding 模型选型

Embedding = 把文本变成向量(数字数组),让计算机能“理解”语义相似度。 选错 Embedding 模型 = 检索效果差 = RAG 失败。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：Embedding 是什么?

把文本映射成固定维度的稠密向量,语义相近的文本向量距离更近。检索时用余弦相似度找最相关的片段。

Q2：怎么选 Embedding 模型?

看中文效果、维度(维度越高存储越大)、是否支持多语言、是否开源可私有部署、以及是否和你要用的向量库兼容。

Q3：为什么换 Embedding 模型要重建索引?

不同模型的向量空间不通用,旧向量和新模型算出来的距离没有意义,必须全部重新生成。

📝 小结

Section titled “📝 小结”
  • Embedding 把文本映射成固定维度的向量,语义相近 → 向量距离近;相似度常用余弦相似度。
  • 维度越高精度可能越好但存储与计算更贵;常见 384 / 768 / 1536 维。
  • 选型维度:中英文效果(中文业务务必试)、维度、是否多语言、开源可私有化、价格与速度。
  • 主流:OpenAI text-embedding-3-*、BGE(中文强、开源)、GTE、Cohere Embed、多语言用 multilingual-e5。
  • 关键工程点:同一套文档与查询必须用同一个 embedding 模型与同一版本,换了模型必须全量重建索引。
  • 面试加分:能讲「embedding 模型换了不清索引,是 RAG 线上效果突然崩掉的常见原因」——这是真实踩坑。
