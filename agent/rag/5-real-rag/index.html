🎯 面试常考

Section titled “🎯 面试常考”

Q1：完整 RAG 项目怎么组织?

分两层:离线索引脚本(加载 → 分块 → 向量化 → 入库)和在线服务(检索 → 拼接 → 调用 LLM → 返回引用)。两部分要能独立重跑。

Q2：上线前要准备什么?

评估集(问题 + 标准答案 + 期望引用片段)、检索与生成的分项指标、引用溯源的展示、失败兜底(检索不到时明说而不是编)。

📝 小结

Section titled “📝 小结”
  • 完整项目结构:ingest(离线加载切分建索引)/ retriever(检索)/ chain(拼 prompt 生成)/ api(对外服务)/ config。
  • 离线与在线分离:文档变更走增量 ingest,查询走在线检索;索引要有版本与重建机制。
  • 工程要点:配置与密钥走环境变量、日志记录召回的 chunk 与相似度(否则无法排查效果)、加评测脚本、接口加超时与降级。
  • 质量闭环:准备 20~50 条问题集,记录答案正确率与引用准确率,改切分/检索参数后回归。
  • 常见坑:切分大小拍脑袋、top-k 太小、没加「不知道就说不知道」导致幻觉、没有记录召回内容导致无法排查。
  • 面试加分:讲清「RAG 上线后我怎么发现效果变差了」——靠评测集 + 线上引用点击率/点赞率。
