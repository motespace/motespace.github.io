RAG 入门(整体流程)

RAG = Retrieval-Augmented Generation,让 LLM 基于私有知识库回答问题。 解决 LLM 的两大痛点:知识陈旧和幻觉。

二、RAG vs Fine-tuning

Section titled “二、RAG vs Fine-tuning”
维度 RAG Fine-tuning
数据要求 任意大小 大量标注数据
更新成本 低(改文档即可) 高(重新训练)
可解释性 ✅ 来源可追溯 ❌ 黑盒
训练时间 0(无需训练) 数小时到数天
适合 知识更新频繁 模型行为定制
推荐 90% 场景 高级定制

最佳实践:RAG 优先,Fine-tuning 兜底(两者可结合)。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：RAG 的完整流程?

离线:加载 → 分块 → Embedding → 入库;在线:问题 Embedding → 检索 → 重排 → 拼 Prompt → 生成 → 引用溯源。

Q2：RAG 怎么评估?

检索侧看召回率(正确片段有没有被检索到,Recall@k / MRR);生成侧看忠实度(faithfulness,回答是否只依赖检索内容)和相关度。检索没召回,生成再好也没用。

📝 小结

Section titled “📝 小结”
  • 为什么需要 RAG:知识会过期、私域数据模型没见过、需要可追溯来源、改知识比重新训练便宜一万倍。
  • RAG vs 微调:微调改变模型的行为与风格,RAG 改变模型能看到的知识;要最新事实与可溯源 → RAG,要固定输出格式与风格 → 微调。
  • 五步流程:加载 → 切分 → Embedding → 存储 → 检索 → 拼 Prompt → 生成(严格说是七步,切分与向量化是质量关键)。
  • 每一步的失败模式要记住:切分不当(答案被切断)→ 召回差;向量模型不合适 → 语义不匹配;检索 top-k 太小 → 找不到;Prompt 没约束 → 不用资料硬答。
  • 质量指标:召回率(该找到的找到了吗)与准确率(找到的是相关的吗),先看召回再看生成。
  • 面试加分:能讲「RAG 做不好通常是检索问题,不是模型问题」——这个判断能帮你在面试里把话题引向工程深度。
