🎯 面试常考

Section titled “🎯 面试常考”

Q1：向量数据库的核心能力?

存向量 + 建索引(用于近邻检索 ANN) + 元数据过滤 + 增删改查。典型:Chroma(简单)、FAISS(库不是服务)、pgvector(复用 Postgres)、Milvus(大规模)。

Q2：怎么选向量数据库?

数据量小(<百万)选 Chroma 或 pgvector 足够;千万级以上考虑 Milvus/Qdrant 独立部署。同时看是否支持元数据过滤和混合检索。

Q3：索引类型 HNSW 和 IVF 有什么区别?

HNSW 是图索引,召回高、查询快、内存占用大;IVF 是聚类倒排,内存友好但要调 nlist/nprobe,召回略低。

📝 小结

Section titled “📝 小结”
  • 向量库的核心能力:相似度检索、元数据过滤(按租户/时间/类型)、持久化、增删改、规模与延迟。
  • 选型:Chroma(最快上手)、FAISS(本地库,需自己管持久化)、pgvector(已有 Postgres 就用它,最省事)、Milvus/Qdrant(大规模生产)、Pinecone(托管)。
  • 中小规模优先 pgvector:省一套系统、事务一致、权限统一,这是最被低估的选型。
  • 检索模式:暴力检索(精确,数据小够用)vs 近似最近邻(HNSW/IVF,大数据量加速但有召回损失)。
  • 元数据过滤是最有用的能力:按租户过滤就能把多租户 RAG 做对。
  • 面试加分:能讲「为什么生产上我建议 pgvector 而不是再引一个向量库」——系统越少越好维护。
