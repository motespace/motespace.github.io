🎯 面试常考

Section titled “🎯 面试常考”

Q1：AI 应用要监控什么?

四类:调用指标(QPS、延迟、错误率)、Token 成本(按模型和场景拆)、质量指标(用户反馈、检索命中率)、链路追踪(每次对话的完整调用链)。

Q2：怎么排查一次慢请求?

用 trace 看每个环节耗时:LLM 首 token 时间 vs 总生成时间、工具调用耗时、检索耗时。有了 trace 才知道是模型慢还是工具慢。

Q3：怎么防止成本失控?

① 按用户/会话设置 token 预算并熔断;② 简单请求路由到小模型;③ 缓存相同问题的答案;④ 对输出长度设上限。

📝 小结

Section titled “📝 小结”
  • 三大支柱:指标(Metrics)、日志(Logs)、追踪(Tracing);Agent 场景还要加Token 与成本追踪。
  • 必备指标:请求量、P50/P95/P99 延迟、错误率、token 消耗与单会话成本、工具调用成功率、Agent 步数与终止率。
  • 追踪用 OpenTelemetry:一次请求一个 trace,span 记录「模型调用 / 工具调用 / 检索」,才能定位慢在哪一步。
  • 日志要带结构化上下文:thread_id、user_id、模型名、prompt 版本、token 数、工具名;敏感信息脱敏。
  • 成本看板:按用户/功能/模型拆 token 消耗,找出贵的那 10% 流量。
  • 告警要有基线与阈值(P95 延迟、错误率突增、成本日环比),避免告警疲劳。
  • 面试加分:讲「没有 token 与步数的追踪,就无法给 Agent 做成本治理」。
