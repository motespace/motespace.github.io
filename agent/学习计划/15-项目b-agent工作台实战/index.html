Section titled “第二步：LangGraph 核心抽象”

2.1 为什么需要 LangGraph？

Section titled “2.1 为什么需要 LangGraph？”

LangChain 的 AgentExecutor（早期版本）的问题：

  • 流程是线性的，难处理复杂分支
  • 状态保存在消息里，难以管理
  • 难以实现人工介入

LangGraph 提供：

  • 图结构（StateGraph）
  • 显式状态（TypedDict）
  • 条件边（Conditional Edges）
  • 持久化（Checkpointing）
  • 人工介入（Interrupt）

第五步：MCP 协议集成

Section titled “第五步：MCP 协议集成”

5.1 什么是 MCP？

Section titled “5.1 什么是 MCP？”

Model Context Protocol，Anthropic 2024 年底提出的工具集成标准。

类比：

  • USB-C：硬件的统一接口
  • MCP：AI 工具的统一接口

之前每个 Agent 框架都有自己的工具格式（MCP 之前）：

  • LangChain Tool
  • Anthropic Tool Use
  • OpenAI Function Calling
  • LlamaIndex Tool

MCP 之后：所有工具都用 MCP 标准，任何 Agent 都能调用。

9.2 简历话术

Section titled “9.2 简历话术”

项目 B：AI Agent 工作台

背景：解决复杂任务需要多步操作的痛点。

技术栈：LangGraph · FastAPI · MCP · Plan-and-Execute · SSE

职责：

  • 设计 Plan-and-Execute 模式，让 Agent 自主拆解任务

  • 实现 Human-in-the-Loop，关键操作需人工确认

成果：单 Agent 可完成原本需要 3-4 步手动操作的任务

  • 第一步理解「从 LLM 调用到 Agent 的进化」:一次调用 → 多轮工具循环 → 显式状态机 → 可持久化工作流。
  • 分步推进:先单工具 → 再多工具 + 路由 → 再 LangGraph 图 → 再加记忆与人工确认。
  • 关键工程点:工具的 description 决定模型选不选它、参数必须二次校验、危险操作要人工确认、每步记录 token 与耗时。
  • 面试加分:能讲「我把 Agent 从黑箱自主决策改成显式状态机」,并说明收益(可控、可测、可恢复)。
