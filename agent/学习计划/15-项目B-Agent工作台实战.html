第一步：从 LLM 调用到 Agent 的进化 ​

1.1 什么是 Agent？ ​

普通 LLM 调用：

用户输入 → LLM → 输出

Agent：

用户输入 → LLM 思考 → 选择工具 → 执行 → 观察 → 再思考 → ... → 最终输出
           ↑                                              ↓
           └───────────────── 循环 ──────────────────────┘

核心区别：Agent 可以自主决策调用外部工具。

1.2 Function Calling 基础 ​

LLM 不直接"调用函数"，而是输出结构化 JSON：

json
{
  "name": "get_weather",
  "arguments": {"city": "北京"}
}

应用层解析 JSON → 执行真实函数 → 把结果反馈给 LLM。

MiniMax 也支持 Function Calling（你的 ai.py 里用了 ChatOpenAI 即可）。

1.3 最小 Function Calling demo ​

python
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
    """获取城市天气"""
    return f"{city}今天晴天，25 度"

llm = ChatOpenAI(model="MiniMax-M3").bind_tools([get_weather])

# 1. LLM 决定调用哪个工具
response = llm.invoke("北京今天天气怎么样？")
print(response.tool_calls)
# [{'name': 'get_weather', 'args': {'city': '北京'}, 'id': '...'}]

# 2. 执行工具
tool_result = get_weather.invoke(response.tool_calls[0]["args"])

# 3. 把结果反馈给 LLM
from langchain_core.messages import ToolMessage
final = llm.invoke([
    response,  # 包含 tool_calls 的 AIMessage
    ToolMessage(content=tool_result, tool_call_id=response.tool_calls[0]["id"]),
])
print(final.content)
# "北京今天晴天，25 度"

第二步：LangGraph 核心抽象 ​

2.1 为什么需要 LangGraph？ ​

LangChain 的 AgentExecutor（早期版本）的问题：

  • 流程是线性的，难处理复杂分支
  • 状态保存在消息里，难以管理
  • 难以实现人工介入

LangGraph 提供：

  • 图结构（StateGraph）
  • 显式状态（TypedDict）
  • 条件边（Conditional Edges）
  • 持久化（Checkpointing）
  • 人工介入（Interrupt）

2.2 最小 LangGraph demo ​

python
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_openai import ChatOpenAI

# 1. 定义 State（图的全局状态）
class State(TypedDict):
    messages: Annotated[list, add_messages]

# 2. 定义 Node（节点是函数）
def chatbot(state: State):
    llm = ChatOpenAI(model="MiniMax-M3")
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

# 3. 构建图
graph = StateGraph(State)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)

# 4. 编译
app = graph.compile()

# 5. 运行
result = app.invoke({"messages": [("user", "你好")]})
print(result["messages"][-1].content)

2.3 关键概念图谱 ​

State（状态）
  ↓
Node（节点：执行单元）
  ↓
Edge（边：流转关系）
  ↓
Conditional Edge（条件边：根据状态分支）
  ↓
Compile（编译成可执行对象）

3.2 自定义工具的模板 ​

python
from langchain.tools import tool

@tool
def my_tool(arg1: str, arg2: int = 10) -> str:
    """工具描述（必填！LLM 靠这个判断何时调用）

    Args:
        arg1: 参数1说明
        arg2: 参数2说明，默认 10
    """
    # 业务逻辑
    result = do_something(arg1, arg2)
    return result

关键点：

  1. 必须有 docstring（LLM 用它判断调用时机）
  2. 参数必须有类型注解
  3. 返回值必须是 string

3.3 实战：写一个 SQL 查询工具 ​

python
@tool
def query_database(sql: str) -> str:
    """执行 SQL 查询并返回结果（仅支持 SELECT）

    Args:
        sql: SQL 语句（必须以 SELECT 开头）
    """
    # 安全检查
    if not sql.strip().upper().startswith("SELECT"):
        return "错误：仅支持 SELECT 查询"

    # 执行
    import sqlite3
    conn = sqlite3.connect("./data.db")
    try:
        cursor = conn.execute(sql)
        columns = [desc[0] for desc in cursor.description]
        rows = cursor.fetchall()
        result = f"列：{columns}\n"
        result += "\n".join(str(row) for row in rows[:20])
        return result or "查询无结果"
    finally:
        conn.close()

第四步：Plan-and-Execute 模式 ​

4.1 项目 B 已实现的 Plan-and-Execute ​

backend/app/rag/agent.py 包含完整代码：

State:
  - messages: 对话历史
  - plan: 执行计划（list[str]）
  - current_step: 当前执行到第几步

Nodes:
  - planner: 生成计划
  - executor: 执行当前步骤
  - replanner: 根据结果调整

Edges:
  START → planner → executor ⇄ executor → replanner → END

4.2 三个 Node 的核心逻辑 ​

python
def planner_node(state: AgentState):
    """让 LLM 生成执行计划"""
    response = llm.invoke([
        SystemMessage(content="你只输出 JSON 数组"),
        HumanMessage(content=PLANNER_PROMPT.format(question=...)),
    ])
    plan = parse_json_plan(response.content)
    return {"plan": plan, "current_step": 0}

def executor_node(state: AgentState):
    """执行当前步骤"""
    current_task = state["plan"][state["current_step"]]
    response = llm_with_tools.invoke([
        SystemMessage(content=EXECUTOR_PROMPT.format(
            plan=state["plan"],
            step=state["current_step"] + 1,
            current_task=current_task,
        )),
    ])
    return {"messages": [response], "current_step": state["current_step"] + 1}

def should_continue(state: AgentState):
    """判断是否继续"""
    if state["current_step"] >= len(state["plan"]):
        return "end"
    return "execute"

4.3 Graph 构建 ​

python
workflow = StateGraph(AgentState)

workflow.add_node("planner", planner_node)
workflow.add_node("executor", executor_node)
workflow.add_node("replanner", replanner_node)

workflow.add_edge(START, "planner")
workflow.add_edge("planner", "executor")
workflow.add_conditional_edges(
    "executor",
    should_continue,
    {"execute": "executor", "end": "replanner"},
)
workflow.add_edge("replanner", END)

memory = MemorySaver()
app = workflow.compile(checkpointer=memory)

4.5 进阶：Replanner 优化 ​

当前项目 B 的 Replanner 是空的（直接结束）。升级版：

python
def replanner_node(state: AgentState):
    """根据执行结果决定：继续 / 重规划 / 结束"""
    completed = state["messages"][-3:]  # 最近 3 条消息
    response = llm.invoke([
        SystemMessage(content=REPLANNER_PROMPT.format(
            plan=state["plan"],
            completed_results=completed,
        )),
    ])

    # 解析：PROCEED 或新计划
    if "PROCEED" in response.content.upper():
        return {"final_answer": "任务完成"}

    # 重新规划
    new_plan = parse_json_plan(response.content)
    return {"plan": new_plan, "current_step": 0}

第五步：MCP 协议集成 ​

5.1 什么是 MCP？ ​

Model Context Protocol，Anthropic 2024 年底提出的工具集成标准。

类比：

  • USB-C：硬件的统一接口
  • MCP：AI 工具的统一接口

之前每个 Agent 框架都有自己的工具格式（MCP 之前）：

  • LangChain Tool
  • Anthropic Tool Use
  • OpenAI Function Calling
  • LlamaIndex Tool

MCP 之后：所有工具都用 MCP 标准，任何 Agent 都能调用。

5.2 项目 B 已实现的 MCP Server ​

tools/mcp_math_server.py：

python
from fastmcp import FastMCP

mcp = FastMCP("MathTools")

@mcp.tool()
def add(a: float, b: float) -> float:
    """两数相加"""
    return a + b

@mcp.tool()
def multiply(a: float, b: float) -> float:
    """两数相乘"""
    return a * b

if __name__ == "__main__":
    mcp.run()

运行：

bash
uv run mcp run tools/mcp_math_server.py

7.1 什么是 Human-in-the-Loop？ ​

某些决策风险高或不可逆（如转账、删数据、发邮件），让 Agent 暂停等人工确认。

7.2 LangGraph 的 Interrupt 机制 ​

python
from langgraph.types import interrupt

def dangerous_tool(state: AgentState):
    """需要人工确认的工具"""
    confirmation = interrupt({
        "question": f"确认执行删除操作吗？影响：{state['impact']}",
        "options": ["confirm", "cancel"],
    })
    if confirmation == "confirm":
        return do_delete()
    return "用户取消"

8.1 LangGraph 的流式输出 ​

python
@app.post("/v1/agent/stream")
async def stream_agent(request: AgentRequest):
    async def generate():
        async for event in agent.astream_events(
            {"messages": [...]}, config, version="v1",
        ):
            kind = event["event"]

            if kind == "on_chat_model_stream":
                # LLM 输出 token
                content = event["data"]["chunk"].content
                yield f"data: {content}\n\n"

            elif kind == "on_tool_start":
                # 工具调用
                yield f"event: tool_start\ndata: {event['name']}\n\n"

            elif kind == "on_tool_end":
                # 工具结束
                yield f"event: tool_end\ndata: done\n\n"

        yield "data: [DONE]\n\n"
