第一步：理解 RAG 的本质 ​

1.1 为什么需要 RAG？ ​

LLM 的三个致命短板：

❌ 知识截止：训练数据停留在某个时间点
❌ 幻觉问题：会编造不存在的"事实"  
❌ 私有数据：无法访问你的内部文档

RAG 的核心思想：

把"知识"从 LLM 内部 → 移到外部
LLM 只负责"理解 + 生成"
检索系统负责"找资料"

1.2 RAG 三阶段图谱 ​

离线索引（一次性）：
  原始文档 → 文档加载 → 文本分块 → Embedding → 向量数据库

在线检索（每次请求）：
  用户问题 → Embedding → 相似度搜索 → Top-K 文档块

增强生成：
  文档 + 问题 → Prompt 组装 → LLM → 最终答案

1.3 关键技术决策点 ​

决策点选项推荐
分块粒度句子 / 段落 / 固定长度 / 语义递归字符（兼顾语义 + 实现简单）
向量数据库ChromaDB / FAISS / pgvector / Milvus学习期 ChromaDB，生产用 pgvector
检索策略相似度 / BM25 / 混合混合检索 + Reranking
EmbeddingOpenAI / BGE / M3E中文 BGE-M3 / M3E
LLMGPT-4 / DeepSeek / MiniMax学习期 MiniMax（你已配置）

2.3 最小 RAG 验证 ​

新建 test_minimal.py：

python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).parent))

from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import TextLoader
from langchain_core.runnables import RunnablePassthrough

from dotenv import load_dotenv
load_dotenv()

# 1. 加载一个文档
docs = TextLoader("./data/samples/01-rag-introduction.md", encoding="utf-8").load()

# 2. 分块
splitter = RecursiveCharacterTextSplitter(chunk_size=300, chunk_overlap=30)
splits = splitter.split_documents(docs)

# 3. Embedding + 存入 ChromaDB
embeddings = OpenAIEmbeddings()
vectorstore = Chroma.from_documents(splits, embeddings)

# 4. 检索
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 5. Prompt
prompt = ChatPromptTemplate.from_template("""
基于上下文回答问题。如果不知道就说不知道。

上下文：
{context}

问题：{question}
""")

# 6. LLM
llm = ChatOpenAI(model="MiniMax-M3", temperature=0)

# 7. 组装 Chain
def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)

# 8. 问答
answer = chain.invoke("什么是 RAG？")
print(answer)

3.1 不同文档格式的加载 ​

python
from langchain_community.document_loaders import (
    PyPDFLoader,            # PDF
    TextLoader,             # TXT
    UnstructuredMarkdownLoader,  # MD
)

def load_document(file_path):
    suffix = Path(file_path).suffix.lower()
    if suffix == ".pdf":
        return PyPDFLoader(file_path).load()
    elif suffix in (".md", ".markdown"):
        return UnstructuredMarkdownLoader(file_path).load()
    else:
        return TextLoader(file_path, encoding="utf-8").load()

3.3 分块策略详解 ​

项目 A 用的递归字符分块：

python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    separators=["\n\n", "\n", "。", "！", "？", "；", "，", " ", ""],
)

分块优先级（从强到弱）：

1. \n\n  → 段落（最强语义）
2. \n    → 换行
3. 。！？ → 句子（中文）
4. ，    → 短语
5. 空格  → 单词
6. ""    → 字符（兜底）

3.4 其他分块策略对比 ​

策略优点缺点适用
固定长度简单容易断句测试用
递归字符 ⭐兼顾语义参数需调通用
按 Markdown 标题保留结构仅限 MD结构化文档
语义分块最准慢、贵高质量需求
按句子粒度细信息分散Q&A

模型维度特点推荐场景

    base_compressor=compressor,

    retriever=retriever,
    llm=llm,
)

from langchain.retrievers import EnsembleRetriever

7.2 Query 改写 ​

python
# 用户问得模糊时，让 LLM 先改写问题
REWRITE_PROMPT = """改写以下问题，让它更适合检索。保持原意。
原问题：{question}
改写后："""

rewritten = llm.invoke(REWRITE_PROMPT.format(question=user_question))
docs = retriever.get_relevant_documents(rewritten)

# 用假设的答案去检索，而不是用问题

问题：{question}
假设答案："""

hypothetical_answer = llm.invoke(HYDE_PROMPT.format(question=query))
