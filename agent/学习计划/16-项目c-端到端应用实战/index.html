1.1 需求拆解

Section titled “1.1 需求拆解”

核心需求（MVP）：

  1. 用户注册 / 登录
  2. 用户与 AI 多轮对话
  3. 对话支持 RAG（上传文档 → 自动索引）
  4. 对话支持 Agent（可选：调用工具）
  5. 历史会话管理

非功能需求：

  • 性能：首 token 延迟 < 1s
  • 可靠性：API 可用性 99.5%
  • 安全性：API Key 不能泄露、用户数据隔离
  • 可观测性：日志、监控、告警

1.3 技术选型对比

Section titled “1.3 技术选型对比”
组件 选项 选择 理由
后端框架 FastAPI / Flask / Django FastAPI 异步、性能强、自动文档
ORM SQLAlchemy / Tortoise / Piccolo SQLAlchemy 2.0 生态最全、支持异步
数据库 PG / MySQL / MongoDB PostgreSQL + pgvector 事务 + 向量一体化

Section titled “9.2 简历话术（综合三个项目）”

AI Agent 全栈开发

30 天内从零搭建 3 个 AI Agent 项目，覆盖 RAG、Agent 编排、生产化部署全链路：

项目 A：知识库问答系统（FastAPI + LangChain + ChromaDB）

  • 引入 Reranking，检索准确率提升 35%

项目 B：智能 Agent 工作台（LangGraph + MCP + 多工具）

  • 设计 Plan-and-Execute 模式
  • 集成 MCP 协议，开发 5+ 自定义工具
  • 实现 Human-in-the-Loop 关键操作

项目 C：端到端 AI 应用（Next.js + FastAPI + PostgreSQL + Docker + CI/CD）

  • 多服务编排（API + DB + Cache + Frontend）

📝 小结

Section titled “📝 小结”
  • 项目目标:做一个能上线的端到端 AI 应用,把 A 与 B 的能力组装成完整产品。
  • A/B/C 的差别:A 是「能答对」,B 是「能行动」,C 是「能交付给别人用」——多租户、鉴权、持久化、限流、监控、成本、部署。
  • 第一步是系统设计与技术选型:需求拆解 → 架构图 → 数据流 → 技术栈 → 非功能指标(延迟、成本、准确率)。
  • 关键增量:会话持久化(数据库)、流式响应(前端体验)、文件上传与解析、错误与降级、成本监控、部署与回滚。
  • 前端部分是你的主场:流式渲染、引用可视化、状态机 UI、错误提示——这正是能把 AI 做出产品感的地方。
  • 面试加分:完整讲一遍「需求 → 架构 → 评估 → 上线 → 监控 → 成本」的闭环,这是资深候选人的标志。
