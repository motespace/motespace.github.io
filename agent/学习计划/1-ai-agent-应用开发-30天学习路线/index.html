Day 8-9｜LLM 核心概念

Section titled “Day 8-9｜LLM 核心概念”

目标：理解底层原理，不只是调 API

知识点清单

Section titled “知识点清单”

  • 基本概念

    • Token：模型处理的最小单位（中文约 1.5 字符 = 1 token）
    • Context Window：上下文窗口（4k / 16k / 128k / 200k）
    • Temperature：控制随机性（0 = 确定性，1 = 创造性）
    • Top-p / Top-k：采样策略
    • System / User / Assistant 三种角色

  • Prompt Engineering ⭐

    • Zero-shot / Few-shot
    • Chain-of-Thought (CoT)
    • ReAct 模式
    • 结构化输出（JSON / XML）
    • 角色设定与任务拆分

  • Function Calling / Tool Use ⭐⭐

    • 原理：让 LLM 输出结构化的函数调用
    • OpenAI 的 tools 参数
    • 解析 LLM 返回的工具调用
    • 工具执行 → 反馈给 LLM

Day 10-11｜Embedding + 向量数据库

Section titled “Day 10-11｜Embedding + 向量数据库”

目标：掌握 RAG 的核心组件

知识点清单

Section titled “知识点清单”

  • Embedding 原理

    • 文本 → 高维向量（通常 768 / 1024 / 1536 维）
    • 语义相似的文本，向量距离近
    • 余弦相似度 vs 欧氏距离

  • 常用 Embedding 模型

    • OpenAI text-embedding-3-small
    • 智谱 embedding-2
    • BGE 系列（开源、本地部署友好）
    • M3E（中文友好）

  • 向量数据库选型 ⭐

    数据库 特点 适用场景
    ChromaDB 轻量、Python 原生 本地开发、原型
    FAISS Meta 开源、极快 大规模检索
    pgvector PostgreSQL 插件 生产环境、已有 PG
    Milvus 分布式、性能强 大规模生产
    Qdrant Rust 写、API 友好 云原生

  • 基础操作

Section titled “知识点清单”

    • 结构化分块：按标题、章节

  • 进阶处理

    • 表格识别与保留

Day 14｜RAG 完整架构

Section titled “Day 14｜RAG 完整架构”

目标：搭建完整的 RAG 系统

知识点清单

Section titled “知识点清单”

  • RAG 三阶段

  • 检索优化 ⭐

    • Reranking：初检 → 重排序（用更强的模型）
    • HyDE：假设文档嵌入
    • 多路召回：向量检索 + 关键词检索（BM25）
    • Query 改写：让问题更适合检索

  • RAG 评估

    • 答案相关性（Answer Relevancy）
    • 上下文相关性（Context Relevancy）
    • 忠实度（Faithfulness）
    • 工具：ragas 框架

  • 高级模式

    • GraphRAG（微软）：基于知识图谱
    • Self-RAG：模型自己决定是否检索
    • Agentic RAG：Agent 自主选择检索策略

Day 21-22｜LangGraph 入门到进阶

Section titled “Day 21-22｜LangGraph 入门到进阶”

目标：构建复杂的 Agent 工作流

知识点清单

Section titled “知识点清单”

  • 为什么需要 LangGraph

    • LangChain Agent：线性循环，难处理复杂流程
    • LangGraph：图结构，可以条件分支、循环、子图
    • 适合：多步骤、有状态、需要人工介入的流程

  • 核心概念

  • 核心特性 ⭐

    • State：图的状态（核心概念）
    • Nodes：执行单元
    • Edges：流转关系
    • Conditional Edges：条件分支
    • Cycles：循环（Agent 的关键）
    • Persistence：状态持久化（Checkpoint）
    • Human-in-the-Loop：人工介入

  • 条件边示例

  • 持久化与记忆

Day 23-24｜Agent 设计模式 + MCP

Section titled “Day 23-24｜Agent 设计模式 + MCP”

目标：掌握主流 Agent 范式

知识点清单

Section titled “知识点清单”

  • ReAct 模式

    • Reason + Act
    • 思考 → 行动 → 观察 → 循环
    • 适用：通用任务解决

  • Plan-and-Execute ⭐⭐

    • 适合：复杂多步骤任务
    • 优势：可观测、可干预

  • Reflection 模式

    • 生成 → 批评 → 改进
    • 适合：代码生成、写作

  • Multi-Agent 协作

    • Supervisor 模式：一个主管协调多个专家
    • 对等模式：Agent 之间直接对话
    • 框架：LangGraph / CrewAI / AutoGen

  • MCP（Model Context Protocol） ⭐⭐⭐

    • Anthropic 提出的协议
    • 让 Agent 能接入各种工具和数据源
    • 类似 AI 时代的 USB-C 接口
    • 快速接入第三方服务

七、避坑指南

❌ 不要做的事

Section titled “❌ 不要做的事”
  1. 不要从 0 读 LangChain 源码——先用，再深入
  2. 不要追求完美架构——先跑起来，再重构
  3. 不要只调 API 不做项目——面试看的是项目能力
  4. 不要忽视 Python 基础——高级特性直接影响代码质量
  5. 不要被新框架吸引——LangChain + LangGraph + FastAPI 已经够用

✅ 应该做的事

Section titled “✅ 应该做的事”
  1. 每天写代码并提交 Git
  2. 项目优先于教程——项目驱动学习
  3. 用国产模型练手（DeepSeek 便宜）
  4. 关注 Token 成本——养成好的工程习惯

📝 小结

Section titled “📝 小结”
  • 总体目标不是「学完框架」,而是30 天内做出三个能跑、能演示的项目(知识库问答 → Agent 工作台 → 端到端应用)。
  • 四周节奏:Week1 打基础(Python + LLM 调用 + 环境)、Week2 项目 A(RAG 检索)、Week3 项目 B(工具与 Agent)、Week4 项目 C(系统设计与上线)。
  • 每天固定三件事:学一个概念 → 写一个小 demo → 记一页笔记,保证每天都产出。
  • 里程碑式验收:每周结束必须有可运行的东西 + 一段能口述的总结,而不是「看完了多少视频」。
  • 配套资源:代码位置见 2-code-location.md,进度看板见 9-学习进度跟踪.md,资源对照见 4-resources.md。
  • 面试加分:能说「我在 30 天里从零做出了三个可部署的 AI 应用」,这是极有说服力的行动力证明。
