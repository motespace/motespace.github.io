裸辞转 AI Agent：学习路径与面试复盘

一位 P6 后端开发裸辞转 AI Agent 的完整复盘。原文含大量表格与重复条目， 这里做了合并、去重、顺序修正与链接补全，并标出了原文缺失但值得补的部分。

一、起点：为什么裸辞

Section titled “一、起点：为什么裸辞”
  • 定位：中厂后端开发，方向偏传统后端
  • 职级：P6
  • 动机：更多是兴趣驱动，恰逢与领导积怨已深，加上公司期间做过几个 Agent 相关项目、自己有积累，痛下决心裸辞

裸辞的理由不是「被裁」，而是「待下去会有腐烂的感觉」。离职前用四象限分析过 「公司 / 部门 / 组的优势、劣势、成长、付出」，结论是：不是烂，是会烂。

这篇复盘的价值在于记录路径、给后来人借鉴、避免走弯路。

二、阵痛期：离职后的心理建设

Section titled “二、阵痛期：离职后的心理建设”

离职前做过很细的规划（细致到单天每小时做什么），但真正执行时依然焦虑：

  • 对未知的恐惧
  • 找不到更满意工作的担忧

应对方式：每次情绪上来，就打开离职前写的那份四象限分析。看完就平静了—— 结论没变，但情绪被事实锚定了。

⚠️ 原文缺失：离职日期、找到工作的时间点、中间的收入缺口。 这是裸辞最实际的部分（现金流、心理安全感），建议补上。

三、规划方法论（最值得抄走的部分）

Section titled “三、规划方法论（最值得抄走的部分）”

3.1 逆向 JD → 拆板块 → 排序

Section titled “3.1 逆向 JD → 拆板块 → 排序”
  1. 收集大部分 JD，以大厂为主
  2. 抽取共性要求，拆成一个个板块
  3. 按优先级和重要性降序排列
  4. 结合自身已有项目再做一次排序
  5. 用甘特图跟踪

Section titled “3.2 节点报告 + 复盘”

每天、每周、每阶段都输出一份节点报告（用 Hermes 定时任务自动生成），再复盘。

4.1 五个阶段

Section titled “4.1 五个阶段”
阶段 目标
① 认知层 建立 Agent 与 LLM 的整体认知，知道每个模块解决什么问题

4.3 两个方法论细节

Section titled “4.3 两个方法论细节”

大模型入门阶段：3B1B 视频信息密度高，看不懂就多看几遍，中途停下来自己推导， 10 分钟还不懂再问 AI 解释，效率更高。

学有余力的加深项：大模型进阶部分（模型侧原理）时间紧可以跳过， 不影响拿到 Agent 岗位的 offer，建议上岸后再补。

六、简历与投递

Section titled “六、简历与投递”

6.1 简历

Section titled “6.1 简历”
  • STAR 法则展开项目，先拆出亮点 / 难点，再按 STAR 阐述，尽量用数字量化
  • 技术栈罗列清晰，目的是命中机筛关键词——现在新公司有专门的 Agent 做匹配度分析

6.2 踩过的坑（很关键）

Section titled “6.2 踩过的坑（很关键）”

坑：简历里只写 AI 相关的项目。

因为本身有后端背景和工作经历，HR 发现漏了后端经历有两种反应：

  • 好的：追问一句
  • 差的：直接筛掉，连面试机会都没有

发现这个坑的过程：每次投完简历都问一嘴「为什么没过」。那段时间中间有一周多没有面试， HR 的反馈是：「发现您这边只有 AI 相关的经验，我们希望候选人有多一些其他方面的经验。」

结论：AI + 后端的双栖画像才是你的优势，别把后端那部分藏起来。

6.3 投递节奏

Section titled “6.3 投递节奏”

顺序：小厂 → 中厂 → 大厂，边面边复盘。

  • 一天最多面 3 场——再多，下一场之前就来不及复习了
  • 面试非常消耗精力，是连续输出
  • 准备到 75% 左右就可以开面：面试会暴露真实短板，也能收集到企业真正关心候选人的素质，方便反过来调整复习体系

地域策略：如果目标城市岗位少、机会成本高，可以先用其他城市的岗位练手。 投递时避开你想去的公司，以及在目标城市有分公司的大型公司。

七、结果与数据

Section titled “七、结果与数据”
指标 数值
面试场次 132 场（含 HR 面）
Offer 约 15 个
每天最多面试 3 场
启动准备水位 75%

按每天 3 场倒推，132 场约需 44 个面试日——这是一个相当密集的投递强度， 能拿到 15 个 offer 说明准备确实到位。

⚠️ 原文缺失（读者最想看但没写）：

  • 132 场覆盖的时间跨度（起止时间）
  • Offer 矩阵：城市 / 岗位 / 薪资 / 最终怎么选
  • 与原岗位相比的薪资变化
  • 转型期间的经济账
  • 三个项目各自的架构、难点和量化结果（这一点尤其可惜——原文自己强调 「最好有数字量化」，但自己的项目描述却没给数字）

八、给后来人的建议（从原文提炼）

Section titled “八、给后来人的建议（从原文提炼）”
  1. 逆向 JD 拆板块，比从零开始「什么都学」高效得多
  2. 先做路线，再动手——甘特图 + 节点报告，别让焦虑驱动学习
  3. 手写一遍最小实现，不要一上来就用框架（nanoAgent 约 100 行 Python）
  4. AI 反问是最高效的检验方式，输出倒逼输入，比反复读强
  5. 准备到 75% 就开面，真实反馈比闭门造车准
  6. 一天最多 3 场，保证复盘时间
