常见报错与排查

Section titled “常见报错与排查”

报错 1:会话列表串了用户

查询会话时必须带 user_id 条件,不能只按 session_id 查。这是越权漏洞,不是 bug。

报错 2:切换会话时上下文丢失

每个会话要独立存自己的 messages,不能共用一个数组。按 session_id 分开存储。

报错 3:会话越来越多,列表卡

分页 + 只返回摘要(标题、最后更新时间、消息数),不要把完整消息列表塞进会话列表接口。

报错 4:删了会话但向量数据还在

会话删除时,要级联清理关联的消息 embedding 和文档索引,否则会残留可被检索到的孤儿数据。

📝 小结

Section titled “📝 小结”
  • 会话是用户与 Agent 的一次连续对话,要建模:会话表(归属、标题、创建时间)+ 消息表(角色、内容、token、耗时)。
  • 关键设计:thread_id 与 user_id 绑定,查询时必须带用户过滤,防止越权读别人会话。
  • 历史长度控制:超长要摘要 + 保留最近 N 轮,否则上下文成本会线性增长甚至超窗。
  • 列表页要分页 + 显示摘要标题(可由首条消息截断或模型生成)。
  • 删除与导出是合规必需(用户有权删除自己的数据)。
  • 面试加分:讲「多租户下每一次查询都强制带 user_id 过滤,而不是靠前端不传」——安全设计原则。
