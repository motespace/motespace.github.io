常见报错与排查

Section titled “常见报错与排查”

报错 1:CI 里 API Key 读不到

GitHub Actions 里 Secrets 要显式声明到 env,而且不能用在 if: 条件判断里(GitHub 的安全限制)。

报错 2:fork 的仓库拿不到 Secret

这是设计如此。PR 的流水线里不要依赖 Secret,只跑 lint 和单元测试。

报错 3:镜像推送失败,权限不足

用 GITHUB_TOKEN 时要显式给 packages: write 权限;推送到 Docker Hub 要用 DOCKERHUB_TOKEN 而不是 GITHUB_TOKEN。

报错 4:流水线太慢,每次提交都跑一遍全量测试

按改动路径过滤(只跑受影响的部分),把慢测试拆到 nightly 流水线。

📝 小结

Section titled “📝 小结”
  • 流水线分阶段:lint/format → 类型检查 → 单元测试 → 构建镜像 → 推仓库 → 部署(测试环境)→ 冒烟测试 → 部署生产。
  • GitHub Actions 需要配置 Secrets:模型 API Key、数据库连接串、镜像仓库凭据、部署令牌——Secrets 绝不能进代码或日志。
  • 缓存加速:pip/uv 依赖缓存、Docker layer 缓存,能显著缩短构建时间。
  • 部署要可回滚:保留上一版本镜像与配置,出问题一键切回。
  • 加质量门禁:测试不过、镜像漏洞过高、lint 报错都不允许进生产。
  • 面试加分:讲「我把冒烟测试放在部署后自动跑,失败自动回滚」——这是完整的交付闭环。
