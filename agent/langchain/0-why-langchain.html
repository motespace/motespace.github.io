为什么需要 LangChain? ​

直接调 LLM SDK 只有几行代码,为什么还要引入一个框架?

一、裸调 SDK 的真实痛点 ​

python
from openai import OpenAI
client = OpenAI()

resp = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "讲个笑话"}],
)
print(resp.choices[0].message.content)

这段代码能跑。但项目做到第三步,就会撞上一堆重复劳动:

痛点具体表现
Prompt 到处硬编码同一个模板在 5 个文件里复制 5 遍,改一处要改 5 处
换模型要重写换 Claude / Gemini / 本地模型,参数名、返回结构都不一样
输出解析靠正则模型返回 JSON 字符串,你要自己 json.loads + 处理 markdown 代码块 + 失败重试
多步流程手写 if"先抽取实体 → 再查数据库 → 再总结",逻辑越写越乱
工具调用协议各不相同每个模型的 function calling 格式都要单独适配
对话记忆要自己拼历史消息截断、摘要、持久化,都是重复劳动

二、LangChain 提供了什么 ​

LangChain 的核心抽象是 Runnable:任何东西只要实现 invoke(input),就能被组合。

python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_anthropic import ChatAnthropic

prompt = ChatPromptTemplate.from_template("用{lang}解释:{topic}")
chain = prompt | ChatAnthropic(model="claude-sonnet-4") | StrOutputParser()

chain.invoke({"lang": "中文", "topic": "RAG"})

一行 | 就是组合,三个环节各自可替换、可测试。

再往上是几个开箱即用的能力:

  • Prompt 模板:变量化 + 复用,支持 partial 预填
  • 统一模型接口:ChatModel / LLM / EmbeddingModel 三个接口,换厂商只改一行
  • 结构化输出:with_structured_output(PydanticModel) 直接拿到类型化对象,不用写正则
  • 工具(Tool):用 @tool 装饰器声明,自动生成 function calling schema
  • LCEL 链:|, .pipe(), .batch(), .stream() 一套 API 打通

三、什么时候不要用 LangChain ​

这是最容易被忽略的一点:

  • 只调一次模型、没有多步流程 → 直接用 SDK,少一层抽象少一层 bug
  • 强类型 + 简单逻辑 → 手写反而更清晰
  • 框架版本升级频繁 → LangChain 0.x → 1.x 的 API 变动不小,锁定版本很重要

判断标准很简单:流程超过两步,或者要换模型,才值得上框架。

四、LangChain 与 LangGraph 的分工 ​

LangChainLangGraph
形态线性链(LCEL)有状态图(节点 + 边 + 状态)
适合确定性的多步流程需要循环、分支、人工介入的 Agent
例子"摘要 → 翻译 → 分类""ReAct 循环直到拿到正确工具结果"

LangChain 是流水线,LangGraph 是工作流引擎。先把简单链路用 LangChain 跑通,遇到"需要循环和分支"再上 LangGraph。

🎯 面试常考 ​

Q1:LangChain 解决了什么问题? 把 LLM 应用的公共工程能力标准化:Prompt 模板化、模型接口统一、结构化输出、工具调用协议、多步流程组合。没有它,这些都要在业务代码里重复实现。

Q2:LCEL 的 | 是什么意思? 管道操作符,把前一个 Runnable 的输出作为后一个 Runnable 的输入。因为每个环节都实现同一个 invoke 接口,所以可以任意组合,也可以单独测试某一环。

Q3:什么时候不该用 LangChain? 单次调用、无多步流程时直接用官方 SDK 更简单,引入框架只增加依赖和抽象成本。另外要注意版本锁定,LangChain 0.x 与 1.x API 差异很大。

Q4:LangChain 和 LangGraph 怎么选? 线性确定流程用 LangChain(LCEL);有循环、条件分支、状态回溯、人工审批的用 LangGraph。LangGraph 也常与 LangChain 混用,前者做编排,后者做模型/工具接入。

📝 小结 ​

  • 裸调 SDK 的痛点不在"调不通",而在 Prompt 硬编码、换模型要重写、输出解析、多步编排这些重复劳动。
  • LangChain 的核心是 Runnable 抽象和 LCEL 管道,让每个环节可替换、可测试。
  • 工具调用和结构化输出是收益最大的两个能力,优先用。
  • 流程不超过两步就别上框架;框架的代价是版本升级和抽象层。
