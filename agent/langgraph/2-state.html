LangGraph State 状态机 ​

State 是 LangGraph 的"记忆中枢"。理解 State 的设计模式, 是写出可维护 Agent 的关键。

一、State 基础 ​

python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# TypedDict 定义 State schema(类似 Python dict 但有类型检查)
class State(TypedDict):
    input: str
    output: str
    messages: list[str]

# 节点返回 State 的子集(只返回修改的字段)
def node_a(state: State):
    return {"output": f"processed: {state['input']}"}

def node_b(state: State):
    return {"messages": state["messages"] + [state["output"]]}

# 构建图
builder = StateGraph(State)
builder.add_node("a", node_a)
builder.add_node("b", node_b)
builder.add_edge(START, "a")
builder.add_edge("a", "b")
builder.add_edge("b", END)

graph = builder.compile()
result = graph.invoke({"input": "hello", "messages": []})
print(result)
# {'input': 'hello', 'output': 'processed: hello', 'messages': ['processed: hello']}

二、Reducer 合并策略 ​

默认情况下,节点的返回值会覆盖 State 中对应的字段。但有些字段应该合并(比如对话消息)。

python
from typing import Annotated
from langgraph.graph.message import add_messages
from operator import add

class State(TypedDict):
    # 1. 默认:覆盖
    name: str
    # 节点返回 {"name": "new"} → 直接覆盖

    # 2. Annotated + add:数字累加
    score: Annotated[int, add]
    # 节点返回 {"score": 10} → 累加(不是覆盖)

    # 3. Annotated + add_messages:消息列表合并(LLM 消息格式)
    messages: Annotated[list, add_messages]
    # 节点返回 {"messages": [AIMessage(...)]} → 追加

    # 4. 自定义 reducer
    history: Annotated[list[dict], lambda old, new: old + new]

三、add_messages(最常用) ​

python
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import HumanMessage, AIMessage

class State(TypedDict):
    messages: Annotated[list, add_messages]

# 1. 基础追加
state = {"messages": [HumanMessage(content="hi")]}
state["messages"] = add_messages(state["messages"], [AIMessage(content="hello!")])
# messages: [HumanMessage("hi"), AIMessage("hello!")]

# 2. 覆盖(用相同 id)
state["messages"] = add_messages(
    state["messages"],
    [AIMessage(content="corrected response", id="msg_123")],  # id 已存在
)
# id="msg_123" 的消息会被覆盖,而不是追加

# 3. 删除消息
from langchain_core.messages import RemoveMessage

state["messages"] = add_messages(
    state["messages"],
    [RemoveMessage(id="msg_123")],  # 删除指定 id
)

4.3 自定义 Reducer(高级) ​

python
# Reducer 签名:(old_value, new_value) -> merged_value

# 1. 字典合并
def merge_dict(old: dict, new: dict) -> dict:
    return {**old, **new}

class State(TypedDict):
    metadata: Annotated[dict, merge_dict]

# 2. Set 去重合并
def merge_set(old: set, new: set) -> set:
    return old | new

class State(TypedDict):
    visited_urls: Annotated[set, merge_set]

# 3. 最新 N 条
def keep_last_n(n: int):
    def reducer(old: list, new: list) -> list:
        combined = old + new
        return combined[-n:]
    return reducer

class State(TypedDict):
    history: Annotated[list, keep_last_n(10)]  # 只保留最近 10 条

# 4. 限长队列
def bounded_list(max_len: int):
    def reducer(old: list, new: list):
        combined = old + new
        return combined[-max_len:] if len(combined) > max_len else combined
    return reducer

# 编译时指定 checkpointer

七、State 更新 vs 覆盖 ​

python
class State(TypedDict):
    # 普通字段:节点返回什么就覆盖什么
    counter: int

    # Annotated 字段:用 reducer 合并
    log: Annotated[list[str], lambda old, new: old + new]

def node(state: State):
    return {
        "counter": 100,         # counter 变成 100
        "log": ["step done"],    # log 追加 "step done"
    }

# 特殊:用 None 显式删除字段
def reset_node(state: State):
    return {
        "counter": None,  # 不会被设为 None,会被忽略
        # 实际上 None 会变成 None(覆盖)
    }

十、常见陷阱 ​

python
# ❌ 坑 1:节点忘了返回字段
def bad_node(state: State):
    print(state["input"])
    # 忘了 return,State 不变

# ✅ 正确
def good_node(state: State):
    print(state["input"])
    return {"output": "result"}  # 必须返回修改的字段

# ❌ 坑 2:State 字段没初始化
def node_a(state: State):
    return {"counter": state["counter"] + 1}  # KeyError

# ✅ 用 .get()
def node_a(state: State):
    return {"counter": state.get("counter", 0) + 1}

# ❌ 坑 3:在节点里修改 State(可变对象)
def node_bad(state: State):
    state["messages"].append("new")  # 不推荐,会用 reducer 处理
    return {}

# ✅ 只返回新对象
def node_good(state: State):
    return {"messages": state["messages"] + ["new"]}

# ❌ 坑 4:reducer 用错
class State(TypedDict):
    messages: Annotated[list, add_messages]  # 用 add_messages
    counter: Annotated[int, add]  # 用 operator.add

# ✅ 正确
from langgraph.graph.message import add_messages
from operator import add

class State(TypedDict):
    messages: Annotated[list, add_messages]
    counter: Annotated[int, add]

🎯 面试常考 ​

Q1：State 是什么?

贯穿整个图执行的共享数据结构(TypedDict)。节点读 State、返回要更新的部分,由 reducer 决定如何合并。

Q2：多个节点同时改同一个字段怎么办?

用 reducer:覆盖(replace)、追加(operator.add)、合并(dict)三种。默认是覆盖,多个分支并行写同一字段会丢数据。

Q3：怎么给 State 加记忆?

把历史消息放进 State,节点返回时追加而不是覆盖;或者用 MessagesState 这类内置的带 reducer 的 State。
