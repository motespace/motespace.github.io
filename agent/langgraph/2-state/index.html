🎯 面试常考

Section titled “🎯 面试常考”

Q1：State 是什么?

贯穿整个图执行的共享数据结构(TypedDict)。节点读 State、返回要更新的部分,由 reducer 决定如何合并。

Q2：多个节点同时改同一个字段怎么办?

用 reducer:覆盖(replace)、追加(operator.add)、合并(dict)三种。默认是覆盖,多个分支并行写同一字段会丢数据。

Q3：怎么给 State 加记忆?

把历史消息放进 State,节点返回时追加而不是覆盖;或者用 MessagesState 这类内置的带 reducer 的 State。

📝 小结

Section titled “📝 小结”
  • State 用 TypedDict(或 Pydantic 模型)定义 schema;节点只返回要修改的字段,其余保持不变。
  • Reducer 决定「新值怎么合并到旧值」:默认是覆盖;Annotated[list, add_messages] 是追加;也可以自定义 reducer 做去重、限长。
  • add_messages 是最常用的 reducer:自动把消息转成 AIMessage/HumanMessage/ToolMessage 并支持消息 ID 去重。
  • 状态设计要点:只放跨节点共享的数据;大对象别进 State(用外部存储 + State 里放引用);敏感信息不进 State(会被 checkpoint 持久化)。
  • Checkpoint 依赖 State 序列化,所以 State 必须可 JSON 序列化(别放不可序列化对象)。
  • 面试加分:能讲「Reducer 是 LangGraph 的灵魂」——它让「追加消息」与「覆盖状态」两种语义共存于同一个 State。
