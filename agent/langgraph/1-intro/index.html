LangGraph 入门

LangGraph = 用状态机的方式构建 Agent。比 LangChain Chain 更适合多步骤、多 Agent、需要状态管理的场景。

Section titled “Chain vs Agent vs LangGraph”
维度 LangChain Chain LangChain Agent LangGraph
范式 线性步骤 ReAct 单循环 图状态机
状态管理 ❌ ❌ ✅ TypedDict
多步推理 弱 弱 ✅ 强
Multi-Agent ❌ ❌ ✅
持久化 ❌ ❌ ✅ Checkpoint
人机交互 弱 弱 ✅ interrupt
适用 简单任务 单循环工具调用 复杂 Agent

🎯 面试常考

Section titled “🎯 面试常考”

Q1：LangGraph 是什么?

用「图」的方式编排 Agent:State 是共享数据,Node 是处理函数,Edge 决定下一步。原生支持循环、条件分支、检查点和人工介入。

Q2：为什么 Agent 需要图?

ReAct 是循环(思考→调工具→看结果→再思考),链只能表达直线,图可以用条件边实现回退和分支。

📝 小结

Section titled “📝 小结”
  • LangGraph 解决的是 LangChain Agent 的三个硬伤:没有显式状态、没有循环与分支控制、无法持久化与恢复。
  • 四个核心概念:State(共享状态)、Node(处理状态的函数)、Edge(流转关系)、Graph(把它们串起来的状态机)。
  • Hello World 四步:定义 State → 定义 Node → add_node + add_edge → compile()。
  • 相比 Agent 类,LangGraph 是显式编排:每一步做什么、跳哪里,写在图里,可读、可测、可画。
  • 适用判断:流程确定 → 链;流程不确定但有状态与循环 → LangGraph。
  • 面试加分:一句话「LangChain Agent 是黑箱自主决策,LangGraph 是白箱显式状态机」,这句能说明你理解了两种范式。
