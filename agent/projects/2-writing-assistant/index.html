🎯 面试常考

Section titled “🎯 面试常考”

Q1：写作助手 Agent 怎么设计?

核心是「多轮改写 + 风格约束」:先问清受众和目标,再产出初稿,之后按反馈迭代。风格约束放在 system prompt,每次输出保持一致。

Q2：怎么防止越改越差?

每一轮只针对用户明确提的点改,保留没被要求改的部分;给用户「保留/修改」的 diff 视图,让人能控制。

Q3：怎么评估写作质量?

人工打分(准确性、流畅度、符合受众)最直接;自动指标可用 BLEU/ROUGE 做参考,但对开放写作参考价值有限。

📝 小结

Section titled “📝 小结”
  • Multi-Agent 的经典案例:Researcher(搜资料)→ Writer(成稿)→ Reviewer(审稿与改写)。
  • 架构用 LangGraph:State 里放 research_notes 与 draft,三个节点顺序流转,Reviewer 不通过则回环到 Writer。
  • 关键点:每个 Agent 只干一件事、只拿到自己需要的上下文(Writer 拿 notes 不拿原始搜索页,避免上下文污染与 token 浪费)。
  • 成本与质量权衡:多 Agent = 更多 token 与更多延迟,要用「审稿不通过才回环」而不是固定多跑。
  • 工程要点:notes 结构化(带来源)、draft 有长度与风格约束、审稿输出是结构化评语而不是自由文本(便于程序判断是否回环)。
  • 面试加分:能讲「多 Agent 的收益来自职责隔离,代价来自协调与成本,所以要有明确的回环条件」。
