🎯 面试常考

Section titled “🎯 面试常考”

Q1：代码助手 Agent 怎么设计?

关键是「给上下文而不是猜」:先检索仓库里相关的文件、函数、类型定义,再让模型基于真实代码作答;编辑用 diff 补丁而不是重写整个文件。

Q2：怎么控制误改?

只允许输出 unified diff 并做校验;改动范围限制在指定文件;改动后跑测试/类型检查,不通过就回滚。

Q3：怎么提升准确率?

补充仓库上下文(检索 + 相关文件打包)、给工具(读文件、搜符号、跑测试)让模型自查、输出前先给「修改计划」再动手。

📝 小结

Section titled “📝 小结”
  • 类 Cursor 的实现:Planner(拆任务)→ Coder(写代码)→ Tester(跑测试/审结果)。
  • 工具集是核心:读写文件、列目录、搜索代码、执行测试命令并拿到输出——Agent 的能力边界完全由工具决定。
  • 安全红线:命令执行必须白名单 + 工作目录限制 + 危险命令拦截,写操作前先给出 diff 预览。
  • 闭环质量靠执行验证:代码写完必须跑测试,测试失败把输出回填给 Agent 继续修(而不是让模型自己判断对错)。
  • 上下文管理:大仓库要靠检索(grep/索引)而不是全量塞入,这正是 Codebase 检索的核心难点。
  • 面试加分:能讲「让 Agent 可靠的关键不是更聪明的模型,而是给它可验证的闭环(跑测试)」。
