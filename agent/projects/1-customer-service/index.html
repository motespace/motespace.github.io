🎯 面试常考

Section titled “🎯 面试常考”

Q1：客服 Agent 怎么设计?

核心是「检索 + 工具 + 转人工」:先用 RAG 找到知识库答案,需要订单状态就调工具查,置信度不足或用户不满就转人工。

Q2：怎么控制转人工的时机?

三个信号:检索置信度低于阈值、用户连续两次追问同一问题没解决、用户明确要求人工。转人工时要把上下文一起带过去,不要让用户重说一遍。

Q3：怎么评估客服 Agent?

解决率(无需人工即解决的比例)、转人工准确率、首次响应时间、平均处理时长,再加人工满意度抽样。

📝 小结

Section titled “📝 小结”
  • 架构:LangGraph 编排 + RAG 知识库 + 业务工具(查订单、建工单)+ FastAPI 对外。
  • 关键设计:Router 判断问题类型(知识问题 → RAG,业务问题 → Tool),工具调用后把结果回填给模型。
  • 数据层:知识库与业务表分开,回答必须带来源(知识库给文档引用,业务给订单/工单编号)。
  • 工程要点:工具权限校验、PII 脱敏、会话历史用 thread_id 管理、超时与降级、每步埋点与 token 统计。
  • 验收:准备 30~50 条真实客服问题,统计回答正确率、引用准确率、工具调用成功率,不达标就改路由与 Prompt。
  • 面试加分:能讲清「为什么客服场景必须把「查订单」做成工具而不是靠模型编」——这是 RAG 与工具的边界问题。
