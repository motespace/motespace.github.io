🎯 面试常考

Section titled “🎯 面试常考”

Q1：数据分析 Agent 怎么设计?

自然语言 → 生成 SQL → 只读执行 → 结果解释 → 图表生成。核心约束是「数据库只允许 SELECT」,并且要限制可访问的表和行数。

Q2：怎么防止 SQL 注入和越权?

① 用只读账号;② 生成后用 AST 解析校验,只允许 SELECT;③ 强制加 LIMIT;④ 表名/字段名用白名单映射,不用字符串拼接。

Q3：生成的图表怎么落地?

让模型输出结构化图表配置(JSON),前端用 ECharts 渲染,不要让模型直接写代码再执行。

📝 小结

Section titled “📝 小结”
  • 场景:Text-to-SQL + 图表生成,把自然语言问题变成 SQL 查询并渲染图表。
  • 核心是把表结构与字段含义喂给模型(schema 注入 + 业务口径说明),这是 Text-to-SQL 成败的关键。
  • 安全铁律:只读账号 + SQL 白名单/解析校验 + 强制 LIMIT,绝不把模型输出直接拼进生产库执行。
  • 结果处理:SQL 执行失败要把数据库报错回填给模型让它自修(迭代 1~2 次),而不是直接失败。
  • 图表:把聚合结果转成 ECharts/Vega-Lite 配置,前端渲染;列名与单位要格式化。
  • 面试加分:讲「Text-to-SQL 的准确率瓶颈不在模型,在 schema 描述与业务口径的清晰度」——这是很到位的判断。
