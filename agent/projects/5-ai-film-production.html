项目 5:AI 短剧生产平台(Agent 编排 + 批量生成 + 一致性资产) ​

一句话 → 分镜 → 生成 → 成片。这是 Agent 所有基础能力(工具调用 / 多 Agent / 记忆 / HITL)在一个垂直行业里的完整落地形态。

写作背景:为一家 AI 服务器厂商的「AI 短剧创作平台」方向做面试准备时,把散落在各个平台上的产品结构和技术约束梳理成了这篇笔记。公司、薪资等个人信息已脱敏。

下一篇:AI 影视开发流程 · 具体实现 —— 把这个平台用代码写出来:领域模型、模型适配层、Agent 编排、任务队列、一致性绑定、成本核算、前端流式交互。

一、需求 ​

1.1 场景 ​

短剧和漫剧的工业化生产:一部剧 80-100 集,每集约 60 个镜头,每个镜头还要生成若干候选版本供挑选。

单部剧镜头数   ≈ 80 集 × 60 镜 = 4800 镜
实际生成量     = 镜头数 × 候选倍数(5~20) = 2 万 ~ 10 万次推理

结论:AI 短剧平台本质上是一个算力消耗大户。 这个数量级决定了后面所有的架构选择。

1.2 核心矛盾 ​

矛盾表现平台的解法
一致性同一角色要跨集跨镜头长得一样把角色沉淀成可绑定、可复用的资产
产能短剧是"集"的量,不是"条"的量把生成批量化、流水线化
成本单集成本决定能不能规模化把成本摊开可见,并用调度层优化

1.3 三种产品形态 ​

形态交互解决的问题短板
简单模式输入文/图 → 调参数 → 生成能不能生成抽卡、不一致、不可复用
画布模式节点化编排工作流一致性 + 批量复杂度高,状态爆炸
工业化流水线画布 + Agent + 算力调度产能 + 成本组织级复杂度

演进关系很关键:简单模式是画布模式的一个节点,画布模式是流水线的局部。用户以为在用一个"生成器",实际上在用一个调度系统。

参照物:腾讯视频的 WorkRally(面向精品漫剧的工业级 AI 平台,公开指标约产能 5 倍 / 成本 -50%)、腾讯云创意工坊(无限画布 + 多模型统一接入)。这类产品的行业信号是:"能不能生成"已经不是问题,"能不能工业化生产"才是。

二、架构 ​

2.1 内容层级 ​

项目 → 集 → 场 → 镜头

这个层级就是前端的页面结构,也是权限、统计、批量的天然分组单位。所有功能都挂在这棵树上,这一点决定了后面 80% 的前端实现方式。

2.2 五层结构 + 一层横向 ​

① 剧本层    小说/大纲 → 分集剧本 → 分场 → 分镜脚本(景别/运镜/时长/口型/台词)
② 一致性层  角色资产(多视角参考图/服装/表情)、场景资产、风格锁定
③ 生成层    文生图/视频、图生视频、首尾帧、运镜、超分
④ 资产层    镜头候选版本、素材库、版本树、配音/字幕/音效
⑤ 成片层    竖屏时间线、字幕轨、音轨、封面、片头片尾、AIGC 标识
─────────────────────────────────────────────────
横向:算力调度层  队列 / 批量 / GPU 配额 / 卡时成本 / 优先级 / 失败重试

只有第 ① ④ ⑤ 层是界面问题,③ 是模型问题,横向那层是基础设施问题。 前端的战场在 ①②④⑤,尤其是 ②(一致性)和 ④(候选版本)——这两层是所有平台都做得最烂的地方。

2.3 Agent 在这里干什么 ​

环节Agent 的职责用到的能力
剧本大纲 → 分集剧本 → 分场 → 分镜脚本提示工程 + 结构化输出
角色生成角色设定与多视角参考图,锁定为资产图生图 + 资产沉淀
分镜剧本 → 分镜表,绑定角色与场景资产工具调用(读写资产库)
生成选模型、填参数、批量派发、失败重试、挑候选Function Calling + 循环
一致性跨集跨镜头保持角色/场景/风格一致长期记忆(角色资产即记忆)
剪辑时间线编排、字幕、配音、卡点结构化输出 → 可编辑 UI

这些机制在本站已有专门章节,不重复展开: Function Calling / Tool Use(工具调用链路) · 多 Agent 系统(Supervisor / Swarm / Debate) · Memory 机制(角色资产就是业务侧的长期记忆) · 反思机制 + Human-in-the-Loop(生成前确认、失败后重试)

2.4 Agent 与 Workflow 的边界 ​

这是这个项目里最该想清楚的一件事:

  • Workflow:人画好固定流程,节点和顺序是确定的。生产线上必须用它兜底。
  • Agent:模型自己决定下一步。只在创意探索环节用它。

WorkRally 那种"专家级 Agent"的做法是混合式:画布是 Workflow 骨架,节点内部是 Agent。

剧本节点(Workflow 确定顺序)
  └─ 剧本 Agent(节点内自由决定怎么拆)
分镜节点(Workflow 确定顺序)
  └─ 分镜 Agent(绑定资产、决定景别)
生成节点(Workflow 确定顺序 + 批量)
  └─ 调度 Agent(选模型、填参数、重试)

工程含义:界面必须同时支持两种交互——用户既能拖出一条确定流程,也能在某个节点里交给 Agent 自己决定。数据模型上,节点是静态的,节点的每一次执行是一次运行实例(run),两者要分开存。

三、关键设计:统一角色资产层 ​

真人仿真短剧和漫剧是两种形态,但平台的资产模型可以统一。

真人仿真短剧漫剧
角色是什么演员设计资产
一致性靠什么换脸 / 微调 / 参考图设定图 + 风格锁定(线稿、色板、笔触)
最难的地方跨集同一张脸、多人同框对话戏、换装换场风格统一、跨镜头作画一致
相对好做的地方风格化容错高,观众对"AI 感"更宽容2D 资产可复用、可编辑

但底层是同一套:

统一「角色资产」层
  角色 ID · 多视角参考图 · 服装/表情/年龄段 · 可绑定到任意镜头 · 版本历史
        ↓                      ↓
  真人仿真路线              漫剧路线
  换脸 / 微调 / 参考图        设定图 + 风格锁定

为什么这个抽象值得单独讲 ​

前端只做一套资产管理 UI,差异收在参数层(真人路线多一个"参考图/微调模型"字段,漫剧路线多一个"风格锚点"字段)。

这和做中台是同一个思路:上面接不同数据源,下面是统一的级联选择与抽象层。指标管理中台里"数据源 → 表 → 字段"的三级级联,和这里"项目 → 集 → 场 → 镜头" + "角色资产 → 版本"是同一类设计。

优先级判断 ​

如果让我排开发优先级:先跑通漫剧全流程,再上真人仿真。理由是 2D 资产复用度高、一致性约束更好做、审核链条更清晰。

但前提是资产层和任务队列层必须共用,不能为两条线各做一套——否则后面加新形态一定返工。这句话在架构评审时比"先做哪个"更重要。

四、前端:这类平台的真正难点 ​

4.1 七个难点 ​

#难点具体是什么解法方向
1批量任务与队列一次几千个任务,要批量提交/重试/调参,还要能定位到"哪个镜头第几次失败"任务列表虚拟滚动 + 批量操作 + 失败索引
2候选版本对比抽卡是常态,一个镜头 3-8 个候选要并排比、一键选定、版本可回溯版本树 + 并排对比视图 + 差异高亮
3四级内容结构项目→集→场→镜头 的树 + 状态流转 + 跨层级批量 + 聚合统计树形虚拟化 + 状态机映射到样式
4一致性绑定建角色 → 选参考图 → 绑定多个镜头 → 卡片上回显"用的是角色 v2"复杂表单 + 关系型选择 + 版本回显
5多模型统一接入混元/即梦/可灵/Vidu 参数各不相同schema 驱动表单,不为每个模型硬编码
6成本与配额每集/每镜头消耗多少卡时和钱,哪个模型更划算成本看板 + 预算预警 + 模型性价比对比
7成片与合规竖屏时间线、字幕轨音轨、封面片头片尾时间线组件 + 预览代理文件 + 导出管线

4.2 第 5 条值得多说一句 ​

不同厂商的接口参数结构完全不同:有的支持运镜、有的支持首尾帧、有的只支持文生视频、有的按时长分档计价。

如果前端为每个模型写一套表单,每接一个模型就要重写一遍界面。正确做法是后端下发能力描述(schema),前端按 schema 动态渲染:

ts
type ModelCapability = {
  id: string
  params: Array<{
    key: string
    label: string
    type: 'select' | 'slider' | 'switch' | 'image'
    options?: Array<{ label: string; value: string; cost: number }>
    min?: number
    max?: number
    default?: unknown
  }>
}

附带收益:options 里带 cost,就能顺带做模型性价比对比,第 6 条的成本看板也一起有了数据源。

4.3 第 7 条里的合规常被漏掉 ​

AI 生成的画面和视频受《生成式人工智能服务管理暂行办法》《互联网信息服务深度合成管理规定》约束,需要显著的"AI 生成"标识,还有水印、溯源存证、送审链路。

这不是法务文档,是产品硬功能——平台交付给片方和发行方,标识与存证不达标就上不了线。做这类平台,合规必须当成界面需求来排期。

五、算力经济学:这类平台的机会在哪 ​

这是这个赛道对做基础设施的人最有吸引力的地方:

  1. 单位算力成本就是核心竞争力。短剧的竞争本质是成本战,谁能把单集成本压到可规模化的水位,谁就能吃份额。而成本 = 算力成本 × 消耗量,平台侧能同时优化这两项。
  2. 高密度部署是物理优势。短剧推理负载密度高、持续时间长,正好是高功率密度机柜的典型场景——液冷解决的是散热这个物理约束,不是 PPT。
  3. 需要生产级负载来验证集群。卖集群的公司最需要证明"我这套能扛真实工业化生产",而不是跑个 benchmark。

推论:做这类平台的最终形态不是内容公司,而是"算力 + 平台 + 工业化产能"的提供者。 它要卖的不是片子,是跑通这条流水线的产能。

六、评估:这类系统怎么测 ​

普通 CRUD 项目测功能,Agent 项目测"质量",而这类项目要测四组指标:

维度指标为什么重要
一致性角色跨镜头相似度、风格漂移率一致性不达标,内容就废了
产能单集产出耗时、批次完成率、队列积压直接对应商业交付
成本单位镜头卡时、抽卡次数分布决定能不能规模化
质量候选入选率、人工修改幅度衡量平台是否真的提升效率

抽卡次数分布是最被低估的指标:它同时反映模型能力和工作流设计质量——如果某个镜头类型平均要抽 8 次才过,说明它的约束条件没配好,这是工作流可以优化的地方,不是模型的锅。

七、生产化清单 ​

✅ 批量任务队列(幂等键 + 优先级 + 分片提交)
✅ 失败重试(按错误类型分级重试,区分可重试/不可重试)
✅ 断线重连后恢复进度(轮询兜底 + SSE 推送双通道)
✅ 候选版本树(入选/淘汰/分支,可回溯)
✅ 角色资产版本化(引用的是具体版本,不是"最新")
✅ 成本核算(按任务/按集/按项目三级归集)
✅ 模型降级(主模型超时自动切备用)
✅ 幂等的回调(模型侧重复回调不能重复入库)
✅ AIGC 标识 + 水印 + 溯源存证
✅ 送审状态机(草稿→送审→过审→发布)

最容易被忽略的三条:

  1. 角色资产必须版本化,引用要绑版本号。绑"最新"会导致历史剧集在角色更新后重新渲染,这是生产事故。
  2. 模型回调必须幂等。生成任务超时重发、回调重复到达,不做幂等就会出现重复镜头和重复扣费。
  3. 成本要三级归集。只记总卡时是没法做优化的,必须能下钻到"哪一集、哪一镜、哪个模型"。

🎯 面试常考 ​

Q1:Agent 在这个平台里具体干什么?

六个环节:剧本拆解、角色设定、分镜生成、生成调度、一致性维护、剪辑编排。关键判断是 Agent 只做决策,模型只做执行——大模型负责写剧本、定分镜、选参数,视频模型只负责出画面。平台的价值在编排层。

Q2:一致性怎么解?前端的角色是什么?

模型侧靠换脸/微调/参考图/风格锁定。前端承担三块:工作流(把参考图做成可复用的绑定,而不是每次重新描述)、可视化与校验(一眼看出这镜头的角色版本和上一镜是不是同一个,不一致要能被发现)、候选管理(达标的候选沉淀成标准资产供后续复用)。

Q3:你觉得最难的技术问题是什么?

模型侧是一致性和多人同框对话戏——单人镜头是当前模型的舒适区,两个人同框要各自动作自然、口型对上、身份不漂、空间关系正确,这是所有主流模型的弱项。

工程侧是把几千个任务的长链路变成人可用的工作台。生成是异步的、慢的、且不确定的,所以界面必须给出位置感(排第几)、安全感(失败能重试、候选能对比)、可见性(花了多少卡时和钱)。

Q4:成本怎么控制?

界面这块能接的是把成本做成用户看得见的:每集花了多少卡时、哪个模型更划算、哪类镜头抽卡次数最多、是否超预算。成本藏起来只会让客户在月底炸掉;摊开看,反而是产品竞争力。

Q5:模型自研还是接第三方?

看阶段。早期接第三方能最快跑通产品形态、验证需求;但要做一致性引擎和控图工作流,就必须有自己的模型或者至少有模型编排层,否则永远在抽卡。

对前端的意义:接第三方 = 界面要为"异步、时长不可控、参数各异"设计;自研 = 可以承诺时延和质量,界面可以更确定。两种界面形态不一样。

Q6:Agent 和 Workflow 怎么区分?你会怎么用?

Workflow 是人画好固定步骤,Agent 是模型自己决定步骤。工业生产上必须混合:画布是 Workflow 骨架,节点内部是 Agent。高风险环节用 Workflow 兜底,创意探索环节用 Agent 发挥。

工程上,节点是静态定义,节点的每次执行是一次运行实例,两者要分开建模。

Q7:如果让你设计分镜编辑器?

从镜头这个基本单元切:左边是集/场的镜头列表(缩略图 + 景别 + 时长 + 绑定的角色版本 + 状态),中间是画面和时间线,右边是这个镜头的参数与一致性绑定。三区联动——点列表定位时间线,点时间线回填参数。

核心取舍是不让用户等:所有生成动作都是异步的,界面必须先给出"我提交了、在第几位、大概多久、不成功能重试",而不是转圈。用户要能一边等一边改下一个镜头,这是工业化生产的节奏。

🎯 面这类方向要准备什么 ​

如果目标是这类岗位,准备可以拆成四块:

① 业务判断(最重要,权重最高)

能一句话讲清:这个赛道的门槛是一致性 + 产能 + 成本,不是单次生成质量;平台化的难点全在编排和状态管理。能说清"为什么这类公司值得做"——因为它是算力消费大户,平台价值在把算力变成可交付产能。

② Agent 机制

四个部件(LLM / 工具 / 记忆 / 循环)、Agent 与 Workflow 的边界、多 Agent 编排模式、Human-in-the-Loop 的触发条件、Function Calling 的完整链路。这一块要能讲原理,不能只背名词——面试官问"Agent 怎么做",问的是机制,不是"我用 LangChain 做过"。

③ 前端工程

复杂工作流界面(可视化编排、动态 schema 表单)、实时数据与长任务(SSE / 断线重连 / 进度可恢复)、层级结构与批量操作、复杂表单关系与回显校验、权限与合规、可观测(自研埋点与错误监控)。

④ 能证明你动手过

最小可行版本就够:FastAPI 四个接口(POST /batches、GET /jobs、GET /stream、GET /stats)+ Next.js 六块(四级树 / 批量提交 / SSE 推进度 / 候选并排对比 / 角色参考图绑定 / 成本看板)。拿不到真实模型 key 就 mock,但结构要真——mock 出的队列、进度流、结果入库、失败重试,就是真实架构。

面试时讲这个 demo 的落点是:"我不需要别人从头教我做接口",而不是"我做了个玩具"。

📝 小结 ​

  • 场景:AI 短剧 / 漫剧的工业化生产平台,单部剧是万级 GPU 任务量级,所以它是算力消费大户,不是内容工具。
  • 结构:五层(剧本 / 一致性 / 生成 / 资产 / 成片)+ 横向算力调度层;Agent 只做决策,模型只做执行;画布是 Workflow 骨架、节点内是 Agent。
  • 关键设计:统一角色资产层 + 两条生成路线,前端一套 UI、差异收参数层。资产层和队列层必须共用,否则加新形态必返工。
  • 前端战场:批量队列、候选版本对比、四级结构、一致性绑定、schema 驱动表单、成本可视化、AIGC 合规标识。
  • 评估四组指标:一致性 / 产能 / 成本 / 质量。抽卡次数分布最能反映工作流设计质量。
  • 最容易翻车的三个细节:角色资产要版本化引用、模型回调要幂等、成本要三级归集。
  • 面试加分:讲"这个赛道的门槛是一致性 + 产能 + 成本,不是单次生成质量",以及"平台化的难点全在编排和状态管理"——这两句能直接和候选人分层。
