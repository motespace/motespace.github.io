为什么开始学习 Agent？

作者：自己

当前身份：7 年前端工程师（React / Next.js / TypeScript）

目标：

成为能够独立开发 AI 产品的 AI Full Stack Engineer。

最近看到一篇关于 Agent 开发是否值得转型 的讨论，引发了很多思考。

讨论中最大的收获不是：

Agent 到底是不是风口。

而是：

AI 时代真正需要学习什么。

因此决定开始系统学习 AI Full Stack、LLM、RAG、Agent，并围绕一个真正的 AI 产品（AI English Coach）持续实践。

Agent 讨论总结

Section titled “Agent 讨论总结”

第一种观点：Agent 没什么神秘

Section titled “第一种观点：Agent 没什么神秘”

代表观点：

Agent 就是 AI 时代的 CRUD。

核心思想：

很多公司的 Agent：

其实就是：

业务 + LLM。

没有独立 Agent 团队。

没有复杂框架。

而是：

原来的后端开发直接接入 AI。

收获

Section titled “收获”

Agent 本身不是重点。

真正重要的是：

  • 是否解决业务问题

  • 是否创造商业价值

  • 是否真正落地

第二种观点：Agent 是新的工程体系

Section titled “第二种观点：Agent 是新的工程体系”

另一派认为：

真正的 Agent 开发远远不是：

而是：

企业每天真正做的是：

  • 收集 Bad Case

  • 调整 Prompt

  • 调整 Context

  • 调整 RAG

  • 调整 Tool

  • 观察日志

  • A/B Test

收获

Section titled “收获”

Agent 更像：

一种新的软件工程。

关于框架

Section titled “关于框架”

讨论中提到：

很多人把重点放在：

  • LangChain

  • LangGraph

  • AutoGen

  • Dify

实际上：

框架一直在变化。

真正不会变化的是：

  • Tool Calling

  • Memory

  • Planning

  • Reasoning

  • Context Engineering

收获

Section titled “收获”

不要学习框架。

学习思想。

关于 RAG

Section titled “关于 RAG”

讨论中出现最多的话题。

真正需要学习的是：

  • Chunk

  • Embedding

  • Retrieval

  • Rerank

  • Vector Database

企业真正的问题：

不是：

“怎么接 GPT”

而是：

“为什么召回不准？”

“为什么回答错误？”

“Chunk 怎么切？”

关于微调（Fine-tuning）

Section titled “关于微调（Fine-tuning）”

讨论总结：

并不是所有项目都需要微调。

什么时候用：

  • 专业领域

  • 小模型

  • 特定格式输出

更多时候：

Prompt + RAG

已经足够。

收获

Section titled “收获”

优先级：

不要本末倒置。

关于 Context Engineering

Section titled “关于 Context Engineering”

这是讨论中我认为最重要的一点。

商业 Agent 最大的工作：

不是 Prompt。

而是：

这些内容：

如何组合。

顺序如何安排。

Token 如何控制。

收获

Section titled “收获”

Context Engineering

比 Prompt Engineering 更重要。

关于 Dirty Work

Section titled “关于 Dirty Work”

企业 Agent 很多工作其实并不炫酷。

每天都在：

  • 清洗数据

  • 调 Prompt

  • Chunk

  • 收集 Bad Case

  • Evaluation

  • 调整 RAG

这是真正的 AI 工程。

关于未来

Section titled “关于未来”

讨论中的观点：

未来真正留下来的：

不是某个框架。

而是：

Agent Loop。

真正有价值的是：

  • AI 工程能力

  • 后端能力

  • 产品能力

  • 系统设计能力

📝 小结

Section titled “📝 小结”
  • 起点问题:为什么普通开发要转向 Agent——答案不是「AI 取代前端」,而是「AI 把需求到成品的中间环节压缩了,价值上移到定义问题与验证结果」。
  • 三层认知:Agent 不神秘(本质是「LLM + 工具 + 循环」)、Agent 是新工程体系(模型、上下文、工具、评测、成本)、Context Engineering 比 Prompt Engineering 更重要。
  • 对 RAG 的判断:不是万能药,知识更新频繁 + 需要溯源才上 RAG,否则先微调或换更长的上下文。
  • 对微调的判断:微调解决行为与风格,不解决知识时效;知识问题优先 RAG。
  • 对框架的判断:先手写一次最小实现,再用框架——不然永远在背 API。
  • 面试加分:能讲清「Context Engineering = 如何把对的信息在对的时间以对的格式放进窗口」,这是当下最能体现判断力的表述。
