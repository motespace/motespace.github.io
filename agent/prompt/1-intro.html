Prompt 基础结构 ​

Prompt = Agent 的"指令系统"。好的 Prompt 让模型表现翻倍, 坏的 Prompt 浪费 80% 效果。本章从基础结构开始,系统讲解 Prompt 设计。

一、Prompt 的 4 要素 ​

python
# 一个完整的 Prompt = 角色 + 任务 + 约束 + 示例

prompt = """
# 角色(Role)
你是一位资深的 Python 后端工程师,专注于 FastAPI 和数据库设计。

# 任务(Task)
请审查以下代码,找出潜在的性能问题和 Bug。

# 约束(Constraints)
- 输出用 Markdown 格式,分点列出
- 每条建议要给出具体代码示例
- 最多 5 条建议,按严重程度排序
- 不要泛泛而谈,要给出具体的行号和变量名

# 示例(Examples)
示例 1:
代码:
```python
def get_users():
    return db.query("SELECT * FROM users")

问题:数据库连接未关闭 建议:

python
def get_users():
    with db.connection() as conn:
        return conn.execute("SELECT * FROM users").fetchall()

实际输入 ​

代码:

python
{your_code}

"""


## 二、4 要素详解

### 1. Role(角色):定义"AI 是什么样的人"

```python
# ✅ 具体 + 专业
roles_good = [
    "你是一位有 10 年经验的 Python 后端工程师,精通 FastAPI 和 PostgreSQL",
    "你是一位资深的金融分析师,擅长股票估值和风险评估",
    "你是一位耐心的 Python 老师,擅长用通俗例子解释复杂概念",
]

# ❌ 模糊
roles_bad = [
    "你是一个助手",
    "你很聪明",
    "请帮我",
]

为什么有效:LLM 在预训练时见过大量特定角色的语料,设定角色能让它"调用"对应的语言模式。

2. Task(任务):明确"要做什么" ​

python
# ✅ 清晰 + 单一任务
task_good = """
任务:对以下用户评论进行情感分类。
输入:用户评论文本
输出:positive / neutral / negative,只输出标签。
"""

# ❌ 多任务模糊
task_bad = """
帮我看看这段评论,告诉我情感怎么样,顺便提取关键词,如果有错别字也帮我改一下。
"""

3. Constraints(约束):限定"怎么做" ​

python
constraints = """
- 输出长度:不超过 200 字
- 输出格式:Markdown 列表
- 语言:简体中文
- 不要重复问题本身
- 如果不知道答案,直接说"不知道",不要瞎编
- 必须给出至少 2 个反例
"""

黄金法则:

  • ✅ 明确说不能做什么(常被忽略)
  • ✅ 指定输出格式(JSON / 列表 / Markdown)
  • ✅ 指定长度限制
  • ✅ 告诉它"不知道"时该怎么办(减少幻觉)

4. Examples(示例):示范"输出长什么样" ​

python
# Few-shot:给 1-3 个示例,效果翻倍
example = """

输入:难吃,等位时间还长,再也不会来了
输出:negative

实际输入:{user_comment}
"""

四、Prompt 调试原则 ​

1. 由简到繁 ​

python
# ❌ 一上来就堆 1000 字 prompt
# ✅ 先写最简版,看效果,再加约束

# 版本 1:最简单
prompt_v1 = "把以下文本翻译成英文:{text}"

# 版本 2:加角色
prompt_v2 = "你是专业译员,把以下文本翻译成英文,保持原文风格:{text}"

# 版本 3:加约束
prompt_v3 = """
你是专业译员。
任务:翻译成英文。
要求:保持风格、专业术语一致。
输入:{text}
"""

# 版本 4:加示例
prompt_v4 = """
你是专业译员。
任务:翻译成英文。
要求:保持风格。

示例:
输入:你好世界
输出:Hello World

输入:{text}
"""

2. 看 LLM 哪里"误解"了 ​

python
# 如果输出不对,问自己:
# 1. 它是不是没明白任务?(改 Task 描述)
# 2. 它是不是不知道约束?(改 Constraints)
# 3. 它是不是没理解格式?(给 Examples)
# 4. 它是不是知识不足?(用更大模型 / RAG)

3. 迭代优化 ​

python
# 用 A/B 测试
prompt_a = "翻译: {text}"
prompt_b = "你是译员。翻译: {text}"

# 在测试集上对比
test_cases = ["测试文本 1", "测试文本 2", ...]

for case in test_cases:
    output_a = llm.invoke(prompt_a.format(text=case))
    output_b = llm.invoke(prompt_b.format(text=case))
    print(f"Input: {case}\nA: {output_a}\nB: {output_b}\n")

## 六、Prompt vs 微调

| 维度 | Prompt | 微调(Fine-tuning) |
|------|--------|-------------------|
| 成本 | 低 | 高 |
| 速度 | 快(秒级) | 慢(数小时) |
| 数据需求 | 0-10 个示例 | 数百-数万条 |
| 适用 | 通用任务、个性化 | 特定领域、风格化 |
| 可解释性 | ✅ | ❌ |

**结论**:**90% 的场景用 Prompt 就够了**,只有当 Prompt 效果始终不达标时才考虑微调。

## 🎯 面试常考

**Q1：Prompt 的四要素是什么?**

角色(Role)、任务(Task)、上下文(Context)、输出格式(Output Format)。写 Prompt 时逐项确认,比反复调措辞高效得多。

**Q2：怎么让模型稳定输出 JSON?**

① 在指令里明确 schema;② 用 `response_format={'type':'json_object'}` 或结构化输出能力;③ 解析时做容错(去 markdown 代码块包裹、失败重试)。

**Q3：Prompt 怎么迭代?**

先写最小可用版本,拿真实样例跑,记录失败案例,再针对失败改 Prompt。改一次只动一个变量,否则无法归因。

## 🎯 实战清单

✅ Prompt = 角色 + 任务 + 约束 + 示例(4 要素) ✅ 角色要具体专业,任务要单一清晰 ✅ 约束要明确说"不能做什么"和"不知道怎么办" ✅ 示例比描述更有效(Few-shot) ✅ 由简到繁,迭代优化 ✅ 90% 场景 Prompt 足够,不要一上来就微调
