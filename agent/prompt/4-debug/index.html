🎯 面试常考

Section titled “🎯 面试常考”

Q1：模型不按要求输出怎么排查?

① 是指令不清还是能力不够?② 把复杂任务拆小;③ 给示例;④ 检查是不是 Prompt 太长淹没了关键约束;⑤ 换成更强的模型对比。

Q2：Prompt 调试的通用流程?

固定测试集 → 跑一遍 → 归类失败模式 → 针对最常见的一类改 Prompt → 重跑对比。改一版只针对一类问题,别混着改。

Q3：怎么防止改 Prompt 引入回归?

准备一组固定的测试样例和期望输出,每次改完都跑一遍做回归;把「Prompt + 测试集」一起版本管理。

📝 小结

Section titled “📝 小结”
  • 调试第一步是做减法:只留 Task + Input,能答对就说明原 prompt 某部分在互相干扰。
  • 常见症状与病因:答非所问(任务不清)、格式乱(没给格式或反例)、幻觉(没约束 + 缺 RAG)、太啰嗦(没长度约束)、不稳定(温度高/示例少)。
  • 定位手段:固定输入看多次输出是否一致、逐段删减、对比不同模型、给 few-shot 反例、看 usage 判断是否被截断。
  • 改进顺序:先结构(角色→任务→约束→示例),再措辞,最后才是堆更多要求。
  • 建立评测集:20~50 条真实输入 + 期望输出/评分标准,改 prompt 前后跑一遍,避免改好一处坏一处。
  • 面试加分:能讲「Prompt 调试的本质是定位是哪一段在干扰,和排查 bug 一样」。
