系统提示词设计模式

System Prompt = Agent 的“灵魂”,决定 LLM 的行为准则 + 角色定位 + 输出格式。 设计良好的 System Prompt 是 Agent 项目的基石。

Section titled “一、System Prompt vs User Prompt”

类比:

  • System Prompt = 老板给员工的“岗位说明”(稳定不变)
  • User Prompt = 每天的具体任务

🎯 面试常考

Section titled “🎯 面试常考”

Q1：System Prompt 的三大模块?

通常包括:输出格式约束、角色设定、审查重点(让模型自查后再输出)。

Q2：System Prompt 和 User Prompt 的区别?

System 是全局指令,长期生效、优先级最高;User 是本次任务的具体输入。把稳定规则放 System,易变内容放 User。

Q3：怎么防止模型不遵守格式?

除了在 Prompt 里写,还要在代码层做校验和重试(比如 JSON 解析失败就带着错误信息让模型重试一次)。

📝 小结

Section titled “📝 小结”
  • System Prompt 与 User Prompt 的区别:system 每次请求都带、定义角色与硬规则;user 是具体任务与输入;system 的优先级更高但不是绝对。
  • 三大模块:行为规则(做什么/不做什么)、输出规则(格式、长度、字段)、输出格式(给一个具体的模板或 JSON Schema,最有效)。
  • 写 system prompt 的原则:具体 > 笼统、可验证 > 主观、给反例、把“不确定就说不确定”写进去。
  • 组合示例(代码审查 Agent)是最实用的范式:角色 + 检查清单 + 输出 JSON + 未知时标注。
  • 版本管理:system prompt 要独立成文件/配置,能灰度与回滚;改 prompt 等于改产品行为,要有评测集兜底。
  • 面试加分:讲清「Prompt 也是需要版本管理、回归测试和灰度的生产资产」,这是工程视角而非技巧视角。
