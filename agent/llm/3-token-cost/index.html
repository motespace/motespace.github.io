🎯 面试常考

Section titled “🎯 面试常考”

Q1：Token 成本怎么算?

总费用 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价。输入单价通常远低于输出。

Q2：怎么降低 token 成本?

① 精简 system prompt(去掉没用的示例);② 控制历史对话长度(滑动窗口 / 摘要);③ 缓存固定前缀(部分厂商支持 prompt caching);④ 输出限制 max_tokens;⑤ 路由:简单问题走小模型。

Q3：Rate Limit 是什么?

厂商对每分钟请求数或每分钟 token 数的限制。超了会返回 429。生产环境要自己做并发控制和指数退避重试。

📝 小结

Section titled “📝 小结”
  • Token 是计费、限流、上下文占用的共同单位,所有成本与容量问题最终都换算成 token。
  • 估算:中文约 1 字 = 1~2 token,英文约 1 词 = 1~2 token;精确值用官方 tokenizer,或直接读 API 返回的 usage。
  • 成本公式:成本 = 输入 token × 输入单价 + 输出 token × 输出单价,输出通常比输入贵好几倍。
  • 降本四招:缩短上下文(裁历史)、加 Prompt Caching(前缀命中可打折)、限制 max_tokens、小模型兜底(分类/改写类任务)。
  • 限流理解三个维度:RPM(每分钟请求数)、TPM(每分钟 token 数)、并发数;超限要指数退避 + 抖动重试。
  • 面试加分:能算出「一个日活 1 万、每次 2k 输入 + 500 输出的应用,月成本大概多少」,这是落地题。
