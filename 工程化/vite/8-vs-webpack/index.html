Vite 和 Webpack 的区别是什么？全方位对比

📚 深度专题推荐：本文是关于「Vite vs Webpack」的精炼对比。完整横评见 Rollup_Parcel_snowpack_Vite.md。

一、核心差异（一句话）

Section titled “一、核心差异（一句话）”
维度 Webpack Vite
设计理念 “一切皆模块”，通用打包 “dev 不打包，prod 用 Rollup”
构建时机 先打包后启动 启动后才按需编译
底层语言 Node.js Go（esbuild）+ JS（Rollup）
配置风格 loader + plugin 链 约定优先 + 插件
生态成熟度 极其丰富 新兴但快速增长

二、dev 阶段对比

Section titled “二、dev 阶段对比”

1. 启动速度

Section titled “1. 启动速度”

原理差异：

步骤 Webpack Vite
1. 解析依赖 递归扫描整个项目 只扫 import 语句
2. 编译 babel/ts-loader 全量编译 按浏览器请求时再编译
3. 打包 完整 bundle 不打包（浏览器原生 ESM）
4. 启动 server 打包完才启动 立即启动

2. HMR 速度

Section titled “2. HMR 速度”

核心差异：

维度 Webpack HMR Vite HMR
触发 Webpack-dev-server 检测到变化 chokidar 监听文件
推送 重新编译的 chunk 失效模块路径
替换 HMR Runtime 替换 浏览器 import + import.meta.hot
依赖图 完整 当前已加载的模块
状态保留 部分保留 更好（Fast Refresh）

三、prod 阶段对比

Section titled “三、prod 阶段对比”

1. 构建工具

Section titled “1. 构建工具”
工具 构建器 产物特点
Webpack 自己 通用、应用层优化好
Vite Rollup 干净、tree-shaking 强、库友好

2. 构建速度

Section titled “2. 构建速度”

原因：Vite 在 transform 阶段用 esbuild（比 babel 快 20-100x），Rollup 的产物生成比 Webpack 快。

3. 产物质量

Section titled “3. 产物质量”

两者都能产出高质量产物，但侧重点不同：

维度 Webpack Vite (Rollup)
体积 一般 更小（tree-shaking 强）
代码分割 强 强
chunk 策略 splitChunks 灵活 manualChunks / dynamic imports
长缓存 contenthash contenthash

五、生态对比

Section titled “五、生态对比”
维度 Webpack Vite
诞生时间 2012 2020
社区插件 数万个 数百个（快速增长）
loader/transformer 极丰富 用 esbuild + 插件补充
大型项目案例 阿里、字节、腾讯 越来越多（Vue 生态几乎全部迁）
学习曲线 陡（loader/plugin 体系） 平缓（约定优先）
文档质量 完善 优秀

六、适用场景

Section titled “六、适用场景”

推荐用 Vite ✅

Section titled “推荐用 Vite ✅”
  • 新启动的 Vue 3 / React 项目
  • 组件库开发
  • 中小型项目
  • 追求开发体验（启动快、HMR 快）
  • 内部工具 / 活动页 / H5

推荐用 Webpack ✅

Section titled “推荐用 Webpack ✅”
  • 存量大型项目（迁移成本高）
  • 需要复杂定制 loader/plugin 链
  • SSR + 微前端（Module Federation）
  • 对老浏览器兼容性要求极高（IE11 等）
  • 团队对 Webpack 经验丰富

⚠️ Vite 的不足

Section titled “⚠️ Vite 的不足”
  1. 生态还在追赶：某些冷门库可能没有 Vite 插件
  2. CJS 依赖偶尔出问题：某些老库需要强制预构建
  3. 生产构建偶尔有边界 bug：需要 fallback 到 Webpack
  4. 不支持 IE11：默认产物是 ES2020

七、迁移成本（Webpack → Vite）

Section titled “七、迁移成本（Webpack → Vite）”
工作量 内容
小时级 改 HTML 入口（引入 main.js 用 &lt;script type="module"&gt;）
天级 替换 loader 为 Vite 插件（vue-loader → @vitejs/plugin-vue）
周级 重写部分配置（less/sass/postcss）、处理环境变量（process.env → import.meta.env）
月级 处理 CJS 依赖兼容、定制构建逻辑

实际项目迁移：中型项目通常 3-5 天 可以迁完。

八、面试追问

Section titled “八、面试追问”

Q：Vite 一定会取代 Webpack 吗？

A：不会完全取代，但会成为主流。Webpack 仍是大厂存量项目的首选（迁移成本高），Vite 会成为新项目的默认选择。

Q：Vite 和 Turbopack 呢？（Next.js 团队的 Rust 打包器）

A：定位类似，但 Turbopack 主要绑定 Next.js。Vite 框架无关，更通用。

Q：什么情况下 Vite 比 Webpack 还慢？

A：

  1. 生产构建：大型项目 Vite（Rollup）可能比 Webpack 慢（Rollup 单线程分析）
  2. 冷启动首次依赖预构建：需要等几秒（但只一次）
  3. 某些极端 loader 链：需要自己写 Vite 插件替代

Q：项目用 Vite 还是 Webpack 怎么选？

A：

  • 新项目 → Vite（首选）
  • 老项目（Webpack）→ 不要轻易迁移，看具体痛点
  • 团队没人懂 Webpack → Vite 更易上手
  • 团队没人懂 Vite → Webpack 文档更全

🎯 面试常考

Section titled “🎯 面试常考”

Q1：Vite 和 Webpack 的核心区别?

开发阶段:Webpack 先打包再启动,Vite 按需编译不打包,启动和 HMR 都快一个量级。生产阶段:两者都用 Rollup/terser 打包,差异主要在分包策略和插件生态。

Q2：Vite 完全取代 Webpack 了吗?

没有。存量项目迁移成本高(Webpack loader 生态庞大),且有特殊 loader 需求时仍要用 Webpack;但新建项目默认 Vite 已是共识。

📝 小结

Section titled “📝 小结”
  • 差异集中在 dev 阶段,prod 阶段两者能力接近。
  • 迁移成本主要来自 loader 生态和自定义构建逻辑,不是配置改写本身。
  • 面试要能说清「为什么 Vite 快」的机制(跳过打包 + 原生 ESM),而不是只说「快」。
