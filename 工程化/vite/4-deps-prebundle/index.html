什么是 Vite 的依赖预构建？为什么需要 esbuild？

📚 深度专题推荐：本文是关于「Vite 依赖预构建」的精炼回答。如需整体原理，建议阅读 Vite 为什么这么快。

一、什么是依赖预构建？

Section titled “一、什么是依赖预构建？”

Vite 在启动 dev server 时，第一次会用 esbuild 把 node_modules 里的依赖处理一遍，结果缓存到 node_modules/.vite/deps/。

六、为什么用 esbuild 而不是 Rollup？

Section titled “六、为什么用 esbuild 而不是 Rollup？”
维度 esbuild Rollup
语言 Go（机器码） Node.js
速度 极快（10-100x babel） 较慢
产物质量 一般（够 dev 用） 优秀（生产用）
用途 dev 预构建、transform 生产构建

核心权衡：

  • 预构建只需要“快速转 ESM + 合并”，不需要完美 tree-shaking → esbuild 完美
  • 生产构建要 tree-shaking、代码分割、polyfill → Rollup 更合适

七、面试追问

Section titled “七、面试追问”

Q：预构建和代码分割（code splitting）冲突吗？

A：不冲突。预构建是把第三方依赖打包；代码分割是把业务代码拆成多个 chunk。两件事独立。

Q：什么时候需要 optimizeDeps.include？

A：

  1. 动态 import() 的依赖（Vite 默认扫不到）
  2. 某些 ESM 包声明不规范的
  3. 用了 require() 的 CommonJS 包

Q：预构建会拖慢 dev 启动吗？

A：首次启动会（要等几秒）。但结果会缓存到 node_modules/.vite/，二次启动毫秒级。

Q：项目里 Monorepo 的本地包要不要预构建？

A：不要，用 exclude: ['@my-org/my-lib'] 排除。本地包是源码，需要 Vite 实时编译监听修改。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：什么是依赖预构建?

启动时用 esbuild 把 node_modules 里 CommonJS 依赖转成 ESM,并把同一个包的多个子路径合并打包成 chunks,让浏览器能直接 import,同时减少请求数量。

Q2：什么时候需要手动重新预构建?

新增/升级了依赖、修改了 optimizeDeps.include / exclude、依赖引入了新的 CJS 子路径。删掉 node_modules/.vite 即可。

📝 小结

Section titled “📝 小结”
  • 预构建解决的是「浏览器不认 CommonJS」这个硬约束。
  • esbuild 负责转换(快),Rollup 负责生产打包(稳),两个工具各司其职。
  • 预构建只在 dev 阶段存在,生产构建不经过这一步。
