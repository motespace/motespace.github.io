Vite 常用配置有哪些？怎么从 Webpack 迁移到 Vite？ ​

📚 深度专题推荐：本文是关于「Vite 实战配置」的精炼回答。如需了解 Vite 整体架构，建议阅读 Vite 是什么。

一、基础 vite.config.ts ​

ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { resolve } from 'path'

export default defineConfig({
  // 1. 插件
  plugins: [vue()],

  // 2. 路径别名（替代 Webpack 的 resolve.alias）
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src'),
      '~': resolve(__dirname, 'src')
    }
  },

  // 3. dev server 配置
  server: {
    port: 3000,
    host: '0.0.0.0',
    open: true,  // 自动打开浏览器
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        rewrite: (p) => p.replace(/^\/api/, '')
      }
    }
  },

  // 4. CSS 配置
  css: {
    preprocessorOptions: {
      scss: {
        additionalData: `@import "@/styles/variables.scss";`
      }
    }
  },

  // 5. 构建配置
  build: {
    outDir: 'dist',
    sourcemap: false,
    minify: 'esbuild',  // 或 'terser'
    chunkSizeWarningLimit: 1500,
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router', 'pinia'],
          echarts: ['echarts']
        }
      }
    }
  }
})

二、环境变量 ​

Vite ​

ts
// .env.development
VITE_API_BASE=http://localhost:8080

// .env.production
VITE_API_BASE=https://api.example.com
js
// 代码中使用
console.log(import.meta.env.VITE_API_BASE)
console.log(import.meta.env.MODE)  // 'development' | 'production'
console.log(import.meta.env.DEV)   // true | false

Webpack 对比 ​

bash
# .env
API_BASE=http://localhost:8080
js
// 代码中使用
console.log(process.env.API_BASE)

差异：

  • Vite 默认只暴露 VITE_ 前缀的变量（更安全）
  • Vite 用 import.meta.env，Webpack 用 process.env

三、路径别名（Webpack → Vite） ​

Webpack 配置 ​

js
// vue.config.js / webpack.config.js
const path = require('path')

module.exports = {
  resolve: {
    alias: {
      '@': path.resolve(__dirname, 'src')
    }
  }
}

Vite 配置 + TS 类型 ​

ts
// vite.config.ts
import { resolve } from 'path'

export default defineConfig({
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src')
    }
  }
})
json
// tsconfig.json（Vite 需要）
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  }
}

四、CSS 处理 ​

Webpack 需要 loader 链 ​

js
{
  test: /\.scss$/,
  use: ['style-loader', 'css-loader', 'sass-loader']
}

Vite 内置支持 ​

ts
css: {
  preprocessorOptions: {
    scss: {
      additionalData: `@import "@/styles/variables.scss";`,
      // sass-loader 配置
    },
    less: { /* ... */ }
  },
  modules: {
    localsConvention: 'camelCase'
  }
}

五、静态资源处理 ​

Webpack ​

js
{
  test: /\.(png|jpg|gif)$/,
  loader: 'file-loader',
  options: { name: '[name].[hash:8].[ext]' }
}

Vite（自动处理） ​

vue
<template>
  <!-- 模板中直接用，Vite 自动处理 -->
  <img :src="logo" alt="logo" />
</template>

<script setup>
import logo from '@/assets/logo.png'
// logo 是一个字符串 URL（Vite 自动处理 hash）
console.log(logo)  // '/assets/logo.abc123.png'
</script>

六、从 Webpack 迁移到 Vite ​

1. 替换入口 HTML ​

html
<!-- Webpack 项目（vue.config.js 自动注入） -->
<!-- index.html 里没有 main.js 引用，由 HtmlWebpackPlugin 注入 -->

<!-- Vite 项目（手动写） -->
<!DOCTYPE html>
<html>
<head>
  <title>My App</title>
</head>
<body>
  <div id="app"></div>
  <!-- 必须显式声明 type="module" -->
  <script type="module" src="/src/main.js"></script>
</body>
</html>

2. main.js 改写 ​

js
// ❌ Webpack 风格
import Vue from 'vue'
import App from './App.vue'
new Vue({ render: h => h(App) }).$mount('#app')

// ✅ Vite + Vue 3 风格
import { createApp } from 'vue'
import App from './App.vue'
createApp(App).mount('#app')

3. 环境变量迁移 ​

bash
# 全局替换
sed -i 's/process\.env\.VUE_APP_/import.meta.env.VITE_/g' src/**/*.js

# Vite 默认暴露 import.meta.env.VITE_XXX

4. 处理 require() ​

js
// ❌ Webpack 支持
const pkg = require('./package.json')

// ✅ Vite / ESM 风格
import pkg from './package.json' assert { type: 'json' }
// 或
const pkg = await import('./package.json', { assert: { type: 'json' } })

5. 动态 import ​

js
// ❌ Webpack 的 require.context（Vite 不支持）
const req = require.context('./images', false, /\.png$/)

// ✅ Vite 用 import.meta.glob
const images = import.meta.glob('./images/*.png')
// { './images/a.png': () => import('./images/a.png'), ... }

七、性能优化配置 ​

1. 依赖预构建 ​

ts
optimizeDeps: {
  include: ['vue', 'lodash-es', 'dayjs'],
  exclude: ['@my-org/my-lib']  // 本地 monorepo 包不预构建
}

2. chunk 拆分 ​

ts
build: {
  rollupOptions: {
    output: {
      manualChunks(id) {
        if (id.includes('node_modules')) {
          if (id.includes('echarts')) return 'echarts'
          if (id.includes('vue')) return 'vue'
          return 'vendor'
        }
      }
    }
  }
}

3. 资源处理 ​

ts
build: {
  assetsInlineLimit: 4096,  // < 4KB 资源转 base64
  cssCodeSplit: true,       // CSS 代码分割
  rollupOptions: {
    output: {
      assetFileNames: 'assets/[name].[hash:8][extname]'
    }
  }
}

4. gzip / brotli 压缩 ​

ts
import compress from 'vite-plugin-compress'

plugins: [
  compress({ algorithm: 'gzip' }),
  compress({ algorithm: 'brotliCompress', ext: '.br' })
]

八、调试技巧 ​

1. 查看依赖预构建结果 ​

bash
ls node_modules/.vite/deps/
# vue.js  react.js  lodash-es.js  ...

2. 查看构建产物分析 ​

bash
npm run build
npx vite-bundle-visualizer
# 打开 dist/stats.html 看 chunk 大小

3. 解决 CJS 报错 ​

bash
# 某个 CJS 包报错时
optimizeDeps: {
  include: ['problem-package']
}

# 强制重新预构建
rm -rf node_modules/.vite
npm run dev

九、面试追问 ​

Q：Vite 项目怎么对接 CI/CD？

A：Vite 产物是标准静态文件，和任何 CDN 兼容：

bash
npm run build  # 产物在 dist/
# 上传到 OSS / S3 / Nginx 即可

Q：怎么在 Vite 项目用 Jest？

A：Vite 用 ESM，Jest 默认不支持。可以用 Vitest（专为 Vite 设计），API 和 Jest 几乎一致。

Q：Vite 项目怎么支持 IE11？

A：Vite 默认产物是 ES2020，不支持 IE11。如需兼容：

  1. 用 @vitejs/plugin-legacy 插件
  2. 或换回 Webpack

🎯 面试常考 ​

Q1：Vite 常用配置有哪些?

server(端口、代理、HMR)、resolve.alias(别名)、build(outDir、target、sourcemap、rollupOptions)、define(编译期常量)、optimizeDeps(依赖预构建范围)。

Q2：Vite 怎么配代理?

写在 server.proxy 里,和 webpack-dev-server 的 proxy 语法基本一致,同样只对开发环境生效。

📝 小结 ​

  • Vite 配置项按 server / build / resolve / define / optimizeDeps 五个方向记就够了。
  • resolve.alias 是最常用的一项,配合 @ 指向 src。
  • define 做编译期常量替换,替代 process.env 的手动判断。
