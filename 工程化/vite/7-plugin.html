Vite 插件机制是什么？怎么写一个 Vite 插件？ ​

📚 深度专题推荐：本文是关于「Vite 插件体系」的精炼回答。Vite 插件基于 Rollup 插件接口 + 独有钩子。

一、Vite 插件是什么？ ​

Vite 插件是一个对象，通过 name + hooks（钩子函数）扩展 Vite 功能。

js
// 最简单的插件
const myPlugin = {
  name: 'my-plugin',
  // Vite 在不同阶段调用对应钩子
  transform(code, id) {
    if (id.endsWith('.md')) {
      return `export default ${JSON.stringify(code)}`
    }
  }
}

二、插件钩子分类 ​

1. 通用钩子（Rollup 兼容） ​

Vite 兼容 Rollup 插件的一部分钩子（不是全部）：

Rollup 钩子Vite 是否支持作用
options✅构建配置初始化
buildStart✅构建开始
resolveId✅自定义模块解析
load✅自定义加载逻辑
transform✅转换模块内容
moduleParsed❌（仅 build）模块解析完
renderChunk✅（仅 build）转换 chunk
generateBundle✅（仅 build）生成产物前
writeBundle✅（仅 build）写入产物后
closeBundle✅（仅 build）关闭 bundle

2. Vite 独有钩子 ⭐ ​

钩子触发时机用途
config解析 Vite 配置前修改 Vite 配置
configResolvedVite 配置解析后读取最终配置
configureServerdev server 中间件注入自定义中间件
transformIndexHtml处理 index.html注入 script / 修改 HTML
handleHotUpdateHMR 更新时自定义 HMR 行为
previewpreview server 中间件preview 模式中间件

三、编写一个完整插件示例 ​

场景：自动给所有 .md 文件生成 import map ​

js
// plugins/md-import-map.js
import path from 'path'

export default function mdImportMap() {
  const virtualModuleId = 'virtual:md-import-map'
  const resolvedVirtualModuleId = '\0' + virtualModuleId

  return {
    name: 'md-import-map',

    // 1. resolveId：告诉 Vite 怎么解析虚拟模块
    resolveId(id) {
      if (id === virtualModuleId) {
        return resolvedVirtualModuleId  // 返回真实路径
      }
    },

    // 2. load：加载虚拟模块内容
    load(id) {
      if (id === resolvedVirtualModuleId) {
        return `export const mdMap = ${JSON.stringify(buildMap())}`
      }
    },

    // 3. transformIndexHtml：注入到 index.html
    transformIndexHtml(html) {
      return {
        html,
        tags: [
          {
            tag: 'script',
            attrs: { type: 'module' },
            children: `import { mdMap } from '${virtualModuleId}'; console.log(mdMap)`,
            injectTo: 'head'
          }
        ]
      }
    }
  }
}
ts
// vite.config.ts
import mdImportMap from './plugins/md-import-map'

export default defineConfig({
  plugins: [mdImportMap()]
})

五、Vite 插件的执行顺序 ​

1. Alias 别名替换
2. 用户插件的 resolveId
3. 用户插件的 load
4. 用户插件的 transform（按 plugins 数组顺序）
5. 内置 transform（esbuild / Vue 编译）
6. 解析完成

⚠️ 注意：transform 钩子先执行用户插件，后执行 Vite 内置插件。所以自定义 transform 拿到的还是原始代码。

六、面试追问 ​

Q：Vite 插件和 Rollup 插件的关系？

A：Vite 插件是 Rollup 插件的超集。Vite 实现了 Rollup 插件接口的子集 + 自己独有钩子。Rollup 插件可以直接用在 Vite 的 build 阶段，但 dev 阶段只能用 Vite 独有钩子。

Q：怎么调试 Vite 插件？

A：

js
{
  name: 'my-plugin',
  resolveId(id) {
    console.log('[my-plugin] resolveId:', id)  // 添加日志
    // ...
  }
}

或者用 vite --debug 看详细日志。

Q：通用插件 vs 预设（preset）的区别？

A：

  • 通用插件：单个功能，单独引入（vite-plugin-xxx）
  • 预设：多个插件打包（如 vite-plugin-pwa 内部组合了多个插件）

Q：怎么发布自己的 Vite 插件？

A：

bash
# 1. 用 create-vite-plugin 模板
npm create vite-plugin@latest

# 2-命名规范
vite-plugin-xxx  # 官方插件
vite-plugin-yyy  # 社区插件
unplugin-xxx     # 跨打包工具的通用插件

🎯 面试常考 ​

Q1：Vite 插件机制是怎样的?

一个插件是含 name 和 config / configResolved / transform / load / configureServer 等钩子的对象。Vite 解析配置时按顺序调用每个插件的钩子来扩展能力。

Q2：Vite 插件和 Rollup 插件能通用吗?

大部分通用,因为 Vite 的生产构建基于 Rollup;但 configureServer、transformIndexHtml 这类只对 dev 生效的钩子不通用。

📝 小结 ​

  • Vite 插件钩子模型直接沿用 Rollup,开发期再扩展一批。
  • config 钩子用来改配置,transform 钩子用来改单个文件,configureServer 用来加中间件。
  • 写插件前先确认 Vite/Rollup 有没有现成的,大多数需求社区已有成熟实现。
