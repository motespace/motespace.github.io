一、是什么

Section titled “一、是什么”

在使用 git 进行版本管理的项目中，当完成一个特性的开发并将其合并到 master 分支时，会有两种方式：

  • git merge
  • git rebase

git rebase 与 git merge都有相同的作用，都是将一个分支的提交合并到另一分支上，但是在原理上却不相同

三、区别

Section titled “三、区别”

从上面可以看到，merge和rebasea都是合并历史记录，但是各自特性不同：

merge

Section titled “merge”

通过merge合并分支会新增一个merge commit，然后将两个分支的历史联系起来

其实是一种非破坏性的操作，对现有分支不会以任何方式被更改，但是会导致历史记录相对复杂

rebase

Section titled “rebase”

rebase 会将整个分支移动到另一个分支上，有效地整合了所有分支上的提交

主要的好处是历史记录更加清晰，是在原有提交的基础上将差异内容反映进去，消除了 git merge所需的不必要的合并提交

📝 小结

Section titled “📝 小结”
  • merge:合并两条历史,产生一个有两个 parent 的 merge commit;默认快进(fast-forward)时不产生新提交。
  • rebase:把当前分支的提交「摘下来」重新应用到目标分支之上,得到线性历史,提交哈希会改变。
  • 结论:公共分支用 merge,自己的特性分支用 rebase;已推送到公共分支的提交不要 rebase。
  • 冲突处理与 merge 相同,rebase 是逐个提交重放,所以可能多次冲突。
  • 面试标准答法:对比「历史形态、提交哈希、是否产生 merge commit、冲突次数」四个维度,并说明团队规范。
