跨标签页通信:多 Tab 数据同步 ​

一、为什么需要跨标签页通信 ​

很多 Web 应用会开多个 Tab:

  • 用户开 2~3 个 Tab 同时处理不同业务
  • 后台系统 + 详情页 + 编辑页
  • 多账号切换(管理员、运营、财务)

数据需要在 Tab 间同步:

  • 退出登录 → 所有 Tab 跳转登录页
  • 修改密码 → 其他 Tab 失效
  • 系统通知 → 多 Tab 都显示
  • 实时数据(WebSocket 推送) → 多 Tab 同步

二、五种方案对比 ​

方案兼容性实时性复杂度适用场景
BroadcastChannel现代浏览器实时简单同源 Tab 实时通信(推荐)
localStorage + storage 事件全兼容实时简单跨源 Tab、持久化场景
SharedWorker现代(被弃用)实时中Chrome 67+ 备用方案
IndexedDB + 轮询全兼容准实时中数据量大,需要持久化
Service Worker + postMessage现代准实时复杂跨源推送

三、BroadcastChannel(推荐) ​

3.1 基础用法 ​

ts
// 任意 Tab
const channel = new BroadcastChannel('app-sync')

// 发送消息
channel.postMessage({ type: 'logout', userId: 123 })

// 接收消息
channel.addEventListener('message', (e) => {
  console.log('收到:', e.data)
})

// 关闭
channel.close()

3.2 实战:统一登录态 ​

ts
// auth.ts — 在所有页面加载
const authChannel = new BroadcastChannel('auth-sync')

// 登录
async function login(credentials: any) {
  const result = await api.login(credentials)
  setToken(result.token)

  // 通知其他 Tab
  authChannel.postMessage({ type: 'login', userId: result.user.id })
}

// 退出登录
function logout() {
  clearToken()

  // 通知其他 Tab
  authChannel.postMessage({ type: 'logout' })
}

// 接收其他 Tab 的消息
authChannel.addEventListener('message', (e) => {
  if (e.data.type === 'logout') {
    // 跳转到登录页
    window.location.href = '/login'
  } else if (e.data.type === 'token-expired') {
    showModal('登录已过期,请重新登录', () => {
      window.location.href = '/login'
    })
  }
})

// 监听服务端推送的"踢下线"事件
window.addEventListener('auth-expired', () => {
  authChannel.postMessage({ type: 'logout' })
})

3.3 实战:WebSocket 消息广播 ​

ts
// 只在主 Tab 连接 ws,其他 Tab 通过 BroadcastChannel 接收
let isMainWindow = false

function tryBeMain() {
  const channel = new BroadcastChannel('ws-leader')
  channel.addEventListener('message', (e) => {
    if (e.data.type === 'request-leader' && isMainWindow) {
      channel.postMessage({ type: 'i-am-leader' })
    }
  })

  // 我是新的主 Tab
  channel.postMessage({ type: 'request-leader' })

  setTimeout(() => {
    if (!isMainWindow) {
      isMainWindow = true
      connectWebSocket()
    }
  }, 100)
}

function connectWebSocket() {
  const ws = new WebSocket('wss://api.example.com/ws')
  ws.onmessage = (e) => {
    const data = JSON.parse(e.data)
    // 广播给所有 Tab
    const channel = new BroadcastChannel('app-sync')
    channel.postMessage(data)
  }
}

四、localStorage + storage 事件 ​

4.1 基础用法 ​

ts
// Tab A:写入 localStorage(注意 key 改变才能触发事件)
localStorage.setItem('user', JSON.stringify(newUser))

// Tab B:监听 storage 事件(同源 Tab 才触发)
window.addEventListener('storage', (event) => {
  // event.key:被修改的 key
  // event.newValue:新值
  // event.oldValue:旧值
  // event.storageArea:哪个 Storage(localStorage / sessionStorage)
  if (event.key === 'user' && event.newValue) {
    const user = JSON.parse(event.newValue)
    updateUserUI(user)
  }
})

4.2 实战:同步购物车 ​

ts
// 监听购物车变更
window.addEventListener('storage', (e) => {
  if (e.key === 'cart') {
    if (!e.newValue) {
      clearCartUI()
    } else {
      const cart = JSON.parse(e.newValue)
      updateCartBadge(cart.items.length)
    }
  }
})

// 添加商品
function addToCart(item: any) {
  const cart = JSON.parse(localStorage.getItem('cart') || '{"items":[]}')
  cart.items.push(item)
  localStorage.setItem('cart', JSON.stringify(cart))
  // 同一 Tab 不会触发 storage 事件,需手动更新 UI
  updateCartBadge(cart.items.length)
}

4.3 局限 ​

  • 同源:跨源 Tab 不触发
  • 同 Tab 不触发:自己在自己 Tab 改 localStorage,不会触发自己的 storage 事件
  • 值序列化:复杂对象需 JSON.stringify / parse
  • 不能传大数据:每次写入触发 storage 事件,大数据浪费

五、SharedWorker(被弃用,了解即可) ​

js
// shared-worker.js
const connections = []

self.addEventListener('connect', (e) => {
  const port = e.ports[0]
  connections.push(port)

  port.addEventListener('message', (e) => {
    // 广播给所有连接
    connections.forEach(c => c.postMessage(e.data))
  })

  port.start()  // 重要:必须 start
})
js
// 主页面
const worker = new SharedWorker('/shared-worker.js')
worker.port.addEventListener('message', (e) => console.log(e.data))
worker.port.start()
worker.port.postMessage({ type: 'sync', data: 'hello' })

状态:Chrome 已弃用,Firefox 仍支持。生产环境慎用。

六、Service Worker + postMessage(高级) ​

6.1 推送通知 + 同步 ​

js
// sw.js
self.addEventListener('message', (event) => {
  // 收到来自页面的消息
  if (event.data.type === 'broadcast') {
    // 广播给所有客户端
    self.clients.matchAll().then(clients => {
      clients.forEach(c => c.postMessage(event.data.payload))
    })
  }
})
js
// 页面
navigator.serviceWorker.register('/sw.js')
navigator.serviceWorker.ready.then(reg => {
  reg.active.postMessage({ type: 'broadcast', payload: { msg: '新订单' } })
})

// 接收
navigator.serviceWorker.addEventListener('message', (e) => {
  if (e.data.msg === '新订单') {
    showNotification()
  }
})

6.2 Web Push(系统级推送) ​

js
// 订阅推送
const registration = await navigator.serviceWorker.ready
const subscription = await registration.pushManager.subscribe({
  userVisibleOnly: true,
  applicationServerKey: VAPID_PUBLIC_KEY,
})

// 把 subscription 发送给服务端
await api.savePushSubscription(subscription)

适用场景:用户关闭 Tab 后,服务端仍能推送消息(如订单状态变更)。

七、IndexedDB + 轮询(老派方案) ​

ts
// 用 BroadcastChannel 触发轮询
const channel = new BroadcastChannel('db-sync')
let lastVersion = 0

// Tab B 监听变更
channel.addEventListener('message', (e) => {
  if (e.data.type === 'data-changed') {
    syncFromIndexedDB()
  }
})

// Tab A 写数据后通知
async function updateData(data: any) {
  await db.put('users', data)
  channel.postMessage({ type: 'data-changed' })
}

async function syncFromIndexedDB() {
  const current = await db.get('users', 'current')
  if (current.version > lastVersion) {
    lastVersion = current.version
    updateUI(current)
  }
}

八、实战选型 ​

8.1 决策: ​

  • 同源 + 实时 → BroadcastChannel(首选)
  • 兼容老浏览器 → localStorage + storage 事件
  • 跨源 → BroadcastChannel(不行)+ Service Worker
  • 后台推送 → Web Push + Service Worker

8.2 性能考虑 ​

  • BroadcastChannel:几乎无开销(消息秒发)
  • localStorage:每次写都触发事件,避免高频写入
  • SharedWorker:被弃用,新项目不用
  • Service Worker:适合"持久后台"场景

8.3 不要做的事 ​

  • 不要用轮询(setInterval 查 localStorage)——浪费 CPU
  • 不要用 Cookie 当消息总线——Cookie 同步,接口不一致
  • 不要滥用 BroadcastChannel——同源限制,跨源要用 Service Worker

🎯 面试常考 ​

Q1：跨标签页怎么通信?

localStorage 的 storage 事件(同源)、BroadcastChannel(同源,更干净)、window.postMessage(跨源)。

Q2：BroadcastChannel 有什么好处?

不用自己序列化、能按 name 分频道、自动在同源所有标签页广播,比用 storage 事件 hack 干净。

Q3：怎么避免消息风暴?

消息体带上来源 ID 和时间戳,接收端去重;大消息走 postMessage 而不是共享存储。

📝 小结 ​

  • 三种方式:localStorage 的 storage 事件(同源)、BroadcastChannel(同源、更干净)、postMessage(跨源)。
  • BroadcastChannel 能按 name 分频道,自动广播到所有同源标签页,比 storage 事件 hack 好。
  • 要传复杂数据用 postMessage 的结构化克隆;大数据用 transferable。
  • 注意消息风暴:带来源 ID 去重。
