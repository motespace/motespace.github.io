观察者 API 全家桶 ​

四个 Observer 解决同一类问题:「变化发生时通知我」,但观察的对象不同。

一、为什么需要 Observer ​

传统做法是轮询 + 事件监听:

js
// 反面教材:每次滚动都读 offsetTop,强制同步布局
window.addEventListener('scroll', () => {
  if (el.offsetTop < 100) hideHeader()
})

问题有三个:① 每次都读 DOM 属性,触发强制同步布局;② 不需要时也在跑;③ 拿不到「变化了多少」。

Observer 的思路是由浏览器在合适的时机通知你,并且回调里直接带上变化量。

二、IntersectionObserver:元素进出视口 ​

最常见的用途:图片懒加载、无限滚动、曝光埋点、吸顶判断。

js
const observer = new IntersectionObserver(
  (entries, obs) => {
    for (const entry of entries) {
      if (entry.isIntersecting) {
        entry.target.dataset.loaded = 'true'
        obs.unobserve(entry.target)   // 只需触发一次
      }
    }
  },
  { threshold: [0, 0.5, 1], rootMargin: '0px 0px -100px 0px' }
)

document.querySelectorAll('.lazy-img').forEach(img => observer.observe(img))

关键参数 ​

参数含义常用值
threshold触发比例的数组[0] 一进入就触发;[0, 0.5, 1] 多个节点
root参照容器null(视口)或某个元素
rootMargin根的边距,向外扩/向内缩'0px 0px -100px 0px' 提前 100px 触发

相比 scroll 事件的三个优势 ​

  1. 不触发强制同步布局 —— 回调直接给 entry.boundingClientRect / intersectionRatio
  2. 浏览器在渲染前批量回调 —— 一次滚动里多个元素变化会合并成一次回调
  3. 可以精确到比例 —— intersectionRatio 告诉你露了多少

曝光埋点的正确写法 ​

js
const io = new IntersectionObserver(entries => {
  entries.forEach(e => {
    if (e.isIntersecting && e.intersectionRatio >= 0.5) {
      trackExposure(e.target.dataset.id)
      io.unobserve(e.target)   // 曝光只记一次
    }
  })
}, { threshold: 0.5 })

三、ResizeObserver:元素尺寸变化 ​

监听元素自身的尺寸变化,而不是窗口。window.resize 只能感知视口变化。

js
const ro = new ResizeObserver(entries => {
  for (const entry of entries) {
    const { width, height } = entry.contentRect
    entry.target.style.setProperty('--w', width)
    entry.target.style.setProperty('--h', height)
  }
})

ro.observe(container)

典型场景 ​

  • 自适应画布:图表/画布按容器尺寸重绘,而不是按窗口
  • 侧栏折叠:折叠后容器变窄,内容要重新布局
  • 虚拟列表:行高变化时重新计算
js
// 自适应图表:容器多大画多大
const ro = new ResizeObserver(([entry]) => {
  const { width, height } = entry.contentRect
  chart.resize(width, height)
})
ro.observe(chartContainer)

注意事项 ​

  1. 回调里改样式会触发死循环 —— ResizeObserver 会观察 contentRect,如果回调里改了被观察元素的尺寸,会再次触发。解决:用 requestAnimationFrame 合并,或只改子元素
  2. 先观察再改尺寸 —— 初始尺寸会立即触发一次回调
  3. 在回调里读 getBoundingClientRect() 是安全的 —— 浏览器已提前算好
js
// 死循环的典型写法
const ro = new ResizeObserver(() => {
  el.style.width = el.offsetWidth + 1 + 'px'   // 每次 +1,无限循环
})

四、MutationObserver:DOM 结构变化 ​

监听 DOM 的增删改。用来做第三方脚本劫持检测、DOM 变更统计、无框架的响应式。

js
const mo = new MutationObserver(mutations => {
  for (const m of mutations) {
    if (m.type === 'childList') {
      console.log('子节点变化:', m.addedNodes.length, '新增', m.removedNodes.length, '删除')
    }
    if (m.type === 'attributes') {
      console.log('属性变化:', m.attributeName)
    }
  }
})

mo.observe(container, {
  childList: true,      // 直接子节点增删
  subtree: true,        // 递归所有后代
  attributes: true,     // 属性变化
  attributeFilter: ['class', 'style'],  // 只关心这几个属性
  characterData: true,  // 文本内容变化
})

实战:检测第三方脚本劫持 ​

js
// 记录初始的原型,发现被改就告警
const cleanFetch = window.fetch
const mo = new MutationObserver(() => {
  if (window.fetch !== cleanFetch) {
    report('fetch 被劫持!')
    window.fetch = cleanFetch   // 恢复
  }
})
mo.observe(document.head, { childList: true, subtree: true })

五、PerformanceObserver:性能指标 ​

浏览器主动上报性能条目,和 performance.getEntries() 拉取不同。

js
const po = new PerformanceObserver(list => {
  for (const entry of list.getEntries()) {
    if (entry.entryType === 'largest-contentful-paint') {
      console.log('LCP:', entry.startTime, entry.element)
    }
  }
})
po.observe({ type: 'largest-contentful-paint', buffered: true })

buffered: true 会把观察者注册之前已经产生的条目也补发出来,避免漏掉首屏指标。

支持的类型:paint、largest-contentful-paint、layout-shift、event(INP)、navigation、resource、longtask。

六、四个 API 对照 ​

API观察什么回调给什么典型用途
IntersectionObserver元素与视口/祖先的交叉比例isIntersecting、intersectionRatio懒加载、曝光埋点、无限滚动
ResizeObserver元素内容盒尺寸contentRect、borderBoxSize自适应图表、侧栏折叠
MutationObserverDOM 树/属性/文本变化mutationRecords劫持检测、DOM 统计
PerformanceObserver性能条目性能条目对象LCP/CLS/INP 上报

🎯 面试常考 ​

Q1: IntersectionObserver 相比 scroll 事件监听好在哪? ① 回调直接给交叉比例,不用自己算,避免强制同步布局;② 浏览器在渲染前批量合并回调,性能更好;③ 可以精确配置触发比例,不用自己写阈值判断。

Q2: ResizeObserver 会不会死循环? 会。如果在回调里修改被观察元素的尺寸,会再次触发。解决:用 requestAnimationFrame 合并多次回调,或者只修改子元素而非被观察元素本身。

Q3: MutationObserver 能替代事件监听吗? 不能。MutationObserver 是异步的(微任务里批量回调),适合「观察变化」;事件监听是同步的,适合「响应用户操作」。而且 MutationObserver 无法监听属性之外的东西(比如 CSS 变化)。

Q4: 怎么保证 LCP 不漏报?PerformanceObserver 注册时传 buffered: true,会把注册之前已产生的条目补发出来。

📝 小结 ​

  • Observer 的共同价值是「浏览器在正确时机通知你,并直接给出变化量」。
  • IntersectionObserver 做可见性,ResizeObserver 做尺寸,MutationObserver 做 DOM 变更,PerformanceObserver 做性能指标。
  • ResizeObserver 回调里改被观察元素的尺寸会死循环,用 rAF 合并。
  • PerformanceObserver 记得开 buffered: true,否则会漏掉首屏指标。
