一、为什么需要理解浏览器架构

Section titled “一、为什么需要理解浏览器架构”

理解浏览器架构,不仅是面试必问,更是性能优化、安全防御、调试难题的基础:

  • 性能优化:为什么 setTimeout 不准时?为什么动画卡?
  • 安全防御:同源策略、Cookie 隔离、CSRF 都依赖进程/线程设计
  • 排查难题:为什么 devtools 里看到的变量值“不对”?——可能是闭包跨线程

2.2 为什么是多进程

Section titled “2.2 为什么是多进程”
优势 说明
稳定性 一个页面崩溃只影响那个 Tab,不会让整个浏览器崩溃
安全性 进程隔离 + 沙箱,恶意页无法访问其他进程资源
性能 多核 CPU 可同时处理多个进程;IPC 并行
隔离 不同域名的页面在不同进程(Chrome 67+ 默认 site-per-process)

实战经验:

  • “为什么我的 Tab 突然卡死但其他 Tab 还正常?” → 渲染进程崩溃,浏览器主进程没受影响
  • “为什么我打开 devtools,内存占用涨?” → devtools 是个独立窗口,有自己的进程

4.2 V8 引擎(Chrome 的 JS 引擎)

Section titled “4.2 V8 引擎(Chrome 的 JS 引擎)”

关键优化:

  • 隐藏类(Hidden Class):V8 给对象建一个隐藏的 shape,属性快速访问
  • 内联缓存(Inline Cache):缓存方法查找结果
  • JIT 编译:热点代码编译为机器码

实战经验:

  • 不要乱改对象结构(添加/删除属性):破坏隐藏类,降低性能
  • 函数参数类型要稳定:同个函数不同类型参数,会被 deoptimize

🎯 面试常考

Section titled “🎯 面试常考”

Q1：浏览器由哪些进程组成?

主进程(GUI)、渲染进程(每个标签页,负责页面渲染)、GPU 进程、插件进程、存储进程、工具进程。多进程是为了隔离崩溃。

Q2：为什么渲染进程要单独一个?

一个页面崩溃不至于拖垮整个浏览器,这是「容错」设计。代价是内存占用更高、进程间通信有成本。

Q3：site isolation 是什么?

按站点分配渲染进程,防止跨站攻击利用同进程内存漏洞。

📝 小结

Section titled “📝 小结”
  • 浏览器是多进程的:主进程(GUI)、渲染进程(每标签页)、GPU 进程、存储进程、工具进程。
  • 多进程是为了容错 —— 一个页面崩溃不至于拖垮整个浏览器。
  • 渲染进程独立也带来了 site isolation(按站点分配进程),防跨站内存攻击。
  • 代价是内存占用更高、进程间通信有成本。
