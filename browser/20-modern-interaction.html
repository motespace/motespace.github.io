现代交互 API:Popover / Dialog / View Transition ​

过去要写一堆 JS 才能实现的交互,现在有原生 API 了。

一、Popover API ​

原生实现「点击外部关闭」「点击切换」「Esc 关闭」这类浮层行为,不用再手写。

html
<button popovertarget="my-popover">打开提示</button>

<div id="my-popover" popover>
  我是一个 Popover,点外面会自动关闭
</div>
js
const popover = document.getElementById('my-popover')
popover.showPopover()      // 打开
popover.hidePopover()     // 关闭
popover.togglePopover()   // 切换

关键能力 ​

特性说明
顶层渲染自动提升到 top layer,不受 overflow: hidden 和 z-index 影响
轻量 dismisspopover="auto" 时点击外部自动关闭,Esc 也能关
无 JS 也能用popovertarget 属性直接触发
嵌套popover="hint" 类型的 popover 可以嵌套在另一个里

定位 ​

Popover 默认在文档流里,可以用 CSS Anchor Positioning 定位到触发按钮:

css
#my-popover {
  position-anchor: --trigger;
  position-area: block-end span-inline-end;
  margin-block-start: 8px;
}

button { anchor-name: --trigger; }

浏览器支持 ​

Chrome / Edge 114+、Safari 17+、Firefox 125+。

二、<dialog> 元素 ​

原生模态框,自带焦点陷阱、Esc 关闭、::backdrop 遮罩。

html
<dialog id="confirm">
  <h2>确认删除?</h2>
  <p>此操作不可撤销。</p>
  <form method="dialog">
    <button value="cancel">取消</button>
    <button value="ok" class="danger">删除</button>
  </form>
</dialog>
js
const dlg = document.getElementById('confirm')
dlg.showModal()      // 模态:背景不可交互,焦点被锁在弹窗内
dlg.show()           // 非模态:相当于非模态 popover
dlg.close('ok')      // 关闭并返回值

用 form 收集结果 ​

html
<form method="dialog">
  <input name="username" value="default">
  <button value="save">保存</button>
</form>
js
dlg.addEventListener('close', () => {
  if (dlg.returnValue === 'save') {
    const username = new FormData(dlg.getElementById('form')).get('username')
  }
})

样式 ​

css
dialog {
  border: none;
  border-radius: 12px;
  padding: 24px;
  box-shadow: 0 20px 60px rgb(0 0 0 / 0.2);
}
dialog::backdrop {
  background: rgb(0 0 0 / 0.4);
  backdrop-filter: blur(2px);
}

要点:::backdrop 只在 showModal() 时出现,show() 时没有。

动画 ​

原生 <dialog> 默认没有开合动画(因为需要等待 close 事件),用 @starting-style 和 transition-behavior: allow-discrete 补上:

css
dialog {
  opacity: 0;
  transform: translateY(8px);
  transition: opacity 0.2s, transform 0.2s, overlay 0.2s allow-discrete, display 0.2s allow-discrete;
}
dialog[open] {
  opacity: 1;
  transform: translateY(0);
}
@starting-style {
  dialog[open] { opacity: 0; transform: translateY(8px); }
}

三、View Transitions API ​

让页面状态切换有平滑动画,核心是「截取旧状态 → 改 DOM → 播放新旧之间的过渡」。

js
async function onClick() {
  if (!document.startViewTransition) {
    updateDOM()          // 不支持就直接改
    return
  }
  const transition = document.startViewTransition(() => {
    updateDOM()          // 这个回调里同步修改 DOM
  })
  await transition.finished
}

给元素起名字做配对 ​

css
/* 旧状态 */
.card { view-transition-name: hero-card; }

/* 新状态里同一个元素 */
.card.is-hero { view-transition-name: hero-card; }

同名元素会自动做「 morph 」(位置和大小平滑过渡),而不是直接消失出现。

定制动画 ​

css
::view-transition-old(hero-card) {
  animation: fade-out 0.2s ease both;
}
::view-transition-new(hero-card) {
  animation: fade-in 0.2s ease both;
}

/* 定制整个过渡 */
::view-transition-group(root) {
  animation-duration: 0.35s;
}

什么时候用 ​

  • 列表筛选后的增删动画
  • 图片点击放大(FLIP 效果)
  • 路由切换的淡入淡出
  • Tab 切换的内容过渡

不要滥用:过渡期间页面是「冻结」的,动画超过 300ms 会让用户觉得卡。

四、Speculation Rules:预渲染下一页 ​

浏览器提前猜用户要去哪,把那个页面提前渲染好,点击时秒开。

html
<script type="speculationrules">
{
  "prerender": [
    { "where": { "href_matches": "/products/*" }, "eagerness": "moderate" }
  ],
  "prefetch": [
    { "where": { "href_matches": "/*" }, "eagerness": "low" }
  ]
}
</script>
规则做什么代价
prefetch下载资源,不渲染低
prerender下载 + 完整渲染页面中(会占用 CPU/内存)
prefetch + eagerness: "moderate"鼠标悬停/聚焦时触发几乎无感

注意:prerender 会真的执行页面的 JS,如果有副作用(埋点、请求)要小心。可以配合 referrerPolicy 和 document.prerendering 判断。

五、四个 API 的适用场景 ​

API解决什么替代的方案
Popover浮层、下拉、气泡提示自研 outside-click + z-index 管理
<dialog>模态框、确认弹窗自己写焦点陷阱 + 遮罩 + Esc
View Transitions状态切换动画FLIP 手写 或 CSS animation
Speculation Rules预取/预渲染下一页手动 <link rel=prefetch>

🎯 面试常考 ​

Q1: Popover 和普通的 absolute 定位浮层有什么区别? Popover 会被提升到 top layer,不受祖先 overflow: hidden 和 z-index 限制;内置「点击外部关闭 / Esc 关闭」;能用 popovertarget 属性零 JS 触发。

Q2: <dialog> 的 showModal() 和 show() 区别?showModal() 是模态:背景 inert(不可交互)、焦点锁在弹窗内、有 ::backdrop 遮罩、Esc 可关;show() 是非模态,行为接近非模态 popover,没有 ::backdrop。

Q3: View Transition 的执行流程?document.startViewTransition(callback) → 浏览器截取旧状态的快照 → 执行 callback 修改 DOM → 截取新状态 → 播放过渡动画 → finished promise resolve。同名 view-transition-name 的元素自动做 morph。

Q4: 什么时候不该用 View Transition? 过渡期间页面是冻结的,动画超过 300ms 用户会觉得卡;而且不能滥用在高频交互上。另外 Safari 18 以下不支持,必须做降级。

Q5: Speculation Rules 的 prerender 和 prefetch 区别? prefetch 只下载资源不渲染,成本低;prerender 会完整渲染页面(包括执行 JS),点击时秒开但有 CPU 和内存开销。prerender 还要注意页面副作用。

📝 小结 ​

  • Popover 解决浮层的「顶层渲染 + 轻量 dismiss」,<dialog> 解决模态框的「焦点陷阱 + 遮罩」。
  • View Transition 的关键是 view-transition-name 配对,同名元素自动 morph。
  • Speculation Rules 让「点击即开」成为可能,但 prerender 有副作用风险。
  • 这四个 API 都必须做能力检测和降级,渐进增强。
