Web Worker 优化:把重活搬到后台线程 ​

一、为什么需要 Web Worker ​

JS 是单线程的——一个长任务(> 50ms)会阻塞主线程,导致:

  • 页面卡顿、滚动迟滞
  • 点击/输入延迟(高 INP)
  • 动画掉帧

Web Worker 在独立线程跑 JS,主线程只发消息/接结果,不影响 UI。

二、Worker 类型 ​

类型用途兼容性
Dedicated Worker单页面专用99%
Shared Worker多页面共享(同源)现代浏览器
Service Worker网络代理、缓存、推送现代浏览器
Worklet浏览器底层 hook现代浏览器

本文主要讲 Dedicated Worker(最常用)。

三、基本用法 ​

3.1 创建 Worker ​

ts
// main.ts
const worker = new Worker('/worker.js', { type: 'module' })

// 监听消息
worker.addEventListener('message', (e) => {
  console.log('收到:', e.data)
})

// 发送消息
worker.postMessage({ data: hugeArray })

3.2 Worker 线程 ​

ts
// worker.ts
self.addEventListener('message', (e) => {
  const result = heavyCalculation(e.data)
  self.postMessage(result)
})

// self 是 DedicatedWorkerGlobalScope,不是 window
// 不能用:document, window, localStorage, DOM API
// 能用:fetch, setTimeout, IndexedDB, WebSocket, crypto

四、实战场景 ​

4.1 大数据计算 ​

真实项目:xinfeng 大屏需要对 100000 条数据做实时聚合(求和、分组、TopN)。

主线程写法(卡顿):

ts
button.addEventListener('click', () => {
  // 100000 条数据,500ms+ 计算,主线程卡死
  const result = data.reduce((acc, item) => {
    acc[item.category] = (acc[item.category] || 0) + item.value
    return acc
  }, {})
  chart.setOption({ series: [{ data: Object.values(result) }] })
})

Worker 写法(流畅):

ts
// main.ts
const worker = new Worker('/aggregate.worker.js')

button.addEventListener('click', () => {
  worker.postMessage({ type: 'aggregate', data })
  // 主线程立刻继续响应用户操作
})

worker.onmessage = (e) => {
  if (e.data.type === 'aggregate') {
    chart.setOption({ series: [{ data: e.data.result }] })
  }
}
ts
// aggregate.worker.ts
self.addEventListener('message', (e) => {
  if (e.data.type === 'aggregate') {
    const result = heavyAggregate(e.data.data)
    self.postMessage({ type: 'aggregate', result })
  }
})

function heavyAggregate(data: any[]) {
  // 同样的 reduce,但在独立线程
  return data.reduce(...)
}

4.2 大文件解析 ​

ts
// main.ts
async function parseFile(file: File) {
  const text = await file.text()
  worker.postMessage({ type: 'parse', text })
}

worker.onmessage = (e) => {
  console.log('解析结果:', e.data.rows)
}

// worker.ts
self.addEventListener('message', (e) => {
  if (e.data.type === 'parse') {
    const rows = parseCSV(e.data.text)  // 100MB CSV 解析 1s+,主线程会卡
    self.postMessage({ type: 'parse', rows })
  }
})

4.3 图片处理 ​

ts
// 在 Worker 里做 canvas 滤镜
self.addEventListener('message', async (e) => {
  const { imageData } = e.data
  // 滤镜算法
  for (let i = 0; i < imageData.data.length; i += 4) {
    const r = imageData.data[i]
    const g = imageData.data[i + 1]
    const b = imageData.data[i + 2]
    // 灰度化
    const gray = 0.299 * r + 0.587 * g + 0.114 * b
    imageData.data[i] = imageData.data[i + 1] = imageData.data[i + 2] = gray
  }
  self.postMessage({ type: 'filter', imageData })
})

4.4 加密/解密 ​

ts
// main.ts
const publicKey = await fetch('/api/key').then(r => r.json())
const worker = new Worker('/crypto.worker.js')

worker.postMessage({ type: 'encrypt', data: sensitiveData, publicKey })

worker.onmessage = (e) => {
  if (e.data.type === 'encrypt') {
    sendToServer(e.data.encrypted)
  }
}

五、性能关键:Transferable Objects ​

默认 postMessage 会结构化克隆——深拷贝整个对象。对于大数组、二进制,这是巨大的浪费。

Transferable 把所有权转移给 Worker,零拷贝:

ts
// 100MB 的 ArrayBuffer
const buffer = new ArrayBuffer(100 * 1024 * 1024)

// 默认:拷贝(慢)
worker.postMessage(buffer)

// Transferable:转移所有权(零拷贝)
worker.postMessage(buffer, [buffer])

// 主线程的 buffer 现在 detached(不可访问)
console.log(buffer.byteLength)  // 0

实战经验:大文件/大数组一定要用 Transferable——10MB 数据从 50ms 降到 < 1ms。

ts
// ImageBitmap 也是 Transferable
const bitmap = await createImageBitmap(imageBlob)
worker.postMessage({ bitmap }, [bitmap])

六、Comlink:让 Worker 更好用 ​

裸 Worker API 太啰嗦,Comlink 让你像调本地函数一样用 Worker:

ts
// math.worker.ts
import { expose } from 'comlink'
const api = {
  fibonacci(n: number): number {
    if (n <= 1) return n
    return api.fibonacci(n - 1) + api.fibonacci(n - 2)
  },
  heavyAggregate(data: number[]) { ... }
}
expose(api)
ts
// main.ts
import { wrap, Remote } from 'comlink'

const worker = new Worker(new URL('./math.worker.ts', import.meta.url), { type: 'module' })
const math = wrap<typeof import('./math.worker')>(worker)

// 像调本地函数一样
const fib40 = await math.fibonacci(40)        // Worker 线程跑,不卡主线程
const result = await math.heavyAggregate(data) // Worker 线程跑

实战经验:Comlink 是用 Worker 的最佳实践——保留 Worker 的并行能力,API 像 Promise。

七、生命周期与清理 ​

ts
// 单次任务:用完销毁
const worker = new Worker('/once.worker.js')
worker.postMessage({ data })
worker.onmessage = (e) => {
  console.log(e.data)
  worker.terminate()  // 立即释放资源
}

// 复用 Worker:长期持有
const worker = new Worker('/persistent.worker.js')
function cleanup() {
  worker.terminate()
}
window.addEventListener('beforeunload', cleanup)

注意:Worker 持有内存(几十 MB),不用的 Worker 要 terminate()。

八、SSR 注意事项 ​

重要:SSR 阶段没有 Worker / window,需要懒加载:

ts
const workerPromise = import('./heavy.worker').then(({ default: worker }) => worker)

// 仅在客户端创建
const worker = typeof window !== 'undefined' ? new Worker(...) : null

或者用 dynamic import:

ts
async function loadWorker() {
  if (typeof window === 'undefined') return null
  const { default: Worker } = await import('./heavy.worker.js')
  return new Worker()
}

九、调试 ​

  • Chrome DevTools 的 Sources 面板 → Workers 标签
  • console.log 在 Worker 里正常输出到 DevTools Console
  • debugger 断点在 Worker 里也可用

十、何时不要用 Worker ​

  • < 10ms 的小任务:启动开销 > 收益
  • 需要 DOM 访问:Worker 没有 DOM
  • 项目刚启动,主线程没事:过度设计

判断标准:任务 > 16ms(单帧)或 > 50ms(感知卡顿)就要考虑 Worker。

🎯 面试常考 ​

Q1：Web Worker 什么时候用?

主线程做重计算会卡住交互时:大数据排序/过滤、复杂 JSON 解析、加解密、大量正则匹配、图像处理。判断标准是单次任务超过 50ms 就该考虑。

Q2：Web Worker 的代价是什么?

通信需要 structuredClone 或 transferable 对象(可转移则零拷贝),调试链路变长,还要考虑 Worker 创建和销毁本身的成本。轻量任务用 Worker 反而更慢。

📝 小结 ​

  • Worker 的价值是「把可等待的工作挪出主线程」,前提是这段工作确实重。
  • 数据传递优先用 transferable(ArrayBuffer)实现零拷贝,大数组别用 structuredClone。
  • 任务调度要用队列 + 分片,避免一次性把主线程塞满,反而更卡。
