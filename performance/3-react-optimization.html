React 性能优化详解 ​

一、渲染优化基础 ​

1.1 React 渲染流程 ​

State/Props 变化 → shouldComponentUpdate/PureComponent/memo?
                    ↓ (返回 true)
                 Re-render → Virtual DOM Diff → Real DOM Update

1.2 触发重新渲染的原因 ​

原因说明
setState组件状态变化
父组件渲染父组件重新渲染，子组件必然渲染
Props 变化传递给子组件的 props 变化
forceUpdate强制更新

1.3 不必要渲染的问题 ​

父组件渲染
├── 子组件 A（状态没变，但也会重新渲染）❌
├── 子组件 B（状态没变，但也会重新渲染）❌
└── 子组件 C（状态变了，需要重新渲染）✅

二、避免不必要渲染 ​

2.1 shouldComponentUpdate（类组件） ​

tsx
class Counter extends React.Component {
  shouldComponentUpdate(nextProps, nextState) {
    // 只在 count 变化时重新渲染
    return nextProps.count !== this.props.count
  }

  render() {
    return <div>{this.props.count}</div>
  }
}

2.2 PureComponent（类组件） ​

tsx
// 自动进行浅比较
class UserCard extends React.PureComponent {
  render() {
    return <div>{this.props.name}</div>
  }
}

PureComponent 浅比较原理：

tsx
// 源码大致逻辑
if (this._compositeType === 'PureClass') {
  shouldUpdate = !shallowEqual(prevProps, nextProps) ||
                !shallowEqual(prevState, nextState)
}

2.3 React.memo（函数组件） ​

tsx
// 默认浅比较
const Button = React.memo(function Button({ onClick, children }) {
  return <button onClick={onClick}>{children}</button>
})

// 自定义比较函数
const Button = React.memo(
  function Button({ onClick, children }) {
    return <button onClick={onClick}>{children}</button>
  },
  (prevProps, nextProps) => {
    // 返回 true 表示 props 相等，不重新渲染
    return prevProps.onClick === nextProps.onClick
  }
)

2.4 浅比较的问题 ​

tsx
// ❌ 问题：每次渲染都创建新对象，导致重新渲染
function Parent() {
  const [count, setCount] = useState(0)

  return (
    <Child
      style={{ color: 'red' }}  // 每次渲染都是新对象
      onClick={() => doSomething()}  // 每次渲染都是新函数
    />
  )
}

// ✅ 优化：使用 useMemo/useCallback
function Parent() {
  const [count, setCount] = useState(0)
  const style = useMemo(() => ({ color: 'red' }), [])
  const handleClick = useCallback(() => doSomething(), [])

  return (
    <Child style={style} onClick={handleClick} />
  )
}

三、useMemo 和 useCallback ​

3.1 useMemo ​

缓存计算结果，只有依赖变化时才重新计算。

tsx
const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b])

使用场景：

  • 复杂计算
  • 创建新对象/数组
  • 上下文值
tsx
// ❌ 错误用法：没有依赖或依赖为空数组
const result = useMemo(() => fetchData()) // 只计算一次

// ✅ 正确：依赖数组
const sortedList = useMemo(() => {
  return list.sort((a, b) => a.name.localeCompare(b.name))
}, [list])

// ✅ 正确：创建对象
const config = useMemo(() => ({
  theme: 'dark',
  language: 'zh'
}), []) // 空依赖，对象创建一次

3.2 useCallback ​

缓存函数引用。

tsx
const memoizedCallback = useCallback(() => {
  doSomething(a, b)
}, [a, b])

使用场景：

  • 传递给子组件的回调函数
  • 作为其他 Hook 的依赖
  • 事件处理函数
tsx
// ❌ 错误
<Child onClick={() => handleClick(id)} />

// ✅ 正确
const handleClick = useCallback((id) => {
  handleClick(id)
}, [handleClick])
<Child onClick={handleClick} />

3.3 两者区别 ​

Hook缓存内容使用场景
useMemo计算结果（值）复杂计算、新对象
useCallback函数引用回调函数
tsx
// useCallback 等价于
const handleClick = useMemo(() => () => doSomething(), [doSomething])

3.4 过度优化的问题 ​

tsx
// ❌ 过度优化：不必要的 memoization
const value = useMemo(() => 1 + 1, []) // 计算常量

// ❌ 过度优化：过早优化
const style = useMemo(() => ({ padding: 10 }), []) // 对象字面量

// ✅ 正确的优化方向
const heavyData = useMemo(() => processLargeData(input), [input])

四、组件拆分 ​

4.1 为什么要拆分 ​

❌ 糟糕：大组件
─────────────────────────────
组件状态变化 → 整个组件重新渲染
  ├── 静态部分 A（不需要重新渲染）
  ├── 静态部分 B（不需要重新渲染）
  ├── 动态部分 C（需要重新渲染）
  └── 动态部分 D（需要重新渲染）
✅ 优化：拆分小组件
─────────────────────────────
状态变化 → 只影响相关小组件
  ├── 组件 A（不受影响）
  ├── 组件 B（不受影响）
  └── 动态组件 C（重新渲染）

4.2 实践示例 ​

tsx
// ❌ 糟糕：所有东西放在一起
function UserProfile({ userId }) {
  const [user, setUser] = useState(null)
  const [posts, setPosts] = useState([])
  const [comments, setComments] = useState([])

  // posts 变化会导致整个组件重新渲染
  // 包括不相关的 user 和 comments 显示

  return (
    <div>
      <UserInfo user={user} />
      <UserPosts posts={posts} /> {/* 只关心 posts */}
      <UserComments comments={comments} /> {/* 只关心 comments */}
    </div>
  )
}

// ✅ 优化：状态提升到需要的地方
function UserProfile({ userId }) {
  return (
    <div>
      <UserInfo userId={userId} />
      <UserPosts userId={userId} />
      <UserComments userId={userId} />
    </div>
  )
}

function UserPosts({ userId }) {
  const [posts, setPosts] = useState([]) // 只管理 posts
  // posts 变化只影响这个组件
  return <List data={posts} />
}

function UserComments({ userId }) {
  const [comments, setComments] = useState([]) // 只管理 comments
  // comments 变化只影响这个组件
  return <List data={comments} />
}

五、列表优化 ​

5.1 key 的重要性 ​

tsx
// ❌ 错误：使用索引作为 key
{items.map((item, index) => (
  <Item key={index} {...item} />
))}

// ✅ 正确：使用稳定 ID
{items.map(item => (
  <Item key={item.id} {...item} />
))}

5.2 虚拟列表 ​

当列表很长时，只渲染可视区域。

使用 react-window：

tsx
import { FixedSizeList } from 'react-window'

function VirtualList({ items }) {
  const Row = ({ index, style }) => (
    <div style={style}>
      <ListItem item={items[index]} />
    </div>
  )

  return (
    <FixedSizeList
      height={600}
      itemCount={items.length}
      itemSize={50}
      width="100%"
    >
      {Row}
    </FixedSizeList>
  )
}

动态高度列表：

tsx
import { VariableSizeList } from 'react-window'

function DynamicList({ items }) {
  const getItemSize = index => items[index].height

  return (
    <VariableSizeList
      height={600}
      itemCount={items.length}
      itemSize={getItemSize}
      width="100%"
    >
      {Row}
    </VariableSizeList>
  )
}

5.3 分页加载 ​

tsx
function PaginatedList({ initialData, fetchMore }) {
  const [data, setData] = useState(initialData)
  const [page, setPage] = useState(1)

  const loadMore = async () => {
    const newData = await fetchMore(page)
    setData(prev => [...prev, ...newData])
    setPage(p => p + 1)
  }

  return (
    <>
      <List data={data} />
      <button onClick={loadMore}>加载更多</button>
    </>
  )
}

六、代码分割 ​

6.1 React.lazy + Suspense ​

tsx
const OtherComponent = React.lazy(() => import('./OtherComponent'))

function MyComponent() {
  return (
    <div>
      <Suspense fallback={<div>Loading...</div>}>
        <OtherComponent />
      </Suspense>
    </div>
  )
}

6.2 路由级分割 ​

tsx
import { BrowserRouter, Routes, Route } from 'react-router-dom'
import React, { Suspense, lazy } from 'react'

const Home = lazy(() => import('./pages/Home'))
const About = lazy(() => import('./pages/About'))
const Dashboard = lazy(() => import('./pages/Dashboard'))
const Settings = lazy(() => import('./pages/Settings'))

function App() {
  return (
    <BrowserRouter>
      <Suspense fallback={<div>Loading...</div>}>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/about" element={<About />} />
          <Route path="/dashboard" element={<Dashboard />} />
          <Route path="/settings" element={<Settings />} />
        </Routes>
      </Suspense>
    </BrowserRouter>
  )
}

tsx
// 条件渲染时分割
const HeavyChart = React.lazy(() => import('./HeavyChart'))

function Dashboard() {

七、状态管理优化 ​

7.1 状态位置 ​

tsx
// ❌ 错误：状态放在父组件
function Parent() {
  const [count, setCount] = useState(0)
  return <Child count={count} onIncrement={() => setCount(c => c + 1)} />
}

// ✅ 正确：状态放在需要它的组件
function Parent() {
  return <Child />
}

function Child() {
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>
}

7.2 派生状态 ​

tsx
// ❌ 错误：派生状态应该 computed
function BadExample({ items, filter }) {
  const [filteredItems, setFilteredItems] = useState([])

  useEffect(() => {
    setFilteredItems(items.filter(item => item.type === filter))
  }, [items, filter])

  return <List data={filteredItems} />
}

// ✅ 正确：直接计算
function GoodExample({ items, filter }) {
  const filteredItems = useMemo(() =>
    items.filter(item => item.type === filter),
    [items, filter]
  )

  return <List data={filteredItems} />
}

7.3 Context 优化 ​

tsx
// ❌ 问题：整个 Context 变化导致所有消费者重新渲染
const ThemeContext = createContext('light')

// ✅ 优化：拆分 Context
const ThemeContext = createContext({ color: 'light' })
const UpdateThemeContext = createContext(() => {})

// 或使用 useContextSelector
function useTheme() {
  const context = useContextSelector(ThemeContext, value => value.color)
}

八、Effects 优化 ​

8.1 正确使用依赖 ​

tsx
// ❌ 错误：依赖不完整
useEffect(() => {
  fetchData(props.id) // 缺少依赖
}, []) // []

// ✅ 正确：包含所有依赖
useEffect(() => {
  fetchData(props.id)
}, [props.id])

8.2 cleanup 函数 ​

tsx
// ❌ 内存泄漏
useEffect(() => {
  const subscription = dataSource.subscribe()
  // 没有 cleanup
}, [dataSource])

// ✅ 正确：清理
useEffect(() => {
  const subscription = dataSource.subscribe()
  return () => {
    subscription.unsubscribe()
  }
}, [dataSource])

8.3 避免无限循环 ​

tsx
// ❌ 问题：effect 中更新状态
useEffect(() => {
  setCount(count + 1) // 触发重新渲染 → 再次执行 effect → 无限循环
}, [count])

// ✅ 正确：在事件处理中更新
const handleClick = () => {
  setCount(c => c + 1)
}

九、运行时优化 ​

9.1 防抖节流 ​

tsx
import { useState, useCallback } from 'react'
import { debounce } from 'lodash'

function SearchInput({ onSearch }) {
  const [value, setValue] = useState('')

  const debouncedSearch = useCallback(
    debounce((query) => {
      onSearch(query)
    }, 300),
    [onSearch]
  )

  const handleChange = (e) => {
    setValue(e.target.value)
    debouncedSearch(e.target.value)
  }

  return <input value={value} onChange={handleChange} />
}

9.2 虚拟滚动（完整示例） ​

tsx
import { FixedSizeList as List } from 'react-window'
import AutoSizer from 'react-virtualized-auto-sizer'

function VirtualizedList({ items }) {

十一、常见错误 ​

错误 1：内联函数作为 props ​

tsx
// ❌ 导致子组件重新渲染
<Child onClick={() => handleClick(item.id)} />

// ✅ 使用 useCallback
const handleClick = useCallback((id) => handleClick(id), [handleClick])
<Child onClick={handleClick} />

错误 2：对象字面量作为 props ​

tsx
// ❌ 每次渲染都是新对象
<Child style={{ color: 'red' }} />

// ✅ 使用 useMemo
const style = useMemo(() => ({ color: 'red' }), [])
<Child style={style} />

错误 3：在渲染中创建新数组/对象 ​

tsx
// ❌ 每次渲染都创建新数组
return items.filter(item => item.active).map(item => ({ ...item }))

// ✅ 使用 useMemo
const activeItems = useMemo(() =>
  items.filter(item => item.active).map(item => ({ ...item })),
  [items]
)
return activeItems.map(item => ...)

错误 4：错误的 useEffect 依赖 ​

tsx
// ❌ 依赖不完整
useEffect(() => {
  fetchData(props.userId)
}, []) // []

// ✅ 正确
useEffect(() => {
  fetchData(props.userId)
}, [props.userId])

🎯 面试常考 ​

Q1：React 性能优化有哪些手段?

避免不必要的渲染(React.memo / useMemo / useCallback)、降低渲染成本(列表虚拟化、状态下沉)、把重活挪出主线程(Web Worker)、减少包体积(代码分割 + Tree Shaking)。

Q2：useMemo 和 memo 有什么区别?

memo 缓存的是组件渲染结果,粒度是组件;useMemo 缓存的是计算结果,粒度是值。两者都是「缓存 + 依赖比较」,不是越多越好,缓存本身也有成本。

📝 小结 ​

  • React 优化第一原则是「先测量再优化」,React DevTools Profiler 的 commit 耗时和 render 次数是唯一定位依据。
  • state 尽量下放到真正需要它的子树,列表项数据量大时组件化 + 虚拟列表是收益最大的组合。
  • key 用稳定唯一 id,不要用 index,否则列表顺序变化会导致大量节点重建。
  • 重计算(大数组排序、复杂解析)放 Web Worker,避免阻塞主线程。
