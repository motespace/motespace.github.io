浏览器渲染原理详解 ​

一、浏览器渲染流程 ​

1.1 完整渲染流程 ​

HTML → Parsing → DOM Tree
                    ↓
              CSS → Parsing → CSSOM Tree
                    ↓
              DOM + CSSOM → Render Tree
                    ↓
                  Layout (Reflow)
                    ↓
                  Paint
                    ↓
               Composite

1.2 详细步骤 ​

步骤过程输出
** Parsing**解析 HTML 构建 DOMDOM 树
CSS Parsing解析 CSS 构建 CSSOMCSSOM 树
Render TreeDOM + CSSOM 合并渲染树
Layout计算元素位置和大小几何信息
Paint绘制像素位图
Composite图层合并最终画面

二、关键渲染路径（CRP） ​

2.1 什么是 CRP ​

关键渲染路径（Critical Rendering Path）是浏览器将 HTML、CSS、JavaScript 转化为屏幕像素的必经之路。

2.2 优化目标 ​

尽可能减少关键资源数量
尽可能减少关键资源大小
尽可能缩短 CRP 长度

2.3 关键资源 vs 非关键资源 ​

类型定义处理方式
关键资源阻止首次渲染preload、inline
非关键资源不影响首屏async、defer、lazy

三、DOM 构建 ​

3.1 过程 ​

HTML String → Bytes → Characters → Tokens → Nodes → DOM Tree

3.2 示例 ​

html
<html>
  <head>
    <title>Title</title>
  </head>
  <body>
    <div>
      <h1>Hello</h1>
    </div>
  </body>
</html>
text
document
├── html
│   ├── head
│   │   └── title
│   └── body
│       └── div
│           └── h1

3.3 JS 阻塞 ​

html
<!-- 阻塞 HTML 解析 -->
<script src="app.js"></script>

<!-- 不阻塞（需要浏览器支持）-->
<script async src="app.js"></script>
<script defer src="app.js"></script>
属性执行时机阻塞 HTML
无立即下载并执行✅ 阻塞
async异步下载完立即执行❌ 不阻塞（但阻塞 load 事件）
deferHTML 解析完、执行前执行❌ 不阻塞

四、CSSOM 构建 ​

4.1 过程 ​

CSS String → Bytes → Characters → Tokens → Nodes → CSSOM Tree

4.2 示例 ​

css
body { font-size: 16px }
div { color: red }
#app { width: 100px }
text
style
├── body { font-size: 16px }
├── div { color: red }
└── #app { width: 100px }

4.3 CSS 阻塞特性 ​

CSS 是阻塞渲染的资源！

html
<!-- 阻塞渲染直到 CSSOM 构建完成 -->
<link rel="stylesheet" href="style.css">

<!-- 打印样式（不阻塞渲染）-->
<link rel="stylesheet" href="print.css" media="print">

<!-- 移动端样式（仅在移动端阻塞）-->
<link rel="stylesheet" href="mobile.css" media="screen and (max-width: 600px)">

4.4 渲染阻塞的影响 ​

html
<!-- 问题：CSS 阻塞首屏渲染 -->
<head>
  <link rel="stylesheet" href="large.css"> <!-- 阻塞！-->
</head>
<body>
  <div class="loading">白屏等待...</div>
</body>

解决方案：内联关键 CSS

html
<head>
  <style>
    /* 关键 CSS 内联 */
    body { margin: 0; font-family: sans-serif }
    .header { background: #333; color: #fff }
  </style>
  <!-- 非关键 CSS 异步加载 -->
  <link rel="preload" href="non-critical.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
</head>

五、渲染树（Render Tree） ​

5.1 构建过程 ​

DOM Tree + CSSOM Tree → Render Tree

5.2 渲染树规则 ​

  • 只包含可见节点
  • 跳过 display: none
  • 保留 visibility: hidden（但不可点击）
html
<div style="display: none">不显示</div>
<div style="visibility: hidden">不可见但占位</div>
<div>正常显示</div>

5.3 渲染树计算 ​

text
Render Tree
├── div (display: none) - 不包含
├── div (visibility: hidden) - 包含但不可见
└── div - 正常显示并计算布局

六、Layout（布局） ​

6.1 什么是 Layout ​

根据渲染树计算每个元素的几何信息：

  • 位置（x, y）
  • 尺寸（width, height）
  • 相对于父元素的位置

6.2 触发 Layout 的操作 ​

操作类型示例
增删 DOMappendChild、removeChild
改变尺寸width、height、margin、padding
内容变化innerText、textContent
浏览器窗口变化resize 事件
获取布局信息offsetWidth、getComputedStyle

6.3 Layout 性能问题 ​

javascript
// ❌ 错误：每次读取都触发 Layout
for (const div of divs) {
  const height = div.offsetHeight // 触发 Layout
  div.style.height = height + 'px'
}

// ✅ 正确：批量读写
const heights = divs.map(div => div.offsetHeight) // 读取
divs.forEach((div, i) => div.style.height = heights[i] + 'px') // 写入

七、Paint（绘制） ​

7.1 什么是 Paint ​

将 Layout 计算后的几何信息转换为屏幕上的实际像素。

7.2 绘制顺序 ​

1. 背景颜色
2. 背景图片
3. 边框
4. 子女
5. 轮廓

7.3 触发 Paint 的操作 ​

CSS 属性触发
color、backgroundRepaint
visibilityRepaint
box-shadow、border-radiusRepaint
transform、opacityComposite Only（不触发 Layout/Paint）

八、Composite（合成） ​

8.1 图层概念 ​

浏览器将页面分为多个图层（Layer）分别绘制。

┌─────────────────────────┐
│         Layer 1          │ ← 导航栏
├─────────────────────────┤
│         Layer 2          │ ← 主内容
├─────────────────────────┤
│         Layer 3          │ ← 浮动按钮
└─────────────────────────┘
          ↓
     合成输出

8.2 图层触发条件 ​

条件说明
position: fixed固定定位
will-change声明即将变化
transform: translateZ(0)GPU 加速
动画 transform / opacity硬件加速
video、canvas媒体元素
iframe插件

8.3 硬件加速 ​

css
/* 开启硬件加速 */
.transform-demo {
  transform: translateZ(0);
  will-change: transform;
}

注意：滥用硬件加速会消耗更多内存。

九、优化关键渲染路径 ​

9.1 优化策略 ​

策略方法效果
最小化资源压缩、Tree Shaking减少下载量
减少请求内联、合并减少 RTT
优化 CSScritical CSS inline减少阻塞
延迟加载defer、async减少 CRP 长度

9.2 实践示例 ​

优化前：阻塞渲染

html
<head>
  <link rel="stylesheet" href="app.css">
  <script src="app.js"></script>
</head>
<body>
  <div id="app"></div>
</body>

优化后：非阻塞加载

html
<head>
  <!-- 内联关键 CSS -->
  <style>
    body { margin: 0; font-family: sans-serif }
    /* 其他关键样式... */
  </style>
  <!-- 预连接关键域名 -->
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <!-- 预加载关键资源 -->
  <link rel="preload" href="app.js" as="script">
</head>
<body>
  <div id="app"></div>
  <!-- 非关键 CSS 异步加载 -->
  <link rel="stylesheet" href="non-critical.css" media="print" onload="this.media='all'">
  <!-- 非关键 JS 延迟加载 -->
  <script defer src="app.js"></script>
</body>

9.3 预加载与预取 ​

html
<!-- 预加载当前页面必需资源 -->
<link rel="preload" href="main.js" as="script">
<link rel="preload" href="font.woff2" as="font" crossorigin>

<!-- 预取未来可能使用的资源 -->
<link rel="prefetch" href="next-page.js" as="script">

<!-- DNS 预解析 -->
<link rel="dns-prefetch" href="https://api.example.com">

🎯 面试常考 ​

Q1: 为什么 CSS 会阻塞渲染？ ​

浏览器需要 CSSOM 才能构建渲染树，所以 CSS 必须加载完成才能渲染页面。

Q2: defer 和 async 的区别？ ​

特性deferasync
下载时阻塞 HTML❌❌
何时执行HTML 解析后下载完成后立即
执行顺序保持文档顺序谁先下载完谁执行
适用场景有依赖的脚本独立的第三方脚本

Q3: 如何避免强制同步布局（Forced Synchronous Layout）？ ​

javascript
// ❌ 强制同步布局：读写交替触发 Layout
element.style.width = element.offsetWidth + 10 + 'px'

// ✅ 分离读写
const width = element.offsetWidth // 读
element.style.width = width + 10 + 'px' // 写

Q4: will-change 使用注意？ ​

css
/* ✅ 正确：提前声明将要变化 */
.will-change-transform {
  will-change: transform;
}

/* ❌ 错误：滥用导致内存浪费 */
* {
  will-change: transform;
}

📝 小结 ​

  • 渲染流水线是 DOM 构建 → CSSOM 构建 → Render Tree → Layout → Paint → Composite 六步,优化的本质就是缩短关键渲染路径(CRP)。
  • CSS 默认阻塞渲染、JS 默认阻塞 DOM 解析,这两者的差别决定了该用 preload、async 还是 defer。
  • Layout / Paint / Composite 各自有独立的触发条件,transform 和 opacity 只触发合成,是动画不掉帧的关键。
  • 读 DOM 紧接着写 DOM 会触发强制同步布局(Forced Synchronous Layout),批量读写或用 requestAnimationFrame 断开即可避免。
