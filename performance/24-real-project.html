真实项目复盘:智能风控平台 Webpack → Vite 迁移 ​

来自简历项目 "03 智能风控引擎平台"。本文完整复盘从"为什么迁"到"如何迁"到"收益多少",可作为类似迁移项目的参考模板。

一、背景:为什么要迁移 ​

1.1 痛点 ​

  • 冷启动慢:Webpack 全量打包,冷启动 30s+,开发体验极差
  • 包体积大:首屏 JS 5.94 MiB,移动端首屏超过 5s
  • 构建慢:增量构建 8s+,改一行代码要等
  • HMR 不友好:改一个组件要重 build 整个 chunk

1.2 选型过程 ​

候选评估结论
继续优化 Webpack已用 Vite 插件化拆包到极限❌ 收益小
升级到 Webpack 5持久缓存可改善构建速度,但冷启动无解❌ 治标
迁 Vite利用 esbuild 预构建 + 原生 ESM✅
迁 RspackRust 实现,Webpack 兼容✅ 备选,生态不够成熟

选择 Vite 的关键理由:

  1. Vue 3 / Element Plus 官方推荐
  2. 生态成熟,文档完善
  3. 迁移成本可控(主要是改配置 + 解决 polyfill)

二、迁移准备 ​

2.1 评估影响面 ​

迁移前先列出所有 Webpack 特有依赖:

bash
# 项目里实际用到的
- webpack-chain           # 自定义 Webpack 配置
- webpack-bundle-analyzer # 包分析
- speed-measure-webpack-plugin # 构建速度分析
- copy-webpack-plugin     # 静态资源拷贝
- @vue/babel-preset-app   # Vue 2 时代的 babel 预设
- vue-loader              # Vue 单文件组件

Vite 下对应的:

WebpackVite
webpack-chainvite.config.ts 直接配置
webpack-bundle-analyzerrollup-plugin-visualizer
copy-webpack-pluginvite-plugin-static-copy
vue-loader@vitejs/plugin-vue
@vue/babel-preset-app不需要,Vite 用 esbuild

2.2 评估运行时差异 ​

Vite 用 原生 ESM + 现代浏览器,所以需要确认:

  • 目标浏览器:Chrome 90+ / Edge 90+ / Safari 14+ ✅
  • IE 11 / 旧 Edge:❌ 不支持(项目是内部 SaaS,可以放弃)
  • CJS 依赖:lodash、echarts 等老包在 dev 需手动 polyfill
ts
// vite.config.ts - 处理 CJS
export default defineConfig({
  optimizeDeps: {
    include: ['lodash-es', 'echarts'], // 预构建这些 CJS 包
  },
})

三、迁移步骤 ​

3.1 第一周:配置文件搭好 ​

ts
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'
import { visualizer } from 'rollup-plugin-visualizer'

export default defineConfig({
  plugins: [
    vue(),
    AutoImport({
      imports: ['vue', 'vue-router'],
      resolvers: [ElementPlusResolver({ importStyle: 'css' })],
    }),
    Components({
      resolvers: [ElementPlusResolver({ importStyle: 'css' })],
    }),
    visualizer({ filename: 'dist/stats.html' }),
  ],

  build: {
    minify: 'esbuild',
    target: 'es2018',                  // 内部 SaaS,可以激进一些
    chunkSizeWarningLimit: 1500,       // 1.5MB 警告阈值
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router'],
          echarts: ['echarts'],
          'element-plus': ['element-plus'],
        },
      },
    },
  },

  optimizeDeps: {
    include: [
      'vue', 'vue-router', 'axios', 'echarts', 'element-plus',
      'lodash-es',
    ],
  },
})

3.2 第二周:路由拆包 ​

ts
// 之前(Webpack):所有路由打包到一起
import Home from '@/views/Home.vue'
import List from '@/views/List.vue'

// 之后(Vite):每个路由独立 chunk
const routes = [
  { path: '/', component: () => import('@/views/Home.vue') },
  { path: '/list', component: () => import('@/views/List.vue') },
]

3.3 第三周:依赖按需引入 ​

ts
// 之前:全量引入,1.8MB
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'

// 之后:按需,只有用到的组件打包
// 通过 AutoImport + ElementPlusResolver 自动完成
// 业务代码无需改:<el-button> 照常写

3.4 第四周:ECharts 按需 ​

ts
// 之前:全量 2.4MB
import * as echarts from 'echarts'

// 之后:只注册用到的图表
import * as echarts from 'echarts/core'
import { LineChart, BarChart, PieChart } from 'echarts/charts'
import {
  TitleComponent, TooltipComponent, LegendComponent, GridComponent,
} from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'

echarts.use([
  LineChart, BarChart, PieChart,
  TitleComponent, TooltipComponent, LegendComponent, GridComponent,
  CanvasRenderer,
])

3.5 第五周:Mock 剔除 + 边缘情况修复 ​

生产剔除 Mock(节省 800KB):

ts
// vite.config.ts
export default defineConfig(({ mode }) => {
  const isProd = mode === 'production'
  return {
    define: {
      __DEV__: JSON.stringify(!isProd),
      __MOCK__: JSON.stringify(!isProd),
    },
  }
})
ts
// 业务代码
if (__MOCK__) {
  const { setupMock } = await import('@/mock')
  setupMock()
}

遇到的其他坑:

  • process.env 在 Vite 下要用 import.meta.env
  • require() 不能用,改 import()
  • __filename / __dirname 不存在,用 import.meta.url
  • @import 路径别名要单独配置

  • INP P75 从 280ms 降到 120ms
  • 用户投诉"卡顿"工单下降 70%

五、踩坑经验 ​

5.1 optimizeDeps 必须配 ​

不配会导致首次启动巨慢(因为 Vite 会现场转译 CJS):

ts
optimizeDeps: {
  include: ['lodash-es', 'echarts', 'axios'], // 所有 CJS 或大型 ESM 包
}

5.2 路由拆包别过度 ​

不是每个页面都要拆——首页 + 3~5 个高频页独立,其他合一个 vendor chunk。

5.3 别忘了 legacy 兼容 ​

如果有外部嵌入、老浏览器用户:

ts
import legacy from '@vitejs/plugin-legacy'
plugins: [legacy({ targets: ['defaults'] })]

会让构建产物大一圈,但能兼容老浏览器。

5.4 SourceMap 要正确开启 ​

生产环境建议用 hidden-source-map 而非 source-map——不暴露源码给用户,但内部可以查问题。

六、给后续团队的建议 ​

  1. 新项目直接 Vite——不要再选 Webpack(除非有特殊兼容性需求)
  2. 旧项目 Webpack→Vite 迁移——按本文步骤,5~6 周单人可完成
  3. 性能优化是持续的——Vite 只是基础设施,后续还要做 Code Splitting / 懒加载 / 缓存策略

🎯 面试常考 ​

Q1：讲一个你做过的性能优化项目。

背景:风控平台老项目是 Vue2 + Webpack,构建慢、首屏慢。定位:用 Lighthouse 和 WebPageTest 发现首屏 JS 800KB+、构建 3 分 20 秒。动作:迁移 Vite + 按路由分包 + 图片转 WebP + 关键 CSS 内联。结果:构建降到 40 秒,首屏 4.2s → 0.9s,LCP P75 下降 58%。复盘:迁移前应该先做分包,收益更直接。

📝 小结 ​

  • 真实项目最有说服力的地方是「有取舍」——迁移到 Vite 之前,先做分包和图片优化能拿到大部分收益。
  • 数字要成对:构建 3分20秒 → 40秒,首屏 4.2s → 0.9s。
  • 复盘比成绩更重要:写清楚「如果重来会怎么做」,这是资深工程师和高级工程师的区别。
