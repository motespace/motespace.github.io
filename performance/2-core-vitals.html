Core Web Vitals 详解 ​

一、Core Web Vitals 概述 ​

1.1 三大指标 ​

指标全称优化目标测量什么
LCPLargest Contentful Paint≤ 2.5s加载性能
INPInteraction to Next Paint≤ 200ms交互响应
CLSCumulative Layout Shift≤ 0.1视觉稳定性

1.2 指标演变 ​

FID (First Input Delay) → 2024年3月 → INP (Interaction to Next Paint)

FID 测量首次输入延迟，INP 测量所有交互的延迟，更全面。

二、LCP（Largest Contentful Paint） ​

2.1 什么是 LCP ​

测量视口中最大内容元素的渲染时间。

LCP 元素可能是：

  • <img> 图片
  • <video> 封面
  • 通过 url() 加载的背景图
  • 块级文本元素

2.2 LCP 时间标准 ​

分数LCP 时间说明
良好≤ 2.5s绿色
需要改进2.5s - 4s橙色
差> 4s红色

2.3 LCP 优化策略 ​

1. 优化服务器响应时间 ​

bash
# 测量 TTFB（Time To First Byte）
# 目标：< 0.8s

优化方法：

  • 使用 CDN
  • 优化数据库查询
  • 启用缓存
  • 减少服务器负载

2. 优化资源加载 ​

html
<!-- 预加载 LCP 图片 -->
<link rel="preload" href="hero-image.webp" as="image">

<!-- 使用 fetchpriority 优先加载 -->
<img src="hero.webp" fetchpriority="high" alt="Hero">

3. 使用现代图片格式 ​

html
<!-- WebP（更好的压缩）-->
<img src="image.webp" alt="">

<!-- AVIF（更好的压缩率）-->
<picture>
  <source srcset="image.avif" type="image/avif">
  <img src="image.webp" alt="">
</picture>

4. 图片优化 ​

html
<!-- 响应式图片 -->
<img
  src="small.jpg"
  srcset="small.jpg 400w, medium.jpg 800w, large.jpg 1200w"
  sizes="(max-width: 600px) 400px, (max-width: 1200px) 800px, 1200px"
  alt=""
>

<!-- 懒加载（非 LCP 图片）-->
<img src="below-fold.webp" loading="lazy" alt="">

5. CSS 优化 ​

html
<!-- 关键 CSS 内联 -->
<style>
  /* Above-the-fold 样式 */
  body { margin: 0; font-family: system-ui }
  .hero { min-height: 100vh }
</style>

<!-- 非关键 CSS 异步加载 -->
<link rel="preload" href="styles.css" as="style"
      onload="this.onload=null;this.rel='stylesheet'">

2.4 代码示例 ​

javascript
// 使用 PerformanceObserver 测量 LCP
new PerformanceObserver((list) => {
  const entries = list.getEntries()
  const lastEntry = entries[entries.length - 1]
  console.log('LCP:', lastEntry.startTime)
}).observe({ entryTypes: ['largest-contentful-paint'] })

  console.log('LCP:', metric.value)
  console.log('Rating:', metric.rating) // 'good' | 'needs-improvement' | 'poor'

三、INP（Interaction to Next Paint） ​

3.1 什么是 INP ​

INP 测量用户交互（点击、键盘输入等）到浏览器绘制下一帧的时间。

计算公式：

INP = max(所有交互的 (input delay + processing time + presentation delay))

3.2 INP 组成 ​

阶段说明优化
Input Delay交互到主线程开始处理减少主线程任务
Processing TimeJavaScript 执行时间优化 JS 执行
Presentation Delay渲染提交到绘制完成减少布局抖动

3.3 INP 时间标准 ​

分数INP 时间说明
良好≤ 200ms绿色
需要改进200ms - 500ms橙色
差> 500ms红色

3.4 INP 优化策略 ​

1. 分解长任务 ​

javascript
// ❌ 长任务阻塞主线程
function processLargeData() {
  for (const item of hugeArray) {
    processItem(item) // 可能需要 500ms+
  }
}

// ✅ 使用 requestIdleCallback 分解任务
function processInChunks(items, chunkSize = 100) {
  function processChunk(index) {
    const end = Math.min(index + chunkSize, items.length)
    for (let i = index; i < end; i++) {
      processItem(items[i])
    }
    if (end < items.length) {
      requestIdleCallback(() => processChunk(end))
    }
  }
  processChunk(0)
}

2. 避免布局抖动 ​

javascript
// ❌ 读写交替导致布局抖动
function updateLayout() {
  const height = element.offsetHeight // 读
  element.style.height = (height + 10) + 'px' // 写
  const width = element.offsetWidth // 读（触发强制回流）
  element.style.width = (width + 10) + 'px' // 写
}

// ✅ 批量读写
function updateLayout() {
  // 先读取所有值
  const height = element.offsetHeight
  const width = element.offsetWidth

  // 再批量写入
  element.style.height = (height + 10) + 'px'
  element.style.width = (width + 10) + 'px'
}

3. 使用 Web Worker ​

javascript
// worker.js
self.onmessage = function(e) {
  const result = heavyComputation(e.data)
  self.postMessage(result)
}

// main.js
const worker = new Worker('worker.js')
worker.postMessage(largeDataSet)
worker.onmessage = function(e) {
  updateUI(e.result)
}

4. 事件处理优化 ​

javascript
// ❌ 同步执行耗时操作
button.addEventListener('click', () => {
  processHeavyData()
  updateUI()
})

// ✅ 延迟到下一帧或空闲时间
button.addEventListener('click', () => {
  requestAnimationFrame(() => {
    processHeavyData()
    updateUI()
  })
})

3.5 测量 INP ​

javascript
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.interactionId) {
      console.log('Interaction:', {
        type: entry.name,

四、CLS（Cumulative Layout Shift） ​

4.1 什么是 CLS ​

CLS 测量页面生命周期内发生的所有意外布局偏移的累计分数。

4.2 CLS 计算 ​

Layout Shift Score = Impact Fraction × Distance Fraction
因素说明
Impact Fraction不稳定元素影响的视口比例
Distance Fraction元素移动的距离（相对于视口）

4.3 CLS 标准 ​

分数CLS 值说明
良好≤ 0.1绿色
需要改进0.1 - 0.25橙色
差> 0.25红色

4.4 布局偏移原因 ​

原因示例
图片无尺寸<img> 没有 width/height
动态内容顶部横幅、聊天窗口
广告异步加载的广告位
Web FontsFOUT / FOIT
CSS 动画height、top 变化

4.5 CLS 优化策略 ​

1. 为图片和视频预留空间 ​

html
<!-- ✅ 正确：指定尺寸 -->
<img src="photo.jpg" width="800" height="600" alt="">

<!-- ❌ 错误：无尺寸导致布局偏移 -->
<img src="photo.jpg" alt="">

2. 响应式图片避免偏移 ​

html
<!-- 使用 aspect-ratio 预留空间 -->
<div style="aspect-ratio: 16/9">
  <img src="video-poster.jpg" alt="">
</div>

<!-- 或 CSS -->
.photo-container {
  aspect-ratio: 4/3;
  background-color: #f0f0f0; /* 占位色 */
}

3. 避免在内容上方插入动态内容 ​

css
/* ❌ 动态内容导致下方内容下移 */
.banner {
  position: absolute; /* 或 fixed */
  top: 0;
}

4. 使用 font-display ​

css
/* Google Fonts */
@font-face {
  font-family: 'MyFont';
  src: url('myfont.woff2') format('woff2');
  font-display: swap; /* 避免 FOIT */
}

5. 动画使用 transform/opacity ​

css
/* ❌ 触发布局 */
@keyframes slideIn {
  from { top: -50px }
  to { top: 0 }
}

/* ✅ 仅触发合成 */
@keyframes slideIn {
  from { transform: translateY(-50px) }
  to { transform: translateY(0) }
}

4.6 测量 CLS ​

javascript
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    // 排除用户交互导致的偏移
    if (!entry.hadRecentInput) {
      console.log('CLS:', entry.value)
    }
  }
}).observe({ type: 'layout-shift', buffered: true })
javascript
// 使用 web-vitals
import { getCLS } from 'web-vitals'

getCLS((metric) => {
  console.log('CLS:', metric.value)
  // metric.entries 包含所有导致偏移的事件
})

六、监控与报告 ​

6.1 web-vitals 使用 ​

bash
npm install web-vitals
javascript
import { getLCP, getINP, getCLS } from 'web-vitals'

function sendToAnalytics({ name, value, rating, id }) {
  // 发送到你的分析服务
  navigator.sendBeacon('/analytics', JSON.stringify({
    metric: name,
    value: Math.round(name === 'CLS' ? value * 1000 : value),
    rating, // 'good' | 'needs-improvement' | 'poor'
    id
  }))
}

getLCP(sendToAnalytics)
getINP(sendToAnalytics)
getCLS(sendToAnalytics)

6.2 CrUX 数据 ​

Chrome 用户体验报告（Chrome UX Report）提供真实用户的性能数据。

查询工具：

  • PageSpeed Insights
  • web.dev Measure
  • Lighthouse

6.3 性能预算 ​

javascript
// 设置性能预算
const BUDGET = {
  LCP: 2500,   // 2.5s
  INP: 200,    // 200ms
  CLS: 0.1     // 0.1
}

function checkBudget(metrics) {
  Object.entries(metrics).forEach(([name, value]) => {
    const limit = BUDGET[name.toUpperCase()]
    if (value > limit) {
      console.warn(`${name} 超出预算: ${value} > ${limit}`)
    }
  })
}

🎯 面试常考 ​

Q1: 如何同时优化三个指标？ ​

答案：它们有时会相互影响，优化时需要平衡。

  • LCP 和 CLS：图片预加载 + 尺寸可以同时改善两者
  • INP 和 CLS：避免动画使用 height/top，改用 transform

Q2: 如何在旧浏览器支持 INP？ ​

答案：INP 是新指标，旧浏览器可以回退到 FID。

javascript
import { getFID } from 'web-vitals'

// 如果 INP 不可用，使用 FID
if ('InteractionObserver' in window) {
  import('web-vitals').then(({ getINP }) => getINP(sendToAnalytics))
} else {
  getFID(sendToAnalytics)
}

Q3: 哪些交互对 INP 影响最大？ ​

答案：

  • 点击按钮
  • 键盘输入
  • 表单提交
  • 拖拽操作

Q4: 如何处理第三方脚本的 CLS？ ​

答案：

  1. 使用 iframe 隔离第三方内容
  2. 为第三方内容预留固定空间
  3. 使用 loading="lazy" 延迟加载
  4. 要求第三方提供商提供尺寸信息

📝 小结 ​

  • LCP 看加载、INP 看交互、CLS 看稳定性,三者分别对应「快」「响应快」「不跳」。
  • 指标要按 P75 分位数看(75% 的会话达到该值),而不是平均值,平均值会被长尾拖平。
  • 优化顺序是先量再改:没有基线就没有收益,先用 Lighthouse / DevTools 定位瓶颈再动手。
  • 线上要看 RUM(CrUX / web-vitals 上报),本地 Lighthouse 只是实验室数据,两者结论可能相反。
