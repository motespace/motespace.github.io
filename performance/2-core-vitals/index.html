Core Web Vitals 详解

一、Core Web Vitals 概述

Section titled “一、Core Web Vitals 概述”

1.1 三大指标

Section titled “1.1 三大指标”
指标 全称 优化目标 测量什么
LCP Largest Contentful Paint ≤ 2.5s 加载性能
INP Interaction to Next Paint ≤ 200ms 交互响应
CLS Cumulative Layout Shift ≤ 0.1 视觉稳定性

1.2 指标演变

Section titled “1.2 指标演变”

FID 测量首次输入延迟，INP 测量所有交互的延迟，更全面。

二、LCP（Largest Contentful Paint）

Section titled “二、LCP（Largest Contentful Paint）”

2.1 什么是 LCP

Section titled “2.1 什么是 LCP”

测量视口中最大内容元素的渲染时间。

LCP 元素可能是：

  • <img> 图片
  • <video> 封面
  • 通过 url() 加载的背景图
  • 块级文本元素

2.2 LCP 时间标准

Section titled “2.2 LCP 时间标准”
分数 LCP 时间 说明
良好 ≤ 2.5s 绿色
需要改进 2.5s - 4s 橙色
差 > 4s 红色

四、CLS（Cumulative Layout Shift）

Section titled “四、CLS（Cumulative Layout Shift）”

4.1 什么是 CLS

Section titled “4.1 什么是 CLS”

CLS 测量页面生命周期内发生的所有意外布局偏移的累计分数。

4.2 CLS 计算

Section titled “4.2 CLS 计算”
因素 说明
Impact Fraction 不稳定元素影响的视口比例
Distance Fraction 元素移动的距离（相对于视口）

Section titled “4.3 CLS 标准”

良好 ≤ 0.1 绿色

差 > 0.25 红色

🎯 面试常考

Section titled “🎯 面试常考”

Q1: 如何同时优化三个指标？

Section titled “Q1: 如何同时优化三个指标？”

答案：它们有时会相互影响，优化时需要平衡。

  • LCP 和 CLS：图片预加载 + 尺寸可以同时改善两者
  • INP 和 CLS：避免动画使用 height/top，改用 transform

Q2: 如何在旧浏览器支持 INP？

Section titled “Q2: 如何在旧浏览器支持 INP？”

答案：INP 是新指标，旧浏览器可以回退到 FID。

Q3: 哪些交互对 INP 影响最大？

Section titled “Q3: 哪些交互对 INP 影响最大？”

答案：

  • 点击按钮
  • 键盘输入
  • 表单提交
  • 拖拽操作

Q4: 如何处理第三方脚本的 CLS？

Section titled “Q4: 如何处理第三方脚本的 CLS？”

答案：

  1. 使用 iframe 隔离第三方内容
  2. 为第三方内容预留固定空间
  3. 使用 loading="lazy" 延迟加载
  4. 要求第三方提供商提供尺寸信息

📝 小结

Section titled “📝 小结”
  • LCP 看加载、INP 看交互、CLS 看稳定性,三者分别对应「快」「响应快」「不跳」。
  • 指标要按 P75 分位数看(75% 的会话达到该值),而不是平均值,平均值会被长尾拖平。
  • 优化顺序是先量再改:没有基线就没有收益,先用 Lighthouse / DevTools 定位瓶颈再动手。
  • 线上要看 RUM(CrUX / web-vitals 上报),本地 Lighthouse 只是实验室数据,两者结论可能相反。
