4.1 React 性能优化 ​

memo / useMemo / useCallback ​

tsx
// 1. React.memo 包裹纯展示组件
const UserCard = React.memo(function UserCard({ user }: Props) {
  return <div>{user.name}</div>
})

// 2. useMemo 缓存计算结果
function FilterList({ items, keyword }: Props) {
  const filtered = useMemo(() => {
    return items.filter(item => item.name.includes(keyword))
  }, [items, keyword])
  return <List items={filtered} />
}

// 3. useCallback 稳定函数引用
function Parent() {
  const [count, setCount] = useState(0)
  const handleClick = useCallback(() => {
    console.log('clicked')
  }, [])
  return <Child onClick={handleClick} />
}

const Child = React.memo(({ onClick }) => {
  return <button onClick={onClick}>Click</button>
})

useTransition ​

tsx
import { useTransition } from 'react'

function Search() {
  const [keyword, setKeyword] = useState('')
  const [results, setResults] = useState([])
  const [isPending, startTransition] = useTransition()

  const handleChange = (e) => {
    setKeyword(e.target.value)  // 紧急：输入框立即更新
    startTransition(() => {
      // 非紧急：搜索结果允许延迟
      setResults(filterResults(e.target.value))
    })
  }
}

大屏性能关键：

  1. 定时器清理：大屏长时间运行，必须清理定时器。
  2. 图表实例销毁：路由切走时 chart.dispose()，避免内存泄漏。
  3. resize 监听：窗口缩放时 chart.resize() 重新计算。
  4. 数据节流：高频数据更新要做节流，避免重复渲染。

4.4 防抖 / 节流 ​

ts
// 防抖：连续触发只执行最后一次
function debounce<T extends (...args: any[]) => any>(
  fn: T,
  delay: number
): (...args: Parameters<T>) => void {
  let timer: number | null = null
  return (...args) => {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => fn(...args), delay) as unknown as number
  }
}

// 节流：固定间隔内最多执行一次
function throttle<T extends (...args: any[]) => any>(
  fn: T,
  interval: number
): (...args: Parameters<T>) => void {
  let last = 0
  return (...args) => {
    const now = Date.now()
    if (now - last >= interval) {
      last = now
      fn(...args)
    }
  }
}

// 使用
const handleSearch = debounce((keyword) => {
  fetch(`/api/search?q=${keyword}`)
}, 300)

const handleScroll = throttle(() => {
  // 滚动处理
}, 100)

🎯 面试常考 ​

Q1：运行时性能都包括哪些?

交互响应(INP)、长任务与主线程占用、动画帧率、内存占用、以及用户操作后的感知延迟,重点是「用户点完之后多久看到反馈」。

Q2：长任务怎么优化?

拆分大任务、把计算移出主线程(Web Worker)、用 scheduler.yield() 或 requestAnimationFrame 让出主线程、把能提前算的提前算(预计算 / 缓存)。

📝 小结 ​

  • 运行时优化的核心指标是 INP,它取代了 FID,衡量的是「用户交互到下一次绘制」的总延迟。
  • 超过 50ms 的任务就是长任务,会阻塞输入响应,拆分是最直接的解法。
  • 动画要跑在合成层,transform / opacity 不会触发布局和绘制,是流畅动画的前提。
