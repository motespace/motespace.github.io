性能优化清单(发布前必看) ​

复制这份到 PR 模板 / 评审 Checklist,逐项打勾。

一、加载性能 ​

资源层 ​

  • [ ] 启用 HTTP/2(或 HTTP/3) —— 多路复用,握手成本降一半
  • [ ] 启用 Brotli 压缩 —— 比 gzip 再小 15~20%
  • [ ] 静态资源走 CDN —— 用户就近访问
  • [ ] 关键 CSS 内联到 head —— 避免首屏白屏
  • [ ] preload 关键资源(LCP 图片 / 字体) —— 提前下载
  • [ ] preconnect / dns-prefetch 第三方域名 —— 减少 DNS 查询
  • [ ] 字体 preload + font-display: swap —— 避免文字闪烁

图片/视频 ​

  • [ ] 图片显式 width / height —— 避免 CLS
  • [ ] 首屏图片用 AVIF/WebP —— 比 JPG 小 30~50%
  • [ ] 非首屏图片 loading="lazy" —— 延迟加载
  • [ ] 大图标用 SVG / iconfont —— 比 PNG 小

JS / 字体 ​

  • [ ] 代码分割:路由懒加载 —— 首屏不加载其他页面
  • [ ] tree-shaking 验证 —— 打包后无未引用代码
  • [ ] 第三方库按需引入 —— element-plus / antd / lodash 全量是反模式
  • [ ] 字体子集化 —— 中文字体只引入用到的字符

二、运行时性能 ​

渲染 ​

  • [ ] 列表 > 100 行用虚拟列表 —— react-window / virtuoso
  • [ ] React.memo / useMemo / useCallback 包裹重组件 —— 避免不必要重渲染
  • [ ] v-memo / v-once(Vue 3) —— 同样避免重渲染
  • [ ] 长任务拆分:await scheduler.yield() —— 让出主线程
  • [ ] requestAnimationFrame 动画 —— 不在定时器里做动画
  • [ ] requestIdleCallback 后台任务 —— 不阻塞用户交互

数据 ​

  • [ ] 防抖 / 节流 —— 滚动、resize、input 都要
  • [ ] Web Worker 处理大数据 —— > 16ms 的任务考虑 Worker
  • [ ] 计算属性 vs 方法(Vue) —— computed 自带缓存

表单/输入 ​

  • [ ] 不在 onChange 里同步发请求 —— 用 blur 或防抖
  • [ ] 受控组件 debounce —— 避免每输入一次就 re-render

三、内存管理 ​

7x24 小时运行 / 路由频繁切换 / 单页应用尤其重要。

  • [ ] beforeUnmount / unmounted 清理定时器
  • [ ] ECharts / Highcharts 实例 dispose
  • [ ] Three.js / Babylon.js 场景 destroy
  • [ ] EventBus / EventEmitter 解绑
  • [ ] AbortController 取消未完成请求
  • [ ] Web Worker terminate
  • [ ] 大的 Blob / File / ArrayBuffer 不再用时置 null
  • [ ] 闭包内引用的 DOM 节点 / 大对象,在不需要时置 null

四、网络 ​

  • [ ] API 请求合并:GraphQL / BFF —— 减少请求数
  • [ ] 客户端缓存:SWR / React Query / Pinia —— 减少重复请求
  • [ ] HTTP 缓存:Cache-Control / ETag —— 静态资源强缓存
  • [ ] Service Worker 缓存关键资源 —— PWA 必备
  • [ ] 接口防重 / 防抖 —— 避免重复点击
  • [ ] WebSocket 断线重连 —— 业务侧容错

五、监控 ​

  • [ ] Web Vitals 自动上报(LCP / INP / CLS)
  • [ ] 长任务监控(PerformanceObserver)
  • [ ] 错误监控(Sentry / 自建)
  • [ ] 业务关键路径耗时打点
  • [ ] 上线后 1 周复查 RUM 看板

六、上线前最后检查 ​

  • [ ] Lighthouse 综合分 ≥ 90(内部页)/ ≥ 70(用户页)
  • [ ] 包体积报警阈值(主 chunk < 500KB / 总和 < 2MB)
  • [ ] 真实设备测试(iOS Safari、Android Chrome)
  • [ ] 弱网测试(Chrome DevTools Slow 3G)
  • [ ] 慢 CPU 测试(DevTools 4x slowdown)
  • [ ] 灰度发布,观察 1 天再全量

七、按场景的快速清单 ​

中后台管理系统 ​

  • 路由懒加载 ✅
  • 虚拟列表(> 100 行表格) ✅
  • 防抖/节流(搜索、滚动) ✅
  • 内存清理(图表、定时器) ✅

移动端 H5 ​

  • 关键 CSS 内联 ✅
  • 字体 font-display: swap ✅
  • 图片懒加载 ✅
  • 首屏骨架屏 ✅
  • 离线缓存(PWA) ✅

内容站 / 博客 ​

  • SSG 静态生成 ✅
  • 图片 AVIF/WebP ✅
  • CDN 加速 ✅
  • 关键路径预取 ✅

大屏可视化 ​

  • Web Worker 大数据计算 ✅
  • ECharts 异步渲染 / tooltip ✅
  • canvas 复用,避免频繁创建 ✅
  • 7x24 内存监控 ✅

🎯 面试常考 ​

Q1：上线前前端性能要检查哪些?

资源体积(首屏 JS < 200KB、图片格式与懒加载)、渲染(CLS、图片宽高)、交互(INP、避免长任务)、网络(缓存头、CDN)、监控(埋点与告警兜底)。

📝 小结 ​

  • 这份清单是「发版前的最后一道闸」,按加载 → 运行时 → 内存 → 网络 → 监控五层过一遍。
  • 不同场景(中后台 / 移动 H5 / 内容站 / 大屏)的性能优先级完全不同,清单末尾给了四套快速清单。
  • 清单的价值在于「可执行」,每条都要能对应到一次具体的改动或一次具体的检查动作。
