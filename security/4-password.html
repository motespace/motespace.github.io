密码安全详解 ​

一、密码存储安全 ​

1.1 为什么不能明文存储 ​

数据库泄露 → 用户密码泄露 → 用户在其他网站密码相同 → 账户被盗

风险：

  • 用户通常在不同网站使用相同密码
  • 内部人员可直接查看用户密码
  • 数据库被 SQL 注入后全部泄露

1.2 密码存储原则 ​

原则说明
不可逆使用单向哈希，不存储明文
防彩虹表使用 salt，即使同密码哈希也不同
慢函数使用 bcrypt 等慢哈希，增加破解成本
有盐每个用户独立 salt

二、哈希函数 ​

2.1 常用哈希算法对比 ​

算法输出长度速度安全性推荐
MD5128 bit快❌ 不安全❌
SHA-1160 bit快❌ 不安全❌
SHA-256256 bit快中⚠️ 仅用于 HMAC
bcrypt可变慢✅✅
scrypt可变非常慢✅✅
Argon2可变慢✅✅（推荐）

2.2 彩虹表防御 ​

bash
# 相同密码的 MD5 值相同
echo -n "password123" | md5sum
# e10adc3949ba59abbe56e057f20f883e

# 攻击者预计算彩虹表，可快速反查
# 解决方案：加 salt

三、Salt（盐） ​

3.1 什么是 Salt ​

Salt 是随机生成的字符串，每个用户独立，在哈希前与密码组合。

javascript
// ❌ 无 salt：相同密码哈希相同
hash("password123") = "e10adc3949ba59abbe56e057f20f883e"
hash("password123") = "e10adc3949ba59abbe56e057f20f883e"  // 相同

// ✅ 有 salt：相同密码哈希不同
salt1 = "random_salt_1"
hash("password123" + salt1) = "a1b2c3d4..."
salt2 = "random_salt_2"
hash("password123" + salt2) = "e5f6g7h8..."  // 不同

3.2 存储结构 ​

sql
-- 用户表设计
CREATE TABLE users (
  id INT PRIMARY KEY,
  username VARCHAR(50),
  password_hash VARCHAR(255),  -- bcrypt 输出
  salt VARCHAR(32)             -- 独立 salt（bcrypt 不需要单独存储）
);

bcrypt 不需要单独存储 salt，因为 salt 被嵌入到哈希结果中：

javascript
// bcrypt 哈希结构
"$2b$10$abcdefghijklmnopqrstuuK5R4X8V7J8H9I0J1K2L3M4N5O6P"
// $2b$ = 算法版本
// 10$ = cost factor (计算强度)
// abcdefghijklmnopqrstuu = 22字符的 salt
// K5R4X8V7J8H9I0J1K2L3M4N5O6P = 31字符的哈希值

四、bcrypt ​

4.1 特点 ​

  • 内置 salt 生成
  • 可配置计算复杂度（cost factor）
  • 输出长度固定（60 字符）

4.2 使用方式 ​

javascript
// Node.js
const bcrypt = require('bcrypt')
const SALT_ROUNDS = 10

// 哈希密码
const hashPassword = async (plainPassword) => {
  const hash = await bcrypt.hash(plainPassword, SALT_ROUNDS)
  return hash
}

// 验证密码
const verifyPassword = async (plainPassword, hash) => {
  const isMatch = await bcrypt.compare(plainPassword, hash)
  return isMatch
}
javascript
// 使用示例
const register = async (username, password) => {
  const hash = await hashPassword(password)

  await db.query(
    'INSERT INTO users (username, password_hash) VALUES (?, ?)',
    [username, hash]
  )
}

const login = async (username, password) => {
  const [users] = await db.query(
    'SELECT * FROM users WHERE username = ?',
    [username]
  )

  if (users.length === 0) {
    return { error: '用户不存在' }
  }

  const valid = await verifyPassword(password, users[0].password_hash)

  if (!valid) {
    return { error: '密码错误' }
  }

  return { user: users[0] }
}

4.3 Cost Factor 选择 ​

javascript
// cost factor 越大越安全，但计算越慢
// 建议：使单次哈希耗时 200-500ms

const BENCHMARK = async () => {
  const start = Date.now()
  await bcrypt.hash('password', 10)
  const duration = Date.now() - start
  console.log(`Hashing time: ${duration}ms`)
  return duration
}

// 根据硬件配置调整
const SALT_ROUNDS = 12  // 普通服务器
// const SALT_ROUNDS = 14 // 高性能服务器
// const SALT_ROUNDS = 8   // 低性能设备

五、Argon2 ​

5.1 特点 ​

Argon2 是 2015 年 Password Hashing Competition 的冠军，比 bcrypt 更安全。

三种变体：

  • Argon2d：抗 GPU/ASIC 并行
  • Argon2i：抗侧信道攻击
  • Argon2id：混合模式（推荐）

5.2 参数说明 ​

javascript
const argon2 = require('argon2')

const hashPassword = async (password) => {
  return argon2.hash(password, {
    type: argon2.argon2id,     // 推荐
    memoryCost: 65536,         // 64 MB
    timeCost: 3,               // 3 次迭代
    parallelism: 4             // 4 线程
  })
}

const verifyPassword = async (password, hash) => {
  return argon2.verify(hash, password)
}

5.3 对比 bcrypt ​

特性bcryptArgon2
内置 salt✅✅
内存占用固定可配置
并行度固定可配置
GPU 抵抗中强
侧信道抵抗中强

六、前端密码处理 ​

6.1 密码强度检验 ​

javascript
const checkPasswordStrength = (password) => {
  let score = 0
  const feedback = []

  if (password.length >= 8) score++
  if (password.length >= 12) score++

  if (/[a-z]/.test(password)) score++
  if (/[A-Z]/.test(password)) score++
  if (/[0-9]/.test(password)) score++
  if (/[^a-zA-Z0-9]/.test(password)) score++

  // 检查常见密码
  const commonPasswords = ['123456', 'password', 'qwerty']
  if (commonPasswords.includes(password.toLowerCase())) {
    feedback.push('不能使用常见密码')
  }

  // 检查键盘序列
  if (/^[qwert]+$/i.test(password)) {
    feedback.push('不能使用键盘序列')
  }

  return { score, feedback }
}

6.2 前端密码传输 ​

javascript
// ❌ 不推荐：明文传输
uni.request({
  url: '/api/register',
  method: 'POST',
  data: { password: this.password }  // 明文
})

// ✅ 推荐：HTTPS + 前端哈希（不替代后端哈希）
// 前端哈希不是安全措施，只是减少日志泄露
uni.request({
  url: '/api/register',
  method: 'POST',
  data: {
    password: await sha256(this.password)  // 前端哈希
  }
})

注意：前端哈希不能替代后端哈希，因为攻击者可以直接提交哈希值绕过。

🎯 面试常考 ​

7.1 为什么 MD5/SHA-1 不安全 ​

javascript
// 攻击者预计算彩虹表
// 只需查表，不需要破解

// 案例：2013 LinkedIn 密码泄露
// 1.6 亿密码使用 SHA-1 存储
// 攻击者用彩虹表快速破解大部分密码

7.2 为什么要用慢哈希 ​

javascript
// 快速哈希：每秒 10 亿次
// 慢哈希（bcrypt）：每秒 1 万次
// 差距：10 万倍

// 攻击者使用 GPU 集群
// 10 亿个常见密码快速哈希后查表
// bcrypt 使得这种攻击变得不可行

7.3 密码找回流程 ​

javascript
// ❌ 错误：发送明文密码到邮箱
// 明文密码泄露风险

// ✅ 正确：发送重置链接
const sendResetLink = async (email) => {
  const user = await db.query('SELECT * FROM users WHERE email = ?', [email])

  if (user.length === 0) {
    return  // 不提示用户不存在，避免枚举
  }

  // 生成一次性 token（短有效期）
  const token = crypto.randomBytes(32).toString('hex')
  const expiry = Date.now() + 3600000  // 1 小时

  await db.query(
    'INSERT INTO password_resets (user_id, token, expires_at) VALUES (?, ?, ?)',
    [user[0].id, token, expiry]
  )

  // 发送邮件
  sendEmail({
    to: email,
    subject: '密码重置链接',
    html: `点击链接重置密码：https://example.com/reset?token=${token}`
  })
}

八、常见面试题 ​

Q1: 密码为什么要哈希存储？ ​

防止数据库泄露后用户密码被直接使用。哈希是单向的，无法反推原始密码。

Q2: 为什么不用 MD5/SHA-1？ ​

  • 计算速度太快，GPU 可快速暴力破解
  • 无 salt，彩虹表可快速反查
  • 已被证明不安全

Q3: bcrypt 的原理？ ​

bcrypt 基于 Blowfish 加密算法，内置 salt，使用可配置 cost factor 增加计算时间。相同密码每次哈希结果不同（因为 salt 不同）。

Q4: salt 的作用？ ​

确保相同密码在不同用户间哈希值不同，防止彩虹表攻击。即使两个用户密码相同，数据库中存储的哈希值也不同。

Q5: 如何选择 cost factor？ ​

在安全性和性能间平衡：

  • 建议使单次哈希耗时 200-500ms
  • 随着硬件性能提升，定期增加 cost factor
  • 用户登录时感知不明显的延迟是可接受的

Q6: 前端需要哈希密码吗？ ​

前端哈希不能替代后端哈希，因为攻击者可以直接提交哈希值。但前端哈希可减少日志泄露风险，不是安全增强措施。

📝 小结 ​

  • 密码必须用故意慢的哈希(bcrypt/Argon2/scrypt),通用哈希(MD5/SHA)太快,GPU 每秒几十亿次。
  • salt 每个用户随机、存数据库,防彩虹表;pepper 服务端统一、不入库,防库泄漏后离线爆破。
  • cost factor 要按线上机器性能定,目标是单次哈希 100~300ms。
  • 前端不要哈希密码 —— 会把密码当成传输凭据,反而多一层风险;传输靠 HTTPS,存储靠服务端哈希。
