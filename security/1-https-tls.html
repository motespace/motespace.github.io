HTTPS 与 TLS 详解 ​

一、HTTPS 原理 ​

1.1 什么是 HTTPS ​

HTTPS = HTTP + TLS，是在 HTTP 基础上加入 TLS 加密层，实现：

  • 加密传输 — 防止数据被窃听
  • 身份认证 — 防止中间人攻击
  • 数据完整性 — 防止数据被篡改
浏览器 ←→ TLS 加密 ←→ 服务器

1.2 HTTP vs HTTPS ​

对比HTTPHTTPS
端口80443
协议明文加密
证书无需要 CA 证书
SEO-优先收录
性能更快略慢（握手开销）

二、TLS 握手过程 ​

2.1 握手流程（RSA 版本） ​

客户端                      服务器
  |                           |
  |──── ClientHello ──────────→|  1. 客户端发送支持的 TLS 版本、加密套件
  |                           |
  |←─── ServerHello ──────────|  2. 服务器选定加密方案，返回证书
  |←─── Certificate ─────────|  3. 服务器发送证书（含公钥）
  |←─── ServerHelloDone ──────|  4. 服务器 hello 结束
  |                           |
  |──── ClientKeyExchange ───→|  5. 客户端生成随机数(pre-master)，用公钥加密发送
  |──── ChangeCipherSpec ────→|  6. 客户端准备切换加密
  |──── Finished ────────────→|  7. 客户端发送握手摘要
  |                           |
  |←─── ChangeCipherSpec ─────|  8. 服务器准备切换加密
  |←─── Finished ────────────|  9. 服务器发送握手摘要
  |                           |
  |════ 加密通信开始 ═════════|

2.2 握手关键步骤 ​

第一步：版本协商

javascript
// 客户端发送支持的最高 TLS 版本
ClientHello {
  version: "TLS 1.3",
  cipher_suites: ["TLS_AES_128_GCM_SHA256", "TLS_CHACHA20_POLY1305_SHA256"],
  extensions: [sni, alpn]
}

第二步：证书验证

bash
# 服务器返回证书链
Certificate {
  chain: [leaf_cert, intermediate_cert, root_cert]
}

# 浏览器验证证书
1. 检查证书是否过期
2. 检查证书域名是否匹配
3. 检查证书链是否可信（从根证书到叶子证书）
4. 检查证书吊销状态（CRL/OCSP）

第三步：密钥交换

javascript
// RSA 密钥交换
pre_master_secret = random_bytes(48)
encrypted_premaster = rsa_encrypt(server_public_key, pre_master_secret)

// 双方计算主密钥
master_secret = PRF(pre_master_secret, "master secret", client_random + server_random)

// 生成会话密钥
client_write_key = AES-GCM(master_secret)
server_write_key = AES-GCM(master_secret)

2.3 TLS 1.3 改进 ​

特性TLS 1.2TLS 1.3
握手往返2-RTT1-RTT
加密算法多种仅AEAD（AES-GCM、ChaCha20）
RSA 密钥交换支持移除（前向安全性）
0-RTT-支持（会话恢复）

TLS 1.3 握手（1-RTT）

客户端                      服务器
  |                           |
  |──── ClientHello + 密钥共享 ─→|
  |                           |
  |←─── ServerHello + 密钥共享 ─|
  |←─── Finished + 加密通信 ───|
  |                           |
  |════ 加密通信开始 ═════════|

三、数字证书 ​

3.1 证书结构 ​

javascript
Certificate {
  // 证书信息
  subject: {
    C: "CN",           // 国家
    ST: "Beijing",     // 省份
    L: "Beijing",       // 城市
    O: "Example Inc",  // 组织
    CN: "www.example.com"  // 域名
  },

  // 颁发者信息
  issuer: {
    C: "US",
    O: "DigiCert Inc",
    CN: "DigiCert Global G2 TLS ECC SHA256"
  },

  // 公钥信息
  subjectPublicKeyInfo: {
    algorithm: "ECDSA",
    publicKey: "04:xx:yy:zz:..."  // EC 公钥
  },

  // 签名
  signature: "xx:yy:zz:..."  // CA 用私钥签名
}

3.2 证书类型 ​

类型说明用途
域名验证（DV）仅验证域名所有权个人站点
组织验证（OV）验证组织真实性企业
扩展验证（EV）严格验证，显示绿色标识金融、企业

3.3 证书链验证 ​

根证书（Root CA）← 自签名
    ↓ 签名
中间证书（Intermediate CA）← 可有多级
    ↓ 签名
叶子证书（Leaf Certificate）← 服务器使用

验证过程

javascript
function verifyCertificate(cert, chain, trustedRoots) {
  // 1. 遍历证书链
  for (let i = 0; i < chain.length - 1; i++) {
    const cert = chain[i]
    const issuerCert = chain[i + 1]

    // 2. 验证签名
    if (!verifySignature(cert, issuerCert.publicKey)) {
      throw new Error('Invalid signature')
    }

    // 3. 验证有效期
    if (!isValidPeriod(cert)) {
      throw new Error('Certificate expired')
    }
  }

  // 4. 信任根证书验证
  const rootCert = chain[chain.length - 1]
  if (!trustedRoots.contains(rootCert)) {
    throw new Error('Untrusted root')
  }
}

四、HSTS ​

4.1 什么是 HSTS ​

HSTS（HTTP Strict Transport Security）强制浏览器使用 HTTPS 连接。

4.2 配置 ​

apache
# Apache
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"

# Nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
http
# 首次响应头
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

4.3 参数说明 ​

参数说明
max-age缓存时间（秒），建议 1 年
includeSubDomains包含子域名
preload申请加入浏览器预加载列表

五、中间人攻击防御 ​

5.1 攻击原理 ​

攻击者插入在客户端和服务器之间
客户端 ←── 明文 ──→ 攻击者 ←── 明文 ──→ 服务器

5.2 防御措施 ​

1. 证书 pinning

javascript

const certificatePinning = {

六、常见面试题 ​

Q1: HTTPS 连接过程？ ​

  1. TCP 三次握手
  2. TLS 握手：版本协商 → 证书验证 → 密钥交换 → 加密算法确认
  3. 验证 Finished 消息
  4. 加密通信开始

Q2: TLS 1.2 和 1.3 的区别？ ​

  • 1.3 握手从 2-RTT 减少到 1-RTT
  • 1.3 移除了不安全的加密算法（RSA 密钥交换）
  • 1.3 支持 0-RTT 会话恢复

Q3: 数字证书验证流程？ ​

  1. 检查证书是否过期
  2. 检查域名是否匹配
  3. 检查证书链完整性
  4. 检查证书是否在吊销列表（CRL/OCSP）
  5. 检查签名是否由受信任 CA 签发

Q4: 为什么不完全信任 HTTP？ ​

  • 明文传输，数据可被窃听
  • 无身份认证，可能遭遇中间人攻击
  • 无数据完整性保护，数据可被篡改

Q5: HSTS 的作用？ ​

  • 强制浏览器使用 HTTPS
  • 防止 HTTP 降级攻击
  • 防止中间人劫持

🎯 面试常考 ​

Q1：HTTPS 做了什么?

用 TLS 给 HTTP 套上加密和身份认证:机密性(对称加密)、完整性(摘要签名)、身份认证(证书链验证服务器身份)。

Q2：TLS 握手做了什么?

① 协商版本与密码套件;② 服务端发证书;③ 客户端验证证书链和域名;④ 协商会话密钥(ECDHE);⑤ 之后用对称加密通信。

Q3：为什么每次请求还要有证书?

服务器证书做身份认证;会话密钥用对称加密是因为非对称加密太慢。TLS 1.3 把握手压到 1-RTT 并移除了不安全套件。

📝 小结 ​

  • HTTPS 的三件事:机密性(对称加密)、完整性(摘要签名)、身份认证(证书链 + 域名校验)。
  • TLS 1.3 把握手压到 1-RTT(密钥交换和证书签名合并进 ServerHello),并去掉了无前向安全的 RSA 交换。
  • HSTS 让浏览器强制 HTTPS,防止 SSL strip;配合 CSP 的 upgrade-insecure-requests 处理混合内容。
  • 证书链靠「根 CA 私钥不外泄」防伪 —— 这是企业代理证书和自签名证书报红的根本原因。
