OAuth 2.0 详解

一、OAuth 2.0 概述

Section titled “一、OAuth 2.0 概述”

1.1 什么是 OAuth

Section titled “1.1 什么是 OAuth”

OAuth 2.0（Open Authorization）是一种开放授权协议，允许第三方应用获取用户授权，访问用户在其他服务上的资源，而无需获取用户的账号密码。

应用场景：

  • 微信登录、QQ 登录、Google 登录、GitHub 登录
  • 小程序授权、App 授权第三方获取用户信息
  • API 开放平台第三方应用授权

1.2 核心概念

Section titled “1.2 核心概念”
角色 说明
Resource Owner（资源所有者） 用户本人
Client（客户端） 第三方应用
Authorization Server（授权服务器） 发放令牌的服务
Resource Server（资源服务器） 存储用户资源的服务
Authorization Grant（授权凭证） 用户授权的凭证

1.3 四种授权模式

Section titled “1.3 四种授权模式”
模式 说明 场景
Authorization Code 授权码模式 Web 服务器应用（最安全）
Implicit 隐式模式 SPA、单页应用（已不推荐）
Resource Owner Password Credentials 密码模式 高度信任的应用
Client Credentials 客户端模式 不涉及用户资源的 API

五、安全威胁与防护

Section titled “五、安全威胁与防护”

5.1 CSRF 攻击

Section titled “5.1 CSRF 攻击”

攻击原理：攻击者伪造授权请求，用户授权后 token 被发送到攻击者网站。

防护：state 参数

5.2 授权码劫持

Section titled “5.2 授权码劫持”

攻击原理：攻击者嗅探或拦截授权码，换取 token。

防护措施：

  1. 授权码一次性使用
  2. 授权码短期有效（建议 5 分钟）
  3. 验证 redirect_uri 必须与注册时一致
  4. 使用 PKCE 增强安全

七、常见面试题

Section titled “七、常见面试题”

Q1: OAuth 2.0 的四种授权模式？

Section titled “Q1: OAuth 2.0 的四种授权模式？”
  1. 授权码模式：最安全，适合后端应用，通过 code 换 token
  2. 隐式模式：直接返回 token，适合 SPA（已不推荐）
  3. 密码模式：用户直接提供账号密码，需要高度信任
  4. 客户端模式：客户端以自己身份访问，不涉及用户

Q2: 授权码模式流程？

Section titled “Q2: 授权码模式流程？”
  1. 用户点击登录，redirect 到授权服务器
  2. 用户在授权页面确认授权
  3. 授权服务器 redirect 回应用，带上 code
  4. 后端用 code + client_secret 换 token
  5. 用 token 访问用户资源

Q3: 为什么 OAuth 要用 code 换 token，而不是直接返回 token？

Section titled “Q3: 为什么 OAuth 要用 code 换 token，而不是直接返回 token？”
  1. code 需要 client_secret 才能换 token，client_secret 只有后端知道
  2. code 在 URL 参数中传递，不会在服务器日志中留下
  3. token 直接暴露在浏览器有安全风险

Q4: state 参数的作用？

Section titled “Q4: state 参数的作用？”

防止 CSRF 攻击。攻击者无法猜测 state 值，攻击者构造的回调请求会因为 state 不匹配而被拒绝。

Q5: 如何防止 Token 泄漏？

Section titled “Q5: 如何防止 Token 泄漏？”
  1. 使用 HTTPS 传输
  2. Token 存储在内存而非 localStorage
  3. 缩短 Token 有效期
  4. 使用 refresh_token 定期轮换
  5. 敏感操作要求额外验证

Q6: PKCE 是什么？

Section titled “Q6: PKCE 是什么？”

Proof Key for Code Exchange，在授权码交换时增加 code_verifier 验证，防止授权码被劫持后兑换 token。推荐用于移动端和 SPA。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：OAuth 2.0 解决什么问题?

让第三方应用「有限授权地」访问用户资源,而不用把用户密码给第三方。四种授权模式里现在推荐 Authorization Code + PKCE。

Q2：四种授权模式?

authorization_code(最安全,配合 PKCE)、implicit(已废弃)、password(已不推荐)、client_credentials(服务间调用,无用户参与)。

Q3：Access Token 和 Refresh Token 的区别?

Access Token 短期(分钟~小时),用于访问 API;Refresh Token 长期,只用于换新的 Access Token。刷新令牌要更严格地存储(能撤销、HttpOnly)。

📝 小结

Section titled “📝 小结”
  • OAuth 2.0 是授权框架不是认证协议;OIDC 才是建在它之上的身份层。
  • 四种模式里现在只推荐 Authorization Code + PKCE;implicit 和 password 已不推荐。
  • 用 code 换 token 而不是直接返回 token:避免 token 出现在 URL 和浏览器历史里。
  • PKCE 用 code_verifier/challenge 绑定,让截获 code 的人无法换到 token。
  • state 防 CSRF,nonce 防重放,redirect_uri 白名单防开放重定向。
