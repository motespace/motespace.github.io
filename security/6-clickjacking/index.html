Clickjacking(点击劫持)

一、是什么

Section titled “一、是什么”

Clickjacking(UI Redress Attack)是一种视觉欺骗攻击:攻击者把目标网站嵌入透明 iframe,叠在诱饵按钮上。用户以为在点诱饵,实际点在 iframe 里的关键按钮(转账、修改权限、删除)。

二、攻击方式

Section titled “二、攻击方式”

2.1 基础攻击

Section titled “2.1 基础攻击”

用户访问页面 → 看到“领红包”按钮 → 点击 → 实际触发了 iframe 里的转账按钮 → 钱被转走。

2.2 进阶攻击

Section titled “2.2 进阶攻击”

Cursorjacking:不光劫持点击,还劫持鼠标光标位置。 Tapjacking:移动端,劫持触摸事件(早期 Android 浏览器)。 Filejacking:通过 iframe + <input type="file"> 让用户上传本地文件。

三、危害

Section titled “三、危害”
  • 诱导支付:伪装“领奖”,实际转账
  • 诱导授权:伪装“同意协议”,实际授权第三方应用
  • 诱导删除:伪装“普通按钮”,实际删除数据
  • 诱导关注/点赞:社交平台刷量

四、防御

Section titled “四、防御”

4.1 服务端:禁止被嵌入

Section titled “4.1 服务端:禁止被嵌入”

老方案:X-Frame-Options

现代方案:CSP frame-ancestors

实战建议:

  • 关键页面(支付、转账、授权)用 DENY / ‘none’
  • 一般页面用 SAMEORIGIN / ‘self’
  • 需要被嵌入的页面(第三方 widget),用 allowlist + 强 CSP

4.2 客户端:JavaScript 检测(辅助)

Section titled “4.2 客户端:JavaScript 检测(辅助)”

服务端头是主防御,客户端 JS 是兜底:

JS 跳出 iframe 的问题:

  • 性能开销:每次加载都执行
  • 攻击者可禁用 JS
  • 现代浏览器默认禁用跨域 iframe 跳出(防止 clickjacking 模式反转)

正确做法:**用 HTTP 头(CSP)**做主防御,JS 做辅助。

4.3 嵌入第三方内容时:sandbox

Section titled “4.3 嵌入第三方内容时:sandbox”

如果你的页面需要嵌入第三方 iframe(广告、统计 widget、社交分享按钮):

sandbox 能力清单:

值 作用
allow-forms 允许提交表单
allow-modals 允许弹窗
allow-popups 允许 window.open
allow-popups-to-escape-sandbox 弹出窗口不受 sandbox 限制
allow-same-origin iframe 内容视为同源(慎用)
allow-scripts 允许脚本执行
allow-top-navigation 允许修改 top.location(慎用)

踩坑警告:allow-scripts + allow-same-origin 同时存在 = 攻击者可移除 sandbox 属性。要么只开 scripts,要么只开 same-origin。

🎯 面试常考

Section titled “🎯 面试常考”

Q1：点击劫持是什么?

攻击者把目标页面用 iframe 藏在透明 iframe 下面,诱导用户点击。

Q2：怎么防?

服务端加 X-Frame-Options: DENY(或 CSP 的 frame-ancestors),现代浏览器优先用 CSP。

Q3：前端有没有办法检测?

可以尝试 window.top !== window.self 判断是否被嵌套,但这只是辅助,真正的防护必须在响应头。

📝 小结

Section titled “📝 小结”
  • 攻击者把目标页用 iframe 藏在透明层下面,诱导用户点击。
  • 服务端加 X-Frame-Options: DENY 或 CSP 的 frame-ancestors 'none' 才是真防护。
  • 前端可以用 window.top !== window.self 检测,但只是辅助,真正的拦截必须在响应头。
  • 需要允许部分站点嵌入时,用 frame-ancestors 列白名单,而不是放开所有。
