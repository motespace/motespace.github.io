HTTPS 与 TLS 详解

一、HTTPS 原理

Section titled “一、HTTPS 原理”

1.1 什么是 HTTPS

Section titled “1.1 什么是 HTTPS”

HTTPS = HTTP + TLS，是在 HTTP 基础上加入 TLS 加密层，实现：

  • 加密传输 — 防止数据被窃听
  • 身份认证 — 防止中间人攻击
  • 数据完整性 — 防止数据被篡改

1.2 HTTP vs HTTPS

Section titled “1.2 HTTP vs HTTPS”
对比 HTTP HTTPS
端口 80 443
协议 明文 加密
证书 无 需要 CA 证书
SEO - 优先收录
性能 更快 略慢（握手开销）

六、常见面试题

Section titled “六、常见面试题”

Q1: HTTPS 连接过程？

Section titled “Q1: HTTPS 连接过程？”
  1. TCP 三次握手
  2. TLS 握手：版本协商 → 证书验证 → 密钥交换 → 加密算法确认
  3. 验证 Finished 消息
  4. 加密通信开始

Q2: TLS 1.2 和 1.3 的区别？

Section titled “Q2: TLS 1.2 和 1.3 的区别？”
  • 1.3 握手从 2-RTT 减少到 1-RTT
  • 1.3 移除了不安全的加密算法（RSA 密钥交换）
  • 1.3 支持 0-RTT 会话恢复

Q3: 数字证书验证流程？

Section titled “Q3: 数字证书验证流程？”
  1. 检查证书是否过期
  2. 检查域名是否匹配
  3. 检查证书链完整性
  4. 检查证书是否在吊销列表（CRL/OCSP）
  5. 检查签名是否由受信任 CA 签发

Q4: 为什么不完全信任 HTTP？

Section titled “Q4: 为什么不完全信任 HTTP？”
  • 明文传输，数据可被窃听
  • 无身份认证，可能遭遇中间人攻击
  • 无数据完整性保护，数据可被篡改

Q5: HSTS 的作用？

Section titled “Q5: HSTS 的作用？”
  • 强制浏览器使用 HTTPS
  • 防止 HTTP 降级攻击
  • 防止中间人劫持

🎯 面试常考

Section titled “🎯 面试常考”

Q1：HTTPS 做了什么?

用 TLS 给 HTTP 套上加密和身份认证:机密性(对称加密)、完整性(摘要签名)、身份认证(证书链验证服务器身份)。

Q2：TLS 握手做了什么?

① 协商版本与密码套件;② 服务端发证书;③ 客户端验证证书链和域名;④ 协商会话密钥(ECDHE);⑤ 之后用对称加密通信。

Q3：为什么每次请求还要有证书?

服务器证书做身份认证;会话密钥用对称加密是因为非对称加密太慢。TLS 1.3 把握手压到 1-RTT 并移除了不安全套件。

📝 小结

Section titled “📝 小结”
  • HTTPS 的三件事:机密性(对称加密)、完整性(摘要签名)、身份认证(证书链 + 域名校验)。
  • TLS 1.3 把握手压到 1-RTT(密钥交换和证书签名合并进 ServerHello),并去掉了无前向安全的 RSA 交换。
  • HSTS 让浏览器强制 HTTPS,防止 SSL strip;配合 CSP 的 upgrade-insecure-requests 处理混合内容。
  • 证书链靠「根 CA 私钥不外泄」防伪 —— 这是企业代理证书和自签名证书报红的根本原因。
