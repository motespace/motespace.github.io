🎯 面试常考

Section titled “🎯 面试常考”

Q1：输入验证该做在哪?

必须做在服务端。客户端验证只是体验优化,攻击者可以绕过。前端要做的同样重要:别把用户输入直接当 HTML 插入。

Q2：白名单还是黑名单?

白名单。格式校验用白名单(只接受 Email 格式),危险字符过滤用黑名单作为兜底。

Q3：输出时还要做什么?

按输出上下文转义:进 HTML 转义、进 JS 用 JSON.stringify、进 URL 用 encodeURIComponent、进 SQL 用参数化查询。转义规则随上下文变,不存在一劳永逸的过滤。

📝 小结

Section titled “📝 小结”
  • 输入验证必须在服务端做,前端校验只是体验优化。
  • 白名单优于黑名单:格式校验用白名单(只接受 Email 格式),危险字符过滤只作兜底。
  • 转义规则随输出上下文变:进 HTML 要转义,进 JS 用 JSON.stringify,进 URL 用 encodeURIComponent,进 SQL 用参数化。
  • 没有「一劳永逸的过滤」,这是 XSS 反复出事的原因。
