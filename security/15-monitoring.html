安全监控与日志审计 ​

一、为什么需要监控 ​

没有监控的安全防御 = 装了门但不报警——攻击发生后才发现。

安全事件生命周期:
发生 → 探测期(几分钟到几个月) → 利用 → 攻击 → 数据泄露

监控目标:缩短"探测期到被发现"的时间

真实场景:从发现漏洞到被攻击,平均窗口期 6 天。有监控的企业能在分钟级响应,没有的可能几个月后才知道。

二、监控的三大类 ​

2.1 应用层监控 ​

异常登录检测:

ts
// 风控引擎规则
{
  rule: '异地登录',
  conditions: [
    { field: 'login_time', op: 'within', value: 'last_1h' },
    { field: 'login_location', op: 'not_in_history', value: 'user_locations' },
  ],
  action: 'require_2fa',
}

// 短时间内多次失败
{
  rule: '暴力破解',
  conditions: [
    { field: 'login_failed_count', op: 'gte', value: 5 },
    { field: 'window', op: 'within', value: '5m' },
  ],
  action: 'lock_account',
}

敏感操作审计:

ts
// 所有"高危"操作必须留痕
async function changePassword(userId: string, newPassword: string) {
  await auditLog({
    userId,
    action: 'change_password',
    ip: req.ip,
    userAgent: req.headers['user-agent'],
    timestamp: Date.now(),
    success: true,
  })
  // ... 改密码逻辑
}

2.2 网络层监控 ​

异常流量检测:

  • DDoS 检测(QPS 突增)
  • 大文件下载异常(数据外泄)
  • 频繁 401/403(扫描/暴力破解)
  • 异常 IP 来源

WAF(Web 应用防火墙):

  • Cloudflare、AWS WAF、阿里云 WAF
  • 自动拦截常见攻击(SQL 注入、XSS、CSRF)
  • 自定义规则

2.3 主机层监控 ​

  • 文件完整性监控(tripwire、AIDE)
  • 异常进程
  • 异常登录(SSH 异地登录)
  • 资源使用异常(挖矿木马)

三、应用层监控实战 ​

3.1 事件埋点 ​

ts
// 安全事件类型
type SecurityEvent =
  | { type: 'login_success', userId: string, ip: string }
  | { type: 'login_failed', userId: string, ip: string, reason: string }
  | { type: 'password_change', userId: string }
  | { type: '2fa_required', userId: string, reason: string }
  | { type: '2fa_failed', userId: string, attempt: number }
  | { type: 'sensitive_action', userId: string, action: string, target: string }
  | { type: 'permission_denied', userId: string, resource: string }
  | { type: 'rate_limited', ip: string, endpoint: string }

async function logSecurityEvent(event: SecurityEvent) {
  await Promise.all([
    db.auditLog.create(event),                          // 持久化
    securityLogQueue.send(event),                       // 实时分析
    sentry.captureMessage(`Security: ${event.type}`, {  // 告警
      level: event.type.includes('failed') || event.type.includes('denied') ? 'warning' : 'info',
      extra: event,
    }),
  ])
}

3.2 实时分析 ​

ts
// Kafka + Flink / ClickHouse / 自建规则引擎
securityEventStream
  .window(5 * 60 * 1000)  // 5 分钟窗口
  .groupBy('ip')
  .count('failed_login')
  .where(count > 10)
  .alert('Possible brute force from IP')
sql
-- SQL 实时查询(最近 5 分钟)
SELECT ip, COUNT(*) AS fail_count
FROM security_events
WHERE type = 'login_failed'
  AND created_at > NOW() - INTERVAL '5 minutes'
GROUP BY ip
HAVING COUNT(*) > 10;

3.3 风控引擎(高级) ​

特征:

  • 用户行为画像(常用 IP、设备、时间段)
  • 实时评分(每笔交易打分)
  • 规则 + 机器学习混合

智能风控平台项目:

  • 运营人员配置规则,不需要开发介入
  • 实时拦截异常操作
  • 数据回流做模型训练

四、日志审计 ​

4.1 必记录的字段 ​

ts
type AuditLog = {
  id: string
  timestamp: number
  userId: string | null        // null = 未登录
  action: string               // 'login' | 'change_password' | 'transfer' | ...
  target?: string               // 被操作的对象 ID
  ip: string
  userAgent: string
  requestId: string            // 链路追踪
  success: boolean
  errorCode?: string
  before?: Record<string, unknown>   // 操作前快照(可选)
  after?: Record<string, unknown>    // 操作后快照(可选)
}

4.2 实战日志格式(JSON Lines) ​

jsonl
{"ts":1700000000,"user":"u123","action":"login_success","ip":"1.2.3.4","ua":"Mozilla/5.0...","rid":"req-abc"}
{"ts":1700000010,"user":"u123","action":"change_password","ip":"1.2.3.4","ua":"Mozilla/5.0...","rid":"req-def","success":true}
{"ts":1700000020,"user":"u456","action":"login_failed","ip":"5.6.7.8","ua":"...","rid":"req-ghi","errorCode":"invalid_password"}

4.3 存储与保留 ​

实时事件 → Kafka → Elasticsearch(查询) → S3 归档(冷数据)

保留策略:
- 热数据(7 天):Elasticsearch
- 温数据(30 天):ClickHouse
- 冷数据(1 年+):S3 / OSS,合规要求

4.4 不能记录的内容 ​

ts
// ❌ 不能记录密码 / 敏感凭证
const record = {
  user: req.body.username,
  password: req.body.password,  // ❌
  token: req.headers.authorization,  // ❌
}

// ❌ 不能记录完整身份证号 / 银行卡
const record = {
  idCard: '110101199001011234',  // ❌
  bankCard: '6225...1234',  // ❌
}

// ✅ 脱敏
const record = {
  idCard: maskIdCard('110101199001011234'),  // '110101********1234'
  bankCard: maskBankCard('6225...1234'),     // '6225**********1234'
}

五、异常检测的常见规则 ​

5.1 登录异常 ​

规则触发条件动作
异地登录登录 IP 不在用户常用地区要求 2FA
深夜登录凌晨 2~5 点登录邮件通知
设备变更新设备首次登录要求 2FA
频繁失败5 分钟内 10+ 失败锁定账户

5.2 交易异常 ​

规则触发条件动作
大额交易单笔 > 阈值人工审核
频繁交易1 分钟内 5+ 笔限速
异常时段凌晨大额高风险标记
IP 异常登录地与常用地不同二次验证

5.3 数据访问异常 ​

规则触发条件动作
大批量下载1 小时下载 1000+ 条限速 + 通知
敏感字段访问访问身份证 / 银行卡审计 + 通知
异地管理后台管理员异地登录强制 2FA

六、应急响应流程 ​

事件发生 → 检测(分钟级) → 评估 → 处置 → 复盘
                ↓
            自动告警(阈值 / 异常检测)

处置选项:
├── 阻断 IP(WAF / 防火墙)
├── 暂停账户(临时锁定)
├── 撤销 token(强制下线)
├── 回滚变更(数据恢复)
└── 通报相关方(用户 / 监管)

复盘:
- 攻击路径
- 漏洞根因
- 修复措施
- 监控盲点
- 改进方案

七、安全 KPI ​

运营安全团队要跟踪的指标:

MTTD(平均检测时间)         ← 越短越好
MTTR(平均响应时间)         ← 越短越好
高危漏洞平均修复时间       ← < 7 天
依赖漏洞扫描覆盖率         ← 100%
HTTPS 配置合规率           ← 100%
CSP 启用率                 ← 100%
2FA 启用率(管理员)        ← 100%

🎯 面试常考 ​

Q1：安全监控要记什么?

认证事件(登录成功/失败、密码重置)、权限变更、敏感操作(导出、删除、支付)、异常模式(短时间大量失败、异地登录)。

Q2：怎么告警?

按「基线 + 偏离」设阈值:失败率突增、异常 IP、非常规时段访问。告警要分级,否则噪音会让人忽略真问题。

Q3：日志能记密码吗?

绝对不能。密码、Token、身份证、卡号一律脱敏;日志本身也要防篡改和越权访问,并设置保留期限。

📝 小结 ​

  • 要记的是认证事件、权限变更、敏感操作、异常模式(短时大量失败、异地登录)。
  • 日志绝对不能记密码、Token、身份证、卡号 —— 要脱敏。
  • 日志本身也要防篡改和越权访问,并设保留期限。
  • 告警要分级并有处理预案,否则全是噪音。
