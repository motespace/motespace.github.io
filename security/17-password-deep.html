密码安全:哈希、存储与策略 ​

一、为什么不能明文存密码 ​

数据库泄露案例:
2013 Adobe:1.53 亿用户,明文密码
2017 Equifax:1.45 亿用户,弱哈希(SHA-1)
2018 Facebook:数百万用户明文密码

明文 / 弱哈希密码的危害:
- 用户通用密码,一站泄露多站失陷
- 撞库攻击其他平台
- 法律责任(违反 GDPR / 等保 / 个人信息保护法)

二、密码哈希算法 ​

2.1 演变历史 ​

MD5(已淘汰)  → SHA-1(已淘汰) → SHA-256(不够) → bcrypt → Argon2(推荐)

为什么 MD5/SHA 不够:

  • 速度太快:现代 GPU 一秒算 10 亿次 MD5
  • 没有盐:两个用户密码相同,哈希值相同,易撞库

2.2 bcrypt(经典) ​

ts
import bcrypt from 'bcrypt'

// 注册
async function hashPassword(password: string) {
  // cost = 12 是 2024 年推荐(每代算力增长约 18 个月)
  return bcrypt.hash(password, 12)
}

// 登录
async function verifyPassword(password: string, hash: string) {
  return bcrypt.compare(password, hash)
}

// 自动含盐(每个用户的 salt 不同,hash 包含 salt)
const hash1 = await bcrypt.hash('123456', 12)
// $2b$12$abcdefghijklmnopqrstuv.HASHED_PASSWORD
const hash2 = await bcrypt.hash('123456', 12)
// $2b$12$xxxxxxxxxxxxxxxxxxxx.HASHED_PASSWORD(每次不同)

优点:

  • 自动含盐
  • 可调 cost factor(适应算力增长)
  • 业内成熟

缺点:

  • 内存需求低,GPU 攻击成本低
  • 最大密码长度 72 字节

2.3 Argon2(现代推荐) ​

Argon2id 是 2015 年 Password Hashing Competition 冠军,综合最强。

ts
import argon2 from 'argon2'

const options = {
  type: argon2.argon2id,
  memoryCost: 65536,    // 64 MB
  timeCost: 3,          // 3 次迭代
  parallelism: 1,       // 1 个线程
}

const hash = await argon2.hash('password', options)
// $argon2id$v=19$m=65536,t=3,p=1$HASH...

const ok = await argon2.verify(hash, 'password')  // true

参数调优:

  • memoryCost:64 MB 是基本,生产环境可用 128~256 MB
  • timeCost:3~4 次
  • parallelism:1(避免侧信道)
  • 目标:哈希一次用 0.5~1 秒

2.4 scrypt ​

ts
import scrypt from 'scrypt-js'

// scrypt(N, r, p) - N 是 CPU/内存成本,r 是块大小,p 是并行
const key = await scrypt(password, salt, 64, { N: 16384, r: 8, p: 1 })

Argon2 是 scrypt 的精神续作,大多数场景直接用 Argon2。

2.5 PBKDF2(不推荐,但合规场景常用) ​

ts
import { pbkdf2Sync } from 'crypto'

const hash = pbkdf2Sync(password, salt, 100000, 32, 'sha256').toString('hex')

合规场景(如 FIPS)常用,但安全性不如 Argon2/bcrypt。

三、密码策略 ​

3.1 长度 > 复杂度 ​

❌ "密码必须包含大小写字母 + 数字 + 特殊字符,8~20 位"
✅ "密码至少 12 位,推荐 16 位以上"

为什么:

  • "Passw0rd!" 满足所有"复杂度"要求,但弱
  • "correct-horse-battery-staple" 简单但极强
  • 长度提升指数级难度,复杂度提升有限

3.2 推荐规则 ​

  • 最短 12 位(NIST 推荐)
  • 无强制复杂度要求(NIST 2024 修订)
  • 检查弱密码黑名单(top 1000 常用密码)
  • 检查泄露密码(HaveIBeenPwned API)
  • 支持密码短语:"四个不相关词"比"8 位复杂密码"更强
  • 限制最大长度(防止 DoS): 64~128 位足够

3.3 实施示例 ​

ts
import { z } from 'zod'

const passwordSchema = z.string()
  .min(12, '至少 12 位')
  .max(128, '最多 128 位')
  .refine(p => !COMMON_PASSWORDS.has(p), '过于常见')
  .refine(p => !/[ ]/.test(p), '不允许空格')  // 避免 "pass word" 这种

async function checkLeaked(password: string) {
  // k-anonymity API:只发哈希前缀,不泄露原密码
  const hash = sha1(password).toUpperCase()
  const prefix = hash.slice(0, 5)
  const suffix = hash.slice(5)

  const res = await fetch(`https://api.pwnedpasswords.com/range/${prefix}`)
  const text = await res.text()

  // 格式: SUFFIX:COUNT
  const lines = text.split('\n')
  for (const line of lines) {
    const [s, c] = line.split(':')
    if (s === suffix) return parseInt(c) > 0
  }
  return false
}

// 注册时
if (await checkLeaked(password)) {
  throw new Error('该密码已被泄露,请更换')
}

3.4 用户体验 ​

强度可视化:

jsx
<PasswordStrengthMeter password={password} />

function getStrength(p: string): 'weak' | 'fair' | 'good' | 'strong' {
  if (p.length < 8) return 'weak'
  const score = zxcvbn(p).score  // 0~4
  return ['weak', 'weak', 'fair', 'good', 'strong'][score]
}

zxcvbn 是 Dropbox 公开的密码强度评估库,比简单规则更准。

不要做:

  • ❌ 强制 30 天改密码(用户会改成 Password1 → Password2)
  • ❌ 禁止特殊字符(用户可能被钓鱼)
  • ❌ 自定义安全问答(可被社工)

3.5 找回密码的正确做法 ​

1. 用户输入邮箱
2. 生成一次性 token(15 分钟有效)
3. 发送邮件:https://yoursite.com/reset?token=xxx
4. 用户点击,设置新密码
5. token 失效,重新登录

注意:
- token 一次性,过期失效
- 不能通过"安全问题"绕过
- 新密码不能与历史密码相同

四、登录安全 ​

4.1 失败处理 ​

ts
const MAX_ATTEMPTS = 5
const LOCK_DURATION = 15 * 60 * 1000  // 15 分钟

async function login(email: string, password: string) {
  const user = await db.user.findUnique({ where: { email } })

  // 通用错误信息(防账号枚举)
  const genericError = '邮箱或密码错误'

  if (!user) {
    // 仍然计算哈希(防时间攻击)
    await bcrypt.compare(password, '$2b$12$...')
    throw new Error(genericError)
  }

  if (user.lockedUntil && user.lockedUntil > Date.now()) {
    throw new Error('账户已锁定,请稍后再试')
  }

  const ok = await bcrypt.compare(password, user.passwordHash)
  if (!ok) {
    user.failedAttempts = (user.failedAttempts || 0) + 1
    if (user.failedAttempts >= MAX_ATTEMPTS) {
      user.lockedUntil = Date.now() + LOCK_DURATION
      user.failedAttempts = 0
    }
    await db.user.update({ where: { id: user.id }, data: user })
    throw new Error(genericError)
  }

  // 成功:重置计数
  await db.user.update({
    where: { id: user.id },
    data: { failedAttempts: 0, lockedUntil: null }
  })

  return issueToken(user)
}

4.2 防时间攻击 ​

ts
// ❌ 用户不存在时立即返回(时间差异大)
async function login(email, password) {
  const user = await db.find(email)
  if (!user) return error('用户不存在')   // 快
  if (!await bcrypt.compare(password, user.hash)) return error('密码错')  // 慢
  // ...
}

// ✅ 始终计算哈希(无论用户存不存在)
async function login(email, password) {
  const user = await db.find(email)
  if (!user) {
    await bcrypt.compare(password, '$2b$12$dummy.hash.to.prevent.timing.attack')
    return error('邮箱或密码错误')  // 时间与用户存在时接近
  }
  // ...
}

4.3 2FA(双因素认证) ​

密码 + 一次性验证码(TOTP / 短信 / 邮件):

ts
import { authenticator } from 'otplib'

// 用户绑定
const secret = authenticator.generateSecret()
await db.user.update({
  where: { id },
  data: { totpSecret: encrypt(secret), totpEnabled: true },
})
// 显示 QR 码: otpauth://totp/yoursite:user@x.com?secret=...

// 登录验证
const ok = authenticator.verify({ token: req.body.code, secret: decrypt(user.totpSecret) })

五、密码学基础(选读) ​

5.1 单向函数 ​

哈希 = 单向函数(几乎不可能反向)

但彩虹表可以反向查表 → 加盐
bcrypt / argon2 每次用随机盐,使彩虹表失效

5.2 哈希 vs 加密 ​

哈希(单向)加密(双向)
不可逆可逆(用密钥)
用于校验密码用于保护数据
慢(故意)快
bcrypt / argon2AES / RSA

5.3 工作量因子(cost) ​

cost = 12 → 2^12 = 4096 次运算 → ~250ms
cost = 13 → 2^13 = 8192 次运算 → ~500ms
cost 每增加 1,时间翻倍

定期评估算力,调高 cost。

🎯 面试常考 ​

Q1：密码哈希要用多少成本?

bcrypt 的 cost 参数或 Argon2 的 timeCost,目标是单次哈希耗时 100~300ms。太低容易被爆破,太高会拖垮登录接口。

Q2：怎么平滑升级哈希算法?

登录时检查用户记录里的算法标识,不是最新算法就用新参数重新哈希并更新,用户无感。

Q3：怎么防撞库?

多因素认证、登录失败延迟、限制尝试次数、异常设备检测、密码泄露库比对(常见密码直接拒绝)。

六、实战清单 ​

6.1 存储 ​

  • [ ] 用 bcrypt(cost ≥ 12)或 argon2id
  • [ ] 自动含盐(每用户独立)
  • [ ] 永远不存明文、永远不回显
  • [ ] 备份也加密存储

6.2 策略 ​

  • [ ] 最低 12 位
  • [ ] 检查弱密码黑名单
  • [ ] 检查已泄露密码(API)
  • [ ] 支持密码管理器(允许 64+ 位)
  • [ ] 不强制定期改

6.3 登录 ​

  • [ ] 失败次数限制(5 次锁定)
  • [ ] 通用错误信息(防枚举)
  • [ ] 2FA(管理员强制)
  • [ ] 防时间攻击
  • [ ] 操作审计

6.4 找回密码 ​

  • [ ] 一次性 token(15 分钟)
  • [ ] 不能用安全问题绕过
  • [ ] 新密码不能与旧密码相同
  • [ ] 修改后撤销所有 token

📝 小结 ​

  • 哈希选 Argon2id > bcrypt > scrypt,目标是单次 100~300ms。
  • 升级哈希算法要平滑:登录时检查记录里的算法标识,不是最新就用新参数重算并更新。
  • 防撞库:多因素认证、失败延迟、限次、异常设备检测、常见密码库比对。
  • 密码策略的重点是长度和唯一性,不是复杂度规则(「必须大小写+特殊字符」反而让人写成 Password1!)。
