SSRF 详解 ​

一、什么是 SSRF ​

SSRF（Server-Side Request Forgery，服务端请求伪造）是一种由攻击者构造请求，由服务器发起请求的安全漏洞。

与 CSRF 的区别：

  • CSRF：攻击者诱导用户发送请求，由用户的浏览器执行
  • SSRF：攻击者构造请求，由服务器执行
正常用户请求：浏览器 → 服务器 → 外部资源
SSRF 攻击：攻击者 → 服务器（作为代理）→ 内部资源

二、攻击原理 ​

2.1 基础攻击 ​

javascript
// 危险代码：用户输入直接作为 URL
const fetchResource = (url) => {
  return uni.request({ url })  // 用户输入：http://内网IP/admin
}

// 攻击者访问
// http://example.com/fetch?url=http://192.168.1.1/admin
// 服务器代为请求，返回内网管理后台内容

2.2 攻击场景 ​

1. 扫描内网端口

javascript
// 探测内网服务
url: "http://192.168.1.1:22"    // SSH
url: "http://192.168.1.1:3306"   // MySQL
url: "http://192.168.1.1:6379"   // Redis

2. 读取本地文件

javascript
// 伪协议读取文件
url: "file:///etc/passwd"
url: "file:///var/www/html/config.php"

// 或利用 URL schema
url: "dict://127.0.0.1:6379/info"

3. 攻击内部服务

javascript
// 攻击 Redis
url: "gopher://127.0.0.1:6379/_*3\r\n$6\r\nconfig\r\n$3\r\ndir\r\n$5\r\n/var/www/html\r\n*1\r\n$8\r\nflushall\r\n"

// 攻击 MySQL
url: "mysql://user:pass@127.0.0.1:3306/test"

三、防御措施 ​

3.1 输入验证 ​

javascript
// ❌ 危险：用户输入作为 URL
const fetchUrl = (userUrl) => {
  uni.request({ url: userUrl })
}

// ✅ 正确：白名单验证
const ALLOWED_HOSTS = ['api.example.com', 'cdn.example.com']

const fetchUrl = (userUrl) => {
  let url
  try {
    url = new URL(userUrl)
  } catch {
    return { error: 'Invalid URL' }
  }

  // 检查协议
  if (!['http:', 'https:'].includes(url.protocol)) {
    return { error: 'Only HTTP(S) allowed' }
  }

  // 检查 Host
  if (!ALLOWED_HOSTS.includes(url.host)) {
    return { error: 'Host not allowed' }
  }

  uni.request({ url: userUrl })
}

3.2 URL 解析绕过与防范 ​

1. DNS 重绑定

javascript
// 攻击原理：DNS 指向先外网后内网
// 防护：缓存 DNS 解析结果
const dnsCache = new Map()

const fetchUrl = (userUrl, timeout = 3000) => {
  const url = new URL(userUrl)

  // 立即 DNS 解析并缓存
  if (!dnsCache.has(url.hostname)) {
    const ips = await dns.lookup(url.hostname)
    dnsCache.set(url.hostname, ips)
  }

  const ip = dnsCache.get(url.hostname)[0]

  // 检查是否为内网 IP
  if (isPrivateIP(ip)) {
    return { error: 'Private IP not allowed' }
  }

  uni.request({ url: userUrl })
}

const isPrivateIP = (ip) => {
  return /^10\.|^172\.(1[6-9]|2[0-9]|3[01])\.|^192\.168\./.test(ip)
}

2. 协议限制

javascript
// 只允许 http/https，过滤其他协议
const fetchUrl = (userUrl) => {
  const url = new URL(userUrl)

  if (!['http:', 'https:'].includes(url.protocol)) {
    return { error: 'Protocol not allowed' }
  }

  // 再次检查：防止 file:///etc/passwd
  if (url.protocol === 'file') {
    return { error: 'File protocol not allowed' }
  }

  uni.request({ url: userUrl })
}

3. Host 黑名单

javascript
const BLOCKED_HOSTS = [
  'localhost',
  '127.0.0.1',
  '0.0.0.0',
  'metadata.internal',
  '169.254.169.254'  // 云元数据地址
]

const isBlockedHost = (host) => {
  return BLOCKED_HOSTS.includes(host) ||
    /^.*\.local$/.test(host) ||
    /^127\.\d+\.\d+\.\d+$/.test(host)
}

3.3 响应过滤 ​

javascript
const fetchUrl = (userUrl) => {
  return uni.request({ url: userUrl })
    .then(response => {
      // 检查响应是否包含敏感信息
      const sensitivePatterns = [
        /password/i,
        /ssh-rsa/i,
        /-----BEGIN/i,  // 私钥
        /root:/i         // /etc/passwd
      ]

      const body = JSON.stringify(response.data)
      for (const pattern of sensitivePatterns) {
        if (pattern.test(body)) {
          console.error('Sensitive data detected')
          return { error: 'Access denied' }
        }
      }

      return response.data
    })
}

3.4 网络隔离 ​

javascript
// 使用独立的网络沙箱
const fetchInSandbox = async (userUrl) => {
  // 只允许访问预配置的外部 API
  const allowedPaths = [
    '/api/public/',
    '/cdn/'
  ]

  const url = new URL(userUrl)
  const isAllowed = allowedPaths.some(path =>
    url.pathname.startsWith(path)
  )

  if (!isAllowed) {
    return { error: 'Path not allowed' }
  }

  return uni.request({ url: userUrl })
}

六、常见面试题 ​

Q1: 什么是 SSRF？ ​

攻击者构造请求，由服务器代替发起请求，可以访问服务器内部网络或本地资源。

Q2: SSRF 和 CSRF 的区别？ ​

  • CSRF：由用户的浏览器发起请求，利用用户已登录状态
  • SSRF：由服务器发起请求，可访问内网资源

Q3: 如何防御 SSRF？ ​

  1. 白名单验证 URL
  2. 协议限制（禁止 file、dict、gopher 等）
  3. Host 黑名单（内网 IP、云元数据地址）
  4. DNS 结果缓存
  5. 网络隔离
  6. 响应内容过滤

Q4: SSRF 能攻击哪些服务？ ​

  • 内网 Web 应用（管理后台、漏洞接口）
  • 数据库（MySQL、Redis、MongoDB）
  • 缓存服务（Memcached）
  • 消息队列（RabbitMQ、Kafka）
  • 云元数据服务（获取凭据）
  • 本地文件读取

Q5: 如何绕过 SSRF 防御？ ​

  1. DNS 重绑定
  2. URL 编码绕过
  3. 协议变换（http → https）
  4. IP 地址变种（十进制、十六进制）
  5. 短域名跳转

🎯 面试常考 ​

Q1：SSRF 是什么?

攻击者让服务器代替自己去请求内网资源,可能打穿内网、偷云凭证、绕过 IP 白名单。

Q2：怎么防 SSRF?

① URL 白名单而非黑名单;② 解析 DNS 后校验 IP 是否属于内网段(防 DNS Rebinding);③ 禁用跟随重定向或校验重定向目标;④ 禁用 file:// gopher:// 等协议;⑤ 出网走代理做统一管控。

Q3：为什么黑名单不行?

内网地址段太多且 IPv6、域名解析、重定向都能绕过。黑名单必然被绕过,要用白名单。

📝 小结 ​

  • SSRF 是让服务器代替你请求内网资源,和 CSRF(利用浏览器带 Cookie 发副作用)方向相反。
  • 防御核心是白名单:校验协议、解析 DNS 后校验 IP 是否落在内网段、重定向后再次校验。
  • 黑名单必然被绕过(DNS Rebinding、IPv6、十进制 IP、URL 编码),不要依赖。
  • 出网统一走代理是服务端最有效的兜底 —— 不给业务代码直接访问内网的权限。
